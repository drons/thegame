### 2.1 Механика миграции JSON (стадия GREEN)

Файлы НЕКАНОНИЧЕСКИ для JSON.stringify(obj, null, 2): ОДНОЭЛЕМЕНТНЫЕ
массивы inline (`"предметы": ["sulfur"],` — проверено 17/17) →
миграция ХИРУРГИЧЕСКОЙ строковой заменой (прецедент 000208 §6.10), НЕ
round-trip. Все строки-ношители — single-line (база 17/17, предметы
11/11, здания 17/17); каждый ключ — ровно 1 раз в файле (схема
additionalProperties:false). Одноразовый скрипт в /tmp (НЕ
коммитится): якорные замены `"база": "<id>"`, `"предметы": […]`,
`"здания": […]` по пин-таблице §2; null и icon — не задевать.
Per-file гейт: parse результата → deepEqual(resolve(parsed),
original) — изменились ТОЛЬКО 3 поля. Счётчики замен: 5/14/26.
После — `npm run gen:spells` → `git diff -- src/spells-data.js` ПУСТОЙ
(обязательная проверка, записать в tasks/result).

### 3.1 assets/spells/schema.json — 3 узла (ТОМ ЖЕ коммите, 000141)

* `база`: anyOf [{type string, pattern `^[a-z][a-z0-9_]*$`}, {type
  null}] → anyOf [{type string, pattern `^assets/spells/\d{6}\.json$`},
  {type null}] (null-ветка СОХРАНЯЕТСЯ — 12 заклинаний без базы).
* `предметы`.items: {type string, pattern `^[a-z]…$`} → {type string,

* `здания`.items: {type integer, minimum 1, maximum 999999} →
  {type string, pattern `^assets/buildings/\d{6}\.json$`} — ЕДИНСТВЕННАЯ
  смена типа в задаче (integer → string, как в 000208 «здания»;

  недвойственность исключена). minItems 1 / maxItems 6 — не трогать.
JSON-escape в schema.json — `"\\d"`, `"\\.json"` (как в существующих
паттернах). Walker «schema.json: только ключи минимального валидатора»
(tests/spells.test.js:93-121) — pattern уже допущен, правок не нужно.
