# 000330: боссы подземелий — 3×3 тайла + коллизии по размеру

## Список боссов (по факту диска до 000330)

Босс в подземельях — ОДИН: босс Бездны (ABYSS).
- `id: 'boss'`, `boss: true`, `mobIds: ['abomination', 'lower_demon', 'lower_demon']`,
  уровень `max(1, effLevel + delta)` — ставится в дальней комнате
  (`rooms[last]`, центр `far.cx/far.cy`) генерацией контента
  (`generateDungeonContents`, src/dungeon.js).
- В CAVE/CRYPT/RUINS/DROWNED боссов нет; в combat-таблице (src/combat.js)
  крупных мобов два — `bone_coloss` (пещерный) и `abomination` (бездный) —
  оба уже `size: {w:3, h:3}` в MOB_TYPES.
- 000330 НЕ вводит новых боссов и НЕ трогает combat.js: размер босса
  подземелья ВЫВОДИТСЯ из флага `m.boss` константой `BOSS_SIZE = {w:3, h:3}`
  в src/dungeon.js (экспорт) — 1:1 с `MOB_TYPES.bone_coloss.size` /
  `MOB_TYPES.abomination.size` (структурный пин B-SIZE).

## Размер и footprint

- Размер НЕ персистится (save v1 0-diff, validateDungeonContents не
  тронут): якорь босса — центральная клетка (m.x/m.y), footprint 3×3
  вычисляется на лету: `D.mobFootprint(m)` — не-босс → ровно `[x,y]`
  (бит-в-бит legacy), босс → 9 клеток (dx,dy ∈ [−1..1], порядок
  строка-за-строкой: (−1,−1)…(+1,+1)).
- `footprintFits(d, m)` — все 9 клеток inGrid + FLOOR.

## Расстановка (fail-closed, 0 новых rng)

- Босс ставится ТОЛЬКО если `footprintFits` (все 9 клеток дальнего
  центра FLOOR); guard `d.type === ABYSS` — не-ABYSS бит-в-бит.
- ВСЕ 9 клеток добавляются в `occupied` ДО первого `takeSpot`
  (паттерн 000183: occupied-резерв до контента) → мобильные группы и
  сундуки не спавнятся на footprint; 0 новых вызовов rng (резерв —
  до потока).
- Последствия для goldens: ABYSS-контент, где старый объект стоял на
  footprint → сдвиг rng-потока (коллизия takeSpot) → ре-пин
  (D-BOSS-2 (11,3): g3+сундуки; Case B: сундуки; Case A — бит-в-бит,
  ничего не стояло на footprint). Deposits (свой поток 0x0DE5) —
  позиции могут сдвинуться, в закреплённых сценах не сдвинулись
  (CH1_DEPOSITS).

## Движение/коллизии (wanderStep)

- `taken` — объединение `mobFootprint` всех живых мобов (не-боссы —
  по 1 клетке); у каждого моба `selfFoot` — свой старый footprint
  (проверка движения пропускает собственные старые клетки — порядок
  проверок для 1×1 идентичен legacy).
- Проверка хода `footprintFree(d, nx, ny, boss, taken, selfFoot)`:
  ВСЕ клетки нового footprint — inGrid + FLOOR + не в taken. Босс не
  заходит в проход шириной < 3 (B-MOVE-1: коридор 2 — 50 шагов,
  footprint всегда целиком на FLOOR, якорь в комнате).
- Приход моба на героя: `landed` — клетка игрока ∈ НОВЫЙ footprint
  (для 1×1 == сравнение клеток — legacy бит-в-бит).
- Догонялка (aggro) — тот же `footprintFree` (chaseDir).
- Детерминизм: 0 новых вызовов c._rng в legacy-путях (то же число
  слотов: 1 dir-ролл/моб + опц. aggro-ролл); B-REG-1 — бит-в-бит
  зеркальный сим-сценарий 1×1; CAVE-golden B-CAVE-GOLDEN.

## Бой на любой клетке footprint

- src/locations.js: helper `mobOnCell(G, m, x, y)` — `G.mobFootprint(m)`
  содержит клетку (fallback `m.x===x && m.y===y` если Game без
  mobFootprint). Три точки: restorePos (спавн/восстановление не на
  клетке моба), dungeonPostMove (шаг на моба → бой), ascendFloor D10
  (спуск не на клетке моба).
- Тест-пин: tests/locations.test.js «000330» — герой шагает на
  НЕ-ЯКОРНУЮ клетку footprint босса → {type:'combat', group}.

## Лестница вниз

- `stairsDownFor` исключает клетки: для ABYSS, где босс встанет
  (тот же predicate `footprintFits` на дальний центр) — все 9 клеток
  footprint недоступны для stairsDown; иначе — как раньше (одна
  клетка дальнего центра, guard 000183).

## Рендер (src/dungeon-ui.js)

- Босс — ТОЧНО footprint 3×3: `fillRect(P(m.x−1, m.y−1), 3*zoom,
  3*zoom)` цветом `#b06ad4` (один на босса), рисуется ДО спрайтов
  юнитов. Размер — из `live.BOSS_SIZE` (дungeon.js; fallback {3,3}
  если dungeon.js не в цепочке).
- Спрайты: 3 юнита на 3 РАЗНЫХ клетках footprint — смещения
  [(−1,0), (0,+1), (+1,0)] от центра (из BOSS_SIZE), каждый zoom*1.2,
  кадр `Math.floor(G.frameIndex(now, u.x, u.y, n))`.
- Фолбэк без лоадера — тот же 3×3-прямоугольник (не квадрат клетки).
- Не-боссы — БЕЗ ИЗМЕНЕНИЙ (MOB_UNIT_OFF [[0,0],[−0.35,0.15],[0.35,0.15]],
  фолбэк-квадрат +3/+3 zoom−6 #d9483b) — бит-в-бит.
- Туман (000225) — по ЦЕНТРУ (якорю) группы: весь босс (bbox + все
  юниты) скрывается, если якорь вне радиуса (MOBV-3).
- Визуальная проверка «3×3 читается как босс» — автотеста нет;
  пин — геометрия draw-вызовов (B-REND-1/2, dungeon-ui, MOBV-3).

## Подводные камни

- `Set.add(...arr)` игнорирует лишние аргументы (host и vm realm) —
  в harness-лоадерах спрайтов добавлять в Set только for-of.
- occupied-резерв 9 клеток меняет rng-поток ТОЛЬКО если старый контент
  стоял на footprint (коллизия takeSpot); «чистые» сцены — бит-в-бит
  (Case A D-BOSS-2) — ре-пинить только по факту node-проба.
- Размер босса не в сейве: сейв старого формата с боссом (якорь)
  работает без изменений (footprint выводится).
- Босс в 3×3-комнате с лестницей: stairsDownFor и генерация используют
  ОДИН predicate (footprintFits на дальний центр) — не расхождение
  «босс стоит, но лестница в footprint».
- combat.js НЕ знает про подземельного босса: mobIds босса — обычные
  MOB_TYPES (abomination/lower_demon); место/размер на карте — только
  dungeon-слой.
