# 000177 — Контракт тайла входа-выхода (для будущих задач)

Станция: ПРОЕКТИРОВАНИЕ (workflow 000177), мастер 7e9a494. Полный дизайн —
`memory/000177-portal-exit-tile.md`. Этот файл — короткая «карта» нового
контракта: ЧТО такое тайл входа-выхода, КУДА ставится герой, КАК работает
[E], КАК это рисуется. Перечитывать перед любой задачей, которая трогает
вход/выход из локаций, dungeon-ui-отрисовку, [E]-ввод, layout городов/
подземелий.

## 1. Какой тайл — вход-выход

- В подземельях и городах тайл входа и выхода — ОДИН (задача 000177).
- **Инвариант: `d.exit` deepEqual `d.entrance`** (оба поля существуют;
  consumers читают оба: `__game.dungeon` (main.js), HUD «До выхода»
  (hud.js/dungeon-ui), validateContentLayout (cities.js)).
- Dungeon: `createDungeon` (src/dungeon.js) — центр **ПЕРВОЙ** комнаты
  (`rooms[0].cx, rooms[0].cy`). Форма подземелья от этого НЕ зависит
  (0 rng-изменений).
- City: `createCityLayout` (src/cities.js) — **дверь на южном периметре**
  (`{ x: col(), y: H−1 }`, ОДИН вызов col()). Северная периметр-клетка —
  WALL (бывший выход больше не FLOOR).
- На этом тайле НЕ генерируются мобы/сундуки (dungeon: safe 5×5) и
  постройки (city: spots = FLOOR − {door}) — но блуждающий МОБ может дойти
  туда позже: [E] на двери всё равно = выход.
- Город НЕ может «запереть» дверь: reachOK-инвариант 000106 — все FLOOR
  достижимы от двери после расстановки построек.

## 2. Куда ставится персонаж при входе

- Вход в подземелье/город (шаг на мировой тайл пещеры 31 / города 51-54,
  buildingId 48-исключение) → `makeDungeonState`/`makeCityState`
  (src/locations.js) → герой на **`(x, y) = entrance = exit`** (дверь),
  мувер телепортирован туда же. `prevX/prevY` — туда же.
- После ВЫХОДА герой стоит на МИРОВОМ тайле пещеры/города (мировые
  координаты выходом не сдвигаются); авто-повторного входа НЕТ — вход
  только новым мировым шагом на тайл (гейт frame() main.js — не менять).
- Старые сейвы: dungeonState не персистится, city-layout генерируется из
  якоря → совмещение автоматически, миграций нет.

## 3. Флоу [E] (клавиша / тач-кнопка / debug-вход — три канала, один код)

1. [E] обрабатывает dungeon-ui (клавиша, listener ДО main.js) / тач-ветка
   main.js (screen 'dungeon') / debug `actions.enterDungeon` — все три
   сводятся к **`locationOnInteract()` (main.js)**:
2. `L.interactExit(ds)` (src/locations.js — чистая функция, 10-й экспорт):
   герой на тайле входа-выхода → `{ type: 'exit', name }` (name: город —
   `ds.name`, подземелье — DUNGEON_NAMES[type]); вне тайла / !ds → null.
3. Если exit → **`exitLocation(ds)`** (main.js — НЕ ТРОГАТЬ, КОНТРАКТ 000170:
   try/catch + finally { dungeonState=null; dungeonUI.close(); saveNow() })
   + flash «Вы вышли из <name>.» (слово в слово, 5 сек).
   - Подземелье: ДЕНЬ+1 (clock.event('dungeon'), память содержимого).
   - Город: день НЕ проходит, памяти нет.
4. Если не exit: город → `buildingActions.interactCity()` (постройки/Диалог
   — 000107); подземелье → no-op.
5. **Шаг на тайл входа-выхода = обычный шаг** (`{type:'moved'}`) — выход
   ШАГОМ больше не существует (exit-ветки из dungeonMove/cityMove удалены
   в 000177).
6. «Между уровнями подземелий — аналогично» (ТЗ): системы этажей в игре
   НЕТ; механизм уровень-независим (interactExit = чистая функция
   «позиция vs d.exit» — PE-3 доказывает на двух разных layout'ах).
   Будущие этажи — НОВАЯ задача: [E]-механизм и interactExit менять не
   нужно, добавляется новый layout-уровень + вид маркера 'stairs'.
7. Двойной фаер KeyE (dungeon-ui + main.js toggle()) — безопасен: вне
   выхода гард dungeonUI.isActive гасит; после выхода мир-ветка toggle
   на пещерных/городских тайлах — действий нет (см. 000177-portal-exit-
   tile.md §2.3).

## 4. Визуал тайла (dungeon-ui.js + sprites.js + assets/dungeon/)

- **Один** маркер на `d.exit` (== entrance), слой — после стен, до
  сундуков/мобов; маска тумана `isCity || mask !== 0` (000136) — без
  изменений.
- Вид по kind: **city → `door` (дверь)**; **dungeon → `cave_mouth`
  (вход в пещеру)**; `stairs` (лестница) — РЕЗЕРВ в реестре, точки
  отрисовки нет (этажей нет).
- Реестр: `G.DUNGEON_PORTAL` (src/sprites.js) =
  { door: 'assets/dungeon/door.svg', stairs: 'assets/dungeon/stairs.svg',
  cave_mouth: 'assets/dungeon/cave_mouth.svg' } — все пути в allAssetPaths;
  SVG 64×64, проходят svg.test.js (000120).
- Рендер: loader-изображение готово → `drawImage(img, p.x, p.y, zoom, zoom)`
  (целая клетка, proj-проекции тайлов); иначе фолбэк: `#d4b45a` (inset 2,
  zoom−4) + буква `'E'` (#101418, ui-monospace bold, как была буква 'X').
- Старые маркеры УБРАНЫ: жёлтый квадрат «X» (exit) и зелёный квадрат
  (entrance) больше не рисуются — пины 'X' и '#3f9d55' в dungeon-ui/
  dungeon-vision-тестах заменены на новый маркер.
- Hints (dungeon-ui build()): город — строка «Дверь — вход и выход:
  встаньте на неё и нажмите [E].»; подземелье — «Вход в пещеру — вход и
  выход: встаньте на него и нажмите [E].» (строки 1 и 3 — прежние:
  «Стрелки/WASD — шаг.», «[E] — постройки.» (город) / «Сундук и мобы — …»
  (подземелье)).
- HUD «До выхода: N клеток (на глаз)» — манхэттен до d.exit; на спавне
  «0 клеток» — легитимно.
