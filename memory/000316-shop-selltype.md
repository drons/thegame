Таблица (констракт ТЗ; bt: 0 Оружейная, 1 Бронник, 2 Аптекарь,

дублируют floor (таблица = полное описание sellable(K), читается без
домысливания). Покрытие: у КАЖДОГО kind каталога есть хотя бы один
магазин — пин T2 (sweep динамический по assets/items с диска —
параллельная 000321.01 добавит оружие/виды, таблица обязана держать).

Причина отказа — КАНОН бит-в-бит: «магазин не скупает такие
предметы» (sellItem; строка не менялась — пин T1 deepEqual).

Отвергнутые варианты:
 * единый allow-list по редкости/цене — ТЗ требует разрез «тип →
   тип магазина»;
 * «продавать всё всем» — ломает десятки отказных пинов (ui/000097/
   000309 и пр.) и смысл специализации лавок;
 * расширение `виды` в каталоге построек — «виды» определяют
   АССОРТИМЕНТ (что лавка продаёт), скупка — отдельный контракт;
   правка каталога задела бы golden-стоки.

## 2. Цена вне ассортимента: SELL_BASE_VALUE (defensive)

sellPrice: `base = Number.isFinite(it.value) ? it.value :
SELL_BASE_VALUE[kind] ?? 1` — формула прежняя
(base × (1 + SELL_WEALTH_MULT·wealth) × derived.sellPriceMult),
изменилась только база для НЕчисленного value. Валидатор каталога
пропускает NaN value (`typeof it.value !== 'number' || it.value < 1`
— NaN — number, не < 1), поэтому база по типу ДОСТИЖИМА; легальных
предметов с нечисленным value на диске нет — ветка страховая
(пин T5: vm-развилка с probe_ring value:NaN → SELL_BASE_VALUE.ring).
Значения таблицы — порядок цен вида (ring 40 > weapon 30 > … food 5).

## 3. Выкуп следующего обновления (только ротационные стоки)

Цикл-в-цикле: сток барахолки лагеря детерминирован (tile, day) —
makeCampShop, сид hash2(x,y,CAMP_STOCK_SEED)^((day+1)·0x9E3779B9),
refresh по respawn_days (main.js campShopFor). «Следующее обновление»
= генерация дня day+respawn_days ТЕМ ЖЕ вызовом → 0 новых RNG
(превью = повторный детерминированный вызов, пин T9).

Модель: модульное хранилище shopPreOrders (src/items.js) —
ключ `'C:x,y'` (PREORDER_KEY_RE /^C:-?\d+,-?\d+$/), значение
{itemId: qty}. Ядро НИЧЕГО не знает о лагерях — поставщик
регистрируется main.js: G.setShopAheadProvider(shop → {key, stock})
(src/main.js, сразу после campShopFor; не-47/нет записи/нет стойки/
исключение → null). nextCycleStock(shop):
 * нет провайдера / provider бросает / ключ не по regex → null
   (обычные городские лавки и мирские NPC — механика НЕ доступна:
   сток не циклический, «следующего» нет);
 * сток провайдера минус уже забронированное (net, avail≥1).

Покупка (buyItem, ветка have < qty): если avail в net-стоке хватает
— цена та же buyPrice (без премий), addItem, c.gold−=price, запись в
shopPreOrders, результат { ok:true, ahead:true, message:
'Забронировано к следующему обновлению: <имя> ×N' }. Не хватает —
каноничный 'нет в наличии' бит-в-бит. Предмет из ТЕКУЩЕГО стока
покупается как раньше (предзаказ не заводится).

Списание: campShopFor при refresh стойки вызывает
G.consumeShopAhead('C:'+key, shop.stock) ДО записи campStocks —
stock[id] = max(0, stock[id] − qty) (clamp: превью могло разойтись с
фактом, если день/respawn сдвинулись) и полное гашение ключа.
main.js — единственная точка списания.

Сейв v1 (без миграции, MIGRATIONS == [] пин цел): collectSaveData —
верхнеуровневый ключ shopPreOrders = serializeShopPreOrders()
(санация: regex ключей, int qty ≥ 1, пустые записи вон); restore —
restoreShopPreOrders(d.shopPreOrders) в try/catch+console.warn
(отсутствующий раздел → тихо {}, старый сейв играбелен). ФОРМА
раздела стоков (campStocks) не менялась — новая секция рядом
(паттерн 000298).

   (P1 раньше P2!) — иначе universam-правило открывало бы скупку

   показом и refresh → consumeShopAhead с max(0,…)-clamp, никогда не
   отрицательный сток; брони гасятся ПОЛНОСТЬЮ при refresh ключа;

   живой сессии просочится в загруженный сейв);
 * кросс-realm: ассерты по сткам/сейвам только через JSON roundtrip
   (память 000328.02 §14);
 * ветка ahead в buyItem НЕ трогает shop.stock — «в текущем сток не
   фигурирует» из ТЗ;
 * vm-харнес divergedBoot: каталог снапшотится items.js при загрузке
   (Game.ITEMS до загрузки items.js) — defensive-ветка value:NaN
   достижима только так (легальные JSON так не проходят);
 * buyPrice берёт derived(c) — у ahead-покупки priceChar общий с
   обычной («Торговец» влияет одинаково, новых множителей нет).
