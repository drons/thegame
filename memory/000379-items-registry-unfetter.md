## Фиксация решения (ДО кода, требование ТЗ)

Выбран **вариант (а) — discovery-изация** в форме «живые предикаты +
append-only реестр», с элементом (б) — механическим self-gate формата 000375
(T12), не дающим волне «починить» файл возвратом литерала.

Почему НЕ чистое «(а) как в ТЗ» (реестр ⊆ каталога, bijection только на
замороженном префиксе 864): оно создаёт ЛОЖНОЕ обещание. `loadCatalog` в
tests/scripts/canon-items-sync-core.js строит `num: NUM_BY_ID[obj.id]` из
ЕДИНСТВЕННОГО реестра tests/scripts/items-num2id-000318.08.json, а
tests/canon-items-sync-000284.02.test.js (тест «T6: items-каталог:
c1+c2+c3+c4+c11», игла c1) требует `it.nums.length == N` и
`nums ≡ {1..N} без дыр`. Предмет БЕЗ строки в реестре даёт `num === undefined`
⇒ c1 краснеет молча («nums != {1..N}»), а `legacy = all.filter(x => x.num <= 10)`
тихо теряет запись. Тот же реестр читают seven+ wave-канареек
(items-{weapon,armor,shield,artifact,tool,ring}-000321.0{1..7}),
items.test.js, items-food-000321.08, spells.test.js, buildings.test.js,
scroll-trade-temples-000347.02 — все ради ВИРТУАЛЬНЫХ numeric-имён
(позиционные пины рядов). ⇒ канон только один: **реестр растёт ВМЕСТЕ с
каталогом построчно APPEND-ONLY; замороженными являются СТРОКИ (запрет
пере-нумерации существующих), а не его длина**.

Почему НЕ чистое (б): оно сохраняет обязанность каждой +50-волны править
ЧУЖОЙ файл. Реальный список ре-пинов волны 000321.08 (её tasks/result):
`EXPECTED_COUNT=864→914` + T2 lex-хвост + T11 spot `000914` + ключевой
диапазон; у .27 — тройка T5 (`TOTAL_OCCURRENCES`/`TOTAL_REF_FILES` + имя).
То есть (б) документирует тройку, но не развязывает её.

## Контракт хелперов волн на ВНЕ-РЕЕСТРОВЫХ id (текущее поведение кода)

Хелперы инлайнятся в 7+ wave-файлов (items-{weapon,armor,shield,artifact,
tool,ring,potion}-000321.0{1..7}, items.test.js, items-food-000321.08):

* `VIRTNUMI08(f)`: диск-имя → `ID2NUM_I08[basename]`; для id, **не**
  внесённого в реестр, возвращает исходное slug-имя (fallback).
* `FILES_I08()`: `readdir().filter(SLUGI08).map(VIRTNUMI08).sort()` —
  сортировка строковая, а `'0' < 'a'`, поэтому вне-реестровый файл попадает
  в КОНЕЦ виртуально-номерного списка (не перемешивается с рядом 000NNN).
* `DISKF_I08(x)`: номер → slug; для отсутствующего номера возвращает
  `<тот же номер>.json` ⇒ файла на диске нет, и краснеет ЧТЕНИЕ предмета
  самой волной (а не молча пустой набор).

Следствие для политики роста: «дописать реестр» — единственная корректная
ветка роста; обход реестра даёт позиционно-красные канарейки и канон c1.
