# 000023: архитектура хранения заклинаний (assets/spells)

Статус: выполнено и закоммичено (тесты 186 → 194 pass).

## Решения

* **Шесть школ магии** — Огонь, Лёд, Тень (Интеллект) и Исцеление,
  Защита, Природа (Мудрость). Атрибут школы (intelligence/wisdom)
  хранится ЯВНО в каждом файле заклинания (`атрибут`), а не вычисляется:
  цена — редундантность, плюс — данные самодостаточны, а тест
  `SCHOOL_ATTR` в tests/spells.test.js держит соответствие с таблицей
  SPEC.md. Школы Интеллекта/Мудрости привязаны к действию
  «Применение заклинания» (раздел «Боевая система»: пул действий по
  основному навыку).
* **Варианты = файлы.** Каждый вариант заклинания (базовое
  + совершенствования) — отдельный JSON-файл 000001…000016. Связь
  «совершенствование → базовое» — поле `база` (id или null),
  `степень` = 1 + глубина цепочки. Инварианты, проверяемые тестом:
  одна школа в цепочке, степень = +1, уровень и мана не ниже базовых,
  без циклов. Цепочка из 3 степеней есть в каталоге
  (fireball → flame_burst → inferno).
* **Ранги школы** — 4 (Ученик 1–10, Знаток 11–25, Мастер 26–50,
  Аркимаг 51–100) по уровню основного навыка; ранг открывает
  `уровень` (1…4) заклинаний. Тест фиксирует покрытие 1..100 без
  разрывов.
* **Связи с миром** через ссылки, а не прозу: `предметы` (опционально,
  id из assets/items: sulfur/moonstone/phoenix_feather) и `здания`
  (обязательно, id из assets/buildings: Башня мага 18, Лаборатория
  алхимика 17, Монастырь 19, Храм исцеления 21, Храм горы 38 и др.).
  Тест проверяет обе ссылки через getItem/getBuilding.
* **Каталог, пока без кода.** Игрового src-модуля нет (задача 000023 —
  только данные+SPEC); в SPEC.md оговорено, что каталог — подготовка
  к задаче реализации (законспирирована как 000045 в pending).
* Имена полей — русские (стиль assets/buildings и assets/npc), id —
  латиница (стиль assets/skills и assets/items). Схема — только ключи
  минимального валидатора (задача 000015): `база: null | строка`
  сделана через anyOf (валидатор умеет тип `null`).

## Тесты

tests/spells.test.js: 8 тестов — нумерация, чистота каталога,
ключи схемы, валидность всех 16 файлов по схеме (минимальный
валидатор), правила каталога (id, «база null ⇔ степень 1», атрибут
школы, покрытие 6 школ и 4 уровней), цепочки «база» (ссылочная
целостность, без циклов, инварианты степени/уровня/маны), ссылки
предметов/зданий, ранги 1..100 без разрывов.
