нумерации items; 000030-000032 заняты skill-свитками).

| id | spell | школа | атрибут | ур. | базовое |
|---|---|---|---|---|---|
| fireball_scroll | fireball | огонь | Интеллект | 2 | нет |
| flame_burst_scroll | flame_burst | огонь | Интеллект | 3 | fireball |
| frost_bolt_scroll | frost_bolt | лёд | Интеллект | 1 | нет |
| blizzard_scroll | blizzard | лёд | Интеллект | 3 | frost_bolt |

Решения (фиксировать в S1):
* spark/mend — стартовые (player.js:114) — свитков НЕТ («уже изучено»).
* inferno (огонь 4), greater_heal (исц. 3), ward (защ. 3), stone_skin
  (защ. 2), shadow_bolt (тень 2), nature_blessing (прир. 2) — НЕ в луте:
  высокая/совершенствующая магия не для сундуков; shadow_bolt/
  stone_skin в рунных пулах (камень/обелиск — §3).
* flame_burst + blizzard (оба tier-3 с базой) — осознанно в луте:
  свиток «сначала база» — отказ-путь «нужно базовое заклинание»
  (тест S6) — обучение читает требования из канона.
* Ранги: Ученик 1-10 (ур.1), Знаток 11-25 (ур.2), Мастер 26-50 (ур.3),
  Аркимаг 51-100 (SCHOOL_RANKS spells.js:40-50) → свиток tier-2 нужен
  Знаток, tier-3 — Мастер; ранг считается по spell.атрибут
  (hero.primary) — canLearn :151-160.

## 2. kind spell_scroll (контракт schema)

* kind: 'spell_scroll' (ITEM_KINDS.SPELL_SCROLL; нестеккуемый —
  STACKABLE не расширяем; qty всегда 1).
* effect: { kind: 'spell', spell: '<spell_id>' } — ЕДИНСТВЕННЫЙ
  допустимый effect для этого kind (validateItem items.js:54).
* spell id — pattern ^[a-z][a-z0-9_]*$ (аналог skill у skill_book);
  членство в SPELLS_BY_ID — только тест S1 (items.js грузится ДО
  spells-data.js — каталог при загрузке недоступен).
* weight 0.2, value ~45-120 по уровню заклинания; desc — с упоминанием
  требования ранга школы (контракт: игрок видит, ЧТО и ПОЧЕМУ не
  выучится — причина из canLearn, не из desc).
* Именование предмета: `Свиток: <название заклинания>` (прецедент
  «Свитки» 000030).

## 3. Источники изучения (source-параметр canLearn/learn)

* 'scroll' — вызывается ТОЛЬКО из src/items.js useItem (ветка
  spell_scroll, после гарда reagent): canLearn(c, spell, 'scroll') →
  learn(c, spell, 'scroll'). Гейт источника НЕ ДОБАВЛЯЕТ проверок
  сверх школьных (spells.js:147-177) — источник фиксируется в
  hero.spells и в log.
* 'rune' — вызывается ТОЛЬКО из спец-модуля src/building-effect-runes.js
  handle(ctx) → G.Spells.learn(ctx.hero, spellId, 'rune') (ctx.hero —
  ЖИВАЯ ссылка; чистый applyRuneSpell НЕ учит — 000071). Добавочная
  проверка источника — Рунопись ≥ spell.уровень (spells.js:170-176):
  hero.secondary.runes.
* 'mentor' — ЗАРЕЗЕРВИРОВАН (spells.js:145 «'mentor' — спецгейты
  добавляются в задаче-исполнителе»), в 000133 НЕ вызывается (см. §4).
* Лог: learn() пишет в G.log (спелл-ид, источник) — существующее
  поведение, правок нет.

## 4. Формат действия «Расшифровка (заклинание)» (каталожная запись)

* effectId: '40_spell' (Рунический камень), '42_spell' (Обелиск) —
  латиница+подчёркивание (registerSpecial-гард, building-actions.js:64).
* Каталог (assets/buildings/000040.json / 000042.json,
  особые_параметры; паттерн Таверны 000044 — массив `эффекты` +
  общий `эффект`-объект сосуществуют):
  * `"эффекты": ["40", "40_spell"]` (камень) / `["42", "42_spell"]`
    (обелиск) — СУЩЕСТВУЮЩЕЕ действие ПЕРВЫМ (порядок строк оверлея
    A48/B21 не сдвигается).
  * ВНУТРЬ существующего `эффект` += `"заклинания": [ ... ]` — пул
    ЗАКЛИНАНИЙ (id-строки), РАЗДЕЛЯЕТ все действия постройки (общий
    объект, как слухи Таверны); applyRuneSpell читает пул из
    st.catalog — код каталог-драйвен, по id не хардкодит.
* Пулы:
  * Камень (40) — РАННИЕ: ['frost_bolt','chill','vine','magic_shield',
    'fireball','shadow_bolt','light_heal'] (ур.1-2, все без базового —
    «разогрев» от XP-действия «Расшифровать», которое растит
    secondary.runes).
  * Обелиск (42) — ПОЗДНИЕ: ['stone_skin','nature_blessing',
    'flame_burst','greater_heal','ward'] (ур.2-3; 3 из 5 —
    совершенствования с базой).
  * Union = 12 из 16; вне пулов: spark/mend (стартовые), inferno
    (ур.4 — не для рун), blizzard (ур.3 — в свитках/бездне).
* Реестр (src/building-effects.js): EFFECTS['40_spell']/['42_spell'] =
  { имя: 'Расшифровка (заклинание)', apply: applyRuneSpell } — ОДИН
  apply на оба; разВДень в записях НЕТ (верхнеуровневый
  `раз_в_день: true` каталога → per-effectId ключи 'x,y:40' /
  'x,y:40_spell', 'x,y:42' / 'x,y:42_spell' — каждое действие по разу
  в день, независимо).
* UI: строка оверлея [E] — АВТОМАТИЧЕСКИ (buildingActions строит из
  effectIds × EFFECTS); DigitN — существующий механизм;
  building-ui.js НЕ правится.
* Семантика (контракт, §3.2 архитектуры): успех → learn + марка дня +
  saveNow + flash «Расшифровано: «Имя»»; пустые кандидаты → ok:false
  (БЕЗ марки — действие не тратится, повтор в тот же день возможен) —
  осознанное отличие от XP-'40' (провал ролла там сгорает, R3 000074);
  «уже использовано сегодня» — существующий текст daily-лимита
  (000072).

## 6. Что видно игроку (контракт UX)

* Свиток: в инвентаре — строка предмета + кнопка «исп.» (указатель —
  «Эффект: изучает «Имя»»); применение при низком ранге/без базового/
  дубле — flash причины, предмет НЕ тратится; успех — flash
  «Изучено: «Имя»», предмет пропадает. В бою [Q] (quick-слот) —
  свиток применим, при отказе действие не сгорает.
* Камень/обелиск: [E]-оверлей — ДВЕ строки (существующая +
  «Расшифровка (заклинание)»); успех — flash «Расшифровано: «Имя»»;
  нет доступных (Рунопись/ранг) — flash причины, день НЕ сгорает;
  после использования — строка disabled «уже использовано сегодня».
* Книга заклинаний (ui-tab-spellbook / пикер зачарования) — БЕЗ ПРАВОК:
  hero.spells — единственный источник, новый свиток/руна появляются
  там автоматически (regression-тесты E1-E3).
