# «Ежедневный контент» построек — переиспользуемый контракт
(введён 000077: магический круг 43 / заброшенный храм 39;
для 000091–000095 и следующих «особых» эффектов)

ИСТОРИЯ: SPEC «Эффекты построек» → раздел «Магический круг и
заброшенный храм — „ежедневный контент“». Конкретика 43/39 (сиды,
тексты, рецепт босса, каталог) — memory/000077-building-content.md;
здесь — МЕХАНИЗМ (что переиспользовать, что — точка расширения).

## 1. Определение

«Ежедневный контент» постройки = ОДИН детерминированный ролл по
(tile, day) РАЗ В ДЕНЬ (каталожный флаг `раз_в_день: true`):
результат-ТИП по каталожным ДОЛЯМ (`особые_параметры.эффект.
доли`) → мир-эффект (инвентарь/бой/сообщение) → ЗАПИСЬ
состояния в раздел сейва `buildingContent`. Повтор в тот же
день — недоступно (reason-строка ТЗ); день D+1 — НОВЫЙ ролл
(может отличаться). НОЛЬ RNG вне (tile, day)-сидов.

Не «ежедневный контент» (не смешивать):
* «раз в день» БЕЗ ролла (благословения 36/38, исцеление 49 —
  000072/000076/000092) — счётчик buildingOncePerDay, состояния
  контента НЕТ;
* эффекты БЕЗ лимита (37 «Сон», таверна 000091) — повторны;
* одноразовые квесты (42, buildingQuests) — не по дням.

## 2. Компоненты (каждый новый эффект переиспользует)

1. **Чистый слой — src/building-effects.js** (нигде больше):
   * СВОЙ ASCII-сид-константа на КАЖДЫЙ ролл-вид (паттерн
     TELEPORT_TIE_SEED/STONE_ROLL_SEED: НЕ GLOBAL_SEED; экспорт
     — golden-пины).
   * Чистые (tile, day)-функции: `f(x, y, day, данные, hash) →
     результат` — hash ПАРАМЕТР; мусор данных → null (apply
     деградирует «недоступно»); детерминизм —
     deterministicRoll(x, y, day, SEED, hash) / pickFragment-
     паттерны (перепривязывать не надо — уже экспортированы).
   * `EFFECTS[id] = { имя, available?(st), apply(st) }`:
     available — по СНИМКУ сейва buildingContent (day ===
     st.day → reason-строка ТЗ); apply — ЧИСТ (000071/000074):
     только ВОЗВРАТ { ok, type, item|seed, message } —
     параметров из st.catalog.особые_параметры.эффект (000053),
     мир-мутаций НЕТ.
   * serialize/restoreBuildingContent — ОБЩИЕ для всех
     «ежедневных» эффектов (один раздел).
2. **Исполнение — спец-модуль** (000128 §2.3):
   * тот же механизм (один хендлер на ролл-вид) — ДОБАВЛЯЕТСЯ
     в src/building-content.js (registerSpecial ещё одного id);
   * свой мир-эффект — НОВЫЙ файл src/building-effect-<id>.js
     (UMD, чист при загрузке; саморегистрация; script-тег в
     слоте L660–663 index.html + пин index-order).
   * хендлер: мир-действие (addItem/startCombat/…) → ЗАПИСЬ
     buildingContent → { ok, message? }; ОТКАЗ мир-действия →
     { ok:false } ДО ЗАПИСИ (000128 §2.6: без марки/saveNow —
     день не сгорает).
3. **Каталог**: запись — `особые_параметры: { эффект: { доли,
   …таблицы }, раз_в_день: true, размещение: {…} }`; зеркало
   src/buildings.js — `npm run sync:buildings` (никогда руками).
4. **main.js — проводка ОДИН РАЗ** (сделана 000077, повторять
   НЕ надо): live Map buildingContent + поле collectSaveData +
   try/catch-блок restore + строка init-бандла.

## 3. Раздел сейва buildingContent (общий)

* Форма: `'x,y' → { day: integer ≥ 1, type: string }`.
* **Whitelist type — ОДНА константа в building-effects.js**
  (массив допустимых типов; 000077: ['chest','boss','relic']).
  Новый тип контента — расширяет СЮДА (restoreBuildingContent
  валидирует по ней) — ЕДИНСТВЕННАЯ точка расширения; каталог
  и хендлер используют свои значения типа.
* Ключ 'x,y' = тайл постройки (одна постройка на тайл —
  коллизий между эффектами НЕТ: разный тайл = разный ключ;
  та же постройка = тот же эффект).
* Запись ПЕРЕЗАПИСЫВАЕТСЯ новым роллом (день D+1) — рост Map
  ограничен числом посещённых построек-контентников; очистки
  onDay НЕТ. day < clock.day — норма (не блокирует новый день);
  day > clock.day — отброс при restore (подделка, 000031).
* Fail-open (000029): раздел/записи мусор → отброс, игра не
  падает; старый сейв без раздела → пусто, без warn.
* Две защиты от повтора (обязательны ОБЕ): (a) available() по
  снимку → ТЗ-строка; (b) daily-марка buildingOncePerDay
  (каталожный флаг) — backstop «уже использовано сегодня».

## 4. Детерминизм (гигиена)

* Сиды: `hash(x, y, SEED ^ day)` (deterministicRoll/pickFragment);
  day ВКЛЮЧЁН (вариант без day отвергнут — 000074).
* Один ролл-вид — один сид; роллы НЕ зависят от порядка вызовов
  (каждый — прямая функция (tile, day, seed)).
* Боевые эффекты: БОЕВОЙ СИД — отдельный сид-вид
  (000077: BOSS_COMBAT_SEED) → передаётся в createCombat
  (opts.seed) — состав/уровень — стандартные формулы ядра
  (НЕ собственные); «уровень по тайлу» = детерминизм по (tile,
  day)-сиду + формула ядра.
* Таблицы данных (предметы/доли/реликвии) — каталог (000053);
  «уровень/тип по тайлу» — из тайла (terrain/альфа/wealth —
  читать из ст.map read-only; правила — фиксировать в памяти
  задачи, прецедент 000077: dungeonTypeFor(terrain, альфа
  pixelAt, fallback 255 — moonDreamHint)).

## 5. Границы и не-требования

* apply НИКОГДА не мутирует мир (000071): инвентарь/бой/золото
  — только спец-хендлер (ctx: hero live, world.buildingContent,
  startCombat, world.game — escape-hatch).
* Сообщения успеха — в apply (чистый строит текст; имя предмета
  — ленивый G.getItem(...).название); пайплайн flash'ит
  r.message (приоритет над sres.message — 000128 §2.4).
* Отказ addItem (инвентарь) — день НЕ сгорает (запись — только
  после успеха мир-действия).
* Бой — стандартный поток (Эфир/buffMods/saveNow — существующие
  точки main.js): настраивать отдельный onEnd не надо, пока ТЗ
  не требует (000077: onEnd startCombatAt безопасен — defeatedAt
  не пишет, notifyGroupDefeated по строковому groupType — no-op).
* Новые ассеты/мобы/предметы — только отдельными задачами
  (пересечения 000057/000058); «ежедневный контент» — только
  СУЩЕСТВУЮЩИЕ id.

## 6. Чек-лист новой «ежедневной» постройки (для 000091–000095)

1. Каталог: эффект-объект (доли/таблицы) + раз_в_день: true;
   зеркало — sync:buildings.
2. building-effects.js: свой сид + чистые функции (hash —
   параметр) + EFFECTS[id] (available по buildingContent +
   чистый apply) + (новый тип?) — whitelist.
3. Спец-хендлер: в building-content.js (тот же ролл-вид) или
   src/building-effect-<id>.js (свой) + script-тег/пин
   (новый файл).
4. Тесты: доли N=10000 ±2%; детерминизм; повтор D/D+1;
   валидность результата (id ∈ каталогам); roundtrip
   buildingContent (если новый тип — whitelist); vm e2e [E]
   (строка действия, эффект, запись сейва, repeat-block).
5. A1-пин (union ключей EFFECTS) — обновить по факту; B5-типа
   «без эффектов»-предикаты — проверить (первая постройка без
   NPC — (4,3) id 43 — с 000077 ИМЕТЬ эффекты).
