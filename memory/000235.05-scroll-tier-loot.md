## 2. Моб-ролл: формула (дословно, контракт §8)

D = maxLvl(сразившейся группы мобов) − c.player.level
  (maxLvl — тот же reduce max(u.level) по killed, что редкий пул).
P_scroll = 0.05 + 0.02·max(0, D), кап 0.25 (кап при D ≥ 10).
Тир: D > 0 → T = min(4, 1 + floor(D/3));
     D ≤ 0 → T = 1 + (coin < 0.5 ? 1 : 0), coin из солёного потока
     (T ∈ {1,2}, 50/50) — ветка D ≤ 0 ПЕРЕХВАТИТЕЛЬНА, базовая
     формула к ней НЕ применяется (уточнение вериф. станции).
Школа — равномерная из 6, из солёного потока.
Выбор — из свитков школы+тира; нет → В РАМКАХ ШКОЛЫ ближайший тир
ВНИЗ (T−1..1), затем ВВЕРХ (T+1..4) (порядок ТЗ «вниз, затем
вверх» — лёд {1,3}, T=2 → frost_bolt, НЕ blizzard); школа без
свитков вообще → дропа НЕТ.

Поток: mulberry32(hash2(c.seed, c.day, SALT_SCROLL) >>> 0) —
ОТДЕЛЬНЫЙ солёный rng-поток (паттерн 000157.02/000158.02), НОЛЬ
вызовов c._rng → per-mob/базовый/редкий/голд-роллы БИТ-В-БИТ.
Вызов — внутри rollVictoryLoot, СТРОГО ПОСЛЕ редкого ролла
(последняя операция перед return items; контракт §9 + порядок
мержа с 000230.05 — после ВСЕХ её роллов).

Порядок выборок на потоке (ФИКСИРОВАН, пин детерминизма):
  [1] r1 = rng(); r1 ≥ P_scroll → НЕТ дропа (ЕДИНСТВЕННАЯ выборка);
  [2] ТОЛЬКО при попадании И D ≤ 0: coin = rng();
  [3] ТОЛЬКО при попадании: school = SCROLL_SCHOOLS[floor(rng()*6)];
  [4] ТОЛЬКО если пул школы+тира после fallback НЕ пуст:
      id = pool[floor(rng()*pool.length)].
Дроп — в тот же c.result.items через существующий drop()
(слияние qty, порядок первого появления); свиток — в инвентарь как
любой предмет (combatEndLoot/main.js без изменений); изучение —
отдельное действие useItem, ранг-гейт canLearn без изменений.

## 3. SALT_SCROLL = 0x2eaef6ed (FNV-1a32 «SCRL»)

Выбрано КОНСТРУКТИВНЫМ ОГРАНИЧЕНИЕМ (решено на станции, зафиксировано):
* Твёрдое ограничение — legacy-фикстуры с ТОЧНЫМ deepEqual
  c.result.items: 000132-N2(a)–(e) и 000165-C6 (ВСЕ — seed 5,
  day 0, strongHero L1, мобы L2 → D=1, P=0.07; проверено по коду
  тестов): первая выборка mulberry32(hash2(5, 0, SALT) >>> 0)
  ОБЯЗАНА быть ≥ 0.07. 0x2eaef6ed → 0.950687 (маржа ×13).
* Сеида 5..10, day 0..2 — ВСЕ первые выборки ≥ 0.07 → ни один
  закреплённый бой не получает свиток (поведение пин-фикстур
  не меняется вовсе).
* Отклонённые кандидаты: 0x5343524c (ASCII «SCRL») → 0.0183 <
  0.07 — ломает N2 (НЕ использовать); 0x5343524d («SCRL»+1,
  кандидат станции архитектуры) → 0.2184 — твёрдое ограничение
  тоже удовлетворяет, НО маржа ×3 и «+1» произволен; FNV-1a32 —
  самопроверяемая деривация (тест пересчитывает хэш «SCRL» и
  ассертит равенство) + максимальная маржа → выбран 0x2eaef6ed.
* Уникальность: коллизий с существующими солями НЕТ (полный grep
  src/*.js: 0x0DE5, 0x5e11, 0x7777, 0xabcdef, 0x154075, 0xb055,
  0x51a11ce5, 0x669f0101, 0x7f3a51c9, 0xf10c7a26, 0x53d10d53,
  0xd0d6b5e5, 0xd337b153, 0x5e11c3a7, 0x0c9f4b2d, 0x5eedc0de,
  0x54454c50, 0x71756974, 0x72656675, ASCII 0x4C4F4F54 и пр.).
  Пин: значение + пересчёт FNV-1a + legacy-safety (first draw
  (5,0) ≥ 0.07) + скан литерала «2eaef6ed» по src/ → ровно 1
  вхождение (combat.js) — авто-детект будущих коллизий.
* Дисциплина: соль ФИКСИРУЕТСЯ ДО подгонки под пины и ЗАПИНЯЕТСЯ
  тестом; НИКОГДА не пере-тюнить соль под новые пины (смена соли =
  сдвиг всей свиточной зоны + риск legacy-пинов).
