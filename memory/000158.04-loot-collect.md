## 1. Кратко: что делает задача

Игрок на глобальной карте входит на тайл с видимым природным лутом
(поле `tileAt.loot`, 000158.03) → HUD-строка «[E] Собрать: <имя>» →
нажимает [E] (единый роутер `G.buildingActions.toggle()`) → предмет в
инвентарь (`G.addItem`, вес/стекки), `collectedLoot.set('x,y', день)`,
`saveNow`, flash «Собрано: <имя>», тайл больше не несёт лут (подсказка
гаснет). Через `respawn_days` (live, по умолчанию 3; та же настройка,
«как для мобов» — НОВОЙ настройки НЕТ) `clock.onDay` удаляет ключ — лут
виден снова. Состояние «собрано» — ОТДЕЛЬНЫЙ раздел сейва
`collectedLoot` (НЕ смешивать с `defeatedAt`!).

## 3. Контракты

### 3.1 Раздел сейва `collectedLoot` (main.js)
- Имя раздела: `collectedLoot` (camelCase, как defeatedAt/
  buildingOncePerDay). Данные: Map 'x,y' → день сбора (абсолютный,
  int ≥ 1). Ключ — plain `'x,y'` (DAY_MAP_KEY_RE L203 принимает без
  суффикса; суффикс ':loot' НЕ ВВОДИТСЯ — раздел отдельный).
- Сериализация: `G.serializeDayMap(collectedLoot)` (тот же
  сериализатор 000072; guard `? : {}`). В `collectSaveData` — ВСЕГДА
  пишется (пустая карта → `{}`), версия сейва = 1, миграций НЕТ
  (000031 — старый сейв без поля не ломается).
- Restore: `raw == null` → тихо пропускаем (пустая карта, 000031);
  `typeof raw !== 'object' || Array.isArray(raw)` → console.warn +
  `collectedLoot.clear()`; иначе `G.restoreDayMap(raw)` (INVALID-ключ/
  день (не int, < 1) — молча отброшены, 000029 fail-open) →
  `dd > clock.day` → delete → clear+set → warn при 0 валидных.
- Поведение с поддельным ключом 'x,y:loot' (валиден по
  DAY_MAP_KEY_RE — формат 000072 принимает суффикс ':id'):
  restoreDayMap его СОХРАНЯЕТ, но lootVisible ищет ТОЛЬКО plain-
  ключ 'x,y' (Map.has('x,y'), суффикс не читает) → лут на том тайле
  остаётся ВИДИМЫМ и собираемым; ключ инертен, а ближайшая onDay-
  зачистка после respawn_days удаляет его (dueForRespawn формат
  ключа не различает). Проверено прямым запуском node (правки по
  ревью, 2026-10-12). ПИНА на suffixed-ключ НЕ СУЩЕСТВУЕТ (LM4(b)
  проверяет только 'abc' / '-2,1': 50 / '-1,1': 1) — сами такие
  ключи не пишем.
- Блок restore — ОТДЕЛЬНЫЙ try/catch, ПОСЛЕ buildingOncePerDay-блока
  (L1099), ДО buffs-блока (L1101); с defeatedAt-блоком (L1058-1071)
  НЕ смешивается (ТЗ «НЕ ТРОГАТЬ»).

### 3.2 `lootVisible(collectedLoot, x, y)` (day.js, чистая)
```
function lootVisible(collectedLoot, x, y) {
  if (!collectedLoot || typeof collectedLoot !== 'object') return true;
  const key = x + ',' + y;
  if (typeof collectedLoot.has === 'function') return !collectedLoot.has(key);
  return !Object.prototype.hasOwnProperty.call(collectedLoot, key);
}
```
- fail-open на мусор (null/undefined/'junk'/42/массив/true → true) —
  000029: битое состояние → лут ВИДИМ (старое поведение), не
  TypeError в rAF-цикле.
- Ключ ТОЧНО `x + ',' + y` (целые, без пробелов, отрицательные
  возможны — единый формат с groupVisible/defeatedAt).
- Принимает и Map (рабочее состояние main.js), и объект (сырой сейв /
  `__game`-копия); объект — `hasOwnProperty`, не `in`
  (прототип-безопасность, Object.create(null) — без crash).
- Чистая: вход не мутируется. Respawn — СУЩЕСТВУЮЩИЙ `dueForRespawn`
  (L127) с live `respawn_days` (default-параметр, 000099): НОВЫХ
  функций/настроек НЕТ.
- Экспорт — рядом с groupVisible (L337).

## 4. Решения (open questions ТЗ + анализы)

**D1. `lootVisible` — чистая функция в day.js, 1:1 зеркало
groupVisible; respawn — переиспользуемый `dueForRespawn` с live
`respawn_days`.** — ТЗ п.1 прямо требует («расширение существующего
модуля, не новый файл — паттерн groupVisible», «как для мобов»,
«без новой настройки»); fail-open = принцип 000029; 17 ключей
global-settings пинены — не трогаем.

**D2. `collectedLoot` — const Map в main.js рядом с defeatedAt;
ОТДЕЛЬНЫЙ раздел сейва через serializeDayMap/restoreDayMap; onDay-
чистка ПОСЛЕ defeatedAt-чистки; сырой live Map в ctx renderHud и
deps-бандле; `__game` getter-копия.** — ТЗ п.2-3 + «НЕ ТРОГАТЬ
defeatedAt-секцию»; serializeDayMap/restoreDayMap — готовый
универсальный 'x,y'-сериализатор (0 ключей/значений невалидных —
молча, 000029); fail-open/старый-сейв → {} — 000031; flash-пин дня
(L1502-1504) не расширяется (Р6: ТЗ молчит о flash-строке респауна
лута).

**D3. Доступ к collectedLoot из building-actions — live Map в
deps-бандле `G.buildingActions.init`; registerSpecial ОТВЕРГНУТ.** —
registerSpecial — спец-ДЕЙСТВИЕ, работает только из
