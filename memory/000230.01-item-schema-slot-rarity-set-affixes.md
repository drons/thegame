## 2. Точные формы (контракт красных тестов — ФИНАЛ)

### 2.1 assets/items/schema.json

Порядок `properties` — **append-конвенция КОНЦОМ** (последний
прецедент: icon 000211.06 «конец»; минимальный diff = минимальная
поверхность merge-конфликтов при ребейзах волн .02–.07):
`id, name, kind, subtype, weight, value, tier, desc, stats,
effect, loot, icon, slot, rarity, set, affixes`. **ИНВАРИАНТ:
порядок properties schema.json ≡ порядку KEYS sync-скрипта**
(конвенция комментария «Канонический порядок ключей (схема)»
sync-items-data.js :72; связь фиксируют E1 + E20, §5).

* `kind` enum (8 → 12): существующие 8 БЕЗ ПЕРЕСТАНОВКИ, новые 4
  КОНЦОМ в порядке ТЗ:
  `["weapon","armor","potion","food","skill_book","reagent",
  "spell_scroll","resurrection_scroll","shield","artifact",
  "tool","ring"]`.
* `subtype` enum (3 → 4): `["sword","bow","heavy","staff"]` —
  staff КОНЦОМ.
* `icon` pattern (ре-пин, ОБЕ директории — ТЗ п.1 + memory §8.5):
  `"^assets/sprites/(loot|items)/[\\w_]+\\.svg$"` (JSON-экранирование
  как в текущем паттерне; без этого первый контент-икон
  assets/sprites/items/… .07/.08 краснел бы в assets-schemas).
* `slot` (ОПЦИОНАЛЬНО, НЕ в required):
  `{ "type": "string", "enum": ["head","ears","neck","torso",
  "forearms","right_hand","left_hand","palms","ring","legs","feet"] }`
  — 11 значений, порядок ДОСЛОВНО ТЗ (ring = одна группа; 8
  физических слотов ring_left_1..4/ring_right_1..4 — модель .02,
  не схема).
* `rarity` (ОПЦИОНАЛЬНО, НЕ в required):
  `{ "type": "string", "enum": ["common","rare","epic","legendary",
  "impossible"] }` — порядок ДОСЛОВНО ТЗ (Д3: отдельное поле, НЕ
  tier 1..4 — редкость реагентов, 000157.01; доли 50/30/15/4.9/0.1
  — применение .05).
* `set` (ОПЦИОНАЛЬНО, НЕ в required):
  `{ "type": "string", "pattern": "^[a-z][a-z0-9_]*$" }` — тот же
  id-regex, что у id/effect.skill/effect.spell.
* `affixes` (ОПЦИОНАЛЬНО, НЕ в required):
  `{ "type": "array", "minItems": 1, "items": { "oneOf": [
    { "type": "object",
      "required": ["type","skill","amount"],
      "properties": {
        "type": { "const": "skill" },
        "skill": { "type": "string", "pattern": "^[a-z][a-z0-9_]*$" },
        "amount": { "type": "number" } },
      "additionalProperties": false },
    { "type": "object",
      "required": ["type","spell"],
      "properties": {
        "type": { "const": "free_cast" },
        "spell": { "type": "string", "pattern": "^[a-z][a-z0-9_]*$" } },
      "additionalProperties": false } ] } }`.

Решения формы (почему):
* **oneOf** (не anyOf): варианты взаимоисключаемы по `const` type —
  строгий; oneOf уже в схеме npc/skills + self-test
  assets-schemas.test.js:163 «oneOf — подходит ровно один вариант».
* **const** на type: ключ в ALLOWED_SCHEMA_KEYS (tests/json-schema.
  js:21-25; self-test :79-110/:131-153).
* **minItems: 1**: пустой массив affixes = мусор; прецедент
  loot.terrains minItems 1 (schema.json:38).
* **amount — ГРАНИЦ НЕТ** (type number без minimum): ТЗ «число,
  может быть отрицательным»; шкала силы — данные контентных волн
  (memory §6); integer проходит как number (json-schema.js:41).
* Все ключи под-схем ∈ ALLOWED_SCHEMA_KEYS: type/enum/pattern/
  minItems/items/oneOf/object/required/const/additionalProperties —
  generic-тест «только ключи валидатора» зелёный без правок.
