  `^assets/(items|skills|npc)/\d{6}\.json$|^assets/(spells|mobs|mob_groups|buildings|craft|dungeons)/[a-z][a-z0-9_]*\.json$`
  (craft уехал из number-ветки в slug-ветку; number-группа теперь — ТРИ

## 3. Решение: сегментный пин → свип basename === id

Каталог был единственным number-каталогом **с дырами** (сегменты волн
000001–…, 000200–000209 и т.п.); его непрерывность явным исключением
отметала RN2 (`GAPPED = new Set(['craft'])`). После rename файловых номеров
нет — «сегменты» и «дыры» теряют смысл, поэтому:

* сегментный тест в `tests/craft.test.js` заменён свипом
  «`basename === data.id` + lex-порядок имён» (заголовок переименован —
  прежний тезис ложен);
* `tests/assets-schemas.test.js` — носитель сегментного пина из ТЗ
  (`[[1,199],[210,237],[260,287],[310,337],[360,719]]`). ВАЖНЫЙ ФАКТ ДИСКА:
  до .07 `craft` в `CATALOGS` НЕ было (строка 33 = 8 каталогов) — т.е.
  крафтовая ветка сегментов была МЁРТВЫМ кодом, а каталог craft вообще не
  проверялся этим файлом (ни ключей схемы, ни валидности 643 файлов, ни
  негативного контроля). Решение: `CATALOGS += craft` + новая ветка
  `SLUG_SWEEP_000318 = { craft: { count: 643 } }` — свип «numeric-файлов
  нет» + `basename === data.id` + уникальность id + lex-порядок имён
  (состав из 643 имён фиксированным массивом НЕ пинится — в отличие от
  `SLUG_PINNED_000318` mobs/buildings и т.п., где сет маленький). Побочный
  результат: +4 теста (полная сетка покрытия как у прочих каталогов) и
  живая валидность всех 643 файлов по `assets/craft/schema.json`;
* `GAPPED` в `tests/assets-renames-000318.test.js` — **пустое множество**
  (механизм оставлен: он защищает будущий number-каталог с дырами);
* числовые идентификаторы волн в заголовках/сообщениях (000144–000199,
  000416…, 000670–000719) — ИСТОРИЯ, не переписываются (прецедент .06):
  правились только теги тестов, чьё утверждение стало ложным;
* счётчик 643 и цепочки «+50 рецептов 000321.0X» в сообщениях сохранены
  дословно — rename не меняет числа файлов.

## 5. Грабли (повторяемые)

* `String.prototype.replace(str, to)` раскрывает `$'`, `$&` в `to`. Новый
  литерал regex кончается `.json$',` ⇒ `$'` подставлял ОСТАТОК ФАЙЛА —
  `tests/assets-refs.test.js` был испорчен и восстановлен из индекса.
  Все пакетные правки — `split(from).join(to)` с проверкой числа вхождений.
* slug-regex (`SHAPE_BASENAME_RES.slug`) матчит `schema.json` — любой свип
  каталога обязан исключать его явно.
* Числовые идентификаторы волн в текстах тестов — не «ссылки»: REF_RE их не
  видит, guard'ы их не ловят; осмысленность держит только T5-свип нулями.
* `parseInt(<slug>.json)` молча даёт NaN — формулы, выведенные из номера
  файла, краснеют НЕ по существу (прецедент T9 выше).
* Пин-ветка обязана быть ДОСТИЖИМОЙ: числовая сегментная ветка craft в
  `tests/assets-schemas.test.js` висела в файле, но каталог в `CATALOGS` не
  входил ⇒ при rename она не краснеет (её просто нет), и «зелёный срез»
  это скрывает. Перед «переписать пин» — проверять, что тест существует
  (`node --test <файл>` + grep имени).
