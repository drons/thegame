Статус: ПРОЕКТИРОВАНИЕ завершено (анализы a1-домен/a2-архитектура/a3-тесты +
сверка с кодом и SPEC на HEAD master 7f61aee, worktree task/000214; базовый

## 1. Механизм (сверено с кодом HEAD)

* Часы — ОДНИ на всю игру: `const clock = G.createClock()` (src/main.js L399,
  src/day.js — чистое ядро, UMD, tests/day.test.js). `stepsPerDay` — live:
  getter day.js L73-74 → `liveStepsPerDay()` (SETTINGS.steps_per_day, 000099,
  дефолт 40, guard ≥ 1).
* `addStep(n)` (day.js L79): `steps += n; while (steps >= perDay) { steps -=
  perDay; advanceDay('steps'); }` — перенос избытка через `while`.
* `event(reason)` / `rest()`: целый день + `steps = 0` (триггеры, не шаги).
* Смена дня → onDay-цепь (main.js L1559+): `G.restoreDay(hero)` (HP/MP),
  `dueForRespawn` (побеждённые группы + природный лут), очистка истёкших
  баффов, `payWages` (спутники, seed `hash2(day, npcId)`), render,
  `hudFlash «День N.»`, `saveNow`. Watchdog try/catch (000170 D8) — throw
  рвёт только flash/сейв, не день.
* Глобальная карта (принцип, который расширяем): `frame()` (rAF) L3344-3368 —
  гейт `!inCombat && !inDungeon && …` → `tryMove()` успех → **L3355
  `clock.addStep(1)`** (ДО `maybeStartCombat` L3364 — шаг, запустивший бой,
  СЧИТАЕТСЯ) → `saveNow()` L3366 (в мире сейв на каждый успешный шаг).
* Локации (почему время «застывало»): шаги идут другим каналом — dungeon-ui
  keydown (src/dungeon-ui.js L294-315, 1 нажатие = 1 клетка) + тач-D-pad
  (touchHoldStep L349) → `ctx.onMove` → main.js `dungeonOnMove` (L2571) /
  `cityOnMove` (L2613) → чистый домен `G.locations.dungeonMove` (L383) /
  `cityMove` (L444) → `{type:'moved', chest?}` | `{type:'combat', group}` |
  `null` (стена/граница/inCombat; exit/ascend/descend — НЕ из move, а из
  `interactExit` — [E]-канал, 000177). clock в этот канал не передавался.
  Оба канала (клавиша/тач) сходятся в ctx.onMove — ОДНА точка проводки.
* Триггеры дня, которые НЕ трогаем: выход из подземелья —
  `exitDungeon` → `o.clock.event('dungeon')` (src/locations.js L557, SPEC
  «Игровое время»); отдых/таверна — `clock.rest()`; выход из города —
  no-op (locations.js L753, SPEC buildings.md L332-334 «явное решение»).
* Сейв: `data.day` + `data.steps` — top-level (collectSaveData L711-712);
  restore (L912-924): `fastForward` + `clock.addStep(d.steps)` с гардом
  `d.steps < clock.stepsPerDay` (live). Формат НЕ меняется. `dungeonState`
  в сейв НЕ сериализуется (перезагрузка — герой всегда в мире).
* Чтение для e2e: `g.state.day` / `g.state.stepsToday` (main.js L3435-3436).
  Отладочный вход: `g.actions.enterDungeon(terrain)` (L3611, 000068 — не
  требует пещеры; тот же `debugEnterDungeon`, что мирской вход).
* HUD: строка «День: N | …» рисуется КАЖДЫЙ кадр (hud.js buildLine) — день
  игроку виден и в подземелье (000212: в подземелье #hud поднят над
  оверлеем). В городе #hud под оверлеем (000212 «город — вне скоупа»).

## 3. Контракты и границы (что именно меняется)

1. Каждый успешный шаг героя ВНУТРИ подземелья или города =
   `clock.addStep(1)` на тех же мировых часах. Счётчик непрерывен между
   миром/подземельем/городом: войдя с 39/40, первый шаг внутри закрывает
   день ВНУТРИ локации (onDay-цепь — полная, режим-независимая).
2. Точки вставки — ровно две, обе в src/main.js (проводка, домен
   locations.js остаётся чистым — паттерн мира L3355):
   * `dungeonOnMove` (L2571): после `if (!ev) return;` (L2576), ПЕРЕД
     `if (ev.type === 'combat')` (L2579): `clock.addStep(1);` — накрывает и
     'moved', и 'combat' (D2/D3).
   * `cityOnMove` (L2613): хвост — вернуть `const ev =
     G.locations.cityMove(...)` (сейчас return-значение игнорируется,
     L2635-2636) и `if (ev) clock.addStep(1);` (cityMove возвращает только
     `{type:'moved'}` | null — мобов в городах нет).
3. НЕ тикает: стена/граница/inCombat (null), [E]-переходы (D4), бой (D5),
   входы (вход = мировой шаг, уже тикает в frame; шаг, при котором герой
   входит в тайл входа, — мировой), портал (000075), выход из города (D6).
   Выход из подземелья — по-прежнему +1 день (D1).
4. Детерминизм: addStep — без RNG; onDay-эффекты — seed'ы от АБСОЛЮТНОГО
   дня (payWages `hash2(day, npcId)`, contentValid) — детерминированы;
   goldens (map/cities/dungeon/combat) не трогаются; wanderStep — свой
   счётчик, от дня не зависит.
5. Ограничение (не дефект): в городе игрок смену дня НЕ видит (#hud под
   оверлеем, 000212) — кандидат в UI-задачу (§7).
