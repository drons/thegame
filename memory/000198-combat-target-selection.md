# 000198 (доп.) — Контракт выбора цели в бою (пересекающий)

Второй (краткий) файл 000198: сквозной контракт `c.targetId` — как его
выбирают, кто уважает, что рисуется. Основной контракт —
`memory/000198-ally-target-select.md` (карта изменений, решения D1–D10,
тесты, подводные камни). Задача 000198 — баг-фикс: на ходу союзника
(наёмник/Эфир — ход игрока, 000168 D9) клик по мобо НЕ менял цель
(D6-гварда `c.selectTarget` «только игрок», master 7875568 L3079) и ядро
союзных действий ИГНОРИРОВАЛО targetId (nearestEnemy — 000168 OQ1).

## 1. Единственный источник цели — `c.targetId`

- `c.targetId` — id юнита из `c.units` (МОБ) или null (авто-цель игрока:
  «вы»). Runtime-only: НЕ в формате сейва, сбрасывается на старте боя/
  раунда (startCombat L3007/L3025, startRound L2550 — `nearestMob(c)`;
  вход в союзный слот — advanceQueue L2597 — `nearestEnemy(c, u)`).
- УСТАРЕВАНИЕ легально: цель может умереть/сбежать (c.targetId НЕ
  очищается в dealDamageToMob — по дизайну, 000166 строка «— мёртв»).
  HUD: живой c.targetId →
  «Цель: <имя> (ур. n, HP a/b)»; МЁРТВЫЙ СОЮЗНИК = c.targetId →
  «Цель: <имя> (ур. n) — мёртв» (000166); мёртвый МОБ = c.targetId →
  «Цели нет»; c.targetId=null + мёртвый игрок + canResurrect → «Цель:
  <имя> (вы) — мёртв» (000166). (combat-ui.js L1451-1504.)
- Правило согласованности (основание D1 000198): когда HUD показывает
  «Цели нет» (мёртвый/флид c.targetId), ДЕЙСТВИЕ с этой целью отказывает
  «нет цели» БЕЗ расхода пулов и БЕЗ авто-переадресации — игрок щёлкает
  новую цель. (До 000198 игрок-путь так и работал; теперь — и союзный.)

Выбор цели — НЕ действие: пулы/мана/лог не тратятся; дальность НЕ

## 3. Кто УВАЖАЕТ c.targetId (потребители)

| Потребитель | Резолв |
|---|---|
| Игрок: playerAttack (L1230), playerSpell (L1283), canDoAction (L1495/L1521) | `targetId ? find : nearestMob(c)`; невалидная (мёртв/fled/союзник/нет) → «нет цели» (СТРОГО, без fallback) — исходный паттерн, зеркало для 000198. |
| Игрок: книга (G.Spells.castSpell, spells.js) | c.targetId; движок evalSpell фолбечит в nearestMob (от ИГРОКА) — путь игрока, 000198 не трогает (000193 — см. §5). |
| Союзник (000198): allyStrike (L1982), efirCastAction (L2064), allyCanDo (L2102/L2143) | **allyTarget(c, u, targetId)**: явная валидная (живой, !fled, side 'mob') → она; явная невалидная → null → «нет цели» (СТРОГО — D1); без аргумента → nearestEnemy(c, u) (v1-бит-в-бит). 0 c._rng. |
| UI: кольцо #ffe27a (L1126-1130), штриховка 000175 (L1287-1313), строка «Цель:» (L1451-1504), тханки (L670-671), canDo (L1542/L768) | Читают c.targetId БЕЗ гвард активного юнита — следуют за выбором автоматически (000198: 0 правок UI). |

Причины отказов — дословно, порядок проверок — закреплён (000037,
000168-CANDO): attack/Касание — checkTurn → цель → пул → дальность;
каст Эфира — checkTurn → c.efs → strongestKnown → пул → мана → цель →
дальность (4). «Цель слишком далеко (ближний бой)/(даль 4)/(дальность
4)».

## 4. Инварианты (проверять в будущих правках боя)

1. Страница/действие с невалидной ЯВНОЙ целью — «нет цели», пул НЕ
   сгорает, fallback на ближайшего НЕТ (HUD и ядро согласованы).
2. Вызов без аргумента — nearestEnemy/nearestMob — старые пины зелёные.
3. 0 новых c._rng в целевой резолюции (чистый поиск).
4. c.selectTarget — только игрок/живой союзник; слот моба — null.
5. UI-клик — единственный путь выбора цели в бою (кнопок/клавиш выбора
   цели НЕТ); выбор бесплатен.
6. support-heal (H) — без цели (авто-«самый раненый», 000168 P8).
7. c.targetId — runtime-only; сейвы/детерминизм-пины не затрагиваются.
