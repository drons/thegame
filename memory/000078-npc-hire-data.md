# 000078: слой данных найма спутников — закреплённые решения

Задача: слой ДАННЫХ найма (JSON source of truth + закрытая схема +
sync + JS-зеркало, паттерн 000053/000057/000058) + минимальная
проводка действия «найм». Родитель — 000065 (memory/000065-companions-plan.md).

## Контракт данных (зафиксирован тестами tests/npc-data.test.js)

* Имена полей найма — родительский контракт 000065 (SPEC «Спутники»):
  `{цена, жалованье, роль, dmg, hp, armor?, skills, spells}`.
  Смешанная номенклатура СОХРАНЯЕТСЯ (dmg/hp/armor/skills/spells —
  НЕ урон/броня/заклинания): 000079/000083/000085/000087 читают эти поля.
* `роль` — enum `melee | ranged | shield | support` — роль СОЮЗНИКА;
  НЕ путать с вражеской `'leader'`/hasLeader (п.6 плана 000065).
* `dmg`/`hp` — МНОЖИТЕЛИ в формулах `makeMob` (как `MOB_TYPES.dmg/hp`
  в src/combat.js): на этом строится 000080 (makeAlly) и 000082 (рост
  статов по формулам makeMob). `armor` — целое как у MOB_TYPES.
* `skills`/`spells` — ОБЯЗАТЕЛЬНЫЕ массивы id (могут быть ПУСТЫМИ:
  мел-наёмник без заклинаний — `spells: []`). skills — id каталога
  skills (основные И вторичные), spells — id каталога spells
  (assets/spells; CATALOGS в assets-schemas.test.js spells не
  покрывает — целостность spells проверяется tests/npc-data.test.js
  через src/spells-data.js SPELLS_BY_ID).
* Наём — ТОЛЬКО в таверне (постройка 44, генерируется, map_index 11);
  наёмники — новые файлы assets/npc/000012… (сквозная нумерация от
  000011). Таверна id 22 — школа Харизмы, НЕ использовать.
* Экономика (мягко; финальный баланс — золотой сценарий 000087):
  контракт 30..150 з (квест у Берты даёт ~50), жалованье 1..6 з/день.
* id существующих NPC НЕ переименовывать (сейв-ссылки 000029/000031).

## Развязка двусмысленности «кандидаты для building 44 (все имеют найм)»

* «Кандидаты» = NPC с найм-данными; ВСЕ они — в building 44
  (`постройки: [44]`), ≥5 штук, у каждого — найм-ОПЦИЯ диалога,
  покрытие ВСЕХ 4 ролей (по одному минимум, роли могут повторяться).
* ТАВЕРНЩИК (Берта, assets/npc/000009.json) найм-ДАННЫХ НЕ получает
  (она не наёмник). Но она получает найм-ОПЦИЮ диалога
  ({действие: «найм»}) — ИНАЧЕ вкладка недостижима в игре: main.js
  открывает диалог таверны с ПЕРВЫМ NPC каталога на постройке
  (npcForBuilding → npcsForBuilding[0] = Берта), новые наёмники [E]
  не выбирают. Аддитивно: id не меняются, сейвы не затрагиваются.
  Тест-фиксация: «доступность найма: ПЕРВЫЙ NPC каталога таверны
  (44) имеет найм-опцию диалога» (tests/npc-data.test.js).

## Проводка (src/npc.js, src/ui.js)

* `dialogOptions` — функционально НЕ меняется: действие НЕ читается,
  требования = доступ к найму (паттерн Оратора). Тест-фиксация
  (зелёная с первого запуска) — tests/npc.test.js «действие «найм»
  проходит через dialogOptions».
* Новый API ядра: `hireCandidates(npcs)` — справочная функция
  (раздел «Справочные» src/npc.js): `npcs.filter((n) => n && n.найм
  && typeof n.найм === 'object')` — только найм-данные (без
  building-фильтра: целостность «все в 44» держит тест каталога),
  порядок = порядок переданного массива (каталога), детерминированно
  (ссылки), мусор (null, найм-не-объект) отфильтрован. Стабильный API
  для 000079 (candidatesForTavern) и 000083.
* src/ui.js — ТОЛЬКО блок Game.npcUI: 5-я вкладка `['hire', 'найм']`
  в ряде вкладок; `renderHireTab()` — ЧИТАЕМЫЙ список из
  `G.hireCandidates(Game.NpcData.NPCS)`: строка .cp-itemrow,
  .cp-itemname — имя, .cp-itemmeta — роль/контракт/жалованье;
  в onOverlayClick (ветка opt): `o.действие === 'найм'` →
  `tab = 'hire'`; в renderTab — ЯВНАЯ ветка `else if (tab === 'hire')`
  (цепочка заканчивалась `else renderQuestsTab()` — без явной ветки
  «найм» тихо рисовал бы квесты). rng НЕ вводится (отказ найма —
  000079, seed = perlin.hash2(day, npcId)). Кнопки «нанять»/
  «уволить» и блок «Отряд» — 000083.
