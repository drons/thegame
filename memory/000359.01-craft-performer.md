## Семантика исполнителя (главный контракт)

Единая формула: **навык / XP / мана — активного листа; инвентарь /
исходники / книги-манускрипты (покупка-расход) / золото — Флогистона
(героя).**

- НАВЫК-сторона (src/craft.js): craftLevel, craftCap, qualityMult,
  qualityChance, yieldChance, craftBonus, addCraftXp, isTypeLearned,
  книга рецептов (perf.spells), мана зачарования — читаются/мутируются
  на perf = исполнитель.
- ИНВЕНТАРЬ-сторона (контракт 000194): hasItem/addItem/capacityCheck
  (слоты/вес/выходной слот) — всегда на герое c.
- ЗОЛОТО — герой (прецедент 000359 D5 «казна партии — герой»; у merc/
  Эфира поля gold нет).
- Резолв ДВУХСЛОЙНЫЙ: API src/craft.js принимает opts.performer
  (валидированный объект → perf, иначе perf = c — hero-фолбэк прямо в
  evalCraft); сам пикер читает craft-ui.js resolvePerformer(h), который
  ДЕЛЕГИРУЕТ единому helper Game.buildingEffects.craftExecutor(h)
  (000359) — если есть Game.LearnTarget.activeSheet → activeSheet(h),
  иначе h (fallback D2: без пикера — прежнее поведение, bit-identical;
  при отсутствии модуля buildingEffects в craft-ui — тоже h, это тот же
  D2: headless-цепи без building-effects.js пикера не несут). craft.js
  про LearnTarget НЕ знает — исполнитель
  приходит параметром (юнит-вызовы craftLevel/isTypeLearned принимают
  лист напрямую).
- craft-ui.js резолвит исполнителя ПРИ ОТКРЫТИИ окна: open() →
  resolvePerformer(h), close() обнуляет. Смена активного листа при
  открытом окне исполнителя НЕ переключает (окно = снимок).
- craft.scroll (изучение типа по книге, items.js useItem/useQuickUnit):
  зеркало spell_scroll 000147 — `const LT = (learnTarget объект и не
  массив) ? learnTarget : c;` изучение на LT, расход книги с c. Трёх-
  аргументные вызовы bit-identical (LT = c).

## Мана зачарования — вариант А (дизайнерское решение, зафиксировано)

Мана — ЛИЧНЫЙ ресурс листа. Лист без числового mp (спутники, Эфир) →
зачаровательные рецепты недоступны: «не хватает маны (N)». Код-гейт
fail-closed: `typeof perf.mp !== 'number' || perf.mp < spell.мани`
(typeof отсекает NaN-отравление — прецедент castOutOfCombat). Обоснование:
в SPEC.md/задачах нет механизма «пула маны партии»; mana — поле листа
(000045 canCastSpell с c.mp); вводить общий пул = менять боевой контракт
ради крафта. Вариант Б (мана героя для чужого навыка) отвергнут: mixing
личных ресурсов двух персонажей в одном действии без текстов ТЗ.
Побочный эффект варианта А: спутник-зачарователь без маны крафтит всё,
КРОМЕ зачарования; Эфир — тоже (у efir.mp есть число? — нет: efir-лист
не несёт mp ⇒ Эфир зачаровать не может; это осознанно и запинено T3/T8).
