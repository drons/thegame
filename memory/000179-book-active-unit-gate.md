## 2. Решения openQuestions (зафиксировано — не пере-решать)

### 2.1 Вариант фикса: ТОЛЬКО гейт (без автозакрытия книги) — почему

ТЗ: «гейт в castRow/rowChk; **и/или** закрывать книгу при смене активного
юнита (endTurn/advanceQueue)». Выбран «только гейт»:
* (а) КРАСНЫЙ ТЕСТ ТЗ требует КЛИКА ПО СТРОКЕ на ходу спутника — при
  автозакрытии книги на endTurn новых строк на ходу спутника в DOM нет
  (renderBook при `bookOpen=false` — только display='none' + return, без
  перестроения) — сценарий ТЗ невозможен.
* (б) Оркестратор требует: гейт срабатывает И в rowChk (disabled + tooltip
  НА ХОДУ СПУТНИКА), И в castRow (стаб-клик = отказ). Строки -off видны,
  только если книга открыта на ходу спутника — автозакрытие делает rowChk-
  половину гейта неobservable.
* (в) Вариант «оба» сделал бы rowChk-гейт мёртвым кодом (дублирование без
  покрытия) и добавил бы UI-хук в `endTurn`-тханк runAction — в том же
  thunk живёт drain-код 000174 (startMoveAnims) — лишний контакт-хотспот.
* (г) UX-последовательность с 000171: кнопка «Воскрешение» на ходу союзника
  НЕ прячется, а гаснет (disabled + tooltip) — строки книги тем же
  паттерном: видны, затемнены, tooltip. «Одно действие — одно поведение».
* (д) bookOpen — модульно-локальная closure-переменная combat-ui.js (L144):
  из ядра (endTurn/advanceQueue в combat.js) сброс невозможен без нового
  API на c — новый интерфейс ядра за рамками ТЗ («не больше и не меньше»).

### 2.2 Хелпер `spellbookUnitGate(c)` — порядок проверок ФИКСИРОВАН

```js
function spellbookUnitGate(c) {
  if (c.result) return { ok: false, reason: 'бой закончен' };
  if (c.phase !== 'player') return { ok: false, reason: 'не ваш ход' };
  const id = (typeof G.activeUnitId === 'function')
    ? G.activeUnitId(c) : 'player';
  if (id !== 'player') {
    return { ok: false, reason: 'недоступно активному персонажу' };
  }
  return null;
}
```
Зеркало порядка `resurrectChk` 000171 (L1648-1662: result → phase →
activeUnitId → canCastSpell). Почему именно так (по одной строке на пункт):
* **`c.result` ПЕРВЫМ** ('бой закончен' — тело checkTurn): все пути
  result-установки (checkVictory L1172, death L1026, flee L1385) ставят
  `phase='over'` одновременно/раньше — причина совпадает с текущей
  (canCastSpell → checkTurn) БИТ-В-БИТ; «бой закончен» важнее любой другой
  причины.
* **`phase` ПЕРЕД `activeUnitId`** ('не ваш ход' — тело checkTurn): на ходу
  МОБА `activeUnitId(c)` возвращает id МОБА (c.turnOrder[c.turnIndex]) —
  гейт-первым дал бы «недоступно активному персонажу» вместо «не ваш ход» —
  ровно тот дефект неверного tooltip, который 000171 зафиксировал
  комментом к порядку resurrectChk (L1645-1647). На ходу моба (сущ.
  состояние: фаза синхронная, рендера нет) причина остаётся БИТ-В-БИТ.
* **typeof-guard с фолбэком `'player'`**: `G.activeUnitId` — экспорт 000167
  (combat.js, ленивое чтение в момент вызова — паттерн resurrectChk;
  закреплён пином index-order); фолбэк = поведение до 000167: гейт мёртвая
  ветка, ноль изменения.
* **строка «недоступно активному персонажу» — ДОСЛОВНО** из
  `allyCanDo('spellbook')` (combat.js L2175-2177, 000168) и
  `resurrectChk` L1661 (000171) — переиспользование той же строки
  предписано ТЗ/оркестратором (контракт «одна строка — одна причина»
  для player-only действий на ходу союзника).
* **Гейт ПЕРЕД canCastSpell/deградацией в rowChk** (выбор a1 §2.2): на ходу
  СОЮЗНИКА причина — гейтовая, даже без G.Spells (осмысленнее деградации);
  на ходу ИГРОКА гейт null → деградация 'Заклинания недоступны' БИТ-В-БИТ
  (пин SB14). Явных result/phase-пинов строк НЕТ (проверено grep в a2) →
  порядок безопасен.

### 2.3 castRow — единый источник доступности строки

гейт + тот же движок — паттерн 000037/000045 «одна причина — одно
поведение». Стаб-клик (смена состояния между рендером и кликом — паттерн,

трат НЕТ, `c._fx` не пишется, очередь не сдвигается.
