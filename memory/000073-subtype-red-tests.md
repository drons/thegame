# 000073: подтипы слотов 8..12 — стадия красных тестов (TDD)

Статус: КРАСНЫЕ ТЕСТЫ готовы (коммит «Задача 000073: красные тесты»).
11 RED-тестов падают до реализации; остальные 1109 — зелёные.
Дочерняя к 000064 (эффекты «особых» построек), P1.

## Фиксированные решения (зафиксированы тестами — смена = перепин)

* **SUBTYPE_SEED_CONST = GLOBAL_SEED ^ 0x53554254** (ASCII «SUBT»;
  прецедент CITY_SEED_CONST = GLOBAL_SEED ^ 0x43495459 «CITY»,
  map.js:185). Отличен от GLOBAL_SEED, CITY_SEED_CONST,
  GLOBAL_SEED ^ 0xabcdef. hash2-пины (tests/map.test.js):
  hash2(12345,−6789)=3791884486; hash2(0,0)=1381530846;
  hash2(−120,33)=126326031; hash2(7,41)=52607510.
* **Правило слотов (единое, зафиксировано тестом subtypeFor):**
  подтипы ЕСТЬ только на слотах 8..12 (buildingId = id выбранной
  записи: базовая или подтип каталога); **слоты 0..7 → buildingId
  null** («как есть», golden не ломается); слот вне 8..12 → null.
  (Кандидат «все слоты получают id базовой» отвергнут:
  минимум изменения мира.)
* **Порядок кумуляции долей (зафиксирован реализацией, распределяется
  golden-пинами):** записи [базовая + подтипы] в порядке
  **возрастания id**; доля базовой = остаток (100 − Σдоля подтипов);
  u = hash2(x,y,SUBTYPE_SEED_CONST)/2^32; кумулятивно; хвост —
  последняя запись (наибольший id). Невалидная конфигурация
  (остаток ≤ 0, нет базовой/каталога) → null (деградация:
  buildingId null, мир как до задачи).
* **Таблица размещения** (assets/buildings,
  особые_параметры.размещение {слот, доля}; ТЗ):
  * слот 8: 37×10, 38×10, 39×10; базовая 36 (остаток 70);
  * слот 9: 48×20; базовая 31 (80);
  * слот 10: 41×15, 42×15, 43×15; базовая 40 (55);
  * слот 11: 45×15, 49×25; базовая 44 (60);
  * слот 12: 46×30; базовая 25 (70).
  У базовых записей (36/31/40/44/25) поле размещения НЕ ДАВАТЬ.
  У подтипов map_index НЕ ДАВАТЬ (13 слотов не меняются).
* **Слот 9 — сознательное изменение геймплея:** ~20% тайлов
  перестают быть входами в подземелье (развалины 48 — постройка).
  Гард maybeEnterDungeon — строго `t.buildingId === 48` (НЕ
  `!== 31`: при buildingId==null вход обязан сохраняться —
  fail-open; vm без каталога). HUD-хинт «(вход — шагните)» подавлен
  для 48 ПАРОЙ с гардом (иначе игрок «входит» в развалины).

## Измерения (до реализации, детерминированы)

* Чистый хэш (окно 512×512 координат, 262144 выборок/слот):
  максимум отклонения от каталожных долей = **0.138 п.п.** → допуск
  теста ±2 п.п. стабилен.
* Размещённые якоря (реальный map.png, окно ±256; ~130–150 якорей
  на слот): максимум отклонения = **8 п.п.** (слот 9: 72% вместо 80)
  → допуск теста ±10 п.п. (±2 п.п. статистически недостижимо).
* **generateSeedPixels() ≡ assets/map.png ПОБАЙТОВО** (seed 20260926,
  256×256): «фолбэк-мир» vm-тестов main.js — тот же мир.
* Цели main.js-тестов от спавна (0,0), BFS-правила файла
  city-screen (проходимый, без групп мобов; промежуточно — без входов
  пещер/городов): **развалины (2,−4) — глубина 5**; храм-подтип
  (50,3) → 38 (якорь [49,1], 3x3) — глубина 54.
