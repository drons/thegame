# 000430 — purify на себя / mass_holy_light снимают c.ps.debuff

## Что реализовано (дельта — ровно 2 строки в src/spells.js)

- Ветка `purify` («лечение», `spellId === 'purify'`) в `castSpell`: в
  else-ветке (само-каст, `t` нет) добавлено `c.ps.debuff = null;` — перед
  прежними `out.purified = null` и логом. Логи обеих веток побитово прежние
  («дебаф с … снят.» у цели / «Очищение: очищено.» у себя); `out.purified`
  для игрока остаётся `null` (пин spells.test.js W-12a «игрок-цель — без
  side-effects» по `purified`/`healed`/hp инертен: `null = null`).
- Блок `if (spellId === 'mass_holy_light')` внутри `PARTY_HEAL_IDS`:
  `c.ps.debuff = null;` ПЕРЕД циклом союзников — очистка героя НЕ зависит
  от наличия живых альясов (мутация M8 «внутри цикла» краснит T3). Новый
  лог не введён: масс-кано́н чистит союзников молча, строка одна —
  «Массовый святой свет: +N.».
- Канон ветвления — «регенерация» (`if (t) … else c.ps.…`, 000420/000235.01):
  снятие СЛОТА ЦЕЛИКОМ (`= null`), а не по stat — зеркало `t.debuff = null`
  у союзника-цели и `a.debuff = null` у массы. Писатель слота один (web
  «ход_вниз», 000420) ⇒ семантика идентична при любой форме снятия.

## НЕ тронуто (контракты)

- `c.ps.debuff` — слот и его тики в `startRound` (combat.js): тик
  `if (c.ps.debuff && c.ps.debuff.turns > 0)` по `null` — no-op без throw
  (пин T2 второй части).
- Потребитель очереди `buildTurnOrder` (`SLOW_INITIATIVE_PENALTY`,
  000235.08.01) — переписывать было запрещено; возврат позиции — автомат
  гейта «штраф, пока запись с `turns > 0` на момент сборки очереди»:
  purify/mass чистят слот ⇒ уже `buildTurnOrder(c)` в РАУНДЕ каста даёт
  игрока по чистой инициативе, а `c.turnOrder` пересобирается на границе
  раунда (в текущем раунде очередь не пересобирается — тесты пинуют
  чистый `buildTurnOrder` + очередь следующего раунда, НЕ «текущий
  c.turnOrder сразу»).
- `c.ps.poison` (яд — отдельный слот, purify его не снимал никогда),
  `c.ps.bind`/`c.ps.buff`, веб-писатели 000420, leader-блоки 000425,
  сейв-формат (c.ps — боевые транзиенты). `c.ps.debuff` у союзника-цели
  purify не трогает (T4).
