# 000017: кнопка полноэкранного режима

Статус: выполнено и закоммичено (тесты 141 → 149 pass).

## Решения

* **Ядро — src/fullscreen.js** (униформный модуль, как day.js):
  `createFullscreenController(doc)`. Детект поддержки — первый вариант,
  где у documentElement есть request-метод: стандартный
  `requestFullscreen`, затем вендорные `webkit`/`moz`/`ms` (и их
  exit/element/event-названия). Состояние `isFullscreen` перечитывается
  из документа при каждом обращении — отражает внешние смены
  (выход по Esc). `toggle()/enter()/exit()` глотают и отклонённые
  Promise, и синхронные броски API (экзотические среды, iframe без
  allowfullscreen) — игра не падает. `onChange(fn)` подписывается на
  `*fullscreenchange` у document, `destroy()` снимает подписку.
* **DOM-привязка — src/main.js** (как и положено, вне ядра): кнопка
  `.fs-btn` в правом нижнем углу, подпись «⛶ полный экран» /
  «⛶ выйти из полного экрана», обновляется через onChange. API
  недоступен — кнопка не создаётся, игра работает как раньше.
* **z-index 15**: выше панели персонажа (10), ниже оверлеев
  боя/подземелья (20) — не мешает в бою.
* Ядро не в ui.js: ui.js — браузерно-только (в шапке «не тестируется
  в node»), поэтому отдельный файл по паттерну day.js/player.js.
* Новая клавиша не добавлялась: выход из полного экрана — Esc/F11
  браузера, состояние синхронизируется через fullscreenchange.

## Тесты

tests/fullscreen.test.js: 8 тестов с мок-документом (4 варианта API) —
детект поддержки (стандарт + все вендорные), безопасный no-op без API
(включая null-документ), toggle и подписчики, синхронизация по
внешнему fullscreenchange, webkit-фолбэк, отклонённый request,
синхронный DOMException в request, destroy.
