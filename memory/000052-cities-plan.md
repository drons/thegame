## Ключевые решения (зафиксированы в SPEC и подзадачах)

1. Город = постройка-вход, 4 типа: хутор 1x1 / деревня 2x2 /
   город 5x5 / столица 7x7 (ОДИН размер на тип; диапазоны
   4x4–5x5/6x6–7x7 закрыты верхней границей; новые размеры —
   новые записи каталога). id 50 (мост/ворота) — НЕ элемент
   внутреннего города (остается резерв 000064).
2. Размещение — городской канал в anchorAt (свой hash +
   редкость по шуму/альфе), ПЕРЕД слотовым hash; 13 слотов и
   `hash % 13` НЕ меняются; тип/размер — из позиции+шума;
   размещение — существующий пайплайн (000026). Мир меняется:
   золотые пины map.test.js перепинываются СОЗНАТЕЛЬНО
   (000103).
3. Вход/выход — dungeonState.kind 'dungeon'|'city', экран —
   dungeon-ui (режим «город»), общий движок 000066. РЕШЕНИЕ:
   день на входе/выходе НЕ проходит (clock.event не вызывается;
   в отличие от подземелий). dungeon_memory_days не применим.
4. Содержимое — детерминированно от ПОЗИЦИИ (seed hash2
   якоря), не от totalXp; существующие типы каталога (квоты —
   `особые_параметры`); таверна в каждом городе; взаимодействие
   ТОЛЬКО через buildingUI (000071) + npcUI, обход — запрет
   тестом.
5. Лавки — стоки по (город, клетка) (makeShop с офсетом; wealth
   якоря). Сейв — data.cities (v1 неломко; обрезка просроченных;
   city_respawn_days — global-settings; слой 000072).
6. Визуал — footprint через 000042 (расширение на 7x7), новые
   SVG по 4 типам (город не слот), HUD-имя (название_карты).
