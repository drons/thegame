# Конфликты номеров задач между ветками worktree

## Ситуация

Все 4 ветки worktree (task/map, task/main, task/data, task/design)
отбиты от 5b59806 (ДО мержа task/combat) и независимо создали
задачи с ОДИНАКОВЫМИ номерами 000032–000035 для разных содержимых.
При мерже в master это даёт конфликты add/add в
tasks/pending/NNNNNN.md.

## Правило разрешения (применено при мерже task/map)

1. Номера MASTER сохраняются (trunk стабилен; уже отсылаемые
   задачи не переименовывать).
2. Новые задачи ветки получают свободные номера (не заняты на
   master И не заявлены другими известными ветками), в файле
   задачи — пометка «была №NNNNNN в ветке …, перепривязана при
   мерже».
3. Обновить кросс-ссылки (tasks/result, memory).

## Вывод для будущих мержей

Перед мержом любой ветки: сверить tasks/pending ветки с
актуальным master; новые номера брать от следующего свободного
на master, а не «как было в ветке». После мержа — проверить
кросс-ссылки на перепривязанные номера (grep по старому номеру
в tasks/ и memory/).

## Ренумерация задач пользователем на master (прецедент 2026-10-06)

Пользователь перемешал номера файлов задач на master МЕЖДУ триажем
оркестратора и запуском workflow (батч 000148–000160: порядок
изменился; HACKING.md ушёл в 000160, барьер-сплит SPEC — в 000159,
A* — в 000155, кнопки [I]/[E] — в 000150, ассеты наёмных — в 000152,
управление Эфиром — в 000154, текстуры боя — в 000151).

Поведение workflow при расхождении «номер запуска ≠ номер файла»
(зафиксировано design-стадиями, все мержи прошли чисто):
задачу выполняет содержимое ФАКТИЧЕСКОГО файла tasks/pending/NNNN.md
(если бриф оркестратора соответствует другому файлу — по брифу,
файл ищут по содержимому); ВСЕ артефакты (коммиты «Задача NNNN: …»,
.merge-pending, git mv pending→done, tasks/result/, memory/) — по
фактическому master-номеру; worktree/ветка сохраняют номер запуска.
Прецеденты: запуск 000151 → задача 000160; запуск 000152 → задача
000155 (A*); запуск 000154 → задача 000150 (кнопки).

Для оркестратора:
* Перед запуском волны — СВЕЖАЯ сверка номер→содержимое
  (head tasks/pending/*.md); номерам из старых триажей не верить.
* Запускают только те номера, файлы которых СОДЕРЖАТ нужную задачу;
  worktree/ветка = фактический номер задачи (имя не занято).
* Если два workflow сходятся на одной задаче (по файлу или брифу) —
  остановить тот, что на более ранней стадии, и запустить
  пропавшую задачу под её фактическим номером (случай: A* 000155
  дублировалась запусками 000152 и 000155; более ранний по стадиям
  остановлен, текстуры запущены как 000151).
