## 3. Контракты и границы

### 3.1 Элемент — `<button>` (решение станции; почему НЕ div и НЕ таблица)
* **НЕ div** (вариант a2): настоящий `<button>` — точное исполнение ТЗ
  («визуальный элемент для нажатия»), нативный tap→click, браузер гасит
  клики по disabled, a11y (focus/role) — всё бесплатно; div требовал бы
  новый CSS-блок в index.html (чужой общий файл) + модульную переменную
  с ручным сбросом в finish().
* **НЕ запись в COMBAT_KEYS** (вариант a3): табличная кнопка появилась бы
  у ВСЕХ героев (вечно disabled «неизвестное действие» без ветки
  canDoAction в ядре) → 6 ре-пинов (7 штук/000124/combat-keys×2/
  spellbook/svg) + новая клавиша + новый SVG — всё вне ТЗ («не больше и
  не меньше»; прецедент 000168 D10 «кнопок новых НЕТ»).
* Гейт `canResurrect(c)` (000166, бит-в-байт) в build() — кнопка создаётся
  ТОЛЬКО если носитель (unitOf = c.player) знает 'resurrect'. Дефолтный
  герой (sheet.js L134: ['spark','mend']) → кнопки НЕТ → все существующие
  сцены бит-в-байт: «7 штук» (L260-276), 000124-пин (L1089-1122),
  000168-UI-2 (master) — зелёные БЕЗ РЕ-ПИНА (спящий пин — паттерн 000166).
* Прецеденты вне-табличного click-управления: строки книги (000149 R9 —
  div, осознанный выбор) и 000168 (thunk'и cast/heal + ветки KeyH/KeyK в
  keydown — вне застывшей таблицы combat-keys.js).

### 3.2 Гашение — resurrectChk(c) (ПОРЯДОК ПРОВЕРОК ФИКСИРОВАН)
```
1. c.result                    → 'бой закончен'          (как в строке
                                                          disabled цикла)
2. c.phase !== 'player'        → 'не ваш ход'            (checkTurn, дословно)
3. G.activeUnitId(c) !== 'player'
                               → 'недоступно активному персонажу'
                               (строка 000168 allyCanDo дословно — та же,
                                что пинит 000168-UI-2; typeof-guard —
                                фолбэк 'player')
4. G.Spells.canCastSpell(c, 'resurrect',
     { targetId: resurrectTargetId(c) }) — ДОСЛОВНО (внутри evalSpell:
     checkTurn/checkBlocked → 'блок — только последнее действие' →
     пул → 'действий «Заклинание» (Мудрость) больше нет' →
     'не хватает маны (15)' → 'нет цели'); без G.Spells —
     'Заклинания недоступны' (строк-фолбэк rowChk, 000149).
```
Почему гейт 3 обязателен: с 000168 на ходу СОЮЗНИКА `c.phase === 'player'`
— checkTurn evalSpell его от хода игрока НЕ отличает (в ядре каста
phase-гвард больше нет); без гейта клик на ходу наёмника/Эфира кастовал
'resurrect' ИГРОКА за ману/пул игрока (000163: castSpell тратит c.ps/p.mp).
До 000168 гейт 3 — мёртвая ветка (activeUnitId === 'player' всегда на
ходу игрока) → ноль изменения поведения, работает и до, и после ребейза.
Порядок 1→2 ПЕРЕД 3: на ходу моба (phase 'mob') причина честная
«не ваш ход», а не «недоступно…».
Зачем спец-кейс в цикле render вместо G.canDoAction:
canDoAction('resurrect') → «неизвестное действие: resurrect» (combat.js
L1579) → кнопка ВЕЧНО disabled с неверным tooltip.

### 3.3 Эффективная цель — resurrectTargetId(c)
```
t = c.targetId; if (!t) return null;
u = c.units.find(x => x.id === t);
return u && u.side === 'ally' && !u.alive && !u.fled ? t : null;
```
Явный выбор 000166 (клик по клетке мёртвого СОЮЗНИКА) уважается; любая
другая цель (живой моб — начальная авто-цель начала хода, чужой id) →
null → автоцель ядра (000163 R-1/R-2: мёртвый ИГРОК приоритетно, иначе
ПЕРВЫЙ мёртвый союзник в порядке c.units; дальности нет). БЕЗ этой
валидации кнопка отвечала бы «нет цели» в типичном мобильном сценарии
(c.targetId = живой волк) — баг остался бы жив. Это и есть «ОДИН тап =
воскрешение». resurrectChk (шаг 4) передаёт canCastSpell ТО ЖЕ
resurrectTargetId(c) — не сырой c.targetId (иначе кнопка была бы disabled
«нет цели» до тапа по клетке мёртвого союзника, хотя цель есть).

### 3.4 Каст — resurrectCast(c) (ЗЕРКАЛО castRow, НО c.targetId НЕ СЫРОЙ)
```
chk = resurrectChk(c); if (!chk.ok) { logRejection(c, chk); render(); return; }
r = G.Spells.castSpell(c, 'resurrect', resurrectTargetId(c))
    (без G.Spells — 'Заклинания недоступны');
r.ok → c._fx = {action:'cast', until: nowMs()+FX_MS}; bookOpen = false;
       иначе logRejection(c, r); render().
```
* Предпроверка (первая строка) — зеркало 'spellbook'-thunk (runAction
  L429-438): стаб-клик (vm: b.listeners.click[0]() работает и при
  disabled) / смена состояния между рендером и кликом → причина в журнал,
  КАСТА НЕТ, трат НЕТ (пин CU171-ALLY/EFIR — без неё клик на ходу
  наёмника кастовал бы за игрока).
* НЕ castRow напрямую: castRow передаёт сырой c.targetId (→ «нет цели»
  на одном тапе) и не имеет предпроверки.
* Ход НЕ сгорает (каст ≠ endTurn — паттерн книги 000149/000166).
* bookOpen=false при успехе — зеркало castRow («действие сделано»);
  книга остаётся открытой при отказе (игрок видит причину).
* 0 новых c._rng (воскрешение без RNG, 000163), 0 новых полей c
  (c._fx/c.targetId — runtime-only; формат сейва не тронут).
* Отдельной модульной переменной кнопки НЕТ: элемент живёт в DOM
  оверлея (finish() снимает overlay.remove(), L1421) — идентичность по
  dataset.act; сбрасывать нечего (в отличие от bookBox).

### 3.5 Тач
Тап по `<button>` = нативное click-событие — ровно как у 7 существующих
кнопок панели (у них только click-слушатели). НОВЫХ pointer-обработчиков
НЕТ (pointerdown дал бы двойное срабатывание). D-pad (controls.js
touchKeyCode L304) шлёт только 4 направления + KeyE — в кнопку не лезет.

### 3.6 «Окно смерти» 000164 (решено)
Поведение кнопки определяется гейтом автоматически: окно/спасение
держат phase 'player' + activeUnitId 'player' → кнопка АКТИВНА, тап =
rescue-каст (автоцель — мёртвый игрок приоритетно) — совпадает с
механикой спасения 000164; фаза другая → disabled с причиной. Отдельного
теста НЕТ (мёртвый игрок в живом бою недостижим вне окна; приоритет
автоцели пинит саб CU171-AUTO).

### 3.7 НЕТ (границы scope, «не больше ТЗ»)
Новой клавиши (комбат-клавиатуру закрывают книга KeyQ + D-pad/7 кнопок;
D-pad новую клавишу и так не выразит — touchKeyCode; прецедент 000168 D10),
нового SVG, CSS, script-тега, модуля, экспорт Game, полей сейва, правок
combat.js/spells.js/combat-keys.js. Ручное воскрешение Эфиром кнопкой —
НЕ v1 (SPEC-механики нет; роль Эфира — авто-спасение в окне смерти 000164).
