# 000383 — Кочевник и лагерная барахолка: единый сток лагерной точки

Задача: tasks/done/000383.md (F2 из 000345, ретро-b22 P6). Ветка — А
(унификация через третью живую ссылку по образцу 000345).

## 1. Обоснование выбора ветви А (зафиксировано ДО кода)

1. F2 — ровно тот же класс дефекта, что закрыл 000345 для магазинных
   тайлов: у одного NPC витрина диалога («купил весь хлеб») и барахолка
   [I] («хлеб есть») расходятся. memory/000345 §3 прямо отложил это
   «отдельной задачей» — задача наступила. Ветвь Б консервировала бы
   UX-расхождение как контракт, хотя расхождение здесь — побочный
   эффект отсутствия третьей ветви в shopFor, а не осознанный дизайн
   (в отличие от деградации №2 «полка vs прилавок»).
2. СТРУКТУРНЫЙ ВОПРОС ОТВЕЧЕН ПОЛОЖИТЕЛЬНО: тайлы лагеря ловятся
   единым каналом БЕЗ правки предикатов респавна. Диалог в мире всегда
   резолвится на тайле ВХОДА (map.js: «hasBuilding — только на тайле
   ВХОДА: магазин/пещера/диалог NPC работают именно там»;
   t.x/t.y === позиция игрока в мире) ⇒ тот же ключ 'x,y', что у [I]
   (hud.js и building-effect-camp.js оба зовут campShopFor(t.x,t.y,t)).
   campShopFor — ЕДИНСТВЕННЫЙ решатель ленивой ротации
   (campStockDueRefresh, respawn_days каталога 47) и уже возвращает
   ЖИВУЮ ССЫЛКУ entry.stock. Диалог просто переиспользует его ⇒
   «респавн по дню» (000095) не ломается ничем: items.js 0-diff,
   сиды 0-diff, голдены A57/B26/B27/camp-е2e не двигаются, сейв-
   раздел campStocks уже персистит списания.
3. Каталогочная семантика кочевника сохраняется там, где она
   персональная: обёртка { npc, stock } несёт npc ⇒ tradeEntry /
   npcBuy / npcSell / npcBuyPrice работают по каталогу 000018 с
   множителями Кочевника. «Прилавок персонален», «витрина = каталог ∩
   полка» — ровно деградация №2 000345, уже принятая проектом.
4. Цена ветви А минимальна: 4 строки в src/main.js (разрешённый
   SCOPE shopFor-хунков) + переписанный B29 + line-neutral spec.
   Формулировка гарда НЕ пересекается с иглами S5/S8 000345
   (S5/S8 — ноль правок, проверено прогоном файла).

## 2. Механизм

src/main.js shopFor, порядок ветвей город → мир → ЛАГЕРЬ → каталог:

    if (!ds && t && t.hasBuilding && t.buildingId === CAMP_ID && npc
        && npc.торговля && Array.isArray(npc.торговля.предметы)) {
      const cs = campShopFor(t.x, t.y, t);
      if (cs) return { npc, stock: cs.stock };
    }

* Живая ссылка на entry.stock (покупка в диалоге = npcBuy мутирует
  in place ⇒ campStocks['x,y'] списывается, [I] показывает остаток,
  сейв пишет campStocks — третья живая ссылка после cityShops
  (000107/000108) и worldShops (000345)).
* Fail-open: campShopFor null (каталог 47 без «виды» / record null) ⇒
  прежний каталожный канал; NPC без торговли ⇒ прежний null-путь.
* Подземелья/города не затронуты: гард `!ds`, город резолвится
  первым; лагерей в подземельях нет.
* Гард с `t.buildingId === CAMP_ID` намеренно разрывает непрерывность
  подстроки `t.hasBuilding && npc` — S5-игла мирской ветви
  (indexOf/regex точных формулировок) остаётся единственной; форма
  гардов 000345 не менялась вовсе (прямое требование ТЗ).
* campShopFor-вызов с (t.x, t.y, t) — тот же решатель и тот же
  ленивый refresh, что у [I]; респавн-предикат 000095 для диалога
  теперь правда «лагерь — по дню» (spec/npc-storage.md строка 83
  усилена, не переписана).

## 3. Принятые следствия

* blueprint_woodwork (чертёж столярного дела из каталога Кочевника) НЕ
  входит в виды лагеря [food,potion,weapon,armor] ⇒ строка «купить»
  у Кочевника исчезла НАВСЕГДА (у мирских магазинов — временное
  отсутствие по полке). Предмет obtainable: дроп troll + сундуки
  castle_ruins; ПРОДАЖА чертежа Кочевнику работает (tradeEntry без
  стока). Каталог (assets/) вне SCOPE задачи — candidate followup
  «blueprint_woodwork в виды лагеря» двигает camp-голдены 000095
  (A57/B26/B27/items) — отдельная задача (не плодить дочерних под
  000383).
* Витрина кочевника ротируется вместе с полкой (возможен день, когда
  пересечение каталог∩полка пусто — пустая вкладка «Магазин», не
  крах; совместимо с 000314 «нет строки при qty<1» и «строка
  возвращается при регенерации стока (лагерь — по дню)»).
* Смена дня при ОТКРЫТОМ диалоге ⇒ осиротевший stock (списания в
  никуда до перезахода) — принятая деградация №1 000345, для лагеря
  с respawn_days=1 заметнее.
* Sell-сторона диалога (npcSell) сток НЕ пополняет — BUY-ONLY полки
  000095 сохранён (костыль «продал Кочевнику хлеб — барахолка
  пополнилась» отсутствует по построению).
* Legacy-ключи 'camp_wanderer@W:x,y' в чужих сейвах после мержа —
  инертны (restore пишет их в npcStocks, для лагерного тайла никто
  не читает) — прецедент 000345 для магазинных тайлов.
