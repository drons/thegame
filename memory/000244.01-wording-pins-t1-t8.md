## 3. Ключевые решения

1. **T8 — ОДИН кавычный needle «недоступно», НЕ contiguous-фраза.**
   Вариант ТЗ/ретро «сплошная contiguous-фраза «нет погибших / отряд
   полон / недоступно»» НЕВЫПОЛНИМА: в тексте spec (L326-329) между
   «отряд полон» и «недоступно» стоит скобка «(roster + dead >
   max_companions, дефолт 3)» — includes() по нормализованному срезу =
   false; фактическая contiguous-форма дублировала бы уже запиненное.
   Одиночная кавычная фраза — точный паттерн существующих двух
   needle-отказов T8 («нет погибших», «отряд полон» — тоже с «»).
   Сuggestion ретро «(contiguous в SPEC)» — неточен.
2. **Счётчик = 70 = число ВЫЗОВОВ phrase() (positive-needle), НЕ 71.**
   Сырой `grep -c "phrase("` считает СТРОКИ и включает строку
   определения `function phrase(slice, label, needle, why) {` (L154):
   до правки 68 строк при 67 вызовах, после — 71 строка при 70.
   Формула ТЗ «(grep -c phrase())» буквально не срабатывает;
   ретро-конвенция считает needle-вызовы (само ретро пишет
   «grep -c phrase() = 67»). Формула для ре-счёта:
   `grep -o "phrase(" tests/spec-000244-wording.test.js | wc -l` − 1.
   История: 63 (красная стадия 000244) → 67 (+4 review-needle
   display-имён flame_step/firelight/hearthfire/frozen_stillness,
   ревью 000244-rv, шапку тогда не обновили) → 70 (+3 из 000244.01).
3. **Шапка: замена числа + 3 строки-уточнение.** Чистая замена 63→70
   оставила бы строку «ВСЕ 70 positive-needle отсутствуют в текущих
   срезах» без базы красноты для 3 новых needle (на HEAD они ПРИСУТСТ-
   ВУЮТ — тест зелёный; шапка — снапшот красной стадии, «эта стадия,
   все срезы на HEAD»). Уточнение: +3 needle — T1 «enterLocation (если
   бой НЕ начался)» / «мана НЕ списана, перемещения нет», T8
   «недоступно»; краснота их — по срезу f2a508d^, не по HEAD. ТЗ
   разрешает править комментарий («Комментарий — ассерты не трогать»);
   ассерты — ноль правок. Фолбэк при строгой минималистике — только
   замена числа (не выбрано: шапка файла и так несёт длинные
   уточняющие блоки, L94-104).
4. **Позиция T1 — после `saveNow` (L194), ПЕРЕД `frost_walk` (L195).**
   Группирует пост-лендинг-цепь по тексту spec (L250-256: подземелье
   dungeonPostMove → saveNow; мир enterLocation → saveNow; мана-нюанс);
   needle frost_walk — о ЛУЧЕ (другая тема, в spec — до пост-лендинга) —
   остаётся в конце тела T1. Альтернатива (после frost_walk, конец
   блока) отвергнута: рвёт пост-лендинг-цепь луч-needle и расходится
   с порядком текста spec. Порядок assert'ов внутри тела семантики не
   меняет (все assert.ok независимы, без короткого замыкания) — позиция
   = читаемость/минимальный diff.
5. **Позиция T8 — после «отряд полон» (L339), ПЕРЕД flash (L340).**
   Три дословных отказа становятся соседними В ПОРЯДКЕ SPEC

6. **НОВЫХ test()-блоков НЕТ.** 3 needle — в существующие тела T1/T8 →
