Разборка — обратная операция к изготовлению: единица предмета из
инвентаря уничтожается, каждая исходная часть может вернуться;
успешный разбор даёт опыт виду крафта канонического рецепта.

## 1. Формула шанса (FIXED)

* p(L) = 20% + 70% × (L − 1) / 99, где **L = craftLevel(c, тип
  канонического рецепта)** (1…100, `craftLevel` craft.js:202:
  `(c.craft && c.craft[type]) || 1`). L=1 → ТОЧНО 0.2;
  L=100 → ТОЧНО 0.9; L=50 → 0.546464…
* Успех части: **ролл < p** (СТРОГОЕ неравенство; ролл == p — провал),
  паттерн qRoll/yRoll (craft.js:739-756).
* НА ЧАСТЬ — ОДИН независимый `rng()`-вызов, В ПОРЯДКЕ
  `recipe.исходники` (порядок закреплён тестом D3).
* При успехе возвращается ПОЛНОЕ `количество` позиции исходника
  (sulfur ×2 → 2 шт.); возвращённые части — ОБЫЧНЫЕ предметы (без
  бонусного качества).
* JS-форма: `(20 + 70 * (L - 1) / 99) / 100`. НАИВНАЯ `0.2 +
  0.7 * (L - 1) / 99` при L=100 даёт 0.89999… (IEEE754: 0.2+0.7 ≠
  0.9) → красный тест «p(100) = 0.9 ТОЧНО» был бы бит; в знаменателе
  70 * 99 / 99 = 70 точно, (20+70)/100 = 0.9 точно.
* SPEC-запись (канон ×/−): `20% + 70% × (L − 1) / 99` (знак × —
  канон 000296/buildings.md:473).
* Чисто (без rng, без мутаций): `disassemblyChance(c, itemId)` →
  число; нет канонического рецепта → 0.

## 2. Маппинг предмет → канонический рецепт (FIXED)

* Канонический рецепт = **базовый (без поля `база`)** рецепт с
  **МИНИМАЛЬНЫМ `уровнем`** среди рецептов с тем же результатом;
  при равенстве — **первый по порядку каталога** (CRAFT-индекс:
  при строго меньшем уровне замена, при равенстве первый остаётся).
  Рецепт с `база` каноническим НИКОГДА не бывает.
* Выводится ПРИ ЗАГРУЗКЕ из зеркала CRAFT (прецедент TYPE_BUILDINGS
  craft.js:173-177 «выводится из зеркала, не хардкод») как
  константа `DISASSEMBLY_BY_ITEM` = {itemId: recipeId}, экспорт.
* Проверенные факты по каталогу (node-прогон по src/craft-data.js,
  база 52a9041; снэпшот — дрейфует при изменении assets/craft,
  см. §10):
  * 343 рецепта, 6 видов; результат — 298 из 511 предметов каталога;
  * канонических с `база` — 0;
  * НЕСКОЛЬКО базовых рецептов на один предмет — ровно 2:
    - iron_sword (items/000002) → `iron_sword` (000001,

    НЕ «stone»/«silver_ore» — опечатки а1/a3 исправлены).

## 3. Опыт (FIXED)

* Каждый УСПЕШНЫЙ разбор: `addCraftXp(c, recipe.тип, 10 +
  recipe.уровень, false)` — ТОЖНАЯ формула практики изготовления
  (craft.js:719); потолок практикой (craftCap = связанный навык × 2,
  CRAFT_TYPE_SKILL craft.js:149-156) в силе: на потолке applied 0,
  reason «потолок практикой»/«максимальный уровень», копилка
  не растёт, `c.craft[тип]` НЕ ставится.
* Опыт даётся независимо от числа возвращённых частей (даже если
  «ничего не вернулось»); при ОТКАЗЕ (canDisassemble не ok) опыт не
  даётся и роллы не расходуются.
* КРИТИЧЕЕ РАЗЛИЧИЕ: p использует **уровень ВИДА** (craftLevel),
  а XP — **`уровень` РЕЦЕПТА**. Для iron_sword у L_вида=1: p=20%,
  но XP +12 (рецепт L2). Не смешивать в тексте/тестах.
* НЮАНС СВЕЖЕГО ГЕРОЯ (проверено node): fresh createCharacter() →
  secondary={} → для видов со связанным SECONDARY-навыком (кузн. →
  forge) cap = 0 → applied 0, копилка 0, isTypeLearned ОСТАЁТСЯ
  false. «Первый разбор делает вид изученным» (D0b) верно ТОЛЬКО
  если связанный навык ≥ 1 (cap ≥ 2). Для столярное_дело (sвязан
  primary dexterity=1 у fresh) cap 2 — XP применяется. Это паритет
  с craft() (свежий герой и в крафте получает applied 0), не
  особенность разборки; D12-фикстура — герой со связанным навыком ≥
  1.

## 5. Прочие решения

* **Д-ГЕЙТ**: разборка НЕ требует изученности вида (гейт 000232
  «вид не изучен» — только evalCraft). Обоснование: разборка —
  ИСТОЧНИК прогресса; опыт делает вид изученным по D0b (прогресс =
  знание); паритет с mentorCraft/bookCraftXp (гейтом не
  ограничены). В SPEC — как осознанное следствие (с оговоркой про
  потолок, §3).
* **Д-АТОМАРНОСТЬ**: disassemble = canDisassemble (зеркало) → роллы
  → dry-run ёмкости → снапшот slots+quick + restoreInventory →
  мутации → restore при ЛЮБОМ отказе (двойная страховка, паттерн
  craft.js L683-696). Ёмкость — ХУДШИЙ СЛУЧАЙ (ВСЕ части
  возвращаются) на ТЕКУЩЕМ инвентаре (предмет ещё не снят —
  консервативно): если худший случай проходит, mid-mutation отказ

## 7. API и код (зелёная стадия)

src/craft.js (ОДИН файл ядра, НОВЫХ МОДУЛЕЙ/скриптов НЕТ):
* `DISASSEMBLY_BY_ITEM` — константа при загрузке (блок рядом с
  TYPE_BUILDINGS ~L173-177), из CRAFT; экспорт.
* Функции ПОСЛЕ yieldChance (~L756), ПЕРЕД «--- Сейв ---» (~L758):
  `disassemblyRecipeFor(itemId)` → recipe|null (чисто);
  `disassemblyChance(c, itemId)` → число (чисто, без rng);
  `canDisassemble(c, itemId)` → {ok, reason?} (зеркало: 1) нет
  рецепта → «предмет нельзя разобрать»; 2) !c.alive → «персонаж
  погиб»; 3) !hasItem(c, itemId, 1) → «нет предмета в инвентаре»;
  4) ёмкость худшего случая → «нет свободных слотов инвентаря» |
  «слишком тяжело (лимит веса)»);
  `disassemble(c, itemId, opts)` → {ok:true, item, type,
