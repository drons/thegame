## 1. Формат ссылки (контракт подзадач 000211.02–.08, 000207/208/209, волна 2)

* Ссылка — строка: путь к целевому JSON-файлу ОТНОСИТЕЛЬНО корня репозитория:
  `"assets/<каталог>/<файл>.json"` (каталог с именованными файлами —
  portraits: `"assets/portraits/npc-000012.json"`).
* `id` целевого файла === прежнее ссылочное значение. Тип id — строка:
  items, craft, npc, skills, spells, mobs, portraits; числовой:
  buildings, dungeons, mob_groups (visuals — числовой, но не цель ссылок —
  вне якорного паттерна).
* Якорные паттерны — ЕДИНЫЙ источник: `REF_RE` / `PORTRAITS_RE` в
  scripts/lib/json-ref.js (verbatim):
    `^assets/(items|skills|spells|mobs|mob_groups|buildings|craft|dungeons|npc)/\d{6}\.json$`
    `^assets/portraits/(efir|flogiston|npc-\d{6})\.json$`
  visuals ВНЕ паттерна — единственный каталог прямых svg-путей (прецедент
  формата: assets/visuals/000001.json «спрайт»:
  "assets/sprites/visuals/grass_blades_light.svg", 13/13).
* Почему путь к файлу, а не id (контракт 000211 §2, пункты а–д):
  (а) dungeons — в файле 000001 id = 0 (id ≠ номер файла);
  (б) portraits — именованные файлы (efir.json, flogiston.json, npc-NNNNNN.json);
  (в) формат единый для всех 11 каталогов;
  (г) прецедент в проекте — assets/visuals уже хранит прямой путь;
  (д) file:// — fetch невозможен (000053) → резолюция только в sync
      (время сборки), не в рантайме.
* Запекание: sync-*.js резолвит ссылки в id при сборке; JS-зеркала
  ОСТАЮТСЯ в id-форме (контракт потребителей Game.ITEMS / MOB_TYPES /
  SPELLS / getBuilding… + сейв v1 — id предметов, 000031: «id предметов
  НЕ перенумеруются»). Ссылки существуют ТОЛЬКО в json и в схемах.
* Схемы: после миграции поле-ссылка закрепляется `pattern` (якорный
  паттерн); новое поле = расширение schema.json в ТОМ ЖЕ коммите
  (additionalProperties:false — 000141; молчаливо красная валидация иначе).

## 2. scripts/lib/json-ref.js — API (Node-only, БЕЗ UMD)

* Node-only CommonJS по конвенции scripts/lib/write-atomic.js
  (`'use strict'`, `module.exports`, только node:fs/node:path, без
  внешних зависимостей — package.json без deps). НЕ UMD: UMD-инварианты
  серии (снапшот Game один раз — 000038, ленивые ссылки rootRef в момент
  вызова) относятся к МОДУЛЯМ src/ последующих подзадач; здесь — lib для
  Node-тестов. `<script>`-тегов в index.html НЕТ (ТЗ §1; пин tests/
  index-order.test.js, audit §7.9 «новых скриптов НЕТ»); все 44 vm-цепочки
  из index.html — без изменений.
* Экспорт (поверхность фиксируется тестом AR1):
    REF_RE, PORTRAITS_RE — якорные паттерны (§1).
    REF_CATALOGS — 11 каталогов общего sweep: items, skills, spells, mobs,
      mob_groups, buildings, craft, dungeons, npc, visuals, portraits.
    isRef(v) → boolean — v строка И совпадает с одним из паттернов.
    resolveRef(root, ref) →
      `{ ok: true, id }` |
      `{ ok: false, reason: 'not-a-ref' | 'no-file' | 'not-json' | 'no-id' }`
      — БЕЗ бросаний (структурный результат: 3 отрицательных случая ТЗ
      различимы по reason — иначе тест не отличит «не-JSON» от «без id»).
      Порядок проверок: isRef → файл существует И isFile (statSync) →
      JSON.parse (JSON-объект) → `'id' in data` (hasOwnProperty).
      root — позиционный, ОБЯЗАТЕЛЕН, дефолта НЕТ: негативные фикстуры
      изолируются в mkdtemp tmp-корне; чужой файл в assets/ сломал бы
      тест «чужих файлов нет» в assets-schemas.
      «Содержит id» — hasOwnProperty, НЕ truthiness: у
      assets/dungeons/000001.json id = 0 (falsy) — резолюция ОБЯЗАНА
      пройти (`{ok:true, id:0}`).
    collectRefs(value) → `[{ path, ref }]` — ВСЕ строки под якорным
      паттерном во вложенной структуре; ЧИСТЫЙ walker без fs.
    collectSvgs(value) → `[{ path, svg }]` — ВСЕ строки, начинающиеся
      `"assets/"` И заканчивающиеся `".svg"`; ЧИСТЫЙ walker без fs
      (проверку существования делает тест, не резолвер).
  Стиль путей — как where в tests/json-schema.js: верхний уровень —
  голые ключи, массивы `[i]`, объекты `.k` → «loot[0].item»,
  «art.move[0]» (mobs: loot[].item, skills[], spells[]; art — не строка
  ссылки, а объект путей — collectRefs его не трогает).
* Границы — резолвер НЕ делает (и почему):
  * не сверяет id === прежнее значение — тесты подзадач (контракт §1;
    подзадачи сами потянут collectRefs и сравнят id с прежним значением
    из зеркала/старых данных);
  * не валидирует схемы — дело tests/assets-schemas.test.js;
  * не проверяет существование svg — collectSvgs только собирает,
    existsSync — в общем тесте;
  * не ищет svg-строки не в форме «assets/…» — см. §3 (скоуп sweep).

## 3. tests/assets-refs.test.js — правила общего теста (9 node-тестов, НИ ОДНОГО vm)

* 11 каталогов — REF_CATALOGS из json-ref.js (единый источник со sweep).
  Перечисление файлов: portraits — ВСЕ *.json (8 именованных: efir,
  flogiston, npc-000012…npc-000017; в каталоге НЕТ schema.json),
  остальные 10 — `/^\d{6}\.json$/` (schema.json исключён: sweep —
  ДАННЫЕ файлы; в схемах regexp-строки, якорных строк в них 0 — проверено,
  но исключение — принцип, не удача).
* Sweep ссылок: каждая строка под якорным паттерном (рекурсивно, через
  collectRefs) → resolveRef ok (файл существует, парсится, содержит id).
  Сейчас таких строк 0 → тест зелёный с первого коммита и служит ГЕЙТОМ
  всех последующих миграций (000211.02–.08, 000207/208/209: после
  миграций — 45 ссылок в skills и ссылки mobs/dungeons/spells/mob_groups).
* Sweep svg — ПРАВИЛО (ТЗ: «решение исполнителя зафиксировать в memory»):
  проверяются ТОЛЬКО строки «assets/…*.svg» ОТНОСИТЕЛЬНО корня репозитория
  (collectSvgs + fs.existsSync(path.join(root, svg))). ГОЛОЕ имя svg
  (8 иконок portraits «icon»: efir.svg … npc-000017.svg) — ВЫНЕСЕНО из
  скоупа sweep, поднимется в ВОЛНЕ 2 (миграция portraits: npc↔portraits
  ссылки + schema.json — тогда добавляется правило для локальных имён).
  Почему: (1) единое правило «только root-абсолютные пути» не зависит от
  каталога-носителя — sweep прост и стабилен; (2) не закрепляет локальную
  конвенцию portraits, которую волна 2 переделывает (иначе sweep
  переписывался бы второй раз); (3) все потребители sweep (000211.06 —
  "assets/sprites/loot/<id>.svg", 000211.07 — спрайты buildings,
  000211.08 — кадры mob_groups) добавляют именно root-пути.
  (Альтернатива «иначе → каталог носителя, 218/218» отклонена — см. выше.)
* Отрицательный контроль (ТЗ) — резолвер ошибается с верным reason:
  * битый путь — реальный root, файл под паттерном, но не существует:
    СЧИТАЕТСЯ ДИНАМИЧЕСКИ (максимальный номер items + 1; сейчас
    000077.json, items 76) — не хардкод, устойчиво к росту каталога →
    reason 'no-file';
  * не-JSON файл — mkdtemp tmp-корень (os.tmpdir, 'assets-refs-',
    структура assets/items/000001.json, cleanup в finally) → 'not-json';
  * файл без id — tmp-корень, валидный JSON-объект без верхнеуровневого
    id → 'no-id';
  * 'not-a-ref' — "assets/visuals/000001.json" (visuals вне паттерна) и
    "fists" (id, не путь).
* Ленивая загрузка модуля (в каждом тесте свой require/existsSync-гард):
  в RED-фазе (json-ref.js отсутствует) каждый из 9 тестов падает со
  СВОИМ осмысленным сообщением (MODULE_NOT_FOUND/ENOENT), а не одним
  file-level падением — RED-план станции a3 (expectedRedCount = 9).
* Анти-вакуумность (sweep не может «прогнать 0 файлов и засчитать»):
  AR2/AR3 — явные isRef (+/−) на реальных примерах; AR9 — закреплён
  прецедент: «спрайт» assets/visuals/000001.json
  "assets/sprites/visuals/grass_blades_light.svg" обязателен в результате
  sweep (файл существует — прецедент закреплён).
* Тест НЕ пиннит КОЛИЧЕСТВО ссылок/svg (0 сейчас, 45+ после миграций) —
  только «все резолвятся / все существуют».
