# 000030: модернизация экрана боя — план (разложение на подзадачи)

Статус: выполнено (проектирование; код и ассеты не менялись).
Подзадачи: 000032–000038 в tasks/pending.

## Решения

* Экран боя: ядро — src/combat.js (чистое, node-тестируемое, весь RNG
  через c._rng — бой детерминирован по сиду); UI — src/combat-ui.js
  (browser-only, canvas 7×7 клеток по CELL=48 px + side-панель).
  Все подзадачи выдерживают границу «ядро/UI»: логика — в ядре,
  отрисовка — в UI.
* Порядок хода: игрок первым, затем ВСЕ живые мобы в порядке массива
  c.units (endPlayerTurn). Семантика не меняется; 000036 делает её
  наблюдаемой (buildTurnOrder/turnOrder/turnIndex).
* Мобы в бою: 36 типов (MOB_TYPES), но спрайтов только 6 базовых видов
  (MOB_FRAMES в sprites.js) — 000032 вводит mobSpriteKind(mobId).
* Бой начинается: (а) на проходимых тайлах мира — SAND/GRASS/FOREST/
  HILL/SWAMP (вода/горы непроходимы); (б) в подземельях — DUNGEON_TYPES
  CAVE/CRYPT/RUINS/DROWNED/ABYSS (тайла мира нет). Отсюда 11 фонов
  боя (000034): 5 террейнов + 5 подземелий + fallback; main.js уже
  передаёт tile в startCombat (terrain = tile.terrain).
* «Препятствия на фоновом SVG» (направление 4) истолковано как SVG-
  спрайты поверх ОБЩЕГО фона, а не как уникальный SVG на каждый бой:
  детерминированно (c._rng), дёшево, фон переиспользуется. Вариант
  «генерировать SVG по сиду» — fallback, если вид будет хуже.
* Клавиатура: найден конфликт KeyA (бой: «Удар», мир: движение влево).
  Решение: WASD/ЦФЫВ в бою = движение как в мире, «Удар» → J,
  единая таблица в новом UMD-модуле src/combat-keys.js (000033).
  main.js в бою ранним return'ит — конфликтов с миром/диалогом NPC нет.
* Найден баг (фикс в 000037): playerSpell('heal') логирует общее HP —
  P.heal возвращает c.hp, а не восстановленное количество.
* Найден «мёртвый» путь (000037): кнопка «Предмет [T]» всегда падает
  на «выберите предмет из инвентаря» (c.invItem() без itemId, UI
  выбора нет) — пока только корректный дизейбл.
