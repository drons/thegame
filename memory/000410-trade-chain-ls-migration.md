## 1. Формула (по ней живут торговые волны 000320.37+)

- Ссылки торговли (`trade`/`entries`), торгующие (`traders`), уникальные
  торгуемые (`traded`/`unique`) — ls-полы: `assert.ok(n >= ПОЛ,
  '<что> — ls-пол ≥ ПОЛ (миграция 000410; …); факт: ' + n)`.
- Пол = число диска на финальной базе станции. Волны пол НЕ поднимают и
  НЕ опускают; краснеет только при удалении входов ниже пола
  (анти-вакуум). Подъём числа волной пол не трогает вообще.
- Вместо точного счётчика синхронность держит кросс-зуб: витрина по
  каталогу `assets/npc/*.json` ≡ зеркалу `src/npc-data.js` (по числу
  входов и по числу торгующих). Забытый `sync-npc-data.js` красит ровно
  этот зуб, а не числовую цепочку.
- Размеры свитковых витрин — ВЫВОД из ростера школа→продавец
  (`SCROLL_SELLER_SCHOOLS` в 000347.01, `SCHOOL_SELLER` в 000347.02 —
  это ростер контракта 000347.02, не счётчик) по дисковому каталогу
  `spell_scroll`. Новые свитки волны кладут в школу — витрины и свипы
  пересчитываются сами.
- Титулы тестируемых имён: движущиеся числа запрещены; канон
  «каталог — ls-предикат: 000001..N подряд (N = счётчик диска); зеркало
  NPCS ≡ каталогу» (000387.01) в T6 .02 сохранён без изменений — его
  читают наборщики игл.
