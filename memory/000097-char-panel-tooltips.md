## Архитектура (текущее состояние, для 000098/000100/000101)

* **Строка навыка** (все 6 основных + все 31 вторичный): в конец <tr> —
  ОТДЕЛЬНАЯ ПУСТАЯ `td.cp-tipcell` с `div.cp-tip` (один текст-нод).
  Почему отдельная ячейка: render() каждый раз переписывает
  textContent .cp-name/.cp-level/.cp-req, а запись textContent в
  ячейку с детьми убрала бы .cp-tip. render() пересчитывает текст в
  ТОМ ЖЕ узле.
* **skillTipText(id, c)** — только из каталога: основное — desc +
  «В бою: <combat>» + «В мире: <world>» + «Требование: —»;
  вторичное — desc + «Эффект: <effectType> (<stat> <perLevel> за
  уровень)» + «Уровень: <титул>» (names[] через G.secondaryName;
  lvl = 0 — базовое имя, артефакт rankOf(0) из player.js НЕ
  дублируем) + «Требование: <тот же текст, что в .cp-req, или —>».
* **Строка предмета**: itemRow(name, meta, buttons, **tip**) —
  АДДИТИВНЫЙ 4-й аргумент. .cp-tip только у ЗАПОЛНЕННЫХ строк:
  снаряжение (оружие/броня), быстрые слоты, инвентарь. Пустые строки
  и СТРОКИ МАГАЗИНА — без .cp-tip (магазин — зона 000101; там те же
  .cp-itemrow, клик по ним ничего не делает).
* **itemTipText(it)** — desc + строка kind: weapon «Урон: N»,
  armor «Броня: +N», effect heal|mp|eat «Эффект: +N HP/MP»,
  skill_xp «Эффект: +N опыта (имя навыка)»; у реагента (effect
  отсутствует) строки «Эффект» нет; + «Вес: N кг» + «Цена: N з».
* **Touch-fallback** (hover на таче нет): ТРЕТЬЯ ветка одного
  делегированного click (после .cp-tab и .cp-btn): клик/тап по
  не-кнопочной части строки — closest('.cp-itemrow') ||
  closest('tr'); есть .cp-tip с текстом → полное описание в
  .cp-notice (существующий flashNotice). Постоянная компактная мета
  (.cp-itemmeta/.cp-req) не убрана. Новые кликабельные элементы
  добавлять ДО ветки строк (паттерн .cp-tab/.cp-btn).
* **CSS (index.html, hunk после .cp-btn)**: .cp-tip скрыт по
  умолчанию (opacity:0 / visibility:hidden / pointer-events:none —
  не перехватывает курсор и клики), position:absolute, z-index 11,
  bottom:calc(100% + 4px), min-width 180 / max-width 300,
  white-space:pre-line (текст склеивается '\n' — в DOM-стабе
  textContent детей не учитывает), overflow-wrap:break-word. Показ —
  ЧИСТЫЙ CSS: .char-panel tr:hover/:focus-within .cp-tip и
  .char-panel .cp-itemrow:hover/:focus-within > .cp-tip.
  position:relative — ТОЛЬКО под .char-panel (.cp-tipcell —
  width:1px, padding:0; .cp-itemrow — relative): npcUI
  ПЕРЕИСПОЛЬЗУЕТ .cp-itemrow (оверлей NPC) — не должно попадать.
  z-index 11 — внутри stacking-контекста .char-panel (z-10);
  корневая лестница 5/10/15/20 — в root-контексте, не тронута.
