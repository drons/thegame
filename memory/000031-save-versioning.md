# 000031: сохранение — версионирование структур данных и миграции

Статус: выполнено и закоммичено (тесты 196 → 212 pass).

## Решения

* **`src/save.js`** — чистый UMD-модуль (браузер — `Game.*`, node —
  require), хранилище (localStorage) подставляется вызывающим.
  Оболочка сейва: `{ version, savedAt, data }`; версия — версия
  СТРУКТУР ДАННЫХ (data), записывается в хранилище.
* **Правило изменения структур:** «ломаете» data — поднимаете
  `CURRENT_VERSION` (в шапке модуля) и добавляете в `MIGRATIONS`
  функцию `N: (dataV_N) => dataV_N+1`. Цепочка применяется
  последовательно 1→2→… при `load()`. Неломкие дополнения (новые поля)
  версию НЕ поднимают.
* **Статусы `load(storage)`:**
  * `empty` — сейва нет;
  * `ok` — прочитан (возможно, промигрирован; `save.migrated === true`);
  * `corrupt` — битый JSON/оболочка (или getItem бросил): восстановить
    нечего;
  * `migration_failed` — миграция упала, миграция отсутствует в цепочке,
    либо сейв «из будущего» (version > CURRENT_VERSION) — поле
    `version` в ответе.
  При `corrupt`/`migration_failed` запись в хранилище НЕ меняется —
  решение об обнулении за UI.
* **UI (main.js):** `migration_failed` → console.warn + `confirm()`
  («данные восстановить невозможно, обнулить?»), `clear` — ТОЛЬКО после
  согласия; `corrupt` → тихий сброс + console.warn. Разделение двух
  режимов — это совмещение требований 000031 (согласие) и 000029
  (тихий сброс невалидного сейва): «невалидный» в 000029 = corrupt/
  невалидные поля, «миграция не удалась» в 000031 = migration_failed.
* **Payload v1:** `{ day, steps, position: {x,y}, hero }` — сознательно
  минимален; квесты/сток NPC (000029) добавятся полями без миграции.
* **Точки записи (saveNow):** шаг по миру, смена дня (onDay), конец боя
  (мир/подземелье), выход из подземелья, beforeunload. Отдельный флаг
  подавления записи во время восстановления НЕ нужен: restoreFromSave
  не вызывает saveNow (fastForward не оповещает слушателей, addStep
  клампится до порога дня, остальное восстановление чисто).
* **Восстановление (restoreFromSave, после загрузки карты):**
  * день — `clock.fastForward(target - clock.day)` (day.js): O(1),
    БЕЗ оповещения слушателей. Сейв — СНИМОК на момент записи: все
    эффекты прошедших дней (HP/MP-реген, респауны) уже учтены в данных,
    а `rest()` (day-1) раз рендерил бы панель (day-1) раз — сейв с
    day=100000 морозил браузер на десятки секунд.
  * верхняя граница дня — `MAX_SAVED_DAY = 1e9` (защита от подделанного
    сейва): день > границы КЛАМПИТСЯ (раньше day > 100000 молча
    сбрасывался на 1, и pruneQuestBookByDay(qb, 1) отбрасывал ВСЕ
    активные квесты — потеря прогресса легитимного сейва).
  * шаги сохранённого дня — `addStep(steps)` ВСЕГДА (включая день 1;
    раньше блок был вложен в `d.day > clock.day`, и {day:1, steps:35}
    восставал со steps=0).
  * hero — `G.sanitizeSavedHero` (player.js): ядро (level/xp/gold/hp/
    все 6 основных навыков) невалидно → null → console.warn, персонаж
    не восстанавливается; вторичные навыки/skillXp — посчётный отброс
    мусора (неизвестный id, нецелый/не-числовой уровень — раньше
    maxHP NaN). Инвентарь/снаряжение — `G.sanitizeInventory`/
    `G.sanitizeEquipment` (items.js): «призрак»-предметы (id удалён из
    каталога между сборками — сейв в localStorage переживает апдейты
    данных) и мусорные записи отбрасываются (раньше `null.weight` /
    `slots.reduce is not a function` в inventoryWeight роняли старт).
    Дальше clamp HP/MP по `derived`, `alive = true`.
  * `defeatedAt` (побеждённые группы, 'x,y' → день) сериализуется
    (day.js: serializeDefeatedAt/restoreDefeatedAt) — после перезагрузки
    группа респаунится через respawn_days, а не оживает мгновенно
    (SPEC «Игровое время»; раньше — фарм награды повторно в тот же день).
  * позиция — только если `map.tileAt(...).passable`, иначе спавн.
  * каждый раздел — свой try/catch, финальный `playerUI.render()` тоже
    в try/catch: невалидное поле — отброс + console.warn, игра
    не роняется (требование 000029 «битый сейв не роняет игру»).
* Тесты меняют `CURRENT_VERSION`/`MIGRATIONS` (общее состояние модуля) —
  обёртка `withVersions` в save.test.js возвращает исходное в finally.

## Тесты

tests/save.test.js — 16 тестов: roundtrip; corrupt (битый JSON, 9
форм некорректной оболочки); цепочка миграций 1→2→3 (порядок
проверяется логированием); ошибка миграции; пропущенная миграция;
сейв «из будущего»; хранилище не меняется при неудаче; квота/
исключения → false; clear (идемпотентно); getItem, бросаящий;
setCurrentVersion (только целое >= 1); браузерный путь UMD (vm-
песочница, не ломает существующий Game).

Правки по итогам ревью (000029/000031): tests/day.test.js — fastForward
(день доводится, шаги сбрасываются, слушатели НЕ вызваны; n<1/net
целое), serializeDefeatedAt/restoreDefeatedAt (roundtrip с
отрицательными координатами, отброс мусора); tests/player.test.js —
sanitizeSavedHero (битое ядро → null, посчётный отброс вторичных
навыков/skillXp, нормализация mp/points/name); tests/items.test.js —
sanitizeInventory/sanitizeEquipment (призрак-предмет, null-записи,
qty-клэмп, лимит слотов, не-объект → пустой инвентарь) + интеграционный
сценарий «битый персонаж из сейва не роняет старт».
