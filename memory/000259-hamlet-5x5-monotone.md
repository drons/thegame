## 2. Контракты и границы

* Таблица размеров (После 000259):

  | f | тип | layout | интерьер | потолок (floor(интерьер/2)) |
  |---|-----|--------|----------|------------------------------|
  | 1 | хутор | 5×5 | 3×3 = 9 | 4 |
  | 2 | деревня | 6×6 | 16 | 8 |
  | 5 | город | 18×18 | 256 | 128 |
  | 7 | столица | 26×26 | 576 | 288 |

  Монотонность интерьеров СТРОГАЯ: 9 < 16 < 256 < 576 (красный M1).
  Формула max(4f−2, 5) монотонна при любом f≥1 (1→5, 2→6, 3→10,
  4→14, 5→18, …, 13→50) — альтернатива «спец-кейс f===1» отклонена
  (ветка вместо одной строки; прецедент 000148.01 — однородное
  изменение формулы).
* Дверь (000177) — инвариант СОХРАНЁН: entrance = exit, южный
  периметр (y = H−1), ОДИН вызов rng. Единственный сдвиг — хуторская
  колонна: было x=0 (W=2, rng-вызова НЕ было); стало col = 1 +
  floor(rng()·3) ∈ 1..3 (W≥3). rng createCityLayout — ЛОКАЛЬНЫЙ
  (seed от позиции), не общий с миром/contents → других сдвигов
  потоков НЕТ. СЕЕДЫ без изменений (от позиции, не от размера):
  layout 2891528378 / 2117505400; contents 1811910784 / 2492498253.
* Застройка хутора — РАЗРЕШЕНА (решение, «вариант A»), НОЛЬ новых
  строк логики:
  * generateCityContents: при 5×5 spots = 9 интерьерных FLOOR
    (дверь на периметре — в spots не входит) → ранний возврат не
    срабатывает; count = мин_постройки + wealth = 0 + wealth;
    постройка 0 — ТАВЕРНА (доли {44:1} содержат 44 — tavernInPool),
    остальные — по долям (только 44 → все таверны).
  * canBuildAt: cap D4 — общая формула floor(интерьер/2) → 4
    автоматически; space — footprint ⊆ [1..W−2]×[1..H−2] (дверь
    (3,4) периметр — «заблокировать» невозможно); reach — общий.
  * мин_постройки = 0 и доли_типов {44:1} — ДАННЫЕ НЕ ТРОГАЕМ
    (изменение 0→1 — за скоупом ТЗ). Следствие (зафиксировано):
    хутор wealth 0 → buildings: [] (бит-в-бит как раньше);
    wealth ≥ 1 → таверны (w1: 1, w2: 2, w3: 3).
  * merge-цикл prepareCityState (main.js) — общий
    (footprint ⊆ интерьер, fail-open); у хутора в сейвах built-
    записей НЕ БЫВАЛО (интерьера не было) → миграции сейвов НЕТ,
    рост обратно совместим.
* Целое ≥ 1 — валидный footprint (валидация НЕ меняется); fp13 → 50
  (max(50,5)=50); CITY_SHOP_CELL_BASE=256 — покрывает (макс-индекс
  4·13−1=51) — без изменений.
