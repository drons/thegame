## 0. Корень (сверено с кодом)

Тайлы рисуются 2D-канвасом по-штучно, каждый `drawImage/fillRect`
растеризируется независимо. Координаты и размер — ДРОБНЫЕ в общем случае:
зум `80·1.2^k` (дробный уже со 2-го тика колёсика: 80·1.44 =
115.19999999999999) × камера-глейд 000033 (асимптотическая, дробная) ×
`viewW/2` (дробный при нечётном окне). На дробном стыке двух соседних тайлов
покрытие экранных пикселей суммарно < 1 (частичное AA-покрытие краёв), и в
шовный пиксель проступает фон ПОД слоем: тёмный — WebGL
`gl.clearColor(0.06, 0.08, 0.10, 1)` (src/main.js L3409; steady state = 0
вершин, 000176) под спрайт-слоем мира и `#0a0d12` (src/dungeon-ui.js L499)
под оверлеем подземелья/города. «Некоторые зумы» = ровно те, где проекция
стыка дробная. WebGL-слой щелей НЕ даёт (общие вершины в одном draw, MSAA).

Три точки отрисовки сетки (все — `G.worldToScreen`, map.js L1251):
* мир: текстура тайла `s2.drawImage(img, sx, sy, zoom, zoom)` — src/main.js
  проход 1 drawSprites (L3147), единственный вызов прохода;
* подземелье: пол `g2.drawImage(img, p.x, p.y, zoom, zoom)` (dungeon-ui.js
  L584) или фолбэк `fillRect(p.x, p.y, zoom, zoom)` '#182029' (L587);
* город: пол/стена `g2.fillRect(p.x, p.y, zoom, zoom)` (dungeon-ui.js L574).

## 2. Контракты и границы

Формула (единый источник — выражение worldToScreen, НИЧЕГО нового):
```
x[i] = Math.round(viewW/2 + (x0+i − camX)·zoom)   (тот же порядок операций,
y[j] = Math.round(viewH/2 + (y0+j − camY)·zoom)    что в worldToScreen —
                                               бит-идентично, поэтому
                                               Math.round(worldToScreen(…).x)
                                               в тестах = значению кода)
```
Ключевое свойство: КРАЙ — чистая функция от ЦЕЛОГО индекса клетки →
соседние клетки дают ОДИН И ТОТ ЖЕ общий край (нет дрейфа от поштучного
round), шовный пиксель 100% накрывается одной клеткой при ЛЮБОМ dpr —
AA на стыке не возникает, линии нет ни при каком зуме/камере/браузере.
Размер клетки w/h ∈ {⌊zoom⌉, ⌈zoom⌉}; сумма широт ряда = правый край −
левый край (сетка РАЗБИРАЕТ экран, не «лепестки»).

* ИДЕНТИЧНОСТЬ: при пиксельно-целых проекциях (целый zoom ×
  целая/полунцелая камера × чётный вьюпорт) снап = identity побайтово.
  Проверено вычислением на ВСЕХ существующих пин-сценариях: 800×600 @48
  cam(2.5,2.5), @40 cam(10,7.5), @42 cam(10,7.5), @40 cam(14,13.5), @20
  cam(13,13), @30 cam(9,9), @4 cam(1,1), @80 cam(0.5,0.5); 1280×720 @80
  cam(3,3) — 34411/34411 identity (TS-1, пин n >= 34000). Отсюда: ВСЕ
  существующие пины
  dungeon-ui (48/42/40/20/30/4/80, tol 1e-9), city-screen G1 (80, CAM 3),
  dungeon-vision (40, cam clamp (10,7.5)), spawn-кадры main-visuals
  (80, cam (0.5,0.5)) — БЕЗ ПРАВОК зелёные.
* Guards (зеркало worldToScreen, 000061): не-число/не-конечный аргумент,
  zoom ≤ 0, view ≤ 0 → `{x:NaN,y:NaN,w:NaN,h:NaN}` (rect) /
  `{x:[NaN],y:[NaN]}` (edges), БЕЗ исключения; edges дополнительно:
  целочисленные границы, x1 ≥ x0, y1 ≥ y0 (иначе [NaN] — длина массива
  из нецелого бросила бы исключение). Детерминизм: два вызова — побайтово.
* Границы применения:
  * МИР (main.js проход 1): снап — ТОЛЬКО текстура тайла. НЕ снапнуты:
    декорации/лут (visualDrawRect от сырых sx,sy — 000039/000158.05),
    постройки/города/лагеря (проход 2, w×h от якоря — 000042/000131/
    000110), агро-окружности (000172), мобы (000173), Флогистон.
    Почему постройки мира не снапнуты: они рисуются ПОВЕРХ текстур тайлов
    (под ними не тёмный фон → тёмных линий на их краях нет), а их сырые
    позиции уже ЗАПИНАНЫ в дробных post-walk-сценариях (main-visuals
    MV-C1/MV-C2, expectedBuildings, EPS 1e-6; global-map-draw RM-9(c)
    tol 1e-3) — снап сломал бы их без пользы.
  * ПОДЗЕМЕЛЬЕ/ГОРОД (dungeon-ui.js): снап — ВСЁ, что лежит ровно на
    сетке клеток (угол клетки, размер ~zoom): пол (оба режима), стена
    города, wallObjs, постройки города (1×1-клетка, 000106/000148.03),
    маркеры выхода/лестницы, туман-затемнение. Туман ОБЯЗАН идти снап-
    сеткой — иначе полупрозрачный слой сдвинут ≤0.5 px от снап-полос
    пола (светлые/тёмные полоски по границам исследованных клеток).
    НЕ снапнуты: сундуки/залежи (0.8×zoom, центр клетки — не угол
    сетки), мобы/босс, игрок (глитт-сущности, дробная точка глейда,
    EPS-пины 000067/000068).
  * WebGL-слой (buildFrame) НЕ ТРОГАЕТСЯ: 0 вершин в steady state (000176),
    межквадные швы невозможны (общие вершины). Вода: frameIndex(t) не
    меняется — фазы анимации снапом не задеты.
* visibleTileRange margin = 2 — без изменений: снап двигает край ≤0.5 px,
  запас 2 тайла накрывает с большим перебором.
* Производительность: world-хот-луп при ZOOM_MIN=4, 1920×1080 ≈ 131k
  тайлов/кадр — отсюда ВТОРОЙ экспорт (edge-массивы: (countX+1)+(countY+1)
  round'ов на кадр, O(1) на тайл). Измерено (node): поштучные вызовы
  хелпера на тайл ≈ 7.6 мс/кадр в худшем случае (НЕ принимать);
  edge-массивы — O(1) на тайл поверх существующего цикла (его стоимость
  задаёт drawImage). dungeon-ui — малые сетки (≤35×35) → per-cell
  snappedTileRect, без edge-массивов.
* Визуальный side-effect (осознанный): при дробном зуме ширины соседних
  тайлов чередуются ⌊zoom⌋/⌈zoom⌉ (±1 px) — на низкоконтрастных
  текстурах 000069 невидимо; сетка движется в глейд шагами 1 px (глейд
  000033 быстрый, ~200 мс, 10+ px/кадр в начале — шаги невидимы),
  сущности при этом остаются плавными (≤0.5 px к снап-сетке — субпиксель).

## 5. Подводные камни

* Не «чинить» WebGL-слой (кванты) — шва в нём нет; «старый вид» до
  готовности ассетов — намеренный контракт 000011/000176.
* Не снапать сущности (мобы/герой/лут/декорации/сундуки/игрок/постройки
  мира) — сломают EPS-1e-6 глитт-пины (000173 RM-9(b), 000172, 000158.05,
  main-loot) и MV-C1/MV-C2/RM-9(c) — а тёмных линий на их краях и так нет
  (под ними контент, не тёмный фон).
* worldToScreen — ЕДИНЫЙ источник проекции (контракт 000061: main.js —
  только потребитель). Не дублировать формулу `viewW/2 + (tx−cam)·zoom`
  в main.js/dungeon-ui.js — только через экспорты map.js (edge-массивы
  считают ТОТ ЖЕ порядок операций — бит-идентичность с worldToScreen
  закреплена тестами).
* edges требует ЦЕЛОЧИСЛЕННЫХ границ (длина массива) — guard [NaN],
  не floor'ить молча: caller'ы (visibleTileRange) уже целые.
* Фолбэк-маркеры (квадрат inset 2 + буква) в dungeon-ui — пересчитаны от
  снап-прямоугольника (r.x+2, r.y+2, r.w−4, r.h−4; буква r.x+r.w/2) —
  при целом zoom побайтово как раньше; не возвращать сырые ex.x/zoom
  (развалит выравнивание маркера со снап-полосой при дробном зуме).
* vm-песочница НЕ растеризирует пиксели — «линия» проверяется
  структурно (целые углы + shared-edge), а не цветом пикселя; финальная
  приёмка — визуальная в реальном браузере (механика устранена
  структурно: при целых краях AA-шов математически невозможен).
* Анти-вакуум в красных тестах обязателен: сценарий дробный (raw-проекция
  нецелая: 313.6 в подземелье, 342.4 в городе, 115.19999999999999 на
  карте), иначе тест может пройти «вхолостую» на целом зуме.
* Один worktree = один полный npm test (память: тест 000054 мутирует
  src/npc-data.js).
