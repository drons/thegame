## 1. Суть (одной строкой)

На ходу союзника (наёмник/Эфир — ход игрока, 000168 D9) игрок выбирает цель
удара/каста КЛИКОМ по мобо (единственный путь — клик по полю, combat-ui.js
L455-484 → `c.selectTarget(u.id)`); выбранная цель первостепенна; ядро
(`allyStrike`/`efirCastAction`/зеркало `allyCanDo`) уважает `targetId`.
UI-слой ПРАВОК НЕ ТРЕБУЕТ (кольцо #ffe27a, штриховка 000175, строка
«Цель: …», тханки `c.attack(c.targetId)`/`c.cast(c.targetId)`,
`canDoAction(…, {targetId: c.targetId})` — уже запитаны под `c.targetId`).
ВСЁ — в `src/combat.js`. НОВЫХ `c._rng` = 0, НОВЫХ экспортов/модулей/
SVG/тегов = 0.

## 3. Ключевые решения (все ОQ закрыты; «решить в анализе/памяти»)

### D1. СТРОГИЙ резолв цели (зеркало игрока) — НЕТ fallback на nearestEnemy
для НЕВАЛИДНОЙ ЯВНОЙ цели.

- `targetId` задан явно: живой, !fled, side 'mob' → эта цель;
  иначе (мёртв/fled/союзник/unknown) → `{ok:false, reason:'нет цели'}`,
  пул НЕ сгорает (валидация ДО списания).
- `targetId` НЕ задан (null/undefined — вызов ядра без аргумента) →
  `nearestEnemy(c, u)` — БИТ-В-БИТ прежнее поведение (все существующие
  пины зелёные).

ПОЧЕМУ (против resilient-варианта a2-arch «тупая цель → фолбэк
nearestEnemy»):
1. «Одна причина — одно поведение» (000037): `allyCanDo` обязано давать ту
   же причину, что ядро, на ТОМ ЖЕ входе. Resilient-ядро заставило бы
   resilient-зеркало: кнопка ВКЛЮЧЕНА, а HUD показывает «Цели нет»
   (stateEl, combat-ui.js L1451-1504: мёртвый c.targetId → «Цели нет»; td-
   строка «— мёртв» — только для мёртвых СОЮЗНИКОВ), а удар/каст бьют ЧУЖОГО
   (ближайшего) моба — состояние UI не согласовано с поведением.
2. Игрок-путь (playerAttack L1224-1234, playerSpell L1273-1286,
   canDoAction L1495-1499) — строгий: явная мёртвая цель → «нет цели».
   ТЗ = баг-фикс «невозможно выбрать цель» — минимально предсказуемое
   расширение = зеркало игрока; авто-перенацеливание без ввода игрока
   противоречит самому смыслу фикса (цель — выбор игрока).
3. a3-план (тестовый контракт) и a1 R1/R2 фиксируют строгую семантику
   (SEL-2(3)/SEL-4(3): «fallback НЕ происходит — семантика игрока»).
4. Сценарий «Эфир-касание убило авто-цель → второй каст»: строгий отказ
   «нет цели» (пул НЕ тратится) + HUD «Цели нет» + клик по новому мобу →
   каст идёт. Аналогично книжке игрока (castSpell по устаревшему
   c.targetId → «нет цели»). Регрессии нет: действие не сгорает, цель
   перещёлкивается одним кликом.
5. BAL-119 (autoPlay119, combat.test.js L4668): бот ВСЕГДА передаёт свежий
   живой id (после каждого убийства `t = autoTargetMob119(c)`; `c.attack(t.id)`
   только при живом t) → строгий ≈ resilient для бота; сдвиг метрик один и
   тот же (цель бота вместо nearestEnemy-от-Эфира), митигация — ре-пин
   баннера (§8).

### D2. Единый хелпер `allyTarget(c, u, targetId)` — одна точка резолва.

```js
// src/combat.js, НОВОЕ, после nearestEnemy (L593-599):
// 000198: цель союзного действия — явная (targetId) или nearestEnemy.
// Явная НЕВАЛИДНАЯ (мёртв/fled/союзник/unknown) — null → «нет цели»
// (зеркало игрока, 000080/000037); без аргумента — nearestEnemy
// (v1-бит-в-бит). 0 c._rng, чистый поиск.
function allyTarget(c, u, targetId) {
  const t = targetId
    ? c.units.find((x) => x.id === targetId)
    : nearestEnemy(c, u);
  if (!t || !t.alive || t.fled || t.side === 'ally') return null;
  return t;
}
```

ПОЧЕМУ: правило валидации в 4 точках (allyStrike, efirCastAction,
allyCanDo-attack, allyCanDo-cast) — единый источник (анти-дублирование,
прецедент 000053); на каждой точке дифф минимален — меняется только строка
`const t = nearestEnemy(c, u)` → `const t = allyTarget(c, u, targetId)`,
существующая `if (!t) return { ok: false, reason: 'нет цели' }` и ВСЕ
последующие проверки/причины/порядок — БЕЗ ИЗМЕНЕНИЙ. Экспорт НЕТ
(тесты — через публичный API; combatInternals НЕ расширяется — пин
L1746 на 6 имён не ломается, но и не требует).

### D3. `c.selectTarget` — ДИСПАТЧ; ВАЛИДАТОР ПЕРЕИСПОЛЬЗУЕТСЯ,
отдельного `allySelectTarget` НЕТ.

```js
// src/combat.js L3078-3081:
c.selectTarget = (targetId) => {
  const aid = activeUnitId(c);
  if (aid !== 'player' && !activeAlly()) return null; // D6: слот моба
  return playerSelectTarget(c, targetId); // игрок ИЛИ живой союзник
};
```

ПОЧЕМУ: `playerSelectTarget` (L1458-1466: `!t || !t.alive || t.fled ||
t.side === 'ally'` → `{ok:false, reason:'недоступная цель'}`, иначе
`c.targetId = targetId; {ok:true}`) — ровно нужная семантика для союзных
ходов (союзник не цель — 000080; мёртв/fled — отказ; выбор бесплатен;
дальность валидирует ДЕЙСТВИЕ, не выбор). Вторая функция с идентичным
телом = чистое дублирование (a2-вариант `allySelectTarget` ОТКЛОНЁН).
Игрок-путь БИТ-В-БИТ (тот же вызов). Слот моба (phase 'mob' — defensive,
мобы действуют синхронно) — `null` как раньше (D6 сохранён).
`checkTurn` в валидаторе НЕТ — как у игрока (phase 'player' гарантирован
остановкой advanceQueue; phase 'over' — безвредный write).

### D4. Порядок проверок в каждом действии — БЕЗ ИЗМЕНЕНИЙ (закреплён

- каст Эфира: checkTurn → c.efs → strongestKnown('урон') → пул (efirPool)

## 5. Контракты и границы

### Контракт резолва цели союзного действия (ядро + зеркало)
- `allyTarget(c, u, targetId)`: явная валидная цель (живой, !fled,
  side 'mob') — приоритет; явная невалидная (мёртв/fled/союзник/unknown)
  ИЛИ targetId отсутствует ИЛИ врагов нет → null.
- Точки-потребители при null — `{ok:false, reason:'нет цели'}` БЕЗ расхода
  пулов/маны (валидация до списания), без log-строки действия.
- Без аргумента (`c.attack()`/`c.cast()` из node-тестов) — `nearestEnemy(c,u)`
  — бит-в-бит v1.
- Причины дальности/пулов/маны — дословно существующие (§3 D4/D6); порядок
  проверок — без изменений.

### Контракт выбора цели (selectTarget)
- Активен ИГРОК или живой СОЮЗНИК (activeAlly() не null) → валидация
  playerSelectTarget: живой не-fled МОБ → `c.targetId = targetId`,
  `{ok:true}`; союзник/мёртв/fled/unknown → `{ok:false,
  reason:'недоступная цель'}` (UI-клик возврат игнорирует — тихий отказ,
  лог не растёт; пин 000084 L1887 — зелёный без правок).
- Слот моба/defensive → null (D6).
- Выбор бесплатен (пулы/мана/лог — не трогаются); дальность НЕ проверяется
  при выборе — валидирует действие (зеркало игрока, 000080).
- Мёртвый c.targetId → HUD «Цели нет» (stateEl; «— мёртв» строка — только
  для мёртвых союзников, 000166) + действия «нет цели» — состояния
  согласованы (основание D1).

### Контракт UI (изменений нет — фиксируется)
- Клик по клетке живого моба в ЛЮБОЙ момент хода (игрока/союзника) →
  `c.selectTarget(u.id)` → `c.targetId` меняется; кольцо #ffe27a
  (L1126-1130), штриховка 000175 (L1287-1313), строка «Цель: <имя> (ур.
  <n>, HP a/b)» (L1451-1504) — рисуются по `c.targetId` без гвард активного
  юнита.
- Тханки: `attack: () => c.attack(c.targetId)`, `cast: () =>
  c.cast(c.targetId)` (L670-671); кнопки/клавиши — canDoAction с
  `{targetId: c.targetId}` (L1542, L768) — причины 1:1 с ядром.
