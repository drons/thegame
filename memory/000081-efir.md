## Ключевые решения (по каждому — почему)

1. **Эфир — частный случай «союзного юнита» (000080), kind 'efir';
   src/combat.js — НОЛЬ изменений.** 000080/000082 уже построили всё:
   исключение из allyXp (ПОЛОЖИТЕЛЬНЫЙ фильтр `kind === 'merc'`, combat.js
   checkVictory — пин tests/combat.test.js «доля — только kind === merc»

   очередь, allyAct support (allyHeal), placeAllies без RNG. ТЗ: «не
   больше и не меньше».
2. **Статы 000081 — ФОРМУЛЬНЫЙ путь makeAlly: efirAllyData НЕ передаёт
   явные maxHP/damage** (пин `!('maxHP' in data) && !('damage' in data)`).
   ТЗ требует И «рост статов по уровню (паттерн makeMob, src/combat.js)»,
   И «маркер морали действует: его урон — в companionMoraleBonus» —
   makeAlly применяет moraleMult ТОЛЬКО в формульном ветвлении
   (data.damage == null). Явные статы (таблица 000035: атрибуты
   3+floor((ур−1)/2), maxHP = 10+2·Телосл., L1: 16) — скоуп 000111
   (его ТЗ: таблица + красные тесты L1/L2/L3/L5): 000111 переключит
   efirAllyData на явные, правя ТОЛЬКО src/efir.js + tests/efir.test.js.
   Заметка memory/000080 «Эфир передаёт явные maxHP/damage» —
   ПЕРЕЗАКРЫВАЕТСЯ этим решением (явные приходят с 000111).
   Значения L1 (support, множители 1): maxHP = round(12·0.7) = 8,
   damage = round(2.7) = 3, armor = 0; L3: 14/4/0; L5: 20/6/0.
   Мораль: hero secondary.leader 10 → mult 1.5 → damage = 4 (пин R7).

   000085 (ТЗ 000085 фиксирует `efir: {level, xp, skills}`; 000035#8:
   «форма 000085 ({level, xp, skills}) → нормализация при чтении» в 000115).
   HP/MP в состоянии НЕТ: каждый бой — новый makeAlly (hp = maxHP) →
   «возвращение 100% HP» структурно, без кода восстановления.
   skills — пул вторичных навыков (id→уровень), v1 = {} (000111:
   {firelord, icelord, perception, precog}; в бой v1 НЕ проецируется —
   efirAllyData.skills = []).

   ['spark', 'mend'] («скромный пул: огонь/исцеление» — ТЗ; по 000111 это
