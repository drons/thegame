## Контракт переноса r.teleport (для 000093+)

apply(state) ЧИСТЫЙ: state = { day, tile, hero, save } — мира и
каталога НЕТ (контракт 000072). apply НЕ выбирает тайл и НЕ читает
стоимость: dest и стоимость — в main.js.
* dest — кэш скана в сейве (раздел teleports): apply возвращает
  { ok, message, teleport: {x, y} } — dest ИЗ СНИМКА сейва.
* onBuildingAction (общая ok-ветка, ПОСЛЕ !r.ok-проверки, ПЕРЕД
  маркировкой раз-в-день; ханк срабатывает ТОЛЬКО при r.teleport —
  чужие эффекты, в т.ч. тестовые B3, не затрагиваются):
  ```js
  if (r.teleport) {
    const info = teleports.get(key);
    const cost = /* finite(b.особые_параметры.эффект.стоимость) ? : 0 */;
    const ch = G.buildingEffects.teleportCharge(hero, info && info.active, cost);
    if (!ch.ok) { hudFlash(ch.message); return; } // ДО saveNow: мир не изменился
    hero.gold = ch.gold;
    if (info && !info.active) info.active = true;
    player.x = r.teleport.x; player.y = r.teleport.y;
    if (mover) mover.teleport(player.x, player.y); // снап (000033)
  }
  ```
  дальше общий saveNow/hudFlash(r.message)/playerUI.render.
* Золото и позиция — в main.js (в снимке мира НЕТ). Недостаточно
  золота — отказ БЕЗ списания/переноса/маркировки (контракт 000071:
  !ok → message в hudFlash, без saveNow). Атомарность: цель найдена
  ДО списания (при скане) — «все соседи непроходимы → dest:null →
  apply not-ok → золото не тратится».

## Раздел сейва teleports (имя — 000072; структура — ЗДЕСЬ)

`data.teleports['x,y'] = { pair: 'px,py'|null, dest: 'dx,dy'|null,
active: boolean }` (pair/dest — СТРОКИ 'x,y'; active — boolean;
в памяти — Map той же формы). Неломкое расширение v1: версию НЕ
поднимать, save.js не трогать, миграций нет. restoreFromSave — СВОЙ
try/catch + ЯВНАЯ проверка формы (объект, не массив) + console.warn
с именем раздела «teleports» на мусоре + сброс (паттерн 000072/
000029) + G.restoreTeleports; отсутствие раздела в старом сейве →
пустой Map → скан при первом [E]. Неконтролируемый рост (мир
бесконечен, каждый вход на новый круг — новая запись) — обрезки
не требуется (ТЗ молчит).

## Скан пары (политика)

* Триггер — openBuildingUI (первый подход, НЕ в кадре, не в frame):
  `t.buildingId === 41 && !teleports.has(t.x + ',' + t.y)`.
  Сейв, восстановленный НА тайле круга (шага нет) → скан всё равно
  пройдёт при [E] (safety-net; семантики «нет кэша = спит» НЕТ).
* Окно [-R..R]², R = finite(каталог.особые_параметры.эффект.радиус)
  ? : 100; предфильтр `G.hash2(x, y, G.GLOBAL_SEED) %
  G.buildingCount() === слот` (слот = каталог.размещение.слот) +
  подтверждение `tileAt(x,y).buildingId === 41` (исключая свой тайл).
  ~20–50 ms вместо ~1 c. РИСК предфильтра: дублирует necessary-
  условие якоря map.js — формулу якоря фиксируют золотые пины 000073
  (tests/map.test.js) — не менять формулу без переписи скана.
* linkTeleportCircles(circles, x, y, R, tieHash) → pair; dest =
  teleportDestination(anchor, size, passable, tieHash); запись в Map
  + saveNow(). Повторного скана НИКОГДА (кэш в сейве).
* passable-оракль dest (main.js): `t.passable && !t.inBuilding &&
  !t.hasMobGroup && (x,y) !== тайл исходного круга` (hasMobGroup —
  шаг в группу = мгновенный бой, паттерн findSpawn).
* TELEPORT_TIE_SEED = 0x54454c50 (ASCII 'TELP', экспорт модуля
  building-effects.js для golden-пинов); main.js передаёт
  `(x, y) => G.hash2(x, y, TELEPORT_TIE_SEED)`; финальный лекс.
  тай-брейк (x, затем y) — внутри чистых функций (hash2 32-битный —
  коллизия теоретически возможна).
