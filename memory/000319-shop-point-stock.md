# 000319 — независимый ассортимент магазинов ПО ТОЧКАМ

Задача: `tasks/done/000319.md`. Тесты: `tests/shop-point-stock-000319.test.js`
(T1–T8). Спецификации: `spec/items.md` «Торговля» (буллет «Сток по точкам
(000319)»), `spec/buildings.md` «### Магазины», `spec/npc-storage.md`
(«точка+npcId»).

## 1. Корень дефекта (две независимые причины)

1. `npcStocks` (src/main.js) ключёлся ТОЛЬКО по `npcId` (000029): все
   тайлы-аптеки мира (и городские клетки-fallback, 000134) торгуют в ОДИН
   сток «Милы» — выкуп у одной точки обнулял витрину всех остальных.
2. «Картовые» магазины мира (hud.js): вкладка «Магазин» строилась
   `ctx.game.makeShop(...)` ЗАНОВО КАЖДЫЙ КАДР — покупка списывалась из
   временного объекта и терялась следующим кадром; в сейв сток таких
   магазинов не попадал вовсе.

## 2. Ключи (фактические ключи кода, НЕ выдуманные формы)

- Мирской «картовый» магазин — `worldShops` (src/main.js): ключ `'x,y'`
  МИРОВОГО тайла (тот же формат, что `campStocks` 000095 /
  `cityShops`-клетки 000109), запись
  `{ day, stock, seed, buildingType, wealth }`. `day` — день ГЕНЕРАЦИИ.
  `worldShopFor(x, y, tile)` возвращает wrap `{x,y,buildingType,wealth,
  stock,seed}` в ПОРЯДКЕ КЛЮЧЕЙ makeShop (JSON-эквивалентность — T2) и
  ССЫЛКОЙ на `entry.stock` — `buyItem` мутирует in place (паттерн
  campShopFor/ui.js L226).
- Диалог-торговля NPC — `npcShopKey(npcId, t)` (src/main.js):
  * БЕЗ тайла / не-целые x,y → прежний plain `npcId` (legacy-совместимость
    harness-проводки building-actions `deps.npcShopFor(npc.id)` и старых
    сейвов);
  * городская клетка (`t.cityAnchor` — строка 'ax,ay', проводка
    building-actions.js:542) → `'npcId@C:ax,ay:tx,ty'`;
  * подземелье (`dungeonState.kind !== 'city'`) → `'npcId@D:<ds.worldKey>:tx,ty'`;
  * мир → `'npcId@W:x,y'`.
  `shopFor(npc, t)` прокидывает `t` в обе NPC-ветви; `cityShops`-ветвь
  построек-магазинов (000109) НЕ тронута.
- Город (`ds.cityShops` per-cell) и лагерь (`campStocks 'x,y'`) — УЖЕ были
  per-точка: 0 изменений (кроме переиспользования предиката ротации).

## 3. Сейв (v1, без смены версии, MIGRATIONS==[])

- Новый топ-раздел `worldShops`: сериализация
  `serializeWorldShops(stocks, day, respawnDays)` (src/items.js) —
  `'x,y' → { day:int≥1, stock:{itemId:int≥0} }`; seed/buildingType/wealth
  НЕ пишутся (воспроизводятся `makeShop(x, y, tile.building,
  tile.buildingWealth)` по тайлу); записи УЖЕ ПРОТУХШИЕ на момент
  сериализации (`campStockDueRefresh`) не пишутся (паттерн
  serializeCityStates). Восстановление `restoreWorldShops(saved, day,
  tileAt)`: ключ — два int; `entry.day` int≥1 и ≤ дня мира («будущий» —
  skip); тайл не-магазин (`makeShop` → null) — skip; qty —
  `min(qty, initial)`, призы вне initial — отброс; absent-раздел — ТИХО
  `{}` (полный сток = дефолт «пересоздать»); мусор — skip (fail-open,
  000029/000072). try/catch+console.warn в restoreFromSave (main.js).
- `npcStocks`: ФОРМА `{ключ: {itemId: qty}}` НЕ менялась; ключи additive.
  `restoreNpcStocks` (src/npc.js) режет ключ по первому `'@'`: plain-ключ
  — прежняя ветвь 1:1; point-ключ валидируется
  `/^([^@]+)@([WCD]):(-?\d+,-?\d+)(?::(-?\d+,-?\d+))?$/` (W — РОВНО одна
  пара координат; C/D — РОВНО две), иначе skip. Выходной ключ — точная
  строка сейва. `serializeNpcStocks` — 0 правок (ключ — прозрачная
  строка).

## 4. Refresh (per-магазин, НЕ глобально)

- Картовые точки мира: окно `cityRespawnDays()` (настройка
  `city_respawn_days`, без новых) ОТ ДНЯ ГЕНЕРАЦИИ записи, предикат —
  `campStockDueRefresh(entry, day, respawnDays)` (000095) — переиспользован
  БЕЗ правок; ротация ЛЕНИВАЯ при резолве точки (`worldShopFor`).
  В окне — остатки целы (W4: покупка переживает повторные резолвы визита).
- Город: без изменений — per-city на входе (`prepareCityState`,
  spec/buildings.md «Состояние, сейв, респаун»).
- Лагерь: без изменений (respawn_days каталога).
- NPC-сток: респавна нет (как и раньше).

## 5. 0 новых RNG и границы с 000316/000317

- Сид makeShop `hash2(x, y, 0x154075) ^ (buildingType+1)`, day/level/
  effWealth в сид НЕ входят — refill бит-в-бит прежней генерации (T3).
  Голдены cities / 000317 / 000222 целы (пины 0-diff).

  CAMP_ID` в провайдере main.js): мирским точкам механика НЕ доступна —

  магазинов привязан к дню генерации записи, которого в сиде нет →
  смешивать нельзя (страж T6 пинит провайдер).

  makeShop(...4 арг...)` — харнес-пины (vm-цепочки без main.js) идут

## 6. Подводные камни

- ДВА НЕСМЕШИВАЕМЫХ канала одной аптеки в мире: вкладка «Магазин»
  (stock точки `worldShops 'x,y'`) и диалог-торговля Милы
  (`npcStocks 'apothecary@W:x,y'`) — паттерн не смешивания 000095/000316.
- `cross-realm`: объекты из vm-песочницы имеют ДРУГИЕ прототипы —
  `assert.deepEqual` между песочницами/хост-литералами красный при
  идентичном содержимом; в тесте — хост-клонирующий `cl()`
  (shop-point-stock-000319.test.js).
- `__game.worldShops` — ГЛУБОКАЯ копия (getter); `__game.npcStocks` —
  ПОВЕРХНОСТНАЯ (значения live) — зафиксировать новый ключ НУЖНО
  ПЕРЕД повторным резолвом либо читать геттер заново (T1).
- `restoreNpcStocks` вызывается ТОЛЬКО при `d.npcStocks != null`;
  пустой `{}` тоже проходит (чистит хранилище — остаток живой сессии не
  просачивается, паттерн restoreShopPreOrders).
- `cityAnchor` — строка 'ax,ay' ВТОРИЧНА для мира: в мире поля нет →
  `@W`; подделка ключа (кривой loc) — skip, не крах.
- sync:check до коммита транзиентно красный (конвенция 000322+) — правки
  spec/ вне sync-цепочки, но зеркала не трогались.
- ПИНЫ ГОРОДСКОГО ДИАЛОГА: tests/city-interact.test.js CI-134A/B (Хольд,
  Лавка) пинуют ключ точки `'wanderer_merchant@C:38,-12:1,1'` (якорь+
  клетка е2e-фикстуры 000134) — прежний глобальный npcId-контракт
  «все Лавки — ОДИН сток» 000134 ОТМЕНЁН 000319. `city-interact` НЕ был
  в исходном списке среза — пойман только полным прогоном; срез задач
  стоков обязан включать city-interact.
