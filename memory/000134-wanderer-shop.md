  `постройки` :39): interactCity (building-actions.js:568-629) →
  `npcForBuilding(NPCS, b.id)` → id 5 вернёт Хольда, как только id 5
  появится в городе. Ни строки кода.

  guard :453 `!pp || typeof pp.map_index !== 'number'`): Лавка без
  map_index → стока постройки НЕ будет → prepareCityState (main.js
  :1771 `if (!shop) continue;`) и locations.js:280 — graceful,
  cityShops-записи для клетки Лавки НЕТ. Это ровно SPEC L349-350
  («не имеет map_index — товары продаются через NPC-торговлю») —
  НЕ баг, пин R1.
* **РАЗРЫВ (найден, ТЗ :50 авторизует минимальную правку)** —
  `shopFor` (main.js:1859-1870): городская ветка при
  `cityShops['x,y'] === undefined` возвращала `null` →
  renderTradeTab (ui.js:471) создавал ОДНОРАЗОВУЮ копию стока
  `G.createNpcShop(npc)` в оверлее (проверено vm-экспериментом
  EXP134: витрина Хольда рисуется с ценами из 000011.json, но

  сейв). Минимальная правка — 1 строка:
  `if (!s) return npc ? npcShopFor(npc.id) : null; // 000134`
  (детали/безопасность — основной файл D2). Смысл: клетка города

## 4. Глобальный сток Хольда (npcId-keyed)

* `npcStocks` (main.js:283-292): `{npcId → stock}`, ленивое
  создание через `npcShopFor(npcId)`: `{npc, stock: npcStocks
  [npcId]}` — ЖИВАЯ ссылка (createNpcShop — mutable-КОПИЯ;
  глобальность держит только npcShopFor). Ключ — npcId, НЕ

* Последствия: ВСЕ Лавки ВСЕХ городов (и потенциальный мирной
  Хольд) торгуют из ОДНОГО стока `npcStocks
  ['wanderer_merchant']` — «что привёз — тем и торгует» (ТЗ
  :37-39; тематически верно для странника). Начальные qty из
  000011.json: wood_log 5, stone_chunk 5, hide 3, coal 5,
  iron_ore 3, copper_ore 3.
* Сериализация: collectSaveData (main.js:539-540) →
  `serializeNpcStocks` (npc.js:710-723) → `data.npcStocks =
  {npcId: {itemId: qty}}`; восстановление main.js:1113-1116 →
  `restoreNpcStocks` (npc.js:733-751): каталог-первый (npcId
  обязан быть в каталоге и торговать), qty > начального —
  сжимается до начального, отсутствующий предмет — начальное.
  Версия сейва v1 — НЕ повышается (неломкое расширение,
  прецедент 000072/000093).
* Покупка в городе (после 000134): ui.js хендлер →
  `G.npcBuy(npcShop, …)` мутирует `shop.stock` = та же ссылка

  000029/000095) → `onChange()` = saveNow → сейв. Закрытый
  диалог → повторное открытие — тот же сток (не «воскрешает»;
  пин CI-134A); после лоада — как в сейве (пин CI-134B).
* Наблюдение в тестах: `g.state.npcStocks` — getter (main.js
