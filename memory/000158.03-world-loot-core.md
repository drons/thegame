## 2. Контракты и границы

### 2.1 Форма поля тайла (контракт для 000158.04/05)

* `tileAt` возвращает СТАРЫЕ 13 полей + **`loot: {item: string} |
  null`** (item — id предмета ИЗ каталога items-data.js; пулы id в
  коде НЕ хардкодятся — 000158.02 D2). Форма JSON-сериализуема
  (vm-golden сравнение работает без изменений).
* Семантика: лут = «что лежит на тайле, если там пусто, кроме
  постройки и моба». Приоритет (SPEC, дословно):
  **строительство > моб > лут > пусто**:
  * любой тайл footprint постройки (ВКЛЮЧАЯ ВХОД) → loot=null;
  * тайл с mob-группой → loot=null;
  * ИНАЧЕ (и только там) — lootCore → ровно ОДИН предмет или null
    (пусто).
* Декорации (tileVisuals, VISUALS_SEED) — ЧИСТО ВИЗУАЛЬНЫЙ канал,
  в единую функцию НЕ входит (могут совпадать с любым контентом).

### 2.2 Контракт `lootAt(x, y)` (публичная, self-contained)

Чистая функция (только hash2/fbm/terrainAt — НОВЫХ вызовов
RNG-состояния НЕТ; mulberry32/день/бой не затронуты). Порядок
проверок (каждая → null):
1. `terrainAt(x, y).passable` (сырая террейнная проходимость) —
   вода/горы — НИКОГДА (структурно, без зависимости от каталога);
2. `coveringFootprint(x, y)` — вне footprint (как у моба, `!cover`);
3. mob-канал (ЧТЕНИЕ той же формулы: `features.fbm(x·FEATURE_SCALE
   + 903.7, y·FEATURE_SCALE + 903.7, 3) > 0.31 + 0.14·(1 −
   pixelAt(x,y)[3]/255)`) — моб приоритетнее;
4. `lootCore(x, y, terrain)`.

Пункт 3 дублирует формулу tileAt L951-961 ЧТЕНИЕМ (константы
НЕ трогаются, канал byte-в-те же); в hot-пути tileAt повторных
проверок НЕТ (локальные cover/hasMobGroup/passable уже вычислены)
— стоимость fbm-3окт в tileAt = ноль.

### 2.3 Контракт `lootCore(x, y, terrain)` (ядро выбора)

Тайл УЖЕ проверен вызывающим. Алгоритм (детерминированно):
* `cands = lootCandidates()` — null (каталога нет) → null
  (тихая деградация, §3);
* `name = TERRAIN_NAMES[terrain]` (L261, локальная константа —
  инъекции НЕТ, ТЗ верно);
* **ЛЕНИВО** `nm = nearMountain(x, y)` — только если есть
  кандидат с nearMountains, НЕ покрываемый terrains (в текущем
  каталоге: true для ВСЕХ террейнов кроме «песка» — 14 самородков
  terrains ['песок']);
* для каждого кандидата допуск: `c.terrains.includes(name) ||
  (c.nearMountains && nm)`; ролл
  `(hash2(x, y, LOOT_SEED + c.index · 0x9e3779b9) >>> 8) /
  16777216 < c.frequency` (паттерн tileVisuals sprites.js
  L674-675: старшие 24 бита, НЕ весь hash);
* победитель — **МАКСИМУМ `roll/frequency`** (< 1), строгий `>` —
  при равном score побеждает РАНЬШЕЕ в каталоге (детерминированный
  tie-break; «лучшее с последним» — order-unstable);
* ровно ОДИН предмет → `{ item: c.id }` | null.

`c.index` = ПОЗИЦИЯ предмета в массиве ITEMS (0-based) — D2.
Дефолты ЧТЕНИЯ (000158.02 §4.3): `frequency` 0.1 (у 000065
berry_wild — absence), `near_mountains` false.

### 2.4 Контракт `nearMountain(x, y)` (публичный предикат)

Гора (terrain === TERRAIN.MOUNTAIN, «горы»; «холмы» — НЕ гора) в
**8-окрестности Чебышёв-1, центр НЕ считается** (SPEC:
«проходимые тайлы в 8-окрестности гор»). Чистый: по `terrainAt`
ТОЙ ЖЕ карты (closure) — НЕ через tileAt (perf, §9.8). Обход —
ФИКСИРОВАННЫЙ порядок (dy: −1..1, dx: −1..1; детерминизм),
early-exit на первой горе. **Per-map `nmCache`** (Map, ключ
`"x,y"`, cap 65536, clear при переполнении — ТОЧНЫЙ fpCache-
прецедент L674-677): чистая мемоизация (terrainAt чист); кэш
PER-INSTANCE (изоляция vm-песочниц).

### 2.5 Degradation (контракт)

items-data не загружен (vm-песочницы perlin+map без items-data) →
`loot = null` на ВСЕХ тайлах; СТАРЫЕ 13 полей — **байт-в-байт**
(мировые каналы не зависят от каталога лута). Деградация

### 3.3 Каталог (модульный уровень)

```js
// --- Каталог лута (задача 000158) ---
// Предметы с полем loot (items-data.js). В node приходит через
// require (6-й UMD-аргумент); в браузере/vm — ЛЕНИВО из живого
// Game.ITEMS в момент вызова (плоское поле, items-data.js;
// паттерн mobGroupsRef L335 — функции, не константы: переживает
// Object.assign-ловушку 000038/000055). Кэш ПУСТОГО вывода
// запрещён (000055). Деградация МОЛЧА (ни одного console.*).
let _lootCandidates = null;

function lootItemsRef() {
  if (itemsData && Array.isArray(itemsData.ITEMS)) return itemsData.ITEMS;
  const g = root && root.Game;
  return g && Array.isArray(g.ITEMS) ? g.ITEMS : null;
}

// Кандидаты: вывод из каталога (таблица {id, index, terrains,
// nearMountains, frequency}) или null. index — ПОЗИЦИЯ в ITEMS
// (0-based; append-only-инвариант каталога — ключ хэша, D2).
// Дефолты ЧТЕНИЯ: frequency 0.1, near_mountains false (000158.02).
function lootCandidates() {
  if (_lootCandidates) return _lootCandidates;
  const items = lootItemsRef();
  if (!items) return null;
  const out = [];
  items.forEach((it, i) => {
    const L = it && it.loot;
    if (!L || typeof L !== 'object' || !Array.isArray(L.terrains) ||
        L.terrains.length === 0 || typeof it.id !== 'string') return;
    out.push({
      id: it.id,
      index: i,
      terrains: L.terrains,
      nearMountains: L.near_mountains === true,
      frequency: typeof L.frequency === 'number' ? L.frequency : 0.1,
    });
  });
  if (out.length === 0) return null;
  _lootCandidates = out;
  return out;
}
```

### 3.4 Per-map (внутри createMap, после coveringFootprint)

```js
// --- Лут (задача 000158): единая точка контента тайла ---
// Чистые функции инстанса: пиксели/террейн — от этой карты.
// Kэш nearMountain — чистая мемоизация (fpCache-прецедент):
// без кэша perf-тест (160k tileAt, бюджет 5000 мс) уходит в
// load-флейк (+50-100%); с кэшем +40-60%.
const nmCache = new Map();

// Гора в 8-окрестности (Чебышёв-1, центр НЕ считается) — чистый
// предикат по terrainAt той же карты. SPEC: «проходимые тайлы в
// 8-окрестности гор».
function nearMountain(x, y) {
  const key = x + ',' + y;
  const hit = nmCache.get(key);
  if (hit !== undefined) return hit;
  let found = false;
  for (let dy = -1; dy <= 1 && !found; dy++) {
    for (let dx = -1; dx <= 1; dx++) {
      if (dx === 0 && dy === 0) continue;
      if (terrainAt(x + dx, y + dy).terrain === TERRAIN.MOUNTAIN) {
        found = true;
        break;
      }
    }
  }
  if (nmCache.size > 65536) nmCache.clear(); // fpCache-прецедент
  nmCache.set(key, found);
  return found;
}

// Ядро выбора лута: тайл УЖЕ проверен (passable, !cover, !mob).
// Чистая: hash2 + nearMountain + terrain. Кандидат — terrains ⊇
// террейн ИЛИ (near_mountains && гора в 8-окрестности). Ролл —
// паттерн tileVisuals; победитель — МАКС roll/frequency, строгий
// > (равенство → ранее в каталоге); ровно ОДИН предмет.
function lootCore(x, y, terrain) {
  const cands = lootCandidates();
  if (!cands) return null; // каталога нет → пусто (тихо)
  const name = TERRAIN_NAMES[terrain];
  let needMountain = false;
  for (const c of cands)
    if (c.nearMountains && !c.terrains.includes(name)) {
      needMountain = true;
      break;
    }
  const nm = needMountain ? nearMountain(x, y) : false; // лениво
  let best = null, bestScore = -1;
  for (const c of cands) {
    if (!c.terrains.includes(name) && !(c.nearMountains && nm)) continue;
    const roll = (hash2(x, y, LOOT_SEED + c.index * 0x9e3779b9) >>> 8)
      / 16777216;
    if (roll >= c.frequency) continue;
    const score = roll / c.frequency; // < 1
    if (score > bestScore) { best = c; bestScore = score; }
  }
  return best ? { item: best.id } : null;
}

// Публичная (тесты/000158.04): САМОДОСТАТОЧНАЯ — свои проверки
// (passable → footprint → mob-канал ЧТЕНИЕМ → lootCore).
function lootAt(x, y) {
  const { terrain, passable } = terrainAt(x, y);
  if (!passable) return null; // вода/горы — никогда
  if (coveringFootprint(x, y)) return null; // любой тайл footprint
  const fm = features.fbm(
    x * FEATURE_SCALE + 903.7, y * FEATURE_SCALE + 903.7, 3);
  if (fm > 0.31 + 0.14 * (1 - pixelAt(x, y)[3] / 255)) return null;
  return lootCore(x, y, terrain); // моб приоритетнее
}
```

```js
// но и структура гарантирует «вода — никогда»; nearMountain на
// непроходимых не вызывается).
const loot = (passable && !cover && !hasMobGroup)
  ? lootCore(x, y, terrain) : null;
```

Возврат createMap: `lootAt, nearMountain` (комментарий
«read-only/чистые функции инстанса (000158)»). Return модуля:
`LOOT_SEED` (рядом с CITY/SUBTYPE, «golden-пины»).

## 4. Решения (openQuestions закрыты на Проектировании)

* **D1. Доступ к каталогу — ЛЕНИВЫЙ rootRef (`lootItemsRef` читает
  live `root.Game.ITEMS` в момент вызова) + 6-й UMD-аргумент
  `require('./items-data.js')` в node-ветке** — потому что
  ITEMS_CHAIN (tests/items.test.js L939) грузит map.js ДО
  items-data.js: load-time-снапшот (как G0.ITEMS) застыл бы на
  «нет каталога» и сломал parity (UMD-ловушка 000038/000055);
  items-data.js самодостаточен (0 require) — цикла нет; домовой
  паттерн map.js (catalogRef L35 / settingsRef L49 / mobGroupsRef
  L335). Маркер — flat `Game.ITEMS` (НЕ именованный объект).
  Альтернатива a1 (снапшот G0.ITEMS) — ОТКЛОНЕНА (порядок
  index.html L846<L858 соблюдается, но ленивость делает порядок
  нерелевантным и покрывает vm-цепочки).
* **D2. `itemId` в формуле хэша = ПОЗИЦИЯ предмета в ITEMS
  (0-based), НЕ строковый id** — потому что hash2 —
  Math.imul-алгебра (string → NaN); ТЗ-формула
  `LOOT_SEED + itemId·0x9e3779b9` (аналог tileVisuals
  `v.id·0x9e3779b9`, где id каталога — число) требует числа;
  позиции устойчивы по append-only-инварианту каталога
  (000157.01/000158.02, закреплено тестами: новые файлы строго
  ПОСЛЕ 000062, иначе сдвигнут ВСЕ rng-хвосты и позиционные
  пины). Альтернатива a1 (FNV-1a fold id-строки) — ОТКЛОНЕНА
  (изобретение функции хэша строки вне ТЗ-формулы; любой выбор
  фиксируется пинами — GOLDEN_TILES loot + MLS).
* **D3. `LOOT_SEED = GLOBAL_SEED ^ 0x4C4F4F54` (ASCII «LOOT»),
  экспортируется из модуля + пин-тест MLS** — потому что точный
  домовой паттерн сидов каналов (CITY «CITY» / SUBT «SUBT» +
  экспорт «golden-пины» + пин-тесты L1559/L2032); канал лута
  обязан быть независим (NE GLOBAL_SEED/CITY/SUBTYPE/моб-сид/
  VISUALS_SEED — ТЗ п.1).
* **D4. `nearMountain`/`lootAt` — функции ИНСТАНСА createMap
  (closure), публичные через return createMap**
  (`map.nearMountain(x,y)` / `map.lootAt(x,y)`) — потому что
  terrainAt/coveringFootprint/features/pixelAt — замыкания
  createMap (зависят от пикселей данной карты); модульного уровня
  невозможен; ТЗ «публичная для тестов» + тест-предикат — прямой
  вызов (прецедент buildingAt L996).
* **D5. `lootAt` — self-contained (свои guard'ы); `tileAt`
  вызывает `lootCore` с условием `passable && !cover &&
  !hasMobGroup` (passable — сырая террейнная из L941)** —
  потому что: (а) ТЗ определяет условия кандидата про lootAt;
  (б) hot-путь не дублирует проверки (локальные уже есть);
  (в) **явная `passable`-страховка в tileAt (в a2-снимке её НЕ
  было) — структурное «вода/горы — никогда» БЕЗ зависимости от
  «случайно нет water-кандидатов в каталоге» + НЕ вызывает
  nearMountain на непроходимых тайлах (perf) + зеркалит
  структуру guard'а моб-канала (L961 `passable && !cover && …`)**.
  Формула mob-канала в lootAt дублируется ЧТЕНИЕМ (те же fbm
  +903.7/порог/константы — канал byte-в-те же, пины не трогаются).
* **D6. `nearMountain` — 8-окрестность Чебышёв-1 (центр НЕ
  считается), ТОЛЬКО TERRAIN.MOUNTAIN (НЕ HILL), через terrainAt
  той же карты (НЕ tileAt), фикс. порядок обхода + early-exit,
  per-map nmCache (Map, cap 65536, clear при переполнении —
  точный fpCache-прецедент)** — потому что: SPEC дословно
  «8-окрестность гор»; tileAt вместо terrainAt = +5.3 с к
