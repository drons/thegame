# 000015: валидация каталогов assets по JSON-схемам (общий валидатор)

Статус: выполнено и закоммичено (тесты 338 → 364 pass, новых 26).

## Решения

* **tests/json-schema.js** — ОДИН общий минимальный валидатор JSON-схем
  (CommonJS, только для тестов, без внешних зависимостей; package.json
  без deps). Ключи: `type` (integer/number/string/boolean/object/
  array/null; integer — только целые), `required`, `properties`,
  `additionalProperties` (false — лишнее поле = ошибка), `items`,
  `enum`, `const`, `minimum`/`maximum` (границы включены),
  `minItems`/`maxItems`, `pattern` (RegExp без флагов, только строки),
  `anyOf` (≥1 вариант), `oneOf` (ровно 1). Экспорт:
  `ALLOWED_SCHEMA_KEYS`, `actualType`, `validate(schema, value, where,
  errors)` (ошибки — строки с путём, массив на вход),
  `validateData(schema, data)` → массив ошибок, `schemaKeys(schema)` —
  обход всех ключей схемы (для проверки «схема использует только
  допустимые ключи»).
* **tests/assets-schemas.test.js** — финальная валидация каталогов
  assets/{items,npc,skills,buildings}: схема существует и содержит
  только ключи ALLOWED_SCHEMA_KEYS; файлы 000001..N.json подряд,
  чужих файлов нет; каждый файл валиден по схеме (финальное состояние
  каталогов после всех мержей: items 32 — с 8 книгами/свитками из
  000013, npc 10, skills 37, buildings 50 — все проходят).
  Отрицательный контроль на каждый каталог (нет обязательного поля /
  лишнее поле — валидатор ловит) страхует от «немой» валидации.
  Плюс самопроверки самого валидатора по каждому ключу.
* **Дедупликация**: три идентичные (по байту) копии валидатора,
  встроенные в tests/npc-data.test.js, tests/spells.test.js,
  tests/craft.test.js ещё в черновиках задач (копии были созданы
  до выполнения 000015 с пометкой «задача 000015»), заменены на
  `require('./json-schema.js')`. Тесты этих файлов не тронуты,
  только определений стало меньше; поведению не изменилось.
* **Схемы в соответствие с данными НЕ приводилось**: все 129 файлов
  четырёх каталогов проходят существующие schema.json без правок
  (проверено до добавления тестов и подтверждено тестами).
  Замечание: у items `weight` мин. 0.05 — реагент phoenix_feather
  лежит ровно на границе (0.05), схема корректна.
* Умозрительные схемы каталогов mobs/spells/craft/visuals тоже
  используют только ключи ALLOWED_SCHEMA_KEYS (иначе их тесты
  падали бы); общий валидатор им теперь доступен тем же require.
