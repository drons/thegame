## G.buildingUI — в НОВОМ файле src/building-ui.js, не в src/ui.js

* Список файлов задачи говорит «src/ui.js — G.buildingUI по образцу
  G.npcUI»; 000071 src/ui.js НЕ ИЗМЕНЯЕТ: оверлей — в новом файле
  src/building-ui.js (IIFE, паттерн ui.js; без UMD/node-require —
  чисто браузерный модуль). Порядок загрузки: ПОСЛЕ ui.js, ДО main.js
  (UMD-ловушка 000038 — main.js снимает Game один раз; закреплено в
  tests/index-order.test.js).
* Обоснование решения (фиксировано на старте задачи, строки 5-6
  src/building-ui.js): 000097 (тултипы панели персонажа) в этот момент
  выполнялась и правила src/ui.js — добавление оверлея туда гарантировало
  мерж-конфликт при параллельной работе; оверлей самодостаточен
  (взаимных require в момент загрузки нет — прецедент 000053).
* «По образцу G.npcUI» — по ПОВЕДЕНИЮ: контракт тот же, что требует
  задача — open({ title, actions, onAction }) / close() / isActive(),
  оверлей .combat-overlay > .combat-side, только СУЩЕСТВУЮЩИЕ CSS-классы
  (.combat-overlay/.combat-side/.cp-*), слушатель клавиш живёт, пока
  оверлей открыт, делегированный click (тач, 000123).
* При перебазировании на актуальный master (000097 уже смержен)
  отклонение не даёт конфликтов: 000071 src/ui.js не трогает вовсе;
  общий с 000097 — только index.html (script-теги), мерж — по правилу
  минимального пересечения.

## Управление buildingUI (пункт 2 задачи: «1..9 / ↑↓, [E]/[Esc] — закрыть»)

Реализовано ПОЛНОСТЬЮ (ревью раунда 1: отсрочка ↑↓ была задокументирована
лишь код-комментарием — не принято; теперь реализовано и зафиксировано
тестом B9):

* 1..9 — выполнить строку N напрямую (покрывает до 9 строк);
* ↑↓ — курсор по ДОСТУПНЫМ строкам (wrap, недоступные пропускаются);
  строка под курсором помечена «▸ » ТЕКСТОВЫМ маркером в имени (новых
  CSS-классов НЕТ — ограничение задачи);
* Enter/NumpadEnter — выполнить строку под курсором: ЕДИНСТВЕННЫЙ способ
  достичь 10-й и следующих строк. Критично для основания: каталог
  открыт (схема не ограничивает длину особых_параметры.эффекты), а
  оверлей создаётся в 000071 ЕДИНЫМ — последующие подзадачи (000074–
  000077, 000091–000095) добавляют только записи реестра и НЕ трогают
  оверлей; отложенный ↑↓ оказался бы необратим.
* клик по строке — выполнить (тач-сценарий 000123, один делегированный
  click, паттерн npcUI onOverlayClick);
* [Esc] — закрыть; [E] — закрывает РОУТЕР main.js (toggleNpcDialog), в
  оверлее не дублируется;
* недоступная строка — disabled (цифра/Enter/клик не выполняют, reason
  виден); после onAction(action) оверлей закрывается САМ (вызов — ПОСЛЕ
  закрытия: обработчик на том же нажатии может открыть npcUI).

  оверлея активны; HUD «[E] диалог» вводит в заблуждение).
* Исправлено: в ветке G.buildingUI проверка `npcUI.isActive()` идёт
  после buildingUI.isActive() и ПЕРЕД открытием — повторный [E]
  закрывает открытый диалог (поведение master восстановлено). Оба
  оверлея одновременно быть НЕ МОГУТ: действие «Диалог» закрывает
  buildingUI ДО открытия npcUI (executeAction). Тест — B4 (второй [E]).
