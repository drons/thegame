## 3. Решения анализа (решение — почему)

1. **frequency 0.02 у всех 5** — редкий тир 000158.02 (root_moon /
   fruit_quince / mushroom_glow = 0.02; наши value 2–5 — строительное
   сырьё, не еда). «По прецеденту copper_ore» трактуется как МЕХАНИЗМ
   (loot-поле + пул DUNGEON_ORES), НЕ как значение 0.04: 0.04 — тир
   T1-самородков ПЕСКА (near_mountains); на лесу/болоте удвоил бы
   плотность и размывал существующие 28 (баланс-пин ТЗ).
2. **Terrains: wood_log/hide — `["лес"]`; 3 травы — `["болото","лес"]`;
   «трава» и «холмы» — НЕТ** — замер (sim-matrix.js, /tmp): roll всех 5
   на (−1,1) [трава] ∈ [0.156, 0.967] → ЛЮБОЙ из 5 с «трава» при freq
   ≤0.15 (наши 0.02) вытеснит root_rock — ломаются LM6/LM7 (по-тайловые
   пины e2e, игрок-видимо); roll на (−120,26) [холмы у горы] ∈
   [0.36, 0.83] → ЛЮБОЙ с «холмы» вытеснит obsidian — ломается ML6.
   Трава — только ценой репина по-тайловых behavior-пинов = семантическая
   правка существующих тестов — запрещена инвариантом workflow и
   баланс-пином ТЗ. Травы {болото,лес} — SPEC-класс «травы
   (трава/болото/лес)» минус запрещённая трава; болото — без
   distribution/по-тайловых пинов (1174 пустых тайла в окне 240×240).
   Лес — без distribution-пина (ML4 пинит только СОСТАВ → чистовой
   репин). a2-вариант «hide → трава+лес» и a1-вариант «травы → лес
   только» — отклонены по замеру/SPEC соответственно.
3. **near_mountains — ABSENT у всех 5** (default false) — семантика поля
   = только самородки (000158.02 D6/D7: «опущено у всех природных»);
   true дал бы кандидата на холмах-у-горы → ML6 красный
   структурно.
4. **DUNGEON_ORES — РАСШИРЯЕМ (5 записей по 1 на reagent)** — цель ТЗ
   «предпочтительно и там, и там» + прецедент copper_ore; a1-вариант
   «не расширять» (enum «вид» заперт; «минерал» — семантическая ложь) —
   ОТКЛОНЕН: обязательная цель «карта ИЛИ подземелье» у него закрыта,
   но мягкая цель и прецедент ТЗ жертвуются; возражение «enum заперт»
   снимается: НОВЫЙ «вид» не нужен — переиспользуем существующий
   «минерал» (§3.5).
5. **«вид» = «минерал» у всех 5** — enum {руда, минерал, самоцвет}
   закрыт КОДОМ и SPEC'ом: src/dungeon.js validDungeonCatalog (2 места
   — guard + FALLBACK 1:1), src/sprites.js DUNGEON_DEPOSIT (3 svg
   deposit_{ore,mineral,gem}), src/dungeon-ui.js
   DEPOSIT_FALLBACK_COLORS (3 цвета), assets/dungeons/schema.json,
   SPEC spec/dungeons-storage.md «Залежи». Новый 4-й «вид»
   (дерево/материал) = механическая фича (schema + 2×src + svg + SPEC) —
   ВНЕ Границ ТЗ («src/ — только если loot-спавн читает данные
   по-другому» — проверено: НЕ читает). «Минерал» — самая общая
   категория (stone_chunk/quartz/obsidian — «минералы»); sprite залежи
   — КОСМЕТИКА (спрайт выбирается по «виду», ПРЕДМЕТ берётся по id из
   записи — игрок получает reagent, не «минерал»). Ловушка: JSON с
   не-enum «вид» БЕЗ правки кода → validDungeonCatalog=false → в
   браузере каталог ОТБРАСЫВАЕТСЯ на FALLBACK (тихий регресс ВСЕЙ
   генерации) — «минерал» исключает эту ветку.
6. **Размещение: CAVE +1 (herb_healing), CRYPT +1 (herb_mana),
   RUINS +2 (wood_log, hide), DROWNED +1 (herb_bitter), ABYSS +0** —
   замер (sim-deposits/sim-matrix/sim-subsets): +1 reagent (append) в
   ЛЮБОЙ пул → бит-в-бит голдены D-BOSS-3 (CAVE d1 [coal]) и ORE-7
   (ABYSS d8 [obsidian, gold_ore, amethyst]) ДЕРЖАТСЯ (25/25
   комбинаций); +2 и более в CAVE → D-BOSS-3 ломается (26/26); +2 и
   более в ABYSS → ORE-7 ломается (26/26); CRYPT/RUINS/DROWNED —
   бит-в-бит депозит-голденей НЕТ. a2-план «CAVE +3 травы» отклонён:
   потребовал бы репина behavior-голдена D-BOSS-3 (депозит d0 другой
   предмет) — семантическая правка, не технический репин. Тематика:
   CAVE — базовая пещера → исцеляющая трава; CRYPT — магия/нечисть →
   манная (в сундуках CRYPT уже mana_potion/mana_elixir-соседи);
   RUINS — обжитые руины → бревно/кожа; DROWNED — вода/мокрота →
   горечавка (в пуле уже sulfur). ABYSS +0: эндгейм-пул T3/T4 — T1
   reagent размыл бы эндгейм-экономику + максимальная безопасность
   ORE-7.
7. **5 НОВЫХ SVG 64×64 ОБЯЗАТЕЛЬНЫ** — ТЗ-допущение «svg у reagent'ов
   есть» опровергнуто: assets/sprites/loot/ = ровно 28 svg, иконок у 5
   НЕТ. sprites.js allAssetPaths пушит конвенционный путь
   `assets/sprites/loot/<id>.svg` для КАЖДОГО предмета с полем loot
   (независимо от icon) + SP-LOOT-1a exists()-цикл — без файла лут
   существует в данных, но НЕВИДИМ в игре (spriteLoader.isReady=false →
   пропуск, ноль console.*). SVG проходят tests/svg.test.js
   (well-formed + корень svg + xmlns + viewBox + без NaN — SPEC/000120)
   ДО добавления в каталог (workflow-инвариант).
8. **Поле «icon» у всех 5** = `"assets/sprites/loot/<id>.svg"` (конвенция;
   пин 000211.06 I1 требует icon=конвенции у ВСЕХ лут-предметов,
   live-скан) — конец JSON-объекта, loot — перед ним.
9. **Силуэты иконки** (64×64; стиль существующих 28: ellipse-тень
   rgba(0,0,0,0.16–0.22) + 3–6 контурных фигур; палитры НЕ дублируют
   28 существующих + декорации лесного тайла — ловушка 000158.02 §9.1,
   в лесу уже «Гриб»-декорация и иконки berry_*/herb_*/root_*):
   * wood_log — горизонтальное бревно: цилиндрический корпус с 2–3
     полосами коры + круглый срез С КОЛЬЦАМИ на правом торце
     (кора #8a5a2b/#6f4520, кольца #d8a05c/#b57b3e) — не путать с
     copper_ore (кисти-пики) и root_* (корни).
   * hide — растянутая шкура: асимметричный пятиугольник с тёмной
     каймой (тело #c89a6a/#a97846, кайма #6f4520) + 3 коротких
     засечки-прорези + круглое отверстие в углу (дырка для сушки).
   * herb_healing — стебель + 2 листа + 5-лепестковый ЗВЕЗДНЫЙ цветок,
     тёплый красно-розовый #d8506a, центр #f0c33c — отличить от
     berry_red (красные КРУГИ-ягоды) и herb_sun (жёлтые круги).
   * herb_mana — стебель + 3 заострённых листа + 4-лепестковый цветок,

   * herb_bitter — веточка из 4 тёмно-оливковых ЛУЧИСТЫХ листьев
