## 2. Контракты и границы

### 2.1 itemRow + tipIcon (src/ui.js) — единый механизм предметной строки

* Подпись: `itemRow(name, meta, buttons, tip, icon, rarity, tipIcon)`.
  Прецедент аддитивных хвостовых аргументов: tip (4-й, 000097), icon
  (5-й, 000237), rarity (6-й, 000230.07) — каждый новый — своим
  аргументом, 6-арг. вызовы — 0 DOM-diff.
* Иконка в тултипе — `img.cp-tipicon` ВНУТРИ .cp-tip (внук строки, НЕ
  прямой ребёнок .cp-itemrow — прямые дети строки не сдвигаются, пины
  237-INV-1/230.07-ICON-1 «img первым прямым ребёнком» целы).
* **Порядок операций КРИТИЧЕН** (ловушка DOM-стаба): (1)
  `tipEl = el('div', 'cp-tip', tip)` — текст пишется СОБСТВЕННЫМ
  textContent узла (в стабе — _text) ДО всех appendChild; (2) img
  строится и добавляется ПОСЛЕ. Стаб makeEl (дубль
  ui-panel.test.js:202): setter textContent ОЧИЩАЕТ children — img-до /
  text-после = img стёрт; getter textContent читает ТОЛЬКО _text (дети
  не считаются) — поэтому текст ОБЯЗАН остаться в _text: span-обёртка
  недопустима (tip.textContent = '' → семантически ломает существующие
  пины 237-INV-1 (iron_ore — С icon) и craft-scroll-use TIP-1/2
  (blueprint_forge — С icon)). createTextNode/insertBefore/firstChild в
  стабах ВСЕХ тестов ОТСУТСТВУЮТ (grep = 0) — краш vm-тестов.
* **Порядок в реальном DOM** (браузер): float:left даёт каноничный вид
  (иконка вверху-слева, текст обтекает справа/снизу) ТОЛЬКО при
  source-порядке [img, текст-нод] — отсюда
  `tipEl.insertBefore(img, tipEl.firstChild)` (firstChild после записи
  textContent = текст-нод; tip === '' → firstChild null →
  insertBefore(x, null) ≡ appendChild — допустимо). **В стабе**
  (insertBefore нет) — appendChild → порядок [_text, img]. Guard
  `typeof tipEl.insertBefore === 'function'` — паттерн деградации
  ui.js (placeTip :311-312 — typeof-guard на getBoundingClientRect).
  Браузерный путь CI не покрывает (нет браузера) — принят, как все
  degradation-ветки проекта.
* В реальном DOM `tipEl.textContent` = текст потомков; img (alt = '')
  не даёт текста → touch-fallback 000097 (flashNotice(tip.textContent),
  ui.js:241-242) бит-в-бит; в стабе = _text — то же самое.
* Guard tipIcon: `typeof tipIcon === 'string' && tipIcon !== ''` (тот
  же, что у icon 000237 / building-ui.js:211). tip == null → .cp-tip
  нет вообще → tipIcon игнорируется.
* 7-й аргумент НЕ выводится в Game-уровень: itemRow остаётся механизмом
  вкладки через ctx (000130). Источник tipIcon — iconOf(it) вкладки
  (it.icon каталога; НЕ фолбэк loot/<id>.svg — он только для карты,
  000237 §2.1).

### 2.2 CSS (index.html) — одно новое правило

```
.char-panel .cp-tip .cp-tipicon { float: left; width: 44px; height: 44px; margin-right: 8px; }
```

* **44×44px = ровно 2× мини-иконки строки 22×22** (:100) — решение
  «крупная» ТЗ (D3). Пин точное значение + >22px (308-TI-4).
* **float: left** — иконка вверху-слева, текст (white-space: pre-line)
  обтекает справа и снизу; source-порядок в браузере [img, текст] (§2.1).
* **Скоуп `.char-panel`** — конвенция tooltip-правил 000097/000262
  (npc-оверлей переиспользует .cp-itemrow — не должен получить
  relative/тултипы; наш img ВНУТРИ .cp-tip, а .cp-tip у оверлея нет —
  скоуп двойная страховка).
* pointer-events: none наследуется с .cp-tip → иконка не перехватывает
  курсор/клики (клик по строке — touch-fallback).
* **Позиция в файле**: ПОСЛЕ `}` правила показа (:162), ДО комментария
  000098 (:163). Байты :100-:162 не сдвигаются.
* **Пины не сдвигаются** (проверено): `cssRule(html, 'cp-tip')` —
  regex `\.cp-tip\s*{` матчит ПЕРВОЕ вхождение = базовое правило
  :133-151; в новом селекторе после «.cp-tip» идёт « .cp-tipicon» (не
  « {») → не матчит. `cssRule(html, 'cp-itemicon')` (build-menu-
  layout:69) — новое правило не содержит «.cp-itemicon» (token-match:
  'cp-tipicon' ≠ 'cp-itemicon'). Flip-regex TF-5
  `\.char-panel\s+\.cp-tip\.cp-tip--down\s*\{` — точный. Regex показа
  `:hover[^{]*\.cp-tip[^{]*\{[^}]*opacity:\s*1` — не тронут.
  `cssRule(html, 'cp-tipicon')` (новый пин) — матчит хвост
  compound-селектора `.cp-tipicon {` — работает.
* margin-right: 8px — отступ между иконкой и обтекающим текстом.
