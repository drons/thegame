## Решения

### R1. Семантика строки: доступен = геометрия И золото И предметы (read-only pre-check)

В `openCityBuildMenu` pre-check расширяется с «только геометрия» на
«геометрия + `hero.gold >= cost.золото` + `hasItem` по ВСЕМ исходникам».
Ничего не мутируется (чтение hero/инвентаря); списание остаётся ТОЛЬКО в
`buildCityAt` с re-check (защита от дрейфа 000148.03). `a.доступен` —
по полной проверке, `a.reason` — при отказе:

* геометрия ПРИБОРОРИТЕТНО: отказ space/cap/reach → reason = капс-текст
  `BUILD_MENU_REASON_TEXT` (НОВЫЙ констант рядом со старым:
  `{space: 'Нет места', cap: 'Лимит 50%', reach: 'Закроет доступ к
  постройкам'}`); ресурсный текст при отказе геометрии НЕ показывается
  (геометрия — более действенная причина, порядок = порядок проверок
  `canBuildAt`);
* иначе (геометрия ОК, ресурсов нет) → reason = «Не хватает …» (R2).

ПОЧЕМУ: ТЗ требует, чтобы причина была видна; строка, которую построить
невозможно, — недоступна (контракт 000071 «недоступные строки — disabled»);
клик по недоступной строке игнорируется (двойная защита: `row.disabled`
+ проверка в `executeAction`). Это ОСОЗНАННЫЙ ТЗ-репин 4 пинов (см. §Репины),
все остальные пины (форматы строк, flash, счётчики, CI-V*) — побайтово.

### R2. Формат «Не хватает …»

`'Не хватает ' + части`. Части:

* золото ПЕРВЫМ (gold-first, как в `buildCityAt`): `<N> золота`
  (`N = cost.золото − hero.gold`); «золота» — инвариантная форма;
* затем предметы С ДЕФИЦИТОМ в ПОРЯДКЕ КАТАЛОГА (`cost.исходники`):
  `<N> <форма>` (только при `have < e.количество`).

**Число предмета N — ДЕФИЦИТ, как у золота (ИТОГОВОЕ, ревью-раунд):**
`N = e.количество − have` (`have = totalQty(hero, e.предмет)`;
предметная часть строится только при `have < e.количество` →
`N ≥ 1` всегда). Пины: (cost 3, have 0) → «3 бревна», (cost 3, have 2) →
«1 бревна» (3−2), (cost 3, have 1) → «2 бревна» (3−1) (CI-B3 —
репин по итогам ревью); (cost 2, have 0) → «2 каменных обломков»,
(cost 2, have 1) → «1 каменного обломка» (CI-B2 — совпал БЕЗ репина);
e2e (have 0) — полное требуемое, не изменился. История: дизайн-стадия
и ИТОГ — `N = e.количество − have` (дефицит); на красной стадии
пины зафиксировали `N = have > 0 ? have : e.количество` (имеющееся)
и код реализовал пины; ревью-раунд вернул дефицитную семантику —
в ОДНОМ сообщении «Не хватает …» золотая часть уже показывала дефицит
(`cost.золото − hero.gold`), а предметная — имеющееся у героя:
внутренне неконсистентно («Не хватает 2 бревна» при дефиците 1 —
игрок доберёт 2 вместо 1; ТЗ-пример «Не хватает 1 серы и 3 бревна»
совместим с обеими семантиками и воспроизводится дословно — там
have = 0). Доступность строки — по ДЕФИЦИТУ (НЕ изменилась:
`have >= e.количество` → доступна; CI-B1: have = 1 = cost → предмета в
reason НЕТ). Деградирующий путь (нет totalQty): have ∈ {0, e.количество}
→ N = e.количество — побайтово как раньше.

Склейка: золотая часть (если есть) — с предметными через ЗАПЯТУЮ (без «и»);
предметные: 2 шт. — «A и B»; ≥3 — «A, B и C» (запятые между, « и » перед
последней, запятой перед «и» НЕТ). Примеры (зафиксированы пинами):
«Не хватает 10 золота, 1 каменного обломка» (репин CI-U14(b), дословно),
«Не хватает 1 серы и 3 бревна» (пример ТЗ, дословно), «Не хватает 5
золота, 2 кож».

ПОЧЕМУ: обе закреплённые строки (ТЗ-пример + текст репина CI-U14(b),
данный workflow-оркестратором) воспроизводятся дословно; gold-first =
конвенция `buildCityAt` (один источник порядка).

### R6. Красная причина: опции open() — `reasonRed` / `scroll`

`buildingUI.open({ title, actions, onAction, reasonRed?, scroll? })` —
новые ОПЦИОНАЛЬНЫЕ поля (побайтовое для других вызовов). Ставит ТОЛЬКО
`openCityBuildMenu` (`reasonRed: true, scroll: true`):

* `reasonRed`: reason-спан строки — класс `'cp-itemmeta cp-itemreason'`
  (текст как сейчас `' — ' + a.reason`); недоступная строка НЕ затемняется
  `opacity: 0.3` (красный — явный маркер, ТЗ «явно»; `row.disabled`
  и клик-гард — без изменений). Без `reasonRed` — серый reason + dim
  (старое побайтово, меню эффектов/«Разобрать»/«Диалог» не тронуты — ТЗ
  о списке ПОСТРОЕК);
* `scroll`: оверлей — класс `'combat-overlay' combat-overlay--build`
  (конвенция модификатора `--combat`, 000124).

ПОЧЕМУ: скоуп строго «Строительство» — остальные меню и пины (вкл.
строку `rowA2.reason === 'выступал сегодня'` building-actions.test.js —
она серой остаётся) не сдвигаются.

### R8. Гарды pre-check (тихая деградация, 000053)

* `heroOk = !!hero && typeof hero === 'object'` — НЕ-ОБЪЕКТ hero
  (undefined — тест 000148.04 «buildCityAt БЕЗ deps.hero») → пропускаются
  И золотая часть И предметные (иначе `totalQty(undefined)` роняет
  `ensureInventory` — регрессия, пойманная полным прогоном);
* gold не-число (`Number.isFinite(hero.gold)` ложь) → только золотая часть
  пропускается;
* hasItem отсутствует → предметы считаются имеющимися (как гард
  buildCityAt, но read-only — молча); totalQty отсутствует (hasItem есть)
  → have = `hasItem ? e.количество : 0`; обоих нет → предметная часть
  пропускается;
* итог: при полном отсутствии API строка доступна по геометрии (СТАРОЕ
  поведение), без reason-нехватки. `console.error` при деградации pre-check
  НЕ летит (пин CI-V4 «без ошибок» — самый жёсткий из e2e-пинов);
  единственный console.error — fallback REAGENT_FORMS (R3, недостижим при
  текущем каталоге).

Доступность (gold/items OK) считается через `hasItem` (тот же предикат, что
в buildCityAt — «меню скажет доступно» = «клик не откажет», дрейф между
открытием и кликом закрывает re-check). Дефицит для ТЕКСТА — через
`totalQty` (имеется сколько).
