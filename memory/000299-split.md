# 000299 — сплит: активный персонаж в постройках, диалоги, цены

Дизайн-решения сплита (анализ 2026-11-03, прецедент 000302):

- **Контракт «активный персонаж» — НЕ новый модуль.** Задокументированная
  тройка: `Game.Party` (src/party.js, 000145) + `playerUI.activeCharId`
  (closure src/ui.js L28; per-session, в сейве НЕТ — 000031) + источник
  live-данных `__game.state` (main.js: hero — СНАПШОТ без
  primary/secondary (D3), efir/efirMet/roster — live). Паттерн резолвера —
  src/learn-target.js (000147) / ui-tab-skills.js partyOf. ID-пространство
  'flogiston' | 'efir' | npcId; fallback — тихо на Флогистона
  (Party.active, без console.error).
- **playerUI.toggle — НЕ сетап** (открывает панель [I]: buildPanel +
  display). Новый `Game.playerUI.setActiveCharId(id)` — без панели,
  без saveNow.
- **Владелец мутаций — ВСЕГДА Флогистон** (общий инвентарь 000194).
  «Цены по навыкам активного» = раздельные параметры: owner (hero) —
  платит золотом/получает предмет, priceChar (активный) — только
  buyPriceMult/sellPriceMult (src/sheet.js derived). ЛОВУШКА: sheet
  наёмника без gold → npcBuy с merc-sheet = NaN (undefined < price →
  false, gold -= price → NaN); RED .03 обязан assert gold undefined.
- **Сигнатурная совместимость**: только ХВОСТОВЫЕ опциональные
  параметры (priceChar = owner) — существующие вызовы/тесты бит-в-бит.
- **Уникальные диалоги**: каталожный ключ `для` (scope: отсутствует/"все"
  → любой активный; "efir" → Эфир; "merc" → любой наёмный;
  {роль: melee|ranged|shield|support} → по найм.роль). Фильтр — в
  dialogOptions (src/npc.js L86-137) ПО ПЕРЕДАННОМУ character.
  Требования (харизма/навык/проверка) — тоже по activeSheet.
- **Иконки**: существующие CSS .cp-portraits/.cp-portrait
  (index.html L1061-1080), НОВЫХ CSS/модулей/тегов НЕТ (иначе
  index-order.test.js). Ряд — в оверлее [E] (building-ui.js, перед
  .cp-items в .combat-side) и в NPC-диалоге (npcUI, над вкладками).
  Клик — СВОЯ ветка делегирования (не data-buid/data-npcact — иначе
  уйдёт в raiseSkill/tab-роутинг; прецедент ui-tab-skills.js L505-509).
  buildingUI.executeAction закрывает оверлей ДО onAction — иконки НЕ
  через executeAction.
- **000300 (потребитель .01)**: trainPoints — hero-only (000298) и ЯВНО
  вне контракта .01 (зафиксировать в companions.md) — иначе 000300
  заблокирован; canSchoolTrain чекит character.trainPoints <= 0.
- **Сейв не меняется ни в одной дочерней** (активный — per-session).
- **Порядок мержа .01 → .02 → .03 СТРОГО последовательный** (общие
  ре-пины spec-split + spec-mobs-companions-efir-wording; .02/.03 —
  npc-storage.md + ui.js). 000300 стартует после .01, может идти
  параллельно с .02 (зоны npc.md + train против npc-storage.md +
  dialog — не пересекаются).
- **SPEC-пины на момент сплита**: companions.md 171, npc-storage.md 71,
  items.md 366 (пин spec-split; wc -l = 365 — без trailing newline),
  nH2=68, nH3=41; word-пины: spec-000296-wording (npc.md 26 — не
  трогаем), spec-000297-wording (npc-storage.md 71 — трогают .02/.03),
