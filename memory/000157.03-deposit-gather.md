## 3. Контракт gatherDeposit (src/dungeon.js)

Подпись: **`gatherDeposit(contents, depositId, canFit)`** — 3 аргумента
(ТЗ-сигнатура 2-аргументна, но проверка ёмкости требует героя — решение D1).
Вставить ПОСЛЕ `openChest` (L985-991 на f7b4d3c), до `wanderStep` (L997).
Экспорт — additive в return-объект (L1040-1054) рядом с `openChest`.

* **Атомарность** (паттерн openChest + dry-run 000046 craft.js): проверки
  → ОДНА мутация (`dp.gathered = true`) → результат. Форма возврата:
  `{ok:true, item, amount} | {ok:false, reason}`.
* **Причины отказов — byte-в-точности** (паттерн 'нет такого сундука'/
  'уже открыт'):
  * `'нет такой залежи'` — id не найден (вкл. contents без ключа
    deposits — guard `(contents && Array.isArray(contents.deposits))`);
  * `'уже собрана'` — `dp.gathered === true`;
  * `'не влезает в инвентарь'` — `canFit` не функция ЛИБО `canFit(item,
    amount) === false`.
* **Ёмкость ДО gathered-марки**: «не влезает» → **НОЛЬ мутаций** (deepEqual
  contents до/после — пин GRD-2) → залежь остаётся, повтор после
  освобождения инвентаря.
* **БЕЗ RNG** — ноль вызовов rng в теле (и main-rng, и отдельного потока);
  ноль обращения к Game. Доказательство: goldens D-BOSS-3/ORE-1..8
  остаются зелёными БЕЗ репина (blast-radius = ноль) + GRD-3.
* **Инверсия зависимостей (canFit)**: чистое ядро dungeon.js НЕ видит
  items.js (DI через factory — прецедент 000038/000053). Вызов
  main.js передаёт лениво: `(it, n) => G.canAddItem(hero, it, n).ok`
  (canAddItem — dry-run 000046: слоты + вес, БЕЗ побочных эффектов;
  items.js L447, flat attach к Game — уже экспортирован L1115).
* **Ghost-item (known-limitation, согласовано с chest-ghost 000153.01)**:
  id предмета удалён из каталога МЕЖДУ сборками, а содержимое персистится
  в сейве → `canAddItem` → `{ok:false, reason:'неизвестный предмет: …'}` →
  canFit false → вечный отказ «не влезает в инвентарь»: залежь собрать
  нельзя, но игра не падает, предмет не начисляется. Достигнимо ТОЛЬКО
  со старым сейвом — принять как known-limitation (в награде —
  ghost-guard `if (it)` на всякий случай: `G.getItem(id)` → null →
  предмет не начисляется, msg с id — паттерн 000153.01 chest L2299-2305).

Код (контракт, готов к реализации):
```js
/** Собирает залежь (один раз, 000157.03). Атомарно: проверки → одна
 *  мутация. БЕЗ RNG (golden-контракт). canFit(item, amount) → boolean —
 *  dry-run ёмкости героя (паттерн 000046: вызывающий передаёт
 *  предикат — ядро не видит items.js); не-функция → отказ.
 *  @returns {{ok:boolean, item?:string, amount?:number, reason?:string}} */
function gatherDeposit(contents, depositId, canFit) {
  const deps = (contents && Array.isArray(contents.deposits))
    ? contents.deposits : [];
  const dp = deps.find((x) => x && x.id === depositId);
  if (!dp) return { ok: false, reason: 'нет такой залежи' };
  if (dp.gathered) return { ok: false, reason: 'уже собрана' };
  if (typeof canFit !== 'function' || !canFit(dp.item, dp.amount))
    return { ok: false, reason: 'не влезает в инвентарь' };
  dp.gathered = true;
  return { ok: true, item: dp.item, amount: dp.amount };
}
```

## 4. interactDeposit (src/locations.js) + инвариант «залежь ≠ выходная клетка»

* **`interactDeposit(ds)`** — 11-й экспорт (additive; LOC-1 перечисляет
  10 функций точным списком БЕЗ count-ассерта → 11-й не ломает; заголовок
  «10 функций» — косметика, обновить в коммите). Вставить ПОСЛЕ
  `interactExit` (L433-440), до `exitDungeon` (L446). Чистая (без мутаций/
  RNG — **LOC-2 regex-гиена по ТЕКСТУ файла, вкл. комментарии**: ни
  `require(`, ни `Math.random|mulberry32|hash2|generateSeedPixels`).
  Лень Game НЕ нужна (ds.contents — данные).
```js
// 000157.03: [E] на залежи — доменное событие «собери» (чистая:
// без мутаций, без rng; null — !ds / !ds.dg / не-dungeon / нет
// НЕСобранной залежи под ногами). СОБРАННАЯ не рисуется (000157.02)
// → no-op, как «пустая клетка».
function interactDeposit(ds) {
  if (!ds || !ds.dg || ds.kind !== 'dungeon') return null;
  const deps = (ds.contents && Array.isArray(ds.contents.deposits))
    ? ds.contents.deposits : [];
  const dp = deps.find((x) => x && !x.gathered
    && x.x === ds.x && x.y === ds.y);
  if (!dp) return null;
  return { type: 'deposit', id: dp.id };
}
```
  Решения: только `kind === 'dungeon'` (город — залежей нет по
  генерации); `find` первой не-собранной (двойное залегание на клетке
  невозможно — occupied-Set, пин ORE-4); развод [E] (выход vs залежь) —
  НЕ на уровне функций (они независимы, каждая по своей клетке), а на
  уровне ПРОВОДКИ locationOnInteract (порядок if-веток) — пин e2e DE-3.

* **Инвариант «залежь ≠ выходная клетка»**: выход = центр rooms[0] =
  entrance (000177: единый тайл), safe-зона 5×5 вокруг входа+выхода
  (dungeon.js L392-396) вырезана из `spots`, occupied-Set — залежь
  физически НЕ МОЖЕТ быть на выходной клетке (и вообще в safe-5×5).
  Запиноется СВИПОМ на уровне взаимодействия: LOC-18 (sweep по
  сгенерированным contents по якорям ORE-4: ABYSS 3 формы xp 1..3000 +
  CAVE (37,−12) xp 1..300): (a) ни одна залежь не на (d.exit.x, d.exit.y)
  — точечно; (b) герой на выходной клетке (spawn = exit) →
  `interactDeposit(ds) → null` для ВСЕХ; (c) на клетке КАЖДОЙ залежи
  (посадка ds.x/ds.y напрямую — прецедент tests/locations.test.js
  L470/534/670) → `{type:'deposit', id: dep.id}`. На ребейзе с 000153.03
  проверить, что stairs-down клетка не совпадает с залежью (по
  приоритету переход выигрывает; при совпадении — залежь остаётся).
