# 000377 — панель персонажа [I] на весь экран

Пользовательская UI-задача. Панель [I] (`.char-panel`, `playerUI.toggle`)
занимает ВЕСЬ экран; сняты внешние отступы и «мёртвые» вертикальные поля
вокруг таблиц. Механика FullscreenController (`src/fullscreen.js`,
`tests/fullscreen.test.js`) НЕ менялась — только видимость её DOM-привязки.

## ФОРМУЛА вертикальной области панели

Эффективная высота контента = `100vh − top − bottom − 2·border − padding-top − padding-bottom`.

Снятые с диска значения (index.html, база 23e1c6d7):
- `.char-panel`: `top:12px left:12px right:12px bottom:56px padding:12px 14px border:1px z-index:10`.
  `bottom:56px` — резерв полосы под `.fs-btn` (`bottom:12px` + высота ≈33px = 45px, +11px запаса).
- ДО: контент = `100vh − 12 − 56 − 2 − 24` = **100vh − 94px**.

ПОСЛЕ (000377):
- `.char-panel`: `top:0 left:0 right:0 bottom:0` (лондхенды сохранены, НЕ `inset:0` —
  тест ui-panel парсит именно keys top/left/right/bottom). padding/border/z-index —
  это КОНТУР, не «мёртвый» отступ, не тронуты.
- ПОСЛЕ: контент = `100vh − 0 − 0 − 2 − 24` = **100vh − 26px**.
- Выигрыш от кромок = **68px ≈ 3.6 строки** (строка 13px/1.45 ≈ 18.85px).

Скоуп-оверрайды «мёртвых» отступов таблиц (СКОУП `.char-panel .cp-*`, глобальные байт-в-байт):
- `.cp-section margin-top 10px → 2px` (−8px на заголовок-секцию),
- `.cp-table margin-top 4px → 0` (−4px на таблицу),
- `.cp-items margin-top 4px → 0` (−4px на список).

Экономия по табам (число секций/таблиц вкладки × дельта):
- «Инвентарь» (1 секция + 1 items-тело) = −12px;
- «Снаряжение» (2 секции + 2 items-тела: Снаряжение + Быстрые слоты) = −24px;
- суммарно ~36px на двух целевых таблицах + 68px кромки = **~104px ≈ 5.5 строк**
  дополнительно видно без прокрутки. T3 автоматически: все табы (Навыки/Квесты/
  Магазин/Настройки/Персонаж) сидят в тех же контейнерах `.cp-tabpane` и тех же
  классах `.cp-section/.cp-table/.cp-items` — получают ту же область.

## Кнопка полноэкранного режима — вариант (а) ТЗ: скрытие CSS+токеном

- `body.char-panel-open .fs-btn { display: none; }` (index.html, СРАЗУ ПОСЛЕ
  `.fs-btn:hover`, т.е. ПОСЛЕ базы `.fs-btn` — first-match парсеры пинов резолвят базу).
- src/ui.js — НОВЫЙ хелпер `markPanelOpen(on)` (строковый className, classList в
  DOM-стабах нет — паттерн tipSetDown) + вызов ОДНОЙ СТРОКОЙ сразу после
  `panel.style.display = show ? 'flex' : 'none'` в `toggle()`.
- `toggle()` — ЕДИНСТВЕННАЯ точка смены видимости панели (main.js KeyI/тач-[I]/
  teardown боя/Esc-диспетчер идут все через неё) → хук покрывает ВСЕ входы/выходы.
- Тожен: `char-panel-open` ∈ body.className ⇔ panel.style.display === 'flex'.
- change-guard (`if (on && i<0)` / `if (!on && i>=0)`) — повторный open/close идемпотентен.
- null-guard `document.body` (ранний boot/чужие стабы без body — no-op, не крах).

### Почему НЕ (б) «кнопка поверх оверлея» и НЕ (в) «FS-контрол в заголовок»
- (б) требует поднять эффективный z кнопки над inline-25 панели → правка frame-блока
  `src/main.js` (ВНЕ SCOPE, main.js неизменяем) либо перестановка DOM-порядка; плюс
  перекрывало бы последнюю строку правой колонки = запрещённое «вырезание».
- (в) вне панели кнопка исчезла бы совсем (регрессия видимости 000017/000256 в
  мире/городе/подземелье), а дублирование контрола ломает пин «в body ровно одна
  .fs-btn» (tests/fullscreen-button-overlay FS-2) и тоже требует main.js.
- display:none снимает и z-конфликт в городе/подземелье: там панель и кнопка оба
  получают inline z-25 (000206/000256) — панель (позже в DOM) накрывала бы кнопку;
  CSS скрывает её при любом inline zIndex main.js (main.js display НЕ пишет).

## Принятые деградации (осознанно, НЕ чинить в этой задаче)
- Выход из FS жестом мыши недоступен при ОТКРЫТОЙ панели: приемлемо — панель [I]
  закрывается [I]/[Esc]/«закрыть», кнопка возвращается мгновенно; браузер сам
  перехватывает Esc для выхода из FS (fullscreenchange-подписка main.js синхронит иконку).
- `bottomInset()` (ui.js ~2285) читает `fsBtn.offsetHeight + 12` для раскладки tc:
  resize при ОТКРЫТОЙ панели (кнопка display:none ⇒ offsetHeight 0) опустит [E]/[I]
  на ~45px ниже; перезапишется на следующем resize после закрытия. Мелочь на тач-
  режимах; починка = трогать controls/main (вне SCOPE).
- tc-кнопки (z-30) теперь поверх полноэкранной панели (перекрывают нижние строки
  прокручиваемого контента на тач-режимах) — существующая лестница, новая экспозиция.
  Полное сокрытие tc при открытой панели — вне скоупа (ломает предикат 000150, урок 000376).
