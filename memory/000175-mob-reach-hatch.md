Контракт (стадия Проектирование, финальная). Задача: `tasks/pending/000175.md`

## 1. ТЗ и решения о семантике

ТЗ: «В бою при выделении моба добавить лёгкую штриховку тайлов, до которых он
может добраться за один ход». Секций в файле ТЗ НЕТ — вся детализация ниже.

* **D1 (семантика) — «достигается за один ход» = зона ДВИЖЕНИЯ (movement
  range), НЕ симуляция ИИ.** Набор = куда моб МОЖЕТ встать за ≤ movePerTurn
  шагов. Реальное поведение mobAct (ranged/support/leader реально делают
  1 шаг/ход даже при fast; остановка в полосе удара, отступление, ретрит) НЕ
  моделируется — иначе превью зависело бы от ИИ-намерения, а ТЗ говорит о
  досягаемости. Задокументированное завышение превью: fast wind_elemental —
  2 клетки превью, 1 шаг в ИИ.
* **D2 (выделение) — единственное «выделение моба» в коде = c.targetId.**
  Клик по живому мобо → c.selectTarget (combat-ui.js build(), ядро
  playerSelectTarget combat.js:1416 — союзник/мёртвый/fled отклоняются);
  авто-цель nearestMob — в createCombat (×2) и advanceQueue на слоте игрока;
  на ходу союзника (000168) — nearestEnemy. Авто-цель ВСЕГДА указывает на
  ближайшего живого моба, пока жив хотя бы один → штриховка видна СО СТАРТА
  боя и следует за перецеливанием кликом (в т.ч. на ходу союзника).
* **D3 (бюджет шагов) — `u.movePerTurn || 1` для ВСЕХ ролей** (fast → 2,
  combat.js:292). Пер-ролевой бюджет отклонён: связка с ИИ-ветками mobAct,
  ТЗ молчит, атрибут «шаги за ход» — задокументированное capability моба.
* **D4 (старт) — стартовое положение ИСКЛЮЧАЕТСЯ из набора.** «Куда может
  дойти» ≠ «где стоит»; штриховка под собственным спрайтом — шум. (1×1:
  ровно 4 соседа при steps=1; fast: 12 при steps=2 на открытом поле.)
* **D5 (мультиклеточные мобы) — объединение ВСЕХ клеток**, покрываемых
  прямоугольником w×h (u.size, 2×2/3×3) на каждом достижимом якоре. Якорь —
  верхний левый угол (канон combat.js).

## 2. Ядро: src/combat.js

* **Сигнатура: `mobReachCells(c, u)`** — чистая функция, возврат `Set<'x,y'>`.
  (Имя — D-решение: mobReachCells, паттерн соседнего экспорта reachableCells;
  альтернатива mobReachableCells отклонена.)
* **BFS-контракт** (по канону reachableCells :397 + pathField :694):
  - старт — якорь (u.x, u.y); `dist` Map 'x,y'→глубина, очередь — массив +
    индекс (FIFO); соседи — 4 в порядке **PATH_DIRS** (combat.js:684, ↑ ↓ ← →);
  - глубина ≤ `steps = u.movePerTurn || 1`; клетка добавляется в результат
    при ОТКРЫТИИ (глубина d+1 ≥ 1) → старт исключается автоматически;
  - проходимость — `rectFree(c, nx, ny, w, h, u)` (combat.js:485), ignore =
    сам моб: стены = границы поля, клетка игрока (c.px/c.py), c.obstacles,
    другие живые не-fled юниты — ТО ЖЕ, что у реального шага моба
    (pathStepTo/mobAct), т.к. в ходе моб никто другой не двигается;
  - порядок вставки в Set = порядок BFS (FIFO + PATH_DIRS) — детерминирован
    (итерация Set в render даёт стабильный порядок штрихов);
  - **чистота: 0 c._rng, 0 мутаций c/u, 0 новых полей c** → сейвы/детерминизм
    боя не тронуты (UI-состояния в сейвах нет, в ядро — ничего нового).
* **Место вставки:** ПОСЛЕ `reachableCells` (завершается :414), ДО
  комментария `// --- Зоны групп (задача 000135) ---` (:416) — рядом с
  каноническим BFS, чью форму повторяет.
* **Экспорт:** return-объект (:3067) — `mobReachCells,` рядом с
  `reachableCells,` (:3081) + комментарий «задача 000175».
  `combatInternals` — 0 правок.

## 3. UI: src/combat-ui.js

* **Гейт (D6): штриховка — только когда c.targetId указывает на ЖИВОГО
  не-fled юнита `side === 'mob'`.** БЕЗ фазовых и result-гейтов — ровно
  условие жёлтого кольца цели в drawUnits (:879): штриховка появляется и
  исчезает точно тогда, когда кольцо (ассоциация «выделенный моб»).
  В сценах targetId=null / мёртвая цель / союзник-цель (000166) / fled —
  **НОЛЬ новых g2-вызовов** (бит-в-бит рендеры: golden 000084, CU166).
* **z-порядок (D7) — слой МЕЖДУ сеткой и препятствиями:**
  фон → сетка → **ШТРИХОВКА** → препятствия → юниты → эффекты. Точка вставки
  вызова `drawMobReachHatch(c)` в render() — ПОСЛЕ двух for-циклов сетки,
  ПЕРЕД блоком «Состояние героя» (:1090), т.е. до блока препятствий (:1113).
  **КРИТИЧНО:** пин 000050 (tests/combat-ui.test.js :989-1001) считает
  `lastGridStroke` = ПОСЛЕДНИЙ 'stroke' во ВСЕМ drawCalls и утверждает
  `iObs > lastGridStroke`. Штриховка — stroke; слой ПОСЛЕ препятствий (как
  предлагали аналитики домена/архитектуры) этот пин ЛОМАЕТ. Между сеткой и
  препятствиями пин держится (последний stroke = последний штрих, он до
  препятствий). Коммент 000050 «сетка — единственные stroke» становится
  устаревшим — КОД теста не правится (инвариант «без правок»).
* **Геометрия (D8): одна диагональ 45° на клетку, inset 8px** (конвенция
  спрайта юнита: golden 000084 — drawImage на ex+8/ey+8, 32×32):
  на клетку — `beginPath(); moveTo(px+8, py+40); lineTo(px+40, py+8);
  stroke();` (px = x·48, py = y·48, CELL=48). Одна диагональ (а не 6
  сегментов) — «лёгкая штриховка» ТЗ: в 6 раз меньше примитивов и 1 stroke
  = 1 клетка (тривиальный декод в тестах). Стиль — ОДИН раз до цикла:
  `g2.strokeStyle = MOB_REACH_HATCH; g2.lineWidth = 1;`. Итерация по Set
  (порядок вставки — детерминирован, паттерн препятствий :1128).
* **Цвет (D9): `MOB_REACH_HATCH = 'rgba(255, 226, 122, 0.35)'`** — низкая
  альфа на подсветке цели #ffe27a (rgb 255,226,122); паттерн 000084
  ALLY_MARKER_UNDERLAY (производное от существующего палитрового цвета +
  альфа, «новых цветов не вводим», 000038). Жёлтая семья = семья
  ВЫДЕЛЕННОЙ ЦЕЛИ (штриховка — атрибут выбранного моба, как кольцо);
  красный #d9483b отклонён — это ROLE_COLORS.melee (роль melee, а не
  «любой моб»). Строка УНИКАЛЬНА: не совпадает ни с одним закреплённым
  styleCalls-значением (#ffe27a — точный непрозрачный, ROLE-цвета — точные,
  grid rgba(255,255,255,0.18), underlay rgba(140,242,252,0.25), #3a4150,
  #0d1117, #6fdc6f, #8cf2fc). Константа — после ALLY_MARKER_UNDERLAY (:82).
* **Деградация (D10): УМД-ловушка 000038** — G снимается один раз при
  загрузке (:59); combat.js грузится ДО combat-ui.js (index.html, пин
  index-order) → экспорт в снапшоте на практике всегда. Guard
  `typeof G.mobReachCells === 'function'`; нет → `console.error` ОДИН раз
  (модульный флаг `let reachWarned = false;` рядом с measureWarned :124,
  паттерн :164-165) + штриховка не рисуется, рендер не падает.
* **НОВЫХ МОДУЛЕЙ/АССЕТОВ/CSS/SCRIPT-ТЕГОВ НЕТ** — index.html,
  tests/index-order.test.js, tests/svg.test.js, assets/ не трогаются.
  createPattern сознательно НЕ используется (стаб canvas в vm-песочнице его
  не умеет; ручные линии = детерминированные пины drawCalls).
* **Место функции:** `drawMobReachHatch(c)` — после `drawBreathFx`
  (:979-1021), до `render()` (:1023). НЕ ТРОГАТЬ: build()/клик (:195+),
  drawUnits, canDoAction/runAction/handleCode/finish — чисто аддитивный дифф.
