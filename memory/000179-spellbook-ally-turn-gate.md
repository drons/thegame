## 1. Суть бага (регрессия 000168)

Игрок может кастовать СВОИ заклинания из ОТКРЫТОЙ книги заклинаний на ходу
спутника (наёмника/Эфира): клик по строке книги → `castRow` (src/combat-ui.js)
→ `G.Spells.castSpell` → `evalSpell` (src/spells.js L322) проверяет ТОЛЬКО
`checkTurn` (`c.phase === 'player'` / `'over'`). С 000168 (e80a737) ход
спутника — интерактивный `c.phase === 'player'` (единая союзная ветка
advanceQueue — ввод от лица союзника) → checkTurn проходит → заклинание
ИГРОКА (evalSpell читает c.player/c.ps) тратит пул/ману ИГРОКА, а эффект
(включая убийство моба → victory) срабатывает вне хода игрока.
Контракт 000168 «книга — только игрок» был соблюдён только для КНОПКИ
(canDoAction → allyCanDo 'spellbook' → «недоступно активному персонажу»,
src/combat.js L2175-2177; пин 000168-UI-2), но НЕ для строк открытой книги:
`bookOpen` (closure combat-ui.js L144) не сбрасывается endTurn, и
rowChk = canCastSpell → на ходу спутника ok:true → строки рисуются
активными.

Репро (master 0f18ed0, подтверждено node-репро /tmp/thegame-wf-000179/
repro179*.js и vm-симуляциями sim-cu179-*.js): createCombat (wolf, seed 42,
hero ['spark','mend']) + наёмник в конце очереди → c.endTurn() →
activeUnitId 'a1', phase 'player' → canCastSpell 'spark' ok:true →
castSpell ok:true: пул spellInt 1→0, mp тратится, волк убит → ПОБЕДА.

## 2. Почему регрессия произошла

000168 сделал ход ЛЮБОГО союзника фазой `phase='player'` (игрок управляет
спутником — движение/атака/лечение/Касание). Все «player-only»-гварды боя,
написанные до 000168, проверяли только фазу (`checkTurn`) и после 000168
стали пропускать ввод на ходу спутника. 000168 закрыл зазор для действий
через КНОПКИ/КЛАВИШИ (canDoAction → allyCanDo — контекстная таблица:
fire/block/quickItem/invItem/flee/spellbook → «недоступно активному
персонажу»; c.cast/c.heal — core-гварды), но путь каста через СТРОКУ
книги (castRow → G.Spells.castSpell) обошёл canDoAction — движок 000045
не знает про activeUnitId. bookOpen не сбрасывается endTurn — открытая на
ходу игрока книга остаётся открытой, и «живые» строки видны на ходу
спутника.

## 3. Где гейт (после фикса)

ОДИН файл — `src/combat-ui.js`, 3 точки (секция «Книга заклинаний», L1494+):
1. Новый хелпер `spellbookUnitGate(c)` (вставка перед rowChk ~L1571):
   порядок ФИКСИРОВАН (зеркало resurrectChk 000171):
   `c.result` → «бой закончен»; `c.phase !== 'player'` → «не ваш ход»;
   `(typeof G.activeUnitId === 'function' ? G.activeUnitId(c) : 'player')
   !== 'player'` → «недоступно активному персонажу»; иначе null (проход).
2. `rowChk` — гейт ПЕРВОЙ строкой: строки книги на ходу спутника рендерятся
   `.combat-spellrow-off` + title (tooltip) «недоступно активному
   персонажу» — ровно как гаснущая кнопка (контракт 000171: disabled +
   tooltip, а не скрытие).
3. `castRow` — предпроверка ПЕРВОЙ строкой: стаб-клик → logRejection
   (ровно одна строка причины в c.log), КАСТА НЕТ, трат НЕТ, c._fx не
   пишется, очередь не сдвигается, книга остаётся открытой (UX 000149).

Строка причины — ДОСЛОВНО «недоступно активному персонажу» (та же, что
allyCanDo('spellbook') 000168 и resurrectChk 000171 — «одна строка — одна
причина» для player-only действий на ходу союзника).

Ядро (combat.js/spells.js), endTurn/advanceQueue, index.html, CSS, assets —
НЕ ТРОГАЮТСЯ. Книга НЕ закрывается при endTurn (решение: только гейт —
красный тест ТЗ требует клика по ОТКРЫТОЙ строке на ходу спутника; см.
контракт §2.1).
