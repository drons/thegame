## 2. Контракты и границы

### 2.1 Формат ссылок в каталоге (D1)
* Схема поля-ссылки (assets/skills/schema.json): `pattern` = REF_RE.source —
  единый источник scripts/lib/json-ref.js, верbatim:
  `^assets\/(items|skills|spells|mobs|mob_groups|buildings|craft|dungeons|npc)\/\d{6}\.json$`
  (в JSON-тексте — с удвоенными бекслэшами `\\d`, `\\.`, `\\/`; патчить
  ПРОГРАММНО из REF_RE.source, не набирать руками).
  Затрагиваются ровно 2 под-схемы (ветка secondary oneOf[1]):
  - properties.primary: `{type:'string', enum:[6 id]}` →
    `{type:'string', pattern: REF_RE.source}` — enum УБИРАЕТСЯ
    (иначе схема отклоняет все 31 migrated файл — молчаливо красная
    assets-schemas-валидация);
  - properties.requires.properties.skill: `{type:'string',
    pattern:'^[a-z][a-z0-9_]*$'}` → `{type:'string', pattern: REF_RE.source}`.
* Почему общий union, а не skills-only `^assets/skills/\d{6}\.json$`
  (вариант a1, ОТКЛОНЁН): (а) ТЗ буквально — «якорный паттерн §2 контракта»,
  а §2 аудита = этот union; (б) uniformity серии: у 000211.03 (mobs)
  cross-catalog поля skills[]/spells[]/loot[].item — единое правило
  «поле-ссылка = REF_RE.source» работает во всех .02–.08 без per-field
  вариантов; (в) пин теста === REF_RE.source — без дублирования
  экранирования; (г) семантика «таргет — навык» держится НЕ схемой, а
  красными тестами SR2/SR3 (id таргета = значение зеркала = id навыка) +
  hard-fail sync + byte-гейтом зеркала (ошибка таргета изменила бы зеркало →
  git diff непуст → дрейф-гейт красный). Отклонён tighter-вариант — осознан
  трейд-офф, зафиксирован здесь; sweep AR8 от выбора не зависит.
* additionalProperties:false — 4 места ИНТАКТНЫ (oneOf[0], oneOf[1],
  requires, effect); новых полей нет (000141).
* Валидатор tests/json-schema.js поддерживает pattern (new RegExp
  без флагов) — проверено; ALLOWED_SCHEMA_KEYS уже содержит 'pattern'.
