## 2. Решения (D1–D10, «решение — почему»)

**D1. Источник иконки — `G.SpellsData.SPELLS_BY_ID[id].icon` через чистый
lookup `spellIconForId(id) → string|null`.** — каталог — единый источник
правды (конвенция `row.icon` строки книги — пин CU196-DESC; иконку НЕ
вычислять из id); деградация (нет каталога — vm-сцены без withSpells,
напр. 000124; неизвестный id; иконка не-строка/пусто) → null →
собственная иконка кнопки, ТИХО (0 console.error) — это презентация без
каталога, а не сломанная зависимость (паттерн bookRows/spellBtnOf —
тихое чтение G).

**D2. Три точки обновления: (a) build() — сидованный выбор; (b)
recordLastSpell() — момент смены выбора; (c) render-цикл — иконка
АКТИВНОГО владельца, только видимая кнопка, сменогвард.** —
(a) ОБЯЗАТЕЛЕН: песочница vm-full tests/save-restore.test.js —
`makeEl.querySelectorAll() { return []; }` (L113) → render-цикл
`overlay.querySelectorAll('.combat-actions button').forEach(...)` —

«бой 2 — то же заклинание НА КНОПКЕ» наблюдаемо ТОЛЬКО через
build-time set (walk-DOM `children[0].src`);
(b) — иконка после каста в бою 1 в vm-full (тоже прямое наблюдение);
(c) — корректность в РЕАЛЬНОЙ игре при 2+ целителях (кнопка «Лечение»
одна — иконка следует за активным владельцем; паритет с бейджем
