# 000205 — Боевой опыт делится поровну между всеми участниками

ТЗ (tasks/pending/000205.md, две строки): «Опыт после боя должен делиться
поровну между всеми кто в нём принимал участие (Флогистон, Эфир, союзные
NPC), иначе Эфир и союзные NPC имеют сильно меньший уровень и бесполезны
в бою.» До 000205: игрок 100%×«Учёный», Эфир 100% (finish), каждый
ВЫЖИВШИЙ наёмник — `companion_xp_share` = 50% независимо.

## 1. Что добавлено / изменено

## 2. Контракты и границы

- **Кто «участник»:** ТЗ буквально — «все кто в нём принимал участие».
  Погибший в бою наёмник — участник: в N И в allyXp. его доля
  сохраняется: combatEndCompanions применяет applyCombatXp ДО
  deadMercs-сплайса (serializeDeadRecord читает запись ПОСЛЕ
  applyCombatXp) → dead_mercs-запись несёт level/xp (SPEC «Спутники»:
  гибель — с сохранением уровня/опыта; цена воскрешения
  round(база + за_опыт × totalXp) учитывает рост согласованно).
  ПогибШИЙ Эфир — в N и получает efirXp: правило 000081/000035#11
  «БЕЗ условия выживания» + e2e main-visuals CB-8/CB-9
  (resolveCombatVictory убивает Эфира ДО победы и пинит efir.xp > 0 —
  этот пин и требует долю мёртвому Эфиру).
- **N стабилен:** `c.units` не пополняется в бою (воскрешение 000162 —
  flip alive существующего юнита) → N детерминирован на момент
  checkVictory.
- **Края:** N=1 (0 союзников) — игрок получает ВСЕ xp — бит-в-бит с
  поведением до 000205 (все соло-пины зелёные без правок). xp=0 (все
  мобы сбежали) — ветка 'fled', полей нет. Неизвестный kind у
  союзного юнита (в игре недостижимо; синтетика): ВХОДИТ в N (это
  союзник-участник), доли не получает — allyXp-фильтр остаётся
  ПОЛОЖИТЕЛЬНЫМ `kind === 'merc'` (устойчивость 000082 к spelling
  'ether' сохранена), efirXp — только kind 'efir'.
- **Остаток — Флогистону** (не «первым rem участникам в произвольном
  порядке»): якорь-протагонист; правило одно, детерминированное.
  «Поровну» выполняется с точностью до остатка (≤ N−1 xp суммарно;
  на участника ≤ 1) — ТЗ-цель (спутники не «сильно меньше») достигнута
  полностью.
- **Эфир — НИКОГДА не в allyXp** (идёт через efirXp): строка main.js
  «Спутники: +N опыта (Имена).» не выведет «efir» (нет в каталоге
  NPC-спутников). Эфир — никогда в deadMercs (000087, структурно).
- **Строка «Спутники: +N опыта (Имена).»** работает без изменений:
  доли у ВСЕХ наёмников ОДНАКОВА (`base`) → `gained[0].xp` корректен;
  в именах теперь могут быть наёмники, погибшие в этом же бою
  (записи ещё в roster на момент xp-строки — splice позже) — правдиво:
  они участвовали.
- **Детерминизм:** 0 новых `c._rng`; порядок операций: xp-сумма →
  gold-роллы → P.addXp(игроку, доля) → gold += → allyXp/efirXp
  (чистая арифметика) → rollVictoryLoot → c.result. Бит-в-бит пины
  000132-N/соло — без правок.
- **Сейвы:** структуры roster/efir/hero/dead_mercs не меняются →
  CURRENT_VERSION НЕ бампится (000031); companion_xp_share —
  session-only → 0 миграций; валидаторы сейвов — как есть.

## 3. Ленивые ссылки и guards

- **Единая точка расчёта — checkVictory** (паттерн allyXp 000082:
  потребители читают c.result, НЕ пересчитывают): finish() читает
  `result.efirXp`; combatEndCompanions читает `res.allyXp`. Никакой
  формулы N/доли вне ядра.
- **finish():** `ctx.efir != null` — только когда G.efir был доступен
  на startCombat (снапшот G неизменен); гвард
  `result.outcome === 'victory' && result.efirXp > 0` — мутационные
  тестовые result БЕЗ поля efirXp (старый формат) → guard false →
  тихий skip, краха нет (деградация). try/catch 000170: исключение в
  addEfirXp — logged once, finish доходит до onEnd/ctx=null.
- **applyCombatXp (companions.js):** тихий skip на неизвестный id /
  xp ≤ 0 / не-массив — без изменений; доля погибшего мерса
  применяется, пока запись в roster (до сплайса).
- **Гвард outcome:** 'fled'/'dead' — полей allyXp/efirXp/items нет;
  main.js combatEndCompanions гвардит `outcome === 'victory'` —
  без изменений (пины `!('allyXp' in result)` зелёные).
- **Деградация без efir.js:** юнита Эфира в c.units нет → N без Эфира,
  efirXp = 0, finish-гвард пропускает; бои бит-в-бит с соло+мерсы.

## 4. Что важно будущим задачам

- `c.result.efirXp` — контрактная форма для finish(): число, victory
  только, 0 без Эфира. Новая логика начисления Эфиру — ЧЕРЕЗ это поле
  (не пересчитывать долю в consumers).
- `c.result.xp` — СУММА (отображение/квестовые строки). Не путать с
  долями; «Победа! +X опыта» — это всегда сумма добытой группы.
- Рост Эфира между боями ЗАМЕДЛИЛСЯ (был 100%, теперь 1/N):
  000119 battle119 баланс-пороги (hpFrac/rounds) — XP статы в бою НЕ
  меняет (очки не тратятся автоматически), но если баланс-пин упадёт —
  проверять по доверию (ложная краснота), не по догме.
- Игрок при «Учёном» > 0 всё равно растёт чуть быстрее Эфира
  (xpMult к его доле) — остаточный разрыв по ДИЗАЙНУ (бонус навыка),
  не дефект (ТЗ-формулировка «Эфир имеет сильно меньший уровень» —
  фактически верна только для наёмников 50%; для Эфира разрыв был от
  «Учёного»/практики игрока).
- companion_xp_share НЕ СУЩЕСТВУЕТ: новые механики доли спутников —
  без этого ключа; если потребуется настройка доли — НОВЫЙ ключ
  (+META явная запись + S1-ре-пин, паттерн 000098).
- Доля погибшего мерса живёт в dead_mercs-записи (sheet.xp/totalXp) —
  воскрешение (000162) уже учитывает её (цена от totalXp).
- SPEC-фразы «100% боевого опыта» в companions.md/efir-spirit.md
  заменены на «равная доля (000205)» — новые ретро-сверки SPEC↔код
  опираться на 000205-формулу.
