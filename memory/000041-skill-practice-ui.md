# 000041: прогресс практики навыков в панели персонажа (src/ui.js)

Ядро практики (задача 000013: `c.skillXp[id]`, `G.skillXpForNext(level)`,
`G.practiceCap(c, skill)`, `G.MAX_SKILL_LEVEL`) не тронуто — изменён только
рендер вторичных навыков в `render()` панели (src/ui.js, цикл
`panel.querySelectorAll('.cp-btn')`).

## Форматы отображения

* `.cp-level` вторичного навыка:
  * `bank > 0 && lvl < MAX_SKILL_LEVEL` → «`lvl (bank/need)`», где
    `bank = (c.skillXp && c.skillXp[skill]) || 0` (защита от старых сейвов
    без skillXp), `need = G.skillXpForNext(lvl)` = 15·(lvl+1).
    Пример: «3 (12/60)».
  * пустая копилка (нет ключа / bank = 0) → просто «`lvl`» (без «(0/N)»);
  * `lvl = MAX_SKILL_LEVEL (100)` → просто «100» даже при bank > 0
    (порог на максимуме бессмысленен).
  * Копилка рисуется ТОЛЬКО у вторичных навыков; у основных — число.
* `.cp-req` вторичного навыка (ячейки нет в строках основных):
  * `0 < lvl < 100 && lvl >= cap` → «потолок практикой: `<имя основного>`
    `cap/2`×2 — дальше растёт только очками и книгами» (напр. «потолок
    практикой: Сила 5×2 — …»). Имя — `G.PRIMARY_SKILLS.find(p =>
    p.id === s.primary)`. Показывается и при lvl > cap (навык поднят
    книгами — практика всё равно не работает).
  * `lvl = 0` → `requiresText(s)` (как раньше); `lvl > 0` ниже потолка → ''.
  * `lvl = 100` → '' (без пометки).

## Известные граничные случаи

* `cap = 0` при `lvl > 0` (навык поднят книгами при основном 0):
  `lvl >= 0` — пометка «потолок практикой: Сила 0×2» показывается —
  фактологически верно (практика не даст ни уровня).
* Клетка `.cp-req` совмещена с «вспышкой» причины неудачи raiseSkill
  (клик по «+» пишет reason в .cp-req на 1.5 с) — пометка потолка может
  быть временно перезаписана и восстанавливается следующим render();
  функционально допустимо, тесты не смешивают клик и проверку пометки.

изменение `c.primary.*` / `c.secondary.*` / `c.skillXp`;
`openPanel(env, c)` = `playerUI.setCharacter(c)` + `playerUI.toggle(true)`.
