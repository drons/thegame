# Разбиение main.js и ui.js — план (задачи 000127–000130)

Решение от 2026-09-30 (обсуждение с пользователем): параллелизм
разработки ограничен зонами src/main.js (~1776 строк) и src/ui.js
(~1239) — почти каждая игровая волна правит одни и те же ханки
([E]-wiring ~600-700, состояние подземелья/города ~900-1160, HUD
~1400, __game.actions ~1647; вкладки панели — один регион ui.js).
План: точечное выделение ДОМЕННЫХ модулей (не ре-архитектура) —
основание для цепочек: эффекты (000074+), города (000107/000109/
000110), панели (000098/000099/000101/000126/000083/000086).

## Правила

* Рефакторинг БЕЗ смены поведения: детерминизм, RNG (ноль новых
  вызовов), сейвы, HUD-выводы, тесты-фиксаторы — зелёные без правок
  (если тест правится — только под новый путь require/import, не
  семантику).
* UMD-ловушка 000038: каждый новый модуль — ЧИСТЫЙ (взаимных
  require в момент загрузки нет, прецедент 000053); снапшот Game —
  один раз; ленивые ссылки — в момент вызова (rootRef-паттерн).
* Порядок: script-теги ДО main.js (locations.js — после
  cities.js/dungeon.js; building-actions.js — после building-ui.js;
  hud.js — после building-actions.js; ui-tab-* — порядок по
  анализу) + pin в tests/index-order.test.js.
* Не резать: combat.js (редкие задачи, доменно-чистый), map.js
  (стабилен после 000073), зеркала (buildings/craft-data — конфликт
  механический, решается регенерацией).
