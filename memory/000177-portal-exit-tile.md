### 2.2 Механика выхода — ТОЛЬКО [E] на тайле
- **`L.interactExit(ds)` — единственный доменный путь события «выход»:**
  ```
  interactExit(ds) → null | { type: 'exit', name }
  ```
  null: `!ds` / `!ds.dg` / kind вне {city,dungeon} / герой НЕ на совмещённом
  тайле (`ds.x !== ds.dg.exit.x || ds.y !== ds.dg.exit.y`).
  name: city — `ds.name`; dungeon — `dungeonName(ds.dg)` (DUNGEON_NAMES —
  та же строка, что в flash на master). Чистая: без мутаций, без RNG,
  без muвер'ов; lazyGame() — только dungeonName (уже в модуле).
- **Шаг на совмещённый тайл = обычный `{type:'moved'}`** (позиция сдвинута,
  mover.step, проверка моба/сундука/wanderStep — как для любого пола).
  Событий `{type:'exit'}` из dungeonMove/cityMove **НЕТ** (ветки удалены).
  Мобы/сундуки на тайле НЕ генерируются (safe 5×5), но блуждающий МОБ может
  дойти до двери позже: [E] на двери всё равно = выход (interactExit не
  смотрит на мобов) — зафиксировано как поведение.
- **`exitLocation` (main.js L2174-2191) — НЕ ТРОГАЕТСЯ** (КОНТРАКТ 000170,
  memory/000170-movement-freeze.md §5): [E]-выход идёт через НЕЁ →
  try/catch/finally { dungeonState=null; G.dungeonUI.close(); saveNow() }
  сохранён. Любое БУДУЩЕЕ изменение выхода обязан вести через exitLocation.
- День: dungeon-выход — ДЕНЬ+1 (clock.event('dungeon') — exitDungeon не
  меняется); city-выход — ДЕНЬ НЕ проходит (exitCity no-op — не меняется).
- Flash: `'Вы вышли из ' + ev.name + '.'` — **СЛОВО В СЛОВО** (000127),
  hudFlashUntil = performance.now() + 5000 — как было.
- Повторный авто-вход НЕТ: enterLocation вызывается только при успешном
  МИРОВОМ шаге (main.js frame L2807-2828) — после выхода герой стоит на
  мировом тайле пещеры/города (гейт НЕ менять).
- Гейты [E] не меняются: dungeon-ui keydown L269-291 (combatUI выше по
