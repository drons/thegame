# 000042: постройка — один w×h-спрайт по footprint'у, от якоря

Статус: реализовано (тесты 512 → 516 pass / 0 fail). Follow-up задачи
000026 (много-тайловые постройки, memory/000026-building-sizes.md):
tileAt/hasBuilding/стены были готовы, не было только отрисовки —
спрайт рисовался 1x1 на тайле входа, 3x3-постройка выглядела как
одиночный спрайт на голом террейне, декорации (000039) вырастали
«на стене».

## Решения

* **Геометрия — из записи размещения, не из скана.** src/map.js:
  createMap экспортирует `buildingAt(ax, ay)` — read-only O(1)-обёртка
  над мемоизированной `buildingAtAnchor`: запись {anchor, type, x, y,
  w, h, entrance, wealth} или null. Источник геометрии footprint'а
  ОДИН — та запись, что раскладывала постройку в мире. Скан краёв
  вправо/вниз по tileAt БЕЗ проверки равенства buildingAnchor
  зальётся чужой соседней постройкой (ложные 2x1/1x2) — закрыто
  тестом на плотной синтетике A=255.
* **drawSprites (src/main.js) — ТРИ прохода по frameTiles**, порядок
  слоёв: (1) текстура тайла + декорации, (2) постройки, (3) мобы;
  Флогистон — после всех. Единый по-тайловый цикл больше НЕ
  используется для спрайтов: w×h-прямоугольник «по тайлам» невозможен
  — текстуры СОСЕДНИХ тайлов footprint'а (каждая итерация рисует свой
  тайл) перерисовали бы часть прямоугольника.
* **Постройка — ОДИН раз на постройку.** Проход 2 собирает якоря
  видимых тайлов-членов в Set за кадр (ключ «ax,ay») и рисует
  `drawImage(spr, worldToScreen(ax, ay), w·zoom, h·zoom)`. Якорь сам
  может быть за краём окна (запас зума < 3), поэтому Set — по якорям
  ВИДИМЫХ тайлов, а не по якорным тайлам.
* **Декорации на стенах выключены** — условие 000039
  `if (showVisuals)` → `if (showVisuals && !(t.inBuilding &&
  !t.isEntrance))` (одна строка, как обещано в memory/000039). Вход
  декорации сохраняет (игрок взаимодействует там).
* **Фолбэк под устаревший map.js** (typeof-гард `map.buildingAt`):
  скан прямоугольника вправо/вниз по tileCache, но с ПРОВЕРКОЙ
  РАВЕНСТВА buildingAnchor (одного inBuilding мало); якоря нет — 1x1.
  ВНИМАНИЕ: кламп скана `G.BUILD_MAX_W || 3` / `G.BUILD_MAX_H || 3` —
  на master после задачи 000055 константы переименованы в
  `buildMaxW()`/`buildMaxH()`: `undefined || 3` пока совпадает
  случайно (максимум каталога 3x3), при правке брать `G.buildMaxW ?
  G.buildMaxW() : (G.BUILD_MAX_W || 3)`.

## Тесты

* tests/map.test.js +1 «buildingAt: геометрия footprint'а — якорь →
  запись, не-якорь → null»: фолбэк-мир (generateSeedPixels) + плотная
  синтетика A=255, скан ±40: запись == пересчёт по tileAt (каждый
  тайл прямоугольника — тот же якорь и тип; вход внутри; правый/
  нижний край — НЕ этот якорь — по равенству якоря, не по
  inBuilding), не-якорь → null (и в чужом footprint'е).
* tests/main-visuals.test.js +3 (vm-песочница, вся цепочка
  `<script>` из index.html, детерминированный фолбэчный мир):
  * footprint рисуется ОДИН раз w×h с якоря (мультимножество
    drawImage == пересчёт; для пройденной постройки ровно один вызов
    на якоре w×h и НОЛЬ по старой 1x1-формуле на входе);
  * декорации на тайлах-стенах не рисуются (тест не вакуумный: >= 1
    стена с потенциальной декорацией в кадре);
  * порядок слоёв: текстура < декорации < постройка (rect w×h) <
    мобы < Флогистон.
  * СЦЕНАРИЙ (общий для трёх тестов): игрок из спавна (0,0) ХОДИТ по
    BFS-путью (на шаг keydown → frame(now+=200) → keyup; mобы/входы
    пещер исключены, день на пороге — onDay безопасен) до ближайшего
    входа multi-постройки — храм 3x3, якорь (6,28), вход (7,30),
    39 шагов; в конце 4 «осадочных» кадра (глейд мувера + камера),
    cam/zoom — из `__game.state` ПОСЛЕ кадра. Это заодно
    интеграционный чек: стены непроходимы (BFS их не режет), вход
    достижим, спрайт стоит на месте при движении камеры (якорь
    детерминирован).
* Обновлены тесты 000039: expectedDecos пропускает стены; маркер
  постройки в «порядок слоёв» — якорный rect w×h.

## Подводные камни (для будущих правок drawSprites)

* **Новая вещь на спрайт-слое — отдельным проходом** в нужном месте
  порядка слоёв, НЕ возвращаться к единому циклу frameTiles: всё, что
  шире/выше тайла (прямоугольники), рисуется один раз, иначе
  соседние текстуры тайлов съедят часть прямоугольника.
* **Геометрия постройки — `map.buildingAt(ax, ay)`** (запись
  размещения), не пересчёт по tileAt; скан — только фолбэк и ТОЖДЕ с
  проверкой равенства якоря.
* **WebGL-маркер входа** (золотой квадрат 0.30..0.70 на тайле
  hasBuilding, слой #game) не тронут: hasBuilding — по-прежнему
  только на входе, квадрат теперь под 2d-спрайтом постройки (слой
  #sprites сверху) — не «ломать», это не баг.
* Магазин/пещера/диалог NPC, hudUpdate, tryMove/mover/motion — от
  hasBuilding/isEntrance, не от отрисовки — не затрагивались.
