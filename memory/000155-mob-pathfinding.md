## Где живёт A* (модуль/функции)

`src/combat.js` (единственный файл ядра), блок после `stepAway` (~:606–690):

* `PATH_DIRS = [[0, -1], [0, 1], [-1, 0], [1, 0]]` (↑ ↓ ← →) — канон порядка
  направлений проекта (дословно `stepAwayRect`, combat.js:591). Используется
  и в BFS (соседи), и в выборе шага (тай-брейк).
* `pathField(c, u, goalTest)` — **внутренняя** (не экспортируется). Чистая.
  Мульти-источниковый BFS: источники — ВСЕ проходимые клетки, где
  `goalTest(x, y)` истинен (dist 0); скан источников — фиксированный
  `for y { for x }`; очередь — массив + индекс (FIFO, паттерн
  `reachableCells` :360–377); соседи — 4, порядок `PATH_DIRS`; проходимость —
  `rectFree(c, x, y, u.size.w, u.size.h, u)` (u игнорирует СЕБЯ; другие живые
  юниты, клетка игрока, `c.obstacles` — стены). Возврат `Map 'x,y' → dist`
  (только достижимые). c не мутирует.
* `probeGreedyStep(c, u, r)` — **внутренняя**. Чистый (БЕЗ мутации) 1:1-проб
  логики `stepTowardRect` (большая ось первой, при равенстве — x; первая
  rectFree-клетка). Возврат `{x, y} | null`.
* `pathStepTo(c, u, r, reach)` — экспортируется. Один шаг К
  цели-прямоугольнику r с допущенным расстоянием `reach` (см. ниже). Полный
  алгоритм шага — см. «Контракты» (это и есть «A* или схожий» ТЗ:
  BFS-поле расстояний + одношаговый спуск; на равномерной сетке поле BFS =
  оптимальный путь).
* `pathStepFrom(c, u, r)` — экспортируется. Один шаг ОТ цели (ретрит).
* Встраивание — closure `mobAct` (:1335–1336); экспорт — return-объект.

## Контракты и границы

* `pathStepTo(c, u, r, reach) → boolean` (мутация `u.x/u.y`). Алгоритм
  (ПРОВЕРЕН veto-check.js, V1–V5):
  1. `f = pathField(c, u, (x, y) => rectDist({x, y, size: u.size}, r) <= reach)`;
     `f0 = f.get(u.x + ',' + u.y)`; `f0 === undefined` (цель недостижима/
     замурован) → **false, стоим** (деградация как до, без краша).
  2. `g = probeGreedyStep(c, u, r)`; если `g` и `f.get(g)` **СТРОГО < f0** —
     шаг на `g` (true). Это «вето поля» на жадный шаг: жадный принимается
     только при строгом улучшении BFS-поля (см. «Подводные камни» — ливелок
     наивного `stepTowardRect || pathStepTo`).
  3. Иначе — шаг A*: среди 4 соседей (rectFree) — минимальное поле,
     **тай-брейк — первое направление PATH_DIRS с минимальным (строгий `<`)**;
     ни одного соседа в поле → false.
  * Оптимальность: у соседей проходима |f(a)−f(b)| ≤ 1 → принятый жадный шаг
    (f0→f0−1) не хуже любого другого одношагового; A*-шаг берёт минимум.
    Монотонное убывание f за каждый принятый шаг → гарантия прибытия при
    достижимости, ливелок невозможен.
* `pathStepFrom(c, u, r) → boolean`: `d0 = rectDist(u, r)`;
  goalTest = `rectDist(cell, r) > d0` (дистанция строго выросла); поле как в
  pathStepTo; один шаг К ближайшей «дальней» клетке (НЕ обязательно рост d
  за один ход — пинить d≥2 через пару ходов). Замурован → false.
* Цель r — прямоугольник ({x, y, w, h}) от `nearestPlayerSide` (игрок 1×1 ИЛИ
  живой союзник — модель целей 000080, без изменений).
* «Проходима» — ровно `rectFree` (одна точка проверки, как у жадных шагов):
  границы, игрок, `c.obstacles`, другие живые юниты. Многоклеточные мобы —
  size-aware через rectFree/rectDist (тест 2×2).
* Границы: c НЕ мутирует (кроме `u.x/u.y` в pathStep*); поле не живёт в
  состоянии боя (вычисляется на лету → формат сейва не меняется); поле
  пересчитывается на каждый вызов (мобы действуют в очереди c.units — другие
  уже на новых местах; кэш не нужен: ≤49 клеток).

## Целевые дистанции (reach)

* melee / shield / swarm / support / leader — **reach = 1** («вплотную»;
  та же граница, что атака при d≤1).
* **RANGED — reach = RANGED_MAX_DIST (4) ТОЛЬКО в ветке dToP > 4** (единственный
  вызов stepToTarget для ranged — mobAct «слишком далеко»): моб доходит до
  полосы d≤4 и ОСТАНАВЛИВАЕТСЯ; дальше работают атака (d≤4) и паника (d≤1).
  reach=1 для ranged = осцилляция «подход-паника» + сломанное «держит
  дистанцию» (риск R3) — ЗАПРЕЩЕНО.
* Ретрит (pathStepFrom) — без reach: цель = любое «дальше текущего d0».
* `dToP` в closure устаревает после шага melee-loop — НЕ ВАЖНО (reach
  не-ranged константа; ranged вызывает stepToTarget ≤1 раза за ход). НЕ
  «чинить» пересчётом.

## Встраивание в ход моба (mobAct :1335–1336)

```
const stepToTarget = () => pathStepTo(c, u, target,
  u.role === MOB_ROLES.RANGED && dToP > RANGED_MAX_DIST
    ? RANGED_MAX_DIST : 1);
const stepFromTarget = () => stepAwayRect(c, u, target)
  || pathStepFrom(c, u, target);
```

* Жадная логика НЕ удалена — она внутри pathStepTo (проб + вето): на чистом
  поле поведение **БИТ-В-БИТ** со старым `stepTowardRect` (проверено: 44/44
  позиций 7×7) → поток c._rng не сдвигается, существующие пины живы.
* `stepFromTarget`: жадный `stepAwayRect` ПЕРВЫЙ (принимает только шаги с
  ростом d → монотонно, осцилляций нет); `pathStepFrom` — только при false
  (блокнутый ретрит). Это решение R4: ranged-паника (d≤1) и TIMID-побег
  получают обходной ретрит — «держать дистанцию» завершено; без него ranged
  в углу получает бесплатные удары (не решена жалоба ТЗ).
* Melee-цикл (mobAct «default», fast-мобы movePerTurn=2) и все ролевые ветки —
  0 правок: closure прозрачно делает обходной шаг.
