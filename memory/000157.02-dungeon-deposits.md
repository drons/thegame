## 3. Данные: пулы, форма записи, tier

Форма записи: `{предмет: <id предмета>, вид: 'руда'|'минерал'|'самоцвет'}`.
РЯДКОСТИ В ЗАПИСИ НЕТ — редкость предмета = поле `tier` каталога
`assets/items` (000157.01; отсущтвование = 1) — единый источник редкости
(DRY). Схема: `руда` — опция (не в required), array, minItems 1, запись
additionalProperties:false, required [предмет, вид], вид — enum.

Пулы (финальные; сверены с каталогом @4156dcb — tier каждого предмета):
* CAVE (000001, самая «рудная»): iron_ore(руда, T1), copper_ore(руда, T1),
  coal(минерал, T1), stone_chunk(минерал, T1), silver_ore(руда, T2),
  quartz(минерал, T2), obsidian(минерал, T2), gold_ore(руда, T3),
  phosphorite(минерал, T3).
* CRYPT (000002): stone_chunk(минерал, T1), quartz(минерал, T2),
  obsidian(минерал, T2), amethyst(самоцвет, T2), phosphorite(минерал, T3),
  sapphire(самоцвет, T3).
* RUINS (000003): iron_ore(руда, T1), copper_ore(руда, T1), coal(минерал,
  T1), silver_ore(руда, T2), quartz(минерал, T2), gold_ore(руда, T3),
  ruby(самоцвет, T3).
* DROWNED (000004, водные): sulfur(минерал, T1), stone_chunk(минерал, T1),
  quartz(минерал, T2), silver_ore(руда, T2), emerald(самоцвет, T3),
  sapphire(самоцвет, T3), phosphorite(минерал, T3).
* ABYSS (000005, легендарные глубины — ЕДИНСТВЕННЫЙ пул с T4): stone_chunk
  (минерал, T1 — чтобы правило «у каждого пула ≥1 T1» держалось для ВСЕХ 5
  типов: depth-1 ABYSS тоже даёт добычу), obsidian(минерал, T2),
  amethyst(самоцвет, T2), ruby(самоцвет, T3), gold_ore(руда, T3),
  phosphorite(минерал, T3), mithril_ore(руда, T4), diamond(самоцвет, T4).

Инварианты данных (пинаются тестом ORE-8 по JSON-каталогу):
* у каждого пула ≥1 предмет T1 (depth-1 даёт добычу во ВСЕХ типах);
* предметы УНИКАЛЬНЫ внутри пула (одна запись на предмет — иначе вид
  стал бы неоднозначен для рендера, §5);
* предметы НЕ пересекаются с полем `предметы` того же файла (залежи ≠ лут
  сундуков) — проверено: пересечение пусто.

## 4. Контракты и границы

### 4.1 dungeon.js
* Фабрика: 5-й аргумент `itemsData` (node: `require('./items-data.js').ITEMS`
  — items-data.js УМД-модуль, node-вход = `{ITEMS}`-массив; browser:
  `root.Game && root.Game.ITEMS` — плоский массив, НЕ Game.ItemsData).
  Нормализация: `Array.isArray(itemsData) && itemsData.length > 0` →
  `HAVE_ITEMS`, иначе false. На load: `ITEM_TIER[it.id] = it.tier || 1`
  (plain object). НИКАКИХ console.* на load без itemsData (vm-песочницы
  R4/R7/LOC-11 без console → ReferenceError, ловит LOC-11
  errors.length===0).
* `validDungeonCatalog`: + `(r.руда === undefined || (Array.isArray(r.руда)
  && r.руда.length >= 1 && r.руда.every(o => o && typeof o === 'object' &&
  typeof o.предмет === 'string' && o.предмет.length > 0 && (o.вид ===
  'руда' || o.вид === 'минерал' || o.вид === 'самоцвет') && (!HAVE_ITEMS ||
  ITEM_TIER[o.предмет] !== undefined))))`. Проверка «предмет» ∈ каталогу —
  СТОПКА (soft) только при HAVE_ITEMS (vm-цепи без items-data остаются
  валидными); «вид» ∈ enum — всегда.
* `DUNGEON_ORES[rec.id] = (rec.руда || []).slice()` в цикле таблиц
  (L147-153 worktree) + в return (L539-546). Поверхностный slice — записи
  не мутируются (рендер читает).
* `generateDungeonContents(d, player, opts = {})`: `const depth = Math.max(1,
  opts.depth | 0)` (default 1). Блок залежей — СТРОГО ПОСЛЕ цикла сундуков,
  ДО return:
  ```
  const deposits = [];
  {
    const pool = DUNGEON_ORES[d.type] || [];
    const T = Math.min(1 + Math.floor((depth - 1) / 2), 4);
    const elig = pool.filter(o => (ITEM_TIER[o.предмет] || 1) <= T);
    if (pool.length > 0 && elig.length > 0) {
      // СВОЙ поток (000157.02): соль 0x0DE5 — ЗАПИНЕНА (ORE-7).
      const rng_dep = mulberry32(hash2(seed, depth, 0x0DE5) >>> 0);
      const takeSpotDep = () => {
        for (let i = 0; i < 200; i++) {
          const [x, y] = spots[Math.floor(rng_dep() * spots.length)];
          const k = x + ',' + y;
          if (!occupied.has(k)) { occupied.add(k); return [x, y]; }
        }
        return null;
      };
      const nDeposits = 1 + Math.min(3, Math.floor(depth / 3));
      for (let i = 0; i < nDeposits; i++) {
        const rec = elig[Math.floor(rng_dep() * elig.length)];        // 1) предмет
        const amt = 1 + Math.floor(rng_dep() * 2)
                    + Math.min(2, Math.floor(depth / 4));             // 2) количество
        const s = takeSpotDep();                                      // 3) клетка
        if (!s) break;
        deposits.push({ id: 'd' + i, x: s[0], y: s[1],
                        item: rec.предмет, amount: amt, gathered: false });
      }
    }
  }
  ```
  return → `{ seed, mobs, chests, deposits, createdAtXp: player.totalXp,
  step: 0 }`.
* Формулы (запины, численные значения НЕ в SPEC — паттерн 000045):
  * `nDeposits = 1 + min(3, floor(depth/3))` → D1-2: 1, D3-5: 2, D6-8: 3,
    D9+: 4.
  * `T = min(1 + floor((depth-1)/2), 4)` → D1-2: T1, D3-4: T2, D5-6: T3,
    D7+: T4.
  * `amount = 1 + floor(rng_dep()*2) + min(2, floor(depth/4))` → 1..4
    (floor(rng*2) ∈ {0,1}; 5 недостижимо).
* Guard: нет поля `руда` ИЛИ нет записей с tier ≤ T → `deposits = []`
  (защитный путь; с текущими данными не срабатывает — у каждого пула T1).
* Точки вызова: src/locations.js L214 (maybeEnterDungeon) и L457
  (debugEnterDungeon). **Решение (000153.01 смержена в master 3ce98ad):**
  подключение реального depth — в ОДНОЙ точке, maybeEnterDungeon, на

### 4.2 RNG-инварианты (САМОЕ ВАЖНОЕ)
* Главный поток (mulberry32(seed), seed = hash2(totalXp, d.seed,
  0x5e11) ^ totalXp·2654435761) — **НОЛЬ новых вызовов после цикла
  сундуков**. Существующие goldens (seed/mobs/chests) БИТ-В-БИТ — НИКАКОГО
  репина значений (tests/dungeon.test.js L250-305, deepEqual seed/mobs/
  chests).
* СВОЙ поток залежей: `rng_dep = mulberry32(hash2(seed, depth, 0x0DE5) >>>
  0)` — hash2(x, y, seed) из perlin.js (уже возвращает >>> 0; `>>> 0`
  в ТЗ сохранён дословно, безвредно). Соль 0x0DE5 произвольна, но
  ЗАПИНЕНА: golden ORE-7 (значения сняты с рабочего кода) + текст-пин
  литерала `0x0DE5` в src/dungeon.js.
* Порядок вызовов rng_dep НА ЗАЛЕЖЬ: предмет → количество → клетка
  (takeSpotDep ≥1 вызов, при успехе ровно 1). Порядок НАД ЗАЛЕЖАМИ:
  i = 0..nDeposits.
* Клетка: СОБСТВЕННЫЙ takeSpot-клёшер на rng_dep + ОБЩИЙ occupied-Set —
  взаимное исключение с мобами/сундуками/босс-клеткой (ABYSS pre-add)
  БЕСПЛАТНО (паттерн 000183). Существующий `takeSpot` НЕ использовать — он
  пьёт главный rng. safe-зона 5×5 (вход+выход) — недоступна (spots уже
  без неё).
* ПРАВИЛО ДЛЯ БУДУЩЕГО: хвост главного потока ПОСЛЕ цикла сундуков ЗАНЯТ
  залежами — новые механики контента получают СВОИ потоки ПОСЛЕ залежей
  (свои соли), никогда не встают в главный поток.
