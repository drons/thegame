# 000025: синхронизация анимации волн на тайлах воды

Статус: выполнено и закоммичено (тесты 186 → 192 pass).

## Решения

* **Причина разрыва.** Волна в текстуре тайла (assets/tiles/water_*.svg)
  имеет период 16px (четверть тайла 64px); каждый из 4 кадров — сдвиг
  волны на 8px (полпериода): translate(0), (-8), (-16), (-24). Старый
  селектор кадров `frameIndex` давал фазу от *целочисленного номера*
  тайла: `(tx*5 + ty*9) % frameCount` — соседи получали разную фазу
  (сдвиг на 1 кадр = полпериода), и рисунок волны на стыке тайлов
  «перескакивал» на 8px.
* **Условие бесшовности.** На стыке двух тайлов рисунок совпадает,
  только если разность их кадров ЧЁТНАЯ (сдвиг на целое число периодов
  16px). С учётом квантизации кадров это означает: фаза должна быть
  непрерывной функцией *мировых* координат с пространственным шагом
  полцикла на тайл по каждой оси.
* **`wavePhase(nowMs, wx, wy)`** (src/sprites.js, чистая) — фаза волны
  в точке мирового пространства, [0; 1):
  `p = 0.5*wx + 0.5*wy − (now mod WAVE_PERIOD_MS)/WAVE_PERIOD_MS`
  (mod 1). Непрерывна по мировым координатам (нет скачка при пересечении
  границы тайлов) и периодична по времени (`WAVE_PERIOD_MS = 3200`,
  800 мс/кадр для 4 кадров).
* **`waterTileFrame(nowMs, tx, ty, frameCount)`** — кадр водяного тайла
  из фазы в *центре* тайла (мировые координаты). Шаг фазы на тайл =
  полцикла → разность кадров соседей = 2 (чётная) → сдвиг волны по
  модулю периода одинаков у всего моря: в каждый момент все водяные
  тайлы показывают один эффективный сдвиг, швы невозможны в принципе.
* **Подключение к рендеру без правок main.js.** `frameIndex` теперь
  диспетчеризует: `frameCount === WATER_FRAME_COUNT` (=4, единственное
  4-кадровое значение — текстуры воды; мобы/Флогистон — 2 кадра) →
  `waterTileFrame`, иначе — старая фаза на тайл (мобы по-прежнему
  «не синхронизированы» между собой). main.js вызывает `G.frameIndex`
  как раньше — волна стала синхронной без изменения рендерера.
* `waterFrame` — теперь синоним `waterTileFrame` (раньше — frameIndex);
  экспорт: `WAVE_PERIOD_MS`, `WATER_FRAME_COUNT`, `wavePhase`,
  `waterTileFrame`.
* Глубокая вода (2 кадра: translate(0) и (-16)) визуально не меняется:
  сдвиг кадра уже целый период; чекерборд кадров 0/1 по (tx+ty) parity
  незаметен.

## Тесты

tests/sprites.test.js: +6 тестов — чистота и диапазон wavePhase,
периодичность по времени; «фаза одинакова на границе соседних тайлов»
(одна точка стыка — одна фаза для обоих тайлов); непрерывность фазы
при пересечении стыка (старая схема прыгала бы на 1/4 цикла);
«волна не рвётся на стыке» (разность сдвигов кратна периоду 16px,
разность кадров соседей чётна по обеим осям); «эффективный сдвиг
волны одинаков на всей карте» в каждый момент. Старый тест
«waterFrame — синоним frameIndex» переписан в «waterFrame — синоним
waterTileFrame; frameIndex для 4 кадров — та же фаза».

## Ограничения

* Вертикальный стык текстуры (линии волн y=14/34/52, шаг 18px не
  делит 64px) не идеально стыкуется — это свойство самих SVG-текстур,
  не фазы анимации; починка потребует новых текстур (отдельная задача).
* Если когда-нибудь появится НЕ-водяная 4-кадровая анимация,
  диспетчеризация в frameIndex по WATER_FRAME_COUNT нужно будет
  заменить на явный аргумент террейна.
