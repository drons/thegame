## 2. Целевая архитектура (нормативна для 000140-000147)

Новый чистый UMD-модуль **src/sheet.js** (паттерн 000053/000130: node-тестируем,
в браузере Game.Sheet; без DOM/RNG; межимодульные чтения — только лениво,
UMD-ловушка 000038):
* Состояние `{kind:'hero'|'efir'|'merc', level, xp, points, primary{6},
  secondary{}, skillXp{}, spells[]}` + носитель (npcId). **Начальный список —
  ПАРАМЕТР** createSheet(kind, initial) — единственное допустимое различие
  персонажей (ТЗ).
* Единые механики: addXp (xpForNext=round(50·L^1.5), **очки 2/уровень — ВСЕМ
  kinds**), raiseSkill, practice (cap = primary×2, **перелив — в bank** —
  эталон reprocessEfirSkills efir.js L402-447), derived(sheet, ctx) — боевые
  статы из характеристик + kind-модификатор (Эфир: формула efirStats как
  derived-модификатор; наёмный: role-множители makeAlly).
* Сейвы НЕЛОМАЮЩИЕ (000031, паттерн 000029): CURRENT_VERSION=1 не меняется;
  hero-лейаут не меняется; записи efir/companions **backfill**'ятся при
  deserialize (level/xp переносятся; invalid → сброс + warn).
* Эфир СОХРАНЯЕТ: 100% XP, «Вдох Эфира», авто-разблокировки (фирменная фича;
  единое изучение 000147 ДОБАВЛЯЕТ источники, не отменяя).
* Наёмные СОХРАНЯЮТ: найм/жалованье/лояльность/dead_mercs в companions.js;
  боевые статы — из sheet через data.maxHP/data.damage (makeAlly).
* UI (000145/000146): «Персонаж» = ряд портретов сверху (000142) + лист
  активного (навыки/очки/практика/книга заклинаний); вкладка «Эфир» удаляется;
  «Отряд» — управление (найм/жалованье/увольнение) + переход на страницу.
