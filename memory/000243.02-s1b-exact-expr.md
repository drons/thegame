## 4. Матрица угроз (верифицировано /tmp: red-demo +
red-counterexample.js + red-check.js; артефакты НЕ в коммите)

Мутация ассерта S1-цикла (копия items.test.js L1640) → struct (старый)
/ exact (новый) / K-regex (извлечение карты):

| форма | struct | exact | K-regex | вердикт |
|---|---|---|---|---|
| pristine (master) | G | G | G | зелёный — ассерт на месте |
| `n <= (SCHOOL_SCROLL_MAX[sch] ?? 99)` | G | **R** | G | ЗАХВАЧЕН (пример ретро) |
| `n <= (SCHOOL_SCROLL_MAX[sch] \|\| 99)` | G | **R** | G | ЗАХВАЧЕН (реалистичная форма fallback) |
| `n <= Math.max(99, SCHOOL_SCROLL_MAX[sch])` | G | **R** | G | ЗАХВАЧЕН |
| переименование карты (`const K_MAP = …`, `n <= K_MAP[sch]`) | G | **R** | **R** | ЗАХВАЧЕН двойно (exact + срыв regex извлечения) |
| промежуточная переменная (`const K = SCHOOL_SCROLL_MAX[sch]; assert.ok(n >= 1 && n <= K, …)`) | G | **R** | G | ЗАХВАЧЕН — exact-пин не матчит `n <= K`; fail-closed ре-пин, НЕ bypass |
| дизъюнкция без скобок `n >= 1 && n <= SCHOOL_SCROLL_MAX[sch] \|\| 99` | G | G | G | **РЕЗИДУАЛЬНЫЙ GAP** — always-true (vacuous assert), все пины зелёны; принятый риск §5 |
| standalone `n <= SCHOOL_SCROLL_MAX[sch] ?? 99` (без `&&`) | G | G | G | no-op: `(bool) ?? 99` = bool — пин жив, ложного пропуска нет |

Краснота осмысленная: на `?? 99`-мутации новый S1-B = ровно 1 fail
(000243-S1-B), ERR_ASSERTION с дампом цикла, в котором виден `?? 99`;
на немутированной копии — 6/6.

## 5. Факты JS-прецедентности (проверены eval) + резидуальный gap

* `a && b ?? c` — **SyntaxError** (`??` не смешивается с `&&`/`||`
  без скобок) → суффикс `?? 99` на всё выражение `n >= 1 && n <=
  X[sch]` написать невозможно.
* `n <= X[sch] ?? 99` валиден как `(n <= X[sch]) ?? 99` (прецедентность
  сравнения выше `??`) — но NO-OP: boolean не nullish → пин жив.
* `n <= X[sch] || 99` валиден как `(n <= X[sch]) || 99` — ВСЕГДА
  truthy → пин мёртв. Единственные валидные формы, убивающие пин:
  в скобках — ЗАХВАЧЕНЫ (скобка ломает substring); без скобок с `&&`
  — резидуальный gap.
* **Резидуальный gap (принятый риск):** `n >= 1 && n <=
  SCHOOL_SCROLL_MAX[sch] || 99` — валидный JS (прецедентность
  `&&` > `||`), всегда true, точный substring сохраняется → проходит
  struct + exact + deepEqual; арбитр мёртв. Почему принимаем: (a) ТЗ
  предписывает pattern дословно; (b) анти-паттерн намерения — автор,
  пишущий fallback, пишет `(X[sch] || 99)` в скобках — та форма
  ЗАХВАЧЕНА; (c) запись gap-формы требует переписи строки ассерта;
  (d) общее ограничение техники text-пинов (substring ≠ семантика)
  зафиксировано в memory родителя §11.4 как принятый риск.
* **Upgrade-point** (zero-gap, если когда-либо потребуется): пинить
  границу аргумента assert.ok — `loop.includes('n <= SCHOOL_SCROLL_MAX[sch],')`
  (запятая после `]`) или regex `/n\s*<=\s*SCHOOL_SCROLL_MAX\[sch\],/` —
  a3-проверено: gap → красный, все формы §4 → красные, master →
  зелёный. В .02 НЕ применяется (вне ТЗ; более хрупко).
