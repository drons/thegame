# 000062: высокодетальные SVG-ассеты для мобов (развитие 000047)

Статус: ЗАВЕРШЕНО (стадии «Правила» → «Ассеты» → «Интеграция»).
Коммиты (ветка task/000062, по порядку): MOBS.md + счётчик (предыдущая
стадия) → «Задача 000062: высокодетальные SVG-ассеты 36 мобов» (180 SVG
+ JSON «описание»/«art» + схема + тесты арта + зеркало без арт-полей)
→ «Задача 000062: интеграция per-mob арта (загрузка, отрисовка, тесты)»
(sprites.js + combat-ui.js + тесты + память).

## Ключевые решения, зафиксированные в MOBS.md (корень проекта)

* Каталог: `assets/sprites/mobs/`, плоская схема имён
  `<mob_id>_<state>_<n>.svg`, state ∈ {move, attack, dead}.
  (Не путать с раскладкой WIP-черновика `assets/mobs/sprites` —
  черновик `wip/task-000047-mobart` — только референс стиля, НЕ копировать.)
* Кадры: move 2–3, attack 2–3, dead ровно 1; кадры различаются
  конечностями/челюстями/энергией, а не общим сдвигом фигуры.
* Геометрия: клетка = 100 единиц, viewBox = `0 0 100·w 100·h`
  (1x1 → 100×100, 2x2 → 200×200, 3x3 → 300×300); якорь — низ-центр.
* Бюджет: ≥ 30 контурных элементов на клетку площади на КАЖДЫЙ кадр
  (1x1→30, 2x2→120, 3x3→270, 5x5→750). Деталь = path/circle/ellipse/
  polygon/rect/line в теле SVG; defs/clipPath/mask/use не считаются.
* Стиль: единый ракурс 3/4 сверху, плоские формы 2–3 тона, палитра
  моба 5–8 HEX, тень-эллипс rgba(0,0,0,0.25–0.3), тонкий тёмный контур.
* JSON-поля моба (добавляются, существующие не трогаются):
  `описание` (≥800 символов: анатомия, палитра HEX, материалы,
  отличительные черты, движение/удар/гибель) и
  `art` = { move: [2–3 пути], attack: [2–3 пути], dead: [1 путь] }.
* Технический формат: самодостаточный SVG (движок грузит через
  Image() под file://) — нет script/text/foreignObject/image/SMIL/
  внешних ссылок; id в defs с префиксом `<mob_id>_`.

## Инструмент

`scripts/count-svg-details.js` (node, без зависимостей):
`node scripts/count-svg-details.js [--min N] FILE.svg ...` — печатает
«файл: K деталей», exit 1 при --min ниже порога. Экспортирует
`countDetails` для тестов. Тесты: tests/svg-details.test.js.

## Генерация ассетов (стадия «Ассеты»)

* 180 SVG (36 мобов × {move 2, attack 2, dead 1}) сгенерированы
  `scripts/gen-mob-art.js` — детерминированный параметрический
  генератор (сид = fnv1a(id+pose), mulberry32, округление до 0.1,
  byte-identical повторный запуск; прецедент — scripts/gen-combat-bg.js).
  Вручную 180 файлов делать не реалистично — генератор легитимен.
* Данные (палитры 5–8 HEX, черты, тексты описаний 36 мобов) —
  `scripts/mob-art-data.js`: `MOBS_ART` (id/name/family/features/
  palette/desc) + `buildDescription(m)` — собирает «описание» со
  сводами «Силуэт/Цветовая схема (HEX)/Арт-дирекшн (движение/удар/
  гибель)». Палитра — источник HEX: SVG использует ТОЛЬКО цвета
  палитры (тест mob-art.test.js сверяет HEX файла ⊆ HEX описания).
* Архитектура генератора: вся фигура — в ЕДИНИЧНОМ пространстве
  100×100, до канваса растягивает ОДИН корневой
  `<g transform="scale(u)">` (u = S/100). Построители по семействам:
  orc/humanoid/demon → buildHumanoid; skeleton → buildSkeleton
  (+buildBonePile/buildWorm); quadruped → buildQuadruped/drawWolfBody;
  arthropod → buildArthropod; flame (4 стихии + голем) → buildFlame
  (+buildFlameDead — остывший остаток, а не «сваленная» фигура).
  Бюджет деталей дотягивается слоем «чертёжной детализации»
  (fillBudget: шрамы/трещины/шерсть/чешуя/капли/угли в C.region,
  детерминированно).
* DEAD-позы: вертикальные фигуры (двуногие, скелеты) — поворот на
  ~82° вокруг центра; ГОРИЗОНТАЛЬНЫЕ (челюсть/членистоногие/личинка)
  — сжатие к земле `translate(0 dy) scale(1 k)` (поворот выводил бы
  лапы за канвас — поймано на структуре); личинка и грудная клетка —
  собственные dead-развёртки.
* Поле `size` в assets/mobs/*.json — ОБЪЕКТ `{w,h}` (не строка "w x h")
  — генератор читает d.size.w/d.size.h.
* JSON-каталог пополнен полями одноразовым скриптом (описание после
  name, art в конце; 2-space, trailing \n); одноразовые скрипты удалены.
  ПОДВОХ пересборки: скрипт перечислял ключи явно и ВЫБРОСИЛ
  опциональные armor/fast/traits у 14 мобов — поймал зеркальный
  deepEqual-тест (mirror combat.js). Урок: пересобирая JSON-объект,
  копировать ВСЕ ключи оригинала (включая опциональные), а не
  фиксированный список; опциональные поля стояли между hp и size.

## Интеграция (стадия «Интеграция»)

* src/sprites.js: `MOB_ART_DIR`, `MOB_ART_FRAME_COUNTS`
  {move:2,attack:2,dead:1}, `MOB_ART_ACTIONS`, `mobArtFrames(mobId,
  action)` (неизвестный id/действие → [] — фолбэк на 6 видов);
  таблица-литерал (зеркало combat.js арта не содержит, как
  MOB_SPRITE_KINDS); `allAssetPaths()` += 180 путей; МОБ_FRAMES/
  mobSpriteKind/mobFrames НЕ тронуты (фолбэк жив).
* src/combat-ui.js drawUnits: цепочка фолбэков ПО ЮНИТУ —
  персональный арт (move/attack 2 кадра, dead 1) → базовые 6 видов
  (000047) → прямоугольник ROLE_COLORS. МЁРТВЫЙ моб (u.alive=false,
  !fled) теперь В списке (ранее пропускался): рисует ТОЛЬКО dead-
  кадр, без HP-полосы/уровня/подсветки цели; кадр не готов/нет
  sprites.js → ничего не рисует (цветного прямоугольника-трупа нет).
  Анимация героя (c._fx) не тронута.
* FX мобов — `unitFxAfterMobPhase(c, beforePos, hpBefore)`: эвристика
  из снимка ДО / состояния ПОСЛЕ c.endTurn() (ядро ходы мобов делает
  синхронно, событий «кто кого» не выдаёт): сменил позицию → 'move';
  стоял в ударной позиции (d≤1 ближние; 2..4 дальние — при d≤1 они
  отступают) И игрок потерял HP → 'attack' (приоритет). Промах
  (HP не упало) → без attack-FX. Точная атрибуция урона мобо —
  БУДУЩАЯ задача (крючок событий в ядре, c._uiEvents). c._unitFx —
  состояние только UI-слоя (как c._fx), ядро не читает.
* Отклонения от «архитектуры аналитика» (зафиксированы, осознанно):
  раскладка — плоская (MOBS.md побеждает), канвас 100·w×100·h
  (MOBS.md), поле «описание» (MOBS.md); зеркало combat.js БЕЗ
  арт-полей (аналитик, экономия ~40 КБ + file://); FX — эвристика, а
  не точная атрибуция (аналитик + ограничение ядра).
* Тесты: tests/mob-art.test.js (36 мобов: «описание» 800+/своды/
  палитра, «art» 2/2/1 + пути + файлы, viewBox/структура/тень/префикс
  id, ≥30·w·h деталей, HEX⊆палитра, уникальность кадров + отриц.
  контроль сканера); combat.test.js — зеркало с ART_ONLY_MOB_FIELDS;
  sprites.test.js — mobArtFrames 36×5, неизвестные id/действие,
  JSON «art» == таблице, allAssetPaths ⊇ 180; combat-ui.test.js —
  труп (dead-кадр без полос/уровня/цели), без sprites.js (труп —
  ничего), endTurn → _unitFx move/attack + истечение + промах.
