# 000176 — Глобальная карта: единый рендер-проход + поэлементный фолбэк

Контракт решения (станция Проектирование, 2026-10-09; worktree
`.worktrees/task-000176`, ветка `task/000176`, база master `3d5bac4`).
База npm test на голом мастер: **1905/1905**. Постмортем бага —
`memory/000176-duplicate-render.md`.

## 1. Решение (главное)

Глобальная карта рисуется ДВАМИ слоями, как и раньше, НО левый
(до-000011) WebGL-проход больше НЕ безучловный: каждый элемент legacy-сцены
(цветной тайл / золотой маркер постройки / красный маркер группы / ромб
Флогистона) рисуется ТОЛЬКО если спрайт-слой (`drawSprites`, #sprites)
НЕ МОЖЕТ нарисовать этот же элемент (спрайт-кадр не загрузился).
В штатном состоянии (все ассеты ready) в WebGL-проходе **0 вершин**
(`gl.drawArrays(gl.TRIANGLES, 0, 0)`) — дублирования нет, пересборка
Float32Array и GPU-загрузка вершин на кадр убраны (нагрузка из брача).

Ключевое решение — **поэлементный гейт по готовности спрайта**, а НЕ
удаление фолбэка (вариант «тёмный фон») и НЕ грубый гейт по
`readyCount()`:

* сохраняем контракт 000011 («фолбэк — прежние цветные тайлы/маркеры»):
  на старте (299 ассетов грузятся) игрок видит цветную карту, затем
  текстуры появляются поэлементно; упал спрайт Флогистона — герой остаётся
  ромбом (видим), а не исчезает;
* грубый гейт (readyCount===0 → вся сцена, иначе ничего) отклонён: при
  падении ОДНОГО ассета он возвращает ПЕРЕЗАРЯДКУ всего вершинного буфера
  (смысл перфоманс-фикса пропадает) и лишает героя фолбэка при остальных
  ready (нарушение 000011);
* полное удаление WebGL-прохода (тёмный фон) отклонено: это смена
  существующего поведения (тёмный экран на старте; герой пропадает при
  сбое спрайта; «WebGL не поддерживается»-ветка меняется) — «больше, чем
  просит ТЗ» (ТЗ — баг, не редизайн загрузки).

Отклонённый вариант «2D-подложка вместо WebGL» (#game → 2d-canvas +
2D-фолбэк fillRect/paths) — см. §5: больше диф в main.js (тронут блок
frame() — зона 000170) и смена no-WebGL-поведения (игра стала бы стартовать
без WebGL) при том же результате.

## 2. Что добавлено / перенесено (src/main.js — ЕДИНСТВЕННЫЙ файл правок)

Всё — замыкания IIFE; новых UMD-модулей, script-тегов, CSS — НЕТ
(index.html не трогается; пин index-order не требуется — зона риска a3
не задействована).

* **Вынесены в IIFE-уровень (были инлайном в drawSprites / в buildFrame)
  — общие селекторы готовности, ОДИН источник для обоих слоёв:**
  * `tileFrameImg(t, now)` → img|null: `G.tileFrames(t.terrain)` +
    `G.frameIndex(now, t.x, t.y, len)` (ТЕКУЩИЙ кадр анимации — вода!) +
    `spriteLoader.image(...)`. Проход 1 drawSprites и гейт тайла в
    buildFrame — через него.
  * `mobFrameImg(t, now)` → img|null: `G.mobFrames(t.mobGroup)` +
    `G.frameIndex(...)`. Проход 3 и гейт маркера — через него.
  * `heroFrameImg(now)` → img|null: выбор action
    (`now < animUntil ? animAction : (now - lastStepAt <
    (G.walkWindowMs ? G.walkWindowMs(stepIntervalMs()) : 260) ? 'walk'
    : 'idle')`) + `G.phlogistonFrames(action)` +
    `Math.floor(now/240) % len`. Проход (г) и гейт ромба — через него.
  * `buildingAsset(rec)` → asset|null: ТАМОЕ трёхветвевое выражение
    (buildingSprite → citySprite(rec.buildingId) → campSprite(rec.buildingId),
    typeof-гарды сохранены). Проход 2 и гейт маркера — через него.
  * `buildingRec(ax, ay)` — ПЕРЕНОС из вложенности drawSprites (была
    L2344) в IIFE-уровень (поведение нейтрально: читает только map/
    tileCache/G).
* **`buildFrame(rp)` → `buildFrame(rp, now)`** (L2253): наполнение
  `frameTiles` НЕ МЕНЯЕТСЯ (его читают 4 прохода drawSprites); legacy-
  вершины — условно:
  * тайл-квад: только `if (!tileFrameImg(t, now))`; `map.brightness(tx,ty)`
    переезжает ВНУТРЬ этого условия (шум пересчитывается только для
    рисуемых legacy-тайлов — побочный перфоманс-плюс, выходной цвет не
    меняется);
  * золотой маркер (hasBuilding — ТОЛЬКО тайл входа, map.js L955-957):
    только если `buildingRec(якорь)` + `buildingAsset(rec)` не дали
    готовый img. ВАЖНО (правка на стадии Реализация): вход НЕ всегда
    якорь — у каталожных построек «вход» смещён (3x3 школа/храм —
    [1,2]; города 2x2/5x5/7x7 — [1,1]/[2,4]/[3,6]; buildings.js,
    id 7/36/52/53/54), а `map.buildingAt(x,y)` ищет ТОЛЬКО якорь —
    `buildingRec(t.x, t.y)` на входном тайле дало бы null и маркер
    «пролил» бы под готовым спрайтом. Якорь берётся из ТАЙЛА:
    `t.buildingAnchor` (проход 2 собирает якоря ровно так же:
    `t.inBuilding && t.buildingAnchor`) — тот же источник; фолбэк
    `buildingRec(t.x, t.y)` — только для устаревшего map.js без поля
    (там tile в любом случае не даст inBuilding → rec null → маркер,
    и проход 2 ничего не рисует — XOR сохранён).
  * красный маркер (hasMobGroup, `else if` сохраняется): только если
    `G.groupVisible(defeatedAt, t.x, t.y)` (guard `!G.groupVisible ||`
    для старого day.js — ТОЧНО как проход 3) И `!mobFrameImg(t, now)`.
    Это и есть фикс «прола»: после победы группа скрыта спрайт-слоем
    (000122) — красный квадрат больше не остаётся;
  * ромб Флогистона (6 вершин, s=0.28, центр rp+0.5): только
    `if (!heroFrameImg(now))`.
  gl-загрузка (bindBuffer/bufferData/vertexAttribPointer×2) и `return
  verts` — без изменений (пустой буфер в ready-состоянии допустим:
  `drawArrays(..., 0)`).
* **`drawSprites`** — правки ПОВЕДЕНИЕ-НЕЙТРАЛЬНЫ (те же выражения,
  вынесенные в хелперы): проход 1 `const img = tileFrameImg(t, now);
  if (img) …`; проход 2 `const asset = buildingAsset(rec); …`;
  проход 3 `const m = mobFrameImg(t, now); if (m) …`; герой
  `const pi = heroFrameImg(now); if (pi) …`. main-visuals пины геометрии
  побайтово — фиксатор нейтральности.
* **`frame()`** — одна строка: `const verts = buildFrame(rp, now);`
  (L2576). gl-блок (viewport/clearColor/clear/uniformMatrix4fv/drawArrays,
  L2566-2577), sizing canvas'ов, rAF — НЕ ТРОГАЮТСЯ (зона движения/
  инпута 000170 внутри frame() — дисъюнктивна).
* Комментарии: L2251 («общие для WebGL и слоя спрайтов» — уточнить:
  frameTiles + поэлементный фолбэк), L2301-2308 (семантика фолбэка —
  поэлементно), L1-9/L17-19 (уточнить «WebGL-рендер» → «WebGL-подложка
  (фолбэк) + спрайт-слой»). Логические правки только там.

НЕ МЕНЯЕТСЯ: L46-52 (TILE_COLORS/BUILDING_COLOR/MOB_COLOR/PLAYER_COLOR —
теперь читает только фолбэк), L124-191 (WebGL setup, guard L125-128,
legacyOrtho — остаются: фолбэк — тот же WebGL, та же проекция),
`G.orthoMatrix` (000061, main.js её по-прежнему использует), `drawSprites`
селекторами, HUD «графика: a/b» (лоадер не тронут), сейвы/детерминизм/RNG,
бой (combat-ui) и подземелья/города (dungeon-ui) — свои canvas.

## 3. Контракты и границы (что важно будущим задачам)

* **XOR-контракт элемента**: в каждом кадре каждый элемент мира рисуется
  РОВНО ОДИН раз — спрайтом (#sprites) ИЛИ legacy-фигурой (#game WebGL),
  никогда оба (и не ни один, если загрузка не зависла вечно). Герой —
  ровно 1× (спрайт phlogiston XOR ромб).
* **Стeady state (все ready)**: 0 вершин в WebGL-проходе; единственный
  «живой» проход — drawSprites. Проверка — tests/global-map-draw.test.js
  (glCalls: bufferData-длины/drawArrays-count).
* **Не возвращать** безучловный legacy draw (дубль) — это баг 000176; и
  **не удалять** фолбэк без отдельной задачи (контракт 000011).
* **Селекторы — только через хелперы**: если будущая задача добавляет
  новый элемент мира (новый тип спрайта/маркера) — добавляет пару
  «проход drawSprites + гейт в buildFrame» ЧЕРЕЗ новый/существующий
  хелпер готовности; инлайн frameIndex/asset-выражений в buildFrame
  запрещён (дрейф = дубль или пропажа).
* **groupVisible-паритет**: любые будущие «скрытые» сущности (аналог
  defeatedAt для других типов) обязаны гейтить ОБА слоя одним предикатом.
* **SPEC.md НЕ правится** (регион 000168, в полёте): его строки
  «WebGL+JS+HTML» и «rgb — 0..1 для WebGL-рендера» ПОСЛЕ 000176 остаются
  верными (фолбэк — тот же WebGL с 0..1-цветами). Дельта для ретро: если
  когда-нибудь фолбэк станет 2D-подложкой — SPEC править отдельной задачей.
* **no-WebGL-поведание не меняется**: guard L125-128 («WebGL не
  поддерживается этим браузером» → игра не стартует) на месте.
* **Наблюдение (НЕ в ТЗ, отдельная задача при желании)**: frame() каждый
  кадр сбрасывает `canvas.width/height` (L2564-2565, L2580-2582) — полный
  reset обоих canvas'ов; перфоманс-момент, в 000176 не трогаем.

## 4. Ленивые ссылки и guards

* `spriteLoader` может быть null (нет s2 / нет G.createSpriteLoader —
  в т.ч. нет sprites.js в цепочке: G.buildingSprite/citySprite/…
  определены ТОЛЬКО в sprites.js) — все ЧЕТЫРЕ селектора
  (tileFrameImg/mobFrameImg/heroFrameImg/buildingAsset) начинаются с
  `if (!spriteLoader) return null;` (buildingAsset-гард — правка по
  ревью 000176: до неё первый кадр спавн-мира крашил rAF-цикл,
  TypeError в buildFrame → frame) → legacy-сцена рисуется ПОЛНОСТЬЮ
  (деградация = текущее поведение «мир без спрайтов», игра не падает).
  Пин — tests/global-map-draw.test.js, RM-8.
* `!G.groupVisible ||` — guard устаревшего day.js, ТОЧНО как в проходе 3.
* `buildingAsset` — typeof-гарды citySprite/campSprite (старый sprites.js)
  сохранены из исходного выражения прохода 2.
* Новых lazy-ссылок на Game, новых UMD-модулей, новых script-тегов — НЕТ.

## 5. Отклонённые варианты (почему)

* **Полное удаление WebGL-прохода (тёмный фон при нет-ассетов)**: смена
  поведения старта (тёмный экран вместо цветной карты до загрузки) и
  пропажа героя при сбое его спрайта; 000011 фиксировал фолбэк
  осознанно; TЗ — баг, не редизайн.
* **2D-подложка на #game (canvas → 2d, fillRect/paths-фолбэк)**: тот же
  пользовательский результат, НО диф тронет WebGL setup (L124-191) И
  gl-блок frame() (L2566-2577 — зона, где параллельно правит 000170), и
  меняет no-WebGL-поведание (игра стала бы стартовать без WebGL —
  «больше, чем ТЗ»).
* **Грубый гейт по readyCount()===0**: при 1 failed-ассете — полный
  вершинный буфер снова (перфоманс-фикс пропадает) + герой без фолбэка.

## 6. Подводные камни

* **Анимированные тайлы (вода)**: готовность проверяется по ТЕКУЩЕМУ кадру
  (`G.frameIndex(now, …)`) — иначе вода «мерцает» цветным при смене кадра.
* **hasBuilding — только на тайле ВХОДА** (map.js L955-957) → маркер-гейт
  берёт якорь из ТАЙЛА: `t.buildingAnchor` (тот же источник, что проход 2;
  уточнено 000176, стадия Реализация — вход НЕ всегда якорь: 3x3
  школа/храм — [1,2], города 2x2/5x5/7x7 — [1,1]/[2,4]/[3,6], см. §2), а
  `buildingRec(t.x, t.y)` на входном тайле — фолбэк ТОЛЬКО для устаревшего
  map.js без поля buildingAnchor.
* **`else if`** в buildFrame (hasBuilding vs hasMobGroup) сохраняется.
* **brightness()** — только в гейте тайла (не выносить обратно в общий
  цикл — шум на все тайлы = старый расход).
* **vm-тесты**: все 21 существующая песочница шлют `makeGl()` на 'webgl' —
  остаются актуальны (WebGL-контекст всё ещё запрашивается); ни одна не

  — усилённый gl-стаб (glCalls) + Image-стаб с rejectSet + e2e-протокол
  победы над группой (паттерн mob-zones-e2e: walk на (1,0) → бой →
  victory-мутация → Escape → defeatedAt.set).
* **Rebase**: 000170 правит main.js (движение/инпут) — наши ханки локализованы
  в L2236-2475 + вызов L2576 (frame()-блок движения не трогаем); после
  ребаса ОБЯЗАТЕЛЕН полный npm test в worktree. Ожидаемый конфликт ТОЛЬКО в
  CHANGELOG.md: мастер с 000168/000169/000172 добавил ту же секцию
