# 000063: базовая скорость передвижения — глобальные настройки

Статус: выполнено и закоммичено (тесты 505 → 512 pass).

Задача: после 000033 (плавное передвижение) движение по глобальной
карте стало «очень быстрым». Базовая скорость передвижения — в
глобальные настройки, уменьшена в три раза.

## Решения

* **src/global-settings.js**: новый ключ `move_interval_ms = 140 * 3 =
  420` — базовый интервал шага по глобальной карте (ранее хардкод
  140 мс в main.js). Скорость = 1/интервал: «в три раза медленнее» =
  интервал ×3. НЕ 140/3 ≈ 47 мс — это УСКОРИЛО бы (и уперлось бы в
  MIN_MOVE_INTERVAL_MS = 60, убивая «Ловкий шаг»).
* **src/main.js**:
  * `MOVE_INTERVAL_MS` — из `Game.GlobalSettings.SETTINGS.move_interval_ms`
    с guard'ом (конечное и > 0) и fallback 140 (деградация без
    global-settings.js — старое поведение, паттерн 000033).
  * Хелпер `stepIntervalMs()` = `G.moveIntervalMs(MOVE_INTERVAL_MS,
    (G.derived(hero) || {}).moveSpeedMult)` — ОДИН источник интервала
    для цикла шагов (гейт `now - lastMove >= stepMs`) и окна
    анимации walk/idle (drawSprites).
  * Окно walk/idle: фикс `now - lastStepAt < 260` удалён, теперь
    `now - lastStepAt < (G.walkWindowMs ? G.walkWindowMs(stepIntervalMs()) : 260)`.
* **src/motion.js**: `walkWindowMs(stepMs) = max(260, stepMs)`
  (константа `WALK_WINDOW_MIN_MS = 260`, экспорт в UMD-API). Окно
  анимации масштабируется от интервала шага: фикс 260 подобран под
  старый интервал 140 и при базе 420 давал 260 мс walk + 160 мс
  ЗАМИРАНИЯ в idle за шаг при удержании клавиш — рваная ходьба, откат
  ощущения 000033. Окно не короче 260 и не короче шага (при удержании
  клавиш — всегда walk). Мусор (NaN/нечисло, <= 0) — 260, без
  исключения.
* **SPEC.md «Карта мира»**: параметр `move_interval_ms` (по умолчанию
  420 мс) настраивается, единый источник — src/global-settings.js;
  «Ловкий шаг» уменьшает интервал, но не ниже минимального.
* Тесты: tests/global-settings.test.js (+2: ключ в списке, значение
  ровно 140*3, структурный «main.js читает GlobalSettings, старый
  хардкод удалён»), tests/motion.test.js (+4: контракт walkWindowMs,
  «Ловкий шаг» с базой 420, структурный «окно через walkWindowMs,
  фикс 260 удалён»).

## Подводные камни

* **«×1/3» — про скорость, не про интервал**: скорость = 1/интервал.
  «Уменьшить скорость в три раза» = интервал ×3 (420 мс). 140/3 —
  наоборот, ускорение. Тест фиксирует ровно `140 * 3`.
* **MIN_MOVE_INTERVAL_MS (60) должен оставаться НИЖЕ базы (420)**:
  кламп в moveIntervalMs — `min(max(MIN, raw), base)`. Если кламп
  >= базы, «Ловкий шаг» никогда не укоротит шаг (навык мёртв).
  Зафиксировано тестом `moveIntervalMs: навык работает с новой базой
  420 мс`. При смене `move_interval_ms` не забыть: база > 60.
* **Окно walk/idle — не константа**: 260 мс подобрано под интервал
  140 (memory/000033-smooth-movement.md). При любой смене базы окно
  должно следовать за шагом — `walkWindowMs(stepIntervalMs())`, иначе
  герой замирает в idle посреди шага (при базе 420 — 160 мс за цикл).
* **140 в main.js — только fallback, не база**: структурный тест
  ищет отсутствие `const MOVE_INTERVAL_MS = 140` (старого
  объявления), а не самого числа 140 — fallback в guard'е это
  устоявшаяся деградация (паттерн 000033 с G.createMover).
* **Единый источник базы — global-settings.js** (паттерн 000020):
  любая будущая настройка/перенастройка скорости — только в SETTINGS
  (`move_interval_ms`); main.js (гейт шага + окно walk/idle) и
  motion.js — потребители. Не плодить вторую хардкод-базу.
