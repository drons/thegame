# 000033: плавное передвижение персонажа

Статус: выполнено (красные тесты + код + адверсариальное ревью); задача
перенесена в tasks/done/, отчёт — tasks/result/000033.md.

## Почему раньше «рваное»

tryMove() (main.js) прыжком менял player.x/y (целочисленный тайл) каждые
140 мс, оба слоя рендера рисовали Флогистона в центре целого тайла
(player.x+0.5), а камера между шагами ехала плавно (lerp 0.2/кадр) — мир
ехал, персонаж телепортировался. Дополнительно коэффициент камеры 0.2/КАДР
зависел от fps: при 144 Гц камера ловила цель в ~2.4 раза быстрее, чем
при 60.

## Решения

* **src/motion.js — новый чистый UMD-модуль** (паттерн controls.js,
  без зависимостей, тестируется в node):
  - `clamp01(t)` — NaN → 0 (мусорное время = начало глейда), ±∞ → 0/1;
  - `lerp(a,b,t)`, `lerpPos(prev,next,t)` — t клампится в [0,1] (не
    вылетает за отрезок), всегда новый объект;
  - `easeInOut(t) = t²(3−2t)` (smoothstep) — плавный старт/финиш глейда,
    симметрична, f(0.5)=0.5;
  - `stepProgress(now, start, interval)` → p∈[0,1], кламп за концом
    (без отката/пересчёта), interval<=0 — мгновенно, NaN-время → 0;
  - `cameraStep(cur, target, dt, tau) = cur + (t−cur)·(1−e^{−dt/tau})` —
    экспоненциальное сглаживание, НЕЗАВИСИМОЕ от fps (безпамятность
    экспоненты: 2 кадра по 8 мс = 1 кадр 16 мс), перелёта через цель
    нет по построению (k∈(0,1));
  - `CAM_TAU_MS = 1000/60/−ln(0.8) ≈ 74.7 мс` — подобрано так, что при
    60 fps коэффициент ≈ 0.2/кадр, т.е. старое ощущение камеры
    сохраняется;
  - `moveIntervalMs(base, mult)` — интервал шага с учётом «Ловкого шага»
    (derived().moveSpeedMult, player.js; SPEC «Ловкость → Скорость
    перемещения по карте»): навык только ускоряет (mult<1 или нечисло —
    игнор → база), `MIN_MOVE_INTERVAL_MS = 60` — нижний кламп, но кламп
    НЕ удлиняет шаг сверх базы (moveIntervalMs(30, 1e6) = 30);
    невалидная база — как есть (модуль не выдумывает числа);
  - `createMover({x, y, intervalMs})` → `{position, step, teleport}`:
    глейд from→to за интервал (с easing'ом), position(now) — ДРОБНАЯ
    позиция в тайловых координатах (до шага — старт, в глейде —
    lerp(easeInOut(p)), после — цель без отката), interval можно
    передавать НА ШАГ (динамическая скорость); teleport(x,y) — снап с
    отменой текущего глейда (для ЛЮБОГО now возвращает точку снапа).

* **main.js (клей, в node не тестируется)**:
  - `mover` создаётся при загрузке (позиция 0,0 — снап при старте);
  - шаг: после успешного tryMove() — `mover.step(prevPos → player, now,
    stepMs)`;
  - рендер: `rp = renderPos(now)` — ОДНА дробная точка на кадр для
    ОБОИХ слоёв: WebGL-ромб (buildFrame(rp), rp+0.5) и спрайт
    (drawSprites(now, rp), rp+0.5) — фолбэк-слой и спрайт не
    расходятся;
  - камера: `updateCamera(now)` — dt-сглаживание через G.cameraStep
    (первый кадр dt=0; dt из разницы с предыдущим rAF-таймстампом);
  - **телепорт-снапы (4 места)**: старт после findSpawn/restoreFromSave
    (иначе «скользит» от (0,0) до спавна), restoreFromSave (позиция
    сейва), combat onEnd при outcome!=='victory' (побег/смерть — назад
    на prevPos, иначе спрайт скользит обратно через поле боя);
  - «Ловкий шаг» ВКЛЮЧЁН (рекомендация аналитика, SPEC-пробел закрыт):
    `stepMs = G.moveIntervalMs(140, derived(hero).moveSpeedMult)` — и
    гейт шага, и интервал глейда. Без навыка (mult=1) — ровно 140 мс
    как раньше. G.moveIntervalMs/MIN_MOVE_INTERVAL_MS в main.js с
    guard'ами (fallback — старое поведение);
  - `__game.state.playerRender` — дробная позиция рендера
    (performance.now()) для ручной/смоук-проверки.

* **index.html**: `<script src="src/motion.js"></script>` между save.js
  и main.js — ОБЯЗАТЕЛЬНО до main.js (UMD-ловушка 000018/000038: main.js
  снимает G = globalThis.Game при загрузке). Порядок зафиксирован в
  tests/index-order.test.js (+vm-тест браузерной ветки UMD).

* **walk/idle окно 260 мс не трогаю** (косметика): при фикс. 140 мс —
  «бег» всегда в walk (норма); при динамическом интервале 60–140 мс
  окно по-прежнему всегда в walk — визуально корректно.
