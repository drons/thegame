# 000291 — Бой: кнопка «Последнее заклинание» — герой сидируется из live-карты (инверсия S3 000249)

ТЗ — `tasks/pending/000291.md` (баг-репорт drons, 2026-11-02). Родительская:
000227 (кнопка). База: master 3c15913 (worktree `task-000291`). Тип: BUG,
формулировка «новая функциональность» — инверсия намеренного поведения
000249 (запрос пользователя 2026-10-22).

## 1. Баг и корневая причина (оба симптома — ОДИН корень)

Кнопка героя (`act='lastSpell'`, src/combat-ui.js) управляется двумя
состояниями:

- модульная `let lastSpells = {}` (combat-ui.js L238; ключ герой
  `'player'`, союзники `u.id`) — пер-бой, сброс build()/finish()/catch;
- live-карта `ctx.lastSpells` (объект `lastSpells` main.js L275; ключи
  `'flogiston'`/`'efir'`/npcId) — персист между боями + раздел сейва v1
  `last_spells` (пишется всегда, main.js L830; restore L1197-1208;
  прокидка live-ссылки в 3× startCombat L1875/L2629/L3243).

`recordLastSpell` (combat-ui.js L2950) на каждом УСПЕШНОМ касте героя
пишет ОБА: `lastSpells['player']` И `ctx.lastSpells['flogiston']`. Данные
(запоминание, персист) ЕСТЬ и целы. НО `build()` (L325-340) сидирует
модульную карту из live-карты ЦИКЛОМ С ПРОПУСКОМ ИГРОКА:
`if (u === ctx.combat.player) continue;` (L335) — **решение S3 000249**
(«У Флогистона — в начале боя кнопки НЕТ, пока он не использует магию» —
явный запрос пользователя 2026-10-22). Следовательно `lastSpells.player`
на старте КАЖДОГО боя пуст → `lastSpellVis` (L3105, требует
`!!lastSpells.player`) false → `display:'none'`, стаб-клик — «нет
выбранного заклинания» (lastSpellChk L3089).

Оба симптома баг-репорта — следствия одной этой строки:

- **(а) «не запоминает заклинание Флогистона»** — персистный выбор
  (live/сейв, 000249 S2 — «Тип (id) заклинания СОХРАНЯЕТСЯ МЕЖДУ БОЯМИ»,
  обещанное 000249 и заново запрошенное в 000227.01 п.2 «раздельно для
  Флогистона / Эфира / наёмников») не подхватывается в бою N+1: кнопка
  «забыла» заклинание между боями (а в бою без кастов — вообще);
- **(б) «не отображается в начале боя»** — на первом ходе игрока
  кнопки нет, хотя персистный выбор есть.

Внутри ОДНОГО боя после успешного каста кнопка работала (record →
`lastSpells.player` → видима; пин CU249-HERO-GATE 2-я половина) — баг
именно на старте боя / между боями. Рендер/логика в остальном —
штатная (CU227-*, CU249-EFIR/MERC-IMMEDIATE зелёные).

## 2. Решение (красная/зелёная станции)

**ФИКС = сидинг ГЕРОЯ в `build()` из `ctx.lastSpells['flogiston']` —
инверсия S3 000249, аналогично союзникам (S4). Одна правка ~+10 строк в
`src/combat-ui.js build()` (блок `if (ctx.lastSpells)` L333, ДО цикла
союзников):**

```
const hp = ctx.combat.player;
if (hp) {
  const vP = ctx.lastSpells['flogiston'];
  if (typeof vP === 'string' && Array.isArray(hp.spells)
      && hp.spells.indexOf(vP) >= 0) lastSpells['player'] = vP;
}
```

Маппинг ключей — тот же, что в `recordLastSpell` (live `'flogiston'` →
модульный `'player'`). Гвард идентичен союзническому (строка + член
`hp.spells`) — забытый/подделанное id (нет в книге) → без сидинга
(legacy-путь, 0 ошибок, 0 console). Дефолтный герой `['spark','mend']`
(sheet.js L167-168; mp 16, spellInt 1, spellWis 1) — гвард проходит.
Следствие (без отдельной правки видимости — `lastSpellVis` сам):

- (б) на первом ходе игрока кнопка `display:''`, enabled (пул/мана на
  старте полные), бейдж = остаток пула сидового заклинания (контракт
  000227/000199: «0» видимо, «нет пула» — скрытие '');
- (а) выбор из боя N (live/сейв) виден в бою N+1 и после save/load.
