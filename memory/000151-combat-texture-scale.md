Дата: 2026-10-06. Worktree: .worktrees/task-000151, ветка task/000151,

## Как масштабировался экран боя раньше (до 000151)

1. **Бэкинг canvas — ФИКСИРОВАННЫЙ 336×336 px** (CELL=48 × 7×7 клеток,
   src/combat-ui.js L108-111: `canvas.width = c.width * CELL`).
   Установлено 000124 (combat-layout): «336×336 — НЕ ПОДНИМАТЬСЯ…
   Масштабирование — ЧИСТЫЙ CSS: без ресайза canvas, без
   resize-обработчиков, без setTransform» (с отсрочкой: «если ревью
   сочтёт плохим — ОТДЕЛЬНАЯ задача» — 000151).
2. **Отображение — чистый CSS** (index.html L403-411, НЕ ТРОГАЕТСЯ):
   `width: min(100vh - 32px, 100vw - 304px)` (landscape) /
   `min(100vw - 16px, 100vh - 16px - 520px)` (portrait),
   `aspect-ratio: 1/1`, `image-rendering: pixelated`, `border-box`.
   На десктопе 1920×1080 canvas отображается ≈ 1048 CSS px, на
   планшете ≈ 720, на телефоне ≈ 308–396.
3. **Механизм мыльности (жалоба ТЗ)**: SVG-спрайты (Флогистон 64×64,
   мобы 100×100, фон 336×336) движок растрит в `drawImage` в размере
   бэкинга (32–55 px на юнит) и CSS РАСТИНЕТ растр ×3.1 — на
   Retina-десктопе/планшете (dpr=2) — ещё ×2. Отсюда «мыльные»
   Флогистон и мобы на больших экранах.
4. **Клик** (src/combat-ui.js L190-201, до 000151):
   `cx = floor((e.clientX − r.left) · (canvas.width / r.width) / CELL)`
   — числитель = БЭКИНГ (336). Верно, пока бэкинг = логическое поле
   1:1; с динамическим бэкингом (000151) старая формула включает
   масштаб и даёт промах на s клеток — правка D5.
5. **Отрисовка**: render() рисовал ВСЁ в логических координатах
   (клетки × CELL), кроме 5 строк, бравших canvas.width/height как
   «размер поля» (L798 fillRect база, L809 фон, L823/L829 сетка, L674
   кламп миниполосы героя) — при 1:1 это совпадало; при динамическом
   бэкинге — растяжение на s² (правка D8: логические W/H).

## Новый механизм (000151)

1. **Откуда берётся текущий масштаб** —
   `Game.combatScale.computeBacking(baseW, baseH, dispW, dispH, dpr)`
   (НОВЫЙ UMD-модуль src/combat-scale.js, тег в index.html МЕЖДУ
   sprites.js и combat-ui.js; пин порядка — tests/index-order.test.js):
   * `baseW/baseH` — логическое поле `c.width·CELL` × `c.height·CELL`
     (336×336 при 7×7);
   * `dispW/dispH` — ТЕКУЩИЙ CSS-размер canvas из
     `canvas.getBoundingClientRect()` — измеряется в build() (ПОСЛЕ
     `document.body.appendChild(overlay)`, canvas в DOM) и в
     onResize(); в vm-песочницах rect = this.width/this.height → 1:1;
   * `dpr` — `window.devicePixelRatio` (typeof-гард → 1; на Retina-
     десктопах/планшетах 2 — цель ТЗ);
   * результат: `sx = min(MAX_SCALE=8, max(1, dispW·dpr / baseW))`
     (sy симм.), `{w: round(baseW·sx), h: round(baseH·sy)}`;
   * **НЕДАУНСКЕЙЛ** (max от 1): маленькие экраны — 1:1 как раньше.
2. **Бэкинг = w × h** присваивается canvas.width/height в build() и в
   onResize() (только при изменении). Значения на реальных экранах
   (dpr=1): 1048 (1920×1080, s≈3.119), 720 (1024×768, s≈2.143),
   396 (430×932, s≈1.179), 336 (390×844 — display 308 < 336 → 1:1);
   с dpr=2: 2096 (1080p, s≈6.24), 672 (336 CSS). Кап: b·d > 2688 →
   2688 (5K+).
3. **Где отрисовка** — render() (src/combat-ui.js), в НАЧАЛЕ:
   `if (sx !== 1 || sy !== 1) g2.setTransform(sx, 0, 0, sy, 0, 0);`
   (АБСОЛЮТНЫЙ, самовосстанавливается после сброса контекста
   при resize; при 1:1 вызова НЕТ — пины бит-в-бит). Далее — ровно
   те же слои, что и раньше, В ЛОГИЧЕСКИХ ЕДИНИЦАХ (поле 336×336,
   юниты, HP-полосы, сетка, шрифты, арки Вдоха): движок растрит
   SVG в drawImage в ЦЕЛЕВОМ device-размере (55.2 логических × s —
   резкость на любом b). 5 строк с canvas.width/height переведены
   в логические W/H (D8).
4. **Клик** — по ЛОГИЧЕСКОМУ полю (D5):
   `cx = floor((e.clientX − r.left) · (baseW / rw) / CELL)`,
   `rw = r.width || baseW` — не зависит от масштаба.
5. **Resize** — top-level `window.addEventListener('resize', onResize)`
   рядом с 'keydown' (паттерн keydown; в finish() НЕ снимается):
   переизмерить → при смене b → canvas.width/height + sx/sy +
   render(). CSS (000124) меняет отображение мгновенно, onResize
   поднимает/понижает бэкинг под неё.
6. **Дегенерация**: Game.combatScale отсутствует (битый порядок
   загрузки) — console.error ОДИН раз + бэкинг 336, s=1 (поведение
   до 000151, бой играбелен). rect без width/height (lenient-стабы
   main-visuals и др.) — 1:1.

## Что НЕ меняется

* **CSS экрана боя** (index.html L403-411, формулы 000124,
  pixelated, бордер 2px) — бэкинг следует за CSS автоматически.
* **Боевое ядро** (src/combat.js): ходы, RNG, сейвы, детерминизм —
  масштаб — UI-состояние (модульные sx/sy в combat-ui.js), в ядро не
  добавлено НИЧЕГО (D11).
* **Спрайты** (svg/combat/*), z-order, кадры, анимации, HP-полосы,
  уровни, подсветка, препятствия, арки Вдоха, шрифты — координаты
  и отрисовка те же (только устройство растит их в большем бэкинге).
* **Маленькие экраны** (display < 336): b = 336, s = 1 — поведение
  бит-в-бит с 000124 (все существующие 1734 теста проходят без
  правок).
* **Глобальные правила** (000038/000053/000043, svg.test.js,
  EXPECTED_SVG_BY_DIR) — новых SVG/модульных require НЕТ.
