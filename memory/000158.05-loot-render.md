## 1. Кратко: что делает задача

Пока лут не собран — на тайле с `t.loot` рисуется спрайт предмета
(ОДИН спрайт на item-id) на 2D-слое #sprites: проход 1 drawSprites,
СТРОГО ПОСЛЕ декораций (крупный объект поверх травы), ПЕРЕД
постройками/мобами/Флогистоном (проходы 2/2.5/3). Порог зума
LOOT_MIN_ZOOM = 16 (своя константа; лут крупнее декораций →
виден дальше, чем декорации с VISUALS_MIN_ZOOM = 24). Собраный лут
НЕВИДИМ — ТОЛЬКО через `G.lootVisible(collectedLoot, x, y)`
(000158.04); рендер своё состояние НЕ хранит. Fallback: спрайт не
загрузился → тайл без иконки, краха нет (паттерн декораций).
Скipped на стенах постройки (000042 — защитный код; структурно
лут под постройкой = null, 000158.03).

## 2. Решения (openQuestions ТЗ + анализы)

**D1. `lootSprite(itemId, tx, ty)` — чистая/детерминированная,
item = СТРОКА id (`t.loot.item`, ТЗ-форма `{item:id}`), результат
`{sprite, x, y, size} | null`.** — неизвестный/мусорный id
(не-строка, пустая, нет в каталоге) → **null** (решение
расхождения a2/a3; паттерн селекторов по id в sprites.js —
dungeonFloorFrame/mercFrames: неизвестный → null/[]; main.js
гардирован `if (ls && …)`; в игре null невозможен — map.js
ставит только id из каталога). Позиция — ОДНА детерминированная
точка (НЕ 2–3 как у декораций — лут один на тайл).
Семантика: «нет каталога/неизвестный id → нет иконки» —
явная и тихая.

**D2. seed = `LOOT_VISUAL_SEED + index * 0x9e3779b9`, index —
ПОЗИЦИЯ предмета в ITEMS (0-based).** — тот же ключ-схема, что
map.js lootCandidates/lootCore (L395-416, L1034: `c.index *
0x9e3779b9`); append-only-инвариант каталога (000157.01/
000158.02) делает индекс стабильным в node (require) и в
браузере (Game.ITEMS) → идентичные позиции; РАЗНЫЕ предметы на
одном тайле → РАЗНЫЕ позиции (тест «не штамп»). hash2 принуд.
32-битит seed (Math.imul-алгебра, perlin.js L110-116) —
`index*0x9e3779b9` (≤ ~2e11) безопасен.

**D3. `LOOT_VISUAL_SEED = 0x7f3a51c9`** — СВОЙ 32-bit сид
рабочего канала рендера лута. НЕ VISUALS_SEED 0x51a11ce5
(декорации), НЕ DUNGEON_FLOOR_SEED 0x669f0101, НЕ LOOT_SEED
map.js (GLOBAL_SEED ^ 0x4C4F4F54 — КАНАЛ ГЕНЕРАЦИИ «что лежит
на тайле»; этот — КАНАЛ РЕНДЕРА «как/где иконка» — разные
смыслы, разные модули). Коллизий с существующими сидами НЕТ
(grep по src/: 0x5eedc0de main.js, 0xd0d6b5e5/0xd337b153/
0x5e11c3a7/0x0c9f4b2d/0x53d10d53 dungeon, 0x4c41594f/
0x434f4e54 cities, 0x72656675/0x71756974 companions и др. —
совпадений нет). **Золотые hash2** (зафиксировать в тесте
SP-LOOT-3, значения вычислены на 1ca4904; x — офсет +1, y —
офсет +2 к seed):
  hash2(-1, 1, SEED+1) = 779866397
  hash2(-1, 1, SEED+2) = 666786471
  hash2(3, 4, SEED + 22*0x9e3779b9 + 1) = 462833820
  hash2(3, 4, SEED + 73*0x9e3779b9 + 2) = 3271630315
(22 = moonstone — первый loot-id каталога; 73 = mushroom_grey —
последний).
**ПРАВКА RED-станции (2026-10-12):** значения gold3/gold4
пересчитаны (node-прогон с перлином 1ca4904): в проекте были
777427825/693094242 — арифметическая ошибка черновика (seed
для index 22/73 превышает 32 бита; hash2 32-битит алгеброй
imul/XOR — ручной пересчёт давал неверные числа). gold1/gold2
(индекс 0) совпали и не менялись.

**D4. `LOOT_SIZE = 0.25`** (имя — решение расхождения a1
LOOT_VISUAL_SIZE/a2 LOOT_SIZE: size — константа РЕНДЕРА, не
«visual-канал» как seed; ТЗ имя не предписывает) — СЕРЕДИНА

**D5. `LOOT_MIN_ZOOM = 16`** — своя константа (ТЗ: «дефолт,

     const items = lootItemsRef();

     if (index < 0) return null; // неизвестный id → нет иконки (D1)
