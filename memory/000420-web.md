# 000420 — паутина гигантского паука (трейт web, замедление хода)

## Что реализовано

- `MOB_TYPES.spider.traits` = `{ poison: true, web: true }` (src/combat.js,
  каталог мобов) + зеркало `assets/mobs/spider.json` + `"web": { "type":
  "boolean" }` в `assets/mobs/schema.json` (traits `additionalProperties:
  false`).
- Константы рядом с FLEE_HP_FRAC: `WEB_CHANCE = 0.25`, `WEB_TURNS = 2`,
  `WEB_SLOW_VALUE = 0.15`.
- Игрок: в `mobAttack` после яд-блока — `u.traits.web && c._rng() <
  WEB_CHANCE` ⇒ `c.ps.debuff = { stat: 'ход_вниз', value, turns }` + лог
  «Паутина: вы замедлены!».
- Союзник: в `mobAttackAlly` после блока «дебафф» суккуба — тот же ролл
  под `dealt > 0` ⇒ `t.debuff` (тот же стат/форма) + лог
  «<имя>: паутина замедляет!».
- `unitDebuffValue`: игрок читается из `c.ps.debuff`
  (`u === c.player ? c.ps.debuff : (u && u.debuff)`) — симметрия с
  `unitBuffValue` (баф игрока живёт в `c.ps.buff`, канон 000235.01
  `if (t) t.buff = eff; else c.ps.buff = eff;` в spells.js «регенерация»).
- НОВЫЕ тики (см. ниже): `c.ps.debuff` в цикле `c.ps.buff`-тика,
  `a.debuff` в цикле `a.buff`-тика союзников — оба в `startRound` ДО
  `buildTurnOrder`.
- Потребитель НЕ тронут: «ход_вниз» > 0 ⇒ ключ очереди инициативы
  `init − SLOW_INITIATIVE_PENALTY (1e9)` (000235.08.01) — замедленный
  ходит последним; при `turns → 0` позиция возвращается сама.
- `spec/mobs.md`: сноска «механики паутины нет» снята, строка паука —
  «Яд; паутина замедляет» (grep по spec/ = 0 хитов старой фразы).

## Машинное состояние: тики дебафов не-мобов появились только здесь

До 000420 тик `debuff.turns` существовал ТОЛЬКО для мобов
(`m.debuff.stat !== 'dot'` в startRound). У слотов `a.debuff` (союзники) и
дебафа игрока не было ни одного ПИСАТЕЛЯ: `unitDebuffValue` для юнита
игрока возвращал 0 вечно (у `c.player` поля `debuff` нет), purify
обнулял `t.debuff` лишь при явной цели. Без новых тиков паутина на
игроке/союзнике была бы ВЕЧНОЙ — поэтому тики входят в задачу, а не
«лишний скоуп». Ритм — паритет с моб-тиком: начало раунда, до пересборки
очереди.

## Семантика слотов и записи

- Повторное попадание паука ОБНОВЛЯЕТ запись (перезапись всего объекта,
  `turns` снова 2) — как `t.buff = eff` у «регенерации»; в отличие от
  яда, который гейтится `c.ps.debuff`-подобным `=== 0` и не перезаливается.
  Это осознанный выбор: «замедление на 2 хода» = свежие 2 хода после
  последнего опутывания.
- `c.ps.debuff` — боевой транзиент, в сейв НЕ идёт (слот в литерале `ps`
  рядом с `buff`/`bind`). Вариант «писать в `c.player.debuff`» (заявлялся
  в анализе) ОТВЕРГНУТ: `c.player` — живой персистированный лист, запись
  трейта просочилась бы в сейв; `c.ps` — документированный слот боёвых
  транзиентов, формулировка карточки («тот же паттерн c.ps/debuff-записи
  с ходами») прямо на него указывает.
- Контроль суккуба живёт в `t.bind` (отдельный слот) — со `t.debuff`
  не конфликтует; единственные читатели/писатели `a.debuff` после 000420:
  web-запись, тик, purify/mass_holy_light (обнуляют), unitDebuffValue.

## Известный зазор (осознанно НЕ расширен)

`purify` на себя (`t` нет) пишет `out.purified = null` и не трогает
`c.ps.debuff` — паутина с игрока само-очищением НЕ снимается;
`mass_holy_light` снимает дебаф только с союзников. Тот же зазор до
000420 был не наблюдаем (не было писателя). Кандидат в отдельную задачу
(«purify-self чистит c.ps.debuff»), в скоуп 000420 не входит: карточка
требует трейт + потребителя + сноску, а не матрицу рассеивания.

## Каталог-паритет: задача НЕ src-only

`tests/combat.test.js` «assets/mobs: зеркало в combat.js идентично
JSON-каталогу» сверяет `MOB_TYPES` c `assets/mobs/*.json` deepEqual после
снятия ART_ONLY (`описание`, `art`) ⇒ любое новое поле трейта обязано
появиться и в JSON, и в схеме. Моб-каталог НЕ входит в sync-генерацию
(sync-* скриптов для mobs нет — зеркало руками), но `sync:check`
отказывается работать на грязном дереве: `spells.test.js` W-08
(«sync:check exit 0») краснеет, пока `src/combat.js` не закоммичен —
артефакт порядка, а не расхождение.

## Эррата анализа/брифа

- Бриф: «sync:check не задействован (src-only)» — неверно дважды:
  assets/mobs/spider.json + schema.json обязательны (паритет-тест),
  W-08 ловит грязное дерево.
- Бриф-кандидаты красных регрессов (интервалы EFIR_BAL119 при новом
  rng-расходе, счётчики) — легли ЗЕЛЁНЫМИ: WEB_CHANCE=0.25 жрёт ролл
  только у паука на попадании; свип 35 боёв (spider_nest,
  avgRoundsMax=12, запас 0.74) прошёл без ре-пинов.
- Тестовые дельты по времени: `endTurn` сдвигает РОВНО ОДИН слот очереди
  (моб ходит внутри своего endTurn; последовательные моб-слоты не
  схлопываются), пред-роллы в createCombat съедают моб-слоты до игрока —
  ожидание «2 вызова за ход» ложно; T2b пинит 1 бросок на промах / 3 на
  попадании при ОДНОМ endTurn.
