## 2. Схема (assets/spells/schema.json)

Новые опциональные поля (required — те же 13, без изменений):

```json
"параметры": {
  "type": "object",
  "additionalProperties": false,
  "properties": {
    "stat": { "enum": ["урон","броня","ход","реген","вампиризм",
      "отражение","попадание","получаемый_урон","иммунитет_контроля",
      "урон_вниз","броня_вниз","попадание_вниз","получаемый_урон_вверх",
      "dot","ход_вниз"] },
    "value": { "type": "number", "minimum": 0 },
    "turns": { "type": "integer", "minimum": 1 },
    "summon": { "type": "string", "pattern": "^[a-z][a-z0-9_]*$" },
    "object": { "enum": ["стена","зона"] },
    "radius": { "type": "integer", "minimum": 1, "maximum": 5 },
    "days": { "type": "integer", "minimum": 1, "maximum": 3 },
    "mode": { "enum": ["метка_установить","метка_вернуться","город"] }
  }
},
"вне_боя": { "type": "boolean" }
```

Дословный контракт параметров по действиям (ТЗ/исследование D1):
- баф `{stat, value, turns}` — stat из 9 баф-статов; цель — себя или союзника;
- дебаф `{stat, value, turns}` — stat из 6 дебаф-статов; цель — враг;
- призыв `{summon: id из assets/mobs, turns: 4}` — уровень призыва =
  `уровень` спелла;
- создание `{object: стена|зона, turns, radius}` — стена: ряд тайлов, 5 ходов;
  зона: radius 1..3, stat-дебаф врагам внутри, 3 хода (алли-зона — баф-стат
  союзникам);
- невидимость `{days: 1..3}` — механика 000235.03 (вне боя);
- телепорт `{mode: метка_установить|метка_вернуться|город}` — 000235.04;
- внебой `{days: 1..3, radius?: 1..5}` — мировая утилита, обработчик по id
  спелла в src/spells.js (switch) — добавляется в .02+.

Решения по схеме:
- union 15 stat = 9 баф (урон/броня/ход/реген/вампиризм/отражение/
  попадание/получаемый_урон/иммунитет_контроля) + 6 дебаф (урон_вниз/
  броня_вниз/попадание_вниз/получаемый_урон_вверх/dot/ход_вниз).
- `value` — number ≥ 0 (доли 0..1 и плоские значения; отрицательные не
  нужны — направление задаёт stat).
- `radius` максимум 5 — общий ключ (зона 1..3 — ограничение КОНТЕНТНОГО
  уровня: схема одного уровня не выразит «зона ≤3, внебой ≤5»; волны
  .07–.12 пином своих заклинаний фиксируют radius 1..3).
- «эффект» (внебой) — НЕ ключ схемы: ТЗ фиксирует ровно 8 ключей карты,
  диспетчеризация внебоевых эффектов — по id заклинания (switch в .02+).
- Валидатор tests/json-schema.js не поддерживает `default`/if-then —
  «default false» вне_боя фиксируется поведением (тест S3), a не схемой.

### 3.5 Призыв (спелл-кэс)

Рецепт (spells.js castSpell, после расхода пула/маны):
```
mt = MOB_TYPES[pa.summon]
u = makeAlly({ id: 's' + c.units.length, name: mt.name, role: mt.role,
               level: spell.уровень, dmg: mt.dmg, hp: mt.hp, armor: mt.armor,
               attrs: { dexterity: mt.dexterity || 0, intelligence: mt.intelligence || 0 },
               kind: 'summon' }, c.units.length)   // moraleMult — дефолт 1
u.summonTurns = pa.turns
placeAllies(c, [u]); c.units.push(u)
log: `${spell.название}: ${u.name} (${pa.turns} ходов).`
```
- Уровень = `уровень` СПЕЛЛА (не героя) — ТЗ; статы масшталируются по
  уровню makeAlly (maxHP = round((8+4·ур)·mt.hp·hpРоль), damage =
  round((2+0.7·ур)·mt.dmg)).
- kind 'summon' (дискриминатор, отличает от 'merc'/'efir').
- moraleMult = 1 — призывные НЕ получают моральный бонус наёмников
  (задокументированное упрощение: createCombat передаёт 1+companionMoraleBonus
  только составу отряда).
- 1×1, movePerTurn 1, traits {}, spells [] — дефолты makeAlly (ТЗ: «паттерн
  makeAlly, 000193»).
- Расстановка — placeAllies: анкоры вокруг игрока + построчный скан снизу;
  occ = игрок + c.units (препятствия НЕ проверяются — то же, что у
  наёмников 000080; задокументировано); 0 c._rng.
- Очередь: в turnOrder входит со СЛЕДУЮЩЕГО пересчёта buildTurnOrder
  (первый ход — раунд R+1).
- Fail-closed в evalSpell (ДО расхода пула/маны, canCastSpell — зеркало):
  - `!pa || !MOB_TYPES[pa.summon]` → «неизвестный призыв: {id|нет}»;
  - `!allyRoom(c)` → «нет места для призыва» (allyRoom — новый чистый
    хелпер, зеркалит скан placeAllies, без мутаций/бросков).
- Истечение: startRound, верх цикла livingAllies: `summonTurns -= 1`; при
  0 → `a.fled = true` + log `${a.name} рассеивается.` + continue (без
  рефилла). Живёт ровно `turns` раундов включая раунд каста (каст R:
  активен R..R+3, действует R+1..R+3, рассеивается в начале R+4 при
  turns:4).
- Почему `fled = true` (а не alive=false): каноническое состояние
  «юнит покинул бой, но не убит» (паттерн timid-моба :1933, где
  fled=true при живых HP); livingAllies (`side 'ally' && alive && !fled`)
  одним фильтром выключает юнит из очереди/рефилла/целей; combat-ui
  пропускает fled в рендере (:1098); hp сохраняется (не труп).
  checkVictory при исчезновении НЕ вызывается (победа — только от
  livingMobs).
- Последствия для XP (формулы НЕ трогаются — минимальная интеграция):
  - checkVictory :1251: N = 1 + ВСЕ юниты side 'ally' в c.units (живые/
    мёртвые/fled) → призывной РАЗБАВЛЯЕТ долю XP даже после исчезновения
    (задокументированное следствие; калибровка при пересиле — 000119);
  - allyXp :1256: фильтр `kind === 'merc'` → призывные НЕ получают allyXp;
  - main.js:554 dead_mercs: `side 'ally' && kind 'merc' && !alive` →
    призывные НИКОГДА не попадают в dead_mercs.

### 3.6 Создание

Стена (object 'стена'):
- Ряд y = clamp(c.py − 2, 1, c.height − 2); ВСЕ x = 0..width−1, кроме:
  - клетки игрока (x===px && y===py);
  - клеток живых юнитов (alive && !fled, rect w×h);
  - клеток, УЖЕ в c.obstacles (000050) — ИНАЧЕ при истечении стены
    постоянные препятствия поля были бы удалены (критично).
- `c.obstacles.add(x+','+y)` + `c.walls.push({ cells, turns: pa.turns })`;
  log `${spell.название}: стена (${pa.turns} ходов).`; out.wall = cells.length.
- Непроходимость «бесплатно»: ВСЕ пути движения уже читают c.obstacles
  (playerMove, A* pathStepTo мобов, reachableCells, rectFree,
  generateObstacles) — ни один путь-код не трогается.
- Истечение: turns−=1; при 0 → delete клеток из c.obstacles, splice из
  c.walls (обход с конца).
- Задокументированный сайд-эффект: ряд во всю ширину РАЗДЕЛЯЕТ поле на 5
  раундов (игрок и мобы не пересекают; A* мобов без пути → «зажатый»
  шаг, без краша); стена рехнетится — вечного застревания нет.

Зона (object 'зона'):
- Слот ОДИН: `c.zone = { x: c.px, y: c.py, radius: pa.radius, stat, value,
  turns: pa.turns }` (рекаст — overwrite).
- Геометрия — Чебышёв (000135): `max(|u.x−px|, |u.y−py|) ≤ radius`.
- Применяется ОДИН раз в момент каста (v1: повторного применения при
  ре-входе в радиус НЕТ — задокументировано).
- Роутинг по стороне stat — ПО ПОЛНОМУ СПИСКУ 6 ДЕБАФ-СТАТОВ ТЗ
  (DEBUFF_STATS, ревью: «ход_вниз» был выпаден — зона с ним шла
  СОЮЗНИКАМ как баф; эффект у «ход_вниз» в .01 нет — no-op, 3.3):
  - дебаф-стат (урон_вниз/броня_вниз/попадание_вниз/
    получаемый_урон_вверх/dot/ход_вниз) → `u.debuff = {stat,value,
    turns}` живым МОБАМ в радиусе;
  - баф-стат (урон/броня/попадание/получаемый_урон) → `u.buff = {...}`
    живым СОЮЗНИКАМ в радиусе (ТЗ: «для зон исцеления — эффект на
    союзников по `параметры`»);
  - игрок НЕ затрагивается (центр зоны — его клетка; ТЗ игрока не
    упоминает — граница v1).
- v1-зоны используют только АКТИВНЫЕ статы (3.3); зона с no-op-статом —
  валидна схемой, боевого эффекта не даёт (граница для волн); РОУТИНГ
  при этом — по полному списку дебаф-статов ТЗ (выше), не по
  «активность» эффекта.
- Log `${spell.название}: зона (радиус ${pa.radius}, ${pa.turns} ходов).`;
  out.zone = pa.radius.
- Fail-closed (evalSpell, ДО расхода пула/маны; зеркало 000037):
  - `!pa || pa.object не стена/зона` → «неизвестный объект: {object|нет}»;
  - (ревью) `turns` не integer ≥1 (СТЕНА ИЛИ ЗОНА) → «неполные
    параметры: turns» (без turns тик «−=1; ≤0 → снять» даёт NaN —
    стена была бы вечной; зона — мёртвый слот);
  - (ревью) зона: `radius` не integer 1..5 → «неполные параметры:
    radius» (без radius сравнение `> undefined` — false: эффект шёл на
    ВСЁ поле); `stat` вне union 15 (EFFECT_STATS = BUFF_STATS ∪
    DEBUFF_STATS, новый констант) → «неполные параметры: stat»;
    `value` не конечное число → «неполные параметры: value».

### 3.7 Отказ внебоевых в бою (единая причина)

- `OUT_OF_COMBAT = new Set(['невидимость','телепорт','внебой'])`.
- evalSpell: гейт ПОСЛЕ KNOWN_ACTIONS-гейта (:336-340), ДО пула/маны:
  `OUT_OF_COMBAT.has(spell.действие)` → reason «внебоевое заклинание».
- canCastSpell — автоматическое зеркало (чистый вызов evalSpell).
