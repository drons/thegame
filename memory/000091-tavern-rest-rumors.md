### 2.5 Чистое ядро слухов `tavernRumors` (экспорт)

**Сигнатура**: `tavernRumors(map, x, y, day, texts, hash) → { entrance: {x,y}|null, dungeonType: number|null, fragments: string[] }` —
ВЕРНЁТ ОБЪЕКТ (никогда не null — `moonDreamHint` уже null-safe: битая/отсутствующая карта →
`{entrance:null, dungeonType:null}` без исключения). Чистое ядро = данные; форматирование —
в apply-слое (1:1 паттерн A40/«Сон»). `hash` = `G.hash2` (передаётся в параметр — как
`deterministicRoll`/`pickFragment`).

- **Число фрагментов** `f = texts.length < 2 ? 1 : 1 + (hash(x, y, RUMORS_COUNT_SEED ^ day) % 2)` → 1 или 2.
- **Индексы** (избегаем повтора подсказки, L≥2):
  `i0 = hash(x, y, RUMORS_TEXT_SEED ^ day) % L`;
  при `f === 2`: `i1 = hash(x, y, RUMORS_TEXT2_SEED ^ day) % L; if (i1 === i0) i1 = (i0 + 1) % L`.
  `fragments` всегда без повторов; L=1 → f=1 по построению.
- **Сиды** (свои, ASCII-именованные, экспортируются для пиноутов; паттерн 000074):
  - `RUMORS_COUNT_SEED = 0x52554D43` ('RUMC')
  - `RUMORS_TEXT_SEED  = 0x52554D54` ('RUMT')
  - `RUMORS_TEXT2_SEED = 0x52554D32` ('RUM2')
  ⚠ Золотые индексы фрагментов a1-domain.md измерены с сидом 'TAVR' (0x54415652) — НЕ
  ПЕРЕИСПОЛЬЗОВАТЬ: e2e-гольдены фрагментов ПЕРЕИЗМЕРИТЬ на стадии реализации/красных
  тестов с сидами выше (таверна (41,2), дни 1 и 2).
- **Вход в пещеру**: `moonDreamHint(map, x, y)` (000076, переиспользуем 1:1, не
  переинвентируем): кандидат = `t.hasBuilding && t.building === CAVE_ENTRANCE`
  (ленивый `G.BUILDING_TYPES`, fallback 9) && `t.buildingId !== 48` (развалины — НЕ входят);
  ближайшее по Чебышеву, тая-брейк лексикографический (x, потом y); `dungeonType` через
  ленивый `G.dungeonTypeFor(terrain, pixelAt alpha fallback 255)`.

### 2.6 Apply-слой `applyTavernRumors(st)` (частный, в building-effects.js)

- Отказы `{ ok: false, message: 'недоступно' }` (fail-open, 000053; без исключений, 000029):
  - `lazyGame()` не имеет `hash2` → отказ (паттерн applyRuneStone);
  - **НЕТ содержимого вообще**: валидных текстов нет И входа нет → отказ.
- Состав подсказок (порядок ФИКСИРОВАН — фрагменты, потом вход):
  1. строки фрагментов: `'«' + f + '»'` (кавычки, паттерн 000074 «фрагмент»);
  2. последняя строка:
     - есть вход: `'Вход в пещеру (' + e.x + ', ' + e.y + ') — ' + имя + '.'`,
       имя = `G.DUNGEON_NAMES[dungeonType]`, fallback `'подземелье'` (1:1 «Сон»);
     - входа нет: `'Входы в пещеры не видны.'` (1:1 «Сон»).
- Успех: `{ ok: true, message: 'Слухи:\n· ' + hints.join('\n· ') }` — 2–3 строки;
  мультисайновый flash рендерится (`#hud { white-space: pre-line }`, index.html L42).
- **Отсутствует карта** → НЕ отказ (в отличие от «Сона», где карта = всё действие):
  слухи = лор из каталога, а карта лишь часть; `ok: true` с фрагментами +
  `'Входы в пещеры не видны.'`. В игре карта всегда есть (getMap() после boot) — ветка
  для node-тестов/устойчивости.
- Снапшот НЕ мутируется (apply-профиль); `texts = validTexts(st.catalog.особые_параметры.эффект.слухи.тексты)`.
