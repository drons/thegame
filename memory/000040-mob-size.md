# 000040: размер мобов на боевом поле (1x1–3x3) из assets/mobs

Статус: выполнено и закоммичено (тесты 216 → 225 pass).

## Решения

* **Размер — данные**: `size: { w, h }` записан в JSON **каждого** из 36
  мобов (assets/mobs), добавлен в assets/mobs/schema.json как
  обязательное поле (integer 1..7, additionalProperties: false).
  Зеркало MOB_TYPES в src/combat.js обновлено идентично (тест
  консистентности держит).
* **Назначенные размеры** (по задаче: волки/орки 1x1, крупные крупнее):
  - 2x2: troll, cave_bear, salamander, water_elemental, lower_demon;
  - 3x3: bone_coloss, stone_golem, earth_elemental, fire_elemental,
    abomination;
  - остальные 26 мобов — 1x1.
  Драконов в каталоге нет, поэтому максимум 3x3; схема разрешает до 7 —
  под будущих (5x5 драконы — просто данные).
* **Геометрия боя (src/combat.js)**:
  - юнит = прямоугольник w×h, якорь — верхний левый угол (x, y);
  - `unitAt` — попадание клетки в прямоугольник (игрок не может зайти
    на любую из клеток моба);
  - `rectFree(c, x, y, w, h, ignore)` — в пределах поля, не на игроке,
    без пересечения других живых юнитов;
  - `unitDist(c, u)` — Манхэттен от клетки игрока до прямоугольника
    (0 = касание); для 1x1 идентично старому dist → поведение мелких
    групп не изменилось;
  - все проверки дальности (атака/лук/заклинания/дальнобойные мобы/
    melee-петля) — по `unitDist`: моб 3x3 «вплотную», когда игрок у
    любого края, а не только рядом с якорем;
  - `stepToward`/`stepAway` двигают ЦЕЛОЕ прямоугольное тело
    (направление — по краям; шаг только если `rectFree`), mobAct
    без изменений по логике;
  - `placeUnits` (замена xs-паттерна): крупные мобы ставятся первыми
    (площадь desc, индекс asc) построчным обходом сверху; мелкие (1x1)
    сохраняют прежние якоря [1,3,5,0,2,4], строки 0/1, и сдвигаются
    построчно только если якорь занят крупным. Детерминированно,
    без RNG; занятость — локальная сетка (не зависит от координат
    не поставленных ещё юнитов).
* **UI (src/combat-ui.js)**: отрисовка моба — прямоугольник
  w*CELL × h*CELL (HP-бар по ширине, уровень по центру, подсветка цели
  по всему прямоугольнику); клик-выбор цели — в любую клетку
  прямоугольника.
* **Глобальная карта**: размер моба туда не выходит — группы рисуются
  фреймом в одном тайле (src/main.js), `size` там не используется →
  «на глобальной карте всегда 1x1» выполнено конструктивно.
* **Баланс**: формулы HP/урона не тронуты; размер влияет только на
  геометрию. Балансовые тесты (000027) после задачи все зелёные —
  в т.ч. elemental_circle (fire 3x3) и abyss_spirit (abomination 3x3 +
  lower_demon 2x2) на medium при hero L15.

## Подводка: тестовый авто-игрок (tests/combat.test.js)

* Хелперы авто-игры (uDist/autoTarget/autoPlay/standNextTo) переведены
  на rectangle-семантику: бот видит моба целиком.
* Две ошибки, найденные и исправленные в боте (не в игре):
  1. Направление шага игрока к цели было инвертировано (формула
     stepToward — от лица МОБА; для игрока знак обратный) — герой
     уходил от цели к краю поля и бой «не завершался».
  2. Приоритет «бить самого раненого соседнего» сломал договор 000027
     «поддержка — приоритет»: суккуб (support) рядом с целью
     оставался в живых и лечил абomination быстрее, чем герой бил →
     stalemate. Теперь: цель рядом — бьём ЕЁ; бить соседа — только
     когда к цели подойти нельзя (закрыт путь многоклеточным мобом).
* standNextTo для крупных мобов — клетки у края прямоугольника с
  фильтром «дистанция до прямоугольника ≤ 1» (диагональ угла = 2).

## Тесты (9 новых, tests/combat.test.js)

size во всех 36 JSON; мелкие 1x1 / крупные >1x1; зеркало несёт size;
боевой юнит получает size из описания; заход на клетки прямоугольника
запрещён; ближний бой по краю, а не по якорю (+проверка «2 клетки от
края — далеко»); крупные двигаются целым телом 20 ходов без
перекрытий; расстановка без перекрытий/в пределах поля (все рецепты ×
4 сида); крупная группа (2x2+3x3+1x1) бьётся авто-игром.

## Ограничения / дальнейшее

* 5x5 (драконы) — только когда появятся в каталоге; код уже
  поддерживает до 7x7 по схеме.
* Лут за бой не выдаётся (только описан) — как и до задачи.
