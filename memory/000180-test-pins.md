## 2. Правила для будущих рефакторов (выводы ретро)

1. **Не удалять последний ненулевой пин члена формулы.** Ре-пин
   000168 заменил фикстуры с attrs (мудр 3/12) на attrs{} —
   «эквивалентные по сюжету», НО потерявшие единственный член
   формулы (0.5·attr). Правило: при замене фикстуры проверять,
   что КАЖДЫЙ член формулы/каждая ветка остаётся с ≥1 пин-ом;
   attrs{}-фикстуры легальны, но НЕ заменяют ненулевые.
2. **Комментарии о покрытии — проверяемый факт.** «Покрыто
   тестами XXXX» писать только после grep-верификации, что XXXX
   пинит ИМЕННО это поведение (формулу/строку/ветку), а не соседнее
   (каталог/guard/другую формулу). Непроверенный комментарий —
   маскировка пробела.
3. **Новая ветка в коммите = новый пин в том же коммите.**
   allyMove-проверка «тут стоит игрок» была добавлена в 000168,
   но сценарий не вошёл в красные блоки → 2 недели без покрытия
   (до ретро). Checkpoint: `grep -r "<новая причина/строка>"
   tests/` → ≥1 совпадение, иначе блок неполный.
4. **Сообщение коммита = реальный список тестов.** 09ffa25
   заявлял «закрытие по [Esc], e2e-сценарии» — в файле ни того, ни
   другого (R0–R7). Правило: перечислять добавленные test-имена
   дословно; ретро сверяет message vs diff.
5. **Стаб ≠ DOM: проверять класс бага под ВЕРНОЙ семантикой
   стаба.** plain-Array `children: []` скрывал HTMLCollection-
   регрессию от 000145 до 000169 (Esc-пин был зелёным на баговом
   коде). Если фикс касается DOM-коллекций/свойств — пин обязан
   стоять под стабом с браузерной семантикой (тест
   ui-panel-htmlcollection — прецедент: R0 self-pin стаба против
   «починки» в сторону Array).
6. **Пинить ТЕКУЩИЙ фактический текст, не цитату.** Строки
   stateEl/логов сдвигаются и правятся последующими задачами
   (000171/000173/000174/000176 двигали область stateEl после
   ретро 000168: 1189 → 1422-1424). Пиновать поведение
   (byte-exact-ассерты по выводу ТЕКУЩЕГО кода, валидированные
   прогоном), а не номера строк.
7. **Двух-веточный формат — пинить ОБЕ ветки.** Д10 (строка
   наёмника / строка Эфира), player/ally-пулы allyHeal,
   c.efs есть/нет — каждая ветка шаблона заслуживает ≥1 пина с
   конкретными цифрами; fallback-ветки (c.efs=null) — тоже
   (документированная деградация = контракт).

## 3. Чувствительность (почему пины не «мёртвые»)

* HEAL-1: откат члена 0.5·attrs (attrs игнорируются) → «+5»
  вместо «+7» → byte-exact лог-ассерт падает; хардкод 7 вместо
  формулы → якорь (b) «+5» падает.
* MOVE-1: удаление проверки (откат 000168) → c.move на клетку
  игрока ok:true + позиция сменилась → AssertionError.
* R8: pre-000169 код → toggle(true) бросает ДО attachEsc →
  первый ассерт openPanel (без выброса) падает; если бы броска
  не было, но слушатель не вешался — ассерт «длина 1» падает;
  если бы Esc не снимал слушатель — ассерт «длина 0» падает.
* CU180: откат Д10 → строки Эфира нет в stateEl → includes падает;
  откат fallback-тернарника (c.efs ? … : 0) → re-render с
  c.efs=null либо краш, либо строка с NaN/undefined → падает.

Валидация значений — прототипы /tmp/thegame-wf-000180/proto1.js
(HEAL-1/MOVE-1), proto2.js (CU180), proto3.js (R8) +
scratch-verify.js (ALL PASS на 0f18ed0, до изменения src).
