# 000422 — acroBonus: потребитель горного лаза (реализация ветки (a))

Вердикт — в `memory/000422-designer-decision.md` (выбрана (a)). Файл append-only: правки
последующих волн — новые секции, не переписывание.

## 1. Механика (src/main.js, браузерная ветка init)

Три разнесённых предиката — это и есть решение задачи (слияние любого пары = баг, §2):

* `acroChance()` — шанс = `clamp(G.derived(hero).acroBonus, 0, 1)`; некорректный derived
  (нет экспорта / NaN) → 0 (деградация = поведение до задачи);
* `heroPassable(t, day)` — горы проходимы для СТОЯНИЯ ровно при `acroChance() > 0`, БЕЗ
  кубика. Ветку поставлена ПЕРЕД frost_walk-веткой (гора не вода, ветки не спорят);
* `acroMountainEnterOk(t)` — только вызывается из tryMove. Порядок: не гора → true;
  шанс 0 → false; СТОИМ на горе → true (хребет без кубика); шанс ≥ 1 → true (клэмп);
  иначе кубик
  `q = ((G.hash2(t.x, t.y, ACRO_MOUNTAIN_SEED) ^ ((clock.day + 1) * 0x9E3779B9)) >>> 0) / 4294967296`,
  вход ⟺ `q < шанс`. `ACRO_MOUNTAIN_SEED = 0x4143524f` (ASCII «ACRO», паттерн
  CAMP_STOCK_SEED в items.js). hash2 — финализатор murmur3 (perlin.js), НЕ rng:
  rng-стрим мира побитов чист (T12 гейт через installRngCounters).

## 2. Почему кубик НЕ внутри heroPassable

Читатели heroPassable о ТЕКУЩЕЙ клетке: позиция-сейв (restore) и onDay-релокат. Кубик там
(a) выталкивал бы с горы ~95% попыток загрузки при acro 1 (сейв лотерея) и (b) на хребте
без прохода нарушал бы переносимость W-10c (память 000235.08 §11): без успешного шага день
не тикает — герой в кармане из клеток с q ≥ шанс сидел бы вечно. Хребет (гора→гора) поэтому
кубика не бросает вообще; день доходит до rest/relocate только через движение.

## 3. Стоимость шага

`worldStepCost`: MOUNTAIN → 2 явной веткой ДО thick-проверки (у гор `thick:false` — без
ветки лазавший герой получал бы бесплатный срез маршрутов). spec/game-time.md «стоимость
шага 1 или 2» остаётся верной. path_of_vines горы НЕ удешевляет: лозы работают по thick
(контракт 000235.12: thick = только FOREST), а горы — отдельная ветка выше неё (пин T13).

## 5. Свип живости derived-статов (карточка п.3)

tests/runes-live-effects-000422.test.js — системный зуб: ни одна руна каталога не продаёт
мёртвый стат. Модель живости (эмпирика базы: мертым был ровно acroBonus): стат жив, если
(dot-чтение `\.{stat}\b` в src/ кроме генерируемых runes-data/skills-data) ИЛИ (токен
`\b{stat}\b` в src/ кроме sheet.js-определений и тех же зеркал). sheet.js в dot-плече —
легальный внутренний консьюмер (hpRegenMult/mpRegenMult через restoreDay); из токен-плеча
исключён (иначе определения сами себе потребители = вакуум). Анти-вакуум: T2 красит
checker на tmp-копии каталога с sure_foot→синтетический мёртвый стат; T2b — инертность
параметризации; T3 — пин ветки (a) (sure_foot остаётся при acroBonus).

## 6. Границы

* союзники/мобы/подземелья — не затронуты: heroPassable ровно 4 читателя (позиция-сейв,
  onDay, tryMove, объявления), союзники по мировой карте не ходят (следования на тайлах в
  src/ нет), подземелья используют собственный проходной канон;
* боевые кандидаты (defDodge-слот, резист «ход_вниз», инициатива) — ОТВЕРГНУТЫ вердиктом;
* обучение [acro] (очередь 000320.41) — теперь учит живой механике; в её бриф входит
  итог: chance = 0.05·acro, вход только с не-горы, стоимость 2.

## 7. Протокол ре-съёма при ре-базе

* фикстура гор — рантайм-BFS (ls-доктрина: координат/количеств в тесте нет); при чужой
  правке worldgen пары переснимутся сами, но T6 требует non-empty обеих классов — если
  рельеф сузился, расширять cap выборки, не ослаблять ассерт;
* формула кубика пинкуется ДВУМЯ носителями: regex-чтение ACRO_MOUNTAIN_SEED из src/main.js
  и независимый пересчёт q в тесте — при переносе константы правится regex, не ожидания;
* TAP-база: cf353dc4 = 4903; новые 16 тестов (4 свип + 12 гор) ⇒ ожидаемый полный прогон
  4919 (пересчитать по диску при ре-базе).
