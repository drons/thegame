## 2. D1 — Строгая видимость без explored-поминания (КЛЮЧЕВОЕ РЕШЕНИЕ)

Моб подземелья (включая босса Бездны — он запись contents.mobs, id
'boss', `boss: true`, блуждает как группа) рисуется ТОЛЬКО пока клетка
группы (m.x, m.y) ВИДИМА в текущем кадре: `mask === 2` (Чебышёв
`max(|x−cx|,|y−cy|) ≤ R`, `R = radiusFor(caveVisionMult) =
ceil(5·mult − 1e-9)`, центр = `playerPos` — та же глейд-точка, что
спрайт игрока). Вне зоны (mask 1 — explored вне радиуса; mask 0 —
неисследованное) — НЕ рисуется: ни спрайты юнитов, ни пер-юнит
фолбэк-квадраты, ни legacy-групповой квадрат, ни босс-подсветка и юниты.
Моб «появляется, когда персонаж подойдёт» — ровно формулировка ТЗ;
граница радиуса плавно следует за `playerPos` во время глейда.

Рациональность (3 пункта):
1. ТЗ буквально: зона = текущий радиус зрения; explored-клетка вне
   радиуса — вне зоны.
2. Мобы ДИНАМИЧЕСКИЕ: `wanderStep` (src/dungeon.js:1049) двигает каждую
   живую группу на каждый успешный шаг героя — explored-поминание
   зафиксировало бы СТАЛОЕ/неведомое положение (игрок не знает, куда
   ушёл моб). «Помню контуры» (000136) обосновано для СТАТИЧЕСКИХ
   объектов (пол/стены/сундуки/залежи/маркеры), не для бродячих существ.
3. Минимальность: одна строка гейта; детерминизм кадра, сейвы, RNG,
   логика боя не тронуты.

Это ПОПРАВКА 000136: пункт memory/000136-dungeon-fog.md §Затемнение
«контенты исследованных клеток (пол, маркеры, сундуки, МОБЫ)
ПРОСВЕЧИВАЮТ под слоем» заменён для мобов: «затемнены, не скрыты»
действует для статистики, для мобов — «скрыты вне радиуса». Файлы
memory/000136-*.md НЕ редактируются (источник правды — код; `git blame`
на строке гейта приведёт к коммиту 000225 и этому файлу).

  гейта → одна точка гейта покрывает бокс и юниты (исчезают вместе с
