## 2. Контракты и границы

### 2.1 Поле `by` (происхождение 'fled'-исхода)

* Значения: `'mobs'` / `'player'`. Почему `'mobs'`, а не `'mob'`:
  исход всегда о ГРУППЕ врагов (livingMobs пусто), множественное
  совпадает с субъектом баннера «Противники» и устраняет
  неоднозначность «один моб». Отклонены: `fledBy` (длиннее), `cause`
  (шире смысла).
* Два fled-писателя — ДВА shape, НЕ унифицированы (явное ТЗ):
  * checkVictory :1428 — 5 полей {outcome, by, xp:0, gold:0, defeated:0};
  * playerFlee :1628 — 2 поля {outcome, by} (без xp/gold/defeated —
    побег игрока — не итог боя, лута нет по определению).
  FLB-2 shape-пин держит именно 2 поля (регрессия «унифицировали» =
  красный).
* `by` стоит СРАЗУ ПОСЛЕ `outcome` (семантическая пара; порядок ключей
  для deepEqual/JSON-рондтрипа не важен).
* 0 новых c._rng — чистые литералы: все c._rng-счётчики голденов
  (FR-2 «ровно 2», FR-4/FR-5 «ровно 1») и бит-в-бит детерминизм не
  затронуты.
* Безопасность аддитивности (свёртка ВСЕХ читателей outcome, не только
  список ТЗ — Δ2): значения-сравнения — main.js:546/560/631/1896/1902/
  1914/2639/2654/2664/3231/3240, combat-ui.js:2611/3398; truthiness
  c.result — combat-keys.js:125, ui.js:815/1763. Никто не читает `by`,
  кроме нового баннера.
* c.result транзиент: в сейвы не идёт (src/save.js — grep 0).
* Бонус-покрытие (Δ5): TIMID-путь (все пугливые сбежали, mobAct
  u.fled) приходит в ТОТ ЖЕ писатель :1428 (livingMobs :645-647
  фильтрует fled) → баннер корректен и для него, 0 доп. кода.

(оба прогона детерминированно одинаковы — самосоответственный); FR-9
ассертирует АБСОЛЮТНОЕ поведение (0 действий за endTurn).
