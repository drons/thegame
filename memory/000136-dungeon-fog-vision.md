## Решения (D1-D12)

* **D1. Метрика — ЧЕБЫШЁВ, форма — квадрат** (ТЗ: «Чебышёв или Манхэттен —
  выбор при реализации»). Почему: один max() — дешёвая чистая функция;
  «5 клеток во все стороны» — то, как читается «база 5 клеток»; квадратная
  граница предсказуема. Отклонён Манхэттен (ромб режет углы: (5,5) невидимо
  при видимом (5,0) — непредсказуемая граница; 2 abs + min дороже).
* **D2. Целый радиус: `R = Math.ceil(5 × mult − 1e-9)`, VISION_BASE_RADIUS = 5.**
  ceil, а не floor: уровень 1 навыка (×1.1 → 5.5) УЖЕ расширяет радиус 5→6 —
  заметный эффект с первого уровня (цель ТЗ: закрыть мёртвый стат); floor
  дал бы 5.5→5 (no-op). −1e-9 — защита от float: `5 × 1.8` =
  9.0000000000000002 → ceil без ε дал бы 10 (≠ +80%). Отклонён Math.round
  (нестабильность на границе .5). Пины (unit-тесты): 1.0→5, 1.1→6, 1.2→6,
  1.3→7, 1.5→8, 1.8→9, 2.0→10. Правило клетки: видна ⟺
  `max(|x−cx|, |y−cy|) ≤ R` (целое сравнение; +0.5-сдвиги центров клеток
  Сокращаются — см. «Подводные камни»).
* **D3. Центр маски = playerPos(s, nowT)** — та же точка, что спрайт игрока
  и цель камеры (000068), НЕ логическая (s.x, s.y). Почему: ТЗ «радиус
  вокруг текущей позиции героя»; во время глейда герой НА глейд-точке —
  центр на логической клетке дал бы сдвиг тумана до клетки относительно
  героя. Отклонён вариант a3 «центр = (s.x, s.y)»: их обоснование
  «иначе ломаются L1827/L806» неверно (оба зелёны с любым центром), а с
  логическим центром ЛОМАЕТСЯ L1139-часть1 (pos-хук (13,13), проба floor
  (13,13) — cheb 12 от (1,1)); с глейд-центром часть 1 остаётся зелёной
  БЕЗ ПРАВОК, техническая правка нужна только части 2.
* **D4. explored — состояние визита в dungeon-ui.js: `Set<'x,y'>`,
  union видимых клеток за кадр (вся сетка, не только вьюпорт); сброс
  `new Set()` в start(), `null` в close(), ленивая инициализация в render.**
  Почему: подземелье НЕ персистируется (collectSaveData без
  dungeonState/dungeonMemory) — explored = чистое UI-состояние визита
  (ТЗ: «сброс при входе в подземелье»); НЕ сейв, НЕ dungeon.js (нулевая
  diff, 000133). Union, а не «только ступавшие»: классический туман;
  e2e «возврат на исследованную — затемнение» устойчив для клеток, где
  герой не стоял. Обновление по ВСЕЙ сетке важно: при большом зуме
  видимые клетки вне вьюпорта (< радиуса) тоже исследуются.
* **D5. Чистое ядро видимости в src/dungeon-ui.js, экспорт
  `G.dungeonUI.vision = { baseRadius, radiusFor(mult), maskFor(w, h, cx, cy,
  radius, exploredSet) → Uint8Array(w·h) }`**, значения маски: 0 — скрыто
  (неисследованное), 1 — исследованное вне радиуса (затемнить), 2 — видно.
  Почему: dungeon-ui.js — браузерный IIFE (экспорт ТОЛЬКО на G.dungeonUI,
  новых src-модулей НЕТ — ТЗ «Мерж: только dungeon-ui.js + тесты» держится
  на уровне модулей; нового <script> нет). maskFor ЧИСТА (не мутирует
  exploredSet — только .has) — детерминизм ТЗ «одна позиция + explored →
  одна маска». Uint8Array — O(1) на клетку в слоях; «маска — на
  уровень/кадр, не на клетку» (ТЗ). Отклонён топ-уровневый G.dungeonFog

## Контракты и границы

**G.dungeonUI.vision** (export-объект, создаётся один раз при загрузке):
```
baseRadius: 5                          // VISION_BASE_RADIUS, golden-пин
radiusFor(mult) → int ≥ 1              // Math.ceil(5·mult − 1e-9);
                                       // guard: не number/NaN/≤0 → baseRadius
maskFor(w, h, cx, cy, radius, exploredSet) → Uint8Array(w·h)
                                       // 0 = скрыто, 1 = explored вне радиуса,
                                       // 2 = видно; ЧИСТА: exploredSet не
                                       // мутирует (только .has)
```
guards maskFor: w/h не integer/≤0 → new Uint8Array(0); radius не number/≤0
→ baseRadius; cx/cy не finite → 0; exploredSet null/undefined/без .has →
пусто. Клетка (x, y): `cheb = Math.max(Math.abs(x − cx), Math.abs(y − cy))`;
cheb ≤ R → 2; иначе exploredSet.has(x + ',' + y) → 1; иначе 0. Ключи —
конвенция проекта 'x,y' (dungeonMemory, safe-набор dungeon.js).

**opts.dungeonUI.start** — новое поле (необязательное):
```
visionMult: Function | Number          // Функция — live (main.js), число —
                                       // статично (тесты); ОДНО чтение на
                                       // кадр; мусор/отсутствие → 1 тихо
```

**Состояние explored (модульное, dungeon-ui.js):** Set<'x,y'>; start() →
new Set() (вход = новый визит); close() → null; render (подземелье) —
ленивая инициализация если null, затем: все клетки mask==2 (ВЕСЬ w·h, не
только вьюпорт) → explored.add. Не в сейв, не в ds, не в dungeon.js.

**Границы (что НЕ делаем):** города (kind === 'city') — туман НЕ
применяется (маска не считается, слои без guard'ов — полный рендер, пины
000105-000107 зелёные); stateEl/logEl — без изменений; viewport-обрезка
(:345-349) — сохраняется, маска — поверх; sprite/позиции/цвета мобов,
сундуков, маркеров — без изменений («в видимости — как сейчас» ТЗ);
детерминизм «тот же now — тот же кадр» — сохраняется (рендер-функция
чистая от (позиция, explored, радиус, cam, zoom)).
