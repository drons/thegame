## Ключевые решения

* **Каталог-против-зеркало — выбрано ЗЕРКАЛО (литеральное), НЕ
  расширение assets/dungeons**: (а) sprites.js по прецеденту
  000049/000058 НЕ тянет dungeon.js и data-модули — vm-песочница
  tests/combat-ui.test.js грузит sprites.js без dungeon.js, а require в
  node-ветке UMD рассинхронизировал бы node/браузер; (б) расширение
  каталога коснуло бы территорию 000058 (5 JSON + schema.json
  additionalProperties:false + ALLOWED_SCHEMA_KEYS + sync-скрипт +
  dungeons-data.js + FALLBACK в dungeon.js), а 000070 параллельно
  правит dungeon.js — гарантированный конфликт; (в) 000066 берёт
  данные из API sprites-слоя (G.dungeonFloorFrame) — dungeon.js в
  цепочке рендера не нужен; (г) «Файлы» в ТЗ задачи не включают
  dungeon.js/JSON. SPEC-пулярь про зеркало добавлен в существующий
  раздел «Архитектура хранения подземелий» (решение принято — пулярь
  есть).
* **DUNGEON_FLOOR_FRAMES** (src/sprites.js) — ЛИТЕРАЛЬНОЕ зеркало
  DUNGEON_TYPES: ключи 0..4 → массив 3 путей
  `assets/dungeon/floor/<slug>_<n>.svg`, n = 1..3 (тот же паттерн, что
  COMBAT_BG_DUNGEON; равенство с DUNGEON_TYPES и каталогом
  assets/dungeons закреплено тестами).
* **dungeonFloorFrame(type, x, y)** — чистая функция: вариант
  `hash2(x, y, DUNGEON_FLOOR_SEED + type) % 3`, путь (не индекс).
  Нецелый/неизвестный type (5, 99, −1, 0.5, 'cave', null, undefined,
  NaN) → null (рендерер 000066 — фолбэк #182029). `DUNGEON_FLOOR_SEED =
  0x669f0101` (отдельный от VISUALS_SEED). Раскладка ГЛОБАЛЬНАЯ —
  только (type, x, y), без per-dungeon сида (как мирские тайлы).
* **Стыки без «шахматки»** — три механизма: (1) базовый
  linearGradient ОДИНАКОВ для всех 3 вариантов одного типа (сид
  меняет только раскладку деталей) — зафиксировано тестом (пара
  stop-цветов первого linearGradient: 5 разных пар по типам, 1 пара на
  3 варианта); (2) детали низкоконтрастные (оптика палитры типа,
  opacity 0.15–0.8) и стоят во ВНУТРЕННОСТИ тайла (margin 8–14 px от
  краёв; отрезки/волны/подтёки целиком внутри) — жёсткий контраст на
  границе не роняет шов на стыке; (3) виньетки НЕТ (в отличие от
  фонов боя 000049 — там она одна на весь экран; у по-клеточных
  тайлов виньетка дала бы сетку тёмных линий).
* **Генератор** — scripts/gen-dungeon-tiles.js (npm run gen:dungeon):
  mulberry32, сид на тайл 0x69000101..0x6900010f, for-циклы, f() до
  0.1 px, join('\n')+'\n', без дат → повторный запуск byte-identical
  (принят: второй запуск → git diff пуст). isMain-guard +
  `module.exports { TILES, buildDungeonFloorTile }` для тестов.
  SVG — статичные ассеты в git (игра по file://, fetch JSON не
  работает — паттерн 000049).
* **allAssetPaths()** — +15 путей; main.js в очередь лоадера ставит
  только этот список — пропущенный путь = файл не загрузится.
* **index.html НЕ менялся** (новых скриптов нет; порядок
  sprites.js → dungeon-ui.js уже корректен для 000066), src/dungeon.js
  и src/dungeon-ui.js НЕ тронуты (рендер — 000066). В vm-песочнице
  tests/dungeon-ui.test.js sprites.js в цепочке НЕТ →
  G.dungeonFloorFrame undefined → фолбэк #182029 срабатывает как
  зафиксировано; добавлять sprites.js в цепочку dungeon-ui в этой
  задаче не нужно.
* **Баланс вариантов**: hash2%3 — лёгкий модульный перекос
  (2^32 % 3 = 1), на уровне ~1%, визуально не значим; проверено
  прямым прогоном: сетка 35×35 даёт все 3 варианта для каждого из 5
  типов (счётчики ~360–445 из 1225) — тест «все 3 варианта» зелёный.
