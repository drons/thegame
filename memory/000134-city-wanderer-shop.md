## 1. Суть

Лавка странника (id 5) генерируется в городах (деревня w2/w3, город w2/w3,
столица w1/w2/w3) через `доли_типов` — БЕЗ map_index (SPEC): стока
постройки у неё нет (`makeCityShop` → null, guard cities.js:453), товары
продаёт NPC Хольд (`assets/npc/000011.json`, id `wanderer_merchant`,
`постройки: [5]`) — ЕДИНСТВЕННЫЙ NPC-источник сырья для крафта
(wood_log/stone_chunk/hide/coal/iron_ore/copper_ore; сток Мага магии —
дубль реагентов, НЕ баг — 000001 §5). `npcForBuilding(npcs, 5)`
(src/npc.js:43) возвращает Хольда АВТОМАТИЧЕСКИ — кода пути [E]→
«Диалог» не добавлялось.

## 2. Дизайн-решения (по каждому — почему)

**D1. доли_типов — ИТОГОВЫЕ значения (сумма = 1.0, ключи — доля убыв,
id растущ при равенстве):**

| Файл | Тип | доли_типов (ИТОГ) |
|---|---|---|
| 000051.json | Хутор (fp1) | `{ "44": 1 }` — **НЕ МЕНЯТЬ** (buildings: [], 000102/000104) |
| 000052.json | Деревня (fp2) | `{ "1": 0.4, "44": 0.4, "5": 0.2 }` |
| 000053.json | Город (fp5) | `{ "25": 0.3, "44": 0.3, "5": 0.2, "1": 0.1, "7": 0.1 }` |
| 000054.json | Столица (fp7) | `{ "25": 0.3, "5": 0.18, "10": 0.18, "44": 0.18, "1": 0.08, "7": 0.08 }` |

Почему именно эти (выбрано из трёх кандидатов анализов; все проверены
зондом, «Журнал верификации»):
* **Альтернатива «только w3» (город 5: 0.1, остальные прежние)
  ОТКЛОНЕНА**: Хольд — единственный источник сырья для крафта (P1),
  лавка только в w3-городах = крафт-цикл недостижим в большинстве
  городов (замер: 9/63 городов, 3/15 столиц; у принятого — 36/63, 13/15).
* **Альтернатива «×0.8 у всех» ОТКЛОНЕНА**: меняет веса ВСЕХ
  существующих типов (максимальный дрейф ассортимента) при тех же
  активных наборах, что у принятого.
* Принятое: доминирующие 25/44 в деревне/городе (0.4/0.4, 0.3/0.3) и
  25 в столице (0.3) — прежние веса; меняется только то, что вынуждено
  (вписать 5 в топ-(1+wealth) и нормализовать до 1.0).
* Ограничения, из которых значения следуют (все проверены зондом):
  * w0-пин «город+столица → ровно {25, 44}» (cities.test.js :886-891) →
    25 строго > доли 5 (равенство = id 5 < 25 сломал бы пин): 0.3 > 0.2,
    0.3 > 0.18;
  * w0-пин «деревня ⊆ {1, 44}» и «(−114,−119) w0 = [1, 44]» → 1 первая
    (0.4, связь с 44 по id: 1 < 44), 5 (0.2) — 3-я;
  * «Арена (7) — НИКОГДА в столице» → 7 вне топ-4: 0.08 — 6-я по
    (доля, id) (после 25/5/10/44/1);
  * сумма долей = 1.0 — конвенция всех четырёх файлов (замер: float-
    сумма ровно 1 во всех трёх).

Активные наборы по wealth (топ-(1+wealth) по (доля убыв, id растущ);
старое → новое):
* Деревня: w0 {1}→{1}; w1 {1,44}→{1,44}; w2/w3 {1,44}→{1,44,5} (+5).
* Город: w0 {25}→{25}; w1 {25,44}→{25,44}; w2 {25,44,1}→{25,44,5}
  (Оружейная 1 — w3); w3 {25,44,1,7}→{25,44,5,1} (Арена 7 ВЫПАДАЕТ).
* Столица: w0 {25}→{25}; w1 {25,10}→{25,5} (Стрельбище 10 — w2/w3);
  w2 {25,10,44}→{25,5,10} (таверна 44 — w3, но строится ПЕРВОЙ всегда);
  w3 {25,10,44,1}→{25,5,10,44} (Оружейная 1 ВЫПАДАЕТ).
* Семантический след (игро-процесс, в CHANGELOG): Арена — вне
  ассортимента городов w3; Оружейная — вне столиц w3; Стрельбище —
  вне столиц w1.

**D2. shopFor — МИНИМАЛЬНАЯ ПРАВКА (разрыв, ТЗ §2 авторизует):**
`src/main.js`, `shopFor` (:1859-1870), городская ветка, ОДНА строка:

```js
      const s = ds.cityShops[t.x + ',' + t.y];
      if (!s) return npc ? npcShopFor(npc.id) : null; // 000134
```

(до: `if (!s) return null;`) + 2 строки комментария над функцией
(000134: клетка города без cityShops-записи = Лавка id 5, нет
map_index → SPEC L349-350 → NPC-канал npcStocks как в мире).
Почему: НАЙДЕН РАЗРЫВ (vm-эксперимент EXP134 + код): клетка Лавки
записи в cityShops НЕ ИМЕЕТ (makeCityShop → null → prepareCityState
main.js:1771 `if (!shop) continue;`) → shopFor → null → renderTradeTab
(ui.js:471) создавал СВЕЖУЮ одноразовую копию стока `G.createNpcShop(npc)`
(НОВЫЙ сток 5/5/3/5/3/3 на каждый диалог; покупки сгорали при close,
npcStocks не сериализовался — сток «воскресал»). После правки:
`npcShopFor(npc.id)` → `{npc, stock: npcStocks[npcId]}` — ЖИВАЯ ссылка
на глобальный сток (npcStocks:283-292); покупка мутирует глобальный
сток → saveNow → сериализация main.js:539-540 → restore :1113-1116.
Почему именно `npcShopFor`, а не `createNpcShop`: createNpcShop (npc.js
:273-276) создаёт mutable-КОПИЮ (глобальность держит ТОЛЬКО npcShopFor —
уточнение к неточности ТЗ :37-39). `npc ? … : null` — дефенсивный

объект — «Диалог» существует только при npc ≠ null,
building-effects.js:1780).
Почему здесь, а не в ui.js: shopFor — ЕДИНСТВЕННЫЙ решатель shop-
формата (коммент main.js:1852); ui.js — общий модуль, не знает
npcStocks. Поведение остальных случаев БЕЗ ИЗМЕНЕНИЙ (зонд + регресс):
клетка С cityShops + торговля (Бренн) → cityShops-сток (000108);
клетка С cityShops + без торговля (Берта) → null (2-й guard,

(ds.kind ≠ 'city') → ветка не тронута.
