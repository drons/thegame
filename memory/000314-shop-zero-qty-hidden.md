# 000314 — магазины: позиция со стоком 0 не отображается

## Контракт (что зафиксировано)

Строка торговой позиции, у которой количество < 1 (сток 0 ИЛИ ключ
отсутствует в карте стока), НЕ рендерится — строка отсутствует, а не
скрыта и не «ост. 0» / «×0». Ре-рендер (после покупки/продажи, смена
вкладки, повторный вход) строку НЕ возвращает, пока сток не
пополнился; строка возвращается при регенерации стока.

Экраны (2, по факту кода на момент коммита):

1. **npcUI, вкладка «торговля»** (`renderTradeTab`, src/ui.js) —
   ИСПРАВЛЕНО 000314 (одна строка: `if ((npcShop.stock[p.предмет] ||
   0) < 1) continue;` после `if (!it) continue;`). До 000314 рендерил
   ВСЕ предметы каталога `npc.торговля.предметы` — включая «(ост. 0)».
2. **[I]-панель, вкладка «Магазин»** (`renderShopTab`,
   src/ui-tab-shop.js) — уже соответствовала контракту с 000101
   (`if (!it || qty < 1) continue;`, L91 — с 000009, с 000130 живёт
   в ui-tab-shop.js); 0-diff, регресс-пины B1/B2.

## Источники стока и семантика «возвращения строки»

- **Мирской NPC** — `npcStocks` (ключ npcId), персистентные
  (000109); main.js передаёт npcUI.open ЖИВОЮ ссылку
  (deps.npcShopFor(npc.id) → существующий объект или createNpcShop).
  Респавна НЕТ: после покупки последнего предмета строка не
  вернётся в этой сессии (A2b).
- **Лагерь** — `campStocks`, регенерация ПО ДНЮ.
- **Город** — `cityShops`/`makeCityShop` (детерминированный по
  (город, клетка, тип, богатство)), регенерация — `city_respawn_days`.
- **Карточные магазины [I]** — `makeShop` ПЕРЕСОЗДАЁТ сток при смене
  shopKey (x, y, buildingType, wealth); shopKey-гард (src/ui.js)
  блокирует перерисовку, пока ключ не изменился (B2).

## Следствие (принято по ТЗ «0 строк»)

В npcUI «торговля» кнопка «продать» — ЧАСТЬ строки покупки (одна
`cp-itemrow` несёт купить+продать, sell disabled, если предмета нет в
инвентаре — src/ui.js). При стоке 0 строка исчезает целиком → кнопка
«продать» для ЭТОГО предмета тоже недоступна, даже если герой предмет
держит (купил ранее у того же NPC). Для [I]-панели это не слепое пятно:
секция продажи — по ИНВЕНТАРЮ героя (shopKindsFor), не по строкам
магазина, — и товар продаётся (B1: после покупки «Зелье лечения ×1»
в строках — строка ПРОДАЖИ). Возможное уточнение (отдельная строка
продажи в npcUI при стоке 0) — кандидат на будущую задачу, НЕ
создавать в рамках 000314.
