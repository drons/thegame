## 3. Контракт ally-ветки drawUnits

Геометрия 1×1 (makeAlly: size ВСЕГДА {w:1,h:1}; формулы записаны через
w/h = (u.size…)||1 — как в mob-ветке; в 1×1 дают CELL=48):

| слой (порядок) | примитив | аргументы (1×1) |
|---|---|---|
| 1. подложка «свой» | fillStyle `ALLY_MARKER_UNDERLAY` = 'rgba(140, 242, 252, 0.25)'; fillRect | (px+2, py+2, pw−4, ph−4) = **44×44** |
| 2. спрайт | drawImage | (px+8, py+8, pw−16, ph−16) = **32×32** (запас 8px — как мобы) |
| 2а. фолбэк (нет спрайта/лоадера) | fillStyle `ROLE_COLORS[u.role] || '#888'`; fillRect | (px+8, py+8, pw−16, ph−16) = 32×32 — как mob-фолбэк |
| 3. HP-полоса, трек | fillStyle '#3a0d0d'; fillRect | (px+8, py+2, pw−16, 4) = **32×4** — геометрия моба |
| 4. HP-полоса, заполнение | fillStyle `G.hpBarColor(frac)` (гард '#6fdc6f'); fillRect | (px+8, py+2, round((pw−16)·clamp01(frac)), 4) |
| 5. уровень | fillStyle '#fff'; font '12px ui-monospace, monospace'; textAlign 'center'; fillText `String(u.level)` | (px+pw/2, py+ph/2+4) — как у мобов |
| 6. рамка «свой» | strokeStyle `ALLY_MARKER` = '#8cf2fc'; lineWidth 2; strokeRect | (px+4.5, py+4.5, pw−9, ph−9) = **39×39** — ВСЕГДА |
| 7. индикатор хода | strokeStyle '#ffe27a'; lineWidth 2; strokeRect | (px+2.5, py+2.5, pw−7, ph−7) = **41×41** — только isCurrent |

* Сигнатуры УНИКАЛЬНЫ в render: fillRect 44×44 (подложка; ближайшее —
  42×42 фолбэк препятствия), strokeRect 41×41 (кольцо; других нет).
  strokeRect 39×39 совпадает с подсветкой цели моба — но союзник целью
  быть НЕ МОЖЕТ (ядро selectTarget отклоняет, 000080), а в тестах
  цвет различается через styleCalls (подложка/рамка/кольцо пинятся
  по fillStyle/strokeStyle, не по геометрии).
* HP-полоса: ЦВЕТ — паттерн 000038 (как у игрока): пороги hpBarColor —
  frac ≥ 0.5 → '#6fdc6f', ≥ 0.2 → '#e0b13c', иначе '#d9483b';
  ГЕОМЕТРИЯ — как у мобов (компактный индикатор, ТЗ). Моб-ветка НЕ
  трогается (её бар остаётся плоским '#6fdc6f'). frac клампится [0,1]
  (u.hp ≤ u.maxHP структурно, кламп — защита).
* Уровень ОСТАВЛЕН (сейчас рисуется mob-веткой; ТЗ молчит — минимум
  визуального дельты и симметрия с мобами).
* Рамка/кольцо — ПОВЕРХ спрайта (паттерн подсветки цели); подложка —
  ПЕРВАЯ (под всеми слоями юнита). Полоса (py+2..py+6) пересекает
  подложку — рисуется ПОСЛЕ → читается.
* px = u.x·48, py = u.y·48 (внутренние px, 000124).

## 4. Спрайт союзника: allyFrames(u, now, action)

Чистая селекция (аналог mobSprite, объявлена рядом в drawUnits):

```js
function allyFrames(u, now, action) {
  let frames = [];
  if (u.kind === 'efir') frames = G.efirFrames ? G.efirFrames(action) : [];
  else frames = G.MOB_FRAMES ? (G.MOB_FRAMES[ALLY_MERC_KIND] || []) : [];
  if (!frames.length || !ctx.spriteLoader) return null;
  const idx = (frames.length > 1 && G.frameIndex)
    ? G.frameIndex(now, u.x, u.y, frames.length) : 0;
  return ctx.spriteLoader.image(frames[idx]) || null;
}
```

* **Эфир: G.efirFrames(action)** (EFIR_FRAMES, assets/sprites/efir/ —
  000034). РЕШЕНИЕ ПО СПРАЙТУ (расхождение а3-анализа, снято): ТЗ
  «Эфир — текущий спрайт героя (000034)» читается через 000034: текст
  задачи 000034 — «текущие ассеты Флогистона уходят Эфиру», т.е.
  «спрайт героя (000034)» = каталог, который 000034 создал ДЛЯ Эфира
  (assets/sprites/efir/). Стабильный контракт 000081
  (memory/000081-efir-ally.md §4/§6) прямо: «спрайт Эфира =
  EFIR_FRAMES/efirFrames (000034)». «Состояние сейчас» в 000114.md
  устарело (писалось, когда 000034 pending: «efir/ — не существует»);
  000034 смержен, EFIR_FRAMES/efirFrames уже в sprites.js → стадия
  «плейсхолдер-героя» неактуальна, её часть 000114 предудовлетворена
  (000114 = кадры по действию, §9). Диспетчер по u.kind держит
  000114/000087 однострочными.
* **Наёмник: G.MOB_FRAMES[ALLY_MERC_KIND], `ALLY_MERC_KIND = 'orc'`**
  (литерал-константа в combat-ui.js, ВСЕ роли → orc). У данных найма и
  у юнита makeAlly НЕТ mobId/ссылки на спрайт (delta a1 D2); MOB_KINDS
  — таблица групп мира, к наёмнику неприменима. orc — человеческий
  силуэт (семейство orc: grunt/archer/shaman/chief), покрывает
  melee/ranged/shield/support. Per-role/per-npc спрайты — явно НЕ в
  этой задаче (ТЗ) → расширение 000087/000114 (таблица role→kind или
  u.mobId → G.mobSpriteKind, прецедент mobSprite).
* **action: v1 = ВСЕГДА 'idle'; c._unitFx в ally-ветке НЕ читается**
  (строго по ТЗ — «не больше»; MOB_FRAMES действий не имеют — 2 кадра
  по frameIndex; ложный 'attack' FX Эфира через player-центричную
  эвристику 000062 — вне скоупа). Точка расширения 000114: выбор
  action в вызове allyFrames (паттерн mob-ветки L469-471).
* Кадр: G.frameIndex(now, u.x, u.y, frames.length) — чистый детерм.
  селектор (000047), now — один на render (nowMs()).
* Спрайт, загрузившийся ПОСЛЕ старта боя — подхватывается следующим
  render (image() — каждый render, паттерн фона 000049).

## 5. Прочие контракты

### 5.1 Сборка списка (drawUnits)

```js
for (const u of c.units) {
  if (u.fled) continue;
  if (u.side === 'ally') {
    if (!u.alive) continue;           // мёртвый союзник — ничего (§5.4)

```

Мёртвые МОБЫ остаются в списке (труп, 000062) — без изменений.

на входе — страховка.

### 5.2 Слои: союзники не перекрывают игрока

Сортировка БЕЗ ИЗМЕНЕНИЙ (bottomY → x → id, 000047; якорь — тест
y-сортировки). ПОСЛЕ sort — перевставка героя:

```js
const hi = list.findIndex((it) => it.kind === 'hero');
let lastAlly = -1;
for (let i = 0; i < list.length; i++) if (list[i].kind === 'ally') lastAlly = i;
if (hi >= 0 && lastAlly > hi) {
  const hero = list.splice(hi, 1)[0];
  // hero удалён на hi → последний ally сдвинулся lastAlly → lastAlly−1;
  // вставка на позицию lastAlly ставит героя РОВНО ПОСЛЕ него.
  list.splice(lastAlly, 0, hero);
}
```

* Инвариант: герой — ПОСЛЕ всех союзников; ИНАЧЕ список не меняется.
  **ВАЖНО (баг в черновике a2, исправлен)**: без условия `lastAlly > hi`
  случай 0 союзников (lastAlly = −1) ставил героя на ПОЗИЦИЮ 0 — НЕ
  no-op: ломал тест «спрайт героя … рисуется последним»
  (requested[last]) и порядок герой/моб.
* 0 союзников — no-op **бит-в-бит** (все 1338 тестов: ни один не
  создаёт союзников, кроме тестов 000081, где drawCalls не asserted).
* Все союзники ВЫШЕ героя в сортировке (lastAlly < hi) — тоже no-op
  (герой и так после них).
* Компромисс (зафиксирован): моб с bottomY МЕЖДУ героем и НИЖНИМ
  союзником — герой «перепрыгивает» его (герой поверх того моба,
  раньше — глубина). Жёсткое ТЗ-требование («союзники не перекрывают
  игрока») побеждает мягкое 000081 («порядок отрисовки игрока/мобов —
  не трогать»); редкая геометрия, при 0 союзников — без изменений.
  Спрайт героя 55.2px вылезает за клетку на 3.6px — без перевставки
  подложка союзника (inset 2) в соседней клетке перекрывала бы вылезание
  (ловушка a3: союзник (px+1,py) → rect idx 91 > hero idx 83).
