# Боевая рамка: ход Флогистона — голубая рамка вокруг героя (000213)

Задача 000213 (ТЗ, одна строка): «На поле боя рисовать голубую рамку
вокруг Флогистона в случае его хода». Новая визуальная функциональность
боевого UI: расширяет «голубая = активный» 000197 с союзников на героя.
ВЫТЕСНЯЕТ части контракта memory/000197-combat-frames.md: §2 пункт
границ «hero-ветвь (у героя рамок НЕТ ни в каком состоянии — ТЗ: «NPC и
Эфир»)» и §4 пункт «Если пользователь захочет рамку и у героя —
отдельная задача» УСТАРЕЛИ для состояния «его ход»: у героя теперь
РАМКА на его слоте в очереди. Прочий 000197-контракт (союзники, жёлтая
цель, палитра, «нет кольца 41×41», «чей ход» = рамка, без текстовой
строки) — действует. Старый файл НЕ переписывается (задача 000197
закоммичена в master; прецедент вытеснения — 000197 над

## 2. Контракт и границы

* ФОРМУЛА — бит-в-бит зеркало isCurrent ally-ветви (000197 §2; токены
  renderTurnOrder 000036: «активен» = c.turnOrder[c.turnIndex]) +
  `c.player.alive` (зеркало `u.alive && !u.fled`; у героя нет `fled`):
  * `!c.result` — бой не окончен (на result рамка гаснет, как у
    союзников).
  * `c.turnOrder && c.turnOrder[c.turnIndex] === 'player'` — «его ход» =
    СЛОТ ГЕРОЯ в очереди, НЕ вся player-фаза: на ходу Эфира/наёмника
    (тоже c.phase === 'player') рамка — у союзника (000197 бит-в-бит).
  * `c.player && c.player.alive` — мёртвый герой без рамки: (a) ранний
    проход 000166 на клетке мёртвого героя рисует СВОИ слои (подложка +
    жёлтое кольцо, гейт canResurrectPick) — не совмещать; (b) white-box
    сцена scene166 deadPlayer — c.result там НЕ возникает, а слот
    'player' может быть активным — без гейта рамка бы горела на трупе.
    Null-гард `c.player &&` — конвенция раннего прохода 000166 (L1024).
  * Читаем c НАПРЯМУЮ, НЕ через G.activeUnitId(c): у activeUnitId
    fallback 'player' (пуста/нет очереди → герой стал бы «активен»);
    ally-ветвь и токены читают c напрямую.
* ГЕОМЕТРИЯ — 39×39: strokeRect (c.px·CELL+4.5, c.py·CELL+4.5, CELL−9,
  CELL−9), inset 4.5, lineWidth 2 — 1-в-1 с рамкой активного союзника
  (000197 §2) и с подсветкой цели/кольцом 000166 (герой всегда 1×1 —
  формула через CELL). Рамка живёт в клетке — clipping НЕ нужен. Спрайт
  героя (55.2px = CELL·1.15) торчит за клетку на ~3.6px (задумано,
  000047) — рамка пересекает край спрайта, как жёлтая рамка цели
  пересекает спрайт моба: рамка рисуется ПОВЕРХ (паттерн ally).
  Альтернатива «обнять спрайт» отклонена: на краях поля (px=0/6) уход за
  canvas + новая геометрия вне ТЗ.
* ЦВЕТ — ALLY_MARKER '#8cf2fc' (существующая константа: герой-ромб,
  --hero-токен, MP-полоса 000199 — «голубой» интерфейса героя). НОВЫХ
  ЦВЕТОВ НЕТ (паттерн 000038/000084/000197).
* Z-ПОРЯДОК: спрайт/фолбэк → миниполоса HP → РАМКА (последний вызов
  hero-ветви) — поверх всего в клетке героя. На уровне render() ничего
  не меняется: рамка — внутри итерации героя в drawUnits (до
  drawBreathFx 000114; штриховка 000175 — между сеткой и препятствиями).
* ВЕРХНИЙ РЯД (py=0): миниполоса героя клампится в by=2 (ревью 000047)
  и слегка наезжает на верхнюю линию рамки — идентично полосе союзника
  (py+2) относительно рамки союзника (py+4.5).
* ГРАНИЦЫ (НЕ ТРОГАТЬ, бит-в-бит): ally-ветвь (000197), mob-ветвь
  (подсветка цели 39×39 '#ffe27a'), ранний проход 000166,
  drawBreathFx 000118, штриховка 000175, перевставка героя 000084 §5.2
  (порядок list не меняется; рамка НЕ входит в heroCall-сигнатуру),
  render() HUD (stateEl — 2 строки; текстовая строка «чей ход» НЕ
  возвращается — 000199 L4: рамка показывает), кольцо 41×41 — НИГДЕ
  (000197: убрано навсегда), src/combat.js (ядро: turnOrder/turnIndex/
  phase/RNG/сейвы — 0 правок), index.html, CSS, assets.
* ДЕТЕРМИНИЗМ: рамка — чистая функция (c.turnOrder, c.turnIndex,
  c.result, c.player.alive, c.px, c.py) + константа CELL; 0 c._rng,
  0 мутаций c, 0 console.error; формат сейва не тронут. Повторный render
  с тем же c → те же вызовы (000047).
