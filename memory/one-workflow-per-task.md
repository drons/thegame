# Одна задача — отдельный workflow (решение, 2026-10-02)

Правило пользователя: «запускай много задач, но каждая в своём workflow».
CLAUDE.md: «Запустить workflow в отдельном git worktree для каждой задачи
из выбранных» — юнит параллелизма = ЗАДАЧА, не «волна из N задач».

* Запуск: `Workflow({scriptPath: <скрипт thegame-task-wave>, args: {tasks: [однаЗадача]}})`.
  Скрипт понимает и `{lanes: [[...]]}`, и `{tasks: [...]}` — для одной задачи
  это один lane.
* Целевой параллелизм на машине (12 CPU): 6–12 одновременных task-workflow.
  npm test тяжёлый (~45–90 с), merge-очередь сериализована `.merge-pending`
  (~2–4 мин на мерж, потолок ожидания агента — 45 мин).
* Проверка старта партии: в journal.jsonl run'а должны быть строки
  `"type":"started"`. Если только одна строка `"launched"` — args не дошли
  (см. баг ниже), запускать заново.

## Подводный камень: большие args Workflow

Опыт 2026-10-01/02: 4 провала мульти-лейн запусков со большими args
(~11–20KB JSON, с `<`/`>` и кириллицей) vs 0 провалов малых args (~1–2KB).
Большие args нестабильно доходят в скрипт как JSON-строка (с HTML-экранированием
`&lt;`/`&gt;`) — `args.lanes` оказывается undefined, lanes теряются.

Меры: (1) guard в скрипте — `JSON.parse` при строковых args + явный throw
«args: пустые lanes/tasks»; (2) в текстах задач не использовать литеральные
ASCII `<`/`>` («ниже», «больше», «не выше»); (3) главное — одна задача на
Workflow, маленькие args всегда доходят.
