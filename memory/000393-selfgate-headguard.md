Файл-носитель всех зубов: `tests/items-rename-000318.08.test.js` (новая файла

## Вилки решения станции (зафиксированы ДО кода)

1. **Предикат F3 = value-based, не «любое число у .length».** Живые значения
   (`FROZEN_LIVE_COUNTS_I08` = мощность каталога assets/items ∪ мощность
   реестра, с диска в рантайме) запрещены как ЛИТЕРАЛЫ в любой форме:
   сравнение слева/справа (`===|!==|==|!=|<=|>=|<|>`), присваивание
   (hoisted-константа `const T = V`), стрелка `() => V`, позиция аргумента/
   элемента (`(V`, `[V`, `,V`), кавычковое сравнение `=== 'V'` (по RAW —
   маскирование съело бы кавычки), hex `0x3c4` (регистронезависимо), перенос
   литерала на новую строку (`\s*`.cross-line). Числовые литералы вне этих
   форм (line-пины документов 477/478, rarity-таблицы, 864-пол) легальны —
   альтернатива «бан всех чисел» окрасила бы половину файла.
   Границы `(?<![\w.])…(?![\w.])` спасают padded-номера `'000914'`;
   адьяцентность оператора спасает арифметику `64 * V * 1024` (maxBuffer).
2. **Маскирование вместо сырой regex-строки.** Посимвольный сканер строки
   вырезает содержимое `'…'`/`"…"`/`` `…` `` (маркер S) и обрывает на `//`
   (комментарий — история, проза assert-сообщений не само-матчится).
   Известные границы: кавычка внутри литерал-regex открыла бы ложную строку
   (в файле таких нет), блочные комментарии не маскятся (в файле их нет),
   маскирование в пределах физической строки.
3. **Positive-маркеры больше не `src.includes('ЦЕЛОЕ_ИМЯ')`** — строка самой
   проверки содержит иглу и гейт тавтологичен (наследный дефект формы 000379,
   тот же узор может жить в других 000375-образных гейтах — проверять при
   касании). Форма 000393: игла собирается конкатенацией сегментов, счёт
   вхождений `≥ 2` (живое определение + хотя бы один потребитель).
4. **HEAD-guard класс (F4) выведен из файла машиной.** `HEAD_GUARD_HITS_I08`
   запрещает в исходнике теста: литерал `HEAD:` + `src`, конкатенацию
   `'HEAD:' + <переменная>` вне allowlist, `'HEAD:' + 'src…'`. Allowlist:
   `LEDGER_I08_REL` (T11 append-зуб реестра — сверяет ДАННЫЕ реестра, не src).
   Документ-гейты T9 (`HEAD:spec/…`, `HEAD:memory/…` полными литералами) —
   легальны структурно. Постоянная таблица истинности HEAD-форм (3 красные,
   3 зелёные) пинует сам детектор.
5. **T8 ⇒ «≡ побайтовому регену из assets» в tmp.** Механизм:
   `REGEN_SYNC_MAP_I08()` — живой свип `scripts/^sync-(.+)\.js$` →
   `src/<X>-data.js` (существующий); карта пинуется равной
   `REGEN_MIRRORS_000393 ∪ items-data.js` (новый sync с зеркалом-регеном
   обязан быть включён осознанно). `makeTmpRegenTree_I08()` копирует ПОЛНЫЙ
   assets (генераторы читают смежные каталоги: portraits ← npc, craft/spells/
   mobs ← items) + scripts + **tests/scripts/*.json** (sync-skills-data
   читает skills-num2id-000318.09 — без копии ENOENT, грабля POC) + пустой
   src; spawn каждого генератора в tmp, выход побайтово ≡ живому зеркалу.
   Цена ~2,2 с на тест (9 spawn + копия 17 МБ). Анти-вакуум — ПОСТОЯННЫЙ зуб:
   порт `wood_sword.value + 1` в tmp обязан покраснить реген items-data.
   Анти-хайджек: свип «нет item-путей `assets/items/`» по 9 зеркалам +
   loot-equip-data.js (заместил прежнюю HEAD-сверку тех же строк).
   Свойства: легальная перегенерация зелена ДО коммита (HEAD-guard красил),
   закоммиченный дрейф красен навсегда (HEAD-guard тавтологичен).
6. **T10 (map.js/items.js — не реген-файлы, генераторов нет) ⇒ структурные
   пины выражений** `const LOOT_SEED = GLOBAL_SEED ^ 0x4C4F4F54;` /
   `const CAMP_STOCK_SEED = 0x43414d50;` + отсутствие numeric-путей. Смена
   сида/формулы красит (золотые переснимает волна в своём коммите — F1-принять
   из ТЗ: золотые-литералы остаются ответственностью map.test/items.test/
   cities), косметическая правка файла — нет (HEAD-guard красил и её, мешая
   живым волнам типа очереди 000359-01, которая правит items.js).

## Переносимость класса HEAD-guard (кандидаты с 000394+)

Тот же дефект «src ≡ git show HEAD» живёт в: `skills-rename-000318.09` (T8),
`craft-rename-000318.07` (T8), `items-potion-000321.03` (:590-класс),
`items-food-000321.04` (:460-класс), `items-skillbook-000321.09` (T10-класс),
`npc-refs`-подобные сверки (:448-класс; номера строк сталят после ре-баз —
искать грепом `'HEAD:' *+`). Рецепт: зеркала-регены → механизм T8 этой волны
(REGEN-карта выводит список файлов ЖИВО, скопируется без правок чисел);
hand-файлы → пины выражений как T10. sync:check/sync-all — отдельный
живой страж, его HEAD-гейт («грязный src») остаётся легальным инструментом.

## Совместимость с 000392 (параллельная волна в том же файле)

000392 добавляет T13 (digest-зуб) и ТРЕТИЙ positive-маркер T12
`FROZEN_PREFIX_DIGEST_SHA256_I08` + импорт createHash. Развязка: наши
маркер-гейты — счёт вхождений конкатенированных игл, их — литеральный regex;
при rebase конфликт только в хвосте T12/шапке — разрешение both-sides,
T13 и digest-маркер сохраняются как есть; `000318.08 T13` не дублируем.
После ff обеих волн TAP: база + наши 0 новых тестов + их 1.

## Само-матч ловушки (для правок этого файла)

- Агрегаты проверок писать через `deepEqual(массив, [])`: любой новый
  `.length, <число>` в однострочной assert-форме = будущий false red, когда
  счётчик дорастёт до этого числа.
- В комментариях/сообщениях не писать целиком `EXPECTED_COUNT`, `HEAD:src` и
  `'HEAD:' + <идент>` — детектор HEAD смотрит RAW (включая строки сообщений).
- Числа живых счётчиков в текст теста — только через String(живое)/конкатенацию.
