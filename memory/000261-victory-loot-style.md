## 1. Решения (фиксация openQuestions ТЗ)

* **D1. Якорь НЕ меняется** — top/left 50% + transform
  translate(-50%, calc(50% + 28px)) + width = формула canvas +
  portrait-зеркало (index.html:751-753) — бит-в-бит. Почему: верх столбика
  = center + H/2 + 28px; нижняя кромка victory-баннера ≈ center + 26–33px
  (2 строки × 22px, line-height 1.5 унаследован) → при H ≥ 35px (одна строка
  = 22px·1.5 + padding строки) верх столбика ≥ center + 45.5px — баннер НЕ
  перекрывается при любом числе строк (зазор растёт). ТЗ допускает смену
  якоря, но требует «НЕ сломать центрирование относительно баннера и
  portrait-зеркало» — сохранение = нулевой риск.
* **D2. Три декларации в базовом правиле** (index.html:463-476):
  `flex-direction: column` (сразу после `display: flex`),
  `align-items: flex-start` (строки — в столбик, влево; ширина строки =
  content-width), `font-size: 22px` (после `padding: 0 12px`). Почему 22px:
  = font-size .combat-banner (:388) — «шрифт как у золота/опыта» буквой ТЗ;
  line-height 1.5 наследуется от .combat-overlay — как у баннера.
  font-weight НЕ добавляется (ТЗ просит только размер, «жирность» баннера
  не просили).
* **D3. flex-wrap: wrap / justify-content: center / gap: 2px 8px / padding
  0 12px / pointer-events: none — оставляются бит-в-бит.** Почему: в
  column-оси — no-op (высота auto → justify-content это вертикальное
  центрирование — разумный дефолт на будущее; flex-wrap не срабатывает —
  строки сжимаются, перенос текста — ВНУТРИ span.cp-itemname, у которого
  flex: 1); ТЗ разрешает менять только якорь (transform/width/position);
  минимальный diff → ре-пин 237-CSS без переписывания ассертов (только
  title).
* **D4. Rarity-класс на СТРОКЕ, markup сохраняется**: `cp-itemrow` +
  `cp-rarity-<r|none>` (порядок классов фиксирован кодом). Почему: ТЗ-пин
  «строка … несёт cp-rarity-legendary» + прецедент itemRow (src/ui.js:575-
  576 — класс на строке); строка лута и строка инвентаря остаются одним
  механизмом (000237 D3 — те же классы/иконка/формат « ×N»). box.children
  === 5, img.src-пины, порядок детей — бит-в-бит.
* **D5. Фолбэк — именованный класс `cp-rarity-none`, цвет #e8dcc0** (= база
  .combat-overlay :247-258). Почему класс, а не чистое наследование:
  (a) тест-скетч ТЗ «расходник — фолбэк-класс»; (b) явное color-правило
  изолирует фолбэк от будущих правок базового цвета .combat-overlay;
  (c) симметрия 5+1 правил. #e8dcc0 = НОЛЬ визуального дельты расходников
  относительно master. Кому: предмет БЕЗ it.rarity (расходники/еда/свитки —
  rarity в каталоге только у экипировки, 225 из 382) И it === null
  (неизвестный id — имя = String(e.id)).
* **D6. БОРДЕР на строках лута — ОТКЛЮЧАЕТСЯ** (ключевая находка a2/a3;
  a1-D5 «принять» ОТОРВАН): глобальные правила
  `.cp-itemrow.cp-rarity-* { border: 1px solid … }` (index.html:108-112)
  автоматически обведут каждую строку лута (строка несёт ОБОИХ классов) —
  ТЗ этого не просит («не больше и не меньше», только цвет ТЕКСТА).
  Контракт 000237 D3 — СТРУКТУРНЫЙ (те же cp-классы/иконка 22×22/формат
  имени) и не обязывает рамку на экране лута: на момент 000237 у строк
  лута не было rarity-класса вовсе. Бонус: без нейтрализации список был бы
  РИСЬБОМ — расходник-строки (cp-rarity-none, глобального правила нет)
  без рамки рядом с рамкой экип-строк. Нейтрализация — новое правило
  `.combat-victory-loot .cp-itemrow { border: 0; }`: специфичность (0,2,0)
  = специфичность глобальной (0,2,0) → при равенстве выигрывает ПОЗЖНЕЕ
  в файле (наш блок ~:478+ после :108-112). Глобальные правила и их пины
  (tests/ui.test.js:399-428) — НЕ ТРОГАЮТСЯ; инвентарь/магазин/снаряжение
  не затронуты (их строки НЕ в .combat-victory-loot).
* **D7. Цвета — 6 descendant-правил в скоупе узла лута, в ФОРМЕ ТЗ** (без
  префикса .combat-overlay--combat):
  `.combat-victory-loot .cp-rarity-{common #a39b8b / rare #58a858 / epic
  #5b8fd4 / legendary #9b6bd4 / impossible #e0952f / none #e8dcc0} {
  color: … }`. hex — дословно :108-112 (единственная существующая палитра
  редкости). Почему скоуп ОБЯЗАТЕЛЕН: cp-rarity-* — ГЛОБАЛЬНЫЙ namespace
  строк; без скоупа color пролился бы на строки инвентаря/магазина
  (сейчас у них цвет = база, рамка = редкость) — регрессия 000230.07 +
  пины. Почему БЕЗ префикса: cssRule (tests/combat-layout.test.js:37-52)
  матчит селектор ТОЛЬКО в начале строки — пин должен находить правило;
  узел .combat-victory-loot собирается ЕДИНСТВЕННО в combat-ui.js →
  потомков с cp-rarity-* вне боевого оверлея не существует. Вставка
  ПОСЛЕ базового правила, ПЕРЕД .combat-spellbook (:477); top-level —
  действует в обеих ориентациях (portrait-медиа зеркалит только width).
* **D8. Тест-фикстура — void_ring (legendary) + bread (расходник).** Почему
  void_ring: a3 ЭМПИРИЧЕСКИ проверил сцену (m0.loot + очередь

* **D9. DOM-ассерты — точные строки на className, НЕ classList.** Почему:

  Технические ре-пины фильтров 237 — по ПЕРВОМУ токену:
  `className.split(/\s+/)[0] === 'cp-itemrow'` (побайтовое равенство

* **D10. Красных тестов = 4** (1:1 с 4 красными пулями ТЗ): 261-CSS
