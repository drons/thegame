## Ключевые решения (решение — почему)

* **D1. Пер-эффектный счётчик «раз в день» — ПЕРЕГРУЗКА ТИПА
  `особые_параметры.раз_в_день`: boolean | объект {effectId: bool}.**
  Фонтан: `{"heal": true, "coin": false}` (явный false —
  самодокументирует независимое решение ТЗ «монета НЕ наследует
  лимит исцеления (тест!)»). Отклонён вариант a1 (новое поле
  `раз_в_день_эффектов`): дублирует одну концепцию в двух полях;
  перегрузка безопасна — ЕДИНСТВЕННЫЙ читатель флага в коде —
  hasDailyLimit (grep: src/building-effects.js:323, остальное —
  комментарии), и ни один каталог/синтетика тестов объект не
  содержит → A7–A11/A18/B12 инвариантны.
* **D2. Id эффектов: 'heal', 'coin' (фонтан), '45' (колодец).**
  Фиксация стадии Архитектуры (a2). Колодец — 1-к-1 по строковому
  id постройки (прецедент '40'/'42': effectIds fallback
  String(building.id), массив `эффекты` не нужен). Фонтан —
  именованные id + каталожный массив `эффекты: ["heal","coin"]`
  (порядок = порядок строк оверлея: «Исцеление», «Монета»). Все id —
  латиница без ':'/','/пробелов (гард registerSpecial +
  DAY_MAP_KEY_RE day.js:172).
* **D3. Имена полей каталога `эффект`:** 49 — `исцеление_доля: 0.25`
  (одна доля на HP и MP — ТЗ «25% макс. HP + 25% макс. MP»),
  `шанс_база: 0.2`, `шанс_шаг: 0.05`, `навык: "dexterity"`,
  `золото_база: 10`, `золото_шаг: 2`; 45 — `шанс_база: 0.15`,
  `предметы: [10 id]`. Почему так: каталог несёт ТОЛЬКО параметры
  формул (000053); «уровень мира» и perLevel навыков — не
  дублируются.
* **D4. Колодец — шанс через `derived().thiefBonus`** (workflow-
  директива «Колодец — Тать (derived.thiefBonus)»):
  `chance = min(1, шанс_база + G.derived(hero).thiefBonus)`.
  thiefBonus = 0.05·уровень(Тать) (player.js:232, perLevel 0.05 —
  skills-каталог; проверено: thief 4 → 0.2) — ЧИСЛЕННО ТОЖДЕСТВЕННО
  формуле ТЗ `0.15 + 0.05·Тать`. ПРЯМОЕ РЕШЕНИЕ a2-OQ5: a2 выбирал
  альтернативу heroSkillLevel('thief') + `шанс_шаг: 0.05`/`навык` в
  каталоге; директива workflow (000128-контракт-стадия) зафиксировала
  derived.thiefBonus — оно и принято. Отклонено дублирование
  `шанс_шаг`/`навык` в buildings-каталоге: perLevel — единый источник
  (skills-каталог, 000053), дубль — риск дрейфа. В каталоге 45 только
  `шанс_база` + `предметы`. Чистая `wellChance(eff, thiefBonus)` —
  min(1, шанс_база + (Number||0)).
* **D5. Монета — уровень Ловкости через СУЩЕСТВУЮЩий `G.skillLevel`
  (npc.js:48): primary СНАЧАЛУ, потом secondary.** ВАЖНАЯ ПРАВКА
  a2: его посылка «G.skillLevel читает только secondary → для
  основного 0» ОШИБОЧНА (сверка с кодом: `p[skillId] != null →

  все 6 основных) читается штатно. `chance = min(1, шанс_база +
  шанс_шаг·G.skillLevel(hero, 'навык'))`, `навык: "dexterity"`.
* **D6. «Уровень мира» = `hero.level`** — единая трактовка 000074

  альтернативу»). Золото = `золото_база + золото_шаг·hero.level`

* **D7. Исцеление: `Math.round` + CLAMP по максимуму; apply
  возвращает АБСОЛЮТНЫЕ новые значения + дельту.**

  `newMp = min(d.maxMP, hero.mp + round(доля·d.maxMP))` (d =

## Контракты и границы

### hasDailyLimit (building-effects.js) — точный код

```js
function hasDailyLimit(building, effectId) {
  const op = building && building.особые_параметры;
  const flag = op && op.раз_в_день;
  if (typeof flag === 'boolean') return flag;
  if (flag && typeof flag === 'object' && !Array.isArray(flag)) {
    // 000092: пер-эффектный объект (фонтан 49): ключа нет = лимита
    // нет (fail-open; catalog silence = no limit). Прототип-
    // безопасно (000029). Фолбэка на реестр НЕТ — объект решает
    // сам (OQ1 a2: дублирование реестр-фолбэка не нужно).
    return Object.prototype.hasOwnProperty.call(flag, effectId)
      && flag[effectId] === true;
  }
  const entry = EFFECTS[effectId];
  return !!(entry && entry.разВДень === true);
}
```

Таблица контракта (зафиксировать A58):
| форма `раз_в_день` | результат |
|---|---|
| boolean | как раньше (A7/A8/A9/A10/A18/B12 инвариантны: каталог побеждает, включая явное false) |
| объект (не массив), own-ключ = true | true |
| объект, ключа НЕТ / значение ≠ true / мусорное значение | **false** (без фолбэка на реестр) |
| массив / строка / число / null / нет | мусор → фолбэк на реестр `разВДень === true` (старая логика) |

## Формулы и сиды (с ИЗМЕРЕННЫМИ golden-значениями)

Формулы:
* исцеление: `hp' = min(maxHP, hp + round(0.25·maxHP))`,
  `mp' = min(maxMP, mp + round(0.25·maxMP))` (max — G.derived).
* монета: `chance = min(1, 0.2 + 0.05·skillLevel(hero,'dexterity'))`
  (primary); успех (roll < chance) → `gold = 10 + 2·hero.level`;
  провал → ничего. БЕЗ лимита; независимый счётчик.
* колодец: `chance = min(1, 0.15 + derived(hero).thiefBonus)`;
  успех → `item = предметы[hash(x,y,WELL_ITEM_SEED^day) % 10]`;
  РАЗ В ДЕНЬ (провал сгорает).
* thiefBonus ≡ 0.05·уровень(Тать) — тождество зафиксировано
  (D4); MAX_SKILL_LEVEL = 100 (player.js:49) — уровни 16/17 в
  тестах валидны.
