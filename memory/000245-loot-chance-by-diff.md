## 2. Формула и контракты

### 2.1 P(D) — ФОРМУЛА (ЗАФИКСИРОВАНО)

D = heroLevel − mobLevel (моб СТАРШЕ → D < 0 → вероятность НИЖЕ —
знак по примеру пользователя: Флогистон 10 / моб 15 → 5%).

**P(D) = clamp(0.25 + 0.04·D, 0.05, 0.25)**
= min(0.25, max(0.05, 0.25 + 0.04·D))

| D      | −6 | −5 | −4 | −3 | −2 | −1 | 0  | +1… |
|--------|----|----|----|----|----|----|----|-----|
| P(D)   | 0.05 | 0.05 | 0.09 | 0.13 | 0.17 | 0.21 | 0.25 | 0.25 |

Якоря:
* P(−5) = 0.05 — пример пользователя РОВНО; пол (floor) достигается
  ТОЧНО при D = −5.
* P(0) = 0.25 — текущая плоская LOOT_BASE_CHANCE: бои «ровный/слабый
  моб» лут НЕ МЕНЯЕТСЯ (минимальное изменение — ТЗ просит только
  ЗАВИСИМОСТЬ от разницы).
* Наклон 0.04/уровень = (0.25 − 0.05) / 5 — прямая интерполяция двух
  известных точек: паритет 25% (текущий код) → 5% (пример
  пользователя, D = −5).
* Кап 0.25 (D ≥ 0): лут НЕ инфлируется за слабых мобов — ТЗ не просит
  стороны награды. BASE == CAP — НАМЕРЕННО.
* Реальные бои (level_delta_max = 3, global-settings.js): D ∈
  [−3, +3] → P ∈ [0.13, 0.25] — clamp не срабатывает в типичных
  боях.

ОТКЛОНЁННЫЙ кандидат (доменный анализ): clamp(0.15 + 0.02·D, 0.05,
0.35). Причины: (а) несанкционированно режет паритетные бои
25% → 15% (самый частый случай при level_delta_max = 3); (б) добавляет
несанкционированную награду до 35% за слабых мобов (кап > базиса);
(в) L4-тест (D = 0, coin 0.15) теряет дискриминацию: P(0) = 0.15 →
0.15 < 0.15 = false → редкий всё равно мимо → красное не станет
зелёным.

### 2.2 ОДИН P(D) для обоих пулов

Базовый (ролл на моба) и редкий (общий ролл на бой) — ОДНА P(D).
Почему: ТЗ-красный прямо приравнивает «вероятность каждого возможного
предмета» к вероятности дропа пула (сейчас «базовый пул 25% плоский,
редкий 0.05+0.01×15 = 20%» → новое «5%» — на ОБА); пример
пользователя — ОДНА вероятность; минимум параметров (4 константы,
не 7).

### 2.3 Семантика рола (НЕ МЕНЯЕТСЯ)

«ОДИН предмет из пула»: попадание → равномерный выбор
`pool[floor(c._rng() * len)]`. Частота: базовый — 1 ролл на каждого
повёрженного моба, редкий — 1 ОБЩИЙ ролл на бой; +1 вызов на выбор
при попадании — как сейчас. «Независимый ролл на каждый предмет пула»
ОТКЛОНЁН: +26 вызовов c._rng на моба, ломает ВСЕ stream-пины, ~×5
инфляция лута — за пределами ТЗ.

### 2.4 Какой D для какого пула

* Базовый: D_u = c.player.level − (u.level || 0) — на ПОВЕРЖЕННОГО
  МОБА (литеральное ТЗ «уровень моба»; ролл и так per-mob).
* Редкий: D = c.player.level − maxLvl(killed) — maxLvl — СУЩЕСТВУЮЩАЯ
  конвенция редкого пула (старая формула использовала его).
* В реальных боях ВСЕ мобы группы ОДНОГО уровня (createCombat ~L3379:
  один level на всю группу, array-путь) → D_u ≡ D; различие чисто
  потенциально (будущие смешанные бои) — пин §7.

### 2.5 Число вызовов c._rng — НЕ МЕНЯЕТСЯ

Те же слоты роллов, другие только пороговые сравнения. Gold/xp —
бит-в-бит (N5); все существующие stream-пины держатся (перестановка
r-значений между лут-роллами — только когда старый ролл пересёк порог
— это и есть геймплэй-изменение; см. ре-пин S3(a) §4.2). Детерминизм
по сиду сохраняется: тот же сид → тот же лут (НОВОЕ значение —
следствие новой формулы).

### 2.6 Редкость выпавшего предмета (ТЗ п.4)

## 7. Подводные камни

* **Знак D — ЛОВУШКА**: пулы — D = hero − mob (000245, новый);
  свитки — D_s = mob − hero (000235.05, старый, НЕ трогать). Функции
  живут рядом в combat.js — сигнатура lootChance(heroLevel, mobLevel)
  (2 аргумента, БЕЗ голого D) выбрана именно для исключения этой
  путаницы (у scrollChance(D) — 1 аргумент со своим знаком).
* **floor = 0.05 — НЕ «5% всегда, когда моб старше»**: 5% — пол при
  D ≤ −5; при D = −3 — 13%, при D = −1 — 21%.

  мобов**: лут там не меняется (принцип «не больше, чем просит ТЗ»);
  BASE == CAP — намеренно, не опечатка.

  потреблять pick-вызов → значение уезжает следующему роллу (S3(a):
