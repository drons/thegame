## Конвенция (закреплена зубом)
* Все буллеты одного дня и одного типа — в ОДНУ секцию `### <тип>`; дублей
  `###`-типов в дате не бывает (зуб T1 — глобален по всем датам и всем типам,
  включая легаси `Графика`/`Управление`).
* Порядок типов дня: `Интерфейс` → `Игровой процесс` → `Исправления`
  (зуб T2; эталон — структура дат 2026-11-13 и новый 2026-11-14 после переноса).
* Буллеты внутри секции идут слитно (без пустых строк), порядок буллетов —
  порядок мержей (память changelog-merge-date-section).

## Порог зуба T2: `2026-11-14` (решение зафиксировано задачей)
История СТАРЫМ правилом порядка НЕ охвачена: в 22 датах от 2026-09-26 до
2026-11-12 исторический порядок обратный (`### Игровой процесс` первым),
переносы истории запрещены задачей («правила уже выполняются» из ТЗ верно
только для антидубль-плеча). Честное минимальное утверждение: правило порядка
действует с даты введения зуба. Легаси-типы `Графика`/`Управление` канонической
проекцией порядка игнорируются (в новых датах их вводить не следует — живой
набор типов дня: Интерфейс/Игровой процесс/Исправления).

## Переносы при rebase-конфликте CHANGELOG
При конфликте секции дня — берём блок HEAD целиком и переносим СВОЙ буллет в
живую секцию своего типа этого дня (не создаём дубль-заголовок). Если чужая
волна заведёт день с дублем — зубы T1/T2 покраснеют на ней; правка — перенос
дубль-буллета в живую секцию (это же входит в разрешение конфликта).
