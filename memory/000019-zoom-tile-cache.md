# 000019: крупный стартовый зум + отрисовка только видимой области

Статус: выполнено и закоммичено (тесты 135 → 141 pass).

## Решения

* **Стартовый зум = 80 px/тайл** (`ZOOM_START` в src/map.js). Изначально
  было 40, но игрок решил рисовать в 2 раза крупнее. Старый обзорный
  14 px держал ~11k тайлов в кадре на 1080p, теперь ~400. Шкала зума
  закреплена в тех же константах: `ZOOM_MIN = 4`, `ZOOM_MAX = 128`
  (поднята с 64, чтобы стартовое значение оказалось в пределах шкалы;
  колесо в main.js клампится ими вместо магических чисел).
* **`visibleTileRange(camX, camY, viewW, viewH, zoom, margin=2)`**
  (src/map.js, чистая) — диапазон тайлов видимой области + запас.
  Вынесена из buildFrame (main.js, не тестируется в node); формула
  идентична старой inline (проверено 200k случайных случаев).
* **`createTileCache(map, maxSize=65536)`** (src/map.js) — кэш тайлов.
  Мир статичен (tileAt — чистая функция координат), поэтому при
  перемещении/зуме шум Перлина пересчитывается только для новых тайлов
  по краям вьюпорта (раньше — все видимые тайлы каждый кадр).
  Кэш ограниченный FIFO: при переполнении вытесняется самый старый
  тайл, худший случай — пересчёт, на результат рендера не влияет.
  Зум out до 4 px не деградирует: при 1080p вьюпорт 131k тайлов
  больше кэша — кэш всё равно режет пересчёт примерно вдвое.
* buildFrame (main.js) рисует ровно диапазон `visibleTileRange`
  через `tileCache.tile(x, y)`; слой спрайтов использует те же
  frameTiles, поэтому и спрайты запрашиваются только для видимых.
  Вся игровая логика (findSpawn, tryMove, бой, подземелья, HUD) ходит
  в `map.tileAt` напрямую — кэш только рендер.

## Тесты

tests/map.test.js: +6 тестов — значение ZOOM_START (64–96 px и в
пределах [ZOOM_MIN; ZOOM_MAX]), свойства visibleTileRange (покрытие
окна+запаса, целочисленные границы, отрицательные координаты,
влияние зума/запаса), createTileCache (совпадение с tileAt,
генерация один раз на координату, FIFO-вытеснение).
