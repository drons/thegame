# 000036: очередь хода — c.turnOrder / c.turnIndex

Боевой порядок (игровая семантика, менять нельзя): игрок первым,
затем ВСЕ живые мобы в порядке массива `c.units`. Задача 000036
сделала порядок наблюдаемым — ядро ничего в геймплее не изменило.

## Поля боя (src/combat.js)

* `c.turnOrder` — `['player', ...id живых мобов в порядке c.units]`;
  собирается чистой функцией `buildTurnOrder(c)` (экспортирована,
  рядом с `livingMobs`). Мёртвые (alive=false) и сбежавшие (fled)
  исключены; все мобы мертвы → `['player']`.
* `c.turnIndex` — индекс действующего в `turnOrder`: 0 в phase
  'player', 1..n в phase 'mob' (присваивается в цикле `endPlayerTurn`
  ПЕРЕД `mobAct` — позиция действующего в УСТАРЕВШЕЙ очереди, см.
  «Инвариант» ниже).

## Правила пересчёта (важно)

* Пересчёт `turnOrder` + `turnIndex = 0` — в начале КАЖДОГО раунда:
  `createCombat` (после placeUnits/refillPools/targetId) и
  `endPlayerTurn` (после `refillPools`, ДО тика яда).
* Старая очередь живёт до конца раунда: моб, убитый в фазе игрока,
  числится в `turnOrder` до `endTurn` (UI-токен при этом серый —
  состояние берётся из `u.alive/u.fled`, а не из «наличия id в
  очереди»).
* Конец боя внутри цикла мобов (`c.result`): цикл `return` (не
  break), `turnIndex` ЗАМИРАЕТ на последнем действовавшем мобе,
  очередь в phase 'over' не пересчитывается.
* Смерть от тика яда — ПОСЛЕ пересчёта: при 'dead' `turnIndex = 0`,
  очередь свежая. В phase 'over' `turnIndex` UI не подсвечивает
  (`isCurrent` требует `!c.result`).
* Инвариант (регрессионным тестом): в момент `mobAct`
  `c.turnOrder[c.turnIndex]` = id действующего моба. ВАЖНО (ревью
  000036): пересчёт очереди — в начале раунда, т.е. ДО фазы игрока,
  поэтому убитый игроком моб числится в УСТАРЕВШЕЙ очереди до конца
  раунда. Фаза мобов итерует эту очередь по позициям (слоты убитых
  сохраняются, токен серый) — порядок `mobAct` тот же, что порядок
  живых мобов в `c.units`, игровая семантика не меняется. Мобы не
  убивают друг друга; побег пугливого — внутри собственного mobAct
  (после присвоения turnIndex).

## UI (src/combat-ui.js, index.html)

* `.combat-turnorder` — ПЕРВЫЙ элемент `.combat-side` (над
  `.combat-state`); токены: герой «◆» (`--hero`, #8cf2fc) и мобы
  (фон `ROLE_COLORS` + уровень). `renderTurnOrder(c)` — полная
  пересборка, единый вызов из `render()`.
* Модификаторы: `--current` (`!c.result && i === c.turnIndex &&
  !dead && !fled` — мёртвый/сбежавший токен не «ходит», ревью
  000036), `--acted` (`i < c.turnIndex`), `--dead`/`--fled` (серый +
  перечёркнут, CSS-правило ПОСЛЕ `--acted` — визуальный приоритет).
* Добавлены только НОВЫЕ CSS-классы — вёрстка NPC-диалога (ui.js)
  и подземелья (dungeon-ui.js), переиспользующих `.combat-overlay/
  .combat-side`, не меняется.

## Точки расширения

* 000047 (rAF-цикл): будет вызывать тот же `render()` — строка
  очереди обновится сама; мини-спрайты вставляются в `.turn-token`
  (сейчас там текст уровня).
* 000037 (кнопки disabled по phase/canDoAction): не конфликтует —
  строка очереди только отображает.
* «Переменный порядок» (инициатива по Ловкости — отдельное
  геймдизайн-решение): заменить тело `buildTurnOrder`; все читатели
  идут через `c.turnOrder`/`c.turnIndex`.
