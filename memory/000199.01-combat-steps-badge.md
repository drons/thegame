## Контракты и границы

### Кнопка = «Конец хода» (endTurn) — решение D-1
Кнопки движения НЕ СУЩЕСТВУЕТ: движение = WASD/стрелки (combat-keys.js,
000048); D-pad (.tc-dpad) — ГЛОБАЛЬНЫЙ тач-контроль ui.js/controls.js
(000018), НЕ в .combat-actions, виден только в touch-схеме. endTurn:
(a) ретро (автор задачи) формулирует требование как «на кнопке "Конец
хода" — число оставшихся шагов»; (b) единственный всегда-присутствующий
кандидат, связанный с бюджетом хода (остаток шагов сгорает именно при
завершении хода: рефилл — refillPools/startRound); (c) НОВАЯ кнопка
отклонена: ломает пины «7 кнопок»/grid 4×2, требует SVG-иконки + действие
ядра = «больше ТЗ».

### Значение бейджа = пул шагов АКТИВНОГО персонажа — решение D-2
Зеркало убранной строки до 000199 (git show 6e99fe0^:src/combat-ui.js
L1506-1525), конвенция 000199 (полоски/бейджи — активного; ТЗ: «Число —
для активного персонажа»):

| кто активен | значение бейджа | источник ядра (не трогается) |
|---|---|---|
| игрок | `c.ps.moveLeft` | refillPools (combat.js L2867) = `d.moveCells` (sheet.js: 3+floor(Dex/5)); трата playerMove L1431; гейт L1417 «шаги на ход исчерпаны» |
| наёмник | `u.moveLeft` | makeAlly L374 (movePerTurn\|\|1); startRound L2754 |
| Эфир | `c.efs ? c.efs.move : 0` | buildEfirUnit (3 клетки); трата allyMove L2090-2100; null-guard — паритет `c.efs.touch` |
| фаза мобов / конец (activeUnit null) | `c.ps.moveLeft` (герой) | D3-fallback 000199 (как attack: `c.ps.attack`) |

Число НЕАКТИВНОГО персонажа на бейдж НЕ подставляется (единый бейдж —
только активного). activeUnit(c) (combat-ui.js L1866) возвращает null и
для 'player', и для моб-фазы (только ally по G.activeUnitId) → обе ветки
падают в «иначе» (герой) — как attack.

### Поле в actionCounts — `steps` — решение D-3
Названо по концепции («Шаги» — метка убранной строки), а не по полю ядра:
`move` утекает имя диспетчера c.move и расходится с именами-концепциями
соседей `attack`/`spell`. Добавлено во ВСЕ ТРИ возврата (efir/merc/иначе).
Функция остаётся чистым чтением c (мутаций, c._rng, Game-чтений сверх
G.activeUnitId в activeUnit — нет) — контракт 000199 сохранён.

### На 0 — «0» ВИДИМО — решение D-4
Паритет с attack-бейджем (D3 000199: «ВСЕГДА видим, включая 0, не зависит
от disabled — opacity .3, «0» читается», пины CU199-BTN-ATK); смысл D4 —
сделать исчерпанность пула ВИДИМОЙ (до 000199.01 обнаруживалась ТОЛЬКО
строкой отказа в журнале); 0 — легитимное состояние пула («исчерпано»),
не «недоступно» → отклонение «0» у spellbook НЕ переносится (там смешивает
«нет пула» с «недоступно» — книга союзнику структурно недоступна); у шагов
пул есть у ВСЕХ активных персонажей.
