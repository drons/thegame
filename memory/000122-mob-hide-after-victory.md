## Решения

* **Фильтрация — в слое отрисовки (src/main.js, `drawSprites`,
  проход 3), а НЕ в map.js.** `hasMobGroup` в `map.tileAt`
  детерминирован (hash координат, чистый мир) и не знает о
  `defeatedAt` — это состояние main.js (Map `'x,y' → день поражения`,
  строка 242). Отображение «повержена/жива» не свойство мира, а
  состояние сессии — поэтому вопрос «рисовать или нет» задаётся там,
  где состояние есть. map.js чужой workflow не трогаем.
* **Чистая функция `G.groupVisible(defeatedAt, x, y)` — в src/day.js**
  рядом с `dueForRespawn`/`serializeDefeatedAt`/`restoreDefeatedAt`
  (там уже живёт вся defeatedAt-логика). false — запись тайла есть в
  defeatedAt; true — нет. Мусор вместо defeatedAt — fail-open (true,
  спрайт рисуется — старое поведение; принцип 000029). Ключ — ТОЧНО
  формат main.js: `x + ',' + y` (целые, без пробелов, отрицательные
  возможны) — другой формат = тихий fail-open навсегда. Принимает и
  Map, и обычный объект (сырой сейв); для объекта — hasOwnProperty,
  не `in` (прототип-безопасность). Чистая: вход не мутирует.
* **Гард `G.groupVisible &&` в main.js** — fail-open-паттерн main.js
  (как `G.serializeDefeatedAt ? ... : {}`): старый day.js без функции
  — старое поведение, без падения.
* **Спрайт возвращается БЕЗ доп. состояния:** запись defeatedAt
  создаётся только при победе (main.js ~716) и удаляется только
  `dueForRespawn` при смене дня (main.js ~517-518) — одно состояние
  для логики боя и отрисовки, рассинхронизация невозможна: день
  респауна (`day - defeatedDay >= respawn_days`) запись уже удалена →
  `groupVisible` true → спрайт на месте.
* **HUD-статус «Группа … повержена» (main.js ~1137) не меняется** —
  тайл всё ещё mob-group, просто скрыт; это согласованно.
* **Не трогать:** подземельные группы (dungeonState.contents — отдельная
  система, на глобальной карте не рисуются), save-версия (000031) —
  нового состояния нет, сериализация/восстановление defeatedAt не
  меняется, сейв совместим.
