# Контракт рендера союзников (000084) — для 000086, 000087, 000114

Стабильный контракт: как 000084 рисует союзников (side 'ally') на
мини-карте боя 7×7 (src/combat-ui.js, drawUnits) и что отрисовка
НЕ зависит от состава отряда. Детали и обоснования —
memory/000084-ally-minimap.md. Файлы задач 000084–000087/000111–
000119 править нельзя; при конфликте — SPEC.md.

## 1. Что даёт 000084 (контракт рендера)

* Рендер союзника — отдельная ветвь `kind: 'ally'` в drawUnits;
  mob-ветка и hero-ветка — без изменений. Идентификация юнита —
  `u.side === 'ally'` + `u.kind` ('efir' / 'merc' / будущие).
  **Рендер от состава НЕ зависит**: любой юнит с side 'ally'
  отрисовывается (000087 — roster в allies — рендерится
  автоматически, кода в drawUnits не нужно).
* Слои союзника (z-порядок внутри юнита): подложка «свой» →
  спрайт/фолбэк → HP-трек → HP-fill → уровень → рамка «свой» →
  индикатор хода (кольцо; только ходящий союзник).
* Маркер «свой» — ОБЕ части, canvas-примитивы (видны без ассетов):
  подложка `rgba(140, 242, 252, 0.25)` fillRect (px+2, py+2, pw−4,
  ph−4) + рамка `#8cf2fc` strokeRect (px+4.5, py+4.5, pw−9, ph−9),
  lineWidth 2. Цвета — существующая палитра «стороны игрока»
  (герой-ромб, --hero-токен; паттерн 000038 «новых цветов не
  вводим»). Константы: ALLY_MARKER / ALLY_MARKER_UNDERLAY
  (combat-ui.js).
* HP-полоса — компактная (геометрия моба: px+8, py+2, pw−16, 4px;
  трек '#3a0d0d'), цвет заполнения — пороговый G.hpBarColor(frac)
  (паттерн 000038: ≥0.5 '#6fdc6f', ≥0.2 '#e0b13c', иначе '#d9483b';
  гард '#6fdc6f'). Моб-бар (плоский '#6fdc6f') — без изменений.
* Индикатор хода — жёлтое кольцо '#ffe27a' (цвет --current-токена
  ряда очереди) strokeRect (px+2.5, py+2.5, pw−7, ph−7), lineWidth 2;
  формула isCurrent — та же, что токены 000036 (!c.result &&
  turnOrder[turnIndex] === u.id && alive && !fled). Только для
  СОЮЗНИКОВ. Ряд очереди renderTurnOrder — без изменений (000080
  generic: токены союзников + --current уже работают).
* Спрайты: `allyFrames(u, now, action)` — чистая селекция:
  kind 'efir' → G.efirFrames(action) (EFIR_FRAMES, 000034);
  иначе → G.MOB_FRAMES[ALLY_MERC_KIND], **ALLY_MERC_KIND = 'orc'**
  (ВСЕ роли наёмника; per-role/per-npc — 000087/000114).
  v1: action = 'idle' всегда; c._unitFx в ally-ветке НЕ читается.
  Кадр — G.frameIndex(now, u.x, u.y, n) (детерминизм, now — один
  на render). Фолбэк по юниту: ROLE_COLORS[u.role] || '#888'
  (без sprites.js / без spriteLoader / image() → null) — рендер
  не падает, исключений 0, console.error 0.
* Слои между юнитами: y-сортировка (bottomY → x → id) без
  изменений + перевставка героя ПОСЛЕ последнего союзника (только
  когда последний союзник в сортировке НИЖЕ героя). Инвариант:
  союзник НИКОГДА не перекрывает игрока; с 0 союзников — no-op
  бит-в-бит.
* Мёртвый союзник — НЕ рисуется (арта нет). Клик по клетке союзника
  — существующее поведение: ядро selectTarget отклоняет
  ('недоступная цель'), цель не выбирается, лог не растёт.

## 2. Правила (что менять нельзя)

* Mob-ветка/hero-ветка drawUnits — без изменений (бит-в-бит при
  0 союзников; 1338 тестов — якоря). Перевставка героя — только
  при наличии союзника НИЖЕ героя (no-op-инвариант).
* ALLY_MERC_KIND/ALLY_MARKER/ALLY_MARKER_UNDERLAY — константы
  combat-ui.js; менять значение — только с новым тестом-пином
  (styleCalls-ассерт). Per-NPC/пер-ролевые спрайты — расширение
  ветки merc в 000087/000114, константу-заглушку не «чинить»
  под конкретную роль.
* Геометрии слоёв (44×44 / 32×32 / 32×4 / 39×39 / 41×41, inset
  2/8/2/4.5/2.5) — пинятся тестами R3/R7/R9 и golden R6;
  сдвиг — только с обновлением пинов.
* Canvas — внутренние px (CELL=48, 336×336; 000124); экранные
  координаты в draw-код не вносить.
* Рендер не мутирует c, не вводит RNG, не добавляет
  console.error (e2e main-visuals 000081 — full-chain регрессия).
