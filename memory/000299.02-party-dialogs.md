## Контракт (spec/npc-storage.md буллет `диалог`)

Опция диалога NPC — `{id, текст, действие, требования?, для?}`.
`для` — (необязательно) ключ scope, КОНЕЦ объекта опции:

| `для` | Кто видит опцию (активный персонаж) |
|-------|--------------------------------------|
| отсутствует / `null` / `"все"` | любой активный (дефолт-семантика) |
| `"efir"` | только Эфир |
| `"merc"` | любой наёмный (любая роль найма) |
| `{роль: "melee" \| "ranged" \| "shield" \| "support"}` | наёмный с ЭТОЙ `найм.роль` |

* Фильтр — `dialogOptions(npc, character)` (src/npc.js): `.filter()`
  ПО ПЕРЕД `.map()`; несовпавшая опция НЕ в списке (не «доступен
  false», а отсутствует). Мусорное значение scope — fail-closed
  (скрыта).
* Требования (`харизма`/`навык`/`проверка`) — по ТОМУ ЖЕ активному
  персонажу, порядок и строки причин без изменений.
* Call-site (src/ui.js, npcUI): `activeSheetNow()` — ОДИН источник
  «активного» с рядом портретов (000299.01): `partyMembersFor(c)` +
  closure `activeCharId`; Party нет — hero-фолбэк внутри
  partyMembersFor; members/sheet нет — `c` (hero). ДВА call-site:
  `renderDialogTab()` + opt-ветка `onOverlayClick`.
* Владелец мутаций НЕ меняется: `c = o.character` (hero) — золото
  всегда платит Флогистон, предмет — в общий инвентарь (000194).
  Вкладка «найм» — без изменений (canHire по hero).
* Клик по портрету при открытой вкладке «диалог» — ИН-ПЛЕЙС
  перерисовка вкладки (`if (tab === 'dialog') renderTab()` после
  `renderPartyPortraitsRow`) — иначе смена scope невидима без
  переключения вкладки; вкладка не переключается, оверлей не
  закрывается (000299.01).
