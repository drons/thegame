## 1. Форма ls-предиката для buildings (отличие от npc)

Имена файлов — slug, НЕ `000NNN.json`: непрерывность каталога живёт не в
именах, а на стороне id. Канон тела (пишется в каждый новый держатель):

    const files = buildingsFiles_00031806(); // readdirSync минус schema.json минус не-slug-шейп
    assert.ok(files.length >= LEGACY_FLOOR_000398, 'не менее 55 …, факт: ' + files.length);
    // границы: id >= 1 && id <= DISK_N_000398; дубль id красен;
    // цикл 1..DISK_N_000398: assert.ok(byId.get(i), 'id 1..N покрывают … нет id ' + i)
    //   → осмысленная краснота на ПРОПУСКЕ id (раньше деструктуризация undefined
    //   давала TypeError — крах вместо ERR_ASSERTION);
    // зеркало: assert.equal(BUILDINGS.length, DISK_N_000398, '… sync не прогнан? …');
    // src/buildings.js ≡ побайтовому РЕГЕНУ из текущего assets в tmp (зуб свёрнут
    //   в существующий блок «зеркало (000102)» — новых test-блоков не заводим).

* Пол `>= 55` — рэтчет наследия: легитимный рост НЕ двигает его никогда,
  удаление ниже пола красит. НЕ поднимать (в этом смысл миграции).
* Ловушка счёта: каталог = РОВНО 55 slug-json + schema.json; наивный
  `ls | wc` = 56 (прецедент П3 .390). Хелпер исключает schema явно.
* Regen-зуб: tmp-дерево = assets/{buildings,items,skills} + scripts/
  sync-buildings-data.js + ОБА файла scripts/lib (write-atomic.js +
  json-ref.js — грабли `memory/000318-buildings.md`) + копия НАСТОЯЩЕГО
  src/buildings.js (внеблочная шапка с маркерами BEGIN/END нужна скрипту;
  без копии — fail-closed «падает», а не «краснеет»). Класс «≡ git show
  HEAD» для зеркал машинозапрещён (000393): легитимный реген зелёный,
  закоммиченный дрейф GENERATED красен навсегда, косметика вне GENERATED —
  не красит (мутации M1/M2/M9).
* `src/buildings.js` вне `REGEN_SYNC_MAP_I08` (items-rename) по построению:
  свип карты = скрипты `sync-*.js` с выходом `src/*-data.js`, а выход
  sync-buildings-data — `src/buildings.js`. Фиксация сознательная;
  перенос класса live-regen на 6 чужих носителей — задача 000395 (её п.5
  про buildings не дублируем: наш зуб живёт только в buildings.test.js).

  :1920/:1933 и т.п.) и контуры пинов (29 спрайтов, 18 школ, 22 D3, 11

  (прецедент 000387.01 §3).
* Шапка/JSDoc `src/buildings.js` («Каталог: 55 типов», «1..55») — ручной
  текст вне GENERATED; его согласованность с каталогом пинует УЖЕ ЖИВОЙ
  guard «buildings.js (000102): шапочный комментарий…» (сверяет с
  BUILDINGS.length) — при добавлении постройки волна bump'ит шапку сама
  (в addition-макете без bump'а он красный — ОЖИДАЕМЫЙ легитимный держатель).
* Контракт роста: новые id — ТОЛЬКО хвостом (N+1). Вставка в середину
  легитимно красит позиционные пины городов/подтипов — не баг миграции.
