# 000171 — ОБЩИЙ ПРИНЦИП: все кнопки/действия интерфейса должны иметь
# визуальный элемент, нажимаемый мышкой или тачем (по ТЗ 000171)

**Правило, записанное в память по требованию ТЗ 000171** («пометить в
памяти, что все кнопки интерфейса должны иметь визуальный элемент для
нажатия мышкой или тачем по экрану»). С 000171 это КОНТРАКТ проекта на
все будущие UI-задачи — проверять при ревью.

## 1. Формулировка принципа

Каждое действие интерфейса (команды боя, навигация, редактор, инвентарь,
журнал и т.п.) должно иметь **видимый DOM-элемент** (кнопка/иконка/строка
с click-обработчиком), на который можно нажать **мышкой (click) или
пальцем (тап = нативный click)** — без обязательной физической клавиши
клавиатуры. Если действие управляется **только** keydown/клавишей
(и нет click-эквивалента) — это **дефект**, кандидат на отдельную задачу
паттерна 000171.

Техническая опора: тап по `<button>`/элементу с click-слушателем
срабатывает нативно (как у 7 кнопок панели боя, у строк книги 000149);
D-pad (controls.js touchKeyCode) покрывает ТОЛЬКО движение + KeyE —
новые команды через клавиатуру Д-pad-ом не выразить, поэтому у них
обязателен собственный визуальный элемент.

## 2. Аудит по 000171 (что нашлось)

**Баг (решён 000171):** воскрешение в бою — выделенного видимого
управления НЕ было. Реальная цепочка: книга заклинаний (кнопка KeyQ —
клик есть, 000149) → строка «Воскрешение» (click есть) → опционально
клик по клетке мёртвого союзника (000166). Каждый шаг формально
тапабелен, но на малом экране цепочка из 2–3 жестов «книга → строка →
клетка» не discoverable, а на таче без D-pad путь «сначала найти
кнопку Q» неудобен → воспринимается как «привязано к клавиатуре».
ФИКС 000171: выделенная кнопка «Воскрешение» в панели действий
`.combat-actions` (8-я клетка, 2-й ряд, правый край) — один тап =
воскрешение (автоцель: мёртвый игрок приоритетно, иначе первый мёртвый
союзник). Контракт: `memory/000171-combat-resurrect-button.md`.

**Дочерняя задача уже создана — 000178 (tasks/pending/000178.md):**
тач-кнопки «Каст» (Эфир, KeyK) и «Лечение» (support-наёмник, KeyH) в
том же паттерне; ТЗ 000178 явно требует после мержа 000171 читать
реализацию кнопки 000171 и этот файл. Отличия 000178 от паттерна
000171: 'cast'/'heal' ВЕТКИ ЕСТЬ в canDoAction (000168) → гашение —
стандартный цикл без спец-кейса (как у 7 табличных кнопок); гейт
видимости — по активному юниту (Каст — только на ходу Эфира, Лечение —
только на ходу support-наёмника), не по spells носителя. Контролы,
которые это баг-аудит зафиксировал:
* **KeyH — «Лечение» (support-наёмник, 000168 P4):** только клавиша; на
  таче D-pad не посылает KeyH → на мобильных недоступно. РЕШАЕТСЯ 000178.
* **Каст/Касание Эфира (J/K, 000168 P16):** заявлено как ограничение
  мобильной раскладки (D-pad: движение + E). РЕШАЕТСЯ 000178.
* (Косвенно) **KeyM/KeyN (журнал/сопутники), KeyR (побег), KeyE** —
  у KeyE есть D-pad; у остальных нет визуального эквивалента —
  задокументированные упрощения 000048/000168; приоритет низкий
  (не боевые команды), кандидат при запросе.

**Уже корректные** (визуальный элемент + click есть — образец для
ревью): 7 кнопок `.combat-actions` (клик/тап нативно), строки книги
(000149: div с click — осознанный выбор R9, DOM-кнопка НЕ обязательна,

000171 — теперь тоже здесь (8-я клетка, гейт canResurrect).

## 3. Правила для будущих задач (чек-лист ревью)

1. Новая команда/действие → есть ли для неё видимый элемент с
   click-обработчиком (кнопка/иконка/строка)? Если только keydown —
   задача НЕ полная (или ограничение явно задокументировано в памяти и
   ТЗ).
2. Вне-табличное управление боя допустимо, ЕСЛИ: гейт видимости —
   осознанный (кнопка видна только при наличии ресурса/цели/активного
   юнита — см. canResurrect-гейт 000171), гашение — собственный chk (не
   «неизвестное действие» из canDoAction), предпроверка ДО cast (стаб/
   состояние), отказ — в журнал (logRejection), ход не сгорает при
   отказе.
3. Гейт видимости предпочтительнее вечного disabled: пин-тесты
   (счётчик кнопок) и discoverability страдают от мёртвых кнопок
   (урок 000171: табличная кнопка без ветки canDoAction = навсегда
   «неизвестное действие»).
4. Тап = нативный click: НЕ добавлять pointerdown к click (двойное
   срабатывание); pointerdown только там, где нужен ранний жест
   (D-pad).
5. Иконки — только из assets/каталога с пин-тестами (000017/000086);
   новый SVG обязателен к прогону tests/svg.test.js ДО добавления
   (000171 новый SVG НЕ добавлял — переиспользует существующий
   assets/spell-icons/resurrect.svg).
6. Мобильные раскладки (390×844/360×740): новая клетка панели — не под
   D-падом (левый низ); бюджет 4 колонки (512px, 000048/000166). Счёт
   кнопок: 7 табличных + 000171 (1) + 000178 (2) = до 10 → 3 ряда
   сетки 4×3 — проверять высоту панели и перекрытия при каждой новой
   кнопке (000124/combat-layout).
