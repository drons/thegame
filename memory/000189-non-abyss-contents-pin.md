## 2. КЛЮЧЕВОЕ РЕШЕНИЕ: xp=32 вместо примера ТЗ xp=1000

ТЗ: «(например CAVE (37,-12), xp=1000 — **выбрать по факту** доступных
фиксированных координат в файле)» — координаты (37,−12) фиксированы
(каноническая точка файла: golden L254, DEP-1 L967) и СОХРАНЕНЫ; выбор xp —
«по факту». Разбор (a1-domain) и карта тестов (a3) разошлись (xp=32 vs
xp=1000); на этой станции перепроверено пробами на master 3ce98ad, решение —
**xp=32**:

1. **Регрессия finding — «обобщат гард»** (`occupied.add(far)` для ВСЕХ
   типов — задокументированное будущее изменение «новый тип подземелья с
   боссом → обобщить исключение», memory/000183 §«Что важно»): свип
   xp 1..3000 на (37,−12) — **132/3000 чувствительны, ПЕРВЫЙ xp=32;
   xp=1000 НЕ чувствителен** → пин на xp=1000 НЕ покраснел бы именно на
   той регрессии, которую описывает finding («если guard ... уберут или
   обобщат, ... НИ ОДИН тест не покраснеет»). Механизм: при xp=32 сундук
   c3 стоит ровно на (18,5) = клетка дальней комнаты; обобщение гарда
   блокирует её → takeSpot сдвигает c3. При xp=1000 поток takeSpot на (18,5)
   не попадает.
2. **До-фикс идентичность** (гард удалён полностью — состояние до 000183):
   CAVE (37,−12) при xp=32 — БИТ-В-БИТ идентично текущему выводу (свип
   CAVE 0/3000) → пин ЗЕЛЁНЫЙ с рождения и фиксирует ровно «НЕ-ABYSS
   бит-в-бит неизменны».
3. **Максимальное содержимое**: 6 групп + 5 сундуков (верхние границы
   генератора) — самая сильная полная сеть на этом подземелье.
4. Направление **«удаление» гарда** НЕ-ABYSS не меняет (0/3000 — add для
   не-ABYSS и так не исполнялся) — его ловят D-BOSS-1/2 на ABYSS-стороне
   (свип 14/400, первый xp=18 — первое нарушение D-BOSS-1); D-BOSS-3 —
   зеркало для НЕ-ABYSS стороны. В сумме D-BOSS-1/2 + D-BOSS-3 закрывают
   blast-radius фикса 000183 с обеих сторон.

Расхождение с примером ТЗ задокументировано в tasks/result/000189.md и в
