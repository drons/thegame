# 000387.02 — миграция держателей-счётчиков skills-плеча на живые предикаты

Закрыта строка `memory/000387-frozen-prefix-contract.md` §4 (долг .02):
`tests/assets-schemas.test.js`, `tests/skills-nature-000318.11.test.js`,
`tests/efir.test.js` — счётчики `44` каталога `assets/skills` переведены на
живые ls-предикаты по модели .387.01 (npc): монотонный пол `>= 44` +
живая биекция «уникальных id == числу файлов». Рост каталога навыков вне
реестра `tests/scripts/skills-num2id-000318.09.json` теперь не требует
ручных ре-пинов этих трёх файлов (прецедент addition-макета .320.30:
+1 валидный `<id>.json` secondary + `node scripts/sync-skills-data.js` →
мигрированные держатели зелёные).

## 1. Форма пола (канон для сиблингов)

- `SLUG_SWEEP_000318` в assets-schemas: запись вида `{ minCount: N }` идёт
  в ветку `assert.ok(files.length >= entry.minCount, …)` со «факт: N» в
  сообщении; `{ count: N }` — прежняя точная сверка (craft/items побайтово
  зелёны как были). Инварианты после счётчика (нет numeric-файлов,
  basename===id, уникальность id, lex-порядок) — общие, вне ветки, они и
  есть живая часть свопа.
- skills-nature T1: `files.length >= 44` + `counts.size === files.length`.
  T2: `fwd.size === files.length` + `rev.size === fwd.size` (размер Map не
  зависит от порядка — winner по readdir ловится и без замороженного числа).
- efir.test.js: `SKILL_CATALOG.length >= 44` (тест 000115 — найден сверх ТЗ,
  ТЗ снималась с базы 8e798539), в `000336 GUARD`: пол
  `SKILL_FILES().length >= 44` + биекция `SKILL_META.size ≡ SKILL_FILES().length`.

## 2. Контрактная подстрока кросс-пина Т4 ↔ GUARD (САМОЛОМ!)

`tests/skills-nature-000318.11.test.js` T4 пинует ИСХОДНИК
`tests/efir.test.js` регулярками; байты-контракт (правятся только СОГЛАСОВАННО
в одном коммите):

- `/SKILL_META\.size, SKILL_FILES\(\)\.length/` — GUARD обязан содержать
  строку `assert.equal(SKILL_META.size, SKILL_FILES().length, …)` одной строкой;
- `/SKILL_FILES\(\)\.length >= 44/` — пол заявлен в GUARD;
- анти-возврат `doesNotMatch /SKILL_(FILES\(\)\.length|META\.size), 4\d\b/` —
  класс замороженного счётчика 40–49 в этих двух формах GUARD запрещён
  (порт идеи HEAD_GUARD_HITS из .393; positive-маркеры без тавтологии —
  ассерт Т4 матчит РЕГУЛЯРКУ живой строки, а не имя теста).
- Якорь извлечения блока `test('000336 GUARD` и имя GUARD-теста НЕ трогать
  (переименование рвёт Т4; имя T1 менять можно — внешних читателей нет,
  свип «000318.11 T» вне своего файла = 0 хитов).

## 3. Остаточный долг класса (НЕ мигрирован скоупом .02) — кандидаты ретро-b25

Все три — счётчик НЕ каталога skills, а производных множеств (часть
производных — от src-списков, часть — от DISK-подмножеств каталога;
немигрируемые referrer-пины класса «npc-refs постройки-строки»
из .387.01); в addition-макете (+1 secondary) краснеют осмысленно:

- `tests/efir.test.js` GUARD `assert.equal(catalog.length, 38, …)` (фильтр
  не-school пула Эфира) и `assert.equal(EFIR_SKILL_CATALOG.length, 38, …)`
  в `tests/save.test.js` — пин-число одно (38), а механизмы РАЗНЫЕ. ЭРРАТА
  000406 (ретро-b26 000387.02 F3): прежний общий механизм «EFIR-пул ≡
  src/main.js `PRIMARY_SKILLS.concat(SECONDARY_SKILLS)`, двигается только
  вместе с правкой src-списка» был ложью для efir-носителя: GUARD фильтрует
  `SKILL_CATALOG`, собранный НАПРЯМУЮ из `assets/skills` (`SKILL_FILES()` =
  readdirSync + чтение json в том же файле), ⇒ чистый +1 secondary-ассет
  красит его БЕЗ всякой правки src (станционный addition-макет §4 красил
  GUARD-38 именно так); с src-пересинком двигается только save-пул — он
  читает зеркало `skills-data.js` (`SD.PRIMARY_SKILLS.concat(…)`);
- `tests/skills-refs.test.js` SR1 `assert.equal(sec.length, 32, …)` и
  SR4 `assert.equal(byPath.get('primary'), 32, …)` (число secondary);
- `tests/magic-schools-000324.test.js` `assert.equal(m.SCHOOLS.length, 6, …)`
  + константа-список `SCHOOLS_EXPECTED` (6 элементов) — семантика списка школ.

ЗАПРЕТ: никогда не трогать цепь «skill-ссылки 954» в `tests/craft.test.js`
