## 1. Формула сида (контракт — одна формула на всё приложение)

`dungeonFloorTileSeed(gx, gy, depth)` — src/dungeon.js (экспортируется):

    (hash2(gx, gy, FLOOR_TILE_SALT) ^ ((depth * 0x9e3779b9) >>> 0)) >>> 0

* `FLOOR_TILE_SALT = 0x5f00d323` — экспортируемая ЗАПЕРТАЯ константа
  (пин R3).
* gx/gy — координаты ВХОДА подземелья на глобальной карте; depth — номер
  этажа (глубина).
* 0 вызовов rng, 0 зависимости от времени/игрока; паттерн — как
  dungeonDepthSeed (000153.01), тот же внутренний hash2.
* `d.floorSeed` — поле ФОРМЫ createDungeon: аддитивное, вычисляется в
  createDungeon (0 новых вызовов rng в createDungeon/
  generateDungeonContents), детерминировано — при восстановлении из
  сейва пересчитывается по (вход, глубина), в сейв не пишется.

abyss = типы 0..4 (те же слоги, что COMBAT_BG_DUNGEON 000049), n = 1..8.

* 000323: ВСЕ 15 старых (5×3) переделаны в flat (старые несли

  defs/градиентов/path/text/transform/stroke.
* Базовые тоны (ОДИН плоский тон на тип во всех 8 вариантах):
  cave #5d554d, crypt #5a6170, ruins #7a6f60, drowned #2a5494,
  abyss #171221.
* Детали по типам (низкоконтрастные, та же палитра, что база): камешки/
  трещины (cave), швы плит/осколки (crypt), плиты/трещины (ruins), волны/

## 3. Бесшовность (контракт)

* Тайлы одного типа стыкуются в ПРОИЗВОЛЬНОМ порядке: края совпадают,
  т.к. база типа — единая плоская заливка во всех 8 вариантах (нет
  фазы градиента, нет виньетки краёв).
* Детали строго ВНУТРИ тайла: bbox каждого из 904 детальных элементов
  всех 40 тайлов в [0.5, 63.5]² (проверено по диску при 000323;
  генератор держит margin: inner(rnd, 8) → центр 8..56 + радиус детали
  ≤ ~4.7).
* Различия вариантов — ТОЛЬКО раскладка/количество мелких деталей.
* Визуальная проверка стыковки — в tasks/result/000323.md
  (автоматический тест краёв не реализован — зафиксировано; механика
  шва исключена конструкцией п.1: единая плоская база).

## 4. Раскладка отрисовки

* `dungeonFloorFrame(type, x, y[, floorSeed])` — src/sprites.js, чистая
  функция (повторный вызов → тот же путь; без RNG-состояния):
  * floorSeed — число → `frames[hash2(x, y, floorSeed) % 8]` —
    основной путь (000323): раскладка per-подземелье/этаж.
  * без floorSeed → `frames[hash2(x, y, DUNGEON_FLOOR_SEED + type) % 8]`
    — легаси-ветка (000069; 3-арг. вызовы chunk-render/wall-autotile):
    глобальная раскладка (type, x, y). ВНИМАНИЕ: модуль 3→8 — клетка
    легаси-ветки может дать новый вариант (намеренно: набор 8).
  * неизвестный/нецелый type (5, −1, 0.5, 'cave', null, NaN, …) → null
    — рендер (000066) рисует фолбэк #182029.
* Вызовы: src/dungeon-ui.js — обе точки отрисовки пола передают
  d.floorSeed (4-й аргумент).
* Изображения — через spriteLoader.image(path) (кэш изображений —
  существующий механизм UI; chunk-кэш per-сессия 000066 не тронут).
