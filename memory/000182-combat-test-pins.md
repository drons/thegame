## 4. Сводка: почему ретро-цикл терял пины (системно)

1. **Деградационные ветки недосягаемы в полной цепочке** (D10 — нет
   mobReachCells; NOSP — нет G.Spells; NOMOTION — нет motion.js): loadCombatUi
   строит ПОЛНУЮ цепочку, ветки «битый порядок загрузки» требуют load-time
   опций (withoutMobReach/withoutMotion, scene166 spells:false) — до 000182 их
   не было.
2. **Координатные пины вместо «наличия»** (FRAC): R8 ассертировал факт
   перерисовки, а не ТОЧКУ — пин «какая точка from» требует вычисления
   дробной координаты (52/27), что не делалось.
3. **Числовые контракты без счётчика** (ONCE, LW, H1-2X2): «logged once»
   читался из текста сообщения, lineWidth не логировался стабом, H1 — 1×1.
4. **Положительные зеркала отрицательных гейтов** (BTN8 vs CU171-GATE):
   отрицательная форма (7) была зафиксирована, позитивная (8) — нет.
5. **Ордер-контракты (последовательности)** (ORDER, GATE-ORDER, UIMOVES):
   наличие/состояние было запинено, порядок/свежесть записей — нет.
6. **Формулы при дегенеративных параметрах** (HEAL): степень=1 скрывает
   произведение — нужен кейс со степенью 2 + ненулевым атрибутом.

Практическое правило для будущих задач: при добавлении guard'а
(try/catch/флаг/деградация/ордер) пинить (а) отсутствие утечки, (б) ЧИСЛО
предупреждений (logged once), (в) позитивное И отрицательное зеркало гейта,
(г) координату/последовательность, а не только наличие.
