# Конвенции ретро-приёмки (retro-protocols)

Носитель протоколов, введённых по итогам ретро-b27/b28 (задача 000411, класс docs).
Темы: протухание финальных агрегатов, смешение метрик подсчёта, ложные универсалии
об инертности. Все числа в этом файле — с sha-рамками или ls-рецептами; пересчёт
только живым свипом (диск первичен).

## 1. Маркёры TAP — канон `grep -c` СТРОК

Счёт иглы в TAP = `grep -c '<игла>' file.tap` (число СТРОК; каждый титул даёт
две строки — `# Subtest:` и `ok N -`). `-o`-вхождения НЕКАНОНИЧНЫ и завышают
счёт на строках с двумя вхождениями. Приёмочный отчёт обязан объявить метрику;
сверка «заявлено N / факт M» в разных метриках — не находка.

Измеренная таблица базовых игл (пересъём `grep -c` по дожившим /tmp TAP на
диск 0e383e04; при исчезновении TAP таблица не перевымеряется — значения
sha-скоуплены базой прогона):

| /tmp/items-ls397-rebase-full.tap (то же дерево + миграция .397) | 4804 | 146 (148) | 58 | 178 (198) |

→ 148 (после ff .34, 7215d6a7) — держится на мастере 0e383e04. Протокол свежести:

снята кросс-отчётом b28 (sources: «000401 (снятый finding №1)»).

## 2. Атрибуция «кто внёс строку» — `git log -S`

`git blame` показывает ПОСЛЕДНЕЕ касание строки (last-touch), а не внесение;
цепочку появления/смены литерала восстанавливает `git log -S '<игла>' -- <файл>`.
Прецеденты b28: padded-форма «000001…000914» внесена 52b75f90, снята с хвостовой
позиции 897b1113, механиз демонтирован 6382cdb1 — blame по строке :340 приписал
бы её не тому автору. Любая атрибуция происхождения в отчёте обязана ссылаться
на `-S`-лог (или `git log -L`), а не на blame.

## 3. «Docs-инертен» = print-перечень fs-читателей, не универсалии

Запрещены универсальные формы «ни один тест не читает tasks/|memory/» — они
опровергнуты диском дважды (b28: 000404, cross). Обязательна пофайловая форма со
скриптовым перечнем. Определяющий свип — по МЕСТАМ ЧТЕНИЯ (дефиниция читателя):
`grep -rn "join([^)]*'memory'" tests/` × `readFileSync/existsSync/readdirSync`
(аналогично для 'tasks'); оконный свип по упоминаниям даёт ложные положительные
строки assert-сообщений/комментариев (прецеденты: npc-000320.34:397,
