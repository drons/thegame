## ГРАБЛИ (обязательно к перечитыванию следующей волной с golden-ре-шутом)

1. Вставка golden-строк СКРИПТОМ перед маркерным комментарием обязана
   проверять завершающую запятую ПРЕДЫДУЩЕЙ кодовой строки литерала:
   пересъём 000321.07 сломала синтаксис в 3 файлах (items.test.js/
   cities.test.js/000317 — литералы вида `meat: 2 } },` без запятой перед
   вставляемым блоком). Ремонт (одноразовый скрипт, /tmp-скетч): вверх от
   маркера до первой НЕ-комментарной строки, если кончается значением —
   дописать «,»; затем node --check всех изменённых файлов.
2. Обёртка makeShop возвращает {x,y,buildingType,wealth,stock,seed} —
   при живой симуляции читать .stock (первая версия ре-шут-скрипта
   подавала объект целиком в merge-путь; поймано гейдом ДО записи файлов).
3. Живой witness-класс 000317 T7/T8: пустой поток (fallback-класс
   «L1 = одна строка») после роста каталога математически мёртв (минимальный
   пул видов 49 ⇒ P ≈ 0.45^49; свип 9M точек empty=0). Зуб перенесён на
   безусловную merge-строку kindPool[0] при L≥2; пины-свидетели (входят
   pool[0] ∉ поток L1 + hash-ранг вне top-6 expansion): T7 (0,1,bt2,w0),
   (0,3,bt11,w0); T8 (0,1,bt2,w0), (0,5,bt2,w0), (0,11,bt2,w0),
   (0,3,bt11,w1). Точки ПЕРЕПИКИНУТСЯ на любой следующей волне, меняющей
   состав/порядок пулов видов: перебор координат (buildingType × wealth)
   по условиям-свидетелям выше (поисковый /tmp-скетч не коммичен).
   См. эррату в memory/000317-shop-assortment-upgrade.md.
