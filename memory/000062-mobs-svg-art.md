## Где что лежит

  мобов: именование, кадры, геометрия, бюджет, стиль, формат,

  ~строка 41). Любое новое требование к ассетам мобов — сначала сюда.
* **assets/sprites/mobs/** — 192 файла:
  * 180 per-mob: `<mob_id>_<state>_<n>.svg`, state ∈ {move, attack,
    dead}; сейчас у каждого из 36 мобов move 2, attack 2, dead 1
    (правила допускают move/attack по 2–3).
  * 12 legacy-фолбэк (000047): 6 видов × 2 кадра — `abyss`,
    `elemental`, `orc`, `skeleton`, `spider`, `wolf`, 64×64. Бюджету
    per-mob НЕ подчиняются, двигать/переименовывать нельзя.
* **assets/mobs/NNNNNN.json** (36 файлов) — у каждого моба поля
  `описание` (800+ символов: анатомия, палитра HEX, материалы,
  отличительные черты, движение/удар/гибель) и `art` = { move: [2
  пути], attack: [2 пути], dead: [1 путь] } — ПУТИ, а не инлайн-SVG.
  `schema.json` — оба поля, `additionalProperties: false`.
* **src/sprites.js** — per-mob таблица (без 180 путей, выводятся из
  id): `MOB_ART_DIR`, `MOB_ART_FRAME_COUNTS` {move:2, attack:2,
  dead:1}, `MOB_ART_ACTIONS`, `mobArtFrames(mobId, action)` — чистая
  функция, неизвестный id/действие → [] (фолбэк). Состав «у кого арт
  есть» задаёт таблица `MOB_SPRITE_KINDS` (000047: 36 id → 6 видов).
  `allAssetPaths()` включает все 180 путей.
* **src/combat-ui.js** — drawUnits: цепочка фолбэков ПО ЮНИТУ —
  персональный арт (move/attack/dead) → базовые 6 видов MOB_FRAMES →
  прямоугольник ROLE_COLORS. Мёртвые мобы рисуются dead-кадром (без
  HP-полосы/уровня/цели).
* **Генератор** (референс для новых мобов): `scripts/gen-mob-art.js`
  (детерминированный, сид = fnv1a(id+pose), byte-identical) +
  `scripts/mob-art-data.js` (палитры/черты/описания 36 мобов).
* **Счётчик деталей**: `scripts/count-svg-details.js`
  (`node scripts/count-svg-details.js --min N FILE.svg ...`, exit 1
  при недоборе; экспорт `countDetails` для тестов).
* **Тесты**: `tests/mob-art.test.js` (все 36 мобов × все кадры:
  структура, бюджет, палитра, уникальность кадров, отриц. контроль),
  `tests/sprites.test.js` (tabлица == JSON «art», allAssetPaths),
  `tests/combat.test.js` (зеркало combat.js с
  `ART_ONLY_MOB_FIELDS = ['описание','art']` — зеркало арт-поля НЕ
  содержит), `tests/combat-ui.test.js` (труп, _unitFx),
  `tests/svg-details.test.js`.

## Правила деталей/бюджета (MOBS.md)

* «Деталь» = контурный элемент в теле SVG: path, circle, ellipse,
  polygon, rect, line. В `<defs>`, `<clipPath>`, `<mask>` и `<use>`
  НЕ считаются. `<g>` сам по себе не деталь.
* Бюджет: **≥ 30 · w · h деталей на КАЖДЫЙ кадр** (1x1→30, 2x2→120,
  3x3→270, 4x4→480, 5x5→750). Проверка:
  `node scripts/count-svg-details.js --min <30·w·h> assets/sprites/mobs/<id>_*.svg`
* Кадры цикла различаются конечностями/челюстями/энергией, а не
  общим сдвигом фигуры; цикл move замыкается (N ≈ 1), attack
  заканчивается «выбросом».
* Стиль: ракурс 3/4 сверху, плоские формы 2–3 тона, палитра моба 5–8
  HEX (SVG использует ТОЛЬКО цвета палитры из «описания» — проверяет
  тест), тень-эллипс rgba(0,0,0,0.25–0.3), тонкий тёмный контур.
* Формат: самодостаточный SVG (движок грузит через Image() под
  file://) — нет script/text/foreignObject/image/SMIL/внешних ссылок;
  id в defs с префиксом `<mob_id>_`; viewBox = 0 0 100·w 100·h;
  якорь — низ-центр; фигура целиком в канвасе.
* Поле `size` в JSON — объект {w, h} (не строка).

## Фолбэк на 6 видов (000047) — жив

* MOB_FRAMES / MOB_SPRITE_KINDS / mobFrames в sprites.js НЕ тронуты;
  12 legacy-файлов остаются. Фолбэк срабатывает по юниту: нет
  персонального арта (id не в MOB_SPRITE_KINDS / кадр не загружен /
  нет самого sprites.js) → базовые 6 видов, потом прямоугольник.
* У мёртвого моба без персонального арта НИЧЕГО не рисуется (нет
  «цветного прямоугольника трупа»).

## Как добавить нового моба (чек-лист по MOBS.md)

1. `assets/mobs/NNNNNN.json` — свободный номер, обязательные поля
   схемы (id, name, role, aggro, dmg, hp, size {w,h}, xp, skills,
   spells, loot) + `описание` (800+ символов, все смысловые блоки,
   палитра 5–8 HEX) + `art` {move:[2–3], attack:[2–3], dead:[1]}
   (пути по конвенции).
2. SVG-кадры `assets/sprites/mobs/<id>_{move,attack,dead}_<n>.svg` по
   MOBS.md: viewBox 100·w×100·h, ≥ 30·w·h деталей на кадр, палитра из
   описания, тень, префиксы id, самодостаточность. Могут генерировать
   scripts/gen-mob-art.js (добавить данные в mob-art-data.js) или
   рисовать вручную.
3. `MOB_TYPES` в `src/combat.js` — боевые данные (ядро).
4. `MOB_SPRITE_KINDS` в `src/sprites.js` — добавить id в таблицу (без
   этого `mobArtFrames` вернёт [] и моб отрисуется legacy-видом);
   при move/attack 3 кадрах поменять `MOB_ART_FRAME_COUNTS`
   (обновить все: все JSON + sprites.js + тесты).
5. Прогнать чек-лист QA MOBS.md (8 пунктов: 6 на кадр + 2 на моба).
6. Тесты: mob-art.test.js и assets-schemas/combat-зеркало подхватят
   JSON автоматически; дополнить табличные тесты sprites.test.js;
   `npm test` зелёный.
