# 000428 — c9 takenLater: направление «<» не контракт (расширение чина 000421)

## Что починено

Ветвь `takenLater` в тестах-читателях каталога `memory/000230.16-c9/` содержала
`assert.ok(<entry-байты> < live-байты)` — допущение «живой счётчик может только расти».
000421 (правка ряда Оружие в spec/items.md, Δ = −7) доказало обратное: line-neutral
правка умеет УСЕКАТЬ файл, и любая будущая отрицательная дельта ниже entry-чисел
законно краснила чужие файлы. Починены три места (значения ассертов не двигались,
тайтлы не двигались, пометка «ре-пин 000428» — внутри сообщения):

- tests/items-spellscroll-000321.11.test.js (T9, переменные `m[1]`/`liveBytes`);
- tests/items-resurrectscroll-000321.12.test.js (T9, те же переменные);
- tests/items-reagent-000321.10.test.js (T9, НАХОДКА свипа п.2 — скрытая форма с
  алиасами `em[1]`/`bytes`, литеральный свип «< liveBytes» её не ловит).

## Эталонная форма (носитель — tests/items-craftscroll-000321.13.test.js, ре-пин 000421)

    assert.notEqual(Number(m[1]), liveBytes,
      'c9: преемственность — байты ' + m[1] + ' не равны живым ' + liveBytes + ...);

Входить должен только класс «установка не совпала» (равенство своей entry живым
байтам при перехваченном счётчике), а не сравнение величин.

## Свип-рецепт (для будущих волн)

Литеральный свип по одному имени переменной НЕ полон. Канон:

    grep -rn "< liveBytes" tests/ ; grep -rn "< bytes" tests/

Алиасы переменных в takenLater-ветвях: `liveBytes` (.11/.12/.13), `bytes` (.10).
Полный список читателей каталога memory/000230.16-c9 в tests/: ровно 5 файлов
(четыре скролла 000321.10–.13 + items-spec-bytes-log-000386). В 000386-файле
направленных допущений нет (только equal/notEqual/фильтр-равенство). Рецептурных
«<»-форм в memory/000386-c9-bytes-log.md нет.

## Семантика предиката takenLater (важно для мутационных proofs)

`takenLater` истинен ⟺ некоторая ЧУЖАЯ entry равна живым байтам ТОЧНО (===).
Следствие: мутация «просто усек ниже своей entry» даёт takenLater=false и краснит
ELSE-ветку (assert.equal) одинаково ДО и ПОСЛЕ правки — proof не изолирует
takenLater-ветку. Мутация обязана бить живые байты ТОЧНО в значение другой entry
(прецедент: E = 41946 = entry 000321.09). ELSE-контракт («entry ≡ живым байтам,
пока хвост счётчика не перехвачен») правкой НЕ ослаблен — сценарий M3.
