# 000427 — Длительность паутины: вилка и вердикт

Файл append-only: нижние блоки не переписывать, новые дописывать сверху раздела истории.

## Вердикт дизайнера (2026-11-17, мастер 4f31f0f3): ВЫБОР (a) — `WEB_TURNS = 3`

Обещание «два хода последним» исполняется движком, а не стирается из текстов.

### Обоснование (цифры с диска)

1. Все остальные источники стата `ход_вниз` в каталоге имеют `turns: 3` —
   `assets/spells/slow.json`, `ice_field.json`, `zyuzyachaya_stuzha.json` (и снимки в
   `src/spells-data.js`). Паучья паутина — единственный писатель `ход_вниз` с `turns != 3`,
   и из-за этого её единственной «виновата» текстовая рамка.
2. Фактика окна доказана кодом и тестом: тик `c.ps.debuff.turns -= 1` в `startRound` идёт до
   `buildTurnOrder` ⇒ `WEB_TURNS=2` даёт ровно одну замедленную очередь;
   `tests/combat-web-000420.test.js` T4(a) пинит ровно это; ретро-b31 подтвердило живым прогоном.
3. Балансный страх «2 очереди при трейте 25%» снят самой механикой refresh: повторное попадание
   перезаписывает запись (`turns` снова максимум). При пауке, бьющем каждый ход, игрок уже сегодня
   замедлен практически каждый раунд; переход 2→3 добавляет лишь один хвостовой замедленный
   порядок после последнего попадания — steady-state почти не меняется.
4. Цена симметрична игроку: такое же окно игрок покупает за 4 маны («Морозное замедление») или 8
   (зона `ice_field`). Идентичность паука — два дебафа с укуса; CHANGELOG уже продал «две беды
   от одного укуса», «ходит два хода последним».
5. (b) — ретроактивная переписывка уже смерженного игроко-facing буллета (прецеденты протокола
   000408 покрывают sha-бэкфилл и перенос внутри дня, но НЕ смену обещания). (a) — одна константа
   + ре-пины одного тестового файла; буллет становится истинным без правки истории.
6. Риск EFIR_BAL119 ограничен: свип включает `spider_nest`; RNG-поток по числу бросков не меняется
   (web-ролл не зависит от `WEB_TURNS`); обязан полный пересъём, ре-пин интервалов лишь при красном.

### Критерий приёмки «текст ≡ фактика»

Число ходов, обещанное игроко-facing текстом (CHANGELOG-буллет «два хода последним», память),
равно числу подряд идущих очередей `c.turnOrder` с замедленной жертвой в хвосте после ОДНОГО
применения паутины без обновлений; сценарный тест (T4(a), сегменты на каждой границе раунда)
измеряет это число на каждом пересъёме базы и красен при любом расхождении текста и замера;
grep по CHANGELOG/spec/memory не оставляет носителей со старым числом.

### Третий путь — отвергнут

Тик дебафа после `buildTurnOrder` (или в конце раунда) сделал бы `turns == окну` глобально, но
ломает запиненный контракт окна `R+1..R+turns-1` (комментарий+ассерты 000235.08.01 в
`tests/combat.test.js`, wording `spec/spells.md` через `tests/spec-split.test.js`), превращает
описания ледяных спеллов «на 3 хода» в 3 реальные очереди, задевает ритм-контракты всех остальных
тиков `startRound` (щиты/weaken/реген/саммоны, пины 000112/000113/000167 D4/BR-5) и контракт 000420
«тики не-мобов — в startRound ДО пересборки». Special-тик только для паутины раздвоил бы семантику
одного стата в одном движке. Цена — десятки ре-пинов против одной константы в (a).
