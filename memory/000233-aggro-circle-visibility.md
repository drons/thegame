## 3. Контракты и границы

### 3.1 Стиль (заморожен, выбран расчётом контраста, ТЗ «Что сделать» 2)

| Параметр | Значение | Почему |
|---|---|---|
| strokeStyle | `rgba(255, 64, 56, 0.9)` | hue 000172 без изменений; α 0.9 < 1 — остаётся полупрозрачной («не заслоняет карту» — принцип 000172); 1.0 отклонён (лишний «лазер», ΔE +6 — не окупает) |
| lineWidth | **2** (константа `AGGRO_CIRCLE_WIDTH`, был инлайн 1) | w≥2 — при ЛЮБОМ дробном сдвиге камеры хотя бы ОДИН ряд пикселей покрыт полностью (принцип голубей) — устраняет AA-растворение 1px (главный дефект 000172); 2.5 — дробная (своё AA), 3 — «плотное кольцо», больше, чем просит ТЗ |
| dash | **[6, 6] — без изменений** | расчёт: паттерн влияет на duty (покрытие), не на ΔE пикселя; 6px-штрих × 2px × 90% — чётко читается; преемство «красная ПУНКТИРНАЯ» 000172; альтернатива [10,6] (а-анализ) даст +1.3× запас в α_eff-кросс-чек-модели — не стоит ломать дизайн-константу, которую ТЗ не просит менять |
| fill | `rgba(255, 64, 56, 0.10)` (константа `AGGRO_CIRCLE_FILL`) | «лёгкая» заливка: ΔE 5.9..10.1 — зона читается, тайлы под тоном читаемы; 0.08 отклонён (min 4.6 — у нижней границы допуска 4), 0.15 отклонён (ΔE до ~11.8 — уже «затенение», ближе к «заслоняет») |

### 3.2 Порядок вызовов в Проходе 2.5 (критичен для пинов — фикс)

```
s2.beginPath();
s2.setLineDash(AGGRO_CIRCLE_DASH);
s2.strokeStyle = AGGRO_CIRCLE_STYLE;
s2.lineWidth  = AGGRO_CIRCLE_WIDTH;
s2.fillStyle  = AGGRO_CIRCLE_FILL;
s2.arc(c.x, c.y, info.radius * zoom, 0, Math.PI * 2);
s2.fill();      // ДИСК зоны — до stroke
s2.stroke();    // КОЛЬцо поверх — главный элемент, полный alpha
s2.setLineDash([]);  // гигиена (коммент в коде — сохранить)
```

* Все style-свойства — БЛОКОМ до arc; `fill()` перед `stroke()`: кольцо —
  верхний элемент 2d-слоя при полном объявленном alpha (замена порядка
  отклонена: fill после stroke лёгко-красным тоном накрывал бы внутреннюю
  половину кольца — не критично, один hue, но кольцу нечего терять).
* **НЕ МЕНЯЕТСЯ (бит-в-бит)**: центр `toPt(t.x + 0.5, t.y + 0.5)`, радиус
  `info.radius * zoom` (чтение на кадр из `G.groupZoneInfo`), 0..2π, гарды
  (`!t.hasMobGroup`, `G.groupVisible(defeatedAt, …)`, `!info || !info.triggers
  || !(info.radius > 0)`, тихий `typeof`-гард), позиция прохода (между
  Проходом 2 и Проходом 3), z-порядок, ранние выходы (`!s2`/`readyCount()===0`
  наследуются), 0 rng, 0 мутаций состояния/сейвов.

### 3.3 Метрика контраста и допуски (ЗАМОРОЖЕНЫ; тест несёт TOL именованными
константами, вывод — здесь)

* **Метрика**: ΔE CIE76 (Lab, sRGB→XYZ D65) между фоном тайла `T` и смешанным
  пикселем линии `B = α·C + (1−α)·T` (сложение в sRGB, канвас-композитинг
  полностью покрытого ряда; C — цвет stroke). `worst = min ΔE` по ВСЕМ
  фоновым цветам ВСЕХ `assets/tiles/*.svg`.
* **Модель** (предусловие, ассертится в тесте): `lineWidth ≥ 2` — тогда у
  худшего пикселя ровно ОБЪЯВЛЕННАЯ альфа (одна полная строка); `α ∈ (0,1]`,
  `α_fill ∈ (0,1)`. Для w<2 модель невалидна → осмысленный fail
  («линия растворяется AA»).
* **TOL_STROKE = 40** (worst ΔE ≥ 40): JND для 8-бит sRGB ≈ 18–25 → 40 ≈
  1.6–2.2× JND. Замерено (этот worktree, `verify-contrast.js`): СТАРЫЙ стиль
  (α0.4, w1) — worst **32.8** (sand_1 #b6a676) → RED; НОВЫЙ (α0.9, w2) —
  worst **69.7** (sand_1 #b6a676) → GREEN, запас **1.74×**.
* **TOL_FILL = [4, 12]** (ΔE заливки vs фон, по каждому фону): «лёгкий тон —
  зона читается, тайлы читаемы». Замерено: **5.9..10.1** (запасы 1.48×/1.19×).
* **Фоновые цвета тайлов — правило парсинга (фикс)**: в каждом
  `assets/tiles/*.svg` — градиент, на который ссылается фоновый
  `<rect width="64" height="64" fill="url(#id)">`; фоны = `<stop>` этого
  градиента **БЕЗ атрибута `stop-opacity`**. Сейчас: 12 файлов, 24 стопа,
  16 distinct-цветов. Исключено: виньетка deepwater (`#deep`, stop-opacity
  0/0.55, НЕ фон), снежные шапки mountain (`#f0f0f6` и др. — polygon-филлы,
  не стопы градиента). Анти-«вакуум»: ≥12 файлов, ≥2 фона на файл (иначе
  осмысленный fail, не skip).
* **Худший тайл = sand** (самый светлый, как в ТЗ): worst 69.7 (sand_1
  #b6a676), второй — hill #7a7452 (71.6). Ассерт «argmin = sand» в тест НЕ
  заморожен (запас до hill всего 1.9 — хрупок при легальных правках стиля);
  факт зафиксирован здесь.
* **ПОЧЕМУ НЕ ЧИСТЫЙ WCAG** (разрешение «подвала» тест-анализа): красный
  (255,64,56) на grass/hill — совпадение по LUMINANCE (WCAG worst старого
  стиля = 1.01 (water), нового = 1.01 (grass) — РОВНЯ) → WCAG-порог НЕ МОЖЕТ
  разделить старый и новый стиль (оба не прошли бы 1.5). Видимость на этих
  фонах несёт ХРОМА — ΔE76 её ловит (ΔE 71.6–94.1 на hill/grass).
* **Почему не sRGB-евклид при α_eff = α·duty·lw/(lw+1)** (модель а-анализа):
  эвристический коэффициент, запас при выбранном стиле всего 1.05× (42.0
  < 56.2); оставлена в этом файле как КОНСЕРВАТИВНЫЙ КРОСС-ЧЕК: новый стиль
  проходит и там (42.0 ≥ 40), старый — нет (14.0).
* **Центры групп — только passable-тайлы, но ДУГА r=2·zoom пересекает любые
  соседние тайлы (вода/горы)** → контроль по ВСЕМ фонам всех 12 файлов, не
  только passable (map.js L1096 `hasMobGroup = passable && …`).

## 4. Решения анализа (openQuestions — все решены)

### 4.1 Линия или слой?
**Линия (стиль).** Пробой §1: layering корректен (ТЗ п.2, не п.3).

### 4.2 Значения стиля
**α 0.9 / w 2 / dash [6,6]** (§3.1) — по расчёту контраста на реальных
тайлах (§3.3); худший случай (самый светлый — sand) 69.7 ≥ 40 с запасом
1.74×; dash не влияет на ΔE пикселя → наследуется от 000172.

### 4.3 Заливка зоны (диск) — ДА, α_fill 0.10
ТЗ допускает («решение анализа»). За: (1) третья жалоба — только линия (даже
усиленная) — тонкий пунктир, легко не заметить; тон диска даёт ЗОНЕ
областность — два независимых признака (кольцо = радиус, диск = область);
(2) цель ТЗ — «НАДЁЖНО видна»; (3) «не заслоняет»: ΔE 5.9..10.1 < 12 —
лёгкий тон, тайлы читаемы. Против (тест-анализ: «линии достаточно, M9 не
трогать»): цифры «достаточно» — в WCAG-метрике, которая не разделяет
стари/нового (§3.3); M9 переписан осмысленно (§5) — гард жив в усилённом
виде. 0.08 (а-анализ) — слабее сигнала (min 4.6 у нижней границы допуска).

### 4.4 Порядок fill/stroke
**fill() → stroke()** (§3.2). Альтернатива (stroke→fill, «M1 не трогать»)
отклонена: ре-пин M1 АВТОРИЗОВАН ТЗ («другие зацепившие стиль пины — в том
же коммите с обоснованием» — fill, вставленный между arc и stroke, задевает
ордер-пин M1; техническая правка, геометрия M1 не трогается), а кольцу —
главному признаку — выгоден верхний слой при полном alpha.

### 4.5 Метрика и TOL
**ΔE CIE76 Lab, B = α·C + (1−α)·T, worst ≥ 40; fill ∈ [4,12]** (§3.3).
WCAG — не разделяет (подвал), α_eff — эвристика с запасом 1.05× (кросс-чек).

### 4.6 Структура тестов
**Один НОВЫЙ файл `tests/aggro-visibility.test.js`** с AV1 (node) +
AV2 (vm) (§5) — метрика/парсинг общие, в пределах одного файла; отдельный
файл (а-анализ) и M11-в-существующем (а-анализ) отклонены: TZ просит (a)
node-пробу и (b) e2e — два теста одного домена, общий код метрики.
