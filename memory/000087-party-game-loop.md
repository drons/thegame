Сопровождает `memory/000087-companion-cycle.md` (полный контракт,
решения D1–D14). Здесь — только фактура игрового цикла отряда.
Все строки main.js — ТЕКУЩИЕ (мастер смещается; ориентир — якоря).

**Конец боя — единый хелпер combatEndCompanions(res, combat):**
- victory: applyCombatXp(roster, res.allyXp) — выжившим xp += доля,
  уровни по порогу xpForNext (while — один бой может дать несколько
  уровней), строки: общая xp-строка + строки level_up.
- ЛЮБОЙ исход: мёртвые юниты (side 'ally', kind 'merc', !alive — из

- Порядок строк: xp/уровни, потом гибель.
- Игрок: 100% (res.xp) — без изменений. Эфир: 100% в СВОЙ пул — в
  combat-ui finish() (000081) ДО onEnd, 000087 НЕ дублирует.

## 2. Как наёмник попадает в бой

- На старте каждого из 3 боев: `opts.rosterData: companionAllies()` —
  по каждой записи отряда allyDataForEntry(entry, npc) (000082):
  kind 'merc', level из записи, dmg/hp/armor/навыки/заклинания из
  каталога; makeAlly пересчитывает maxHP/damage/armor из уровня при
  каждом createCombat (рост статов — ИМПЛИЦИТНЫЙ, в запись статы не
  пишутся).
- combat-ui: `allies = [efirData?, …rosterData]` — **Эфир ПЕРВЫМ**
  (якорь placeAllies px−1, py−1 — «всегда со мной», 000081).
- «Призрак» (npcId нет в каталоге) — не идёт в бой (null-skip), жалованье
  не платится, xp не начисляется — тихий skip всюду (000079/000082).
- Гибель в бою — юнит покидает бой, НЕ поражение (SPEC «Бой»).

## 3. Фиксированные строки (пины тестов; ТЗ фиксирует подстроки)

Смена дня — hudFlash, порядок: «Мобилизуются…» → строки отряда → «День N.»
(«День N.» — последняя строка, как до 000087):
- `Жалованье выплачено.`
- `Не хватает денег на жалованье — лояльность падает.`
- `<имя> покинул отряд.` («призрак» — голый npcId)

Конец боя — мир/debug: дописываются к базовой строке через '\n' (база НЕ
трогается: «Победа! +N опыта, +N золота.» / «Вы очнулись. −20% золота.» /
«Вы ушли от боя.»); подземелье — ds.log.push, строка = событие:
- `Спутники: +N опыта (<имя>, <имя>).` — victory, только выжившие с
  xp>0; N — ОБЩАЯ доля (round(base × companion_xp_share), base один на
  всех — доли равны); порядок имён = порядок allyXp = порядок roster.
- `<имя> повысил уровень (до N).` — на каждое level_up-событие.
- `<имя> погиб в бою.` — ЛЮБОЙ исход (victory/fled/dead).

Не трогаются: «Победа! +… опыта, +… золота.», «Вы очнулись. −20%
золота.», «Вы ушли от боя.», «(Босс|Группа) повержена. +N опыта.»,
«Мобилизуются новые группы мобов.», боевой журнал combat.js «… пал в
бою!» (in-combat layer), найм/увольнение 000083 («Нанят: <имя> за N з»,
«Уволен: <имя>», «<имя>: NPC отказался вступать в отряд — повторить
попытку можно на следующий день»).

## 4. Правила повторного найма

- После УВОЛЬНЕНИЯ — МОЖНО (даже в тот же день): кандидат возвращается
  при следующем открытии вкладки «найм» — candidatesForTavern
  (000079) пересчитывается при каждом open на ЖИВЫХ ссылках
  roster/deadMercs (deps-бандл 000083, main.js L1048-1049). ДЕНЬ на
  фильтр не влияет (сид найма — hash2(day, npcId) — влияет только на
  ОТКАЗ, а не на список).
- После ГИБЕЛИ — НЕЛЬЗЯ (окончательно, SPEC): npcId в deadMercs →
  отфильтрован навсегда; dead_mercs — раздел сейва (000085).
- Кандидаты = каталог найма (000078, 6 наёмников) − нанятые (roster)
  − мёртвые (deadMercs); порядок = порядок каталога.
- Гибель фиксируется только в бою (combat.units, kind 'merc');
  Эфир в dead_mercs не попадает НИКОГДА (SPEC: не умирает навсегда).

## 5. Числа баланса (из каталога 000078 и SETTINGS — не хардкод)

- Жалованье (з/день) и цена контракта (з):
  merc_volk 1 / 40, merc_ashka 1 / 50, merc_baldor 2 / 60,
  merc_mira 2 / 80, merc_torga 3 / 100, merc_rena 3 / 120.
- Самое дорогое трио (torga+rena+baldor/mira) = 8 з/день = **16%**
  дохода квеста ~50 з → **каталог НЕ правится** (ТЗ: править данные
  только при дисбалансе). Порог тест-пина W3: любое трио ≤ 10 з/день
  (20% от ~50) — проходит с запасом (максимум 8).
- Лояльность (SETTINGS.companion_loyalty): старт 50+Харизма (cap 100),
  paid +2, unpaid −20, quit_low 20 (уходит верно), quit_high 40,
  quit_chance_mid 0.5 (полоса 21…40, roll seed (day, npcId)).
- companion_xp_share = 0.5 (live-чтение в combat.js).
- max_companions = 3 (live).
- Отказ при найме: 30% − 2%·Харизма − 5%·Артист (min 0), seed (day, npcId).
