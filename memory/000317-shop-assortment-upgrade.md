## 1. Правило расширения (по ФАКТУ КОДА)

`items.makeShop(x, y, buildingType, wealth, level)` — пятый факультативный
аргумент `level` (items.js:1538). Не-целый/<2 → L=1 (бит-в-бит прежняя
генерация: ОДИН mulberry32(seed)-поток на wealth — сид-цепочка не
сдвинута, 0 новых RNG-вызовов на не-улучшенном пути).

При L ≥ 2 сток = union двух семейств (слияние — `max` количеств):

1. UNION базовых генераций: потоки `w = wealth .. lo`, где
   `lo = max(0, wealth − floor((L−1)/2))` (та же f(L), что effWealth
   000222). Каждый поток `w` — mulberry32(ТОГО ЖЕ seed) и тот же цикл
   `rng() < 0.55 + 0.1·w`; ВАЖНО: пул потока — пул БОГАТСТВА `w`
   (`w===3` → allItems(), иначе фильтр видов), НЕ пул `wealth` — иначе
   на переходе богатства (effWealth 2→3) сдвигается выравнивание
   потока и ⊇-контракт ломается (зафиксировано RED-прогоном: на паре
   L4→L5 богатство 2→3 пропали 1 ключ и упали 3 количества).
2. EXPANSION: `expSeed = (hash2(x, y, SHOP_EXPAND_SEED) ^
   (buildingType + 1)) >>> 0` (items.js:1521/1561; SHOP_EXPAND_SEED =
   0x45585031 — derived-константа-соль, паттерн CAMP_STOCK_SEED;
   СИД НЕ содержит level и wealth). Ранг предмета:
   `h(id) = (expSeed ^ fnv1a(id)) >>> 0`; берутся первые `L−1`
   предметов пула ВИДОВ лавки по порядку (h, id) — top-k по
   ФИКСИРОВАННОМУ случайному порядку над полным пулом видов (не
   «pool \ stock» — вложенность E(L) ⊆ E(L+1) тогда априорна).
   Количество: `1 + floor(((h ^ SHOP_EXPAND_QTY_SALT) >>> 0) / 2^32 ·
   (2 + wealth))` (SHOP_EXPAND_QTY_SALT = 0x51747931).

Fallback «магазин не пуст»: при L=1 пустой поток → `stock[pool[0].id]=1`
(items.js:1575, бит-в-бит как до задачи; w3 — pool=allItems, не kindPool).
При L≥2 ДО expansion безусловно мержится ГАРАНТИРОВАННАЯ СТРОКА
`merge(kindPool[0].id,1)` (items.js:1561) — первый предмет пула ВИДОВ,
количество 1 (max-слияние), не зависит от богатства и непустоты потоков.
Раунд 1 мержил её условно («если потоки пусты») — этого МАЛО: условие
неинвариантно по L, т.к. cities поднятым effWealth добавляет непустой
поток нового богатства, он глушит «пусто», и fallback-ключ терялся на
ШАГЕ БОГАТСТВА (аудит-блокер раунда 2; контрпримеры (0,1,bt2,w0),
(−34,48,bt2,w0), (−54,51,bt2,w0), (−53,10,bt11,w1): minor_healing
исчезала L2→L3; брутфорс 120×120×bt{0,1,2,3,11}×w{0,1} — 32 события
потери; до раунда 1 — ещё и пересечение с expansion: (1082,5771,bt2,w0)
L1={minor_healing:1} → L2={bread:1}; частота пустого потока ~0.035%
координат — малый пул видов × богатство 0/1).
Известный ТЕОРЕТИЧЕСКИЙ край (находка ревью раунда 3, не блокер): при
ПУСТОМ kindPool (вид лавки без единого предмета в каталоге)
гарантированная строка бросит TypeError — недостижимо (у всех shop-
записей каталога виды всегда имеют предметы) и симметрично старому
fallback L=1 (падал на пустом pool[0:] так же до задачи); решение —
ОСТАВИТЬ без гарда (0 новых веток, поведение совпадает с пре-задачным).

Контракт монотонности (airtight ПОСЛЕ раунда 2, пины T1+T7+T8):
множества ключей И количества НЕ убывают с уровнем на каждом шаге
L→L+1 (union-потоки: множество потоков растёт с L и каждый поток
определён фиксированно; E(L): top-(L−1) над фиксированным пулом;
гарантированная строка kindPool[0] мержится при ЛЮБОМ стоке и
богатстве — ключ инвариантен; T8 пинит ⊇/qty по ЦЕПОЧКЕ effWealth
min(3,w+floor((L−1)/2)), L=1..7 — именно её условный fallback
раунда 1 нарушал на шаге богатства). Строгий рост: +1
кандидат-ранг на шаг, НО шаг не даёт новой строки, если ранг уже покрыт
стоком; верхняя граница — полное покрытие пула видов (documented в
спеке; тесты пинят строгий суммарный рост L1→L7 и ≥3 строгих шага на
незакрытых координатах).

## 3. Сид-цепочка (уровень НИ В КАКИЕ сиды не входит — 000222 сохранён)

1. Координаты: x′ = cityX·256+tx, y′ = cityY·256+ty
   (CITY_SHOP_CELL_BASE=256, GOLDEN 000108 — не трогать).
2. Базовый сид: `(hash2(x′, y′, 0x154075) ^ (buildingType+1)) >>> 0` —
   без изменений; пин: одинаков для всех L.
3. Derived-сид расширения: `hash2(x′, y′, SHOP_EXPAND_SEED) ^
   (buildingType+1)` — level/wealth НЕТ; далее чистые хэши fnv1a(id),
   Math.random/c._rng/новые энтропийные источники — НОЛЬ
   (mulberry32 перезапускается от существующего seed — multi-stream,
   не новая энтропия).
4. Доставка уровня: built.level (сейв v1, persistent) → syncShopLevels
   при входе (locations.js:348-349) и после upgrade/demolish
   (building-actions.js:1446/1637, registerSpecial('upgrade') :1537) →
   реестр shopLevels → makeCityShop читает реестр (cities.js:486-495) →
   пятый аргумент makeShop (cities.js:498-499). Свежая сессия /
   повторный fresh-вход — тот же seed + тот же level → тот же сток
   (пин T3).

## 7. Подводные камни

- Пул потока = пул богатства ПОТОКА (см. §1.1) — не «pool(wealth) на
  все потоки» (RED-прогон показал конкретные потери).
- Fallback × expansion и fallback × effWealth (аудит-блоки раундов 1
  и 2): при пустом потоке (богатство 0/1, малый пул видов) строка
  pool[0] исчезала с экрана после апгрейда — сначала из-за expansion
  (раунд 1), потом из-за поднятого effWealth (раунд 2, условный
  «потоки пусты»); фикс — БЕЗУСЛОВНАЯ гарантированная строка
  kindPool[0] при L≥2 ДО expansion; стражи: T7 — координата класса
  (1082,5771,bt2,w0) + свип «stock(L) ⊇ stock(1)» по фиксированному
  богатству; T8 — ⊇/qty по цепочке effWealth (пин (0,1,bt2,w0),
  (−34,48,bt2,w0), (−54,51,bt2,w0), (−53,10,bt11,w1) + свип
  bt{0,1,2,3,11}×w{0,1}×сетка 24×24; точки перепикинуются при росте
  каталога — прецедент стражей T2).
- Expansion — top-k над ПОЛНЫМ пулом видов (не над «пул \ union»):
  вложенность E(L) ⊆ E(L+1) и qty-монотонность априорны; у варианта
  «top-k по пулу \ union» количество может УПАСТЬ при переходе
  expansion-предмета в базовый поток на следующем уровне (редкий, но
  реальный контрпример — не выбирать его ради «пошаговой строгости»).
- vm-песочницы без buildings.js: SHOP_KINDS_FALLBACK тоже получает
  расширение (kinds из фолбэка, тот же путь кода).
- makeCampShop — своя сигнатура/сид (CAMP_STOCK_SEED, по дню) — level
  не принимает, 0-diff.
- Тесты ДИНАМИЧЕСКИЕ (⊇/strict по фикс-координатам) — каталог
  разрастается (000333), count-канарейк нет; «≥3 строгих шага» —
  устойчивость к единичному stalled-шагу при росте каталога.
- Полный прогон — только в worktree, ОДИН за разом
  (--test-concurrency=1: sync-all/LF7 в items.test.js гоняют sync-скрипты

- Мутации: реализацию сначала коммитить (git restore откатывает к HEAD —
  прецедент 000315).
