# 000026: размеры построек, размещение без пересечений, вход

Статус: выполнено и закоммичено (тесты 200 → 213 pass).

## Решения

* **Данные.** В `assets/buildings/` и JS-фолбэке `src/buildings.js`
  добавлены необязательные поля `размер` {ширина, высота} и `вход`
  [dx, dy] (схема — `assets/buildings/schema.json`: ширина 1..5,
  высота 1..4, вход — 2 целых 0..4, additionalProperties=false).
  Крупные: Арена/Монастырь/Ратуша/Храм солнца — 3x3, вход [1,2]
  («юг», середина нижнего ряда); Башня мага — 2x2, вход [1,1];
  Рунический камень — явный 1x1, вход [0,0] (пример в каталоге).
  Остальные 44 — без поля (по умолчанию 1x1).
  Важно: из 13 «картовых» типов (map_index) в мир реально рождаются
  только Арена (idx 4) и Храм солнца (idx 8) — они и крупные;
  Башня/Монастырь/Ратуша — только каталожные типы.
* **Чистые функции** (src/buildings.js, экспорт):
  * `buildingSize(b)` → {width, height} (по умолчанию 1x1);
  * `buildingEntranceRel(b)` → [dx, dy], зажат в размер;
  * `sizeChain(w, h)` — цепочка уменьшения: каталожный → (если > 3x3)
    [min(w,3), min(h,3)] → (если > 1x1) [1,1]; 5x4 → [[5,4],[3,3],[1,1]];
  * `placeBuilding(b, x, y, isFree)` — пробует цепочку, footprint =
    прямоугольник w×h от якоря (вправо/вниз); принимает, если ВСЕ
    тайлы свободны; вход для уменьшенного размера зажимается;
    null — не влезло даже 1x1.
* **Размещение** (src/map.js, closure createMap):
  * `anchorAt(x, y)` — то же правило якоря, что было до задачи
    (проходимый + fbm > 0.33 + 0.14·rarity + hash типа).
  * `isFreeForBuilding(ax, ay, tx, ty)` — проходимый И не занят
    постройкой с лексикографически РАНЬШИМ якорем (oax < ax или
    (oax == ax и oay < ay)). Ссылка только «вперёд по порядку» —
    порядок хорошо основной, рекурсии/циклов нет.
  * `buildingAtAnchor(ax, ay)` — мемоизация (fpCache, clear при
    >65536): запись {anchor, type, x, y, w, h, entrance, wealth}
    или null. wealth 0-3 считается в якорном тайле и принадлежит
    постройке как целому.
  * `coveringFootprint(x, y)` — окно [x-2..x]×[y-2..y] (окно =
    BUILD_MAX_W/H, сверяется тестом с максимумом каталога); первый
    найденный = лексикографически первый = единственный (пересечений
    нет по построению).
* **Гарантия без пересечений:** тайл принадлежит постройке с
  лексикографически РАНЬШИМ якорем, если тот его успешно занял;
  поздняя постройка всегда проверяет всех «раньше», поэтому не может
  занять занятый тайл — она сжимается (sizeChain) или исчезает.
* **Семантика tileAt (назад-совместимо для main.js):**
  * новые поля: `inBuilding`, `isEntrance`, `buildingAnchor`
    ([ax,ay]|null);
  * `hasBuilding` = true ТОЛЬКО на тайле входа (магазин/пещера/
    диалог NPC — там же, где и раньше для 1x1);
  * `passable` = terrainPassable && !(в footprint'е и не вход) —
    стены построек непроходимы;
  * `hasMobGroup` = passable && НЕ покрыт footprint'ом (раньше —
    только «не якорь»);
  * `building`/`buildingWealth` отдаются на всех тайлах footprint'а
    (main.js читает их только при hasBuilding — на входе).
* **Каталог лениво** (браузер): в index.html buildings.js (строка 189)
  грузится ПОСЛЕ map.js (строка 185), поэтому map.js в browser-ветке
  получает catalog=null и в `catalogRef()` берёт `root.Game` в момент
  tileAt (все скрипты загружены до main.js). Третий аргумент фабрики
  — сам `root` (в node — undefined, каталог уже через require).
  Фолбэк без каталога — все постройки 1x1 (defensive).

## Правки по итогам ревью (дефект major: замурованный вход)

**Баг.** Алгоритм размещения требовал проходимости всех тайлов
footprint'а, но не проверял, что у входного тайла есть проходимый
сосед. 3x3-постройка на пляже (нижний ряд на песке, под ней вода)
ставила вход (середина нижнего ряда) в кольцо из 3 собственных стен
+ воды — постройка генерировалась, но в неё нельзя было войти
никогда (игрок ходит в 4 направлениях, tryMove пускает только на
t.passable). Определённые экземпляры на реальной карте: Арена
якорь (-128,36) вход (-127,38) и Арена якорь (1,-88) вход (2,-86).
Второй подслучай (не назван в ревью, но тот же дефект): стена
ПОЗДНЕЙ постройки могла замуровать последний свободный сосед входа
РАННЕЙ (найдено в плотном синтетическом мире: вход якоря (35,-30),
стена якоря (35,-27)).

**Фикс (2 условия, индукция по порядку якорей).**
* `placeBuilding(b, x, y, isFree, validateSize)` — новый опциональный
  аргумент: размер принимается, только если все тайлы свободны И
  `validateSize(x, y, w, h, entrance)` не отклонила его; иначе —
  следующий (меньший) размер в sizeChain, до 1x1 или null.
  Без аргумента — старое поведение (тесты совместимы).
* src/map.js (closure createMap):
  * `entranceReachable(ax, ay, rx, ry, rw, rh, rex, rey)` —
    валидатор размера: (1) у входа кандидата есть свободный сосед
    вне его footprint'а; (2) каждый вход РАННЕЙ постройки,
    соседний с footprint'ом кандидата, сохраняет свободный сосед
    помимо тайлов кандидата (стена не замуровывает чужую дверь).
    Свободный сосед = проходимый рельеф + не занят ранней
    постройкой; сам вход кандидата внутри footprint'а считается
    свободным (он проходим).
  * `entranceHasFreeNeighbor` / `isFreeEntranceNeighbor` — проверка
    4 направлений (игрок ходит без диагоналей);
  * `buildingWithEntranceAt(ax, ay, x, y)` — ранняя постройка с
    входом в (x, y) (якорь в 2 тайлах, footprint ≤ 3x3), только
    якоря «раньше» — циклов нет, мемоизация fpCache работает.
* Инвариант в готовом мире: у входа КАЖДОЙ постройки есть
  проходимый сосед. Доказательство: индукция по лексикографическому
  порядку якорей — (1) даёт сосед новому, (2) гарантирует, что
  поздние постройки не заберут последний сосед ранним.
* Поведение: крупная постройка на прибрежном/тесном месте сжимается
  по sizeChain (3x3 → 1x1), 1x1 с замурованным якорем исчезает.
  Контент не теряется: на реальной карте обе «замурованные» арены
  стали 1x1 на якорном тайле (проверяемо).

**Числа.** Реальная карта ±150: ДО 763 построек / 110 multi /
2 замурованных входа → ПОСЛЕ 764 / 108 / 0 (одна новая постройка
— следствие того, что сжатые footprint'ы освободили тайлы; всё
детерминировано). Плотный синтетический мир ±100: 3 замурованных
(2 «свои стены + вода» + 1 «чужая стена») → 0. Сканирование
реальной карты ±400: 5408 входов, 0 замурованных, 0 пересечений.

**Тесты.** tests/buildings.test.js: placeBuilding с validateSize
(цепочка при отклонении, null при полном отклонении, вход
кандидата в аргументах, чистота). tests/map.test.js:
`assertEntrancesReachable` — инвариант «у входа есть проходимый
сосед» на 3 синтетических мирах (по умолчанию; R=0 прилив —
прибрежный случай; A=255 плотный — случай чужих стен) ±100 и на
реальном assets/map.png ±150 (с проверкой, что в сэмпле остались
много-тайловые постройки).
