## Экран подземелья: как есть

* Ядро — src/dungeon.js (чистое, node): форма (createDungeon)
  сидируется ТОЛЬКО точкой входа → d.seed («один вход — один
  лабиринт», SPEC); содержимое (generateDungeonContents) — сидом
  player.totalXp. 5 типов DUNGEON_TYPES (CAVE/CRYPT/RUINS/DROWNED/
  ABYSS), размеры 25/27/31/27/35, сетка бинарна (CELL_WALL/
  CELL_FLOOR), мобы — блуждающие группы 1–3 mobId (DUNGEON_MOBS;
  босс Бездны — 3 юнита), сундуки 2–5, wanderStep на каждый шаг
  игрока.
* UI — src/dungeon-ui.js (browser): отдельный canvas в оверлее
  (.combat-overlay .dungeon-overlay), cell = 22/18 px, ВСЯ карта на
  экран, без камеры/зума/rAF; пол #182029, стены — тёмный фон,
  выход «X», вход зелёный, сундуки золотые, мобы красные/фиолетовые
  с уровнем, игрок — голубой ромб. Ввод — keydown через
  G.deltaForEvent (000043); один шаг на нажатие (автоповтор ОС);
  день — на выходе (clock.event('dungeon'), SPEC «Игровое время»).
* dungeonState/dungeonMemory — in-memory, НЕ в payload сейва
  (collectSaveData: day/steps/position/hero/quests/npcStocks/
  defeatedAt).

## Решения (зафиксированы в подзадачах)

* «Тот же движок» (000066) = та же математика камеры/зума, а не
  переписывание: у подземелья НЕТ WebGL-слоя (весь визуал SVG), но
  zoom px/клетку = мировому zoom (ZOOM_START=80, ZOOM_MIN/MAX
  4..128, map.js), камера — G.cameraStep + CAM_TAU_MS (motion.js),
  видимая область — G.visibleTileRange (map.js), проекция те же
  (x = W/2 + (tx−cam.x)·zoom). НОВОЕ для конечной сетки: кламп
  камеры к границам; вьюпорт > подземелья (35×4 px при ZOOM_MIN) —
  центрирование, снаружи тёмный фон.
* Колесо: мировой слушатель зума — на canvas #game, оверлей его
  накрывает → зум в подземелье сейчас НЕ РАБОТАЕТ. Решение:
  ОДИН общий zoom (мировая переменная), слушатель на оверлее,
  HUD «Масштаб: Xpx» остаётся корректным.
* Фон оверлея ПОЛУПРОЗРАЧНЫЙ (rgba(5,8,12,0.88)) — мир проступает
  на 12%: решение — непрозрачный canvas/фон #0a0d12 (мир за
  оверлеем рендериться продолжает — не предмет задачи).
* Детерминизм вида: стены/пол сидируются d.seed (ФОРМА), а не
  сидом содержимого (totalXp) — иначе возврат с новым опытом менял
  бы вид при той же форме. Форма/содержимое в dungeon.js уже
  сидируются по-разному — использовать так.
* Пять типов — пять видов (матрицы зафиксированы): пол — 3 SVG-
  варианта на тип (палитры — в духе фонов боя 000049), стены —
  CAVE: камень+сталактит; CRYPT: колонна+камень; RUINS: колонна;
  DROWNED: только камень (под водой); ABYSS: сталактит+камень.
  Предметы стен — только wall-клетки edge-маски (8-соседство с
  полом), иначе сплошная стена = густая стена камней.
* Все новые пути ассетов — в allAssetPaths() (sprites.js): main.js
  в очередь лоадера ставит только этот список. Детерминированный
  выбор — hash2-паттерн tileVisuals/frameIndex; каталоги —
  литеральные зеркала (паттерн COMBAT_BG_DUNGEON) без зависимости
  sprites.js от dungeon.js (vm-песочница dungeon.js не грузит).
* Спрайты (000067): подземельные мобы — группы 1–3 mobId → каждый
  через mobSpriteKind (000047; таблицы в sprites.js); НЕ хардкодить
  числа кадров — frames.length (000062, master, расширит MOB_FRAMES:
  2–3 кадра движения/удара + уничтоженный, MOBS.md). Сундук —
  спрайт (открытый не рисуется); выход «X»/вход — остаются
  текстовыми/цветовыми маркерами (зафиксировано). Фолбэки пер-юнит.
* Глейд (000068): ОТДЕЛЬНЫЙ createMover в dungeonState (мировой
  мувер main.js ~206 не трогать); teleport-снапы — побег/смерть из
  подземного боя (onEnd: ds.x=ds.prevX) и вход; группы — снап
  (интерполяция за рамками). motion.js менять не нужно.
* Сейв: структура не меняется ни в одной подзадаче; персистентность
  подземелья = отдельная задача (save.version + MIGRATIONS,
  000031-save-versioning.md).
* Ввод/цикл подземелья НЕ унифицировать с миром (одна клетка на
  keydown без троттлинга; день — clock.event('dungeon'), не
  clock.addStep): регрессии 000043 (e.key ц/ф/ы/в) и 000061
  (в подземелье вверх/вниз корректны — в мире инверсированы).
