## 1. Суть бага

000145 (мерж f4fd4e3, коммит **9d8b9ed**) добавил в render-хук вкладки
«Персонаж» цикл «устаревшие узлы» ряда портретов —
**`src/ui-tab-skills.js:612`**:

```js
for (const ch of row.children.slice()) {   // row = div.cp-portraits
```

(проверено `git log -L`: строка введена 9d8b9ed, последующие 000146/000147
её не трогали).

В РЕАЛЬНОМ браузере `element.children` — **HTMLCollection**: есть
`length`, индексный доступ, `item(i)`, `contains()`, итератор — НО НЕТ
Array-методов (`.slice`/`.forEach`/`.find`/`.map`/`.filter`/`.includes`)
→ `TypeError: row.children.slice is not a function or its return value is
not iterable` при каждом `toggle(true)`/`render()`.

Во ВСЕХ ~30 DOM-стабах проекта `children: []` — **plain Array** →
`.slice()` в стабах легален → регрессия невидима тестам. Ловушка
«стаб ≠ реальное DOM», тот же класс, что у 000098 (там — классы, здесь —
коллекции). Единственная точка в src, вызывающая Array-метод на
`.children` (grep по `src/*.js`): `ui-tab-skills.js:612`. Строка 577
(`for (const ch of row.children)`) — голое итерирование, в браузере
легально (итератор у HTMLCollection есть).

## 3. Фикс (решено)

**ОДНА строка** `src/ui-tab-skills.js:612` + 1 строка комментария:

```diff
-          for (const ch of row.children.slice()) {
+          // 000169: row.children — HTMLCollection (нет .slice) —
+          // копируем через Array.from (итерируемый; на стаб-массиве
+          // та же семантика, что у .slice()).
+          for (const ch of Array.from(row.children)) {
```

Почему `Array.from` (кандидаты `Array.prototype.slice.call` и индексный
цикл тоже проходят проверенный red/green — выбор по идиому):
* **устоявшийся паттерн кодовой базы**: src/items.js:119,
  src/sprites.js:785, src/building-effects.js:2681, src/main.js:2651;
* работает и на реальном HTMLCollection (итерируемый), и на стаб-массиве
  (`Array.from(array)` — копия, семантика `.slice()`);
* семантика СОХРАНЕНА: КОПИЯ списка детей ДО цикла `ch.remove()` —
  «уход устаревших узлов» работает как задумано 000145.

## 6. Правило для будущих задач

* `element.children` / `element.childNodes` — **ЖИВЫЕ коллекции**
  (HTMLCollection/NodeList): `for...of`, `length`, `item(i)`,
  индексный доступ — ДА; Array-методы (`.slice`/`.forEach`/`.find`/
  `.map`/`.filter`/`.includes`) — **НЕТ** → `Array.from(el.children)`.
* `querySelectorAll` — **NodeList**: есть `.forEach`/`.item`; НЕТ
  `.map`/`.find`/`.slice` → тоже `Array.from`. (Текущий src использует
  на qsa-результатах только for..of/.forEach — легально; см. ловушку §7.)
* **vm-стаб с plain-Array children скрывает этот класс багов**: для
  браузерно-специфичных DOM-путей (UI-модули панелей) добавлять тест с
  collection-fidelity-стабом (прецедент — 000169,
  `tests/ui-panel-htmlcollection.test.js`).
* Ревью-скан diff-а: новые обращения к `.children`/`.childNodes`/
  `querySelectorAll` на браузерные-only методы (grep-паттерн 000169:
  `children\.slice|children\.forEach|children\.find|children\.map|
  children\.filter|children\.includes`).
