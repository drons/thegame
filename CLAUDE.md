Создаём игру по спецификации SPEC.md

Текущие задачи берём из каталока tasks/pending
Правила работы над задачами: @tasks/CLAUDE.md

Пушить в основной репозиторий нельзя.
Изменения вносим только в локальный репозиторий.
Каждая задача должна выполняеться в отдельном git worktree и 
финально оформленна в виде одного коммита, содержащего все изменения.

Изменения кода должны сопровождаться созданием тестов.

Важную информацию записывай в каталог memory в проекте и коммить вместе с изменениями

Алгоритм работы такой:
 1) Проанализировать задачи в каталоге `pending`, выбрать те, которые имеют
 минимальные пересечения при мерже и которые сейчас не выполняются
 (для них отсутствует ветка и git worktree)
 2) Запустить workflow в отдельном git worktree для каждой задачи из выбранных:
   - Запустить субагентов для детального анализа задачи
   - По результатам анализа выработать общую архитектуру изменений
   - При необходимости разработать 'красные' тесты, которые покажут выполнение задачи
   - Решить задачу, написать код, создать ассеты и т.п.
   - Запустить агентов по анализу решения задачи, запустить тесты, 
   ещё раз провести анализ решения и убедиться, что поставленные цели достигнуты
   - Заблокировать мерж в мастер для других параллельных workflow создав в
   корне проекта текстовый файл `.merge-pending` с номером задачи 
   - Перебазировать изменения на новый актуальный мастер 
   (он мог измениться с начала старта workflow), ещё раз протестировать,
   проанализировать, убедиться, что всё зелёное
   - Если изменение касается изменению игрового процесса или графического дизайна, то 
   добавить в CHANGELOG.md краткое упоминание по дате мержа.
   - Произести мерж в мастер (без создания отдельного мерж-коммита), удалить файл `.merge-pending`
   - Если был произведён мерж последней подзадачи для задачи `XXXXXX.md`, то запустить
   субагентов и убедиться, что поставленные цели достигнуты, если цели не достигнуты, 
   то создать дополнительные подзадачи, и приступить к ним в порядке очереди.
   - Вернуться к пункту 1
3) Раз в несколько итераций запускать агентов в отдельном workflow, проводящих
глубокий ретроспективный анализ изменений и проверяющих, не нарушили ли новые задачи
в процессе изменений смежные аспекты и старые контракты из SPEC.md, если найдено
нарушение или баг, то создать новую задачу с целью исправления. И в любом случае,
если ретро-анализ проводился после коммита с решенем задачи `XXXXXX`, то в папку 
`tasks/results` коммитить файл `XXXXXX-retro-{somesuffix}.md` с результатами анализа.
