Лагерь на карте: размещение и появление (SPEC)
(follow-up 000095 — открытый вопрос из её анализа;
Зависимости: 000095 (механики лагеря: костёр/барахолка/
кочевник — СМЕРЖЕН); мерж ПОСЛЕ 000095)

Родительская: 000095 (лагерь: костёр и барахолка).

Проблема: 000095 реализовала механику лагеря (постройка
id 47: «Костёр» = clock.rest, «Барахолка» = сток по ключу
тайла лагеря, NPC кочевник 000018), но НЕ разместила
лагеря на карте — по SPEC «Расширение карты» лагерь на
глобальной карте не генерируется (map_index не дан),
e2e-тесты 000095 работают через ГРАНЬ building-actions
с синтетическим тайлом. Для игрока лагерь НЕДОСТИЖИМ:
механика есть, встречать её негде.

Цель: зафиксировать (по SPEC, сверено в коде) где и как
появляется лагерь и реализовать размещение. Варианты по
прецедентам: (а) стационарное место/места на карте (как
город 000052 получил мост 000050), (б) элемент городов
(000104/000106/000107), (в) детерминированная генерация
по сид-миру (1–N лагеря, (x, y) от seeds — паттерн
generateDungeonContents/000099). Если SPEC прямого
правила не даёт — предложить вариант, согласовать по
спецификации раздела «Лагеря и кочевники» (если есть) и
зафиксировать решение в memory + SPEC-примечании.

Что сделать
-----------
* АНАЛИЗ (агенты): где SPEC позволяет лагерю существовать
  (поиск по SPEC.md: «лагерь», «кочевник», «Расширение
  карты», «Города»); какие точки уже заняты (пины
  e2e-координат); как размещаются аналогичные объекты
  (000052: мост→город; 000093: смотровая башня; 000077:
  магический круг).
* Реализация размещения: детерминированная позиция
  (сид-мир), не пересечение с существующими постройками
  и входами в пещеры; лагерь НЕ генерируется дважды.
* e2e: игрок реально ДОХОДИТ до лагеря (walkTo, [E] →
  оверлей: «Костёр» / «Барахолка» / диалог кочевника),
  сток барахолки живёт по ключу тайла (000095).
* Регрессия: синтетические e2e 000095 (грань
  building-actions) остаются зелёными; стоки/NPC —
  без изменений.

Тесты (красные)
---------------
* e2e vm: лагерь на карте в сид-мире (координаты
  зафиксировать голденом), достижим за N шагов (N ниже
  steps_per_day — иначе день сдвинется), оверлей с тремя
  действиями; детерминизм (тот же seed → тот же тайл).
* Если размещение — в городах: vm-тесты в стиле
  city-screen (000105/000106/000107).
