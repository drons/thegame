Телепорт-круг: пары, активация, перемещение
(подзадача 000064, приоритет P2 — параллельно с 000074/000076,
после 000071/000072/000073)

Родительская: 000064 (эффекты «особых» построек: проработка и
планирование)

Цель: перемещение между телепорт-кругами (id 41, подтип слота 10 —
с 000073) по детерминированным парам с разовой активацией.

Состояние сейчас (сверено с кодом master)
* id 41 — только в каталоге (`особые_параметры.эффект` — проза); на
  карте появляется как подтип слота 10 с 000073.
* Выбор проходимого тайла (стартовый тайл/спавн — src/main.js ~440:
  поиск по проходимости) — готовый паттерн для точки переноса.
* Раздел сейва `teleports` — имя зафиксировано в 000072.

Ключевые проектные решения (зафиксировано в SPEC «Эффекты
построек»)
* ПАРНОСТЬ: для круга в (x, y) — ближайший другой круг по
  РАССТОЯНИЮ CHEBYSHEV в радиусе R=100 тайлов; при равенстве
  расстояний — тай-брейк по hash координат (детерминированно);
  круг без пары в радиусе — «СПИТ»: действие показывает сообщение
  («круг молчит: нет пары вблизи»), это НЕ ошибка и не «мёртвый»
  круг. R и стоимость — в каталоге (`особые_параметры.эффект`).
* АКТИВАЦИЯ: разовая оплата золотом (стоимость из каталога);
  активированные круги — в сейве (раздел `teleports`, паттерн
  000072): повторная активация/телепорт НЕ тратит золото.
* ПЕРЕМЕЩЕНИЕ: на проходимый тайл РЯДОМ с парным кругом
  (алгоритм — как выбор стартового тайла: ближайшие проходимые,
  детерминированный порядок по hash); если рядом нет проходимого —
  сообщение, перенос не происходит (золото не тратится).
* СКАН: окно R=100 — до ~40k вызовов tileAt — делается ТОЛЬКО при
  ПЕРВОМ подходе к кругу, результат (id пары) кэшируется в сейве
  (`teleports`); в игровом кадре скан не повторяется.

Что сделать
1. Чистая функция `linkTeleportCircles(circles, x, y, R, tieHash)`
   (src/building-effects.js или новый модуль — решать в задаче):
   circles — список позиций кругов (в тесте — синтетический, в
   игре — результат скана `tileAt` по окну); → `{ pairId | null,
   reason }`.
2. main.js: скан при первом подходе (окно R, `tileAt(...).
   buildingId === 41`), кэш в сейве; действие «Активировать/
  Телепорт» из реестра buildingUI (000071): проверка стоимости →
  списание золота → перенос (или «спит»/«нет проходимого»).
3. Каталог: id 41 — `особые_параметры.эффект.стоимость` (и R, если
  решим параметризировать) + зеркало (паттерн 000073/000055).

Тесты
* `tests/building-effects.test.js`:
  * парность: ближайший по Чебышеву (не евклидов), на границе
    R=100 включительно, за R — нет;
  * тай-брейк: два круга на одном расстоянии — стабильный выбор по
    hash (перестановка списка не меняет результат);
  * одиночный круг → «спит» (message, ok=false, не исключение);
  * телепорт: цель проходимая и в footprint-соседстве пары;
    непроходимые соседи пропускаются; все соседи непроходимы →
    переноса нет, золото не списано;
  * активация: первое использование списывает золото (стоимость из
    каталога), повтор — не списывает; сейв roundtrip (`teleports`).
  * детерминизм: один и тот же круг в двух «мирах» — та же пара.
