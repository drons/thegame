  квадрат W×W из `DUNGEON_SIZE[type]`, тип — из ТЕРРЕЙНА

* Содержимое подземелья сидируется ОПЫТОМ персонажа (totalXp,
  `generateDungeonContents`) — для города НЕ подходит (город не

  «внутри + несколько дней» — к персистентному городу НЕ

* src/cities.js — НЕТ; vm-песочницы (tests/sprites.test.js,

Что сделать
1. src/cities.js (НОВЫЙ, чистый UMD по паттерну day.js/npc.js:
   node — require, браузер — `Game.cities`; зависимость —
   perlin.js; взаимных require в момент загрузки НЕТ):
   * `createCityLayout(cityX, cityY, footprint)` →
     `{ width, height, cells, entrance:{x,y}, exit:{x,y}, seed,
       kind: 'city' }` (дungeon-совместимая структура; `kind` —
     маркер для 000105):
     - width/height — из footprint типа (1, 2, 5, 7 — каталог
       000102); внутренний размер layout — решение (например,
       footprint×2 — город 5x5 снаружи = 10x10 внутри) —
       зафиксировать в задаче + тестом;
     - `cells` — периметр = CELL_WALL, внутренность — открытое
       пространство CELL_FLOOR (город — не лабиринт;
       «улицы/кварталы» — решение в задаче, по умолчанию —
       открытое пространство);
     - `entrance`/`exit` — на перимете (вход — сторона, с
       которой герой зашёл, выход — противоположная сторона/
       другой угол — зафиксировать); обе клетки — FLOOR и
       достижимы;
     - `seed = hash2(cityX, cityY, CITY_LAYOUT_CONST)` — от
       ПОЗИЦИИ города (константу зафиксировать; НЕ totalXp,
       НЕ террейн). Layout СТАТИЧЕН: один якорь → один layout
       навсегда.
