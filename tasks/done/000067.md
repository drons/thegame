Анимированные спрайты Флогистона и мобов в подземелье + спрайт сундука
(подзадача 000032, направление 2)

Родительская: 000032 (модернизация экрана подземелья).

Цель: персонажа и мобов в подземелье рисовать графическими
анимированными спрайтами в том же стиле, что и на глобальной карте
(SVG из assets/sprites + Game-спрайт-лоадер), вместо голубого ромба
и цветных квадратов. Сундук — тоже спрайтом.

Состояние сейчас
* src/dungeon-ui.js render(): игрок — голубой ромб #8cf2fc; мобы —
  блуждающие ГРУППЫ (1–3 mobId из DUNGEON_MOBS; босс Бездны — 3
  юнита: abomination + 2 lower_demon) — красные #d9483b / босс
  фиолетовый #b06ad4 квадраты + белый номер уровня; сундук — золотой
  квадрат #e0b13c + тёмная полоса (открытые — не рисуются); выход —
  жёлтый «X», вход — зелёный квадрат.
* Глобальная карта (drawSprites, src/main.js ~863): Флогистон —
  G.phlogistonFrames(action) (idle/walk/attack/cast), размер
  zoom*1.15, центр — ДРОБНАЯ точка рендера; группы мобов мира —
  ОДИН спрайт MOB_FRAMES[kind], размер zoom*1.2; выбор кадра —
  чистая G.frameIndex(now, tx, ty, n) (FRAME_MS=480, sprites.js).
* mobSpriteKind(mobId) (задача 000047, sprites.js): все 36 id
  MOB_TYPES → 6 базовых спрайт-видов MOB_FRAMES (orc/skeleton/wolf/
  spider/elemental/abyss); неизвестный id → null. Id мобов
  подземелий (DUNGEON_MOBS) — подмножество этих 36.
* МИРОВОЙ паттерн «одна группа = один спрайт» в подземелье
  неприменим: группа — 1–3 mobId (босс — 3 юнита) → рисовать каждого
  моба группы через mobSpriteKind(g.mobIds[i]).
* Задача 000062 (master, pending, развитие 000047): новые
  высокодетальные ассеты мобов — 2–3 кадра движения + 2–3 кадра
  удара + кадр уничтоженного состояния, конвенция MOBS.md;
  MOB_FRAMES/таблицы будут РАСШИРЕНЫ. Поэтому эта задача зависит
  ТОЛЬКО от таблиц MOB_FRAMES/mobSpriteKind в sprites.js (число
  кадров — frames.length) и НЕ хардкодит имена/числа кадров.
* Спрайт-лоадер уже есть в main.js (G.createSpriteLoader, очередь —
  allAssetPaths()); в бой он передаётся (000047/000049:
  startCombat({ spriteLoader })).

Работа
1. src/main.js: dungeonUI.start({ ..., spriteLoader }) — готовый
   лоадер (паттерн 000047/000049: combat-ui получает его так же);
   spriteLoader может быть null (нет s2/лоадера) — UI терпит:
   полный фолбэк.
2. Игрок: кадры G.phlogistonFrames('idle'), размер zoom*1.15
   (формула мира), центр клетки; 'walk' — ХУК для 000068 (глейд →
   'walk', иначе 'idle') — в этой задаче всегда 'idle'.
3. Мобы: для каждого mobId в g.mobIds — mobSpriteKind(mobId) →
   MOB_FRAMES[kind] → кадр G.frameIndex(now, g.x + off[i].x, g.y +
   off[i].y, frames.length) (off — детерминированные смещения по
   индексу юнита в группе: [0,0], [−0.35,0.15], [0.35,0.15] клеток —
   группа «встает» вокруг своей клетки); размер zoom*1.2 (как мобы
   мира). Номер уровня группы и boss-подсветка сохраняются поверх
   (как сейчас: белый номер уровня, подсветка по прямоугольнику
   группы).
4. Сундук: assets/dungeon/chest.svg (один файл, высокодетальный,
   viewBox 64×64) + путь в src/sprites.js (литерал, как
   BUILDING_SPRITES) + allAssetPaths() += путь. Отрисовка — zoom*0.8
   по центру клетки; ОТКРЫТЫЙ сундук — не рисуется (как сейчас —
   клетка пуста; вариант «открытый» спрайт — не нужен).
5. Выход «X» и вход (зелёный) — остаются текстовыми/цветовыми
   маркерами (читаемость; спрайт-изация — за рамками). Решение
   зафиксировано, чтобы экран не остался «наполовину современным»
   молча.
6. Фолбэки ПЕР-ЮНИТ (паттерн 000047): image null / spriteLoader null
   / sprites.js не загружен → текущий прямоугольник/ромб именно для
   этого юнита (остальные — спрайты).

Тесты (tests/dungeon-ui.test.js, красные — до кода падают)
* с ready-лоадером (заглушка createSpriteLoader): drawImage вызывается
  на кадрах phlogiston и на кадрах MOB_FRAMES; ожидаемые размеры
  (zoom*1.15 игрок, zoom*1.2 мобы);
* смена кадра во времени: фиктивный now → другой кадр frameIndex

* группа из 2–3 mobIds: drawImage по числу mobIds (босс Бездны — 3),
  смещения по индексу;
* сундук: рисуется при !opened, НЕ рисуется при opened;
* номер уровня и boss-подсветка — сохранены (регрессия существующих
  drawCalls текста/цветов).
