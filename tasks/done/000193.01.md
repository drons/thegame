# 000193.01 — БОЙ: MP-полоска наёмника — показать ману (u.maxMP + HUD-ветка)

Родительская задача: 000193 (tasks/pending/000193.md — заклинания Эфира и
союзных NPC в книге заклинаний, те же механики, что у Флогистона).
Исход: finding 1 (minor) ревью 000193. Тип: малая функциональность
(полевая модель + HUD-ветка + репины). Приоритет: P2. Зависимость:
мерж ПОСЛЕ 000193 (использует его модель makeAlly.u.mp).

Проблема (зафиксирована в memory/000193-ally-spell-mechanics.md §15)
----------------------------------------------------------------------
После 000193 модель ДАЁТ наёмнику ману (makeAlly: u.mp = 5+Int+Wis,
рефилла в бою нет — startRound рефиллит только пулы; касты из книги
тратят u.mp — пин CU193-BOOK: 9→3). Но MP-полоска HUD 000199 (D5,
src/combat-ui.js, ветка «наёмник: маны нет») по-прежнему рисует
наёмника по KIND: fill 0%, текст «MP —» (пин CU199-MPBAR-ALIAS(b) —
ре-пинен 000193 технически: только фикстурная строка merc.mp).
У активного наёмника, кастующего из книги, остаток маны не виден
нигде в HUD (в строках книги — только стоимость «Мана N»; title
«не хватает маны (N)» — только при дефиците). Асимметрия видимости
механики: у игрока и Эфира мана на полосе, у наёмника — нет
(000193 «те же механики, что и у Флогистона» — механики есть,
видимость HUD неполная). Решение «HUD 000199 не трогать» — осознанное
(000193 не правит смерженный чужой регион и не делает семантических
репинов чужих тестов).
