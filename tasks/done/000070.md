«Непроходимые» предметы стен — камни, колонны, сталактиты
(подзадача 000032, направление 3)

Родительская: 000032 (модернизация экрана подземелья).

Перепривязка: была №000065 в ветке task/000032; при мерже на master
(579285a занял 000065 — «Найм спутников») перепривязана на 000070
(правило — memory/task-numbering-conflicts.md).

Цель: стены (клетки CELL_WALL) рисовать не тёмным фоном, а
«непроходимыми» предметами — камнями, колоннами, сталактитами
(формулировка задачи 000032). Набор предметов зависит от типа
подземелья; назначение предметов на клетки — детерминированное, по
сиду ФОРМЫ подземелья.

Состояние сейчас
* Сетка бинарна: CELL_WALL=0 / CELL_FLOOR=1 (src/dungeon.js). В
  отрисовке (src/dungeon-ui.js) стены — просто тёмный фон canvas
  (#0a0d12), на «стенах» ничего нет.
* Форма лабиринта (createDungeon) сидируется ТОЛЬКО точкой входа →
  d.seed (SPEC: одинаковый вход — одинаковый лабиринт); содержимое
  (generateDungeonContents) сидируется player.totalXp. Сиды уже
  разведены в src/dungeon.js — и вид стен обязан сидироваться
  d.seed, а НЕ сидом содержимого: иначе после возвращения с новым
  опытом то же подземелье (та же форма) выглядело бы иначе.
* Пять типов (DUNGEON_TYPES) — набор предметов на КАЖДЫЙ тип
  (типичный косяк — один набор для всех пяти).
* При каждом входе dg создаётся заново (maybeEnterDungeon, main.js —
  createDungeon по точке входа, детерминированно); в dungeonMemory
  хранится только contents (не dg) — новое поле на d безопасно:
  пересчитывается идентично при каждом входе.
* Паттерн детерминированного выбора — hash2 от координат
  (tileVisuals, src/sprites.js).

   * Матрица тип → допустимые предметы (таблица-литерал рядом с
     DUNGEON_MOBS, чтобы 000058 (каталог assets/dungeons) переносила

     - CRYPT:   column, rock;

       дизайн-решение, зафиксировано);

   * Чистая функция wallObjFor(x, y, d) → 'rock_1'|'rock_2'|
     'column_1'|'column_2'|'stalactite_1'|'stalactite_2'|null:
     зависит ТОЛЬКО от (x, y, d.seed, d.type) через hash2 — без

     прилегающих к проходам. На floor/entrance/exit предметов нет.

Ограничения
* Детерминизм: ТОЛЬКО (x, y, d.seed, d.type); порядок/состояние
  содержимого — не аргументы (иначе повторный вход при том же лабиринте
  давал бы другую картину).
* Слои рендера (000066): стены (предметы) — ПОД мобами/игроком/сундуками;
  сталактиты — внутри слоя стен (порядок «поверх» между видами стен не
  нужен: предметы занимают разные клетки).
* 000058 (каталог assets/dungeons, подзадача 000053) может
  реорганизовать константы/вывод src/dungeon.js — матрица типов
  размещена переносимым в JSON образом; при коллизии — ребейс на
  актуальный master + сверка (зависимость зафиксирована).
* Не пересекается с 000069 (отдельные директории/скрипты/таблицы;
  в allAssetPaths — разные блоки).
* Структура сейва не меняется: dg не в payload, wallObjs
  пересчитывается при каждом входе; персистить вид стен НЕ нужно.
* Зависимости: жёстких нет (работает standalone, фолбэк — тёмный
  фон); визуальный смысл — после 000066.
