Биндинги клавиатуры в бою: аудит, единая таблица, тесты
(подзадача 000030, направление 2)

(В ветке task/design задача была под номером 000033; при мерже в master
номер занят другой задачей — перепривязана.)

Цель: проверить и привести к порядку клавиатурные биндинги атак,
заклинаний, предметов, бега и перемещения в бою; вынести таблицу
биндингов в единое тестируемое место; устранить конфликты.

Модель клавиш (база для всей задачи — см. src/controls.js, задача 000028)
* e.code — ФИЗИЧЕСКАЯ клавиша, не зависит от раскладки. Кириллических
  code не существует: 'KeyЦ'/'KeyЫ'/'KeyФ'/'KeyВ' — невалидные значения,
  они никогда не приходят в событии.
* Русские символы лежат на тех же физических клавишах (code — позиция
  в US-раскладке): Ц=KeyW, Ф=KeyA, Ы=KeyS, В=KeyD (ряд ASDF),
  Й=KeyQ, К=KeyR, У=KeyE, Г=KeyU, А(кир.)=KeyF, Л=KeyK.
* e.key — символ в текущей раскладке (на KeyW в русской — 'ц').
* Движение в мире уже идёт через двухуровневое маппирование
  src/controls.js (Game.moveKeyForEvent / Game.deltaForMoveKey: уровень
  1 — e.code, уровень 2 — e.key 'ц/ф/ы/в' для сценариев, где code не
  несёт информации); таблица боя должна быть с ней согласована.

Состояние сейчас (src/combat-ui.js)
* Действия — в keydown-цепочке, перехватываются по e.code ДО проверки
  движения: KeyA—Удар, KeyQ—Огонь, KeyR—Исцел., KeyB—Блок,
  KeyE—Быстрый предмет, KeyT—Предмет, KeyF—Побег, Space—Конец хода;
  Esc — закрыть (только после боя), Space/Enter — закрыть после боя.
* Перемещение — fallback keyDir(e.code): стрелки + KeyW + KeyS + KeyD
  + мёртвые записи 'KeyЦ'/'KeyЫ'/'KeyФ'/'KeyВ' (невалидные code —
  никогда не срабатывают).
* Что реально двигает (по раскладкам):
  * английская: W/S/D — вверх/вниз/вправо; A — «Удар» (не движение),
    влево — только стрелка;
  * русская: Ц(KeyW)/Ы(KeyS)/В(KeyD) — вверх/вниз/вправо (работают
    «случайно», через те же физические коды WASD); Ф(KeyA) — «Удар»,
    влево — только стрелка; кириллическое А(KeyF) — «Побег».
  * Шапка-комментарий combat-ui.js («стрелки / WASD / ЦФЫВ — шаг»)
    верна только для Ц/Ы/В; для Ф — нет (Ф = «Удар»).
* Таблица биндингов задублирована: в keydown-обработчике, в keyDir(),
  в подписях кнопок ('Удар [A]'), в шапке-комментарии файла.
* Невозможное действие по клавише — тишина (нет сообщения в лог).

Проблемы, которые нужно закрыть
1. Конфликт KeyA: в бою KeyA = «Удар» (цепочка перехватывает его до
   keyDir), в мире KeyA = влево (CODE_DIRS, src/controls.js) — на
   русской раскладке физический Ф не двигает влево. Решение по
   умолчанию: WASD/ЦФЫВ в бою = то же движение, что в мире (полностью,
   включая A/D/Ф/В), «Удар» переносится на правую руку — J (KeyJ,
   позиция «джойстик» у Space; на русской раскладке это клавиша Л).
   Остальные действия (Q/R/B/E/T/F/Space) — без изменений.
   Если аудит покажет лучшее решение — документировать.
2. Русская раскладка: таблица по e.code, а русские «дубли» на
   ЙЦУКЕН-позициях для существующих действий — те же самые физические
   клавиши (Й=KeyQ, К=KeyR, И=KeyB, У=KeyE, А(кир.)=KeyF) и ничего не
   добавляют. Добавляются только НОВЫЕ физические клавиши:
   Л=KeyK (дубль действия на J) и Г=KeyU (дубль действия на T).
   Каждая клавиша — ровно одно действие, без двойных назначений.
   Поддержка по e.key (виртуальные клавиатуры, code 'Unidentified') —
   опциональный второй уровень по паттерну src/controls.js (KEY_DIRS),
   не блокирует задачу.
3. Единый источник таблицы: новый UMD-модуль src/combat-keys.js (без DOM):
   - константа-таблица: code → { type: 'move', dx, dy } |
     { type: 'action', action } | null; ТОЛЬКО канонические e.code
     (записей с кириллицей быть не должно — это мёртвый код); часть
     перемещения совпадает с CODE_DIRS из src/controls.js —
     переиспользовать Game.Controls.CODE_DIRS или дублировать
     согласованно (решение в реализации);
   - чистая функция resolveCombatKey(code, state) →
     { kind: 'move'|'action'|'none', action?, dir?, reason? }, где
     state — сводка боя (phase, result, canDo по 000037); невозможное
     действие → kind 'action' + reason (UI пишет reason в лог боя);
   - describeCombatKeys() → строка/список для подписей кнопок
     (подписи кнопок генерировать из таблицы, не хардкодить).
   combat-ui.js использует модуль; мёртвые записи 'KeyЦ'/'KeyЫ'/
   'KeyФ'/'KeyВ' удалить из keyDir; шапка-комментарий combat-ui.js —
   актуальная сводка.
4. Нажатие «мёртвой» клавиши (действие невозможно) — строка с причиной
   в c.log (интеграция с 000037; без 000037 — минимум «сейчас нельзя»).
5. Проверить согласованность:

Тесты (tests/combat-keys.test.js)
* Таблица: каждое действие назначено минимум одной клавише; ни одна
  клавиша не имеет двух назначений; все ключи таблицы — канонические
  e.code (прогон по списку ключей: кириллицы/невалидных значений нет).
* Движение: KeyW/KeyA/KeyS/KeyD и стрелки → 4 направления (8 физических
  клавиш); после решения по KeyA — KeyA влево и KeyD вправо работают
  (физические Ф и В).
* resolveCombatKey: неизвестный code → 'none'; 'KeyJ' → action 'attack'
  (после переноса «Удара»); 'KeyA' → move left; фаза не игрока →
  действия с причиной; result → 'none' (кроме закрытия).
* Дубли на новых физических клавишах: Л=KeyK даёт то же действие, что
  KeyJ, и Г=KeyU — то же, что KeyT.
