Отрисовывать постройку по всему footprint'у, а не на одном тайле входа (src/main.js)


(В ветке task/map задача была под номером 000033; при мерже в master номер занят другой задачей — перепривязана.)
Задача 000026 сделала постройки много-тайловыми (Арена/Храм солнца —
3x3, см. memory/000026-building-sizes.md). tileAt теперь отдаёт
`inBuilding`, `isEntrance`, `buildingAnchor`, а `hasBuilding` — true
только на входе. Слой спрайтов (drawSprites, src/main.js) рисует
спрайт постройки там, где `t.hasBuilding` — т.е. 3x3-постройка
видится одним спрайтом на входном тайле, стены — голым террейном.

Что сделать (drawSprites / drawTile, src/main.js):
* Для тайла с `t.inBuilding` определить размеры постройки:
  `t.buildingAnchor` = [ax, ay]; правый/нижний край — через
  соседние tileAt (или закэшировать запись по якорю: все тайлы
  footprint'а несут buildingAnchor).
* Спрайт постройки (buildingSprite(t.building)) рисовать не
  1x1 тайлом, а прямоугольником w×h тайлов с якорём (ax, ay):
  `ctx.drawImage(img, sx_ax, sy_ay, w*zoom, h*zoom)` (до остальных
  спрайтов, как сейчас).
* Не дёргать drawImage 9 раз: один раз на постройку (проход по
  frameTiles: если `t.inBuilding` и (t.x, t.y) == якорь — рисовать;
  либо словарь по якорю за кадр).
* Декорации (Game.tileVisuals, задача 000021) на тайлах-стенах
  (inBuilding && !isEntrance) не рисовать — иначе травинки
  вырастают «на стене».
* Проверить: игрок обходит постройку (стены непроходимы —
  уже работает), на входе открывается магазин/пещера/диалог
  (hasBuilding — уже работает), спрайт стоит на месте при
  перемещении камеры (якорь детерминирован).
