Работа
* Точка входа: стоя на тайле постройки, чей тип ∈ union `здания`
  рецептов, — [E] (когда NPC нет) либо опция диалога (когда NPC
  есть) — открывает экран крафта ЭТОЙ постройки.
* Экран (паттерн современных экранов 000030/000041; vm-тесты в стиле
  tests/dungeon-ui.test.js / combat-ui.test.js / ui-skills.test.js):
  - список рецептов, доступных в этой постройке (recipe.здания
    включает тип), сгруппированный по видам: текущий уровень вида
    (Game.Craft.craftLevel) и требуемый (recipe.уровень) —
    недоступные помечены;
  - по рецепту: исходники (нехватка помечается — по инвентарю),
    шанс качества/выхода (qualityChance/yieldChance; у постройки —
    качество, в поле — 0), результат (имя предмета);
  - действие — Game.Craft.craft(hero, id, {building}) — показ
    результата (предмет, качество, выход, xp/уровень виду);
  - зачарование: для вида зачарование выбор заклинания из
    recipe.заклинания (только изученные — hero.spells, с маной
    spell.мани) → opts.spellId.
* Диалог NPC (npc.js): у NPC, чьи обучения.навыки маппятся в вид
  крафта (Game.Craft.SKILL_CRAFT_TYPE) — опция «обучить <вид>» за
  цена_за_уровень (проверка — canMentorCraft: постройка вида,
  уровень < 100, золото); действие — mentorCraft.
* В поле (building=null — без шанса качества, SPEC «Рецепты»):
  есть ли UI-точка входа — проектное решение, зафиксировать в
  memory.
* index.html — новые модули в правильном порядке (UMD-ловушка
  000038: craft.js ДО consumer'ов; main.js/combat-ui.js — снимают G
  один раз); добавить в tests/index-order.test.js.
