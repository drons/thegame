Что сделать
-----------
1. src/map.js: новая чистая функция `lootAt(x, y)` (вызов внутри
   tileAt; публичная для тестов):
   * кандидат существует только если тайл passable и вне footprint
     постройки (через cover/anchor — как моб) и БЕЗ mob-группы
     (исключение — приоритет ниже, см. п.2);
   * кандидаты — предметы с полем `loot` (items-data.js), чей
     `terrains` содержит TERRAIN_NAMES[terrain] тайла, либо
     (`near_mountains` && гора в 8-окрестности — предикат
     nearMountain(x,y), чистый, по terrain из той же map-функции);
   * выбор кандидата: для каждого — ролл
     `(hash2(x, y, LOOT_SEED + itemId·0x9e3779b9) >>> 8) / 2^24
     < frequency` (паттерн tileVisuals sprites.js L665-688);
     победит кандидат с МАКСимальным роллом/частотой — детерминированно;
     ровно ОДИН предмет на тайл;
   * LOOT_SEED — НОВАЯ константа (не трогать GLOBAL_SEED, каналы
     построек/мобов, VISUALS_SEED).
2. tileAt: единая точка решения (п.1 вызывается ЗДЕСЬ, не снаружи):
   `cover (постройка) → loot=null, mob=null (как сейчас);
   ИНАЧЕ hasMobGroup → mob, loot=null (ИСКЛЮЧЕНИЕ — ТЗ);
   ИНАЧЕ lootAt → loot: {item: id}|null;
   ИНАЧЕ пусто.`
   Новые поля в tile: `loot` (null | {item}). Старые поля
   (hasMobGroup, mobGroup, cover, hasBuilding…) — НЕ ПЕРЕСЧИТЫВАЮТСЯ
   (логика каналов 1:1, только порядок: лут спрашивается только там,
   где раньше было пусто) → старые golden-значения неизменны.
3. Детерминизм: только hash2/fbm/terrain-функции; два вызова
   createMap с теми же аргументами → один loot (тест).
4. Degradation: items-data не загружен (vm-песочница, паттерн
   000058/000073) → `loot` = null на всех тайлах; старые поля
   байт-в-байт (пины map.test.js зелёны без перепина СТАРЫХ полей;
   GOLDEN_TILES — осознанный перепин добавочного поля `loot` —
