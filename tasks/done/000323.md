Пол подземелья: 8 тайлов на тип, сид = координаты + номер этажа,
бесшовная стыковка

Источник: запрос пользователя (drons, 2026-11-05).

Цель: для каждого типа подземелья сгенерировать 8 различных тайлов для
пола и рисовать их в случайном порядке. Сид этого порядка для каждого
этажа подземелья должен быть фиксирован и зависеть только от координат
подземелья на глобальной карте и номера этажа. Тайлы одного типа
подземелья обязательно должны безшовно стыковаться друг с другом в
произвольном порядке и отличаться только в небольшом количестве деталей
(наличие камешка, грибочка, мха, лужи и т.п.).

Что сделать:
* Типы подземельй по факту диска (каталог/генерация — аудит). На каждый
  тип — 8 НОВЫХ SVG тайлов пола (размер тайла — по факту кода рендера;
  формат — flat-SVG паттерн 000302: flat polygon/circle/ellipse, без
  градиентов/текста/transform) в каталоге тайлов (раскладка — по факту
  кода/анализа, зафиксировать в memory).
* Бесшовность: тайлы одного типа стыкуются в произвольном порядке
  (края совпадают); различия — только мелкие детали (камешки, грибочки,
  мох, лужи и пр.). Контракт бесшовности — в memory; визуальная
  проверка — в result (если автоматический тест краёв нереализуем —
  зафиксировать).
* Порядок отрисовки: детерминированный PRNG, СИД = f(координаты
  подземелья на глобальной карте, номер этажа) — одна формула на всё
  приложение (контракт в memory + SPEC), 0 зависимости от времени/
  игрока.
* Рендер этажа — тайлы пола по этому порядку (рендер подземелья — по
  факту кода).

Тесты (красные):
* 8 тайлов на каждый тип (sweep каталогов), формат — sweep svg-паттерна
  (well-formed/strict-парсер, паттерн tests/svg.test.js).
* Детерминизм: те же (координаты, этаж) → ОДИНАКОВЫЙ порядок тайлов
  (две независимые генерации, точное равенство); другие этажи/
  координаты → другие порядки (пин на 2–3 пары).
* Рендер: пол этажа рисуется тайлами из набора типа (не одна старая
  текстура — по факту кода).
