Тач-D-pad: перемещение в подземелье и на поле боя

Цель
----
On-screen D-pad (тач-контролы, задача 000018) сейчас работает только
на глобальной карте. Сделать так, чтобы на мобильных устройствах
(и в режиме `?controls=touch`) D-pad управлял перемещением в подземелье
и на поле боя — полный игровой цикл играем без клавиатуры.

Состояние сейчас (сверено с master)
-----------------------------------
* Тач-контролы (000018): on-screen D-pad (удержание → направление) +
  кнопка действия «E»; собирается в src/ui.js при загрузке, чистая
  раскладка/хит-тест — src/controls.js (`layoutTouchControls`,
  `touchActionAt`). Подключены ТОЛЬКО к глобальной карте:
  main.js → `touchControls.init({ onHold: (dir) => keys.add('touch:'+dir),
  onRelease, onInteract: toggleNpcDialog })`; движение карты потребляет
  этот Set (tryMove → `deltaForMoveKey`).
* Подземелье (src/dungeon-ui.js): собственный `window keydown` —
  `G.deltaForEvent(e)` → `ctx.onMove(dx, dy)`. Тача нет.
* Бой (src/combat-ui.js): только `keydown` → `resolveCombatKey`
  (единая таблица src/combat-keys.js, задача 000048: move / block /
  quickItem / заклинания). Тача нет.
* Итог: в подземелье/бою на телефоне D-pad — декорация: onHold
  продолжает писать в Set `keys`, но движение карты подавлено, а
  UI подземелья/боя этот Set не читают. Кнопка «E» —
  `toggleNpcDialog`, который сам гасится при активном бою/подземелье.
* Готово к переиспользованию: чистые функции src/controls.js
  (`deltaForEvent`, `deltaForMoveKey`, `touchMoveKeyForAction`,
  `TOUCH_ACTIONS`) и src/combat-keys.js (`resolveCombatKey` по
  `code`) — если тач-направление маппить на те же коды, что и
  клавиатура (ArrowUp/KeyW, …), вся логика боя переиспользуется
  без параллельных таблиц.
* Боевой UI уже имеет кликабельные элементы (кнопки действий, выбор
  цели) — в бою тачом кликами уже можно действовать; не хватает
  именно перемещения (и «быстрого предмета»).

Что сделать
-----------
1. МАРШРУТИЗАЦИЯ ВВОДА: единый тач-источник (D-pad из 000018)
   маршрутизирует события в активный экран по приоритету:
   бой > подземелье > глобальная карта. Решение «какой экран активен
   → какой колбэк» — чистая функция (src/controls.js или новый
   модуль), main.js — только клей. Решение по умолчанию: ОДИН D-pad
   с маршрутизацией (не по D-pad на экран) — раскладка уже на
   вьюпорте, оверлеи боя/подземелья не должны перекрывать контролы
   (проверить z-index).
2. ПОДЗЕМЕЛЬЕ: направление D-pad → `ctx.onMove(dx, dy)` (как сейчас
   по клавише). Семантика удержания решить и задокументировать:
   шаг по тапу + повтор по фиксированному интервалу при удержании
   (интервал — глобальные настройки, 000063) либо только по тапу.
3. БОЙ: направление D-pad → те же `code`, что и клавиатура (ArrowUp/
   KeyW, …) → `resolveCombatKey` (src/combat-keys.js) — без дублирования
   таблицы. Тап = одно действие (шаг), БЕЗ повтора при удержании
   (в бою каждое действие тратит ход). Кнопка «E» → `quickItem`
   (как KeyE). Остальные действия (блок, заклинания, выбор цели) —
   кликами по элементам боевого UI; при необходимости — отдельная
   кнопка «Блок» (решить и задокументировать).
4. КНОПКА «E» ПО ЭКРАНАМ: карта → диалог NPC (как сейчас), бой →
   «Быстрый предмет», подземелье → действия нет (скрыть кнопку или
   no-op — решить и задокументировать).
5. UI: D-pad и кнопки не перекрываются оверлеями боя/подземелья
   (z-index), не заезжают под кнопку полноэкранного режима; подпись
   кнопки действия по экранам (опционально).
6. Память: `memory/000121-touch-dungeon-combat.md` — архитектура
   маршрутизации, семантика удержания в подземелье, маппинг
   тач→code в бою.

Тесты
-----
* Чистая функция маршрутизации: все комбинации активных экранов
  (карта / подземелье / бой / диалог) и приоритет бой > подземелье
  (tests/controls.test.js или новый файл, паттерн node --test).
* Маппинг тач→бой: каждое направление D-pad через resolveCombatKey
  даёт то же действие, что и соответствующая клавиша (move dx/dy,
  quickItem) — tests/combat-keys.test.js.
* Подземелье: onMove получает правильные (dx, dy) по направлениям
  (чистые функции + vm-песочница, паттерн tests/global-settings.test.js,
  — dungeon-ui/main не грузятся в node).
* `npm test` зелёный; ручная проверка в режиме `?controls=touch`:
  карта → подземелье → бой → выход, без клавиатуры.
