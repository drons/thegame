Случайные непроходимые клетки (препятствия) на поле боя
(подзадача 000030, направление 4)

(В ветке task/design задача была под номером 000035; при мерже в master
номер занят другой задачей — перепривязана.)

Цель: случайные непроходимые клетки на мини-карте боя; на их местах —
изображённые препятствия, «встроенные» в фоновый слой поля боя
(направление из 000030: «на их местах на фоновом изображении SVG должны
быть изображены препятствия»).

Состояние сейчас: поле 7×7 (ширина/высота настраиваются в createCombat;
игрок стартует в (floor(w/2), h−1)), препятствий нет. Юниты —
прямоугольники size w×h с якорем в верхнем левом углу (задача 000040,
мобы до 3×3): playerMove/stepToward/stepAway уже учитывают клетки
прямоугольников (unitAt/rectFree/unitDist); расстановка мобов —
placeUnits.

Ключевое проектное решение (зафиксировать в реализации и memory)
Формулировка 000030 допускает два прочтения:
  (а) препятствия запекаются в уникальный SVG-фон на каждый бой
      (процедурная генерация SVG по сиду) — дорого и избыточно;
  (б) фон — общий (000049), а препятствие — отдельный SVG-спрайт,
      рисуемый ПОВЕРХ фона в слое «фон/препятствия» (до юнитов).
      Визуально неотличимо от «запечённого», детерминировано,
      тестируемо, фон переиспользуется.
РЕШЕНИЕ ПО УМОЛЧАНИЮ: (б). Вариант (а) — только если (б) не даст
нужного вида (тогда — отдельная задача).

Работа (ядро, src/combat.js)
1. c.obstacles — множество непроходимых клеток, например Set('x,y').
   Генерация в createCombat ТОЛЬКО через c._rng (mulberry32) —
   детерминирована по сиду, как всё в бою.
2. Параметры в src/global-settings.js SETTINGS (стиль 000020):
   доля/диапазон препятствий, например combat_obstacle_min_frac = 0.10,
   combat_obstacle_max_frac = 0.20 (доля клеток поля).
3. Ограничения генерации:
   - не на старте игрока (floor(w/2), h−1) и не на ЛЮБОЙ клетке
     стартового прямоугольника любого моба (расстановка — placeUnits:
     крупные мобы (w·h > 1, до 3×3) ставятся первыми построчным
     обходом сверху, мелкие (1×1) — на якорях [1,3,5,0,2,4], строки
     0/1, со сдвигом, если якорь занят крупным);
   - достижимость: BFS из старта игрока по не-препятствиям (мобов
     игнорируя) должен достигать ХОТЯ БЫ ОДНУ клетку стартового
     прямоугольника КАЖДОГО моба (для 1×1 — его клетку) (иначе
     моб «за камнем» может стать недосягаемым/неподвижным);
   - при нарушении — перегенерация нарушенной клетки (с ограничением
     попыток, после — меньше препятствий).
4. playerMove: препятствие → { ok: false, reason: 'препятствие' }.
5. stepToward/stepAway: учитывать препятствия (тот же фильтр, что и
   юниты — rectFree) — мобы не «проходят сквозь камни» и не «прилипают»
   к ним бесконечно (если некуда — стоят, текущее поведение
   stepToward=false уже такое).
6. Экспорт c.obstacles в UI.

Работа (визуал)
7. Ассеты: assets/combat/obstacles/ — 2–3 универсальных SVG-спрайта
   препятствия в стиле сказочного фона (камень/валун/пни-кусты) —
   должны подходить ко всем 11 фонам (000049); выбор типа по клетке —
   чистая функция (например (x*3+y*5)%N). Пути — в allAssetPaths().
8. combat-ui.js: рисовать препятствия после фона и сетки, до юнитов
   (z-порядок: фон → сетка → препятствия → юниты → эффекты).

Файлы: src/combat.js, src/global-settings.js, src/sprites.js,
src/combat-ui.js, assets/combat/obstacles/*.svg,
tests/combat.test.js, tests/global-settings.test.js.

Тесты (tests/combat.test.js, дополнить; tests/global-settings.test.js —
новый параметр, «единый источник»)
* Детерминизм: один сид → одинаковый set препятствий; другой сид —
  (с высокой вероятностью) другой.
* Число препятствий в пределах [min, max] от площади поля.
* Нет препятствий на клетках старта игрока и на клетках стартовых
  прямоугольников мобов (у крупных 2×2/3×3 — все клетки прямоугольника).
* Достижимость: для каждого моба BFS-путь от игрока по
  не-препятствиям существует.
* playerMove в препятствие → { ok: false, reason: 'препятствие' };
  шаги игрока вокруг препятствия работают.
* Моб stepToward не встаёт на препятствие (сценарий: моб за камнем,
  игрок напротив — после хода моба моб жив и не «внутри» камня).
* Регрессия: существующие тесты боя зелёные (лог боя при фиксированном
  сиде может СМЕНИТЬСЯ — обновить снимки при намеренном изменении).

Ограничения
* 000040 (размер мобов) уже выполнен: мобы — до 3×3; препятствия
  остаются 1×1 клетка; генерация (п. 3) и движение мобов (п. 5)
  учитывают прямоугольники. rectFree (проверка хода моба) должна
  включать клетки препятствий в фильтр занятости.
* Фолбэк: без ассетов препятствия рисовать хотя бы как тёмный квадрат —
  непроходимость — правило ядра, а не только визуал.
* Желательно после 000049 (фон) — слой «фон+препятствия» тогда единый.
