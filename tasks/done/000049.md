Фоновые SVG-изображения поля боя по типу местности
(подзадача 000030, направление 3)

(В ветке task/design задача была под номером 000034; при мерже в master
номер занят другой задачей — перепривязана.)

Цель: несколько фоновых SVG-изображений поля боя — по каждому типу
местности, на которой начинается бой, + по каждому типу подземелья
(дungeon-бой тоже идёт через combatUI). Стиль — «высокодетальные SVG
в сказочном стиле» (SPEC.md, «Графика»), согласованный с существующими
текстурами тайлов (assets/tiles/*.svg).

Состояние сейчас: боевой canvas залит сплошным #0d1117 + серая сетка.

Множество фонов (11 файлов)
Бой на мировой карте начинается только на проходимых тайлах
(map.js PASSABLE: SAND, GRASS, FOREST, HILL, SWAMP — вода и горы
непроходимы, боя там нет):
  assets/combat/bg/sand.svg, grass.svg, forest.svg, hill.svg, swamp.svg
Бой в подземельях (dungeon.js DUNGEON_TYPES, в мире тайла нет):
  assets/combat/bg/cave.svg, crypt.svg, ruins.svg, drowned.svg, abyss.svg
Фолбэк (неизвестный тип / лоадер не готов):
  assets/combat/bg/plain.svg (нейтральный тёмный фон в духе текущего).

Работа
1. Создание 11 SVG-ассетов. Ручной или скриптовый генеринг (скрипт
   допустим, например scripts/gen-combat-bg.js) — решение на усмотрение,
   но стиль единый: сказочная 2D-мультипликация, палитра родная
   assets/tiles (TILE_BASE в sprites.js). Размер: мини-карта 7×7 клеток
   по 48 px = 336×336; рисовать с запасом (например 768×768) для
   чёткости на retina (canvas масштабируется). Тесселяция/рисунок фона
   не должен конфликтовать с сеткой 48 px (мягкая текстура либо период
   — кратный 48). В фон препятствия НЕ запекаются (см. 000050).
2. Выбор фона — чистая функция в src/sprites.js:
   combatBackground(bg) → путь SVG, где bg — один из
   { terrain: <TERRAIN> } | { dungeon: <DUNGEON_TYPES> } | {} (фолбэк).
   TERRAIN/DUNGEON_TYPES известны sprites.js (map.js уже зависимость;
   для dungeon — литералы или зависимость от dungeon.js — решить,
   но без циклов: проще key-строки 'sand'...'abyss' + fallback).
3. Все пути добавить в allAssetPaths() (sprites.js) — main.js загрузит
   их тем же spriteLoader автоматически.
4. Передача контекста в бой: combatUI.startCombat({ ..., terrain }) для
   мира (main.js уже передаёт tile, terrain = tile.terrain) и
   combatUI.startCombat({ ..., dungeonType }) для подземелья
   (startDungeonCombat: dungeonState.dg.type). Ядро combat.js не менять
   (фон — чисто визуальное, в опции UI).
5. Отрисовка в combat-ui.js: drawImage(фон) первым слоем, поверх —
   сетка (цвет линии приглушить/прозрачность — решение на глаз, чтобы
   сетка читалась на фоне), дальше препятствия (000050) и юниты.
   Фолбэк: текущий сплошной фон.
6. Каталог assets/combat/ новый; для SVG schema.json не требуется
   (данных нет), но в README задачи/отчёте зафиксировать состав.

Файлы: assets/combat/bg/*.svg (11 новых), src/sprites.js,
src/combat-ui.js, src/main.js, (опц.) scripts/.

Тесты (tests/sprites.test.js, дополнить)
* combatBackground: каждый проходимый TERRAIN → свой файл; каждый
  DUNGEON_TYPES → свой файл; неизвестный/пустой → plain.svg.
* allAssetPaths() содержит все 11 путей; файлы существуют на диске
  (паттерн теста 'tileFrames: файлы существуют' для тайлов).
* Старые тесты — зелёные.

Ограничения
* Ассеты — статичные SVG (Lottie не требуется для фона; анимация фона —
  отдельная задача при желании).
* Не трогать генерацию мира (map.js) — детерминизм карты не меняется.
* Порядок: эту задачу разумно делать до 000047 (спрайты) и 000050
  (препятствия) — они рисуются поверх фона.
