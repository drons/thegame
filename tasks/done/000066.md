«в город можно зайти как в подземелье, движок тот же») строится
поверх этой задачи.

Состояние сейчас (факты)

src/sprites.js) — два слоя и общее состояние:
* WebGL-canvas #game — цветные квады тайлов через
  orthoMatrix(zoom, cam.x, cam.y) (main.js ~130). WebGL в main.js
  обязателен: без него игра не стартует.
* 2D-canvas #sprites поверх — текстуры: тайлы (TILE_FRAMES +
  frameIndex), постройки, группы мобов, Флогистон (drawSprites,
  main.js ~863).
* Общие cam/zoom: zoom = G.ZOOM_START (80 px/тайл), диапазон
  G.ZOOM_MIN..G.ZOOM_MAX = 4..128 (src/map.js ~466); колесо — на
  canvas #game, ×1.2 (main.js ~574).
* Камера: G.cameraStep(cur, target, dt, G.CAM_TAU_MS≈74.7 мс)
  (src/motion.js) — fps-независимое экспоненциальное сглаживание.
* Видимая область: G.visibleTileRange(camX, camY, w, h, zoom, margin)
  (src/map.js ~486) — рисуется только она.
* Проекция «мир → экран» одна для обоих слоёв:
  x = W/2 + (tx − cam.x)·zoom,  y = H/2 + (ty − cam.y)·zoom.

Проектное решение «по умолчанию» (зафиксировано)
* «Тот же движок» = та же математика камеры/зума и те же слои, а НЕ
  переписывание: у подземелья НЕТ WebGL-слоя (цветные квады не
  нужны — весь визуал SVG), но canvas, зум, камера и проекция —
  мировые: zoom px/клетку = мировому zoom (px/тайл) — клетка
  подземелья масштабируется так же, как тайл мира.
* ОДИН общий zoom: подземелью передаётся мировое значение
  (dungeonUI.start({ ..., zoom })); колесо ПО ВЕРХУ оверлея меняет
  тот же zoom (та же математика ×1.2, те же клампы 4..128) — мир и
  подземелье не «расходятся»; HUD-строка «Масштаб: Xpx» (hudUpdate,
  main.js ~922) остаётся корректной без изменений.
* Размещение: канвас подземелья — весь вьюпорт (window.innerWidth/
  innerHeight, как #game/#sprites; ресайз — в цикле), фон —
  непрозрачный тёмный (цвет «за пределами подземелья» #0a0d12):
  мир позади оверлея больше не проступает (решение по
  полупрозрачности: непрозрачный фон, а не скрытие мира).
* Камера: cam в координатах клеток (дробная), цель — центр клетки
  игрока (x+0.5, y+0.5 — как cam/тайл в мире), сглаживание
  G.cameraStep + CAM_TAU_MS; НОВОЕ для конечной сетки — кламп камеры
  к границам подземелья (мир бесконечен, такого механизма нет);
  краевой случай «вьюпорт больше подземелья» (35 клетки × 4 px =
  140 px при ZOOM_MIN на широком экране): подземелье центрируется,
  снаружи — тёмный фон.
* rAF-цикл (паттерн src/combat-ui.js: nowMs/raf/caf-гарды, старт —
  start, стоп — close) — нужен для камеры и для следующих слоёв:
  анимации спрайтов (000067) и глейда (000068).
* Рендер только видимых клеток (G.visibleTileRange) — всю сетку
  35×35 не рисуем (производительность: при zoom 80 вьюпорт ~26×16
  клеток — сотни drawImage/кадр, сопоставимо с миром;
  spriteLoader.image — дешёвый Map.get).
* Общность движка: рендерер принимает opts/state (размеры, визуал
  клетки, сущности, колбэки); семантика подземелья (мобы/сундуки/
  выход) — в клейке main.js, а не хардкодом в dungeon-ui.js.
  Зафиксировано: 000052 выполняется ПОСЛЕ этой задачи (иначе база —
  старый dungeon-ui).
