## Решения (зафиксированы, см. memory)

1. **CITY_CONTENT_CONST = 0x434f4e54 — новая соль + golden-пин**
   (прецеденты 000103/000104). GLOBAL_SEED не смешивается (cities.js
   не тянет map.js; дублировать литерал нельзя — аудит 000053).
2. **Сид — от ПОЗИЦИИ, wealth НЕ входит**: один якорь → один
   rng-поток на все wealth; город НЕ сидится totalXp (в отличие от
   generateDungeonContents).
3. **count = мин_постройки + wealth** — без верхнего лимита;
   ассортимент = топ-(1+wealth) по (доля убыв, id растущ).
4. **Таверна (44) — минимум 1, строится ПЕРВОЙ** (тип без rng): найм
   000065/000078 в городской таверне. Исключение — хутор
   (fp1, buildings: []): противоречие разрешено 000102/000104
   нулём минимума.
5. **ВСЕ внутренние постройки 1x1** — включая Арены (id 7, 3x3 в
   каталоге): размер каталога внутри города НЕ уважается (scope;
   2x2/rectangular — решение в 000105/000107/000110 при
   необходимости).
6. **Достижимость — строгий инвариант, минимум — best-effort**:
   BFS-проверка КАЖДОЙ попытки размещения; graceful-стоп при
   нехватке валидных мест (у деревни ~50% якорей → 1 постройка).
7. **cityRecord — source of truth (000053)**: pool и квоты только из
   особых_параметры; текст задачи по id типов устарел (реальный пул
   = КЛЮЧИ долей: 1/7/10/25/44; 7 и 8 — школы_навыков, 25 —
   дом_npc, 44 — прочее).
8. **Результат — plain** (JSON-сериализуемо — 000109); layout НЕ
   мутируется (000105 кеширует layout).
9. **Чистота**: без DOM/totalXp/глобального состояния; vm-песочница
   без dungeon.js; единственный require — ./perlin.js (000104).
