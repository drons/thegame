## Что сделано

1. **src/building-effects.js** (НОВЫЙ, ~190 строк) — чистый UMD-модуль:
   * **REЕСТР EFFECTS = {}** (в этой задаче ПУСТ — подзадачи 000074+
     добавляют только СВОИ записи): id → `{ имя, разВДень?,
     available?(state), apply(state) → { ok, message? } }`.
   * `buildingActions(building, npc, state)` → `[{ id, имя, доступен,
     reason? }]` — ПЕРВЫМ «Диалог» (id 'dialog', если npc != null),
     затем эффекты. Связка «постройка → эффекты»: массив
     `особые_параметры.эффекты` (порядок из каталога) ИЛИ, если
     массива нет, запись `EFFECTS[String(building.id)]` (1-к-1:
     камень 40, обелиск 42, круг 43). Чистая: снимок state не
     мутирует.
   * `available?(state)` — НЕДНЕВНАЯ доступность (ревью раунда 2:
     дыра — был задокументирован, но не опрашивался): истина (не
     строка) — доступно; false/null/undefined/'' — reason
     «недоступно»; непустая строка — reason (пример: круг без пары
     «молчит»). Опрашивается ДО лимита раз-в-день.
   * **hasDailyLimit(building, effectId)** — лимит ТОЛЬКО по ЯВНЫМ
     флагам (ревью раунда 3 — implicit «есть apply → лимит» УБРАН,
     контракт плана 000064 «фонтан: исцеление лимит / монета — нет»):
     каталог `особые_параметры.раз_в_день` (boolean, побеждает,
     включая явное false) либо запись реестра `разВДень === true`.
     Без флага — эффект повторяем в тот же день (тесты A18, B12).
   * `readOncePerDay(save, 'x,y:effectId')` — fail-open (000029),
     прототип-безопасно; координаты целые, могут быть отрицательными
     (тест A11). `canUseToday` — day.js лениво из globalThis.Game
     (UMD-ловушка 000038), fallback `last !== day`.
   * Взаимных require в момент загрузки НЕТ (тест A14, прецедент
     000053); в vm-песочнице без других модулей работает (A17).
