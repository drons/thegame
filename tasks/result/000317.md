# Результат 000317 — расширение ассортимента лавки уровнем постройки

## Итог

Цель достигнута: ассортимент магазина городской постройки
детерминированно расширяется уровнем (L=1..7), та же сид-цепочка,
0 новых RNG-источников; L=1 — бит-в-бит прежняя генерация; цены
улучшением вне существующих wealth-множителей не меняются; расширение
видно на экране «Магазин» при fresh-входе (UI data-driven, 0 правок).

Контракт правила/уровней/сид-цепочки и точки кода —
memory/000317-shop-assortment-upgrade.md. Раунд 1 (аудит-фикс):
⊇-контракт восстановлен на fallback-классе (пустой поток × expansion).
Раунд 2 (аудит-фикс): ⊇-контракт восстановлен на ШАГАХ БОГАТСТВА
effWealth-цепочки города (гарантированная строка kindPool[0] при L≥2 —
см. «Раунд 2» ниже).

## Реализация

- src/items.js — makeShop(x, y, buildingType, wealth, level) — 5-й
  факультативный аргумент; при L≥2: union базовых генераций потоков
  w = wealth..max(0, wealth−floor((L−1)/2)) (тот же seed, mulberry32
  перезапускается — multi-stream, не новая энтропия; пул потока = пул
  богатства потока) + expansion: top-(L−1) пула видов лавки по
  хэш-порядку derived-сида (hash2(x,y,SHOP_EXPAND_SEED)^(bt+1),
  fnv1a(id); количества — соль SHOP_EXPAND_QTY_SALT); слияние — max;
  level/wealth ни в один сид не входят. L≠целое≥2 → прежняя генерация;
  fallback «магазин не пуст» — L=1 бит-в-бит; при L≥2 ДО expansion
  безусловно мержится гарантированная строка kindPool[0] количество 1
  (раунд 2; условный вариант раунда 1 терял ключ на шаге effWealth;
  ⊇-стражи T7+T8).
- src/cities.js — makeCityShop передаёт пятый аргумент L (из реестра
  shopLevels, доставка syncShopLevels: вход в город / upgrade /
  demolish — 000222-механизм без изменений); дифф — ровно одна строка
  вызова (комментарий D-детерминизма откатан в раунде 2: в src/
  комментариев не пишем, контракт — в memory).
- src/ui.js / src/ui-tab-shop.js — 0-diff (экран data-driven из
  shop.stock); тайминг видимости — канон 000222 (ин-визит сток не
  регенерится, fresh-вход/респаун — да).
- Сейв v1 — миграции нет (level уже persistent; сток transient 000109).

## Раунд 1 (аудит-фикс)

- БЛОКЕР (аудит): fallback × expansion (items.js:1574-fallback ×
  1552-1559-union в префиксере) — при пустом потоке (достижимо при
  богатстве 0/1 на малых пулах видов) L1 = fallback {pool[0].id:1},
  а непустой expansion при L≥2 глушил fallback → ключ pool[0] ТЕРЯЛСЯ
  при улучшении (контрпример (1082,5771,bt2,w0): L1={minor_healing:1}
  → L2={bread:1}; строка товара исчезала с экрана после апгрейда;
  частота ~0.035% координат bt{0,1,2,3,11}×w{0,1}). Фикс: fallback
  применяется и на пути L≥2 при пустых потоках — `merge(pool[0].id,1)`
  ДО expansion (items.js:1561); L=1 бит-в-бит не затронут (строка
  1575 цела), 0 новых RNG-вызовов, сид-цепочка не сдвинута.
- Тест: T7 — нога на координате класса (1082,5771,bt2,w0): L1 — одна
  fallback-строка, «stock(L) ⊇ fallback-L1» для L=2..7; свип-страж
  bt{0,1,2,3,11}×w{0,1}×сетка 24×24: stock(L) ⊇ stock(1) на всех
  координатах (L=2,3,5,7) и непустота fallback-класса в свипе (точки
  перепикинуются при росте каталога — прецедент стражей T2).
  Мутация M9 (убрать фикс-строку): красная ТОЛЬКО T7 (6 pass/1 fail,
  «пропало: [minor_healing]» на L2), T1–T6 зелёные — подтверждена
  слепая зона префиксера.
- CHANGELOG: буллет уточнён — «после обновления стока
  (перегенерация при заходе/респауне)» вместо «(новый заход в город)»

## Раунд 2 (аудит-фикс)

- БЛОКЕР (аудит): ⊇-контракт нарушался на ШАГАХ РОСТА effWealth
  (L≥2 при поднятом cities богатстве): условный fallback
  «потоки пусты» (фикс раунда 1) неинвариантен по L — на уровне N
  строка pool[0] попадала через fallback (потоки пусты), на N+1
  effWealth растёт, добавленный поток непуст и пропускает pool[0],
  expansion top-(L−1) его тоже не берёт → КЛЮЧ ИСЧЕЗАЛ при улучшении.
  Публичные контрпримеры (минимальная нога — цепочка
  makeShop(x,y,bt,min(3,w+floor((L−1)/2)),L)): (0,1,bt2,w0),
  (−34,48,bt2,w0), (−54,51,bt2,w0), (−53,10,bt11,w1) — minor_healing
  терялась L2→L3; брутфорс окна 120×120×bt{0,1,2,3,11}×w{0,1} —
  32 события потери (теряемый ключ всегда minor_healing — первый
  предмет пула видов bt2/bt11).
- Фикс (src/items.js:1561): при L≥2 ДО expansion безусловно мержится
  гарантированная строка `merge(kindPool[0].id, 1)` — первый предмет
  пула ВИДОВ (не pool(wealth)! — при w3 pool=allItems давал бы
  wealth-зависимый ключ), количество 1 через max-слияние. Множества
  union-потоков и E(L) монотонны по L априорно (каждый поток S(w) —
  фиксированная функция seed, множество потоков с L растёт), поэтому
  unconditional-строка делает ⊇/qty-монотонность airtight на любом
  effWealth-пути. L=1 не затронут бит-в-бит (строка 1575 цела);
  0 новых RNG-вызовов; сид-цепочка не сдвинута.
