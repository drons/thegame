# Результат 000352 — BUG: экранные кнопки движения выделяются как текст

## Диагноз

Экранные кнопки движения — ровно D-pad: `div.tc-dpad` + четыре
`span.tc-arrow` с текстовыми глифами ▲▼◀▶ (src/ui.js, схема 'touch';
в 'keyboard' экранных кнопок движения нет — 000123). Выделение давало
отсутствие `user-select:none` в каскаде: default mousedown (мышиный
drag-жест D-pad), double-click и long-press НЕ подавляются существующим
`preventDefault()` на `pointerdown`. «Некоторые кнопки» = жестозависимость
(drag/двойное нажатие), а не конкретные направления. Сверка «заодно»:
`.tc-action` [E]/[I]/«Отряд» и `.spellbook-oc-btn` — содержимое только
`<img>` (выделять нечего), `.combat-placebar-btn` уже имел
`user-select:none` (прецедент), `.fs-btn`/боевые кнопки — вне scope ТЗ.
Выделяемым оставался только D-pad — ровно scope ТЗ.

## Фикс

index.html, правило `.tc-dpad`: **+1 строка `user-select: none;`**
(без `-webkit-` — house-style и прецедент placebar; свойство
наследуется ⇒ один механизм покрывает все 4 стрелки и будущий текст
D-pad, без дублей на кнопку). src/* не тронут; pointer-обработчики,
setPointerCapture, touch-action — инертны к user-select.
sync-зеркала не затронуты: sync:check = 0 («синхронно»).
