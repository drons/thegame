## Почему задача разделена

* В задаче явно: «пока код не пишем — только создаём подробные
  подзадачи и дополняем SPEC.md» — это исследовательская (мета-)
  задача; реализация — объёмная (данные, ядро отряда, боевой
  фреймворк, Эфир, 3 UI, сейв, интеграция в цикл).
* По правилам tasks/CLAUDE.md: слишком большая задача делится —
  дочерние в pending со ссылкой «Родительская: 000065», в результате
  родительской — ссылки на дочерние.
* Высокое пересечение с параллельными pending: combat.js правят
  000045/000046, ui.js/main.js — 000051/000052, assets/npc —
  (пока не трогают), taверна-поток — 000064 — каждая подзадача
  мержится отдельно, с ребейзом на актуальный master.

## Ключевые проектные решения (зафиксированы в SPEC.md «Спутники» и в подзадачах)

1. **ЕДИНЫЙ фреймворк «союзные юниты»** (side 'ally'): Эфир и
   наёмники — одна модель. Приоритеты задаёт это решение:
   фреймворк (000080) → Эфир (000081) → найм (000079/000083).
2. **Эфир — постоянный союзник** (решение по 000035): всегда на поле,
   свой независимый пул навыков (100% боевого опыта), не умирает
   навсегда (реген 100% HP), без жалованья/лояльности. Файлы
   000034/000035 (master/pending) — НЕ менять, только ссылаться;
   данные пула Эфира изолированы в src/efir.js — подзадачи 000035
   правят только этот модуль.
3. **Найм**: NPC каталога assets/npc с новым опциональным полем
   `найм` + новое действие диалога «найм»; найм — в таверне
   (building 44; таверна id 22 — школа Харизмы, на карту не
   генерируется — НЕ использовать); отряд ≤ 3 (max_companions).
4. **Экономика**: разовый контракт + жалованье в день при смене дня
   (точка — clock.onDay, main.js ~425); нет золота → −20 лояльности,
   уход ≤20 — верно, 21…40 — 50%; увольнение — без возврата, повтор
   возможен; гибель — окончательна (dead_mercs в сейве).
5. **Лояльность**: 0…100, старт 50+Харизма (cap 100), +2 за оплату;
   отказ при найме: 30% − 2%×Харизма − 5%×Артист (min 0) — связь
   Артиста зафиксирована в SPEC «Навыки»→«Харизма».
6. **Бой**: союзники — отдельные юниты с ИИ (ход + атака по роли;
   поддержка лечит самого раненого, включая игрока); очередь
   игрок → союзники → мобы; гибель ≠ поражение; Предводитель —
   подключение существующей companionMoraleBonus (player.js:230,
   +5%/ур. — НЕ смешивать с ролью 'leader' вражеских мобов).
7. **Опыт**: игрок 100%, выживший спутник — companion_xp_share (0.5);
   спутники качаются сами (статы по уровню, навыки фиксированы из
   каталога, очков нет); практика (000013/000041) — только навыки
   игрока (v1, зафиксировано в 000082); Эфир вне механизма (000081).
8. **Сейв**: неломкое расширение v1 без миграции (000031) +
   «призрак»-правило (000029) — битый сейв не роняет игру.
9. **Детерминизм**: нового «мирового» rng НЕ вводится — все новые
   случайности (отказ найма, уход) — seed = perlin.hash2(day, npcId)
   (mulberry32 есть в perlin.js), воспроизводимо (000079).
10. **Данные наёмников живут в записи NPC** (не в постройке) —
    переживут Cities-реворк 000052; требования диалога (`требования`:
    харизма/навык) — механизм доступа, новую систему проверок не
    изобретать (паттерн Оратора).
