## Архитектура решения

1. **index.html `.char-panel`** — top/left/right/bottom = 0 (лондхенды
   сохранены — тест ui-panel парсит keys, `inset:0` не used); комментарий
   блока переписан.
2. **Скоуп-оверрайды** `.char-panel .cp-section/.cp-table/.cp-items` — в зоне
   существующих скоуп-правил `.char-panel .cp-tip*` (ПОСЛЕ глобальных баз —
   first-match парсеры пинов build-menu-layout/storage-000313 резолвят базу).
   Глобальные правила байт-в-байт: их читают оверлеи NPC/крафта/хранилища.
3. **Кнопка FS — вариант (а) ТЗ**: `body.char-panel-open .fs-btn { display: none; }`
   (сразу после `.fs-btn:hover`) + токен на `document.body`, который пишет
   `markPanelOpen(on)` — хук ОДНОЙ СТРОКОЙ сразу после записи
   `panel.style.display` в `playerUI.toggle()` (ЕДИНСТВЕННАЯ точка смены
   видимости; все входы/выходы — KeyI main.js:2450, тач-[I], teardown боя,
   Esc-диспетчер — идут через неё). Строковая запись className (classList в
   DOM-стабах нет — tipSetDown-паттерн), change-guard идемпотентность,
   null-guard body, preserve чужих токенов.
   - (б) «поверх оверлея» отклонена: требует правки frame-блока main.js
     (вне SCOPE) и перекрывает строку контента («вырезание» — запрещено ТЗ);
   - (в) «контрол в заголовок» отклонена: вне панели кнопка исчезает
     (регрессия 000017/000256) либо ломает пин «в body ровно одна .fs-btn»
     (fullscreen-button-overlay FS-2) и требует main.js.
   - display:none снимает и z-конфликт 000206/000256 (в городе/подземелье
     панель и кнопка оба получают inline z-25; CSS скрывает кнопку при любом
     inline zIndex, main.js display не пишет никогда).
   - Риск ТЗ «недоступность выхода из FS жестом мыши» принят: панель [I]
     закрывается [I]/[Esc]/кнопкой, кнопка возвращается мгновенно; Esc
     браузера выходит из FS, иконка синхронится fullscreenchange-подпиской
     (основание — memory/000377-panel-fullscreen.md).
