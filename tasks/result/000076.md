## Решения (зафиксированы в memory и тестами)

1. **Бафф — ПАРАМЕТР формул, не поле персонажа** (контракт ТЗ):
   `derived()` не трогается; новый объект персонажа не добавляется
   (прецедент `_lastUnkillDay` — не в сейве, отвергнут); `buffMods`
   — чистый параметр createCombat + множитель/вычет в формулах;
   бит-в-бит без баффа (×1/−0, ноль новых c._rng).
2. **apply — чистый, по снимку**: новый массив благословений
   (grantBuff) — в r.buffs; живой массив меняет main.js общим хуком
   ПЕРЕД saveNow. Любое «состояние», возвращённое apply, — общий
   паттерн (не храм-специфично).
3. **Лимит раз-в-день — из КАТАЛОГА** (000053/000043): 36/38 —
   есть, 37 — нет (подсказка бесплатна).
4. **«Сон» — детерминирован**: окно side×side, центрированное на
   храме (ревью раунд 1), Чебышёв + лекс. тай-брейк, без RNG;
   «не видно» — сообщение, не ошибка.
5. **Роутер по buildingId** — ОБЩАЯ линия 000074/000075/000077:
   первый смерженный задаёт ханк, остальные адаптируют при ребазе
   (у 000075 — то же выражение в 4 местах; у 000076 —
   buildingRecForTile).
6. **СНИМОК расширяется map'ом** (read-only ссылка) — сознательное
   отклонение от «снимок = копия» (000071); альтернатива (ленивый
   Game-хук карты) отвергнута.
7. **Бафф действует во ВСЕХ боях дня** (мир/подземелье/отладочный) —
   одна точка currentBuffMods().
8. **NPC-схема не тронута** (assets/npc/schema.json, 000065):
   благословение — действие buildingUI, не опция диалога; стоки/
   диалоги Элдиры не меняются (npcStocks по id NPC — поведение
   текущее, не «чинить»).
