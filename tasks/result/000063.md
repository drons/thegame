# Отчёт: задача 000063 — базовая скорость передвижения (×1/3) в глобальных настройках

Статус: выполнено. Тесты: 505 → 512 pass, 0 fail.
Коммиты: 1b54a86 (красные тесты), 43edf63 (реализация).
Память: memory/000063-base-move-speed.md.

## Суть

После 000033 (плавное передвижение) движение по глобальной карте стало
плавным, но «очень быстрым». Задача: вынести базовую скорость
передвижения в глобальные настройки и уменьшить её в три раза.

## Что сделано

1. **src/global-settings.js** — новый ключ `move_interval_ms =
   140 * 3 = 420` мс (базовый интервал шага; ранее хардкод
   `MOVE_INTERVAL_MS = 140` в main.js). Скорость = 1/интервал, значит
   «в три раза медленнее» = интервал ×3. НЕ 140/3 — это ускорение.
2. **src/main.js**:
   * `MOVE_INTERVAL_MS` читается из
     `Game.GlobalSettings.SETTINGS.move_interval_ms` с guard'ом
     (конечное и > 0) и fallback 140 (деградация без settings-файла —
     старое поведение, паттерн 000033 с G.createMover). Старое
     объявление `const MOVE_INTERVAL_MS = 140` удалено.
   * Хелпер `stepIntervalMs()` =
     `G.moveIntervalMs(MOVE_INTERVAL_MS, derived(hero).moveSpeedMult)` —
     ОДИН источник интервала для цикла шагов (гейт `now - lastMove >=
     stepMs`) и окна анимации walk/idle в drawSprites.
   * Окно walk/idle: фикс `now - lastStepAt < 260` заменён на
     `now - lastStepAt < G.walkWindowMs(stepIntervalMs())` (guard,
     fallback 260).
3. **src/motion.js** — новая чистая функция `walkWindowMs(stepMs) =
   max(260, stepMs)` (экспортирована в UMD-API). Окно анимации
   масштабируется от интервала шага: фикс 260 мс подобран под старый
   интервал 140 мс и при базовых 420 давал 260 мс walk + 160 мс
   ЗАМИРАНИЯ в idle за шаг при удержании клавиш (рваная ходьба — откат
   ощущения 000033). Окно не короче 260 (старое ощущение) и не короче
   самого шага (при удержании клавиш — всегда walk). Мусор (NaN,
   нечисло, <= 0) — 260, без выброса.
4. **SPEC.md** «Карта мира» — параметр `move_interval_ms` (по умолчанию
   420 мс) настраивается, единый источник — src/global-settings.js;
   «Ловкий шаг» (Ловкость) уменьшает интервал, но не ниже минимального.

## Решения и подводные камни (см. memory)

1. **Ловушка «×1/3»**: скорость = 1/интервал, «в три раза медленнее» —
   это интервал ×3 (420 мс), а не 140/3 ≈ 47 мс (это ускорение,
   упирающееся в MIN_MOVE_INTERVAL_MS = 60).
2. **Минимальный кламп 60 мс должен оставаться ниже базы 420** —
   иначе «Ловкий шаг» не работает (зафиксировано тестом).
3. **Окно walk/idle — не константа**: фикс 260 мс был подобран под
   интервал 140; при любой смене базы окно должно следовать за шагом
   (walkWindowMs), иначе герой замирает в idle посреди шага.
4. **Единый источник базы — global-settings.js** (паттерн 000020):
   будущая настройка/перенастройка скорости — только в SETTINGS,
   main.js и motion.js — потребители.
