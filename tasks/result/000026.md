# 000026: размеры построек, алгоритм размещения без пересечений, вход

Статус: выполнено. Тесты: 200 → 213 pass (+13: buildings +8, map +5;
один старый тест обновлён под стены).

## Что сделано

* **Размер — в JSON описаниях** (`assets/buildings/*.json` +
  schema.json): необязательные поля `размер` {ширина 1..5, высота
  1..4} и `вход` [dx, dy] (2 целых 0..4, additionalProperties=false).
  Крупные постройки: Арена, Монастырь, Ратуша, Храм солнца — 3x3,
  вход [1,2]; Башня мага — 2x2, вход [1,1]; Рунический камень —
  явный 1x1, [0,0] (пример). Остальные 44 — 1x1 по умолчанию.
  JS-фолбэк src/buildings.js синхронизирован (тест deepEqual JSON↔JS).
* **Чистые функции размещения** (src/buildings.js, экспорт):
  `buildingSize`, `buildingEntranceRel` (зажим входа в размер),
  `sizeChain(w, h)` — цепочка уменьшения
  (5x4 → [[5,4],[3,3],[1,1]]), `placeBuilding(b, x, y, isFree)` —
  пробует цепочку, принимает первый размер, все w×h тайлы которого
  свободны по isFree; null — не влезло даже 1x1.
* **Генерация** (src/map.js): постройка «живёт» на якорном тайле
  (правило порога не изменилось) и занимает прямоугольник от якоря.
  Тайл «свободен», если проходим и не занят постройкой с
  лексикографически РАНЬШИМ якорем — порядок «раньше/позже» делает
  размещение детерминированным и без пересечений: поздняя постройка
  уступает ранней, сжимаясь по sizeChain (или исчезая). Кэш
  развёртывания якорей в closure createMap.
  В браузере каталог подхватывается лениво из Game (buildings.js
  грузится после map.js в index.html); в node — require.
* **Семантика тайла** (назад-совместимо для main.js):
  * новые поля `inBuilding`, `isEntrance`, `buildingAnchor`;
  * `hasBuilding` — только на входном тайле (торговля/пещера/
    диалог работают там же, что и раньше для 1x1);
  * `passable` — стены (footprint без входа) непроходимы;
  * `hasMobGroup` — не рождается на тайлах постройки;
  * `building`/`buildingWealth` — едины на всех тайлах постройки.
