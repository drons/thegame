## Решения и отклонения от файла задачи

1. **Выбран рекомендуемый вариант (а)** — каталог = источник
   функционального ассортимента: `виды` = id из ITEM_KINDS, а не
   русская проза. Проза остаётся описательной для игрока. Таблица кода
   не удалена, а вынесена в `SHOP_KINDS_FALLBACK` — vm-песочницы
   combat-ui/dungeon-ui грузят items.js БЕЗ buildings.js; без фолбэка
   торговля в песочнице умерла бы.
2. **НАХОДКА: текст задачи «map_index 0..4» НЕВЕРНО**: map_index 4 —
   Арена (id 7, школа_навыков), не магазин. Таверна — map_index 11
   (запись 000044), категория «прочее», прозы `ассортимент` у неё нет.
   `виды` добавлены ровно 5 записям: id 1, 2, 3, 4, 44; Арена без
   `виды` (закреплено тестом).
3. **Лавка странника (id 5)** — без map_index, проза
   «вьюки/повозки/верёвки/факелы» несовместима с ITEM_KINDS — `виды`
   НЕ вводятся (guard их отклонил бы); товары — NPC-торговля
   (assets/npc), не в скоупе.
4. **Детерминизм торговли сохранён**: значения видов не изменились,
   источник — каталог; golden-стоки makeShop (6 снимков, вкл. seed'ы)
   до и после идентичны.
5. id не перенумерованы, сейв v1 не поднимался; универсам
   (богатство 3) — смесь всего, как было.

## Подводные камни (для будущих задач, см. memory)

* **Ленивое чтение**: в index.html items.js (297) грузится ДО
  buildings.js (298) — каталог берётся из root.Game в МОМЕНТ ВЫЗОВА;

* **Таверна** — категория «прочее» в каталоге, но магазин в торговле:
  при работе с `виды` ориентироваться на map_index, а не на категорию.
* Новые «картовые» магазины обязаны иметь валидные `виды` — иначе
  shopKindsFor вернёт null (не магазин) даже для известного типа.
* Проза `ассортимент` — только для игрока; код, читающий её, —
  дублирование (аудит 000053).
