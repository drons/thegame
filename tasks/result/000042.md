## Что сделано

* **src/map.js** — createMap экспортирует `buildingAt(ax, ay)`:
  read-only O(1)-обёртка над внутренней мемоизированной
  `buildingAtAnchor` — та же запись {anchor, type, x, y, w, h,
  entrance, wealth}, что РАЗМЕЩАЛА постройку в мире, или null.
  Источник геометрии footprint'а — ОДИН (запись размещения), а не
  скан по tileAt: скан «вправо/вниз» без проверки равенства
  buildingAnchor зальётся чужой соседней постройкой (ложные 2x1/1x2 —
  случай закрыт тестом на плотной синтетике A=255).
* **src/main.js (только drawSprites)** — по-тайловый цикл frameTiles
  разбит на ТРИ прохода с глобально согласованным порядком слоёв:
  (1) текстура тайла + декорации, (2) постройки, (3) мобы; Флогистон —
  как был, после всех проходов. Разбить пришлось, потому что w×h-
  прямоугольник «по тайлам» в старом едином цикле невозможен:
  текстуры СОСЕДНИХ тайлов footprint'а (каждая итерация цикла рисует
  свой тайл) перерисовали бы часть прямоугольника.
  * Проход 2 собирает якоря построек из видимых тайлов в Set за кадр
    и рисует каждую постройку ОДИН раз: `drawImage(spr,
    worldToScreen(ax, ay), w·zoom, h·zoom)` — вместо 1x1 на (вход +
    0.04·zoom, 0.92·zoom). Якорь сам может быть за краём окна (запас
    зума < 3), поэтому Set строится по якорям ВИДИМЫХ тайлов, а не по
    якорным тайлам.
  * Проход 1: на тайлах-стенах (`inBuilding && !isEntrance`)
    декорации НЕ рисуются — условие 000039 `if (showVisuals)` стало
    `if (showVisuals && !(t.inBuilding && !t.isEntrance))`. Вход
    декорации СОХРАНЯЕТ (там игрок взаимодействует с постройкой).
  * typeof-гард: устаревший map.js без `buildingAt` — фолбэк-скан
    прямоугольника вправо/вниз по tileCache, но с ПРОВЕРКОЙ РАВЕНСТВА
    buildingAnchor (одного inBuilding мало); якоря нет — 1x1.
  * НЕ тронуты: tryMove/mover/motion (000033, 000063), WebGL-маркер
    входа (золотой квадрат на входном тайле остаётся — теперь под 2d-
    спрайтом), магазин/пещера/диалог NPC (hasBuilding — по-прежнему
    только на входе), hudUpdate.

## Решения

1. **Источник геометрии — запись размещения** (`buildingAt` →
   `buildingAtAnchor`), а не скан по tileAt: у постройки один
   владелец (якорь), запись мемоизирована, скан без проверки якоря
   зальётся соседом. Скан оставлен только как фолбэк под устаревший
   map.js — и ТОЖДЕ с проверкой равенства якоря.
2. **Три прохода вместо единого цикла**: постройка рисуется не «по
   тайлам», а один раз на якорь; иначе текстуры соседних тайлов
   footprint'а съели бы прямоугольник. Порядок слоёв закреплён
   тестом (текстура < декорации < постройки < мобы < Флогистон).
3. **Декорации: одна строка-условия в блоке 000039** (как
  обещалось в memory/000039): `!(t.inBuilding && !t.isEntrance)` —
  стены чистые, вход декорирован.
4. **Якоря Set'ом за кадр** (ключ «ax,ay»): одна запись на
   постройку, не 9; якорь может быть вне окна — рисуем по якорям
   видимых тайлов.
