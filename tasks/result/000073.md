## Ключевые решения (зафиксированы в memory и тестами)

1. **Ловушка детерминизма — `% 13` НЕ менять** (зафиксировано в задаче):
   новые map_index перераспределили бы слот почти на всех тайлах
   (golden tileAt, сейвы). Подтипы — вторым хэшем ВНУТРИ слотов 8..12;
   слоты 0..7 — buildingId null («как есть»). Кандидат «все слоты
   получают id базовой» отвергнут (минимум изменения мира).
2. **Слот 9 — сознательное изменение геймплея**: ~20% тайлов (развалины
   48) перестали быть входами в подземелье. Гард maybeEnterDungeon —
   строго `=== 48` (не `!== 31` — при buildingId null вход обязан
   сохраняться), HUD-хинт подавлен ПАРОЙ с гардом.
3. **Геометрия инвариантна**: footprint/вход/wealth/проходимость — по
   БАЗОВОЙ записи слота; сейвы — валидация по проходимости, инвариант
   сохраняется.
4. **Спрайт подтипа = спрайт СВОЕГО СЛОТА** (buildingSprite(rec.type));
   новых SVG в этой задаче НЕТ (визуальное различение — отдельная
   дизайн-задача).
5. **shopKindsFor(t.building)/setShop — СЛОТОВЫЕ** (решение 000073:
   семантика района — у колодца/фонтана (слот 11) подсказка про
   торговлю и вкладка магазина остаются, как до задачи).
6. **Ловушка 000103: «buildingId != null ⇒ город» СЛОМАНО 000073** —
   город опознаётся теперь по `inBuilding && building ===
   BUILDING_TYPES.NONE` (у тайла БЕЗ постройки building тоже NONE —
   предикат обязан включать inBuilding). Переопределены: scanCityGroups
   и 7 пунктов в tests/map.test.js, findNearest + предикат пещеры 000105
   в tests/city-screen.test.js (+ `buildingId !== 48`),
   findNearestMulti в tests/main-visuals.test.js, findBuilding в
   tests/building-effects.test.js.
7. **vm-фолбэк**: map.js без buildings.js → подтипы = null (базовая),
   golden идентичен; кэш пустого вывода таблиц запрещён (паттерн 000055).
