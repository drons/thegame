## Решения (зафиксированы в memory)

1. **Детерминизм — seed = perlin.hash2(day, npcKey(npcId),
   константа_события), бросок = perlin.mulberry32(seed)()**: один
   [0,1) на свежем генераторе, без глобального состояния и БЕЗ
   «мирового» rng (его в main.js нет — не вводится). Тот же (день,
   npcId) → тот же исход; повторная попытка найма в тот же день — тот
   же исход отказа (воспроизводимость, НЕ баг — UI-лог учитывает,
   000083).
2. **npcKey — FNV-1a строка→uint32 ОБЯЗАТЕЛЕН**: perlin.hash2(day,
   СТРОКА) вырождается (Math.imul(NaN) → 0) — все наёмники имели бы
   ОДИН сид на день и отказы/уходы синхронизировались. Вырождение
   зафиксировано тестом.
3. **Разные события — разные константы** (3-й аргумент hash2):
   SEED_REFUSE = 0x72656675 ('refu'), SEED_QUIT = 0x71756974 ('quit').
   Золотые пины в tests/companions.test.js — смена формулы/констант =
   ре-пин.
4. **refused ≠ ok:false**: отказ ({refused:true}) — не сбой canHire
   ({ok:false} для disabled-кнопок); 000083 по флагу `refused` пишет
   текст в npcLog. При отказе золото не списывается.
5. **Запись отряда — ровно {npcId, level, xp, loyalty, hiredDay}**:
   форма зафиксирована под сейв 000085 (000082/000085 не меняют);
   «призраки» (npcId нет в каталоге) — тихий skip, валидация — 000085.
6. **total = 0 → событий нет** (правки ревью c64c12f): иначе 000087
   написал бы «Жалованье выплачено» при нулевом жалованье; guard полный
   (при total = 0 и gold ≥ 0 unpaid-ветка недостижима).
7. **Настройки читаются ЖИВО** при вызове (не захват при загрузке) —
   паттерн combat.js/live-чтения level_delta_max; тесты меняют SETTINGS
   без перезагрузки модуля.
8. **loyaltyTick = экспорт-алиас payWages** (000087 пишет «payWages /
   loyaltyTick» — оба имени работают).
