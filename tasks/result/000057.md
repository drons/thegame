## Решения и отклонения от файла задачи

1. **id = кодовый индекс группы + 1** (файл 000001 = тип 0 =
   ORC_CAMP): генерация, квесты kill_group («группа: 0…6») и
   MOB_GROUP_TYPES работают с индексами 0..6; +1 — только в каталоге
   (паттерн assets/buildings: id = номер файла).
2. **`состав.название` = имя рецепта** ('orc_camp', …) — строка в
   логе боя и в тестах, НЕ русское название группы; русское имя —
   верхнеуровневое `название`.
3. **Порядок `состав.мобы` критичен**: индекс юнита → makeMob/
   placeUnits → расстановка и очередь в бою → детерминизм. Перенос
   1:1; golden-тесты createCombat зафиксированы ДО миграции и
   проходят без изменений.
4. **Фолбэки = ровно значения master** (7/7 имён; 7 рецептов; 7
   видов) — прецедент 000055 (фолбэк 13/3/3). Кэш ПУСТОГО вывода
   запрещён (map.js): первый вызов до загрузки каталога не должен
   зафиксировать фолбэк.
5. **Сейв v1 не тронут**: проверено по коду — группы в сейв не
   пишутся (defeatedAt — сессионный Map в main.js; квест-прогресс
   kill_group — число типа группы; grep mobGroup/group в save.js
   пуст) → CURRENT_VERSION не поднимать.
6. **Модуль данных в index.html ДО map.js** + ленивость map.js +
   гарды combat.js/sprites.js — порядок избыточно безопасен;
   vm-песочницы без модуля получают фолбэки.
7. **diff combat.js фокусирован ради 000062** (зеркало MOB_TYPES):
   только UMD-обёртка + блок GROUP_RECIPES; таблица MOB_TYPES и
   createCombat не тронуты → rebase чистый.
8. **sync-скрипт генерирует файл целиком** (чисто данные), а не блок
   между маркерами (как sync-buildings-data.js) — паттерн
   sync-npc-data.js.
