## Что сделано

* **src/controls.js** — чистое ядро:
  * `layoutTouchControls` → ВСЕГДА три прямоугольника
    `{dpad, action, inventory}`: inventory — того же размера, что
    action, непосредственно над ним (зазор GAP = 12 px, приватная
    константа; ТЗ требует ≥ 8); в формулу B добавлен член
    `floor((availH − inset − GAP)/2)` — пара влезает с учётом
    bottomInset; на типичных вьюпортах (800×600, 390×844, 320×240,
    568×748+45, 1280×720+45, 300×200, 360×640) новый член не активен →
    action побайтово как раньше (существующие deepEqual-пины без
    правок); невалидные (≤0/NaN) размеры → три нулевых
    прямоугольника;
  * `touchActionAt` — точка в inventory → 'inventory' (кнопки
    первыми — до D-pad; guard для старых layout-объектов без поля);
  * `TOUCH_ACTIONS` += 'inventory' (в конец);
    `deltaForMoveKey('touch:inventory')` /
    `touchMoveKeyForAction('inventory')` → null (на master уже так —
    код не тронут, контракт заперт тестами).
* **SVG-иконки** (каталог assets/ui/ — общий с 000124):
  * `icon_action.svg` — ДВЕРЬ (действие / вход в постройку): рама с
    скруглённым верхом, просвет (fill-rule evenodd), ручка-точка;
  * `icon_inventory.svg` — СУНДУК (инвентарь): крышка + корпус с
    прозрачным швом + замок-плашка. Рюкзак отклонён:
    combat_invitem.svg уже рюкзак — два одинаковых силуэта в одной
    системе иконок нет;
  * система иконок 000124 (24×24, единый fill #e8dcc0, fill-only);
    обе прошли `checkSvg` (правило SPEC.md/000120) на временных
    копиях ДО добавления в assets/; счётчик tests/svg.test.js
    `'ui': 8 → 10` (коммит с иконками).
* **src/ui.js** — IIFE `Game.touchControls`:
  * вторая кнопка [I]: `pointerdown` → `onInventory()` (+`blur()`) —
    копия обработчика «E»;
  * содержимое ОБЕИХ кнопок — `<img>` с иконкой из assets/ui/
    (alt=""), ТЕКСТОВЫХ букв «E»/«I» больше нет; aria-label
    сохранён («Действие (диалог NPC / постройка)» / «Инвентарь»);
  * D-pad строится только при `h.dpad === true` (строго);
  * `applyLayout` — перестроен: guard `!root || !actionEl`,
    кнопки размещаются ВСЕГДА, D-pad/стрелки — только при dpadEl
    (старый guard по dpadEl убивал бы кнопки в keyboard-схеме);
  * show()/hide() — typeof-guard classList (vm-стабы, где
    classList — функция-заглушка).
* **Панель персонажа** `G.playerUI`: `toggle(force)` →
  `toggle(force, tabId)` — кнопка [I] открывает панель сразу на
  вкладке «Инвентарь» (существующий `activateTab` по `columnState`);
  неизвестный id — тихо; вызовы без tabId (KeyI, Esc, closeBtn,
  тесты) — поведение без изменений.
* **src/main.js** — `init()` + `show()` в ОБЕИХ схемах: 'touch' →
  `dpad: true`, 'keyboard' → `dpad: false` (только [E] + [I], без
  D-pad); `onInventory: () => { if (G.playerUI)
  G.playerUI.toggle(undefined, 'inventory'); }` — эквивалент KeyI +
  авто-вкладка; `onInteract` не тронут (`G.buildingActions.toggle()`,
  000128); `console.error` при отсутствии Game.touchControls
  сохранён (теперь для обеих схем).
* **index.html** — CSS: `.tc-action` — flex-центрирование (мёртвые
  color/font убраны), новое правило `.tc-action img` (60% от
  диаметра — верх диапазона ТЗ 50…60%); pointer-events/z-index не
  тронуты; новых script-тегов НЕТ → пин tests/index-order.test.js
  без изменений (guard IIFE дословно).
* НОВЫХ JS-МОДУЛЕЙ НЕТ (UMD-ловушек нет). Детерминизм боя, сейвы,
  RNG не тронуты (новых данных в сейве нет; раскладка —
