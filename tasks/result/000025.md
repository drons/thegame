# 000025: синхронизовать анимацию волн на тайлах воды

Статус: выполнено. Тесты: 186 → 192 pass (+6, tests/sprites.test.js).

## Что сделано

* **Нашёл причину разрыва.** Волна в текстуре (assets/tiles/water_1..4.svg)
  имеет период 16px (четверть тайла 64px); кадры — сдвиги translate(0),
  (-8), (-16), (-24), т.е. 8px = полпериода на кадр. Старый `frameIndex`
  брал фазу от целочисленного номера тайла: `(tx*5 + ty*9) % frameCount` —
  соседи получали сдвиг на 1 кадр (полпериода), и рисунок волны на стыке
  перескакивал на 8px.
* **`wavePhase(nowMs, wx, wy)`** (src/sprites.js, чистая функция) — фаза
  волны в точке мирового пространства ([0;1)), `WAVE_PERIOD_MS = 3200`.
  Фаза непрерывна по мировым координатам (нет скачка при пересечении
  границы тайлов) и периодична по времени.
* **`waterTileFrame(nowMs, tx, ty, frameCount)`** — кадр водяного тайла из
  фазы в центре тайла. Пространственный шаг фазы — полцикла на тайл по
  каждой оси → разность кадров соседних тайлов всегда чётная (2 из 4) →
  сдвиг волны у всех тайлов совпадает по модулю периода 16px: в каждый
  момент море показывает ОДИН эффективный сдвиг, швы невозможны в принципе.
  (Это единственное семейство фаз, бесшовное для данных текстур: любое
  нечётное число кадров на тайл рвёт горизонтальный стык.)
* **Рендер без правок main.js.** `frameIndex` теперь диспетчеризует:
  4 кадра (= текстуры воды, `WATER_FRAME_COUNT` — единственное
  4-кадровое значение; мобы/Флогистон — 2) → `waterTileFrame`,
  иначе — прежняя фаза на тайл. main.js вызывает `G.frameIndex` как
  раньше, волна стала синхронной автоматически.
* `waterFrame` переопределён как синоним `waterTileFrame`; новые
  экспорты: `WAVE_PERIOD_MS`, `WATER_FRAME_COUNT`, `wavePhase`,
  `waterTileFrame`.

## Тесты (tests/sprites.test.js, +6)

* wavePhase: чистота, диапазон [0;1), периодичность по времени
  (WAVE_PERIOD_MS).
* «фаза одинакова на границе соседних тайлов»: точка общего стыка
  (мировая линия x = tx+1) имеет одну фазу — одинаковую для левого и
  правого тайла.
* Непрерывность: переход через стык (±1e-6) не даёт скачка фазы
  (старая схема прыгала бы на 1/4 цикла).
* «волна не рвётся на стыке»: разность сдвигов соседних тайлов кратна
  периоду 16px; разность кадров соседей чётна по X и по Y.
* В каждый момент эффективный сдвиг волны одинаков для всех водяных
  тайлов (проверено по 20×20 тайлов).
* Старый тест «waterFrame — синоним frameIndex» переписан: waterFrame —
  синоним waterTileFrame, а frameIndex для 4 кадров даёт ту же фазу.

## Ограничения

* Вертикальный стык текстур (линии волн y=14/34/52, шаг 18px не делит
  64px) идеален не будет — это свойство самих SVG, не фазы анимации;
  требует новых текстур (вынесено в память, не в pending — мелкая
  доработка ассетов).
* Если появится НЕ-водяная 4-кадровая анимация, диспетчеризацию
  frameIndex по WATER_FRAME_COUNT нужно заменить явным аргументом
  террейна (зафиксировано в памяти).
