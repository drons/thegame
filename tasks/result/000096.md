## Что сделано

Полноэкранная двухколоночная панель персонажа со широкими
вкладками:

* **src/ui.js, buildPanel()** — два `.cp-column`, у каждого ряд
  вкладок `.cp-tab` (по 3) + скроллящийся `.cp-tabpane`.
  Data-driven: отдельные массивы `{ id, label, build(pane) }` —
  левый: «Персонаж» / «Инвентарь» / «Игровые настройки»
  (placeholder → 000098); правый: «Снаряжение» / «Магазин»
  (placeholder → 000101) / «Квесты» (placeholder → 000100).
  Переключение — style.display; состояние вкладки живёт через
  render() (активный pane не пересобирается). Кнопки вкладок —
  класс `.cp-tab` (не `.cp-btn`); делегированный click — ОДИН
  (вкладка — отдельная ветка). `.cp-title` = c.name (захардкоженный
  «Флогистон» убран), обновляется render(). При открытии
  display = 'flex' (не 'block' — иначе CSS flex-верстка мёртвая).
  [Esc] — document keydown-слушатель, вешается на open, снимается
  на close, guard isOpen().
* **src/main.js** — панель закрывается при старте боя во ВСЕХ
  входах (мир, подземелье, отладочный actions.startCombat).
* **index.html (CSS)** — `.char-panel`: fixed, top/left/right 12px,
  bottom:56px (верхняя кромка .fs-btn ниже — кнопка кликабельна в
  обоих состояниях подписи), НЕТ фиксированного width (был 380px),
  два `.cp-column` (flex:1, gap), `.cp-tabpane` overflow-y:auto;
  z-index: char-panel 10 < fs-btn 15 (лестница 5/10/15/20).
* **tests/ui-panel.test.js** (новый, 16 test'ов) — локальный
  DOM-стаб (дубль ui-skills.test.js + document add/remove
  EventListener + body). Красные: верстка 2×3, подписи, .cp-title
  = имя, переключение/живость вкладок, CSS-геометрия, z-index,
  один делегированный обработчик, [Esc] open/close/detach/reopen,
  структурный тест закрытия панели во всех входах боя. Зелёные
  (регрессия): строки навыков .cp-btn[data-skill] внутри <tr>,
  item-кнопки data-act (buy/use/quick/remove), контракты
  ui-skills.test.js прошли БЕЗ ИЗМЕНЕНИЙ.

## Ревью (3 раунда, adversarial)

1. **Раунд 1** — инлайновый display:'block' переопределял CSS
   flex (верстка панели мёртвая) → 'flex'; закрытие панели
   пропущено в 2 из 3 входов боя (main.js) → все 3 + структурный
   тест.
2. **Раунд 2** — одно нажатие [Esc] закрывало и диалог NPC
   (window-слушатель), и панель (document-слушатель) → гард
   `G.npcUI.isActive()` в escHandler панели (Esc закрывает
   верхний слой; гард в document-слушателе, т.к. он срабатывает
   ДО window-слушателей, а не stopPropagation).
3. **Раунд 3** — тот же дефект на оверлее РЕЗУЛЬТАТА боя
   (combat-ui.js, c.result): [Esc] закрывало и панель, и
   оверлей результата → гард `G.combatUI.isActive() &&
   current().result`; во время самого боя (result нет) гард не
   срабатывает — Esc закрывает панель, как штатное управление
   панелью в бою. Финальный фикс внесён вручную в worktree
   (пайплайн остановился на verify с этой единственной
   неблокирующей находкой) + 2 новых теста (результат открыт —
   панель живёт; бой в ходу — панель закрывается), затем
   протокол мержа выполнен вручную.
