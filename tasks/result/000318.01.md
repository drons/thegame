## Что сделано

1. **scripts/lib/json-ref.js** — формы имён стали настраиваемыми:
   * `ASSET_NAME_SHAPES` (живой объект): 11 нумерованных каталогов →
     'number' (items, skills, spells, mobs, mob_groups, buildings, craft,
     dungeons, npc, runes, visuals), portraits → 'named';
   * `SHAPE_BASENAME_RES` = { number `^\d{6}\.json$`,
     slug `^[a-z][a-z0-9_]*\.json$` } (slug с буквы — отсекает голое число/
     заглавную/слеши);
   * `REF_LINKED_CATALOGS` — РОВНО 9 мишеней ссылок (REF_CATALOGS минус
     visuals и portraits); ref-eligibility ≠ name-shape: runes/visuals при
     ЛЮБОМ шейпе не ref (AR14), portraits — только PORTRAITS_RE;
   * `refPath(catalog, basename)`, `isRefPath(catalog, basename)`,
     `isRefPathFull(p)` (парсинг `^assets/([^/]+)/([^/]+)$`, слэш в basename
     отсекается); `isRef` = isRefPathFull ∪ PORTRAITS_RE — читает шейпы
     ЖИВО (временные подмены в тестах работают);
   * `REF_RE` ВЫВЕДЕН из шейпов группами по форме (порядок REF_CATALOGS);
     при всех 'number' source побайтово = прежний литерал (пин AR11;
     рантайм-носитель строки — pattern в assets/skills/schema.json, SR5);
   * lib остался ОДНИМ файлом без внутренних require (копируется в tmp
     tests/items.test.js); ни одного new RegExp на вызов.
2. **Перевод чужих REF_\* на общий lib** (поведение/exit-коды/тексты —
   дословно, пины R4/R5/SR8): sync-craft-data.js и sync-spells-data.js —
   refId(ref, catalog, where) = startsWith(prefix) + isRefPath;
   sync-buildings-data.js — хелпер isCatalogRef('items'/'skills');
   sync-mob-groups-data.js — инлайн isRefPath('mobs', …). Формат-строки
   сообщений («assets/items/NNNNNN.json») НЕ «улучшались».

   makeTmpCraftRepo (tests/craft.test.js) копируют теперь и json-ref.js —
   иначе MODULE_NOT_FOUND в запускаемом sync (доказано мутацией M4).
   Зеркала перегенерацией НЕ меняются: все 4 sync перегенерированы —
   git status src/ пуст; sync:check = 0.
