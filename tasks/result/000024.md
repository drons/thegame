# 000024: Крафт — каталог assets/craft (рецепты, схема) и раздел SPEC.md

Статус: выполнено. Тесты: 194 → 203 pass (новых 9, tests/craft.test.js).

## Что сделано

* **Каталог `assets/craft`** — 10 рецептов (`000001.json` …
  `000010.json`) + JSON-схема `schema.json`:
  * виды крафта (enum): кузнечное_дело, алхимия, резьба_по_камню,
    столярное_дело, зачарование, рунопись; в каталоге представлены
    кузнечное дело (3), алхимия (3), зачарование (2), 2 улучшенных
    способа («база»);
  * каждый рецепт ссылается на: предмет-результат и исходники с
    количеством (assets/items), навыки (assets/skills), здания
    (assets/buildings); заклинания (assets/spells) — по назначению
    (реальные id: fireball, stone_skin, frost_bolt — каталог задачи
    000023);
  * поля: `id`, `название`, `тип`, `база` (опц.), `результат`,
    `исходники`, `навыки`, `здания`, `заклинания` (опц.), `уровень`,
    `описание`.
* **SPEC.md, новый раздел «Крафт»**: «Виды крафта» (таблица
  вид → что делает → навыки → постройки), «Навыки крафта и их
  совершенствование» (уровень на вид, рост: практика/книги/наставники,
  потолок практикой, влияние на качество и выход), «Рецепты» (поля,
  условия изготовления), «Совершенствование способов изготовления
  (особый вид крафта)» (поле `база`, инварианты), «Архитектура
  хранения (каталог assets/craft)» (схема, ссылки, тесты,
  ограничения).
* **tests/craft.test.js** (9 тестов): нумерация и чистота каталога;
  схема — только ключи минимального валидатора (000015); каждый файл
  валиден по схеме; правила (уникальные id, enum = виды, исходник ≠
  результат, дубли); ссылки: навыки → skills, здания → buildings,
  заклинания → assets/spells; улучшенные способы (база: тот же вид и
  результат, уровень не ниже, исходники покрывают базовые, без
  циклов); покрытие требований задачи.

## Ключевые решения

* «Совершенствование способа изготовления» — рецепт с полем `база`
  (тот же паттерн, что совершенствования заклинаний в 000023):
  отдельное игровое действие, «прокачивает» сам рецепт, не создаёт
  новый предмет; улучшенный способ гарантирует качество/выход.
* Игровой код не писался (по условию задачи): каталог и схема —
  source of truth, за реализацию (src-модуль уровней крафта,
  изготовление, качество/выход) открыта задача 000046 в pending.
* Текущие рецепты используют существующие предметы как исходники
  (перковка оружия/брони, варка зелий из реагентов): каталог
  assets/items не содержит сырья — это ограничение зафиксировано в
  SPEC.md и закрыто задачей 000044 (сырьё + базовые рецепты).

## Ограничения

* Рецепты столярного дела, резьбы по камню и рунописи появятся после
  добавления сырьевых предметов (задача 000044) — типы в enum и SPEC
  уже зафиксированы.
* Числовые параметры (опыт за изготовление, формулы качества/выхода)
  — за задачей реализации 000046.
* Тест читает id заклинаний из JSON-каталога через fs; после появления
  src/spells-data.js (задача 000045) разумно переключить на модуль.
