# Результат 000343: реюз Float32Array в buildFrame (RENDER-OPTIMIZE §5G, G1)

## Что сделано

`src/main.js` — ровно 2 правки в upload-пути `buildFrame`:

1. у `quadVerts` объявлен capacity-растущий склад `let uploadBuf = new
   Float32Array(0)`;
2. `gl.bufferData(ARRAY_BUFFER, new Float32Array(verts), DYNAMIC_DRAW)`
   заменён на: рост capacity по необходимости → **свежий** exact-length
   `uploadBuf.subarray(0, verts.length)` → `view.set(verts)` → `bufferData`
   ВСЕГДА (1 вызов/кадр, в т.ч. 0 вершин).

Вывод — бит-в-бит (`view.set` ≡ прежняя аллокация, V8 Buffer-cmp проба);
GC-win — убрана пофреймовая аллокация data-block.

Путь «bufferSubData при неизменной capacity» и «пропуск bufferData при
0 вершин» ЗАПРЕЩЕНЫ пинами: оба убирают bufferData с кадра и красят RM-10
(tests/global-map-draw.test.js:840, ассерции :864/:866) — доказано
мутациями M4/M1 (матрица в memory/000343-buildframe-buffer-reuse.md).
Возврат того же объекта запрещён пином свежести 000339 T4 (:486–488) —
поэтому обязателен свежий `subarray`-view (мутация M3 красит канарейку
000339). Нумерация по эррате 000342: bufferData-пин несёт RM-10, НЕ RM-6.
