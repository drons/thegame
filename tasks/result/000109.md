## Решения (зафиксированы, см. memory)

1. **Формат и ключ — контракт 000108, НЕ переименовывать**:
   город = якорь (buildingAnchor, не тайл входа — многотайловый
   footprint), сток = локальная клетка (x/y shop-объекта).
2. **Валидация в src/cities.js, НЕ day.js**: require-пин
   tests/cities.test.js (perlin/items/buildings) + прецедент
   000072 (section-валидаторы в доменных модулях: npc.js,
   building-effects.js). day.js-слой 000072 использован на
   границе композиции (идентичная семантика дней, dueForRespawn).
3. **ОБРЕЗКА — ОБА конца обязательна**: при сейве (мир бесконечен
   — без неё раздел растёт до квоты → save() false) и при
   восстановлении (fastForward без слушателей — onDay-очистки не
   пройдёт, 000031).
4. **Респаун = НОВЫЙ ПОЛНЫЙ сток БЕЗ соли по дню**: makeCityShop/
   generateCityContents детерминированы по (якорь, клетка) —
   golden-пины 000106/000108; соль ломала бы ВСЕ городские стоки.
5. **city_respawn_days = 3** (дефолт, int, min 1): «несколько
   игровых дней», симметрия respawn_days/dungeon_memory_days.
6. **Сохранённый сток АВТОРИТЕТЕН** — кламп по начальному стоку
   НЕ делаем (в отличие от restoreNpcStocks; TZ «проверка
   структуры»; чужой валидный сток переживает roundtrip — R6).
7. **Версия НЕ поднимается** (v1, неломкое расширение —
   000031/000029; прецеденты quests/npcStocks/buildingOncePerDay).
8. **false-возврат save() (квота)** — один warn за сессию
   (saveWarned), без падений/confirm (confirm — только
   migration_failed/corrupt при загрузке).
9. **ds.contents у города — null ВСЕГДА** (ловушка dungeon-ui.
   js:318 / __game.dungeon); состояние — в cityStates Map.
