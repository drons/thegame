## Решения

Все 13 — в **memory/000081-efir.md** (по каждому — почему); стабильный
контракт для следующих задач — **memory/000081-efir-ally.md** (API,
состояние/сейв, данные makeAlly, где что проводилось, что менять
нельзя, чек-лист 000084–000087/000111–000119). Ключевые:

1. Эфир — частный случай «союзного юнита» 000080, kind строго 'efir'
   (не 'ether'!) — combat.js не трогается.
2. Статы 000081 — ФОРМУЛЬНЫЙ путь makeAlly (явных maxHP/damage нет —
   пин; маркер морали companionMoraleBonus действует через формулу);
   явная таблица 000035 — 000111 (правит только efir.js +
   efir.test.js).
3. Состояние = форма сейва 000085 `{level, xp, skills}`; 100% XP —
   только victory (условие не ослаблять: fled/defeat — 0; Эфир мёртв
   в бою — XP всё равно).
4. Эфир первым в allies (якорь «всегда со мной»); один воронка
   combat-ui.js вместо трёх onEnd в main.js.
5. 000087 НЕ дублирует addEfirXp — Эфир-XP уже смержен в finish()
   (000081); его onEnd — только доля наёмников + dead_mercs +
   saveNow.
6. Сейв (serializeEfir/deserializeEfir в efir.js) — 000085; до него
   состояние — только память сессии (перезагрузка страницы → L1;
   допустимо).
7. УMD: ноль require в обеих ветках, снапшота Game при загрузке нет
   (000038); throw на загрузке не делается — мягкая зависимость +
   пин R12 + console.error-гарды в потребителях.
