## Решения (зафиксированы в memory/000153.01-dungeon-depth-save.md §8)

1. Гард depth — fail-open clamp (не throw) — 000029: не крашить игру.
2. Соль 0xd337b153 + hash2^depth·0x9e3779b9 — эмпирика реальным hash2:
   детерминированно, ≠ base, depths 2..12 попарно различны, без
   коллизий с существующими солями.
3. Ключ `worldKey + ':' + depth` — прецедент buildingOncePerDay
   'x,y:effectId'; единый источник dungeon.js.
4. Секция — MULTIPLE records (1:1 с runtime-Map), не single — per-
   этажный re-loot-фикс остаётся закрытым после .03.
5. Сериализатор — чистые функции dungeon.js (cities.js-паттерн):
   node-тестируем без Game; main.js — тонкий glue + guards.
6. Merge activeRec «активный поверх» — ОБЯЗАТЕЛЬНАЯ часть фикса
   (in-flight-сейв первого входа обязан нести contents).
7. Pos-restore — в maybeEnterDungeon (locations.js): main.js не знает
   размеров подземелья; FLOOR-валидация + fallback entrance.
8. Debug-путь без аргумента / при совпадении terrain — поведение
   master сохранено (флаг только на вынужденный mismatch).
9. Призрак-предмет — null-гард в dungeonOnMove (паттерн buyItem);
   альтернатива (нормализация id при restore) отклонена —
   сериализатор чистый, каталог ему недоступен.
10. CHANGELOG — отдельный коммит (9ac1739): игрокам заметно (игровой
    процесс) — re-loot закрыт + позиция в этаже восстанавливается.
