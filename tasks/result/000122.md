## Что сделано

1. **src/day.js** — чистая функция `groupVisible(defeatedAt, x, y)`
   рядом с `dueForRespawn`/`serializeDefeatedAt`/`restoreDefeatedAt`
   (там уже живёт вся defeatedAt-логика):
   * false — если в `defeatedAt` есть запись тайла, true — если нет;
   * ключ — ТОЧНО формат main.js: `x + ',' + y` (целые, без пробелов,
     отрицательные возможны — мир бесконечный); другой формат = тихий
     fail-open навсегда;
   * принимает и Map (рабочее состояние main.js), и обычный объект
     (сырой сейв); для объекта — `hasOwnProperty`, а не `in`
     (прототип-безопасность: `Object.create(null)`, чужие ключи
     прототипа не лгут о записи);
   * мусор вместо `defeatedAt` (null/undefined/строка/число/массив/
     булево) — fail-open: true, без исключений (принцип 000029 — битое
     состояние не роняет rAF-цикл; спрайт рисуется = старое поведение);
   * чистая: вход не мутируется (зафиксировано тестом);
   * экспорт в returned-объект (браузер — `root.Game`, node — require).
2. **src/main.js** — `drawSprites`, проход 3 (спрайты групп поверх
   построек): перед `drawImage` спрашивается
   `G.groupVisible(defeatedAt, t.x, t.y)` — поверженная группа
   пропускается. Гард `G.groupVisible &&` — при отсутствии функции
   (старый day.js) — старое поведение, без падения (fail-open-паттерн
   main.js, как `G.serializeDefeatedAt ? …`). Остальной код прохода не
   тронут.
3. **Без доп. состояния:** запись `defeatedAt` создаётся только при
   победе (main.js) и удаляется только `dueForRespawn` при смене дня
   (onDay) — ОДНО состояние для логики боя и отрисовки,
   рассинхронизация невозможна: в день респауна (`day − defeatedDay
   >= respawn_days`, по умолчанию 3) запись уже удалена →
   `groupVisible` true → спрайт на месте.
4. **Память**: memory/000122-mob-hide-after-victory.md — где живёт
   фильтрация и почему, формат ключа, fail-open.

## Решения (зафиксированы, детали в memory)

* **Фильтрация — в слое отрисовки (main.js), а НЕ в map.js**:
  `hasMobGroup` в `map.tileAt` детерминирован (hash координат, чистый
  мир) и не знает о `defeatedAt` — это состояние main.js.
  «Повержена/жива» — состояние сессии, не свойство мира; вопрос
  «рисовать или нет» задаётся там, где состояние есть. map.js не
  тронут.
* **Альтернатива «мёртвый маркер»** (костёр/кострище на месте
  поверженной группы) — НЕ делалась: ТЗ явно за scope; решение о
  маркере, если захочется — отдельная задача.
* **HUD-статус «Группа … повержена» не меняется** — тайл всё ещё
  mob-group, просто скрыт; согласованно.
* **Подземельные (блуждающие) группы не затронуты** —
  `dungeonState.contents`, отдельная система, на глобальной карте не
  рисуются.
* **Сейв совместим** — нового состояния нет: сериализация/
  восстановление `defeatedAt` не меняется, версия сейва (000031)
  не поднималась.
