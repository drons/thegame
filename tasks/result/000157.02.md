* **Генерация** (`src/dungeon.js`): экспорт `DUNGEON_ORES[type]` (паттерн
  `DUNGEON_WALL_KINDS`); `generateDungeonContents(d, player, opts)` —
  `depth = max(1, opts.depth|0)`; блок залежей СТРОГО ПОСЛЕ цикла
  сундуков: СВОЙ поток `mulberry32(hash2(seed, depth, 0x0DE5) >>> 0)`
  (соль запинена ORE-7), `nDeposits = 1+min(3,floor(depth/3))`,
  `T = min(1+floor((depth-1)/2), 4)` (tier предмета — из каталога
  `assets/items`, DRY 000157.01), порядок предмет→количество→клетка,
  `amount = 1+floor(rng_dep()*2)+min(2,floor(depth/4))`, собственный
  takeSpot на ОБЩЕМ occupied (взаимоисключение с мобами/сундуками/
  босс-клеткой, паттерн 000183). Главный rng — НОЛЬ новых вызовов после
  сундуков: goldens seed/mobs/chests БИТ-В-БИТ (ORE-7 не перебинтован).
  Guard: нет «руда» или нет tier ≤ T → `deposits = []`.
  `HAVE_ITEMS/ITEM_TIER` — мягкий путь для vm-песочниц без items-data
  (без console.*). FALLBACK_DUNGEONS + «руда» 1:1 с каталогом.
* **Подключение реальной глубины (после ребейза, 000153.01 смержена)**:
