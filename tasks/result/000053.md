## Отклонения/принятые решения (по замечаниям критика)

* file://: JS-зеркала каталогов существуют НАМЕРЕННО (двойной клик,
  fetch локальных JSON не работает) — дедепликация = JSON как source
  of truth + синхронизация зеркал, а НЕ удаление зеркал (во всех
  дочерних зафиксировано).
* BUILDING_NAMES — не чистая копия (3 обобщённых имени) — решение
  через новое поле каталога (000055), альтернатива — явная таблица с
  усиленным тестом; SPEC правит 000055.
* Порядок загрузки (map.js 294 < buildings.js 298, index.html):
  производные данные в map.js — только ЛЕНИВО (catalogRef/root.Game,
  паттерн, зафиксированный vm-тестом tests/map.test.js); vm-
  песочницы не ломаются (гарды, без взаимных require).
* Сейв (v1): постройки/группы/подземелья в сейв не пишутся —
  имена/размеры менять безопасно; перенумерация id (npc/предметы)
  запрещена (npcStocks/quests) — в дочерних: id не менять, при
  необходимости — версия + миграция (memory/000031-save-versioning.md).
* SPEC.md — четвёртая копия таблиц (разделы «Постройки», «Мобы» и т.д.):
  каждую дочерняя обновляет свою часть (указано в каждой задаче).
* Детерминизм: любое перемещение данных — только с golden-тестами
  (tileAt, составы групп, генерация подземелий, сток магазина) —
  обязательное требование в каждой дочерней.
