## Что сделано

1. **src/spells-data.js** (новый) — зеркало каталога assets/spells
   (16 заклинаний): `SPELLS` (порядок файлов) и `SPELLS_BY_ID`
   (строится ЦИКЛОМ от SPELLS — те же объекты, идентичность нужна
   для сравнения «высшая степень цепочки»). Генератор
   **scripts/sync-spells-data.js** (`npm run gen:spells`), стиль
   src/skills-data.js (000024). В браузере — Game.SpellsData.
2. **src/spells.js** (новый) — ядро, чистый код без DOM, в браузере
   Game.Spells:
   * ранги школы по SPEC: Ученик 1–10 / Знаток 11–25 / Мастер 26–50 /
     Аркимаг 51–100 → уровни 1..4 (schoolRank/rankAllowsTier);
   * книга заклинаний: `p.spells` (стартовая `['spark', 'mend']` —
     аналоги старых кнопок «Огонь»/«Исцел.»), ленивая bookOf;
     learn/canLearn — порядок проверок: неизвестное id → уже изучено
     → ранг школы ПО АТРИБУТУ заклинания (Int/Wis) → базовое
     заклинание → для источника 'rune' — Рунопись ≥ уровень;
   * цепочки «база»: предвычислены обходом дерева от корня (все
     улучшения, а не только kids[0]), highestKnown/activeSpells —
     в бою действует только высшая известная степень цепочки;
   * castSpell/canCastSpell — зеркало 000037 (один общий evalSpell,
     одна причина — одно поведение, canCastSpell без побочных
     эффектов): пул spellInt/spellWis по атрибуту → мана → цель
     (default nearestMob, дальность 4) → действие. Формулы
     детерминированы: урон (всегда попадает, броня моба
     игнорируется), лечение, щит {armor: 1+степень, turns: 3},
     ослабление ×0.75 на 3 удара, контроль (моб пропускает
     действие). Практика PRACTICE_XP.spell=3 по мапе школа→навык
     (огонь→firelord, лёд→icelord, исцеление→meditation,
     природа→nature; тень/защита — практики нет);
   * sanitizeSpellBook (сейв: только строки-каталожные id, без
     дублей, порядок сохранён).
3. **src/combat.js** — мелкие локализованные правки:
   * экспорт `combatInternals` = { log, nearestMob, unitDist,
     checkTurn, checkBlocked, dealDamageToMob } — публичный API
     ядра для spells.js;
   * `c.ps.shield` в createCombat (новый бой — чистый): в
     dealDamageToPlayer гасит `armor` от RAW-урона (до блока/брони);
     тик в endPlayerTurn ПОСЛЕ refillPools — защита ровно `turns`
     раундов, включая раунд каста;
   * `u.bind`: в начале mobAct — тик + лог «…скован — пропускает
     действие.» + return; пока скован, прочие эффекты НЕ тикают;
   * `u.weaken`: в mobAttack — урон ×mult, тик ВМЕСТЕ С ПРИМЕНЕНИЕМ
     (×0.75 ровно 3 удара; промах — тика нет).
   Старые `c.spell('fire'/'heal')` (playerSpell/canDoAction) НЕ
   тронуты — два «огня» в бою сосуществуют до будущей UI-задачи.
4. **src/player.js** — `spells: ['spark', 'mend']` в createCharacter.
5. **src/main.js** — restoreFromSave: `hero.spells` через

6. **index.html** — `spells-data.js` и `spells.js` сразу ПОСЛЕ

## Адверсариальное ревью (правки закоммичены, коммит 9bc725d)

Три потенциальных дефекта; все невоспроизводимы на актуальном
каталоге (схема/тесты данных 000023 их закрывают) — тесты-правки
мутируют каталог В ПАМЯТИ с восстановлением в finally:
1. неизвестное `действие`: castSpell тратил пул/ману ДО «ok:false»,
   а canCastSpell давал ok:true (нарушение зеркала 000037) →
   проверка KNOWN_ACTIONS в общем evalSpell (отказ до расхода;
   default-ветка switch в castSpell — недостижимая страховка);
2. обход цепочки только по kids[0]: второе улучшение одной базы —
   «сирота» (своя цепочка, обе степени кастуемы одновременно,
   undefined-ключ в activeSpells) → обход дерева от корня, строгое >
   по степени (равные — порядок каталога);
3. лечение: зашитый wisdom → spell.атрибут (как у урона; численно —
   без изменений, в каталоге все исцеления Мудрость).

  цепочка) — поддержать их как предметы изучения» — НЕ ПРИМЕНИМ:
  в assets/items таких предметов нет (свитки 000030–000032 —
  skill_xp вторичных навыков, не заклинаний). learn/canLearn уже
  принимают source='book'|'scroll'|'mentor'|'rune' — подключение
