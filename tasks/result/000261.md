## Ревью (станция правок, 2026-10-24)

Три finding'а ревьюеров (все minor) — вердикты и действия:

1. **border: 0 зависит от порядка в файле — пин не фиксировал
   порядок — РЕАЛЕН, исправлено.** Правило `.combat-victory-loot
   .cp-itemrow { border: 0; }` побеждает глобальные
   `.cp-itemrow.cp-rarity-*` только благодаря более позднему
   положению (специфичности равны (0,2,0)); 261-CSS-RAR пинил
   декларацию, но не взаимный порядок — перенос блока 000261 выше
   :108-112 вернул бы рамки при зелёном пине. Фикс — ассерт
   порядка в 261-CSS-RAR (tests/combat-layout.test.js):
   `html.indexOf('.combat-victory-loot .cp-itemrow {') >
   html.indexOf('.cp-itemrow.cp-rarity-common {')`. Перенос блока
   теперь краснеет. Memory §6.6 — пометка «порядок запитан».
2. **Ветка it === null (неизвестный id → cp-rarity-none) не
   покрыта — РЕАЛЕН, исправлено.** 261-CU-LOOT-RAR покрывал
   rarity-ветку (void_ring) и расходник без rarity (bread); ветка
   деградации it === null (G.getItem → null) не была запитана.
   Фикс — новый тест 261-CU-LOOT-UNK (tests/combat-ui.test.js):
   лут с id 'no_such_item_261' (фикстура: G.getItem → null;
   очередь [0.25, 0, 0.99, 0.99] — базовый/редкий роулы мимо) →
   строка ТОЧНО 'cp-itemrow cp-rarity-none', 1 ребёнок (img НЕТ),
   имя = String(id). Memory §4 — пометка «пин — 261-CU-LOOT-UNK».
3. **Fail полного прогона — known-флейк нагрузки map.test.js —
   НЕ ПО ЗАДАЧЕ, правки не требуются.** «перформанс: 160k tileAt»
