   gen:combatbg`): детерминированный (mulberry32, фиксированный сид на

   md5 после второго прохода совпали). В репозиторий попали статичные
   SVG; schema.json не нужен (данных нет) — состав 11 файлов зафиксирован

   картинка ищется в spriteLoader КАЖДЫЙ render (фон, загрузившийся после

## Решения и отклонения от файла задачи

1. **Размер 336×336, а не 768×768.** Файл задачи: «рисовать с запасом
   (например 768×768) для чёткости на retina (canvas масштабируется)».
   Отклонение: viewBox 0 0 336 336 = 7×7×CELL(48 px). Обоснование:
   боевой canvas — 336×336 DEVICE px, CSS-апскейла нет (`.combat-box
   canvas` без width/height — index.html), и SVG — ВЕКТОР: браузер
   растеризует его под фактический размер drawImage, «запас под retina»
   для вектора не существует (ретинская чёткость — свойство растра, а
   canvas рисуется целиком в device px). Выгода 336: детали, привязанные
   к 48 px, ложатся точно на сетку.
2. **COMBAT_BG_DUNGEON — литеральное зеркало** DUNGEON_TYPES
   (`{0:'cave',1:'crypt',2:'ruins',3:'drowned',4:'abyss'}`), без
   зависимости sprites.js → dungeon.js. Обоснование: (а) vm-песочница
   tests/combat-ui.test.js не грузит dungeon.js — Game.DUNGEON_TYPES там
   undefined, а sprites.js в той же песочнице загружается; (б) require
   dungeon.js в node-ветке UMD создал бы рассинхрон node/браузер веток
   (в браузере зависимость не использовалась бы). Защита от рассинхрона —
   тест, сверяющий зеркало с реальным DUNGEON_TYPES (тест 2 выше).
   Файл задачи допускал вариант («ключ-строки литералы или уже
   существующая зависимость»).
3. **Цвет сетки — rgba(255,255,255,0.18)** вместо «на глаз приглушить/
   полупрозрачнее» без конкретного значения. Расчёт на полюсах:
   * тёмная полупрозрачная линия (план предлагал rgba(18,22,30,0.55)) на
     тёмных фонах (plain ≈ #0d1117, abyss bottom #0a0713) даёт Δ яркости
     ~3–4/255 — нечитабельна; это как раз полюс, который план
     выделял («на тёмном abyss потеряется»);
   * светлая линия: на plain #0d1117 → (57,60,65) — ≈ старый вид
     (#2a3140 = (42,49,64)), т.е. фолбэк без деградации; на abyss bottom
     → (56,53,60) — читается; на самом светлом sand top (#cabf94) →
     (211,200,161) — приглушённо (Δ ≈ 13/255), как и требовалось
     «приглушённее»; на drowned/forest/swamp/пещерах — между полюсами.
   Один цвет/альфа на все 11 фонов + фолбэк — просто и предсказуемо.
   Визуальная проверка в браузере не выполнялась (headless-окружение
   без дисплея) — решение по расчёту контраста, зафиксировано здесь.
4. **Фолбэки (три уровня, все штатные):** (а) неизвестный тип/пустой bg →
   plain.svg (чистая функция); (б) spriteLoader === null (main.js без
   s2 / без G.createSpriteLoader) или картинка ещё не загрузилась →
   сплошной #0d1117 (базовый слой рисуется ВСЕГДА); (в) sprites.js
   отсутствует вовсе (vm-песочница) → bgPath = null → то же сплошное.
   Асинхронность закрыта lookup'ом `spriteLoader.image(bgPath)` в render()
   (каждый вызов), а не один раз в startCombat.
5. **Детали — на внешнем кольце, центр 3×3 без жёстких деталей**
   (низкий контраст в зоне юнитов — ТЗ). Мягкая текстура (пятна, туман)
   может быть в центре — она и есть «пониженный контраст».
6. **Вода/глубокая вода/горы → plain.svg** — осознанный фолбэк: тайлы
   непроходимы, бой там не начинается (PASSABLE в map.js); зафиксирован
   тестом с комментарием.
7. **Препятствия НЕ запечены в фоны** (000050 рисует их отдельными
   спрайтами поверх; слой встанет между сеткой и юнитами).
