# 000029: персистентность журнала квестов и стоков торговцев NPC

Статус: выполнено. Тесты: 212 → 222 pass (новых 10, tests/npc.test.js).

## Что сделано

* **src/npc.js** (чистое ядро):
  * `acceptQuest(book, npcs, npc, questId, day)` — опциональный аргумент
    `day`: при целом `day >= 1` в инстанс квеста пишется `day` — день
    ВЫДАЧИ. Без аргумента поведение не меняется (назад-совместимо).
  * `serializeQuestBook(book)` — JSON-безопасная копия `{active, done}`;
    `null`, если аргумент не объект.
  * `deserializeQuestBook(data)` — валидация структуры: `active` — объект
    инстансов (`questId === key`, `npcId` строка, `status` —
    'active'|'ready', `progress` целое ≥ 0, `day` целое ≥ 1, если есть),
    `done` — массив строк (не-строки отбрасываются). Любой дефект → `null`
    (раздел сейва невалиден — сброс раздела, игра не роняется).
  * `pruneQuestBookByDay(book, worldDay)` — чистая функция: из `active`
    убирает квесты с `day > worldDay` (квест «выдан в будущем» противоречит
    дате — состояние не может ей противоречить); возвращает `{book,
    dropped}`; `worldDay` не-целое → журнал не тронут; `inst.day`
    не-число/отсутствует → квест остаётся; вход не мутируется.
  * `defaultStock(npc)` — вынесен из `createNpcShop` (токены начального
    стока по `торговля.количество`, по умолчанию 1).
  * `serializeNpcStocks(stocks)` — только целые ≥ 0; `null` для
    не-объекта.
  * `restoreNpcStocks(npcs, saved)` — `{npcId: stock}`: неизвестный NPC и
    не-торговцы пропускаются; количество клэмпится
    `min(saved, initial)`; отрицательное/не-число → значение из
    `defaultStock`; неизвестные id предметов отбрасываются; «грязный»
    вход → `{}`.
* **src/ui.js** (диалоговый оверлей):
  * `open(o)` принимает `shop` (готовый сток из реестра main.js — диалог
    больше НЕ пересоздаёт сток на сессию), `onChange` (хук — вызывается
    после ЛЮБОГО мутирующего действия: покупка/продажа, прокачка,
    перенос очков, возврат, принятие/сдача квеста) и `day` (целое ≥ 1) —
    передаётся в `G.acceptQuest(..., day)`.
* **src/main.js** (сборка и восстановление):
  * реестр `npcStocks = {}` + `npcShopFor(npcId)` — сток создаётся ОДИН
    раз на NPC и живёт в main.js (как и журнал); оба места вызова
    `npcUI.open` передают `shop`, `onChange: saveNow`, `day: clock.day`.
  * `collectSaveData()` дополнен: `quests: G.serializeQuestBook(questBook)`,
    `npcStocks: G.serializeNpcStocks(npcStocks)` — неломкие поля v1,
    версия не поднимается (правило 000031).
  * `restoreFromSave()`: после дня/персонажа/позиции — в try/catch:
    `deserializeQuestBook` → `null` = console.warn + журнал не тронут;
    `pruneQuestBookByDay(qb, clock.day)` — отброшенные → console.warn;
    `restoreNpcStocks(NPCS, d.npcStocks)` → реестр. Раздел битый — тихий
    сброс раздела, игра не падает (принцип 000029).
  * `__game.state.npcStocks` — отладочная копия реестра.

## Ключевые решения

* **Согласованность с датой** — через штамп дня выдачи: квест «принят в
  день N» не может существовать в мире дня M < N; при восстановлении такие
  инстансы отбрасываются с console.warn (а не «чинятся») — честнее, чем
  сдвигать штамп.
* **Сток живёт в main.js, не в NPC-объекте и не в ui.js**: NPC-данные из
  каталога неизменяемы; ui.js остаётся без состояния между сессиями.
* **Хук onChange в диалоге**, а не сохранение в чистом ядре: ядро (npc.js,
  save.js) остаётся DOM- и хранилище-agnostic; клей в main.js.
* Не-ломкость полей `quests`/`npcStocks`: сейвы v1 без этих полей
  восстанавливаются как есть (журнал/сток — начальные), миграция не
  нужна.

* Награда квеста/прогресс `kill_group` привязаны к инстансу — при отбросе
