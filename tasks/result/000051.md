## Почему задача разделена

Заключение аналитика: 000051 — цельный UI-фич («делить не
требовалось»), НО объём работ — один из крупнейших в проекте:
перестройка базового оверлея (src/ui.js — панель + npcUI),
тултипы, вкладка «Игровые настройки» с рефакторингом ядра на
live-чтение (day/player/dungeon/main), проводка questBook в
playerUI, перенос торговли. Независимый критик выделил
самостоятельные зоны риска: live-применение настроек (без него
вкладка не работает до перезагрузки), решение о персистентности,
валидация/кламп (steps_per_day=0 → зависание rAF-цикла),
расширение DOM-стаба, скрытая data-зависимость questBook,
поверхность merge-конфликтов (src/ui.js + index.html + main.js
параллельно правят 000042/000046/000083/000085/000087; 000083 сам
пишет «Конфликтует с 000051 (ui.js) — мержить с разнесением/
ребейзом»). Одна реализационная задача имела бы максимальную
поверхность конфликтов и не влезла бы в один цикл
«красные тесты → реализация → ревью». По правилу
tasks/CLAUDE.md («если задача слишком большая — делим») задача
разбита на 6 сфокусированных подзадач с разнесённой поверхностью
мержа и зафиксированным порядком.

## Ключевые проектные решения (зафиксированы в подзадачах и
memory/000051-char-panel-plan.md)

1. ВЕРСТКА: .char-panel — fixed top/left/right:12px, bottom:56px,
   z-10, полностью перекрывает карту; два .cp-column, у каждого
   СВОЙ ряд широких .cp-tab и скроллящийся .cp-tabpane. Вкладки:
   левый — «Персонаж» (c.name, статы, таблицы навыков) /
   «Инвентарь» / «Игровые настройки»; правый — «Снаряжение»
   (одетые + быстрые слоты) / «Магазин» / «Квесты».
2. ГЕОМЕТРИЯ ПОД fs-btn: .fs-btn — fixed right:12/bottom:12,
   z-15, высота ≈33px, ДЛИННАЯ подпись «⛶ выйти из полного
   экрана» ≈217px. bottom:56px — нижняя кромка панели ВЫШЕ
   верхней кромки кнопки (12..45px) в обоих состояниях подписи;
   раскладка терпимая к отсутствию кнопки (нет Fullscreen API).
   Структурный тест: bottom ≥ 56px.
3. DOM-КОНТРАКТ: ОДИН делегированный click на .char-panel;
   .cp-btn[data-skill] внутри <tr>; .cp-name/.cp-level/.cp-req;
   item-кнопки data-act — tests/ui-skills.test.js (000041)
   проходит БЕЗ ИЗМЕНЕНИЙ. Вкладки — отдельный класс .cp-tab,
   переключение — style.display (стаб не знает classList);
   форма/содержимое активного pane НЕ пересобирается в render()
   (focus игрока живёт).
4. НАСТРОЙКИ: новые экспорты GlobalSettings.META (генерация из
   Object.keys(SETTINGS) + таблица метаданных label/ед./step/
   границы — будущие ключи, напр. companion_xp_share серии
   000065, подхватываются автоматически; первый deepEqual-тест
   фиксирует ровно 8 ключей — добавление ключа ломает его
   осознанно) и GlobalSettings.DEFAULTS (frozen JSON-клон).
   Форма строится ОДИН раз в buildPanel; apply по change;
   кламп (steps_per_day int ≥ 1 — иначе while-бесконечность в
   addStep; move_interval_ms int ≥ 60 = MIN_MOVE_INTERVAL_MS,
   иначе «Ловкий шаг» умирает; дни/уровни int ≥ 1;
   combat-множители float > 0; combat_difficulty — enum);
   вложенные combat_difficulties.*.{hp,damage} — редактируются,
   не молча отбрасываются; сброс per-ключ и «сбросить всё».
   ПЕРСИСТЕНТНОСТЬ — РЕШЕНИЕ ЗАФИКСИРОВАНО: ТОЛЬКО НА СЕССИЮ
   (в сейв не пишутся; после перезагрузки — DEFAULTS);
   персистентность (data.settings, санитайзер 000029/000045,
   round-trip-тесты) — кандидат в отдельную задачу (save.js,
   000031).
5. LIVE-ПРИМЕНЕНИЕ: ядро читает SETTINGS в момент ВЫЗОВА
