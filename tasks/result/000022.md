# 000022: вынести описание мобов в JSON-файлы в каталог assets/mobs

Статус: выполнено. Тесты: 211 → 216 pass (новых 5).

## Что сделано

* **assets/mobs/000001–000036.json** — описание каждого из 36 типов
  мобов (все id из `MOB_TYPES` в src/combat.js; таблица `DUNGEON_MOBS`
  в src/dungeon.js — подмножество этих id, проверено тестом).
* Поля описания:
  - боевые (были в коде): `id, name, role, aggro, dmg, hp`, опц.
    `armor, fast, traits {poison, lifesteal, regen, debuff}`;
  - **`xp: { base, perLevel }`** — получаемый за моба опыт
    (`base + perLevel * уровень`; все мобы 8/4 — прежняя формула);
  - **`skills: [id]`** — ссылки на описания скилов `assets/skills`;
  - **`spells: [id]`** — ссылки на `assets/spells` (каталог появится
    с задачей 000023 — другая цепь; пока все массивы пусты);
  - **`loot: [{ item, chance }]`** — ссылки на предметы `assets/items`.
* **assets/mobs/schema.json** — схема каталога (enum ролей/агрессии,
  формат id, additionalProperties: false).
* **src/combat.js** — `MOB_TYPES` стало зеркалом JSON-каталога
  (source of truth — assets/mobs, паттерн предметов/навыков: под
  file:// браузер не может fetch() локальные JSON). Новый src-файл не
  создавался (ограничение: без изменений index.html). `makeMob`
  передаёт в юнит `xp/skills/loot` из описания; опыт победы считается
  из данных: `Σ round(xp.base + xp.perLevel * уровень)` — поведение
  боя и баланс (000027) не изменились.

## Проверки (тесты)

* Структура всех JSON по схеме, id уникальны и валидны.
* Зеркало в combat.js идентично JSON-каталогу (по каждому файлу).
* Все ссылки `skills` разрешаются в assets/skills, весь `loot` —
  в assets/items; `spells` проверяются, если assets/spells появится.
* Юнит в бою несёт `xp/skills/loot`; опыт за победу = данным описания
  (волк 5-го уровня → 28 опыта).
* Все id из `DUNGEON_MOBS` (каждый тип подземелья) есть в каталоге.
