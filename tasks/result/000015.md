# 000015: тесты соответствия JSON-файлов каталогов их JSON-схемам

Статус: выполнено полностью. Тесты: 338 → 364 pass (новых 26).

## Что сделано

Задача: добавить тесты, проверяющие соответствие JSON-файлов их
JSON-схемам для каталогов assets/{items, npc, skills, buildings}.
Выполнялась последней, после всех мержей — валидируется финальное
состояние каталогов (в items — 32 предмета, включая 8 книг/свитков,
добавленных задачей 000013).

* **tests/json-schema.js** (новый, CommonJS, только для тестов, без
  внешних зависимостей) — ОДИН общий минимальный валидатор
  JSON-схем. Поддерживаемые ключи (ALLOWED_SCHEMA_KEYS):
  `type` (integer/number/string/boolean/object/array/null),
  `required`, `properties`, `additionalProperties`, `items`, `enum`,
  `const`, `minimum`, `maximum` (границы включены), `minItems`,
  `maxItems`, `pattern`, `anyOf` (≥1), `oneOf` (ровно 1). Семантика —
  как у валидатора, который уже стоял в тестах npc-data/spells/craft
  (копии были идентичны по байту). Экспорт: `validate`,
  `validateData` (→ массив ошибок), `schemaKeys` (обход ключей схемы),
  `actualType`, `ALLOWED_SCHEMA_KEYS`.
* **tests/assets-schemas.test.js** (новый) — 26 тестов:
  * 10 самопроверок валидатора: каждый ключ — позитивные и
    отрицательные случаи, границы minimum/maximum/minItems/maxItems
    включены, integer ≠ number, путь вложенных ошибок (arr[1].v),
    oneOf с двумя подходящими вариантами = ошибка;
  * на каждый из 4 каталогов (items, npc, skills, buildings):
    - schema.json существует и использует только ключи
      ALLOWED_SCHEMA_KEYS (рекурсивный обход, включая под-схемы
      properties/items/oneOf/anyOf);
    - файлы 000001.json … N.json строго подряд, каталог не пуст,
      чужих файлов нет;
    - каждый файл валиден по schema.json;
    - отрицательный контроль: удаление обязательного поля и добавление
      лишнего поля ловятся (страховка от «немой» валидации — если
      валидатор/схема сломается, тест упадёт, а не промолчит).

## Ключевые решения

* **Схемы править не пришлось.** Все 129 файлов (items 32, npc 10,
  skills 37, buildings 50) проходят существующие schema.json без
  единой ошибки — финальное состояние каталогов согласовано со
  схемами. Проверено до добавления тестов и зафиксировано тестами.
  Единственная близость к границе: items 000024 (phoenix_feather)
  `weight: 0.05` = minimum схемы (граница включена — валидно).
* **Общий валидатор вместо копий.** В tests/npc-data.test.js,
  tests/spells.test.js, tests/craft.test.js уже были три идентичные
  встроенные копии валидатора (созданы черновиками задач с пометкой
  «задача 000015: минимальный валидатор»). После создания общего
  модуля копии заменены на `require('./json-schema.js')` — только
  определения удалены, сами тесты не трогались, поведение не
  изменилось (364 pass).
* **Схема skills — oneOf primary|secondary**: в отрицательном
  контроле обязательные поля берутся из первого варианта oneOf;
  лишнее поле не принимается ни одним вариантом (у обоих
  additionalProperties: false) → oneOf не совпадает → ошибка.
* Тесты не фиксируют точное число файлов (оно держится зеркалами
  src/*-data.js и тестами каталогов) — только сквозную нумерацию,
  чтобы добавление данных не ломало валидационные тесты.

## Ограничения

* Валидатор покрывает только ключи ALLOWED_SCHEMA_KEYS (это
  сознательное ограничение, зафиксированное в SPEC.md и в тестах
  «схема — только ключи минимального валидатора»); если в схемы
  добавят новые ключи (not, if/then, $ref…), их надо добавить в
  валидатор и в ALLOWED_SCHEMA_KEYS — тест «ключи схемы» это
  поймает.
* Каталог assets/npc валидировался и ранее (tests/npc-data.test.js);
  теперь он валидируется и общим тестом — покрытие дублируется
  намеренно (общий тест — единая точка проверки всех 4 каталогов).
