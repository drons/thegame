## Решения (зафиксированы в memory/000086-squad-panel.md)

1. **ОТДЕЛЬНЫЙ глобальный оверлей `G.squadUI`, НЕ вкладка панели
   персонажа** — решение ПО ИТОГУ смерженной 000051 (memory §1):
   ТЗ фиксирует хоткей KeyC (у вкладки хоткея нет), 000130 сделал
   вкладки саморегистрирующимися модулями (новый файл + script-тег
   — за пределами ТЗ-файлов), состав панели персонажа ЗАПИНЕН
   tests/ui-panel.test.js, 000083 §9 проектировала именно оверлей.
   Стиль/геометрия — 1:1 .char-panel (паттерн панели персонажа).
2. **rosterSummary — чистая, efirData — ПАРАМЕТР** (не чтение
   G.efir): контракты 000081/000038 + node-тест без efir.js.
3. **ЖИВЫЕ ссылки через init** (roster/efir) — мутации
   hire/dismiss/payWages/addEfirXp видны без re-wiring; onChange —
   saveNow (хук в main.js; литерал saveNow в ui.js отсутствует —
   пин 000100).
4. **KeyC остаётся** (не занята — сверено с 000048/000052; ТЗ:
   «если заняли — выбрать новую» — не заняли); в COMBAT_KEYS/
   controls НЕ добавлялась (в бою [C] не боевое действие).
5. **Закрытие при старте боя — 3×** (паттерн 000096): боевой
   оверлей z-20 непрозрачный, панель под ним устаревает (000087).
6. **XP-бар строки Эфира — по контракту 000081 §6** («000086: …
   xp-бар до xpForNext(level)»); данные только (efir.xp +
   G.xpForNext), новых механик нет.
