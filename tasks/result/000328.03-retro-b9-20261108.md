Где: src/ui.js:17 `const G = globalThis.Game` (снапшот ссылки на объект Game на момент загрузки модуля); `runeOf` (:749) читает `G.RunesData` каждое обращение → ПРЯМАЯ замена свойства `Game.RunesData = …` НА захваченном объекте ui.js видит. Невидима замена самого `globalThis.Game` — именно это делают все *-data.js UMD (`root.Game = Object.assign({}, root.Game, {…})` — runes-data.js:5, visuals-data.js:22, …; каждый пересоздаёт объект-копию; ловушка 000038). Практически «заменить каталог» в этом коде можно только этим идиомом (пересозданием Game) — для него вывод верен; буква «объекта RunesData» — лишняя. СЛЕДСТВИЕ: нулевое — тесты замену RunesData не делают, рантайм-путь не затронут; риск — будущий тестовый автор решит, что рабочий способ (`G.RunesData = фикстура`) не работает. 2. **Микро-асимметрия резолверов за заявлением «строка есть ⟺ иконка есть»** [структурно; на диске безопасно]. Где: src/ui.js:767 `runeIconsOf` гейтится ТОЛЬКО `runeOf(id)` (резолв по id), тогда как :757 `runeLine` дополнительно требует `typeof r.название === 'string' && r.название` — гипотетическая каталожная запись «валидный id + пустое/не-строковое название» дала бы иконку БЕЗ строки (нарушение двунаправленности). Недостижимо на диске: assets/runes/schema.json — required + `pattern: ^\S(.*\S)?$` для названия (проверено чтением схемы) + свип валидности всех 55 (runes-catalog-000328.01 T1); биекция id↔иконки пересчитана — 55↔55.
