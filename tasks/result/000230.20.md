## Что сделано

1. **src/items.js equip() — ЕДИНСТВЕННЫЙ кодовый ханк** (ветка отказа,
   ~+5/−1): note-ветка `{ok:true, note:'вернуть <prev> не удалось: …'}`
   заменена ОТКАТОМ — `eq[slot] = prev; eb[slot] = prevBonus;
   if (pos >= 0) inv.slots.splice(pos, 0, taken); syncEquipmentMirrors(eq);
   return { ok: false, reason: back.reason }`:
   * prev восстанавливается в слот (включая бонус — prevBonus захвачен
     ДО мутаций, restore точный);
   * new возвращается в ОРИГИНАЛЬНУЮ позицию inv.slots (`splice(pos, 0, …)`
     — «как был», порядок слотов = детерминизм сейва 000031; push-в-конец
     отклонён);
   * syncEquipmentMirrors ОБЯЗАТЕЛЕН на откате (eq[slot] мутирован;
     зеркала weapon/armor D-01; прецедент M11-фикса 000230.02 §9);
   * reason — ПАССТРУЧНО из back.reason, единый словарь checkAdd с
     unequip-failsafe ('слишком тяжело (лимит веса)' | 'нет свободных
     слотов инвентаря');
   * success-путь БИТ-В-БИТ (инвариант ТЗ «НОЛЬ изменений»); форма
     `{ok:true, note}` УБИРАЕТСЯ навсегда (единый UI-контракт
     {ok, reason}; ui.js flashNotice(r.reason) — без правок).
2. **JSDoc** equip (items.js): «все или ничего» + `@returns
   {ok:true, slot, item}|{ok:false, reason}`; allyEquip (companions.js):
   `@returns` без note-формы, «некуда положить — откат swap».
   КОД allyEquip НЕ МЕНЯЕТСЯ (pass-through подхватывает фикс).
3. **Тесты** (красный коммит e495b1a): РЕ-ПИН M11 in-place (hero-путь,
   vm, fixture-каталог; setup без изменений 29/30 кг) + РЕ-ПИН I2 in-place
   (ally-путь через allyEquip, vm, реальный каталог; setup без изменений
