## F1 (major). Append-only против HEAD — защита до коммита, а не «НАВСЕГДА»

Текст зуба обещает обратное — `tests/items-rename-000318.08.test.js:866-873`:

```
'… — существующие «номер → id» заморожены НАВСЕГДА (виртуальные'
+ ' номера позиционных пинов и канона c1); дописывать pad(N+1)…'
+ ' в конец — единственная легальная правка'
```

Механизм (`:157-172`) сверяет диск с `git show HEAD:tests/scripts/items-num2id-000318.08.json`.
Значит пере-нумерация, **попавшая в коммит**, становится новым «HEAD-эталоном» и
красным больше не является. Доказательство в чистой копии `/tmp/b24ctl` (tip = мастер),
подмена значений двух НЕ-spot строк `000300 ↔ 000301`:

```
=== STEP 1: swap НЕ закоммичен (HEAD = 2aa15e8d) ===
not ok 24 - 000318.08 T11: реестр … — APPEND-ONLY против HEAD …
# tests 245   # pass 244   # fail 1          ← поймал ровно один зуб, как и задумано
=== STEP 2: тот же swap закоммичен (HEAD содержит его) ===
# tests 245   # pass 245   # fail 0          ← машина слепа: ложное «номер→id» стало нормой
```
(скоуп STEP 1/2: `items-rename + items-registry-unfetter + canon-items-sync +
items.test.js + items-weapon-000321.01` — 245 тестов в обоих прогонах.)

Почему это достижимо на практике: реестр — единственный в репозитории JSON, который
правит **каждая** items-волна, и он же — место конфликтов при ручной ре-базе/`sync-amend`
оркестратором (прецедент формата: `memory/000385` «ff 000320.28 ре-пинил файл»,
`tasks/CLAUDE.md`-поток с ручным мержем). Если в такой правке одна пара сдвинется,
мастер получит устойчивую ложь: виртуальный номер `000300` будет указывать не на
`gold_brace`, позиционные пины волн (`.321.01`…) и канон c1 продолжат быть зелёными,
а откатить постфактум нельзя (Р.3). Единственные постоянные якоря `num → id` —
10 spot-строк (items-rename:817-834) и диапазоны собственных канареек волн; 000300/000301
вне их.

Вердикт: **major** (не активный баг, а дыра в гарантиях, заявленных как вечные).
Кандидат в исправительную задачу — К1.

## F2 (major). Зуб правдивости памяти: три режима неверной покрытости

Зуб: `tests/items-registry-unfetter-000379.test.js` Т1 (`:79-116`), границы блока —
`/С 000318\.08 в волнах:/` … `/С 0003\d\d\.\d\d в волнах:/`; запреты —
`/НЕ\s+расширять/` (`:84`) и `/замороженн/i` (`:91`).

**(а) Настоящая ложь проходит.** Правка памяти (копия): в items-clause добавлена
фраза `Реестр заморожен ЦЕЛИКОМ и не растёт вовсе` (ни `/замороженн/i/, ни
`/НЕ\s+расширять/` её не матчат):

```
=== A: lie «заморожен ЦЕЛИКОМ и не растёт вовсе» ===   A applied: True
# pass 3   # fail 0
```
То есть ровно та директива, ради снятия которой создавалась задача, проходит зуб
в любой форме, отличной от суффикса «-енн*»/«замороженный».

**(б) Честная цитата красится.** В тексте памяти историческая директива уже
цитируется, но строчными (`прежняя директива «не расширять» была ложна`,
`memory/000318-asset-rename.md:286-287`) — зуб её не видит. Перевод цитаты в
орфографически корректный верхний регистр (как она записана в `:297-300` у skills,
в `tasks/done/000379.md:11` и во всех result-артефактах) красит зуб как «ложь»:

```

# pass 2   # fail 1
```

**(в) Граница блока ломается на чужом перефразе — с ложной атрибуцией.** Если
соседний (skills-)clause будет озаглавлен иначе — `С 000318.09 (навыки) в волнах:`
(единственный регэксп-эндпоинт перестаёт матчить), — items-блок «съедает» текст
skills, гдеuppercase-«НЕ расширять» и «замороженный реестр» живут законно

Сообщение при этом обвиняет **items**-реестр — волну 000387 разбираться придётся с

## F3 (minor). Self-gate T12 обходится двумя формами

Зуб (`items-rename:881-903`) regex-ом `assert\.equal\([^\n]*?\.(?:length|size)\s*,\s*\d+`
плюс проверка имени-идентификатора `EXPECTED_COUNT` (concat-сборка). Провозглашённое
в имени теста обещание шире реализованного: «…нет замороженного живого счётчика
каталога (**ни имени-константы**, ни assert.equal(<…length|size>, <литерал>))»
(`:879-881`), а `tasks/result/000379.md:152` — «возврат замороженного литерала
красится машиной».

```
=== E2: assert.ok(registryKeys.length === 914) ===      → # pass 12  # fail 0   (зуб молчит)
=== H2: const TOT_B24 = 914; assert.equal(registryKeys.length, TOT_B24, …) ===
                                                        → # pass 12  # fail 0   (зуб молчит)
=== G:  assert.equal(registryKeys.length, 914, …) (инлайн-литерал) ===
        not ok 12 - 000318.08 T12: self-gate …            # pass 11  # fail 1   (пойман)
```
(Все пробы — в `/tmp/b24ctl`, после каждой `git checkout --`; «hoisted»-проба
изначально давала TDZ-красный T1, переснята с корректным порядком объявлений.)

Последствие не катастрофично (такой литерал сам покраснеет на следующем росте —
это T1), но это ровно тот случай, когда «замороженный счётчик» возвращается в
мигрированный файл без машинного запрета; сообщение «сам этот файл дальше не
правится» (items-rename:241-253) при этом остаётся зелёным.

Вердикт: minor. Кандидат — К3.
