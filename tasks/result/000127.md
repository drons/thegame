## Инварианты (рефакторинг без смены поведения)

* **Детерминизм**: в diff НЕТ новых вызовов RNG (grep
  `_rng|Math.random|mulberry32|hash2|generateSeedPixels` — пусто);
  порядок и КОЛИЧЕСТВО Game-вызовов с RNG — те же: вход —
  createDungeon → memory.get → contentValid → generateDungeonContents
  (→ createMover); шаг — mover.step → моб → openChest → wanderStep
  (ровно раз на успешный dungeon-шаг; в ветках combat/exit — нет);
  город — без RNG.
* **Осознанное переупорядочивание (D9, зафиксировано в контракте)**:
  применение наград сундука (hero/log/hudFlash/playerUI) теперь
  ПОСЛЕ `G.wanderStep` (в main.js — до). Состояния дизджойнтные,
  порядок/число RNG-вызовов не меняется — наблюдаемого отличия нет.
* **Сейвы**: форма ds поле-в-поле (worldKey/prevX/prevY/…);
  collectSaveData не содержит dungeonState; точки saveNow() те же
  (frame после входа, exitDungeon, exitCity; в ветке сундука — нет).
* **HUD/flash — побайтово**: `'Вы вышли из ' + name + '.'`,
  `'Сундук: +' + gold + ' золота' + itemMsg`, `name + ': вход.'`,
  `hudFlashUntil = performance.now() + 5000` — строки дословно;
  hudUpdate не правился (000129). Существующие HUD/структурные
  ассерты (.cp-*, строки HUD) — фиксаторы, прошли БЕЗ правок.
* **[E]-гарды**: ключевые строки keydown-гардов dungeonUI.isActive и
  toggleNpcDialog/onBuildingAction НЕ тронуты; гард
  combatUI.isActive — в том же логическом месте (первая строка move),
  вычисляется проводкой в момент нажатия.
* **UMD-ловушка**: locations.js ДО main.js — пин index-order;
  загрузка модуля чистая (LOC-11/LOC-12), vm-песочницы
