## Решения и отклонения от файла задачи

1. **Плоское Game.ITEMS сохранено** (в отличие от Game.VisualsData):
   у items-data.js контракт «плоский namespace» — items.js и все
   vm-цепочки читают G.ITEMS; смена на ItemsData дала бы правки
   потребителей ради нулевой пользы. Для visuals — НОВЫЙ модуль,
   namespace Game.VisualsData введён сразу (своих потребителей у
   литерала VISUALS, кроме sprites.js, не было).
2. **Гард visuals — тихая деградация до пустого каталога** (не
   fallback-копия, не console.error): vm-песочницы combat-ui/map.test
   грузят sprites.js без data-модулей; fallback-копия вернула бы
   дублирование данных (анти-дрейф grep-тест), console.error — шум в
   выводе npm test каждый запуск. Паттерн — 000058 (dungeon.js).
3. **НАХОДКА: текст задачи устарел по числу предметов** — «32
   записи» на момент аудита; на актуальном master (ребейз ветки на
   483df47) — 42 (каталог рос: 000044 и позже). Тесты и скрипты
   считают число от каталога, хардкода нет. visuals — 13, как в задаче.
4. **Детерминизм подтверждён двояко**: (а) существующие golden
   (разброс VISUALS_SEED по тайлам, стоки/seed торговли) без
   изменений; (б) новый тест «цепочка index.html» — tileVisuals НЕ
   пуст на сетке трав, т.е. каталог реально подхвачен, а не «вакуумно»
   (само по себе «ожидается пусто = фактически пусто» бы прошло).
5. **Единый интерфейс sync-скриптов = конвенция имён**: sync-all.test.js
   (000054) подхватывает sync-*.js автоматически — CI-дрейф-гейт
   заработал для items/visuals без единой правки в CI.
6. Сейв v1: id предметов НЕ менялись (npcStocks/quests по id —
   000031), визуалы в сейв не пишутся (детерминированный разброс от
   seed+id) — версию сейва НЕ поднимали.
