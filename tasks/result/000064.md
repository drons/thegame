## Ключевые проектные решения (зафиксированы в SPEC «Эффекты
построек», подзадачах и memory)

1. МОДЕЛЬ ВЗАИМОДЕЙСТВИЯ — единый оверлей `Game.buildingUI`
   (аналог `Game.npcUI`): [E] = список действий («Диалог» через
   npcUI + эффекты из `особые_параметры`); постройка без NPC и без
   эффектов — ничего (как сейчас). Реестр эффектов — чистый модуль
   src/building-effects.js (создаётся единый в 000071).
2. «РАЗ В ДЕНЬ» — `canUseToday` + dayMap-сериализация; состояние в
   НОВЫХ разделах сейва — неломкое расширение v1 (версию НЕ
   поднимать, правило 000031; паттерн 000029: битый раздел → warn +
   отброс); дни — АБСОЛЮТНЫЕ (fastForward без слушателей); «сброс»
   ничего не сбрасывает. Ловушка-прецедент `_lastUnkillDay`
   (combat.js:321, вне сейва) — новое состояние обязано быть в
   сейве (тест-фиксатор). Счётчики — на ЭФФЕКТ ('x,y:effectId'),
   не на здание (фонтан: исцеление лимитировано, монета — нет).
3. ОБЪЁМ/ГЕНЕРАЦИЯ — ловушка детерминизма: новые `map_index`
   (13→N) МЕНЯЮТ слот почти на всех тайлах (% 13 → % N) — ЗАПРЕЩЕНО
   (golden-тесты, сохранённые позиции в чужом контексте). Стратегия:
   `hash % 13` не меняется; подтипы слотов 8/9/10/11/12 — ВТОРОЙ
   hash (seed XOR константа) по долям из каталога
   (`особые_параметры.размещение {слот, доля}`); `tileAt` получает
   `buildingId`; слот/footprint/вход/спрайт — без изменений.
   Слот 9: вход 80 / развалины 20 — развалины постройка, не вход
   (`maybeEnterDungeon` — по buildingId; сознательное уменьшение
   входов на 20%).
4. ХРАМЫ ЧЕРЕЗ buildingUI, НЕ ЧЕРЕЗ ДИАЛОГ: enum действий NPC-
   диалога жёсткий (торговля|обучение|квесты|подсказка) — схему
   NPC не расширять (коллизия с 000065). У храма солнца NPC УЖЕ
   ЕСТЬ (elder Элдира, постройки [20, 36]) — «Диалог» первое
   действие; жрецов луны/горы в каталоге НЕТ (исправление
   заключения аналитика «жрецов нет» — для солнца это неверно).
5. СВЯЗЬ С НАВЫКАМИ: рунопись — через существующий `runePowerMult`
   (player.js:240) — не изобретать новый derived; «Удача» — НЕ
   навык в коде (skills-data.js) — монета фонтана на Ловкость,
   предмет колодца — на Тать (замена «Удачи» зафиксирована в
   SPEC как плейсхолдер).
6. ТЕЛЕПОРТ: ближайший по CHEBYSHEV в R=100, тай-брейк по hash,
   одиночный — «спит» (сообщение); активация — разовая оплата
   золотом; скан — только при первом подходе (кэш в сейве).
7. МАГИЧЕСКИЙ КРУГ/ЗАБРОШЕННЫЙ ХРАМ: единый ролл (tile, day) —
   сундук 60 / босс 30 / реликвия 10; босс — только из
   СУЩЕСТВУЮЩИХ MOB_TYPES (новый рецепт GROUP_RECIPES), реликвия —
   существующие id assets/items.
8. МОСТ/ВОРОТА (id 50): отдельного объекта на глобальной карте НЕТ
   (проходы = стационарные группы MOB_GROUP_TYPES, генерация
   независима от построек); элемент городов (000052); id 50 —
   резерв.
9. МИНИКАРТА (башня) — ОТСРОЧЕНА: 000093 — только данные
   `explored` (компактный формат, радиус R=20 → ≤1681 ключей на
   башню) + HUD-индикатор; UI — отдельная задача при потребности.
10. ДАННЫЕ: все параметры эффектов — `особые_параметры` каталога
   (source of truth, 000053); JS-зеркало src/buildings.js —
   синхронно (вручную до 000055, sync-скриптом после).
