## Что сделано

1. **src/dungeon.js (+152/−6) — единственный src-файл**:
   * **Размер**: `DUNGEON_SIZE_CAP = 63` + чистая экспортированная
     `dungeonSizeFor(base, depth) = min(CAP, round(base·1.1^(depth−1)))`
     — СТОРОНА ×1.1/этаж (ПЛОЩАДЬ ×1.21); рост ТОЛЬКО в коде от базы
     JSON (assets/dungeons не тронуты; cap = максимум схемы «размер»
     5..63 — дизайн-решение, перформанс НЕ лимитирует: W=63 → 3.0 мс,
     W=128 → 2.6 мс, N=30). createDungeon: `W = dungeonSizeFor(
     DUNGEON_SIZE[type], depth)`.
   * **Уровни мобов**: `effLevel = player.level + (d.depth − 1)`
     (константа, 0 rng) — сдвиг БАЗЫ; группы = `max(1, effLevel ± δ)`;
     босс ABYSS = `max(1, effLevel + δ)` (000183 D-BOSS сохранён:
     rooms[last], occupied).
   * **Лут**: `nChests = 2 + floor(rng·4) + (d.depth − 1)` (+1 сундук/
     этаж, диапазон [d+1, d+4], ОДИН вызов rng как сейчас);
     `gold = round(10 + rng·20·(1 + 0.2·effLevel))`; item — uniform,
     шанс 0.4 НЕ меняется (редкость предметов = территория 000157).
   * **stairs-down**: `STAIRS_SALT = 0x53d10d53` + `stairsDownFor` +
     внутренний `bfsDistances` (4-соседство в порядке reachableFrom):
     max-BFS-дистанция от entrance среди FLOOR ∖ 5×5 safe
     (entrance/exit) ∖ клетка босса ABYSS; тай — min
     `hash2(x, y, STAIRS_SALT ^ d.seed)`, финальный тай min (y·W+x);
     БЕЗ rng (паттерн wallObjFor); fail-open → null (дегенеративные
     формы, JSDoc). Поле ФОРМЫ `d.stairsDown` — в createDungeon
     (после wallObjs), ЕСТЬ на всех depth ≥ 1; НЕ в contents:
     validateDungeonContents / секция сейва / версия сейва — не
     тронуты. Safe-зона depth>1 расширяется на 5×5 вокруг stairsDown
     (ТОЛЬКО depth>1 — бит-в-бит depth=1).
   * Экспорты: +4 additive (DUNGEON_SIZE_CAP, dungeonSizeFor,
     STAIRS_SALT, stairsDownFor).
