# Отчёт по задаче 000306

Урон/лечение заклинаний по степеням — значение зафиксировано в каталоге
`assets/spells`, хардкод-констант по степеням в коде не осталось.

## Что сделано

- **Каталог**: поле `множитель_степени` в 46 JSON (36 «урон» + 10 «лечение»):
  ст.1 → 1, ст.2 → 1.15, ст.3 → 1.3. Значения бит-в-бит прежней кривой
  `1 + 0.15·(степень−1)` (одни и те же double в IEEE754) — числовое поведение
  не изменилось. `schema.json` — опциональное свойство number 0.01..10
  (не в required; 121 прочий файл не тронут).
- **sync**: `scripts/sync-spells-data.js` — ключ в KEYS после `степень` +
  валидации exit 1 (обязательность у «урон»/«лечение», строгий рост значения
  в цепочке «база»); зеркало `src/spells-data.js` перегенерировано.
- **Код**: helper `spellTierMult` (фолбэк 1 = бит-в-бит степень 1) —
  ТРИ независимые копии (UMD-изоляция): `src/spells.js` (2 точки),
  `src/ally-spells.js` (2), `src/combat.js` (3: allyHeal, allyHealAction,
  efirCastAction). Итого 7 точек формулы вместо 4 из анализа — три пути
  в combat.js (союзное лечение/эфир-касты) зашиты goldens ст.2 и содержат
  ту же константу 0.15; без них цель ТЗ «без хардкод-констант по степеням
  в коде» недостижима. В `src/` констант `0.15·(степень−1)` не осталось
  (проверено grep).
- **SPEC**: `spec/spells.md` +7 (буллет «Урон по степеням» в H2
  «Совершенствования», пин 420→427), `spec/efir-spirit.md` line-neutral
  (147, щит-буллет дословно), формулы Эфира с `множитель_степени`.
- **Ре-пины**: spec-split (spells.md 427), efir-wording (формула лечения),
  000211.04-фикстуры (FIXTURE_SPELL/FIXTURE_BASE_SPELL получили поле —
  иначе новый sync-чек exit 1 убивал R4 tmp-репо); комментарии-лож в
  tests/spells/ally-spells/combat.
