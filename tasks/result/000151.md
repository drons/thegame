## Что сделано

1. **Новый чистый UMD-модуль src/combat-scale.js (+104)** —
   `Game.combatScale = { MAX_SCALE, computeBacking }`:
   * `computeBacking(baseW, baseH, dispW, dispH, dpr) → {w, h, sx, sy}`
     — красное ядро ТЗ, чистая функция «размер canvas/масштаб → размер
     отрисовки»: `sx = min(MAX_SCALE, max(1, dispW·dpr/baseW))`
     (sy симметрично), `w = round(baseW·sx)` — ЦЕЛЫЕ;
   * НЕДАУНСКЕЙЛ (max от 1): маленькие экраны/мобайл — бэкинг 336,
     поведение до 000151 (не ломать); кап MAX_SCALE = 8 (GOLDEN-ПИН):
     бэкинг ≤ 336·8 = 2688 px (~29 МБ RGBA) — только для 5K+;
   * фолбэки: base → 336, disp (на оси) → 1:1, dpr → ×1 (безопасно);
     ноль побочных эффектов, детерминирована;
   * загрузка чистая (0 require/DOM/чтения Game при загрузке — паттерн
     cities.js/building-effects.js, 000038/000053); тег в index.html
     (+6) ПОСЛЕ sprites.js, ДО combat-ui.js (UMD-ловушка: combat-ui
     снимает Game один раз, читает G.combatScale лениво; порядок
     закреплён пином tests/index-order.test.js).
2. **src/combat-ui.js (+123/−18)** — РЕНДЕР-ПУТЬ (боевое ядро
   combat.js НЕ тронуто — логика хода/детерминизм/RNG не затронуты):
   * `measureBacking()` — rect (`getBoundingClientRect`, try/catch) +
     dpr (typeof-гард → 1) → computeBacking; отсутствует
     Game.combatScale (битый порядок) → console.error ОДИН раз + 1:1
     (деградация, бой играбелен — паттерн 000081);
   * `build()` — ПОСЛЕ appendChild: бэкинг = w×h, sx/sy, getContext
     ровно ОДИН раз ПОСЛЕ присваиваний canvas.width/height;
   * `render()` — в НАЧАЛЕ `if (sx≠1||sy≠1) g2.setTransform(sx,0,0,sy,
     0,0)` (АБСОЛЮТНЫЙ, идемпотентен, самовосстанавливается после
     сброса контекста при resize; при 1:1 вызова НЕТ — пины индексов
     drawCalls бит-в-бит, якорь A1); всё далее — в логических
     единицах (клетки × CELL), 5 строк canvas.width/height переведены
     в логические W/H (база, фон, сетка, кламп миниполосы героя) —
     движок растрирует SVG в drawImage в ЦЕЛЕВОМ device-размере
     (резкость на любом b);
   * клик — нормализация по ЛОГИЧЕСКОМУ полю (baseW = c.width·CELL,
     D5): при динамическом бэкинге старая формула (canvas.width/rw)
     включала бы масштаб — промах на s клеток; при s = 1 — бит-в-бит;
   * `window.addEventListener('resize', onResize)` — top-level рядом с
     'keydown' (один раз при загрузке, guard isActive внутри, в
     finish() НЕ снимается): переизмерить → при смене b →
     canvas.width/height + sx/sy + render().
3. **CSS экрана боя НЕ тронут** (000124: `min(100vh−32px, 100vw−304px)`
   и т.п., aspect-ratio, pixelated) — бэкинг следует за CSS
   автоматически; dpr=2 входит в формулу (цель ТЗ — в основном
   Retina-десктоп/планшет).
