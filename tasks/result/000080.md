## Что сделано

1. **src/combat.js** (+534/−51) — ядро фреймворка:
   * `makeAlly(data, idx, moraleMult = 1)` (экспортирован, чистая функция) —
     союзник ВСЕГДА 1×1, side 'ally'. Формулы статов — паттерн makeMob БЕЗ
     множителей сложности (combat_difficulties — для врагов) и без hasLeader:
     maxHP = max(1, round((8+4·ур)·hp·hpРоль)) (hpРоль: support 0.7, shield
     1.8, иначе 1.0), damage = max(1, round((2+0.7·ур)·dmg·moraleMult)),
     armor = (armor||0) + floor(ур/10). Явные maxHP/damage/kind/attrs/id —
     обход формулы (данные Эфира, 000081). `damageTakenMult: 1` (раунд
     ревью 1: тотальная модель урона dealDamageToMob умножает на это поле —
     без него уронный каст ставил союзнику hp = NaN). `u.moraleMult`
     хранится на юните — 000112/000113 (урон-касты) читают, не пересчитывают.
   * `makeMob` — добавлено явное поле `side: 'mob'` (на логику не влияет).
   * `createCombat({… , allies})` — новый параметр `opts.allies` (массив
     data для makeAlly; [] по умолчанию). Мораль: `moraleMult = 1 +
     P.derived(p).companionMoraleBonus` (навык ПРЕДВОДИТЕЛЬ, src/player.js,
     +5%/уровень) применяется к damage ВСЕХ союзников. НЕ вражеский hasLeader
     (бафф ГРУППЫ МОБОВ — другая сущность; регрессионный тест).
   * `rectOf/rectDist` — манхэттен-ГАП между прямоугольками (0 —
     пересечение/соседство по оси). Формула gap-based: первый вариант
     «дистанция до дальнего края» ломал бой 2×2-демоном против игрока (моб
     не подходил) — исправлено до мержа. `stepToward/stepAway` → тонкие
     обёртки над `stepTowardRect/stepAwayRect` (порядок осей моба и
     тай-брейк не тронуты — бит-в-бит).
   * `allyStepToward(c,u,r)` — шаг союзника к цели: СНАЧАЛА ось x, потом y,
     первая rectFree-клетка. `allyStepAway(c,u,r)` — порядок →, ↑, ↓, ←;
     первая rectFree-клетка, где rectDist выРОСЛО. Оба зафиксированы
     красными тестами (пinned).
   * Модель целей: `livingMobs`/`livingAllies` (фильтр side), `nearestMob` —
     дополнительно отбрасывает не-mob, `nearestEnemy(c,u)` — ближайший живой
     МОБ от союзника (тай-брейк — порядок c.units), `nearestPlayerSide(c,u)` —
     **ключ к гибельности союзника**: ближайшая цель СТОРОНЫ ИГРОКА от моба =
     игрок ИЛИ живой союзник (тай-брейк — игрок); возврат
     `{x,y,w,h,isPlayer}|{x,y,w,h,unit:ally}`. При 0 союзников — всегда игрок.
   * `mobAct` переписан на closure-ы `stepToTarget/stepFromTarget/attackTarget`
     поверх nearestPlayerSide: `attackTarget = target.isPlayer ? mobAttack
     (игрок) : mobAttackAlly(c, u, target.unit)`. Все ветки ролей (melee-
     подход, ranged-дистанция, support-лечение, leader, default-цикл) — через
     них; поведение при 0 союзников бит-в-бит.
   * `mobAttackAlly(c,u,t)` — бросок hitChance, тик ослабления,
     dealDamageToAlly; трейты моба (яд/вампиризм/дебафф) в v1 — ТОЛЬКО
     против игрока.
   * `dealDamageToAlly(c,t,raw)` — max(1, round(raw) − armor); гибель:
     hp=0, alive=false, лог «X пал в бою!», клетка освобождается; НИКАКОГО
     checkVictory/поражения. Никаких c.ps-эффектов (щит/блок — игрок, v1).
   * `checkVictory` — лут/опыт/«defeated» ТОЛЬКО за `side==='mob'`.
   * `allyAttack(c,u,t)` — т = МОБ: ролл `c._rng() >= hitChance(u.level, 0,
     t.level, 0)` → «промахивается»; иначе `dealDamageToMob(c, t, u.damage)`
     (2-й аргумент — ПОЛУЧАЮЩИЙ; ошибка «бьёт себя NaN» была зафиксирована в
     ревью) → «X бьёт Y: N.»
   * `allyHeal(c,u)` — лечение support: каталог ЛЕНИВО из
     `combatInternals.allySpells` (нет → false → melee-фолбэк); спелл —
     сильнейшая степень «лечение» из СПИСКА СОЮЗНИКА u.spells; цель —
     САМОГО РАНЕНОГО пула [игрок, …живые союзники] (мин. доля hp/maxHP;
     frac ≥ 1 исключается, включая «пере-HP»; тай — порядок пула, игрок
     первым); формула лечения spells.js с attrs СОЮЗНИКА
     `round((4 + 0.5·attr + ур)·(1 + 0.15·(степень−1)))`; игрок — P.heal,
     союзник — прямой hp. Лог «X лечит Y (+N).»
   * `allyAct(c,u)` — ИИ союзника (аналог mobAct): цель nearestEnemy, врагов
     нет → return. **ranged**: d ≤ 1 — ПАНИКА (цикл `while (dNow ≤ 2)
     allyStepAway`, лог «отступает.» независимо от успеха шага — одного шага
     недостаточно: за ход враг тоже сдвинется); 1 < d ≤ RANGED_MAX_DIST (4) —
     атака в даль БЕЗ сближения; d > 4 — «кайтинг»-шаг allyStepAway (pinned).
     **support** — allyHeal, иначе melee-ветка. **melee/shield/swarm/фолбэк**
     — d ≤ 1 → allyAttack, иначе movePerTurn × allyStepToward.
   * `endPlayerTurn` — `u.side === 'ally' ? allyAct : mobAct`; инвариант 000036

   * `buildTurnOrder` — `['player', …живые союзники, …живые мобы]` (порядок
     c.units; мёртвые/fled исключены).
   * `placeAllies(c, allies)` — расстановка БЕЗ RNG (поток c._rng не

## Решения (зафиксированы в memory)

1. **Одна модель союзного юнита (side 'ally') для Эфира и наёмников** —
   явное решение по Эфиру (000035): 000081/000082 различаются только
   данными (id/kind/'ether', явные maxHP/damage, attrs) — фреймворк общий.
2. **Ленивый каталог заклинаний через combatInternals.allySpells** (не
   require('spells.js') из combat.js — циклическая зависимость; UMD-ловушка
   000038: порядок загрузки combat.js → spells-data.js → spells.js).
   Один объект — одна ссылка (node-require кэш / Game.combatInternals);
   без каталога — melee-фолбэк, бой не падает.
3. **Гибельность союзника — через nearestPlayerSide** (моб бьёт ближайшую
   цель СТОРОНЫ ИГРОКА, игрок ИЛИ союзник, тай-брейк — игрок). При 0
   союзников всегда игрок → mobAct бит-в-бит (rectDist(u, игрок 1×1) ≡
   unitDist). Альтернатива (мобы «видят» только игрока) делала союзников
   неуязвимыми.
4. **rectDist — gap-based** (0 — пересечение/соседство по оси). Первый
   вариант «дистанция до дальнего края» ломал бой 2×2-демоном (моб не
   подходил) — найден до мержа.
5. **Мораль ≠ hasLeader**: companionMoraleBonus (ПРЕДВОДИТЕЛЬ, +5%/уровень)
   — множитель damage ВСЕХ союзников, хранится u.moraleMult (000112/000113
   читают); вражеский hasLeader (LEADER_DMG_MULT — бафф группы мобов) не
   тронут, регрессионный тест.
6. **Гибель союзника ≠ поражение**: dealDamageToAlly — alive=false, лог,
   клетка освобождается; checkVictory считает только side==='mob'.
   Лут/опыт — только за мобов.
7. **Расстановка без RNG** (детерминизм: один сид → одна расстановка; поток
   c._rng боя не меняется): якоря вокруг игрока + скан снизу вверх;
   throw при нехватке места (как у мобов). ПОРЯДОК в createCombat зафиксирован:
   placeAllies ДО concat и ДО generateObstacles (раунд ревью 2).
8. **ranged-союзник держит дистанцию жёстко**: д≤1 — отступление ПОКА d ≥ 3
   (один шаг не спасает — за ход враг сближается), d>4 — кайтинг-шаг
   allyStepAway. Оба поведения pinned красными тестами (в т.ч. «математически
   невозможный» шаг из (5,4) в (6,4) к волку в (0,0) — поведение зафиксировано
   тестом, менять без изменения теста нельзя).
9. **Трейты мобов против союзников (яд/вампиризм/дебафф) — НЕ v1**
   (mobAttackAlly — только бросок/ослабление/урон); эффекты c.ps (щит/блок/
   «Несокрушимость») — только на игрока (v1).
10. **Отказ игрока цельсить союзников — во ВСЕХ точках прицеливания**:
    playerAttack/playerSpell/canDoAction/playerSelectTarget + evalSpell
    (spells.js) — раунд ревью 1 (evalSpell был единственным путём без
    side-проверки, каст ставил hp = NaN).
