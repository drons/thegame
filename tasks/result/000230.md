### 5.2 Решения D1–D8

* **D1** — один kind `armor` для всех бронепчастей
  (различает `slot`), чтобы ассортимент магазинов (виды
  каталога построек) не трогать; новый subtype оружия
  `staff`; новые kind: `shield`, `artifact` (левая рука),
  `tool` (правая рука), `ring` (пальцы). Новые kind ВСЕГДА
  с явным `slot` (slotOf-фолбэк покрывает только
  weapon→right_hand, armor→torso — items.js).
* **D2** — магазинная торговля НЕ расширяется новым видом:
  armor-ассортимент (Бронник/Универсам, SHOP_KINDS_FALLBACK
  items.js:877-883) покрывает все бронепчасти;
  shield/artifact/ring/tool — в ассортимент `weapon`
  (Оружейная/Универсам). Таблица `виды` — без изменений.
* **D3** — редкость экипировки — поле `rarity`
  (common/rare/epic/legendary/impossible), ОТДЕЛЬНО от
  `tier` (1..4, только реагенты, 000157.01 — источник тира
  залежей dungeon.js:212).
* **D4** — affixes: `{type:'skill', skill, amount}` /
  `{type:'free_cast', spell}`; валидатор проверяет ФОРМУ
  id (прецедент spell_scroll items.js:159-166),
  каталожность — тестом. ЕДИНАЯ точка масштаба — derived():
  (1 + Σ affix skills[id]), clamp ≥ 0 базового нуля.
  free_cast = мана 0, действие «Заклинание» сгорает (книга
  рангов — без изменений); союзники — те же правила
  (000193); Эфир — исключён.
* **D5** — данные наборов — в JSON предметов (`set` +
  `set_bonus {2,3,4}`); НОВОГО каталога/синка/script-тега
  НЕТ. Активация — число НАДЕТЫХ предметов (каждый — 1;
  кольцо — тоже 1). set_bonus без set → throw.
* **D6** — редкость дропа: фиксированная таблица
  0.50/0.30/0.15/0.049/0.001 (данные модуля, пин тестом) →
  ролл редкости → детерминированный предмет этой редкости
  из фиксированного пула (000132). Моб — свой вызов
  c._rng ПОСЛЕ существующих (goldens бит-в-бит); сундуки —
  свой rng-поток (000157.02). Расходники — пулы без
  изменений (000132/000158).
* **D7** — экипировка наёмников = entry.sheet.equipment той
  же формы (API .02 generic); предмет — из ОБЩЕГО
  инвентаря героя (000194); найм-данные (dmg/hp/armor) —
