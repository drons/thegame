## Что сделано

* **src/combat.js — `canDoAction(c, action, args={})`** (чистая функция,
  экспорт в UMD-блоке добавлен): предпросмотр доступности действия
  БЕЗ побочных эффектов — не тратит пулы/ману, не вызывает `c._rng()`,
  не мутирует `c.ps`, `p.hp`, `p.mp`, инвентарь, `c.log`, `c.targetId`.
  Точное зеркало проверок ядра (одна причина — одно поведение,
  reason — формулировками ядра):
  * `attack` — checkTurn, checkBlocked, пул `attack`, цель
    (`args.targetId` или ближайший живой), дальность: лук ≤ 4
    (`equipmentStats(p).subtype === 'bow'`), иначе ≤ 1;
  * `fire` — checkTurn, checkBlocked, пул `spellInt`, `mp ≥ 3`, цель,
    дальность ≤ 4;
  * `heal` — checkTurn, checkBlocked, пул `spellWis`, `mp ≥ 3`,
    при полном HP → «здоровье полное» (решение задачи: P.heal
    восстановил бы 0, действие бесполезно);
  * `block` — checkTurn, пул `block`; checkBlocked НЕ проверяется
    (playerBlock в ядре его не вызывает — блок и есть последнее
    действие, 000027);
  * `quickItem` — checkTurn, checkBlocked, пул `quickItem`,
    `firstQuickSlot`, `quickItem(slot)`, применимость предмета по
    blacklist useItem (weapon/armor/reagent) — проверки БЕЗ самого
    `useItem` (он мутирует);
  * `invItem` — checkTurn, checkBlocked, пул `invItem`, в инвентаре
    есть хотя бы один применимый предмет (potion/food/skill_book);
    новый reason «нет применимых предметов в инвентаре» (кнопка
    «Предмет [T]» — семантика кнопки, мини-меню выбора —
    отдельная задача);
  * `flee` / `endTurn` — только checkTurn (ядро их в checkBlocked
    не гоняет);
  * неизвестное действие → «неизвестное действие: <action>».
* **src/combat.js — фикс найденного бага: лог исцеления** в
  `playerSpell('heal')`: раньше `P.heal` возвращает новое ОБЩЕЕ HP
  (player.js), лог печатал «Исцеление: 35» = «стал 35». Теперь
  логируется фактически восстановленная величина
  (`hp после − hp до`). Результат сохраняет поле `hp` (совместимость)
  и добавляет поле `healed` (восстановленная величина).
* **src/combat-ui.js**:
  * `build()`: кортежи кнопок `[label, key, action, fn]`,
    `b.dataset.act = action` (старое значение — код клавиши —
    нигде не читалось; панель ui.js со своими dataset.act —
    отдельная механика, не пересекается);
  * `render()`: `b.disabled = c.phase !== 'player' || !!c.result
    || !canDoAction(c, action, { targetId: c.targetId }).ok`;
    причина — в `b.title` (tooltip);
  * `keydown`: все 8 клавиш действий — через хелпер `keyAction()`:
    canDoAction не ok → reason в `c.log` (игрок видит причину;
    раньше — тишина), ok → действие как раньше. Кнопка «Конец хода»
    и «Побег» активны всю свою фазу (шанс побега — в ядре).
    Клик по disabled-кнопке в браузере невозможен — лог только
    по клавише. Ключи движения не тронуты.

## Тесты (tests/combat.test.js, +13)

## Ограничения

* Мини-меню выбора предмета из боя (чтобы кнопка «Предмет [T]»
  реально применяла выбранный предмет) — отдельная задача; здесь
  только корректный дизейбл + причина. До неё нажатие T при активном
  дизейбле-зеркале логирует отказ ядра («выберите предмет из
  инвентаря»), а не молчит.
