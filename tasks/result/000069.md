   `<slug>_{1,2,3}.svg` для slugs cave/crypt/ruins/drowned/abyss —
   ровно 3 варианта на каждый из 5 типов (DUNGEON_TYPES 0..4).
   viewBox 64×64 (масштаб мировых тайлов, SPEC «Графика»); палитра

   видов (матрица тип → палитра/декор), типовой косяк «один пещерный
   вид для всех пяти» исключён тестом slug ≡ COMBAT_BG_DUNGEON[id].
   Стыки без «шахматки»: базовый linearGradient ОДИНАКОВ для всех 3
   вариантов одного типа (сид меняет только раскладку деталей), детали

   дала бы сетку тёмных линий — в отличие от фонов боя 000049, где
   виньетка одна на весь экран).
2. **Генератор** `scripts/gen-dungeon-tiles.js` (`npm run
   gen:dungeon`) — детерминирован по образцу gen-combat-bg.js:
   mulberry32, сид на тайл 0x69000101..0x6900010f, for-циклы,
   стабильный порядок элементов/атрибутов, f() до 0.1 px, без дат.
   Повторный запуск — byte-identical (проверено в Finalize: второй
   прогон → git diff пуст). isMain-guard + module.exports

3. **src/sprites.js** (+57 строк):

     ключи 0..4 → массив из 3 путей `<slug>_<n>.svg`. Зависимости от

   * `dungeonFloorFrame(type, x, y)` — чистая функция (паттерн

## Решения и отклонения от файла задачи

1. **Каталог-против-зеркало — выбрано ЗЕРКАЛО (литеральное), НЕ
   расширение assets/dungeons**: (а) sprites.js по прецеденту
   000049/000058 не тянет dungeon.js и data-модули; (б) расширение
   каталога коснулось бы территорию 000058 (5 JSON + schema
   additionalProperties:false + sync-скрипт + dungeons-data.js +
   FALLBACK в dungeon.js), а 000070 параллельно правит dungeon.js —
   гарантированный конфликт; (в) 000066 берёт данные из API
   sprites-слоя (G.dungeonFloorFrame) — dungeon.js в цепочке рендера
   не нужен; (г) «Файлы» в ТЗ задачи не включают dungeon.js/JSON.
2. **Баланс вариантов**: hash2 % 3 — лёгкий модульный перекос
   (2^32 % 3 = 1, ~1%), визуально не значим; прямым прогоном проверено:
   сетка 35×35 даёт все 3 варианта для каждого из 5 типов
   (счётчики ~360–445 из 1225) — тест 4 выше.
