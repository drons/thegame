## Что сделано

1. **src/cities.js** — ДОБАВЛЕНИЯ (ядро 000104/000106 не тронуто) + 2
   строки в экспорт-объект:
   * `makeCityShop(cityX, cityY, tx, ty, buildingId, wealth)` — ровно
     6 параметров (тест `.length === 6`; layout/cityRecord-аргументов
     НЕТ — данные только из (город, клетка) и каталога по buildingId).
     Лавка = обёртка СУЩЕСТВУЮЩего `items.makeShop` с офсетом
     координат города: `makeShop(cityX*256+tx, cityY*256+ty,
     map_index, wealth)` — seed/сток/ассортимент/универсам-w3 —
     семантика makeShop БЕЗ дублирования логики (items.js НЕ тронут;
     его 6 golden-снимков makeShop в items.test.js зелёные без
     правок).
   * `CITY_SHOP_CELL_BASE = 256` (GOLDEN-ПИН литерала) — инъективная
     кодировка (город, клетка) → координаты makeShop: x′ =
     cityX*256+tx, y′ = cityY*256+ty. 256 > максимального layout
     (2×footprint−1 ≤ 14). Две РАЗНЫЕ пары (город, клетка) никогда не
     дают общие координаты — ВКЛЮЧАЯ СОСЕДНИЕ якоря: наивная сумма
     cityX+tx дала бы коллизию (100,−40)+tx=1 и (101,−40)+tx=0 — оба
     x′=101 → общий сток (ловит тест «анти-прецедент»). Смена
     константы после мержа = смена ВСЕХ городских стоков —
     недопустима (паттерн CITY_CONTENT_CONST 000106). Guard:
     tx/ty вне [0,256) → throw (защищает кодировку, а не layout).
   * Кросс-ссылка `buildingId` → запись каталога (assets/buildings,
     buildings.js) → `особые_параметры.map_index`: это id КАТАЛОГА
     (1..54), НЕ map_index (44 (Таверна) → 11, 1 (Оружейная) → 0;
     shopKindsFor(44) — null). Нет записи в каталоге → throw (ошибка
     вызывающего, /cities\.js/); map_index нет (города 51..54) или
     «виды» нет (Арена 7 / Стрельбище 10 / Дом кузнеца 25) → **null**
     (не лавка).
   * Формат возврата — РОВНО 6 полей makeShop/setShop-формата
     `{x: tx, y: ty, buildingType: map_index, wealth, stock, seed}`,
     где x/y = ЛОКАЛЬНАЯ клетка города (ключ состояния 000109
     «tx,ty»), а НЕ смещённые координаты makeShop. Объект «влезает»
     в существующий `playerUI.setShop` (ui.js) и в buyItem/sellItem/
     buyPrice/sellPrice (читают shop.stock/buildingType/wealth) БЕЗ
     изменений. Plain-объект — JSON-сериализуемо (сейв 000109).
   * wealth — cities.js-конвенция: throw (целое 0..3, как в
     generateCityContents), а НЕ clamp makeShop'а.
   * Каждый вызов — НОВЫЕ объекты: stock — новый plain-объект (мутация

   * UMD: node — factory(require('./perlin.js'), require('./items.js'),

     root) с ЛЕНИВЫМИ референсами в момент вызова (rootRef.Game;
     паттерн buildingsCatalogRef items.js, 000055/000060).
     Load-time-гарда на items.js/buildings.js НЕТ — цепочки
     vm-песочниц perlin→cities (000104/000106, dungeon-ui/sprites)
     обязаны грузиться без них; гард срабатывает на ПЕРВОМ вызове

## Решения (зафиксированы, см. memory)

1. **Лавка = обёртка СУЩЕСТВУЮЩего items.makeShop с офсетом
   координат города** (дизайн уже зафиксирован в SPEC.md,
   «Содержимое города») — семантика стока/seed/ассортимента НЕ
   дублируется; items.js не тронут.
2. **CITY_SHOP_CELL_BASE = 256 — инъективная кодировка (город,
   клетка)** — исключает общий сток, ВКЛЮЧАЯ СОСЕДНИЕ якоря
   (ловушка наивной cityX+tx); golden-пин (паттерн
   CITY_CONTENT_CONST 000106).
3. **Кросс-ссылка buildingId → каталог → map_index** (id каталога,
   НЕ map_index); нет записи → throw; map_index/«виды» нет → null
   (не лавка). Реальный пул городов {1,7,10,25,44}: лавки дают 1 и 44.
4. **Формат shop — РОВНО 6 полей, x/y = локальная клетка** — влезает
   в playerUI.setShop и buy/sell без изменений; ключ 000109 «tx,ty».
5. **wealth — cities.js-конвенция (throw 0..3)**; в проде —
   tileAt().buildingWealth (уже 0..3, map.js).
6. **Каждый вызов — новые объекты** — анти-прецедент npcStocks на
   уровне ссылок.
7. **UMD: ленивые референсы items.js/buildings.js в браузере;
   load-time-гарда НЕТ** (vm-цепочки perlin→cities обязаны
   грузиться); гард на первом вызове (порядок: items.js первым).
8. **Ослабление пина 000104 (осознанное)**: grep-тест структуры
   теперь допускает require ['./perlin.js', './items.js',
   './buildings.js']; items.js/buildings.js cities.js НЕ требуют
   (цикла нет); браузерная ветка при загрузке ничего не требует.
