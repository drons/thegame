## Решения (подробно — memory/000056-terrain-table.md)

1. **Одна таблица, два представления цвета.** `base` (hex) и `rgb`
   (0..1) хранятся ВМЕСТЕ в записи; согласованы соотношением
   `rgb[i] = round(hex[i]/255·100)/100` (проверено по всем 8 парам,
   закреплено тестом). rgb — ТОЧНЫЕ старые литералы main.js, НЕ
   пересчёт из hex: чистая конверсия сдвинула бы WebGL-цвета на
   ~0.0002 — «визуально мир не меняется».
2. **Формат — код в map.js, не JSON-каталог assets/terrains.** 8
   записей — ядро генерации; JSON-каталог дал бы зеркало +
   sync-скрипт, т.е. перенёс бы дублирование, а не убрал. Копии имён
   на стороне ДАННЫХ (enum assets/buildings/schema.json, enum
   assets/visuals/schema.json, имена файлов assets/tiles/*.svg)
   связаны с таблицей тестами, данные не трогаются (в файле задачи —
   «только согласование данных», имена файлов не переименовывать).
3. **Ленивое разрешение в buildings.js.** Циклический require в node
   (map.js уже требует buildings.js) разрешается в момент вызова: к
   тому моменту кэш require содержит полный map.js. Пустой вывод не
   кэшируется (паттерн 000055: buildingDerived). vm без map.js —
   грациозно `passableTiles() === []` без собственных
   фолбэк-литералов.
4. **API: `ALL_PASSABLE` (константа) → `passableTiles()`/
   `denseTiles()` (функции)** — функция переживает
   `Object.assign({}, Game, …)` между скриптами (ловушка UMD 000038)
   и лениво берёт таблицу.
5. **DENSE — мёртвая константа** (логикой не использовался):
   литерал удалён, значение переведено в таблицу, доступ —
   `denseTiles()`.

## Подводные камни (для будущих задач, см. memory)

* **Cross-realm в vm-тестах:** массив, созданный в vm-песочнице,
  НИКОГДА не пройдёт `assert.deepStrictEqual` против массива
  внешнего realm (разные Array.prototype) — JSON-нормализация
  vm-стороны (установленный паттерн tests/map.test.js).
* **UMD-фабрика buildings.js** не видит `root` обёртки — браузерная
  ветка ОБЯЗАНА передавать root в фабрику (как map.js).
* **Grep-тест литералов** ограничен частью файла вне маркеров
  BEGIN/END GENERATED: в GENERATED-блоке имена террейнов — данные
  каталога (допустимые_тайлы из JSON), их трогать нельзя.
* **Мерж**: 000056 — ПОСЛЕ 000059 (общие строки sprites.js вокруг
  TILE_BASE/VISUALS); SPEC правится только в своём разделе
  («Карта мира»).
* **Новый террейн** (если появится) — добавляется в TERRAIN_DATA +
  на стороне данных (enum/файлы); сквозные тесты
  (50 записей buildings, 13 файлов visuals, TILE_FRAMES, имена
  файлов assets/tiles) поймут дрейф.
