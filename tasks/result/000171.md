## Решения (отклонённые варианты — memory §3.1)

* **`<button>`, НЕ div и НЕ запись в COMBAT_KEYS** (гибрид a1+a2, a3
  отклонён): настоящий `<button>` — точное исполнение ТЗ («визуальный
  элемент для нажатия»), нативный tap→click, a11y, браузер гасит
  disabled-клики — всё бесплатно; div требовал бы CSS-блок в
  index.html (чужой файл). Табличная кнопка (COMBAT_KEYS) появилась бы
  у ВСЕХ героев (вечно disabled «неизвестное действие» без ветки
  canDoAction в ядре) → 6 ре-пинов + новая клавиша + новый SVG —
  вне ТЗ («не больше и не меньше»; прецедент 000168 D10 «кнопок
  новых НЕТ»). Вне-табличное управление боя — осознанный домовой
  паттерн (строки книги R9; thunk'и 000168).
* **Гейт видимости вместо вечного disabled** (чек-лист
  000171-touch-buttons.md п.3): пин-тесты (счётчик кнопок) и
  discoverability страдают от мёртвых кнопок.
* **Окно смерти 000164** — поведение кнопки определяется гейтом
  автоматически (rescue-путь; отдельного теста нет — мёртвый игрок в
  живом бою недостижим вне окна, приоритет автоцели пинит CU171-AUTO).
* **Ручное воскрешение Эфиром кнопкой — НЕ v1** (SPEC-механики нет).

## Подводные камни (выявленные при исполнении)

1. **Красный CU171-BTN читает FRESH-state кнопки**: startCombat
   рендерит ДО симуляции смерти в фикстуре → без одного tick rAF
   после мутаций scene166 кнопка оставалась бы в состоянии startCombat
   («нет цели»). Добавлен tick (только при мутациях — сцена `{}`
   бит-в-байт); существующие CU166-тесты — дельтовые, не задеты.
2. **advanceQueue МЁРТВЫЙ слот ПРОПУСКАЕТ** (combat.js 000167/000168:
   «серый слот»): для CU171-ALLY (кнопка активна на ходу игрока +
   стоп очереди на союзнике после Space) нужны ДВА наёмника — мёртвый
   a1 (автоцель) + живой a2 (стоп). Один мёртвый наёмник до Space не
   остановил бы очередь (пролёт до startRound → «player»).
3. **scene84 без `spells: true` — G.Spells отсутствует** → кнопка
   гаснет деградацией «Заклинания недоступны» (не по гейтам 000171):
   обе сцены ходов союзников — с `spells: true`.
4. **addMerc84 всегда делает id 'a1'** (makeAlly idx 1) — второй
   наёмник создаётся ручным `G.makeAlly({...}, 2)` (id 'a2').
5. **Хелперы ПОСЛЕ castRow** (не после canResurrect — hunk 000168):
   нарушение = rebase-конфликт (memory §8.2).
6. **Стаб querySelectorAll игнорирует селектор** (все кнопки
   песочницы) — спец-кейс в цикле гашения обязан работать по
   dataset.act (в стабе и реальном DOM идентичность одинакова).
