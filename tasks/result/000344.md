# Отчёт 000344 — Туман подземелья: один квад с explored-mask текстурой (RENDER-OPTIMIZE §5G / G2)

## Итог

Затемнение тумана (`FOG_DIM_FILL`, клетки mask==1) в `src/dungeon-ui.js`
перестало литься на main-канвас циклом `fillRect` каждый кадр: тот же цикл
(те же `proj`/`cellRect`/порядок обхода/`fillStyle`) печатается в экранную
offscreen bake-маску размера вьюпорта, в кадр идёт РОВНО ОДИН
`drawImage(bake, 0, 0)`. Пересборка маски — только по изменению ключа
`(d, cam.x, cam.y, zoom, w, h, pos.x, pos.y, fogR, explored.size)`;
steady-кадр — 0 пересборок. Канвас создаётся ЛЕНИВО (первый непустой dim),
город — вне прохода (`!isCity`), позиция блита прежняя (после контуров,
перед игроком — контракт 000136), клетка игрока (mask==2) не затемняется.
Бит-в-бит прежнему выводу (premul/source-over 1:1; снап-края соседних ря —
общие выражения) — доказательство и все ловушки:
`memory/000344-dungeon-fog-mask.md`.

## Отклонения от ТЗ

1. «Без ре-пинов» буквально невыполнимо: ТЗ меняет МЕХАНИКУ вывода (fillRect на
   main → bake + blit) при неизменных пиксельных контрактах; пины, считавшие
   `fillRect(FOG_DIM_FILL)` на main, обязаны смотреть внутрь bake (4 файла,
   маркеры «РЕ-ПИН 000344» в коде и заголовках).
2. «Пересборка только на изменение explored (монотонно)»: для экранной маски
   (ТЗ-ветка «bake теми же fillRect в offscreen») содержание ря зависит ещё и
   от геометрии (cam/zoom/w/h) и окна видимости (pos/R) — ключ пересборки
   superset `(d, cam, zoom, w, h, pos, R, explored.size)`; монотонная ЗАГРУЗКА
   только explored не применима в принципе (клетка выходит из dim переходом
   1→2). Смысловое требование «НЕ каждый кадр» выполнено: steady — 0 пересборок
   (FOGM-2, мутация M1 красна).
