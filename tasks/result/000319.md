## Что сделано

Корень (два независимых, см. memory/000319-shop-point-stock.md §1):
(1) `npcStocks` ключён только по `npcId` — все точки мира/города-fallback
торгуют в один сток NPC; (2) «картовый» магазин мира пересоздавался
`makeShop` каждый кадр в hud.js и в сейв не попадал вовсе.

Реализация (по фактическим ключам кода):
* src/main.js — `worldShops` `'x,y'` тайла → `{day, stock, seed,
  buildingType, wealth}` + `worldShopFor` (live-ссылка на entry.stock,
  ротация `campStockDueRefresh` с окном `city_respawn_days` от дня
  генерации, лениво); `npcShopKey(npcId, t)`: мир `'npcId@W:x,y'`,
  город-fallback `'npcId@C:ax,ay:tx,ty'`, подземелье
  `'npcId@D:worldKey:tx,ty'`, без тайла — прежний plain `npcId`;
  `shopFor` прокидывает tile в NPC-ветви; поле ctx `worldShopFor`;
  раздел сейва `worldShops` (collect/restore); `__game.worldShops` +
  `__game.worldShopFor`.
* src/items.js — `serializeWorldShops` (пропускает ПРОТУХШИЕ на момент
  записи; seed не сериализуется) / `restoreWorldShops` (ключ два int,
  day≤мира, тайл-магазин, min(qty,init), призы drop, absent→{}) —
  паттерны campStocks/cityStates.
* src/hud.js — `ctx.worldShopFor` с фолбэком `makeShop` бит-в-бит
  (vm-харнес-пины 0-diff; хранилище при фолбэке не создаётся).
* src/npc.js — `restoreNpcStocks`: point-ключи (`@W|@C:|@D:` + regex
  координат) валидируются, plain-ключи — прежняя ветвь 1:1 (старые
  сейвы играбельны); форма раздела НЕ менялась.
* Город (`cityShops`/`cityStates`) и лагерь (`campStocks`) — 0 правок
  (уже per-точка); 000316 выкуп остаётся camp-only (страж T6).
* 0 новых RNG: сид `hash2(x,y,0x154075)^(bt+1)` не тронут, день в сиды
  не входит (refill бит-в-бит; T2/T3).
