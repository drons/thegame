## Решения (зафиксированы в memory/000158.06-visuals-size-pins.md)

1. **ТЮНИНГ ДАННЫХ, не фикс бага** — вывод аудита: функционального
   бага 000021 НЕТ (pipeline полон: 000021/000059 данные+ядро,
   000039 рендер — смержен РАНЬШЕ создания ТЗ 000158); «не видно» —
   от малого `размер` (0.10–0.14 → rect 8–11 px при ZOOM_START=80) +
   SVG-контент в центральных 30–50% viewBox + слой выключен при
   zoom<24. 000021 done — история не переписывается (в её memory
   правится ОДНА строка — факт текущего контракта схемы).
2. **Единое значение 0.18** (не «лестница») — min каталога = ровно
   порог пина (0.18×80 = 14.4 px ≥ 14 px).
3. **Схема min = 0.18 — контракт** (решено зафиксировать; ТЗ
   оставляло решение, аудит §4.4 предписывает).
4. **VISUALS_MIN_ZOOM=24 — ОСТАВИТЬ** (перф: zoom 16 / 1080p ≈ 8k
   тайлов ≈ 12 мс/кадр — перебор бюджета, memory/000039); если
   после п.1–2 «вблизи всё равно не видно» — ОТДЕЛЬНАЯ задача с
   замером (ТЗ п.4: не гадать).
5. **«70–80% площади» — НЕ буквально** (подводный камень 10):
   приземистые силуэты (pebble 43%×22%, snow 62.5%×28%, цветы 31% по
   ширине); rect drawImage 14.4–20.8 px — ЭТО фиксируют пины (≥14
   px); фактический глиф (bbox×rect/64) 3–14 px; «14–20 px
   читаемо» ТЗ внутренне не согласовано (70–80%×14.4 px = 10–11.5
   px); функциональная цель достигнута ростом ×1.3–2.5 и закреплена
   пином.
6. **lily_pad «пасть» — геометрически ШИП** (raster-прогон winding-
   номера): 06 сохранил конструкцию «как сейчас»; если по замыслу
   000021 была именно «пасть» — арт-баг 000021 → отдельная задача.
