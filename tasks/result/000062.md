## Что сделано

1. **Правила** — `MOBS.md` в корне проекта (194 строки): плоское
   именование `<mob_id>_<state>_<n>.svg` (state ∈ move/attack/dead),
   набор кадров (move 2–3, attack 2–3, dead ровно 1), геометрия
   (клетка = 100 единиц, viewBox = 100·w×100·h, якорь низ-центр),
   бюджет деталей, единый стиль, технический формат, JSON-поля,
   чек-лист QA. SPEC.md (раздел про мобов) ссылается на MOBS.md.
2. **Ассеты — фактические счётчики** (проверено скриптом): в
   `assets/sprites/mobs/` 192 файла = **180 per-mob SVG** (36 мобов ×
   {move 2, attack 2, dead 1}) + **12 legacy-фолбэк** (6 видов 000047 ×
   2 кадра: abyss, elemental, orc, skeleton, spider, wolf; 64×64,
   бюджету НЕ подчиняются). У всех 36 мобов полнота кадров 2/2/1
   подтверждена.
3. **Генерация** — 180 файлов сгенерированы детерминированным
   параметрическим генератором `scripts/gen-mob-art.js` (сид =
   fnv1a(id+pose), byte-identical повторный запуск; прецедент
   gen-combat-bg.js) на данных `scripts/mob-art-data.js` (палитры
   5–8 HEX, черты, тексты описаний). Вручную 180 файлов делать
   нереалистично — генератор легитимен и остаётся в репозитории.
4. **Данные** — в 36 JSON каталога `assets/mobs/NNNNNN.json` добавлены
   поля: `описание` (800+ символов: анатомия, палитра HEX, материалы,
   отличительные черты, движение/удар/гибель) и `art` = { move: [2
   пути], attack: [2 пути], dead: [1 путь] }. `schema.json`
   дополнена обоими полями (+ недостающее `size` в properties, без
   которого все 36 JSON падали бы валидацией).
5. **Интеграция** — `src/sprites.js`: `MOB_ART_DIR`,
   `MOB_ART_FRAME_COUNTS` {move:2, attack:2, dead:1}, чистая функция
   `mobArtFrames(mobId, action)` (неизвестный id/действие → [] —
   фолбэк), `allAssetPaths()` += 180 путей. `src/combat-ui.js`
   drawUnits: цепочка фолбэков ПО ЮНИТУ — персональный арт → базовые
   6 видов (000047) → прямоугольник ROLE_COLORS. Мёртвые мобы
   (ранее пропускались) теперь рисуются dead-кадром без HP-полосы/
   уровня/подсветки. FX-эвристика `unitFxAfterMobPhase` (снимок ДО /
   состояние ПОСЛЕ endTurn: сменил позицию → move; ударная позиция +
   потеря HP игрока → attack).

## Ключевые решения

* **MOBS.md как источник правды** по ассетам; плоская раскладка и
  канвас 100·w×100·h победили вложенную раскладку и другой канвас из
  «архитектуры аналитика» (отклонения зафиксированы в
  memory/000062-mob-art.md).
* **Per-mob арт — слой ПОВЕРХ фолбэка 000047, а не замена**:
  MOB_FRAMES/MOB_SPRITE_KINDS/mobFrames не тронуты; legacy-файлы и
  таблица видов живут, неизвестный id → старые 6 видов.
* **Схема/зеркало**: `additionalProperties: false` в schema.json
  потребовала расширения; зеркало MOB_TYPES в combat.js арт-поля НЕ
  получает (ядро не читает; под file:// арта не грузится) — в
  зеркальном тесте combat.test.js вычитаются
  `ART_ONLY_MOB_FIELDS = ['описание','art']`. В sprites.js таблица-
  литерал без 180 путей: число кадров фиксировано, путь выводится из
  id (равенство с JSON закрывает тест).
* **Бюджет деталей**: ≥ 30 контурных элементов на клетку площади на
  КАЖДЫЙ кадр (1x1→30, 2x2→120, 3x3→270, 4x4→480, 5x5→750);
  detail = path/circle/ellipse/polygon/rect/line в теле SVG,
  defs/clipPath/mask/use не считаются. Мобы 4x4/5x5 пока отсутствуют
  (фактически 1x1/2x2/3x3).
* **Технический формат** — самодостаточный SVG (Image() под file://):
  нет script/text/foreignObject/image/SMIL/внешних ссылок; id в defs
  с префиксом `<mob_id>_`.

## Как проверяли

* **Счётчик деталей** — `scripts/count-svg-details.js` (exit 1 при
  недоборе) + `tests/svg-details.test.js` (включая работу на legacy-
  ассетах). Все 180 кадров ≥ 30·w·h.
* **Независимая проверка на каждого моба** — `tests/mob-art.test.js`
  (собственный сканер, не генератор): для ВСЕХ 36 мобов из каталога
  JSON — «описание» (800+/своды/палитра), «art» (2/2/1, пути, файлы на
  диске), на КАЖДЫЙ кадр: viewBox/структура XML/тень/префикс id/
  запрещённые теги, ≥ 30·w·h деталей, HEX файла ⊆ HEX палитры
  описания, уникальность кадров состояния (move_1≠move_2 и т.п.);
  отрицательный контроль — сканер ловит намеренные поломки.
* **Адверсариальное ревью** — независимые агенты разбирали решение;
  пойманные на ходу дефекты: пересборка JSON выбросила опциональные
  armor/fast/traits у 14 мобов (поймал зеркальный deepEqual-тест),
  dead-позы горизонтальных фигур выводили лапы за канвас (поймала
  структурная проверка) — оба исправлены, урок зафиксирован в памяти.
* **Тесты интеграции** — sprites.test.js (mobArtFrames 36×5,
  неизвестные id/действие, таблица == JSON «art», allAssetPaths ⊇
  180), combat-ui.test.js (труп — dead-кадр без полос/уровня/цели;
  без sprites.js труп не рисуется; endTurn → _unitFx move/attack,
  истечение, промах без attack-FX).
* **Полный прогон** — `npm test`: **495 тестов, 0 падений**.
