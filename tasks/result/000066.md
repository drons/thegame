# Отчёт: задача 000066 — вьюпорт/камера/зум подземелья — тот же
  движок, что и глобальная карта

Дочерняя к 000032 (модернизация экрана подземелья; отчёт родителя —
tasks/result/000032.md), направление 1 + «движок не должен отличаться».
Родитель зафиксировала: «масштаб картинки в подземелье такой же, как и
на глобальной карте», «движок отображения для подземелья не должен
отличаться от глобальной карты». Экран подземелья стал полноэкранным
вьюпортом с мировой математикой камеры/зума: ОДИН общий zoom (px/клетку
= px/тайл мира), плавная камера, зум колесом, отрисовка только видимой
области.

## Решения и отклонения от файла задачи

1. **«Тот же движок» = переиспользование ЧИСТЫХ API** (visibleTileRange,
   cameraStep, CAM_TAU_MS, ZOOM_MIN/MAX, worldToScreen из
   map.js/motion.js) + те же формулы проекции — БЕЗ выноса
   drawSprites/buildFrame из main.js (ограничение задачи: 000039 правит
   эти функции, merge-конфликты).
2. **Колесо — на оверлее, не на #game**: полноэкранный оверлей накрывает
   мировой слушатель, #game — sibling (не предок, bubbling не идёт).
   Один обработчик, один zoom — мир и подземелье не «расходятся».
3. **clampCam — каждый кадр ПОСЛЕ cameraStep**: сглаживание тянет cam к
   игроку, а зум меняет допустимый диапазон — кламп после сглаживания
   возвращает cam в границы (фикс «cam улетает при зуме»).
4. **Нет WebGL-слоя у подземелья** (зафиксировано в ТЗ): весь визуал
   SVG на 2D-canvas; «тот же движок» — canvas/зум/камера/проекция, а не
   слои.
5. **spriteLoader — DI через opts** (main.js передаёт свой):
   dungeon-ui.js не импортирует его (паттерн 000058/000059: модуль
   standalone, vm-песочница без спрайтов → фолбэки срабатывают).
6. **close() — caf ДО overlay.remove()** (паттерн combat-ui.js): поздний
   tick после close не рендерит (закреплено тестом).
