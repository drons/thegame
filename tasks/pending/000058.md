Подземелья: каталог assets/dungeons (JSON) + схема
(подзадача 000053)

Родительская: 000053 (аудит дублирования данных; принцип — JSON в
assets/ первичный источник)

Цель: данные о 5 типах подземелий сейчас в src/dungeon.js (кодом), а
названия дублируют записи каталога построек (пещеры id 31..35) —
вынести в каталог assets/dungeons (JSON + schema.json) по устоявшему
паттерну и согласовать с постройками-пещерами.

Состояние сейчас (сверено с кодом master)
* src/dungeon.js: DUNGEON_TYPES (5 id), DUNGEON_NAMES («простая
  пещера», «склеп», «руины замка», «затопленная пещера», «бездна»),
  DUNGEON_MOBS (списки mob-ид на тип), DUNGEON_ITEMS (списки
  item-ид), DUNGEON_SIZE (размер поля на тип).
* assets/buildings: пещеры — id 31..35 (категория «пещера»); их
  `название` дублирует DUNGEON_NAMES (проза vs id — связь только
  семантическая, кодом не проверяется); `особые_параметры` пещер
  (уровень/содержимое) частично дублируют DUNGEON_MOBS/ITEMS.
* src/sprites.js: COMBAT_BG_DUNGEON — осознанное литеральное зеркало
  DUNGEON_TYPES (000049: sprites.js НЕ тянет dungeon.js — vm-песочница
  combat-ui не грузит dungeon.js; равенство зеркала закреплено тестом).
* assets/dungeons — каталога НЕТ.

Ключевое проектное решение
* Каталог assets/dungeons: 000001..000005.json + schema.json (валидатор
  — tests/json-schema.js; русские имена полей, стиль assets/buildings):
  * `id` — целое 1..5, совпадает с номером файла (и с существующими
    значениями DUNGEON_TYPES — перенумерации НЕТ: сейв-совместимость,
    фон боя по номеру — 000049);
  * `название` — из DUNGEON_NAMES;
  * `мобы` — из DUNGEON_MOBS (id ∈ assets/mobs);
  * `предметы` — из DUNGEON_ITEMS (id ∈ assets/items);
  * `размер` — из DUNGEON_SIZE;
  * (опц.) `постройка` — id постройки-пещеры из assets/buildings
    (31..35): явная связь «подземелье ↔ вход в мире» (сейчас связь
    только по смыслу названий).
* Согласование с 000055: названия входы-пещер (idx 9 «вход в пещеру»)
  остаются ОБЩИМИ; конкретные пещерные постройки 31..35 ↔ типы
  подземелий — через новое поле `постройка` (если 000055 ввёл
  `название_карты` — не путать: это имя ТАЙЛА, не пещеры).
* JS-фолбэк-модуль (src/dungeons-data.js или аналог) под file:// —
  БЕЗ взаимных require (паттерн COMBAT_BG_DUNGEON/000049): dungeon.js,
  sprites.js, main.js читают лениво/через гарды.
* COMBAT_BG_DUNGEON (sprites.js): либо сохранить как зеркало с
  усиленным тестом (≡ каталог), либо вывести из того же фолбэк-модуля
  (решение в задаче; принцип — sprites.js без require dungeon.js).

2. JS-фолбэк-модуль + синхронизация (по образцу 000055/000057,

4. Согласование с assets/buildings 31..35 (поле `постройка`; имена не

5. SPEC.md: НОВЫЙ раздел «Архитектура хранения подземелий»

Тесты
* Валидация каталога схемой; зеркало ≡ JSON.
* Ссылки: `мобы` ∈ assets/mobs, `предметы` ∈ assets/items,
  `постройка` ∈ assets/buildings (категория «пещера», 31..35).
* Golden: детерминизм генерации подземелья (фикс. вход: тип + сид +
  totalXp → идентичный результат) — до/после одинаково.
* COMBAT_BG_DUNGEON ≡ каталог (тест 000049 — усилить на каталог).
* vm-песочницы: dungeon-ui/combat-ui без dungeon.js-каталога работают
  (гарды).
* Регрессия: npm test — все зелёные.
