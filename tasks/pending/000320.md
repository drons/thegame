+100 уникальных NPC для глобальной карты и зданий городов
(РОДИТЕЛЬСКАЯ: разбить на 100 дочерних, по одному агенту на NPC)

Источник: запрос пользователя (drons, 2026-11-05).

Цель: сгенерировать ещё 100 различных NPC для размещения на глобальной
карте и в зданиях городов. Для каждого — создать подзадачу и запустить
отдельного агента для генерации уникальной истории NPC и диалогов
общения с Флогистоном, Эфиром и наёмниками.

Что сделать:
* В анализе (ОБЯЗАТЕЛЬНО): РАЗБИТЬ на 100 дочерних задач
  000320.01–000320.100 — одна задача = ОДИН NPC (имя, тип/роль,
  размещение: глобальная карта или здание города, уникальная история,
  диалоги с Флогистоном/Эфиром/наёмными по формату диалогов — по
  факту кода). В result родительской — ссылки на дочерние (tasks/CLAUDE.md).
* Каждую дочернюю выполнять ОТДЕЛЬНЫМ агентом (отдельный workflow/
  worktree/коммит) — НЕ выполнять несколько NPC в одном коммите
  (правило конфликтов мержа).
* Имена/idi NPC — уникальны относительно текущего каталога (сweep);
  новые id — сквозная нумерация по факту диска на момент реализации
  (правило резервирования номеров: id НЕ фиксировать в ТЗ заранее).
* Родительская закрывается, когда все 100 дочерних смержены
  (проверка цели родительской — субагентами).

Тесты (красные):
* На дочернюю: JSON NPC валиден (schema), id уникален (sweep каталога),
  история и диалоги не пусты и в формате (по факту кода), история
  УНИКАЛЬНА (не копия из текущего каталога — проверка агентом в анализе
  дочерней).
* Sweep каталога: количество NPC растёт ровно на 1 на каждую смерженную
  дочернюю.

Ограничения:
* один NPC = одна дочерняя = один коммит в своём worktree;
* memory: по дочерней — файл памяти + сводный memory/000320-npcs-batch.md
  (контракт формата истории/диалогов, список размещений);
* CHANGELOG при мерже (контент/игровой процесс) — сводные буллеты по
  мере мержа дочерних;
* если формат NPC/диалогов не описан в SPEC — описать в SPEC;
* RED → GREEN, полный прогон ТОЛЬКО в worktree (ps-проверка);
  0-diff вне SCOPE.
