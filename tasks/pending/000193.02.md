# 000193.02 — БОЙ: «Воскрешение» из книги союзника — выбор мёртвого союзника, когда 'resurrect' знает СОЮЗНИК

Родительская задача: 000193 (tasks/pending/000193.md — заклинания Эфира и
союзных NPC в книге заклинаний; решение Д-H закрепило canResurrect на
c.player). Исход: finding 2 (minor) ревью 000193. Механика — территория
000166/000171/000196 (НЕ регрессия 000193: союзный каст 1:1 с пайплайном
игрока — 000163-зеркало; ТЗ «те же механики, что и у Флогистона»
соблюдено — поведение идентично игроку). Приоритет: P2. Зависимость:
мерж ПОСЛЕ 000193 (использует его книгу союзника + Д-H).

Проблема (проверена по коду, зафиксирована в
memory/000193-ally-spell-mechanics.md §15)
------------------------------------------------
Ядро корректно: 000163-зеркало (src/ally-spells.js, «воскрешение») —
явный c.targetId — ТОЛЬКО мёртвый СОЮЗНИК (side 'ally', !alive, !fled),
иначе отказ «нет цели»; БЕЗ targetId — автоцель (мёртвый ИГРОК
приоритетно, иначе первый мёртвый союзник; дальности нет). Но ЕДИНСТВЕННЫЙ
UI-путь поставить c.targetId на мёртвого союзника (или сбросить на null —
клик по клетке МЁРТВОГО игрока) — клик по канвасу под гейтом
`else if (canResurrect(c))` (src/combat-ui.js, canvas-клик, ветка 000166),
а canResurrect зашит на c.player (Д-H 000193: бит-в-байт 000166/000171
во всех фазах; Эфир 'resurrect' учит на L25 — efir.js).

Состояние-баг: игрок НИКОГДА не выучил 'resurrect' + c.targetId уже
указывает на живой юнит (клик по мобо на предыдущем ходу — обычная
ситуация в бою) → на ходу Эфира строка «Воскрешение» в ЕГО книге
попадает в ветку явного targetId → отказ «нет цели» при ЛЮБОМ клике
по строке; сбросить цель на null из UI нельзя (оба пути — под
canResurrect). Автоцель (мёртвый игрок / первый мёртвый союзник)
работает ТОЛЬКО при c.targetId === null. Игрок-UI то же ограничение
имеет 000163/000166 — Эфир его наследует.

Что сделать
-----------
1. Выбор мёртвого союзника (canvas-клик-ветка combat-ui.js): гейт
   «(ИГРОК ИЛИ активный союзник) знают 'resurrect'» — т.е.
   `canResurrect(c) || (активный u.spells содержит 'resurrect')`;
   путь «клетка мёртвого игрока → c.targetId = null» — под тем же
   расширенным гейтом. И/или путь сброса устаревшей цели ДО каста
   воскрешения (решить в анализе: минимально — расширенный гейт
   + клик по клетке активного союзника/пустой клетке не сбрасывает
   targetId — статус-кво).
2. Маркеры мёртвых союзников (drawUnits, регион 000166) — если
   вводится: светятся и для активного союзника, знающего 'resurrect'
   (игроку — бит-в-байт).
3. Кнопка «Воскрешение» (000171, resurrectChk) — решение в анализе:
   расширить на активного союзника (одна кнопка, оба пути) ИЛИ явно
   оставить player-only (кнопка — мобильный путь; книга — рабочий
   путь союзника) и зафиксировать в памяти.
4. Тесты: новый пин (Эфир с 'resurrect' в книге, игрок БЕЗ 'resurrect':
   (a) строка «Воскрешение» без -off при c.targetId === null (автоцель
   есть); (b) клик по мёртвому союзнику на канвасе — цель ставится
   (targetId = его id), строка кастуется: лог «Возвращён в бой.»,
   расход пул/мана ЭФИРА; (c) СТАЛОЕ c.targetId на живом мобе →
   работает путь сброса (targetId → null) → каст автоцелью; (d) игрок
   БЕЗ 'resurrect' без активного союзника-носителя — клики по мёртвым
   — no-op как сейчас (000166-пины бит-в-байт).
5. SPEC (если поведение фиксируется): spec/efir-spirit.md — буллет
   «Цель воскрешения — по 000166 (мёртвый союзник/игрок), выбирается
   союзником-носителем» (+ spec/companions.md при необходимости);
   spec-репины — в том же коммите.
