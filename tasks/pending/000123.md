Кнопки [E] и [I] на глобальной карте: кнопка инвентаря, SVG-иконки вместо букв, видимость в обеих схемах контролов

Цель
----
На глобальной карте рядом с on-screen-кнопкой «E» (действие на
тайле: диалог NPC / вход в постройку, задача 000018) добавить
кнопку «I» — открыть инвентарь (панель персонажа), сделать ОБЕ
кнопки видимыми и на мобильных устройствах, и в настольных
браузерах (сейчас кнопки существуют только в схеме контролов
'touch'), и на обеих кнопках показать ПОНЯТНЫЕ SVG-иконки вместо
текстовых букв («E»/«I»): иконка «действия» (вход в постройку /
диалог) и иконка «инвентаря».

Решения (зафиксированы для задачи)
----------------------------------
* Кнопка «I» открывает панель персонажа (`G.playerUI.toggle()`) —
  то же самое, что клавиша [I], включая поведение в бою (панель —
  поверх оверлея). Автосекцион вкладки «Инвентарь» при открытии
  с кнопки — опционально (пункт 5 «Что сделать»); минимум —
  эквивалент клавиши.
* Видимость в обеих схемах: в 'touch' — D-pad + [E] + [I]; в
  'keyboard' (настольный браузер) — ТОЛЬКО кнопки [E] и [I]
  (без D-pad). Запрашивались именно «эти кнопки»; выводить D-pad
  на десктопе — отдельное решение, здесь не делать.
* Кнопка «I» — над «E» (вертикальная пара внизу справа), того же
  размера; «E» сохраняет позицию и поведение.
* Вместо букв — ПОНЯТНЫЕ SVG-иконки: «E» (действие/вход в
  постройку) — иконка, говорящая «действие/вход» (дверь/рукоятка
  двери, стрелка-вход); «I» (инвентарь) — иконка, говорящая
  «инвентарь/предметы» (рюкзак/сумка/сундук). Иконки — статичные
  SVG-ассеты в assets/ (НЕ canvas-отрисовка и НЕ инлайн-SVG в
  JS-строках), должны проходить tests/svg.test.js.

Что сделать
-----------
1. Красные тесты СНАЧАЛА (tests/controls.test.js, см. «Тесты») —
   на текущем master они красные.
2. src/controls.js (чистое ядро):
   * `layoutTouchControls` — в возвращении второй прямоугольник:
     `{dpad, action, inventory}`: `inventory` — того же размера,
     что `action`, над ним с фиксированным зазором (≥ 8 px); пара
     влезает в вьюпорт с учётом `bottomInset` (на низком вьюпорте —
     уменьшение B как сейчас); невалидные размеры → нулевые
     прямоугольники;
   * `touchActionAt` — точка в `inventory` → 'inventory'
     (приоритет как у 'interact');
   * `TOUCH_ACTIONS` — добавить 'inventory';
   * `deltaForMoveKey('touch:inventory')` и
     `touchMoveKeyForAction('inventory')` → null (не направление).
3. SVG-иконки (новые ассеты):
   * новый каталог `assets/ui/` (или иной — зафиксировать в
     памяти): две иконки, например `icon_action.svg` (действие /
     вход в постройку) и `icon_inventory.svg` (инвентарь);
   * стиль: простые, узнаваемые силуэты (дверь/рукоятка, рюкзак —
     либо иные «понятные» варианты — зафиксировать выбор в
     памяти), светлый одноцветный рисунок под тёмный фон кнопки
     (цвет по `#e8dcc0` из `.tc-action`), чёткие контуры при
     размере 56…96 px;
   * ОБЕ иконки обязаны проходить `tests/svg.test.js` (правило
     SPEC.md / задача 000120) ДО добавления в каталог.
4. src/ui.js (DOM-клей, IIFE тач-контролов):
   * кнопки БЕЗ текстовых букв: содержимое — иконка
     (вариант на усмотрение реализации: `<img>` с
     `src: 'assets/ui/…svg'` внутри кнопки, либо CSS
     background-image на `.tc-action` с модификаторами классов);
     aria-label сохраняется («Действие…» / «Инвентарь») — буква
     больше нигде на кнопке не показывается;
   * вторая кнопка-«I» → теперь иконка инвентаря, тот же
     обработчик `pointerdown` (+ `blur()`) как у «E» →
     `onInventory()`;
   * `init(h)` — новое поле `h.onInventory`; D-pad строится только
     при `h.dpad === true` (вариант на усмотрение реализации, но
     раскладка ядра возвращает оба action-прямоугольника всегда);
   * `applyLayout` размещает обе кнопки по новой раскладке.
5. src/main.js:
   * `G.touchControls.init({...})` + `show()` — в обеих схемах, а не
     только 'touch': 'touch' → `dpad: true`, 'keyboard' →
     `dpad: false` (только кнопки);
   * `onInventory: () => { if (G.playerUI) G.playerUI.toggle(); }` —
     эквивалент KeyI-обработчика (main.js:594-596);
   * ветка `console.error` при отсутствии `Game.touchControls`
     сохраняется (регрессия порядка загрузки — tests/
     index-order.test.js).
6. (Опционально) `G.playerUI` — минимальный API открытия панели на
   конкретной вкладке (например `toggle(force, tabId)`), чтобы
   кнопка «I» открывала сразу вкладку «Инвентарь»; если это не
   входит в существующий механизм вкладок (ui.js:214-217)
   дёшево — не делать, минимум — эквивалент клавиши [I].
7. index.html: CSS пары кнопок (реюз `.tc-action`), стиль
   иконки внутри кнопки (размер ≈ 50…60% от диаметра кнопки,
   центрирование), при необходимости модификатор контейнера без
   D-pad; `pointer-events`/z-index не менять.
8. Память: `memory/000123-touch-buttons.md` — решения (кнопки в
   обеих схемах, D-pad только 'touch'; контракт раскладки
   action+inventory; кто кого вызывает; путь каталога иконок и
   выбор силуэтов), чтобы задачи 000071 и 000121 подхватывались
