Анимированные графические спрайты героя и мобов на поле боя
(подзадача 000030, направление 1)

(В ветке task/design задача была под номером 000032; при мерже в master
номер занят другой задачей — перепривязана.)

Цель: на мини-карте боя (src/combat-ui.js) рисовать персонажа и мобов
графическими анимированными спрайтами в том же стиле, что и на глобальной
карте (SVG из assets/sprites + Game-спрайт-лоадер), вместо цветных
прямоугольников и голубого ромба.

Состояние сейчас
* combat-ui.js: моб — цветной прямоугольник size.w × size.h по роли
  (ROLE_COLORS) + 4px полоса HP + номер уровня (задача 000040: юниты —
  прямоугольники, мобы до 3×3, якорь — верхний левый угол);
  игрок — голубой ромб (#8cf2fc). Анимаций нет.
* Глобальная карта (drawSprites в src/main.js) — 2D-canvas поверх WebGL:
  G.createSpriteLoader (Image, работает под file://) + чистая функция
  G.frameIndex(now, tx, ty, frames) (src/sprites.js, FRAME_MS=480):
  - текстуры тайлов (TILE_FRAMES, вода анимирована 2–4 кадра);
  - группы мобов (MOB_FRAMES: orc/skeleton/wolf/spider/elemental/abyss,
    по 2 кадра — idle);
  - Флогистон (PHLOGISTON_ACTIONS: idle/walk/attack/cast, по 2 кадра).
  Фолбэк, если ассеты не загрузились: цветные тайлы/маркеры.

Работа
1. src/sprites.js — новая чистая функция `mobSpriteKind(mobId)`:
   отображение ВСЕХ типов мобов MOB_TYPES (combat.js, сейчас 36 штук:
   8 орков, 7 нежити, 6 диких зверей, 4 насекомых, 8 стихийников,
   3 бездны) на базовые спрайт-виды MOB_FRAMES:
   - orc_* (8) → 'orc';
   - skeleton, skeleton_archer, crawling_bones, giant_larva, vampire,
     rot, bone_coloss (7) → 'skeleton';
   - wolf, wolf_pack, boar, cave_bear, troll (5) → 'wolf';
   - spider, ant, ant_queen, scorpion, centipede (5) → 'spider';
   - fire/water/wind/earth_elemental, imp, salamander, fairy,
     stone_golem (8) → 'elemental';
   - lower_demon, succubus, abomination (3) → 'abyss'.
   Неизвестный mobId → null. Таблица — литерал в sprites.js (не
   зависит от combat.js — нет циклической зависимости).
2. Герой: кадры PHLOGISTON_ACTIONS:
   - 'idle' — в обычном состоянии;
   - 'attack' — после успешного c.attack (анимация ~300 мс);
   - 'cast' — после успешного c.spell (fire/heal, ~300 мс).
   UI-состояние действия — поле ТОЛЬКО в UI-слое (например
   c._fx = { action: 'attack', until: <now> }), пишет combat-ui.js
   после вызова c.attack/c.spell. Ядро combat.js не менять.
3. Мобы: idle-анимация (2 кадра, frameIndex(now, u.x, u.y, 2)).
   Анимация атаки мобов — за рамками (базовые спрайты мобов содержат
   только idle-кадры); при желании порождается отдельная задача.
4. Цикл анимации: сейчас render() событийный. На время открытого оверлея
   — requestAnimationFrame-цикл (старт в startCombat, стоп в finish());
   выбор кадров — только чистые функции от времени/координат
   (детерминизм, как в мире).
5. Отрисовка: спрайты — на боевом canvas поверх фона (000049), сетки и
   препятствий (000050); игрок — ≈ CELL×1.1–1.2 (как в мире, zoom-аналог),
   моб — на весь его прямоугольник size.w × size.h (000040, до 3×3)
   с тем же относительным запасом. Порядок рисования:
   фон → сетка → препятствия → юниты (сортировка по y
   для «глубины») → эффекты. Полоса HP, номер уровня и подсветка цели
   сохраняются поверх спрайта (по всему прямоугольнику, как сейчас).
6. Интеграция: готовый spriteLoader передавать в бой —
   combatUI.startCombat({ ..., spriteLoader }) (в main.js лоадер уже есть;
   dungeon-бой через тот же startCombat). Без лоадера/ассетов — текущий
   фолбэк (прямоугольники/ромб), бой остаётся играбельным.

Файлы: src/sprites.js, src/combat-ui.js, src/main.js (передача лоадера).

Ограничения
* Детерминизм: выбор кадра — чистая функция (не Math.random, не Date.now
  в логике — только как аргумент чистого селектора).
* Фолбэк обязателен (file://, нет ассетов).
* Не ломать NPC-диалог (классы .combat-overlay/.combat-side переиспользуются).
* Желательно после 000049 (фон) — спрайты рисуются поверх фона;
  фолбэк-вариант позволяет делать и раньше.
