Отображение строки очерёдности хода во время боя
(подзадача 000030, направление 5)

Цель: во время боя показывать строку очерёдности — кто сейчас действует
и кто действует дальше (игрок + живые мобы).

Состояние сейчас
* Явного порядка хода в ядре нет: игрок действует (phase 'player'),
  затем ВСЕ живые мобы в порядке массива c.units (endPlayerTurn:
  c.phase = 'mob'; for (const u of c.units) { mobAct(c, u);
  if (c.result) break; }). c.phase — 'player'/'mob'/'over'.
  Из UI непонятно, какой именно моб «сейчас ходит».

Проектные решения
1. Игровая семантика НЕ меняется: игрок — первым, затем мобы в порядке
   массива units. Полный переход на «переменный порядок» (инициатива
   по Ловкости и т.п.) — отдельное геймдизайн-решение, вне задачи.
2. Ядро (src/combat.js) — сделать порядок наблюдаемым:
   - чистая функция buildTurnOrder(c) → ['player', ...ids живых мобов
     в порядке c.units]; экспорт для тестов;
   - c.turnOrder — пересчитывается в начале каждого раунда
     (createCombat и endPlayerTurn, после refillPools);
   - c.turnIndex — индекс действующего юнита в turnOrder: 0 в phase
     'player', 1..n в phase 'mob' (обновлять в цикле endPlayerTurn);
     после endTurn — снова 0 (следующий раунд).
   - turnOrder обязан совпадать с фактическим порядком mobAct
     (тест-инвариант).

Работа (UI, src/combat-ui.js + index.html)
3. Строка очереди: DOM-полоса (div) над canvas или вверху .combat-side:
   токены — герой (ромб/иконка, после 000047 — мини-спрайт) и мобы
   (цветные прямоугольники ROLE_COLORS, уровень). Для каждого токена:
   - сейчас ходит — подсветка (рамка/свечение, курсор на токене);
   - уже ходил в этом раунде — приглушение;
   - мёртвый/убежавший — серый, перечёркнут.
4. Обновление на render() (и в rAF-цикле после 000047 — автоматически).
5. CSS: новые классы .combat-turnorder / .turn-token (+modifier'ы)
   в index.html; не ломать верстку NPC-диалога (переиспользует
   .combat-overlay/.combat-side).

Файлы: src/combat.js, src/combat-ui.js, index.html, tests/combat.test.js.

Тесты (tests/combat.test.js, дополнить)
* buildTurnOrder: 'player' первым; затем мобы в порядке units; мёртвые
  и fled исключены; все мобы мертвы → ['player'].
* turnOrder/turnIndex: в начале боя — ['player', ...], turnIndex 0;
  после endTurn — turnOrder пересчитан (убитый моб исчез из очереди).
* Регрессия порядка: сценарный бой с фиксированным сидом (скрипты
  действий игрока) — порядок строк лога «X промахивается/бьёт/лечит»
  совпадает с порядком units (снимок-тест; зафиксировать до изменений
  и не менять семантику).

Ограничения
* DOM-часть в node не проверяется (опц. — паттерн мока документа, как в
  tests/fullscreen.test.js, если захочется).
* Совместимость: 000047 (иконки-спрайты в токенах), 000037 (не ваш ход —
  кнопки уже disabled по phase).
