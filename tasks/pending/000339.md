Оптимизация рендера A: пропуск legacy-гейта в steady state (RENDER-OPTIMIZE §5A)

## Цель

Убрать доминирующий CPU-цикл steady-кадра: legacy XOR-гейт (000176) выполняется
каждый rAF-кадр по всем frameTiles — при z=4 это ~131k вызовов `tileFrameImg` +
`brightness()` на кадр, даже когда все ассеты готовы и гейт детерминированно
даёт 0 вершин. При `readyCount() === totalCount()` пропускать цикл гейта
полностью (и сбор brightness).

## Знания (вынесены из RENDER-OPTIMIZE.md, анализ 2026-11-08 vs maplibre-gl-js 6.17.0)

* Цикл: `frame()` src/main.js (unconditional `requestAnimationFrame`); тело
  tryMove → updateCamera → gated resize → buildFrame → drawSprites → renderHud.
* Legacy-гейт XOR 000176: WebGL-подложка рисует ТОЛЬКО неразрешённые спрайты
  (XOR-контракт, memory/000176-duplicate-render.md); штатный кадр — 0 вершин.
* Цикл гейта — внутри rebuild-обхода frameTiles (вызовы `tileFrameImg(t, now)`;
  строки пересчитать: якорь `tileFrameImg` ~main.js:3578, цикл-потребитель
  ~:3539/:3687 — номера дрейфуют, искать символом).
* API готовности есть: `readyCount()` и `totalCount()` — src/sprites.js
  (~:1262/:1268, экспорт в return-объекте); канал readiness монотонен
  (memory/000263-chunked-render.md §3.8).
* `bufferData` (`new Float32Array(verts)`, DYNAMIC_DRAW) остаётся каждый кадр
  — пин RM-6 не трогать (this — не область задачи).
* Оценки (RENDER-OPTIMIZE §5.1): Эффект 9, Простота 9, Риск 2. Для движения
  персонажа (§5.2) — 10: гейт выполняется и на hit-, и на miss-кадрах
  (movement-кадр = пересечение тайла = miss); пропуск снимает 131k+ вызовов с
  каждого movement-кадра.

1. В цикле гейта buildFrame: условие `readyCount() === totalCount()` → пропуск
   тела гейта и сбора brightness для всех frameTiles; при неравенстве — прежний
   полный путь.
2. Красные тесты (tests/render-steady-gate-skip-000339.test.js, kind=node):

   T2 — частичная загрузка (readyCount < totalCount): гейт работает,
   неразрешённые спрайты попадают в WebGL (regression RM-4/RM-8);
   T3 — steady-вершины 0 сохранён (эквивалент RM-3/RM-10);
   T4 — bufferData каждый кадр сохранён (RM-6, не сломать соседним кодом);
