Детерминированная генерация содержания города (подзадача 000052,
приоритет П2; Зависимость: 000104)

Перепривязка: в анализе 000052 была №000100; 000096–000101
заняты подзадачами 000051 (мерж b5a9535) — перепривязана на
000106 по правилу memory/task-numbering-conflicts.md.

Родительская: 000052 (города и деревни)

Цель: чистая функция `generateCityContents` в src/cities.js —
что внутри города: внутренние постройки (лавки, таверна, школы,
дома NPC, малые постройки) на FLOOR-клетках layout'а. Стоки
лавок — 000108, взаимодействие — 000107, сейв — 000109.

Состояние сейчас (сверено с кодом master)
* Layout города — 000104 (`createCityLayout` → {width, height,
  cells, entrance, exit, seed, kind:'city'}).
* Размещение сущностей в подземельях — `takeSpot` (src/
  dungeon.js:225): рандомные свободные FLOOR-клетки из rng —
  готовый паттерн (чистый, без DOM).
* Внутренние постройки — СУЩЕСТВУЮЩИЕ типы каталога
  assets/buildings (магазины id 1..4/7/8, школы id 9..24,
  дома NPC id 26..30, таверна id 44, малые постройки id
  41/42/43/49): город НОВЫХ типов построек НЕ вводит
  (исключение — решение в задаче с обоснованием).
* NPC — связь каталога `постройки` (assets/npc):
  `npcsForBuilding`/`npcForBuilding` (src/npc.js:37/43) — в
  городе та же связь (постройка → NPC), без новой механики.
* Сиды подземелий — `hash2` + perlin (perlin.js, mulberry32).

Что сделать
1. src/cities.js: `generateCityContents(layout, cityX, cityY,
   cityRecord, wealth)` →
   `{ buildings: [{ x, y, buildingId }], seed }`:
   * rng = mulberry32(hash2(cityX, cityY, CITY_CONTENT_CONST))
     — детерминированно от ПОЗИЦИИ города (константу
     зафиксировать; НЕ totalXp — город не меняется при
     получении опыта); `seed` — в возврате (для стоков 000108
     и сейва 000109);
   * `cityRecord` — запись каталога города (000102): квоты из
     `особые_параметры` — `мин_постройки`, `доли_типов`
     (source of truth, 000053): код читает каталог, не
     хардкодит;
   * `wealth` (0..3, богатство якоря города из tileAt) —
     влияет на число/ассортимент (формулу зафиксировать
     тестом);
   * типы внутренних построек — из каталога (магазины, школы,
     дома NPC, малые); таверна (id 44) — В КАЖДОМ городе
     (минимум 1 — решение: найм спутников 000065/000078 в
     городской таверне; найм в этой задаче НЕ описывается);
   * размещение — по FLOOR-клеткам layout'а, паттерн
     `takeSpot` (dungeon.js:225): ничего на entrance/exit;
     постройки города 1x1 (внутренние — одиночные; если
     захочется 2x2 — решение в задаче, по умолчанию 1x1);
   * достижимость: после размещения BFS — все FLOOR-клетки
     достижимы (постройки не «замуровывают» кварталы).
2. Чистота: функция без DOM/clock/глобального состояния —
   node-тестируема (паттерн dungeon.js).
