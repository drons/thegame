# Задача 000344: Туман подземелья — один квад с explored-mask текстурой (RENDER-OPTIMIZE §5G, подход G2)

## Цель

Заменить per-cell цикл `fillRect` затемнения (`src/dungeon-ui.js`: константа
`FOG_DIM_FILL = 'rgba(10, 13, 18, 0.65)'` (~:164), двойной цикл по viewport
`x0..x1 × y0..y1` с `fillRect` для `mask == 1` (~:1200–1216, закоммичено
000136)) на ОДИН квад с текстурой explored-mask (upload на изменение
explored — монотонное расширение 00263 §3.5). До 3969 fillRect/кадр в
подземелье на низком зуме → 1 (оценка §5.1: эффект 5, простота 5, риск 4).
Кандидат 000263 §9.

## Контракты (НЕ нарушать)

- **Затемнение обязано быть бит-в-бит** прежнему циклу: пины dungeon-vision /
  MOBV и золотые pixel-ассерты подземелья — зелёные БЕЗ ре-пинов. ГЛАВНАЯ
  ЛОВУШКА — полупрозрачный fill при перекрывающихся/нецелые границах клеток
  даёт двойное смешивание альфы (двойное затемнение на общих рёбрах):
  ДО реализации анализ обязан установить, что `cellRect`/снап-сетка
  (000215/000228) целочисленно-выровнены при рабочих зумах (тогда fillRect
  не перекрываются и один квад эквивалентен), Иначе — mask-текстура должна
  воспроизводить фактическое смешивание (например, bake маски в offscreen
  canvas ТЕМИ ЖЕ fillRect по клеткам один раз на изменение explored, а в
  кадр — один drawImage результата). Выбор решения — за анализом с
  доказательством pixel-parity на серии зумов.
- Порядок слоёв фиксирован: квад строго ПОСЛЕ всех контурных слоёв/контуров
  мобов и ПЕРЕД игроком (коммент 000136 в коде — источник); игрок никогда
  не затемняется (клетка mask == 2).
- Город — проход не выполняется (`!isCity`), подземелье только.
- Upload/пересборка маски — только на изменение explored (монотонно), НЕ
  каждый кадр; сброс при смене подземелья/ресторе (свип мест мутации mask).

## Что сделать

1. Анализ (обязателен до кода): вывод cellRect по зумам (целые/дробные
   границы), pixel-parity доказательство выбранного решения, список пинов
   dungeon-vision/MOBV/золотых ассертов, точки инвалидации маски.
2. Реализация в `src/dungeon-ui.js` (SCOPE — этот файл + память; при
   необходимости mask-хелпер — новый `src/dungeon-fog.js` с экспортом через
   существующую проводку).
3. Новый тест `tests/dungeon-fog-mask-000344.test.js`: (a) золотой паритет —
   draw-вызовы/пиксели до и после на серии (пустое/частично/полностью
   исследованное, граничные клетки viewport, зум-коридор); (b) счётчик
   fillRect-затемнения/кадр: steady-кадр без изменения explored — НОЛЬ
   пересборок маски и РОВНО 1 quad/drawImage вместо N fillRect; (c) изменение
   explored → ровно 1 пересборка; (d) игрок не затемнён; (e) город — 0
   затемнений.
4. RED-then-GREEN; мутации (пересборка каждый кадр / квад после игрока /
   mask==2 в текстуру) — краснота.
