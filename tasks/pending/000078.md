Спутники: данные найма — схема assets/npc + каталог наёмников + sync

Родительская: 000065 («Найм» спутников: проработка и планирование).

Цель: слой ДАННЫХ найма — без боевого кода (паттерн каталогов 000057/000058:
JSON source of truth + схема + sync-скрипт + JS-зеркало). Плюс минимальная
«проводка», чтобы игра осталась зелёной с новым действием диалога.

Что сделать
-----------
* assets/npc/schema.json (схема ЗАКРЫТА — additionalProperties: false на
  верхнем уровне и в элементах «диалог», править явно):
  - новое ОПЦИОНАЛЬНОЕ поле `найм` на уровне NPC:
    {цена (число — цена контракта), жалованье (число — в день),
     роль (enum: melee | ranged | shield | support), dmg, hp,
     armor (опционально), skills (массив id из assets/skills),
     spells (массив id из assets/spells)};
  - в enum `действие` (сейчас: торговля | обучение | квесты | подсказка)
    добавить «найм».
* 5–6 новых NPC-наёмников — файлы assets/npc/000012.json… (сквозная
  нумерация продолжается от 000011): `постройки: [44]` (таверна
  «Таверна (общественная)» — генерируется, map_index 11), у каждого —
  данные `найм` и действие диалога «найм» (по одному на боевую роль,
  роли могут повторяться). Навыки/заклинания — ссылки на каталоги
  (assets/skills, assets/spells). Цена/жалованье — в рамках текущей
  экономики (квест дают ~50 золота; баланс зафиксирован в разделе
  «Спутники» SPEC.md и проверяется золотым сценарием 000087).
  id записей НЕ переименовывать (сейв-ссылки 000029/000031).
* scripts/sync-npc-data.js — поддержать новое поле; регенерировать
  src/npc-data.js (file:// — fetch локальных JSON не работает,
  зеркало — паттерн 000053).
* Минимальная проводка нового действия диалога (чтобы игра с новым
  enum-значением оставалась рабочей — все слои обязательны, пропуск
  любого даёт красный тест):
  - src/npc.js — dialogOptions: прохождение действия «найм»
    (как «квесты» открывает вкладку);
  - src/ui.js — Game.npcUI, маппинг действие→вкладка (блок
    торговля/обучение/квесты, ~строки 557–570): «найм» открывает
    вкладку «найм»; в ЭТОЙ задаче вкладка — ЧИТАЕМЫЙ список
    кандидатов (имя, роль, навыки, цена контракта, жалованье/день)
    из данных (Game.NpcData) — кнопки «нанять»/«уволить» и список
    текущего отряда добавляет 000083;
  - требования диалога (существующее поле схемы `требования`:
    харизма ≥ N, навык) — механизм доступа к найму, НОВОЙ системы
    проверок НЕ изобретать (паттерн Оратора).
* assets/buildings НЕ трогать (таверна id 44 уже существует;
  tests/buildings.test.js хардкодит категории/количества каталога —
  каталог зданий не менять).
* SPEC.md правит родитель (000065) — раздел «Спутники» уже добавлен;
  в этой задаче SPEC не трогать.

Тесты (красные)
---------------
* tests/npc-data.test.js — валидность новых записей по схеме
  (включая новое поле и enum), сквозная нумерация без пропусков,
  ссылочная целостность (skills/spells существуют в каталогах;
  постройки содержат 44), наличие кандидатов для building 44
  (все имеют `найм`), JS-зеркало src/npc-data.js == JSON-каталог
  (после sync).

  открывает вкладку «найм»; список кандидатов — из данных,
  детерминированно.
