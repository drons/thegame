Полоска здоровья основного персонажа на экране боя
(подзадача 000030, направление 7)

Цель: видимая полоска здоровья (HP) героя на экране боя. Сейчас —
только строка текста «HP x/y» в .combat-state; у мобов же есть
4px-миниполоса над головой.

Работа
1. Основная полоса HP героя в DOM: элемент в .combat-side (над
   .combat-state, под строкой очереди 000036):
   - div-полоса: контейнер + заполнение (width = hp/maxHP),
     текст «HP 23/40» (числа не прятать — доступность/читабельность);
   - цвет по порогу (чистая функция): >50% — зелёный #6fdc6f
     (как у мобов), 20–50% — жёлтый, <20% — красный; на границах
     (ровно 0.5 / ровно 0.2) — решение зафиксировать в коде и тесте;
   - maxHP из Game.derived(hero).maxHP (как в .combat-state).
   - MP-полоса — опционально (задача про HP); если делать — рядом,
     синяя, тот же паттерн.
2. Миниполоса над героем на поле (как у мобов, 4px) — поверх ромба
   (сейчас) или поверх спрайта (после 000032): canvas, в render().
3. Чистая функция цвета: hpBarColor(frac) → css-цвет — вынести в
   тестируемое место. Решение по умолчанию: src/sprites.js (графический
   модуль, уже тестируется в node).
4. Обновление: render() (после каждого действия); при появлении
   rAF-цикла (000032) полоса обновляется и по циклу — без дублей
   логики (один вызов обновления).
5. CSS: классы .combat-hpbar / .combat-hpbar-fill в index.html;
   не ломать верстку NPC-диалога (переиспользует .combat-side).

Файлы: src/combat-ui.js, index.html, src/sprites.js, tests/sprites.test.js.

Тесты (tests/sprites.test.js, дополнить)
* hpBarColor: frac 1/0.6/0.4/0.21/0.19/0 → ожидаемые цвета;
  границы по зафиксированному решению; frac вне [0,1] — не ломается
  (clamp).
* Старые тесты зелёные.

Ограничения
* DOM-часть в node не проверяется (опц. — мок-документ, паттерн
  tests/fullscreen.test.js).
* Источники данных — те же, что в .combat-state (hero + derived):
  без новых полей в ядре.
* Совместимость: 000036 (строка очереди), 000032 (спрайты) —
  миниполоса рисуется поверх любого вида героя.
