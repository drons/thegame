Дизейбл кнопок действий, когда действие невозможно
(подзадача 000030, направление 6)

Цель: кнопки применения атак/заклинаний/предметов (и прочие действия)
в бою disabled, когда действие в текущем состоянии невозможно; игрок
видит причину.

Состояние сейчас (src/combat-ui.js)
* Кнопки disabled только когда phase !== 'player' или есть result.
* Невозможное действие — тихо возвращает { ok: false, reason },
  игрок не получает обратной связи.

Связанный найденный баг (зафиксировать и починить в этой задаче)
* playerSpell 'heal': `const hp = P.heal(p, amount); log('Исцеление: ' + hp)`
  — P.heal (src/player.js) возвращает НОВОЕ ОБЩЕЕ HP, а не количество
  восстановленного. Лог выдаёт «Исцеление: 35», имея в виду «стал 35».
  Починить: логировать фактическую восстановленную величину
  (hp после − hp до) и покрыть тестом.

Работа (ядро, src/combat.js)
1. Чистая функция canDoAction(c, action, args) → { ok, reason? }:
   БЕЗ побочных эффектов (не тратить пулы/ману!), дёшево, на каждом
   render. Действия:
   - 'attack': checkTurn; c.ps.attack > 0; есть цель (targetId или
     ближайший живой); дальность (ближний бой ≤1; лук ≤ BOW_ATTACK_DIST
     — проверка по equipmentStats(p).subtype как в playerAttack);
   - 'fire': checkTurn; c.ps.spellInt > 0; p.mp ≥ 3; есть цель;
     dist ≤ SPELL_MAX_DIST;
   - 'heal': checkTurn; c.ps.spellWis > 0; p.mp ≥ 3; решение: при
     полном HP — disabled, reason «здоровье полное» (действие бесполезно;
     P.heal при полном HP вернул бы 0 восстановления);
   - 'block': checkTurn; c.ps.block > 0; «только последнее действие» —
     остальные пулы (attack+spellInt+spellWis+quickItem+invItem) == 0,
     как в playerBlock;
   - 'quickItem': checkTurn; c.ps.quickItem > 0; первый быстрый слот не
     пуст (items.firstQuickSlot) и предмет в нём применим (не weapon/
     armor/reagent — см. items.useItem);
   - 'invItem': checkTurn; c.ps.invItem > 0; в инвентаре есть хотя бы
     ОДИН применимый предмет. (Сейчас кнопка «Предмет [T]» всегда падает
     на «выберите предмет из инвентаря» — UI выбора предмета из боя
     отсутствует. Мини-меню выбора — отдельная задача; здесь только
     корректный дизейбл + причина.)
   - 'flee': checkTurn;
   - 'endTurn': checkTurn.
   reason — человекочитаемая строка (использовать те же формулировки,
   что в ядре, чтобы UI и лог согласованы).
2. Экспорт canDoAction (тестируется в node).

Работа (UI, src/combat-ui.js)
3. render: b.disabled = (c.phase !== 'player' || c.result) ||
   !canDoAction(c, action).ok; причина — в title кнопки (tooltip).
4. Клавиатура (интеграция с 000033, если он уже сделан): нажатие
   клавиши невозможного действия — reason в c.log (сейчас — тишина).
   Без 000033: хотя бы лог по клику на disabled кнопку невозможен —
   лог по клавише обязателен.
5. Кнопка «Конец хода» — почти всегда активна в свою фазу (endTurn);
   «Побег» — активен в свою фазу (шанс описан в ядре).

Тесты (tests/combat.test.js, дополнить)
* Матрица canDoAction по действиям × причинам: нет цели; цель вдали
  (ближний/лук/заклинание); mp < 3; ps.attack/spellInt/spellWis == 0;
  phase 'mob'; есть result; полный HP для heal; блок при ненулевых
