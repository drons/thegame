Цель
----
Добавить в `npm test` проверку ВСЕХ файлов `assets/**/*.svg`:
XML well-formedness + структурная схема SVG (корень, xmlns, viewBox,
допустимость значений атрибутов) — и исправить файлы, которые уже
сейчас некорректны. Повторно сломанный SVG должен падать в тестах,
а не в браузере (сломанный спрайт не грузится как картинка и молча
исчезает в игре).

Что сделать
-----------
1. `tests/svg.test.js` (node --test, без внешних зависимостей):
   * пройтись по ВСЕМ `assets/**/*.svg` (включая logo, tiles, combat,
     dungeon, sprites/*);
   * XML well-formedness: минимальный парсер для ограниченного
     SVG-подмножества (теги/атрибуты/кавычки, комментарии, `<?xml?>`),
     самодостаточный, без npm-пакетов; при ошибке — путь файла +
     строка/колонок в сообщении теста;
   * структурная схема: корневой элемент `<svg>`;
     `xmlns="http://www.w3.org/2000/svg"`; есть `viewBox` (или
     width/height);
   * значения атрибутов: без `NaN`/`Infinity`, без пустых значений,
     без незакрытых кавычек (покрывается парсером), без лишних
     токенов перед `/>` (покрывается парсером);
   * (на усмотрение реализации) таблица ожидаемых размеров viewBox
     по каталогам (tiles 64×64, спрайты мобов 100×100 и т.д.) — если
     добавлять, зафиксировать в памяти.
2. Исправить 29 дефектных файлов (25 невалидных + 4 с NaN):
   * восстановить сломанные атрибуты по соседним кадрам того же моба
     (другие кадры того же действия/другие мобы) и по остальным
     элементам файла: `stroke`/`opacity`/`stroke-width` — осмысленные
     значения, убрать лишние токены;

     (проверить загрузкой в браузере/рендером — опционально).
3. Правила генерации: в `MOBS.md` (правила ассетов мобов, задача
   000062) и в SPEC.md (раздел «Графика») зафиксировать требование:
   каждый сгенерированный SVG обязан проходить `npm test`

   (шаг «Проверка соответствия SVG описанию и правилам») — добавить
