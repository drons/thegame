Цель: в каталог assets/npc для 6 наёмных NPC записать начальные списки
(различия персонажей — ТОЛЬКО начальные списки, ТЗ 000139): базовые
основные характеристики по роли + уровни начальных навыков. Играется в
000143 (sheet наёмного создаётся из этих данных).

Состояние сейчас (база master 0397799)
* Наёмных 6: assets/npc/000012.json … 000017.json, поле `найм = {цена,
  жалованье, роль, dmg, hp, armor?, skills:[id], spells:[id]}` — навыки
  БЕЗ уровней, характеристик нет. Примеры: 000015 (support) skills
  [meditation], spells [mend, light_heal]; 000017 (ranged) skills
  [archer], spells [spark, frost_bolt].
* Каталог — source of truth, зеркало src/npc-data.js, sync
  scripts/sync-npc-data.js + CI-гейт sync:check (паттерн 000053).

Состав работ
1. Схема найма (дописать в файл задачи при реализации):
   `найм.базовые_характеристики = {strength, dexterity, constitution,
   intelligence, wisdom, charisma}` (значения ≥1, по роли: melee→
   strength, ranged→dexterity, shield→constitution, support→
   intelligence/wisdom — конкретные цифры задаёт реализация и фиксируются
   тестом) и `найм.начальные_навыки = {id: level}`. Решение: плоский
   `skills:[id]` остаётся (id → implicit level 1); `начальные_навыки` —
   явные уровни, при слиянии побеждает.
2. Заполнить 6 файлов assets/npc/*.json согласованно с ролями.
3. scripts/sync-npc-data.js — переносить новые поля в зеркало;
   src/npc-data.js — регенерировать; sync:check зелёный.
4. Тесты: schema-тест (все 6 наёмных имеют базовые_характеристики с
   6 целыми ≥1 и начальные_навыки по id каталога skills; skills[] ⊆
   ключей начальные_навыки; spells[] ⊆ каталога spells), drift-тест
   sync:check. Красный ДО: поля отсутствуют → fail.

Файлы: assets/npc/000012..000017.json, scripts/sync-npc-data.js,
src/npc-data.js (генерируемый), tests (новые/доп. к npc-data).
