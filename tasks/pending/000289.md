Рендеринг: не сбрасывать canvas каждый кадр — ресайз только при
реальном изменении размера окна + явная GL-состоятельность +
само-исцеление 000170 (src+tests)

Источник: исследование drons (сообщение оркестратору, 2026-11-02).
Факты, свёренные с диском:
* src/main.js:4100-4102 — каждый кадр `canvas.width/height =
  window.innerWidth/innerHeight` + `gl.viewport`;
* src/main.js:4120-4121 — то же для spriteCanvas (при наличии);
* присвоение `.width`/`.height` canvas пересоздаёт backing store и
  сбрасывает состояние GL-контекста — 60 раз/сек: просадки FPS,
  батарея, риск артефактов;
* src/main.js:3984 и memory/000170-movement-freeze.md (~L203, пункт 8
  — «canvas.width/height пересет каждый кадр … частичный кадр
  watchdog-сценария само-исцеляется (не нужен отдельный рендер-гард)»)
  — само-исцеление частичного кадра 000170 ОПОРНО на пересет каждый
  кадр; фикс ресайза обязан сохранить этот контракт явно;
* батчинг тайлов (buildFrame → один gl.drawArrays), viewport-culling
  (visibleTileRange/frameTiles), дедупликация построек (anchors Set),
  createTileCache — реализованы грамотно, ИМЯ задачи не касаются.

SCOPE:
1. В цикле frame ресайзить canvas/spriteCanvas только когда реальный
   размер изменился. Вариант A — remember lastWidth/lastHeight и
   сравнение внутри frame; вариант B — ResizeObserver. Решение — в
   анализе: в node-vm тестовом окружении ResizeObserver может быть
   недоступен, вариант A тестуем мутацией mock'а window.innerWidth/
   innerHeight между кадрами — при отсутствии веского довода за B
   брать A.
2. Само-исцеление 000170 — явно на error-пути: при исключении в
   кадре (catch/watchdog 000170) принудительно сбросить
   canvas.width/height (оба слоя), чтобы частичный кадр не просачивал
   в следующий. Обновить memory/000170-movement-freeze.md: пункт 8 и
   § (~L203) — новый механизм вместо «пересет каждый кадр».
3. GL-аудит: что опиралось на пересет каждого кадра (bound program,
   текстуры, blend/depth/stencil/scissor, viewport) — сделать эти
   установки явными (при инициализации и/или безусловные в кадре).
   Код уже ре-сетит viewport/uniforms каждый кадр — аудит по полному
   набору состояния, вывод зафиксировать в memory-контракте.
4. Тесты (красные по паттерну репо, mock'и canvas с drawCalls —
   tests/chunk-render.test.js как образец harness'а):
   a. счётчик присваений canvas.width/.height — M подряд идущих
      кадров без изменения окна → пересет только на первом кадре,
      далее 0 (spriteCanvas — то же);
   b. изменение innerWidth/innerHeight между кадрами → ровно один
      ресайз на следующем кадре + gl.viewport с новыми размерами;
   c. сценарий 000170 (исключение в кадре) → на следующем кадре
      canvas сброшен (частичный кадр не просачивает).
   Существующие тесты с innerWidth-mock'ами (chunk-render,
   building-levels, camp-map-e2e, aggro-visibility и др.) — зелёные
   без правок.
5. memory/000289-render-canvas-resize.md — контракт: что изменилось
   и почему (backing store + GL-сброс), новый механизм само-исцеления,
   результат GL-аудита, выбранный вариант A/B и почему.

Ограничения:
* батчинг/culling/дедупликация/tile-cache НЕ трогать (по исследованию
  работают корректно);
* рендер-контракты слоёв не менять: XOR-контракт 000176 (`now` одна
  и та же в buildFrame/drawSprites), 000033 (одна точка рендера на
  кадр);
* полный прогон ТОЛЬКО в worktree (memory/test-runner-worktrees.md),
  ps-проверка до пуска;
* CHANGELOG — нет (изменение поведения/графики нет; если анализ
  найдёт user-visible эффект — решить ему и зафиксировать в
  отчёте).

Отложено в будущее (НЕ цель задачи; кандидаты на follow-up при
появлении нужды):

* OffscreenCanvas для статичных слоёв (земля/декорации) — только если
