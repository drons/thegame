# Руны

## Руны: каталог и эффекты

* Каталог assets/runes/<id>.json (задача 000328.01; 000318.02 — basename == id,
  55 записей, порядок зеркала по id); формат {id, название, описание, эффект}
  (схема assets/runes/schema.json, additionalProperties false; id —
  латиница ^[a-z][a-z0-9_]*$; название/описание непустые и уникальны;
  файл — roundtrip-канон JSON.stringify(obj,null,2) с переводом строки).
* Эффект — объект с дискриминатором type, ДВА машинных типа (третий без
  потребителя запрещён): derived {"type":"derived","stat":…,"amount":…} —
  stat ∈ derived-статы src/sheet.js derived() (37 ключей: maxHP, maxMP,
  armor, …, hpRegenMult, mpRegenMult), amount — базовая прибавка к стату
  носителя предмета; skill {"type":"skill","skill":…,"amount":…} — паттерн
  аффиксов предметов (000230.03): skill ∈ вторичные навыки каталога
  assets/skills, effect-множитель навыка ×(1+amount). «Юмор» несётся
  названием/описанием, механика реальная.
* Категории эффектов: броня и живучесть, мана и восстановление, эффекты
  заклинаний (по факту derived — огонь/лёд), оружейный бой, поход,
  экономика/расходники/опыт, бафы вторичных навыков; 55 УНИКАЛЬНЫХ
  эффектов (дедупликация по сериализации), контракт-список —
  memory/000328-runes.md §3 (каталог ↔ список 1:1, тестом).
* Иконки: assets/sprites/runes/<id>.svg — по одной на id (биекция
  каталог↔иконки; иконка НЕ поле JSON); flat 64×64 (контракт 000302:
  только rect/circle/ellipse/polygon, без градиентов/text/path/use/
  stroke/defs, тень-эллипс, палитра — memory/000328-runes.md §4).
* Зеркало src/runes-data.js (UMD, Game.RunesData / require) — ГЕНЕРИРУЕТСЯ
  scripts/sync-runes-data.js (авто-подхват sync-all по конвенции sync-*.js;
  npm run sync:runes); JSON — source of truth, зеркало и каталог — в одном
  коммите.
* Семантика для механики (дочерняя 000328.02 — нанесение/стирание/лимиты):
  механика ОБЯЗАНА читать эффекты из каталога: derived → стат носителя
  +amount (базовое значение масштабируется runePowerMult — решение
  механики); skill → усиление вторичного навыка носителя как слияние
  аффиксов. Лимит рун на предмет (по редкости), стоимость нанесения и
  стирания на руническом камне — ВНЕ каталога, в 000328.02; в каталоге их
  нет. Навык «Рунопись» (id runes) уже в каталоге навыков — руны его не
  создают.
* Отображение в интерфейсе (задача 000328.03, только показ): для надетого
  предмета и стопок инвентаря — на тултипе предмета строки
  «Руна: «<название>»» по порядку массива runes (канон первого вхождения —
  не сортировать), с описанием из каталога; рядом — иконка руны
  assets/sprites/runes/<id>.svg. Механику показ не меняет.

## Нанесение и стирание рун

* Рунический камень (assets/buildings/000040.json, задача 000328.02) даёт
  действия построек «Нанести руну» и «Стереть руну» (эффекты 40_inscribe /
  40_erase); дневного лимита у них нет — гейт стоимости золотом.
* Лимит рун на предмет задаёт редкость предмета (RUNE_LIMITS): common 1,
  rare 2, epic 3, legendary 4, impossible 5; предмет без редкости руны
  не принимает (отказ с причиной, хранящиеся руны сносит санация).
* Стоимость нанесения задаёт таблица камня 40: база по редкости, шаг за
  каждую следующую руну предмета, скидка за уровень «Рунопись» с
  потолком; стирание дешевле нанесения всегда. Мало золота или нулевой
  уровень «Рунопись» — отказ с причиной.
* Выбор руны при нанесении детерминирован по (клетка, день): одно и то
  же место в тот же день даёт ту же руну; уже нанесённые предмету руны
  повторно не наносятся.
* Руны хранятся на инстансе предмета: массив runes (id из каталога) в
  записи инвентаря и runes-слой equipmentBonus экипированного предмета;
  стопки складываются по (id, бонус, руны); мусор сносит санация, формат
  сохранений не меняется. Снятие с предмета возвращает руны вместе с
  предметом.
* Руны действуют только на надетом предмете: derived-эффекты суммируются
  в базовые значения derived() с масштабом runePowerMult (целостные
  статы — после округления), skill-эффекты усиливают вторичные навыки
  как слияние аффиксов. Руны в инвентаре (не надеты) не действуют.
