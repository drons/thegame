# Архитектура хранения навыков

Описания навыков (раздел «Навыки») хранятся в каталоге `assets/skills`:
 * Один навык — один JSON-файл: `000001.json`, `000002.json`, … — сквозная нумерация,
   без пропусков и дубликатов. Сначала шесть основных навыков (`000001`–`000006`),
   затем вторичные по группам основного навыка
   (Сила, Ловкость, Телосложение, Интеллект, Мудрость, Харизма — `000007`–`000037`).
 * Структура файла закреплена JSON-схемой `assets/skills/schema.json`.
   Схема использует ограниченный набор ключей
   (`type`, `required`, `properties`, `additionalProperties`, `items`, `enum`, `const`,
   `minimum`, `maximum`, `minItems`, `maxItems`, `pattern`, `anyOf`, `oneOf`) —
   их покрывает минимальный валидатор без внешних зависимостей (задача 000015).
 * JSON-файлы каталога — source of truth для описаний навыков.

Структура файла:
 * Основной навык: `id`, `type: "primary"`, `name`, `desc` (характеристика),
   `combat` (влияние в бою) и `world` (влияние на карту мира) — по таблице
   раздела «Навыки».
 * Вторичный навык: `id`, `type: "secondary"`, `name`, `primary` (id основного
   навыка), `requires` — опциональное поле `{"skill": <id>, "level": N}`:
   требование к другому навыку (основному или вторичному); если поле опущено,
   требований нет. Далее: `effect` — `{"stat": <производная характеристика>,
   "perLevel": <доля за уровень, напр. 0.05>}`, `effectType` —
   `"Бой" | "Карта" | "Бой/Карта" | "ОТСРОЧЕНО"`, `desc` (текст эффекта) и `names` — ровно 6 имён,
   по числу рангов (см. «Ранги и переименование»).

Игра запускается без сервера (file://), где `fetch()` локальных JSON недоступен,
поэтому каталог дублируется в униформном JS-модуле `src/skills-data.js`
(в браузере — `Game.SkillsData`, в node — `require()`). Модуль генерируется
из JSON-каталога скриптом:

    node scripts/sync-skills-data.js

`src/player.js` читает основные и вторичные навыки из этого модуля;
ранги и формулы производных характеристик остаются в коде.
Консистентность `assets/skills` ↔ `src/skills-data.js` ↔ `src/player.js`
проверяют тесты `tests/skills.test.js`: каждый навык каталога присутствует в коде
и наоборот, эффекты и требования совпадают. Колонка «Тип эффекта» в spec/skills.md — дизайн-классификация; не обязана совпадать с effectType JSON (степень реализации).
