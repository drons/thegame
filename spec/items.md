# Предметы

## Типы предметов
 | Тип | Подтип | Влияние |
 |---|---|---|
 | Оружие | меч / лук / тяжёлое / посох | урон в бою; меч — попадание «Мечник», лук — попадание «Стрелок» + урон «Меткость» и дальность 4 клетки, тяжёлое — урон «Тяжёлое оружие», посох — только урон (без бонусов попадания/урона; маркер практики 'staff' — навыка в каталоге нет, 000230.12) |
 | Броня | часть тела (slot) | добавляет к броне («Голем»); части: head/ears/neck/torso/forearms/palms/legs/feet |
 | Щит | shield | слот left_hand; броня (stats.armor) + аффиксы/наборы (000230.13) |
 | Артефакт | artifact | слот left_hand; аффиксы/наборы, 3 из 13 — броня (000230.13) |
 | Орудие | tool | слот right_hand (заменяет оружие — бить или ковать, 000230.12); аффикс — навык крафта (forge/alchemy/runes) |
 | Кольцо | ring | слот ring — первый свободный из 8 (раздел «Снаряжение»); аффиксы (000230.14) |
 | Зелья | — | восстанавливают здоровье/ману; сила зелий — «Алхимик» (+5%/ур.) |
 | Еда | — | восстанавливает здоровье; сила еды — «Сердце природы» (+5%/ур.) |
 | Книги навыков | — | дают опыт вторичному навыку (практика, см. раздел «Навыки») |
 | Реагенты | — | компоненты: торговый товар, основа алхимии и крафта |
 | Свиток воскрешения | resurrection_scroll | в бою (быстрый слот): возвращает мёртвого союзника на поле (50% HP), цель не выбирается (первый мёртвый) |
 | Свиток заклинания | spell_scroll | изучение при применении (чтение — Интеллект); tier (1..4) = уровень заклинания; лут — с мобов от разницы уровней, с сундуков — tier по глубине (spec/dungeons-storage.md «Лут», 000235.05) |
 | Чертёж | craft_scroll | изучение вида крафта при применении; эффект {kind:'craft_recipe', recipe}; нестаккуем |
 * Влияние по слотам (000230.02): 10 частей тела + 8 слотов колец
   — 18 физических слотов (11 групп; модель и детали — раздел
   «Снаряжение»):
   head/ears/neck/torso/forearms/palms/legs/feet — броня;
   right_hand — оружие (меч/лук/тяжёлое/посох) или орудие;
   left_hand — щит или артефакт; пальцы (ring) — кольца
   (первый свободный из 8). Новые экипировочные kind — ВСЕГДА с
   явным slot (000230.01); legacy 000001–000010 — явный slot с
   000230.10 (3 брони → torso) и 000230.12 (7 оружий →
   right_hand); slotOf-фолбэк для weapon/armor БЕЗ slot —
   защитная ветка кода, в каталоге таких предметов НЕТ.

## Руды, минералы и самоцветы
 * Руды, минералы и самоцветы — предметы вида `reagent`: торговый товар,
   основа крафта; у реагентов не бывает effect, складываются стопкой
   до 99 (задача 000157.01).
 * Редкость — ОПЦИОНАЛЬНОЕ поле `tier` схемы assets/items (целое 1..4,
   отсутствие = 1) — источник редкости пулов залежей (000157.02).
   Самородки карты (000158) связаны с каталогом предметом id; редкость
   самородка — поле loot.frequency каталога.
 * Шкала редкости качественная: 4 тира, «чем глубже — тем реже»;
   числовые формулы — в коде и тестах (000157.02, паттерн 000045).
 * Источники: залежи в пещерах/подземельях (000157.02), самородки на
   глобальной карте (000158), торговля — магазин магии и универсам
   подхватывают реагенты автоматически по виду, Хольд — сток
   (000157.04).

## Редкость и дроп экипировки
* `rarity` — ОПЦИОНАЛЬНОЕ поле схемы assets/items (enum
  common/rare/epic/legendary/impossible): есть ТОЛЬКО у
  экипировочных (kind armor + явный `slot`); расходники — БЕЗ
  rarity (БЕЗ рамки, 230.07-RAR-G). НЕ путать с `tier` руды
  (целое 1..4 — раздел «Руды, минералы и самоцветы»).
* Данные — src/loot-equip-data.js (UMD: браузер Game.LootEquipData,
  node require; потребители combat.js/dungeon.js — на load):
  * RARITY — 5 тиров, канонический порядок common, rare, epic,
    legendary, impossible ОБЯЗАТЕЛЕН (acc-накопление): шанс
    0.5/0.3/0.15/0.049/0.001 (сумма = 1 в FP).
  * EQUIP_POOLS — ДАННЫЕ МОДУЛЯ (каталог в рантайме НЕ читается —
    паттерн 000132): редкость = КЛЮЧ (id тира), id в каталожном
    порядке, 111/77/56/22/11 = 277 (финал после
    000230.15/000230.19; на момент 000230.11 — 150, волны
    000230.12–.15 и .19 добавляли id КОНЦОМ тиров); legacy-брони
    (leather_armor/chainmail/knight_plate — slot БЕЗ rarity)
    НИКОГДА не в пулах.
  * pickRarityTier(rngFn) — чистая: 1 вызов rngFn, строгое
    r < acc, fallback = impossible (никогда не undefined);
    FP-границы 0.9500000000000001/0.9990000000000001 — часть
    контракта (пины EQ1/EQ3/CH4).
* Дроп с сундуков (000230.05) — dungeon.js generateDungeonContents,
  блок ПОСЛЕ залежей: триггер — сундук с непустым item, у предмета
  ЯВНЫЙ slot (it.slot !== undefined; расходники/legacy — без
  изменений); СВОЙ rng-поток rng_eq = mulberry32(hash2(seed,
  depth, CHEST_EQ_SALT = 0x0E5C) >>> 0) (паттерн 000157.02);
  вызовы строго по сундукам, только триггернутые (1 tier + 1
  select при непустом тире); guard eqTotal > 0 ДО rng (пустые
  пулы — 0 вызовов); замена ch.item IN-PLACE (новых ключей
  объекта сундука нет — сериализатор save.js {id,x,y,opened,gold,
  item} держится); главный rng/gold/mobs/позиции — бит-в-бит
  (CH1 golden ABYSS).
* Дроп с мобов (000230.05) — combat.js rollVictoryLoot: ОДИН ролл
  на ПОБЕДУ (killed.length > 0), СТРОГО ПОСЛЕ редкого ролла
  (порядок c._rng — пин EQ4); дроп-шанса НЕТ; пустой тир-пул —
  предмета НЕТ (select не вызывается, деградации в нижний тир нет);
  drop() merge (qty += 1).
* Редкость НЕ хранится (сейв/лут) — определяется каталогом
  (000230.01/.02); UI: рамка cp-rarity-<rarity> — 5 редкостей =
  5 классов (000230.07),
  5 цветов: серый/зелёный/синий/фиолетовый/жёлто-оранжевый
  (index.html, 000230.07); предмет без rarity — БЕЗ рамки
  (cp-rarity-none, 230.07-RAR-G).

## Наборы и аффиксы
 * Наборы (000230.04): set (id) + set_bonus — В JSON предмета
   (отдельного каталога наборов НЕТ — 000230.01/D5); set_bonus
   без set — ошибка валидации. Каталог: 17 наборов / 43 предмета
   — у всех 43 есть и set, и set_bonus; контент-контракт
   (SB13/D-03): set_bonus ОДИНАКОВ у всех членов набора.
 * Активация — число НАДЕТЫХ предметов (каждый = 1, кольцо = 1;
   18 физических слотов — раздел «Снаряжение»); пороги {2,3,4}
   (SET_BONUS_THRESHOLDS, items.js) — каждый активен независимо,
   кумулятивно. В каталоге: уровень 2 — у всех 17 наборов,
   уровень 4 — только fate, уровень 3 — отсутствует.
 * Значение порога — одна из двух форм: stat-объект {armor: N} /
   {damage: N} (armor — плоская сумма в броню; damage — только
   при надетом оружии в right_hand, «фантомного оружия» НЕТ —
   D-02) ИЛИ affix-массив (та же форма, что аффиксы предмета —
   единый пайплайн). Агрегатор — activeSets(c) (чистая):
   значение порога — от ПЕРВОГО (по порядку EQUIP_PHYS_SLOTS)
   надетого предмета набора, имеющего ключ порога.
 * Аффиксы (000230.01/.03) — две формы: {type:'skill',
   skill:<id>, amount:<±>} (id навыка из assets/skills;
   валидатор — ФОРМА id, каталожность — тестом) и
   {type:'free_cast', spell:<id>} (id из assets/spells). У всех
   277 — минимум 1 аффикс; 287 skill-аффиксов на 31 навык.
 * ЕДИНАЯ точка применения — derived() (sheet.js): вклад навыка ×
   (1 + Σ affix skills[id]), clamp ≥ базового нуля (отрицательный
   аффикс не уводит вклад ниже базового нуля); без аффиксов —
   бит-в-бит (000230.03). Агрегатор — equipmentAffixes(c)
   (чистая): аффиксы ВСЕХ 18 физических слотов + set-бонусы →
   {skills: {id: Σamount}, freeCast: Set(spellId)}.
 * free_cast: мана 0, действие «Заклинание» сгорает, книга рангов
   без изменений; в бою (000230.03) и вне боя (000230.17 —
   spec/spells.md «Каст вне боя»); союзники — те же правила
   (000193); Эфир — guard (не применяется). Каталог: 16
   предметов (15 epic + 1 legendary).
 * Шкала силы (amount, на аффикс): common 0.02–0.05, rare
   0.05–0.10, epic 0.10–0.20, legendary 0.20–0.35, impossible
   0.35+; free_cast — только epic+. Покрытие: ВСЕ 31 вторичный
   навык — минимум 1 предмет (базовые навыки — НЕ аффиксуются).
 * Орудие (000230.12/D8): заменяет оружие в right_hand (игрок

## Свиток заклинания (spell_scroll)
* Свиток-носитель изучения (000133; расширение 000235.05):
  `kind` = `spell_scroll`, `effect` = {kind: 'spell', spell: <id>}
  (связь свиток ↔ заклинание, id из assets/spells); изучение — при
  применении (чтение — Интеллект); ранг-гейт — без изменений
  (spec/spells.md «Ранги в школе»).
* `tier` (1..4) = `уровень` изучаемого заклинания (000235.05:
  у 8 свитков 000043–000050 tier проставлен); свиток без tier —
  tier 1 (dungeon.js).
* Лут (формулы дословно — spec/dungeons-storage.md «Лут»): с мобов
  — от разницы уровней (D, P_scroll, тир, школа); с сундуков —
  tier по глубине (T = min(4, 1 + floor((depth−1)/2))).

## Чертёж вида крафта (craft_scroll)
* Носитель изучения (000232): `kind` = `craft_scroll`,
  `effect` = {kind: 'craft_recipe', recipe: <ссылка>} — в JSON-
  каталоге assets/items — файловая ссылка
  `assets/craft/NNNNNN.json` (source of truth), в зеркале
  src/items-data.js — id (sync-items-data.js резолвит; битая
  ссылка — exit 1).
* Применение — изучение ЦЕЛОГО вида крафта (вид якорного
  рецепта; предикат/гейт/способы — spec/craft.md «Изучение
  видов»); цель — персонаж (носитель инвентаря); повторное
  применение (вид уже изучен, в т.ч. по прогрессу) — отказ
  БЕЗ расхода (предмет цел).
* Источники: NPC-сток (статичный, по одному чертежу на вид),
  сундуки подземелий (каждый чертёж — ровно в одном пуле,
  append концом), лут мобов (предметная таблица `u.loot`
  моба, chance 0.05 — spec/mob-groups-storage.md «Лут»).
* В бою — быстрый слот (000223): отказ ДО расхода (слот
  цел), успех — расход у вызывающего.

## Архитектура хранения (каталог assets/items)
 * Описание предметов хранится в каталоге assets/items: каждый предмет —
   отдельный JSON-файл (000001.json, 000002.json, …).
 * Структура файла закреплена JSON-схемой assets/items/schema.json.
 * Игра открывается двойным кликом (file://), где fetch() локальных JSON
   не работает, поэтому каталог дублируется в униформном JS-модуле
   src/items-data.js (фолбэк; в браузере — Game.ITEMS, в node —
   require()). JS-модуль ГЕНЕРИРУЕТСЯ скриптом `node
   scripts/sync-items-data.js` (npm `sync:items`) из JSON-каталога
   (source of truth — JSON, как в `src/buildings.js` /
   `src/dungeons-data.js`): шапка файла помечена «GENERATED — не править
   руками», генерация идемпотентна (повторный запуск — byte-identical),
   вывод пишется атомарно (scripts/lib/write-atomic.js, конвенция
   раздела «CI и публикация на GitHub Pages», задача 000054); из CI
   вызывается тем же образом (sync-all.js подхватывает скрипт по
   конвенции имён). id предметов НЕ перенумеруются: сейв v1 ссылается на
   id (npcStocks/quests, задача 000031) — данные переносятся 1:1.
   Node-тест проверяет, что JS-модуль идентичен JSON-файлам.
 * Ядро (src/items.js, без DOM) при загрузке семантически валидирует
   каталог: типы, подтипы оружия, эффекты, навыки книг.
 * Сундуки подземелий (src/dungeon.js) хранят id предметов каталога.

## Архитектура хранения (каталог assets/visuals)
 * Декорации тайлов (задача 000021) хранятся в каталоге assets/visuals:
   каждый элемент — отдельный JSON-файл (000001.json, 000002.json, …),
   поле `id` равно номеру файла. Структура файла закреплена JSON-схемой
   assets/visuals/schema.json.
 * Игра открывается двойным кликом (file://), где fetch() локальных JSON
   не работает, поэтому каталог дублируется в униформном JS-фолбэке
   src/visuals-data.js (в браузере — Game.VisualsData, в node —
   require()). Модуль ГЕНЕРИРУЕТСЯ скриптом `node
   scripts/sync-visuals-data.js` (npm `sync:visuals`) из JSON-каталога
   (source of truth — JSON, та же конвенция, что и items/buildings/
   dungeons): шапка «GENERATED — не править руками», генерация
   идемпотентна (повторный запуск — byte-identical), вывод пишется
   атомарно (scripts/lib/write-atomic.js, раздел «CI и публикация на
   GitHub Pages», задача 000054); из CI вызывается тем же образом
   (sync-all.js подхватывает скрипт по конвенции имён).
 * src/sprites.js — потребитель БЕЗ собственной копии каталога:
   браузерная ветка снимает Game.VisualsData при загрузке (visuals-data.js
   в index.html подключён ДО sprites.js — УМД-ловушка 000038), node-ветка —
   require('./visuals-data.js'). Без data-модуля (vm-песочницы) гард
   деградирует до пустого каталога — рендер не падает.
   VISUALS_SEED/MAX_VISUALS_PER_TILE/VISUALS_MIN_ZOOM — параметры рендера
   (логика, не данные) — остаются в sprites.js.
 * Визуалы в сейв НЕ пишутся: разброс на тайлах детерминирован
   (seed VISUALS_SEED + id элемента), закреплён golden-тестами.

## Инвентарь
 * Инвентарь — (20 + 2 × уровень «Крепкая спина») слотов; база — INVENTORY_SLOTS (20). Складываемые предметы
   (зелья, еда, книги, реагенты) складываются стопкой до MAX_STACK (99)
   в одном слоте; оружие и броня занимают каждый свой слот.
 * Лимит веса: суммарный вес (вес предмета × количество) не превышает
   базовый переносимый вес (30 кг) × множитель «Крепкая спина»
   (+10% за уровень).
 * «Быстрые предметы» — QUICK_SLOTS (3) закреплённых слота для действий
   в бою: действие «Применение предмета из быстрых предметов»
   (Ловкость/Харизма), пул — от Ловкости. «Вытаскивание предмета из
   инвентаря» (Удача) — один раз за ход.

## Снаряжение
 * 18 физических слотов (000230.02): 11 групп — 10 частей тела
   (head, ears, neck, torso, forearms, right_hand, left_hand,
   palms, legs, feet) и кольца — 8 слотов (4 на каждую руку:
   ring_left_1..4, ring_right_1..4). Один предмет — в одном слоте;
   кольцо — в первый свободный из 8 (все заняты — отказ).
   Экипировка берёт предмет из инвентаря; снятие возвращает
   обратно. Смена предмета возвращает предыдущий в инвентарь.
 * Наборы (000230.04): счёт — по слотам, каждый надетый предмет
   набора = 1 (кольцо = 1).

## Торговля
 * Магазины (типы построек): оружейная (оружие), бронник (броня),
   аптекарь (зелья и еда), магазин магии (реагенты и книги),
   таверна (еда и зелья). Постройка богатства 3 — универсам:
   смешанный ассортимент.
 * Источник видов ассортимента магазина — каталог assets/buildings:
   `особые_параметры.виды` записи «картового» магазина (массив id из
   ITEM_KINDS), читается src/items.js ЛЕНИВО (items.js грузится до
   buildings.js; vm-песочницы без каталога — фолбэк-таблица в
   items.js, поведение идентично). Цены, богатство, сток и seed
   (hash2) от видов не зависят.
 * «Богатство» постройки (0-3, из шума) влияет на ассортимент и цены:
   −10% цена покупки за уровень богатства, +15% цена продажи.
 * Навык «Торговец»: −5% цены покупки, +5% цены продажи за уровень.
 * Ассортимент (витрина) детерминирован: от координат тайла, типа
   постройки и богатства.
 * NPC-торговля (раздел «NPC», поле «торговля») расширяет ассортимент
   построек: аптекарь продаёт травы, странствующий торговец
   (Лавка странника) — руду, минералы, дерево, камень, кожу и уголь; магазин
   магии и универсам покрывают новые реагенты автоматически.
   «Травы» аптекаря в таблице «Магазины» реализованы именно через
   NPC-торговлю — in-game ассортимент постройки: зелья и еда.
